
## 1. Vulnerabilidades importantes de Windows

|Vulnerabilidad|Identificador|Descripción|
|---|---|---|
|**MS08-067**|MS08-067|Fallo en SMB que permitía comprometer sistemas Windows vulnerables. Fue utilizado por el gusano Conficker y también por Stuxnet.|
|**EternalBlue**|MS17-010|Vulnerabilidad de SMBv1 que permite ejecución remota de código. Se utilizó en ataques como WannaCry y NotPetya.|
|**PrintNightmare**|CVE-2021-34527|Vulnerabilidad de ejecución remota de código relacionada con Windows Print Spooler.|
|**BlueKeep**|CVE-2019-0708|Vulnerabilidad de ejecución remota de código en RDP que afecta a determinadas versiones antiguas de Windows.|
|**SIGRed**|CVE-2020-1350|Vulnerabilidad en el servicio DNS de Windows que puede permitir ejecución remota de código y comprometer un controlador de dominio.|
|**SeriousSAM**|CVE-2021-36934|Problema de permisos en archivos de Windows que podía permitir acceder a información sensible, incluida la base de datos SAM mediante copias de instantáneas de volumen.|
|**Zerologon**|CVE-2020-1472|Vulnerabilidad criptográfica en Netlogon que puede permitir comprometer un controlador de dominio vulnerable.|

## 2. Fingerprinting de Windows

El _fingerprinting_ permite identificar el sistema operativo de un objetivo mediante distintas características de la red y de sus servicios.

### 2.1. Identificación mediante TTL

Podemos utilizar `ping` para observar el valor TTL (_Time To Live_) de las respuestas ICMP.

```
ping <IP_OBJETIVO>
```

Ejemplo de respuesta:

```
64 bytes from 192.168.86.39: icmp_seq=0 ttl=128 time=102.920 ms
```

Valores orientativos del TTL inicial:

|TTL observado|Posible sistema operativo|
|---|---|
|`128`|Windows|
|`64`|Linux/Unix|
|`255`|Algunos dispositivos de red y sistemas Unix|

**Importante:** son valores orientativos, no una prueba definitiva. El TTL disminuye con los saltos de red y puede variar según el sistema y la configuración.

### 2.2. Identificación del SO con Nmap

```
sudo nmap -v -O <IP_OBJETIVO>
```

- `-v`: aumenta el nivel de detalle de la salida.
    
- `-O`: intenta identificar el sistema operativo.
    

Ejemplo de información obtenida:

```
Device type: general purpose
Running: Microsoft Windows 10
OS CPE: cpe:/o:microsoft:windows_10
OS details: Microsoft Windows 10 1709 - 1909
Network Distance: 1 hop
```

Los campos más importantes son:

- `Running`: sistema operativo identificado o estimado.
    
- `OS CPE`: identificador normalizado del sistema.
    
- `OS details`: detalles de la versión estimada.
    
- `Network Distance`: distancia aproximada en saltos.
    

Si Nmap no consigue identificar el sistema operativo, podemos probar:

```
sudo nmap -A -Pn <IP_OBJETIVO>
```

**Nota:** los firewalls, los filtros de red y la falta de respuestas pueden afectar a la precisión del fingerprinting.

## 3. Enumeración de servicios y banner grabbing

Una vez identificado el sistema operativo, debemos enumerar los servicios expuestos para buscar posibles vías de explotación.

### Escaneo completo de servicios

```
nmap -sC -sV -Pn <IP_OBJETIVO>
```

### Banner grabbing con Nmap

```
sudo nmap -v <IP_OBJETIVO> --script banner.nse
```

El script `banner.nse` intenta obtener información proporcionada por los servicios que aceptan conexiones.

Ejemplo de resultado:

```
902/tcp open  iss-realsecure
| banner: 220 VMware Authentication Daemon Version 1.10
```

El banner puede revelar:

- Nombre del servicio.
    
- Software utilizado.
    
- Versión del servicio.
    
- Protocolos o características compatibles.
    

Esta información permite buscar posibles vulnerabilidades asociadas al software identificado.

**Importante:** que un servicio revele su versión no significa necesariamente que sea vulnerable.

## 4. Tipos de archivos utilizados en Windows

Al crear payloads para Windows, debemos tener en cuenta qué formatos pueden ejecutarse y qué mecanismo de entrega está disponible.

|Tipo|Extensión|Descripción|
|---|---|---|
|**DLL**|`.dll`|Biblioteca de código y datos compartidos por aplicaciones. Su carga o secuestro en determinadas condiciones puede utilizarse para explotar problemas de seguridad o elevar privilegios.|
|**Batch**|`.bat`|Archivo de texto que contiene comandos para ejecutar mediante el intérprete de comandos de Windows. Permite automatizar tareas.|
|**VBScript**|`.vbs`|Lenguaje de scripting que puede utilizarse para automatizar acciones en entornos Windows compatibles.|
|**MSI**|`.msi`|Paquete de instalación utilizado por Windows Installer.|
|**PowerShell**|`.ps1`|Script de PowerShell que permite automatizar tareas y utilizar funcionalidades de .NET y del sistema operativo.|

### Consideraciones

- **DLL:** puede ser cargada por un proceso; no se ejecuta normalmente como un `.exe` independiente.
    
- **BAT:** resulta útil para ejecutar secuencias de comandos.
    
- **VBS:** puede utilizarse en determinados mecanismos de automatización, aunque su disponibilidad depende del entorno.
    
- **MSI:** se utiliza para instalar aplicaciones mediante Windows Installer.
    
- **PowerShell:** ofrece funcionalidades avanzadas mediante cmdlets, scripts y objetos .NET.
    

La elección del formato depende del objetivo, el entorno y las restricciones de ejecución.

## 6. Transferencia y ejecución de payloads

Una vez generado un archivo, es necesario transferirlo al objetivo y disponer de un mecanismo para ejecutarlo.

### Métodos y herramientas

**Impacket**

Conjunto de herramientas Python que permite interactuar con protocolos de red. Incluye utilidades relacionadas con SMB, ejecución remota, WMI y Kerberos.

**SMB**

Puede utilizarse para acceder a recursos compartidos y transferir archivos cuando los permisos y las credenciales lo permiten.

Recursos habituales:

- `ADMIN$`: recurso administrativo asociado a Windows.
    
- `C$`: recurso administrativo que permite acceder a la unidad C: si se dispone de los permisos necesarios.
    

**Otros protocolos**

Dependiendo de los servicios disponibles, también pueden existir mecanismos de transferencia mediante:

- FTP.
    
- TFTP.
    
- HTTP/HTTPS.
    
- SMB.
    

**Metasploit**

Algunos módulos permiten preparar, transferir y ejecutar automáticamente un payload como parte del proceso de explotación.

La transferencia de un archivo y su ejecución son pasos diferentes: conseguir que el archivo llegue al objetivo no garantiza que pueda ejecutarse.

## 7. Flujo de trabajo de un compromiso de ejemplo

### Paso 1. Enumerar el objetivo

```
nmap -v -A <IP_OBJETIVO>
```

El escaneo puede revelar:

- Puertos abiertos.
    
- Servicios y versiones.
    
- Sistema operativo estimado.
    
- Información SMB.
    
- Nombre del equipo.
    
- Posibles configuraciones inseguras.
    

Ejemplo de servicios:

|Puerto|Servicio|
|---|---|
|`80/tcp`|HTTP — Microsoft IIS|
|`135/tcp`|MSRPC|
|`139/tcp`|NetBIOS-SSN|
|`445/tcp`|SMB|

Con estos resultados se identifican posibles vectores que conviene investigar.

### Paso 2. Comprobar MS17-010

Metasploit incluye un módulo auxiliar para comprobar si un sistema SMB podría ser vulnerable a MS17-010.

```
use auxiliary/scanner/smb/smb_ms17_010
```

Consultar las opciones:

```
show options
```

Configurar el objetivo:

```
set RHOSTS <IP_OBJETIVO>
```

Ejecutar la comprobación:

```
run
```

Un mensaje como:

```
Host is likely VULNERABLE to MS17-010!
```

indica que el módulo considera probable la vulnerabilidad.

**Importante:** es una indicación del resultado de la comprobación, no una garantía absoluta de que la explotación vaya a funcionar.

### Paso 3. Buscar módulos relacionados

```
search eternal
```

La búsqueda puede mostrar módulos relacionados con MS17-010, entre ellos:

```
exploit/windows/smb/ms17_010_eternalblue
exploit/windows/smb/ms17_010_psexec
auxiliary/scanner/smb/smb_ms17_010
```

Hay que distinguir entre:

- `exploit`: módulo que intenta explotar una vulnerabilidad.
    
- `auxiliary/scanner`: módulo de comprobación o enumeración.
    
- `auxiliary/admin`: módulo auxiliar de administración.
    

Los módulos pueden tener diferentes requisitos, sistemas compatibles y probabilidades de éxito.

### Paso 4. Revisar las opciones

Después de seleccionar un módulo:

```
show options
```

Hay que comprobar especialmente:

- `RHOSTS`: objetivo.
    
- `RPORT`: puerto remoto.
    
- `LHOST`: dirección local para recibir la conexión inversa.
    
- `LPORT`: puerto del listener.
    
- Las opciones de autenticación, si son necesarias.
    

No deben asumirse los valores predeterminados como correctos para todos los laboratorios.

### Paso 5. Verificar el resultado

Si una explotación autorizada tiene éxito, Metasploit puede mostrar:

```
Meterpreter session 1 opened
```

Desde Meterpreter, podemos consultar la identidad del usuario de la sesión:

```
getuid
```

En el ejemplo del módulo, el resultado es:

```
Server username: NT AUTHORITY\SYSTEM
```

`NT AUTHORITY\SYSTEM` es una cuenta de servicio integrada de Windows con privilegios muy elevados.

## 8. Identificar CMD y PowerShell

Después de obtener una sesión, es importante reconocer qué intérprete de comandos estamos utilizando.

### CMD

Ejemplo de prompt:

```
C:\Windows\system32>
```

Características:

- Es el intérprete de comandos tradicional de Windows.
    
- Trabaja principalmente con entrada y salida de texto.
    
- Permite ejecutar comandos del sistema y archivos batch.
    
- Es útil para operaciones básicas y para equipos antiguos.
    

### PowerShell

Ejemplo de prompt:

```
PS C:\Windows\system32>
```

Características:

- Es un intérprete de comandos y un lenguaje de scripting.
    
- Ofrece cmdlets y funcionalidades de .NET.
    
- Trabaja con objetos además de texto.
    
- Permite automatizar tareas avanzadas y administrar sistemas y servicios.
    

### Comparación

|Característica|CMD|PowerShell|
|---|---|---|
|Entrada y salida|Principalmente texto|Objetos .NET y texto|
|Automatización|Archivos `.bat`|Scripts `.ps1` y cmdlets|
|Funcionalidades|Comandos tradicionales|Funcionalidades avanzadas de .NET|
|Compatibilidad|Amplia, incluidos sistemas antiguos|Depende de la versión instalada|
|Prompt habitual|`C:\...>`|`PS C:\...>`|

### Desde Meterpreter

Para abrir una shell del sistema:

```
shell
```

El prompt que aparece permite identificar el intérprete. También podemos utilizar:

```
help
```

para consultar los comandos disponibles en CMD o PowerShell, según la shell abierta.

## 9. ¿Cuándo utilizar CMD o PowerShell?

### CMD

Puede resultar adecuado cuando:

- Se trabaja con un sistema antiguo sin PowerShell.
    
- Solo se necesitan comandos básicos.
    
- Se van a utilizar archivos batch.
    
- Se necesitan herramientas tradicionales de Windows.
    

### PowerShell

Puede resultar adecuado cuando:

- Se necesitan cmdlets o scripts personalizados.
    
- Se requiere interactuar con objetos .NET.
    
- Se necesita automatizar tareas complejas.
    
- Se administran servicios o sistemas basados en Windows y la nube.
    

La elección depende de las funcionalidades necesarias y de las restricciones del entorno.

## 10. WSL y PowerShell Core

### WSL — Windows Subsystem for Linux

WSL permite ejecutar un entorno Linux integrado en Windows.

Su existencia amplía las posibilidades de administración y ejecución de herramientas, pero también introduce aspectos adicionales que deben considerarse durante la monitorización y la seguridad del sistema.

### PowerShell Core

PowerShell Core permite utilizar PowerShell en diferentes sistemas operativos, incluido Linux.

Puede utilizarse para automatizar tareas y administrar sistemas desde distintos entornos.

**Enfoque defensivo:** las herramientas y los entornos de scripting deben supervisarse según las capacidades reales de los mecanismos de seguridad instalados. No se debe asumir que WSL o PowerShell quedan automáticamente fuera de la monitorización: la visibilidad depende de la configuración y de las soluciones de seguridad presentes.

## Conceptos que debes recordar

- El **fingerprinting** ayuda a identificar el sistema operativo.
    
- El TTL es una pista, pero no confirma por sí solo que un sistema sea Windows.
    
- Nmap permite detectar puertos, servicios, versiones y posibles características del sistema.
    
- El _banner grabbing_ puede revelar información útil para investigar servicios.
    
- DLL, BAT, VBS, MSI y PowerShell tienen funciones y mecanismos de ejecución diferentes.
    
- La generación, transferencia y ejecución de un payload son etapas distintas.
    
- MS17-010 está relacionado con vulnerabilidades de SMB y EternalBlue.
    
- Un módulo `auxiliary/scanner` puede comprobar o enumerar sin ser necesariamente un exploit.
    
- Meterpreter permite consultar la identidad de la sesión mediante `getuid`.
    
- `C:\...>` suele indicar CMD; `PS C:\...>` suele indicar PowerShell.
    
- La selección de herramientas y shells depende de las características del objetivo y de los permisos disponibles.
