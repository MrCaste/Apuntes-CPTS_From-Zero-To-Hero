
## 1. ¿Qué es una Web Shell?

Una **Web Shell** es una shell accesible desde un navegador web que permite interactuar con el sistema operativo subyacente de un servidor web.

Normalmente, se obtiene subiendo un archivo que contiene un payload escrito en un lenguaje compatible con la aplicación web, como:

- **PHP**
    
- **JSP**
    
- **ASP.NET**
    

Si el servidor ejecuta el archivo subido, podemos llegar a conseguir **ejecución remota de comandos (RCE)** a través del navegador.

El objetivo inicial es aprovechar una vulnerabilidad o una configuración incorrecta que permita subir y ejecutar archivos en el servidor.

---

## 2. Vectores habituales de entrada

Durante una auditoría de seguridad, podemos encontrar diferentes formas de conseguir que una Web Shell llegue al servidor.

### Subida de archivos sin restricciones

Una aplicación puede permitir subir archivos sin validar correctamente su contenido o extensión.

Ejemplos de funcionalidades potencialmente vulnerables:

- Formularios públicos de subida de archivos.
    
- Subida de fotografías de perfil.
    
- Funcionalidades de carga de documentos.
    
- Formularios disponibles después de autenticarse.
    
- Funcionalidades de autorregistro que permiten subir archivos.
    

### Evasión de validaciones

Algunas aplicaciones realizan comprobaciones de seguridad únicamente en el lado del cliente.

Si las validaciones del servidor son insuficientes, podría ser posible subir archivos que la aplicación pretendía bloquear.

### Despliegue de aplicaciones

Algunas plataformas permiten desplegar aplicaciones o archivos ejecutables desde sus interfaces de administración.

Ejemplos mencionados en el módulo:

- Apache Tomcat.
    
- Axis2.
    
- WebLogic.
    

En determinados escenarios, estas plataformas permiten desplegar código JSP mediante un archivo WAR.

### FTP mal configurado

Un servidor FTP podría permitir subir archivos directamente al directorio raíz de una aplicación web, conocido como `webroot`.

Si además el servidor web puede interpretar el archivo subido, podría convertirse en un punto de entrada para ejecutar comandos.

### Otros vectores

Las aplicaciones web también pueden presentar vulnerabilidades que permitan alcanzar la ejecución de comandos, como:

- Inyección SQL.
    
- Inclusión remota o local de archivos (RFI/LFI).
    
- Inyección de comandos.
    
- Vulnerabilidades en funcionalidades de subida de archivos.
    

**Importante:** detectar una vulnerabilidad no significa que permita automáticamente ejecutar una Web Shell. Debemos comprobar qué capacidades ofrece y cómo está configurado el servidor.

---

## 3. ¿Cómo funciona una Web Shell?

El proceso general es el siguiente:

1. **Enumerar:** identificar los servicios web y las aplicaciones disponibles.
    
2. **Investigar:** buscar funcionalidades vulnerables o configuraciones incorrectas.
    
3. **Obtener capacidad de subida:** localizar una funcionalidad que permita cargar archivos.
    
4. **Subir el payload:** utilizar un archivo compatible con la tecnología del servidor.
    
5. **Ejecutar el archivo:** acceder a él mediante el navegador si el servidor permite su ejecución.
    
6. **Ejecutar comandos:** utilizar la interfaz de la Web Shell para interactuar con el sistema operativo.
    
7. **Evaluar las posibilidades de acceso:** determinar si conviene establecer una shell más interactiva.
    

El funcionamiento depende de que el servidor interprete el archivo y de los permisos del proceso que ejecuta la aplicación.

---

## 4. Limitaciones de las Web Shells

Aunque una Web Shell puede proporcionar ejecución remota de comandos, presenta varias limitaciones.

### Interacción limitada

La interacción se realiza a través de una aplicación web y no necesariamente mediante una terminal completa.

Por ello, algunas operaciones pueden resultar menos cómodas o fiables que en una shell interactiva.

### Eliminación de archivos

Algunas aplicaciones web eliminan automáticamente los archivos subidos después de cierto tiempo.

Esto puede provocar que una Web Shell deje de estar disponible.

### Permisos del proceso web

Los comandos se ejecutan con los permisos del proceso que atiende la aplicación web.

Por tanto, obtener una Web Shell no implica necesariamente tener acceso administrativo o privilegios de `root`.

### Fiabilidad

La disponibilidad de la Web Shell depende de factores como:

- La configuración del servidor.
    
- Los permisos sobre los archivos.
    
- La posibilidad de ejecutar el lenguaje correspondiente.
    
- Las restricciones de la aplicación.
    
- La eliminación de archivos subidos.
    

---

## 5. Web Shell frente a Reverse Shell

|Característica|Web Shell|Reverse Shell|
|---|---|---|
|Interacción|A través del navegador web|Mediante una conexión de shell|
|Acceso inicial|Habitualmente mediante una aplicación web vulnerable|Mediante un mecanismo que permita establecer la conexión|
|Terminal interactivo|No necesariamente|Depende de cómo se establezca la sesión|
|Dependencia del archivo web|Normalmente sí|No necesariamente después de establecer la sesión|
|Limitaciones|Aplicación web, permisos y disponibilidad del archivo|Conectividad, configuración y tipo de shell|

Una Web Shell puede servir como punto de partida para conseguir una shell más interactiva, si el entorno y los permisos lo permiten.

## 6. Metodología práctica en HTB

Cuando nos encontremos con una posible vulnerabilidad web:

1. Identificar la aplicación y su tecnología.
    
2. Enumerar las funcionalidades disponibles.
    
3. Investigar las posibilidades de subida y ejecución de archivos.
    
4. Revisar las validaciones y los permisos aplicados en el servidor.
    
5. Comprobar si existe una vulnerabilidad que permita ejecutar comandos.
    
6. Si se obtiene una Web Shell, identificar el usuario y los permisos del proceso.
    
7. Evaluar las limitaciones de la sesión y las posibilidades de obtener una shell más interactiva.
    

### Ideas clave para el examen

- Una Web Shell permite interactuar con el sistema operativo desde un navegador.

- Las aplicaciones web expuestas suelen representar una superficie de ataque importante.
    
- Tomcat, Axis2 y WebLogic son ejemplos de plataformas que pueden ofrecer funcionalidades de despliegue.

- Los comandos se ejecutan con los permisos del proceso correspondiente.
    
- Una Web Shell puede servir como acceso inicial para intentar establecer una shell más interactiva.
