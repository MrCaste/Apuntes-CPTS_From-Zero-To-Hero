
## 1. ¿Qué es Laudanum?

**Laudanum** es un repositorio de archivos preparados para utilizarse como payloads en pruebas de penetración. Incluye archivos que permiten ejecutar comandos en un sistema víctima desde el navegador y otros que pueden utilizarse para establecer conexiones de shell.

Contiene archivos para diferentes tecnologías web, entre ellas:

- ASP
    
- ASPX
    
- JSP
    
- PHP
    

En **Kali Linux y Parrot OS**, los archivos de Laudanum están disponibles normalmente en:

```
/usr/share/laudanum/
```

Antes de utilizar un archivo, debemos revisar su contenido y sus comentarios para conocer los parámetros que requiere.

---

## 2. Preparar una copia del payload

Es recomendable copiar el archivo que vamos a utilizar a un directorio de trabajo para modificarlo sin alterar el original.

En el ejemplo del módulo se utiliza una Web Shell ASPX:

```
cp /usr/share/laudanum/aspx/shell.aspx /home/tester/demo.aspx
```

El archivo se copia como `demo.aspx`, que será el nombre utilizado durante la demostración.

### Configurar las IP permitidas

Algunos archivos de Laudanum incluyen una lista de direcciones IP autorizadas para utilizar la shell.

En el ejemplo, debemos editar la variable `allowedIps` del archivo y añadir la IP de nuestra máquina atacante.

Es importante distinguir entre:

- **IP atacante:** dirección desde la que accedemos a la Web Shell.
    
- **IP objetivo:** dirección del servidor web donde se encuentra la aplicación.
    

La dirección permitida debe corresponder con la que espera el mecanismo de autorización del archivo.

---

## 3. Configurar el archivo `/etc/hosts`

Para acceder al servidor utilizando el nombre virtual indicado por HTB, debemos añadir una entrada al archivo `/etc/hosts` de nuestra máquina atacante.

Editar el archivo:

```
sudo nano /etc/hosts
```

Añadir:

```
<IP_OBJETIVO> status.inlanefreight.local
```

Sustituir `<IP_OBJETIVO>` por la dirección IP del objetivo del laboratorio.

Esto permite resolver `status.inlanefreight.local` hacia la IP correspondiente.

**Importante:** la entrada debe configurarse en el entorno desde el que estamos realizando el laboratorio, ya sea nuestra máquina conectada a la VPN o Pwnbox.

---

## 4. Subir la Web Shell

El laboratorio utiliza una aplicación web de estado del servidor que incluye una funcionalidad para subir archivos de configuración.

El procedimiento descrito es:

1. Acceder a `status.inlanefreight.local`.
    
2. Localizar la funcionalidad de subida de archivos.
    
3. Seleccionar el archivo `demo.aspx`.
    
4. Subirlo mediante el formulario.
    
5. Comprobar si la aplicación indica dónde se ha guardado.
    

Si la subida funciona, la aplicación muestra la ruta donde se ha almacenado el archivo.

### Aspectos importantes

- La extensión del archivo debe ser compatible con la tecnología que ejecuta el servidor.
    
- Subir un archivo no garantiza que el servidor permita ejecutarlo.
    
- La aplicación puede modificar el nombre del archivo o guardarlo en una ubicación no accesible públicamente.
    
- La ruta de almacenamiento puede determinar si es posible acceder a la Web Shell desde el navegador.
    

---

## 5. Acceder a la Web Shell

En la demostración, el archivo se guarda dentro del directorio `files`.

La ruta utilizada es:

```
status.inlanefreight.local/files/demo.aspx
```

En el material del módulo, la ruta devuelta por la aplicación utiliza inicialmente barras invertidas (`\`), pero el navegador puede normalizar la dirección al mostrarla.

Una vez abierta la ruta, aparece la interfaz de Laudanum ASPX.

La interfaz permite introducir comandos y consultar su salida.

---

## 6. Ejecutar comandos desde Laudanum

En la interfaz de la Web Shell encontramos un campo de entrada de comandos y un botón para enviar la consulta.

El módulo utiliza el siguiente comando de Windows como ejemplo:

```
systeminfo
```

Este comando muestra información del sistema, como:

- Nombre del equipo.
    
- Versión del sistema operativo.
    
- Fabricante.
    
- Tipo de sistema.
    
- Procesador.
    
- Memoria.
    
- Información de red.
    

La salida aparece en el navegador, dentro de la sección correspondiente a `STDOUT`.

Esto demuestra que el servidor está ejecutando el comando y devolviendo su resultado a través de la aplicación web.

---

## 7. Flujo de trabajo resumido

1. **Localizar Laudanum:**
    
    ```
    ls /usr/share/laudanum/
    ```
    
2. **Copiar el payload** a un directorio de trabajo:
    
    ```
    cp /usr/share/laudanum/aspx/shell.aspx /home/tester/demo.aspx
    ```
    
3. **Modificar el archivo:** revisar sus parámetros y configurar `allowedIps` según el entorno.
    
4. **Configurar el nombre virtual** en `/etc/hosts`:
    
    ```
    <IP_OBJETIVO> status.inlanefreight.local
    ```
    
5. **Subir el archivo** mediante la funcionalidad de carga del laboratorio.
    
6. **Comprobar la ruta** donde se ha guardado.
    
7. **Acceder a la Web Shell** desde el navegador.
    
8. **Ejecutar un comando de comprobación**, como `systeminfo`, y revisar el resultado.
    

---

## 8. Ideas clave para el examen

- Laudanum contiene payloads preparados para distintas tecnologías web.
    
- En Kali y Parrot OS, se encuentra normalmente en `/usr/share/laudanum/`.
    
- Conviene trabajar sobre una copia del archivo original.
    
- Algunos payloads requieren configurar una lista de IP permitidas.
    
- `/etc/hosts` permite resolver el nombre virtual del laboratorio hacia la IP del objetivo.
    
- La subida correcta de un archivo no garantiza que pueda ejecutarse.
    
- Debemos identificar la ruta donde se guarda el archivo para comprobar si es accesible desde el navegador.
    
- Una Web Shell permite enviar comandos al servidor y consultar su salida.
    
- En la demostración de HTB se utiliza una Web Shell ASPX y el comando `systeminfo`.
    
- Los comandos se ejecutan con los permisos de la cuenta que utiliza el proceso web.
