
## 1. Emuladores de terminal

Un **emulador de terminal** es una aplicación que permite interactuar con un sistema mediante una interfaz de línea de comandos (CLI).

Algunos ejemplos:

|Emulador|Sistema operativo|
|---|---|
|Windows Terminal|Windows|
|Cmder|Windows|
|PuTTY|Windows|
|Kitty|Windows, Linux y macOS|
|Alacritty|Windows, Linux y macOS|
|xterm|Linux|
|GNOME Terminal|Linux|
|MATE Terminal|Linux|
|Konsole|Linux|
|Terminal|macOS|
|iTerm2|macOS|

La elección depende de las preferencias personales y del entorno de trabajo.

**Importante:** el emulador de terminal no determina qué intérprete de comandos se utiliza. Una misma aplicación de terminal puede ejecutar diferentes shells.

## 2. Intérpretes de comandos (Shells)

Un **intérprete de comandos** es un programa que interpreta las instrucciones del usuario y solicita al sistema operativo que las ejecute.

La interfaz de línea de comandos combina tres elementos:

1. **Sistema operativo:** proporciona los recursos y servicios del sistema.
    
2. **Emulador de terminal:** permite interactuar con la línea de comandos.
    
3. **Intérprete de comandos:** interpreta y ejecuta las instrucciones introducidas.
    

Algunos intérpretes habituales son:

- **Bash:** frecuente en sistemas Linux.
    
- **PowerShell:** utilizado principalmente en entornos Windows, aunque también funciona en Linux y macOS.
    
- **Ksh:** KornShell.
    
- **POSIX shell:** interfaz de comandos compatible con el estándar POSIX.
    

Conocer el intérprete utilizado es importante porque los comandos, la sintaxis y los scripts disponibles pueden variar.

## 3. Identificar el shell en Linux

### Método 1: observar el prompt

En muchos shells de Linux aparece el símbolo `$`:

```
usuario@htb:~$
```

Este símbolo suele indicar que el shell está preparado para recibir comandos.

Sin embargo, **el prompt por sí solo no identifica de forma inequívoca el intérprete**, ya que puede personalizarse.

### Método 2: utilizar `ps`

El comando `ps` permite consultar los procesos asociados a la terminal.

```
ps
```

Ejemplo de salida:

```
PID   TTY      TIME     CMD
4232  pts/1    00:00:00 bash
11435 pts/1    00:00:00 ps
```

En este caso, la salida muestra el proceso `bash`, lo que permite identificar el intérprete que aparece ejecutándose en esa terminal.

### Método 3: consultar las variables de entorno

Ejecuta:

```
env
```

Busca la variable `SHELL`:

```
SHELL=/bin/bash
```

Esto indica que el shell de inicio configurado para el usuario es Bash. Ten en cuenta que esta variable no siempre identifica el intérprete que se está ejecutando actualmente en una sesión anidada.

Para consultar directamente la variable:

```
echo "$SHELL"
```

## 4. PowerShell frente a Bash

Bash y PowerShell son intérpretes de comandos diferentes. Pueden ejecutarse desde un emulador de terminal compatible, pero utilizan sintaxis y herramientas distintas.

|Característica|Bash|PowerShell|
|---|---|---|
|Entornos habituales|Linux y sistemas Unix|Windows, Linux y macOS|
|Sintaxis|Comandos y herramientas Unix|Cmdlets y expresiones de PowerShell|
|Variable de entorno habitual para identificar el shell de inicio|`SHELL`|`SHELL` no es el mecanismo habitual de identificación en Windows|
|Ejemplo de comando para consultar procesos|`ps`|`Get-Process`|
|Ejemplo de comando para mostrar archivos|`ls`|`Get-ChildItem`|

Aunque algunos comandos tienen nombres parecidos, su funcionamiento y sus resultados pueden ser diferentes.

### ¿Por qué utilizar uno u otro?

Depende del sistema y de las tareas que quieras realizar.

- **Bash:** especialmente útil para administrar Linux y utilizar herramientas habituales de sistemas Unix.
    
- **PowerShell:** especialmente útil para administrar Windows y trabajar con sus servicios, procesos y componentes.
    

En pentesting, identificar el shell permite seleccionar la sintaxis y los comandos adecuados para el sistema objetivo.

## 5. Flujo práctico de identificación

Cuando obtengas una terminal durante una prueba de penetración:

```
1. Observa el prompt.
        |
        v
2. Ejecuta un comando de identificación,
   como ps en Linux.
        |
        v
3. Consulta las variables de entorno
   si necesitas más información.
        |
        v
4. Identifica el intérprete.
        |
        v
5. Adapta los comandos y scripts
   al shell disponible.
```

## Cheat Sheet

|---|---|

|Mostrar las variables de entorno|`env`|
|Consultar la variable `SHELL`|`echo "$SHELL"`|
|Mostrar procesos con Bash|`ps`|
|Mostrar procesos con PowerShell|`Get-Process`|

|Listar archivos con PowerShell|`Get-ChildItem`|

### Conceptos clave para el examen

- Un emulador de terminal es una aplicación que proporciona una interfaz para interactuar con el sistema.
    
- Un shell es el intérprete que procesa los comandos introducidos.
    
- El emulador de terminal no está ligado a un único intérprete.
    
- `ps` permite examinar los procesos en Linux e identificar el shell que aparece ejecutándose.
    
- `env` muestra las variables de entorno; `SHELL` suele indicar el shell de inicio configurado.
    
- Bash y PowerShell utilizan sintaxis y herramientas diferentes.
    
- Identificar el shell es importante para ejecutar los comandos y scripts adecuados durante el pentesting.
    

**Idea clave:** antes de ejecutar comandos en una sesión obtenida, identifica qué intérprete utiliza para adaptar la sintaxis y las herramientas al entorno.
