
## 1. ¿Qué es una Reverse Shell?

Una **Reverse Shell** es una conexión en la que la máquina objetivo inicia una conexión hacia la máquina atacante.

- **Atacante:** ejecuta un listener que espera conexiones.
- **Objetivo:** ejecuta un payload que inicia la conexión hacia el atacante.
- **Resultado:** el atacante obtiene acceso interactivo a la shell del objetivo.

### Diferencia entre Bind Shell y Reverse Shell

|Bind Shell|Reverse Shell|
|---|---|
|El objetivo abre un puerto y espera conexiones.|El atacante abre un listener y espera conexiones.|
|El atacante inicia la conexión.|El objetivo inicia la conexión.|
|Necesita permitir conexiones entrantes.|Necesita permitir conexiones salientes.|

Las Reverse Shells suelen ser útiles porque las conexiones salientes están menos restringidas en muchas redes.

## 2. Configurar un listener con Netcat

En la máquina atacante iniciamos un listener:

bash

```
sudo nc -lvnp 443
```

Significado de los parámetros:

- `-l`: modo escucha (listen).
- `-v`: modo verbose.
- `-n`: evita resolver nombres DNS.
- `-p`: especifica el puerto.
- `443`: puerto utilizado para recibir la conexión.

Ejemplo de salida:

text

```
Listening on 0.0.0.0 443
```

### ¿Por qué utilizar el puerto 443?

- Es el puerto habitual de HTTPS.
- Muchas organizaciones permiten conexiones salientes por este puerto.
- Puede facilitar que la conexión atraviese determinados firewalls.

**Importante:** utilizar un puerto habitual no garantiza que la conexión pase desapercibida. Los sistemas IDS/IPS y la inspección profunda de paquetes (DPI) pueden detectar tráfico malicioso.

## 3. Reverse Shell en Windows con PowerShell

Windows incluye PowerShell, por lo que podemos utilizarlo para establecer conexiones TCP sin necesidad de instalar Netcat.

Esto es un ejemplo de **Living off the Land (LotL)**: utilizar herramientas y funcionalidades que ya existen en el sistema objetivo.

### Elementos necesarios

1. Tener un listener activo en la máquina atacante.
2. Conocer la IP y el puerto del atacante.
3. Ejecutar el payload desde el objetivo Windows.
4. Conseguir que la conexión llegue al listener.

### Componentes principales del payload

|Componente|Función|
|---|---|
|`TCPClient`|Crea una conexión TCP con el atacante.|
|`GetStream()`|Obtiene el flujo de comunicación.|
|`Read()`|Recibe comandos del atacante.|
|`ASCIIEncoding`|Convierte los datos recibidos en texto.|
|`iex`|Ejecuta los comandos recibidos.|
|`Out-String`|Convierte la salida en texto.|
|`Write()`|Envía el resultado al atacante.|
|`Flush()`|Fuerza el envío de los datos pendientes.|
|`Close()`|Cierra la conexión.|

## 4. Antivirus y Windows Defender

Durante la práctica, al ejecutar el payload, Windows Defender detectó y bloqueó su ejecución.

Mensaje mostrado:

text

```
This script contains malicious content and has been blocked by your antivirus software.
```

Esto demuestra que los antivirus pueden detectar comportamientos asociados a Reverse Shells.

### Conceptos importantes

- **AV (Antivirus):** detecta y bloquea software o comportamientos maliciosos.
- **Real-time Protection:** analiza archivos y procesos en tiempo real.
- **EDR:** monitoriza comportamientos y actividades sospechosas de los sistemas.
- **DPI (Deep Packet Inspection):** inspecciona el contenido del tráfico de red.

En un laboratorio HTB autorizado se puede estudiar cómo afectan estos mecanismos a la ejecución de payloads y cómo validar las detecciones desde una perspectiva defensiva.

## 5. Comprobar que la Reverse Shell funciona

Cuando la conexión se establece correctamente, Netcat muestra un mensaje similar a:

text

```
Connection received on 10.129.36.68 49674
```

Aparece un prompt de PowerShell:

powershell

```
PS C:\Users\htb-student>
```

Podemos comprobar el usuario actual:

powershell

```
whoami
```

Ejemplo de resultado:

text

```
ws01\htb-student
```

Esto confirma que estamos ejecutando comandos en el sistema Windows remoto con los permisos del usuario que ejecutó el payload.

## 7. Flujo de una Reverse Shell

1. El atacante prepara un listener con Netcat.
2. El atacante configura la IP y el puerto que utilizará el objetivo.
3. El objetivo ejecuta el payload.
4. El objetivo inicia una conexión TCP hacia el atacante.
5. El listener recibe la conexión.
6. El atacante obtiene una shell interactiva.
7. Puede ejecutar comandos con los permisos del usuario comprometido.

---

## 8. Ideas importantes para el examen HTB

- En una **Reverse Shell**, quien inicia la conexión es el objetivo.
- En una **Bind Shell**, quien inicia la conexión es el atacante.
- El listener se ejecuta en la máquina atacante.
- Netcat puede utilizarse para recibir conexiones.
- PowerShell permite establecer Reverse Shells en Windows sin instalar herramientas adicionales.
- Los puertos habituales, como el 443, pueden estar permitidos para conexiones salientes, pero no garantizan que el tráfico pase inadvertido.
- Windows Defender puede detectar y bloquear payloads maliciosos.
- `whoami` permite comprobar con qué usuario estamos ejecutando comandos.
- Siempre debemos identificar qué herramientas y lenguajes están disponibles en el sistema objetivo.

**Idea fundamental:** En una Reverse Shell, el atacante escucha y el objetivo se conecta de vuelta. Esto permite obtener una shell remota aprovechando las conexiones salientes del sistema objetivo.
