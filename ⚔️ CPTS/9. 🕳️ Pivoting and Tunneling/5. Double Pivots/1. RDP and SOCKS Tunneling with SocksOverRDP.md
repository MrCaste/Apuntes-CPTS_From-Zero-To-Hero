
## 1. ¿Qué es SocksOverRDP?

**SocksOverRDP** permite tunelizar tráfico a través de una conexión RDP utilizando los **Dynamic Virtual Channels (DVC)** de los Servicios de Escritorio Remoto de Windows.

Los DVC se utilizan para transportar información a través de una sesión RDP, por ejemplo, datos del portapapeles y audio. SocksOverRDP aprovecha esta característica para transportar paquetes y permitir el pivoting hacia redes internas.

En este escenario se utilizan dos herramientas:

- **SocksOverRDP:** establece el canal SOCKS a través de RDP.
- **Proxifier:** redirige el tráfico de las aplicaciones a través del proxy SOCKS.

### Escenario del laboratorio

| Máquina | Dirección / función |
|---|---|
| Máquina Windows con acceso inicial | Red `10.129.x.x` |
| Host RDP intermedio | `172.16.5.19` |
| Objetivo interno | `172.16.6.155` |
| Proxy SOCKS | `127.0.0.1:1080` |

---

## 2. Preparar las herramientas

En la máquina de ataque, obtener los siguientes archivos:

- Binarios x64 de SocksOverRDP.
- Versión portable de Proxifier, identificada en el material como `ProxifierPE.zip`.

Después, conectarse al objetivo Windows inicial mediante RDP y transferir los archivos necesarios.

---

## 3. Cargar el plugin de SocksOverRDP

En el primer equipo Windows, extraer los archivos de SocksOverRDP y abrir una consola en el directorio correspondiente.

Registrar el plugin mediante `regsvr32.exe`:

```cmd
regsvr32.exe SocksOverRDP-Plugin.dll
```

Si se registra correctamente, aparecerá un mensaje de confirmación.

El plugin permitirá utilizar el canal virtual de RDP para transportar el tráfico SOCKS.

---

## 4. Establecer la conexión RDP con el host intermedio

Desde el equipo Windows inicial, iniciar una conexión RDP hacia `172.16.5.19` utilizando `mstsc.exe`.

Credenciales del laboratorio:

```text
Usuario: victor
Contraseña: pass@123
Destino: 172.16.5.19
```

Si el plugin está habilitado correctamente, aparecerá un aviso indicando que SocksOverRDP está activo y escuchando en:

```text
127.0.0.1:1080
```

Este puerto será el punto de entrada del proxy SOCKS para el tráfico que se tuneliza mediante RDP.

---

## 5. Iniciar el servidor SocksOverRDP

Transferir al host `172.16.5.19` el archivo `SocksOverRDPx64.zip` o, al menos, el ejecutable:

```text
SocksOverRDP-Server.exe
```

Ejecutar `SocksOverRDP-Server.exe` con privilegios de administrador.

El servidor establecerá el canal necesario para transportar el tráfico a través de la conexión RDP.

### Comprobar que el puerto SOCKS está escuchando

En el equipo Windows con acceso inicial, ejecutar:

```cmd
netstat -antb | findstr 1080
```

Resultado esperado:

```text
TCP    127.0.0.1:1080    0.0.0.0:0    LISTENING
```

La presencia de `LISTENING` confirma que existe un proceso escuchando en el puerto TCP local `1080`.

---

## 6. Configurar Proxifier

En el equipo Windows inicial, transferir y ejecutar la versión portable de Proxifier.

Configurar Proxifier para redirigir el tráfico al proxy SOCKS de SocksOverRDP.

### Configuración del proxy

Añadir un servidor proxy con estos valores:

| Campo | Valor |
|---|---|
| Dirección | `127.0.0.1` |
| Puerto | `1080` |
| Protocolo | SOCKS5 |

Comprobar que la configuración esté activa.

Proxifier permitirá que las aplicaciones seleccionadas envíen su tráfico a través del proxy SOCKS local, que transportará las conexiones por el canal RDP.

---

## 7. Pivotar hacia el objetivo interno

Con SocksOverRDP y Proxifier funcionando, iniciar `mstsc.exe` desde el equipo Windows inicial y conectarse al objetivo interno:

```text
172.16.6.155
```

El tráfico seguirá este recorrido:

```text
Equipo Windows con acceso inicial
              |
              v
         Proxifier
              |
              v
     127.0.0.1:1080
              |
              v
        SocksOverRDP
              |
              v
      Conexión RDP activa
              |
              v
       172.16.5.19
              |
              v
       172.16.6.155:3389
```

De esta forma, podemos utilizar la conexión RDP existente para alcanzar otro equipo de la red interna, incluso cuando no disponemos de SSH para realizar el pivoting.

---

## 8. Mejorar el rendimiento de RDP

Si las sesiones RDP funcionan lentamente, especialmente cuando hay varias abiertas simultáneamente, el material recomienda reducir la calidad de la conexión.

En `mstsc.exe`:

1. Abrir las opciones de conexión.
2. Entrar en la pestaña **Experiencia**.
3. Seleccionar el perfil de rendimiento **Módem (56 kbps)**.

Esta configuración reduce los efectos visuales para mejorar el rendimiento de la sesión.

---

## 9. Solución de problemas

- **No aparece el aviso de SocksOverRDP:** comprobar que el plugin esté registrado y que la conexión RDP se haya establecido correctamente.
- **El puerto `1080` no aparece escuchando:** verificar que SocksOverRDP esté activo y revisar la ejecución del servidor.
- **Proxifier no redirige el tráfico:** comprobar que el proxy SOCKS5 esté configurado como `127.0.0.1:1080` y que las reglas de Proxifier incluyan la aplicación que se desea utilizar.
- **La conexión al objetivo interno falla:** comprobar que el canal RDP siga activo y que el host intermedio pueda alcanzar el destino.
- **El laboratorio no está preparado:** HTB recomienda esperar entre **3 y 5 minutos** después de iniciar el objetivo.

## 11. Conceptos clave para el examen

- **DVC (Dynamic Virtual Channels):** canales virtuales dinámicos de RDP que permiten transportar datos a través de una sesión de Escritorio Remoto.
- **SocksOverRDP:** utiliza los canales virtuales de RDP para tunelizar tráfico SOCKS.
- **Proxifier:** redirige las conexiones de las aplicaciones hacia el proxy configurado.
- **Puerto `1080`:** puerto SOCKS utilizado en el escenario del laboratorio.
- **`regsvr32.exe`:** se utiliza en el ejemplo para registrar el plugin `SocksOverRDP-Plugin.dll`.
- **`SocksOverRDP-Server.exe`:** ejecutable del servidor que debe iniciarse en el host intermedio.
- **Pivoting mediante RDP:** permite alcanzar equipos internos utilizando una conexión RDP existente, sin depender de SSH.
