
## 1. ¿Qué es la tunelización ICMP?

La **tunelización ICMP** permite encapsular tráfico dentro de paquetes ICMP, como las solicitudes y respuestas de eco utilizadas por `ping`.

Puede utilizarse para establecer un túnel cuando la red protegida por un firewall permite las respuestas ICMP. Un host con acceso a un servidor externo puede transportar tráfico dentro de paquetes ICMP y utilizar el túnel para comunicarse con otros servicios.

En esta sección se utiliza **ptunnel-ng** para crear un túnel ICMP entre la máquina de ataque y un host pivote Ubuntu.

### Escenario del laboratorio

|Máquina|Dirección IP|
|---|---|
|Máquina de ataque|`10.10.14.18`|
|Host pivote Ubuntu|`10.129.202.64`|
|Interfaz interna del pivote|`172.16.5.129`|
|Objetivo interno (DC)|`172.16.5.19`|

**Objetivo:** establecer una conexión SSH a través de ICMP y, posteriormente, utilizar `proxychains` para acceder a servicios de la red interna.

---

## 2. Instalar y compilar ptunnel-ng

### Paso 1. Clonar el repositorio

En la máquina de ataque:

```
git clone https://github.com/utoni/ptunnel-ng.git
cd ptunnel-ng
```

### Paso 2. Ejecutar el script de compilación

```
sudo ./autogen.sh
```

Este script prepara y compila el proyecto para poder utilizarlo tanto en el lado cliente como en el servidor.

### Compilación alternativa: binario estático

Si necesitamos generar un binario estático, el material propone instalar las siguientes dependencias:

```
sudo apt install automake autoconf -y
```

Después, desde el directorio `ptunnel-ng`:

```
sed -i '$s/.*/LDFLAGS=-static "${NEW_WD}/configure" --enable-static $@ \&\& make clean \&\& make -j${BUILDJOBS:-4} all/' autogen.sh
```

Ejecutar nuevamente el script:

```
./autogen.sh
```

---

## 3. Transferir ptunnel-ng al host pivote

Desde la máquina de ataque, transferimos el repositorio completo mediante SCP.

La opción `-r` permite copiar directorios de forma recursiva:

```
scp -r ptunnel-ng ubuntu@10.129.202.64:~/
```

Una vez transferido, tendremos el proyecto en el directorio personal del usuario `ubuntu` del host pivote.

---

## 4. Iniciar el servidor ICMP

En el host pivote Ubuntu, entrar en el directorio `src`:

```
cd ~/ptunnel-ng/src
```

Iniciar el servidor:

```
sudo ./ptunnel-ng -r10.129.202.64 -R22
```

### Parámetros

|Parámetro|Función|
|---|---|
|`-r10.129.202.64`|Especifica la dirección del host remoto en el que se acepta la conexión del túnel, según el escenario del laboratorio.|
|`-R22`|Configura el puerto remoto `22`, correspondiente al servicio SSH del ejemplo.|

Salida esperada:

```
[inf]: Starting ptunnel-ng 1.42.
[inf]: Forwarding incoming ping packets over TCP.
[inf]: Ping proxy is listening in privileged mode.
[inf]: Dropping privileges now.
```

El servidor queda preparado para recibir tráfico ICMP y reenviar las conexiones TCP a través del túnel.

---

## 5. Conectar el cliente desde la máquina de ataque

En la máquina de ataque, iniciar el cliente:

```
sudo ./ptunnel-ng -p10.129.202.64 -l2222 -r10.129.202.64 -R22
```

### Parámetros

|Parámetro|Función|
|---|---|
|`-p10.129.202.64`|Especifica la dirección del servidor ptunnel-ng.|
|`-l2222`|Configura el puerto local `2222` para utilizar el túnel.|
|`-r10.129.202.64`|Especifica la dirección remota utilizada en el túnel.|
|`-R22`|Selecciona el puerto remoto `22` del servicio SSH.|

Salida esperada:

```
[inf]: Starting ptunnel-ng 1.42.
[inf]: Relaying packets from incoming TCP streams.
```

El puerto local `2222` permite enviar conexiones TCP a través del túnel ICMP.

---

## 6. Conectarse por SSH a través del túnel ICMP

Con el túnel establecido, podemos conectarnos al servicio SSH del host pivote utilizando el puerto local `2222`.

```
ssh -p2222 -lubuntu 127.0.0.1
```

### Parámetros

- `-p2222`: utiliza el puerto local `2222`.
    
- `-lubuntu`: especifica el usuario remoto `ubuntu`.
    
- `127.0.0.1`: conecta con el extremo local del túnel.
    

Si la configuración es correcta y disponemos de las credenciales, obtendremos una sesión SSH con el host pivote.

**Flujo de conexión:**

```
Máquina de ataque
       |
       v
127.0.0.1:2222
       |
       v
Cliente ptunnel-ng
       |
       | Tráfico encapsulado en ICMP
       v
Servidor ptunnel-ng
       |
       v
10.129.202.64:22 (SSH)
```

---

## 7. Reenvío dinámico de puertos SSH

Una vez que el túnel ICMP funciona, podemos utilizar SSH para crear un proxy SOCKS local. Esto permite enrutar conexiones a través del host pivote.

Ejecutar desde la máquina de ataque:

```
ssh -D 9050 -p2222 -lubuntu 127.0.0.1
```

### Parámetros

|Parámetro|Función|
|---|---|
|`-D 9050`|Crea un proxy SOCKS local en el puerto `9050`.|
|`-p2222`|Utiliza el puerto local del túnel ICMP.|
|`-lubuntu`|Especifica el usuario SSH.|
|`127.0.0.1`|Conecta con el extremo local del túnel.|

La conexión SSH queda establecida a través de ICMP y proporciona un proxy SOCKS para enrutar tráfico hacia las redes accesibles desde el host pivote.

---

## 8. Utilizar Proxychains para acceder a la red interna

Con el proxy SOCKS escuchando en `127.0.0.1:9050`, podemos utilizar `proxychains` para ejecutar herramientas a través del túnel.

### Paso 1. Configurar Proxychains

Editar el archivo de configuración:

```
sudo nano /etc/proxychains.conf
```

Añadir en la sección `[ProxyList]`:

```
socks5 127.0.0.1 9050
```

### Paso 2. Escanear un puerto del controlador de dominio

Ejecutar Nmap a través del proxy:

```
proxychains nmap -sV -sT 172.16.5.19 -p3389
```

### Parámetros de Nmap

|Parámetro|Función|
|---|---|
|`-sV`|Intenta identificar la versión del servicio.|
|`-sT`|Utiliza conexiones TCP completas.|
|`-p3389`|Escanea el puerto `3389`, utilizado habitualmente por RDP.|

En el ejemplo del laboratorio, el resultado muestra:

```
PORT     STATE SERVICE       VERSION
3389/tcp open  ms-wbt-server Microsoft Terminal Services
```

Esto indica que el puerto RDP está abierto y que se identifica el servicio Microsoft Terminal Services.

**Flujo de conexión:**

```
Nmap
  |
  v
Proxychains
  |
  v
127.0.0.1:9050 (SOCKS)
  |
  v
SSH a través de ptunnel-ng
  |
  v
Túnel ICMP
  |
  v
Host pivote Ubuntu
  |
  v
172.16.5.19:3389 (RDP)
```

## 9. Analizar el tráfico con Wireshark

El material recomienda utilizar un analizador de paquetes como Wireshark para comprobar qué tráfico se genera.

### Conexión SSH directa

```
ssh ubuntu@10.129.202.64
```

En una captura de red se observa tráfico TCP y SSHv2.

### Conexión SSH a través del túnel ICMP

```
ssh -p2222 -lubuntu 127.0.0.1
```

En este caso, el tráfico SSH se transporta a través del túnel ICMP.

El análisis de paquetes permite comprobar la diferencia entre una conexión SSH directa y otra que utiliza encapsulación ICMP.

## 10. Solución de problemas

- **El túnel no funciona:** comprueba que el servidor y el cliente ptunnel-ng estén ejecutándose con los parámetros adecuados.
    
- **No se establece la conexión SSH:** verifica que el puerto local `2222` esté configurado y que el servicio SSH remoto esté accesible.
    
- **Proxychains no conecta:** comprueba que el proxy SOCKS esté escuchando en `127.0.0.1:9050` y que `/etc/proxychains.conf` tenga la entrada correcta.
    
- **El binario falla en el objetivo:** comprueba las versiones de `glibc` del sistema de ataque y del objetivo. Prueba una compilación compatible si es necesario.
    
- **El laboratorio no responde:** HTB recomienda esperar entre **3 y 5 minutos** después de iniciar el objetivo para que termine de configurarse.

## 12. Conceptos clave para el examen

- **Tunelización ICMP:** encapsula tráfico dentro de paquetes ICMP.
    
- **ptunnel-ng:** herramienta utilizada para crear el túnel ICMP.
    
- **Puerto local** `**2222**`**:** punto de entrada para conexiones TCP que atraviesan el túnel.
    
- **SSH dinámico (**`**-D 9050**`**):** crea un proxy SOCKS local sobre la conexión SSH.
    
- **Proxychains:** permite ejecutar herramientas como Nmap a través del proxy SOCKS.
    
- **Wireshark:** permite analizar el tráfico y comprobar la diferencia entre SSH directo y SSH transportado mediante ICMP.
    
- `**glibc**`**:** una incompatibilidad entre las versiones del sistema de ataque y el objetivo puede provocar fallos al ejecutar el binario.
