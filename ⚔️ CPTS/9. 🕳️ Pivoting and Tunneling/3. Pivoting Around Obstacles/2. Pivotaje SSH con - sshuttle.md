
## 1. Concepto

`sshuttle` es una herramienta escrita en Python que permite enrutar tráfico hacia una red remota a través de una conexión SSH, sin necesidad de configurar `proxychains`.

Características principales:

- Permite pivotar a través de un servidor SSH.
    
- Redirige el tráfico destinado a las redes especificadas a través del host pivote.
    
- Automatiza la configuración de reglas de firewall mediante `iptables`.
    
- Permite utilizar herramientas como `Nmap` directamente, sin anteponer `proxychains`.
    
- Está diseñado para pivotar mediante SSH; no ofrece el mismo soporte para otros tipos de proxy, como Tor o proxies HTTPS.
    

## 2. Instalar sshuttle

En nuestra máquina de ataque, instalamos la herramienta:

```
sudo apt-get install sshuttle
```

## 3. Crear el túnel SSH y enrutar una red interna

### Escenario

Tenemos acceso por SSH a un servidor Ubuntu que utilizaremos como punto de pivote para alcanzar una red interna.

Ejecutamos:

```
sudo sshuttle -r ubuntu@10.129.202.64 172.16.5.0/23 -v
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`sudo`|Ejecuta la herramienta con privilegios elevados para configurar las reglas de red.|
|`-r`|Especifica el usuario y el host remoto al que conectarse mediante SSH.|
|`ubuntu@10.129.202.64`|Usuario y dirección IP del servidor pivote.|
|`172.16.5.0/23`|Red cuyo tráfico queremos enrutar a través del servidor pivote.|
|`-v`|Activa la salida detallada (_verbose_).|

Al ejecutar el comando, sshuttle solicitará la contraseña del usuario SSH si es necesaria.

Una vez conectado, configurará las reglas de red necesarias para redirigir el tráfico TCP destinado a la red indicada.

### Flujo de conexión

```
Máquina de ataque
       |
       | sshuttle + SSH
       v
Servidor Ubuntu (10.129.202.64)
       |
       v
Red interna (172.16.5.0/23)
       |
       v
Objetivos internos
```

**Importante:** la red `172.16.5.0/23` es la red del ejemplo. En otras prácticas, debemos sustituirla por la red interna que necesitamos alcanzar.

## 4. ¿Qué hace sshuttle internamente?

Durante la conexión, sshuttle configura reglas de firewall para interceptar y redirigir el tráfico destinado a la red indicada.

En la salida detallada podemos encontrar mensajes relacionados con:

- La inicialización del cliente y del servidor remoto.
    
- El establecimiento de la conexión SSH.
    
- La configuración del firewall.
    
- La creación de reglas `iptables` y, cuando corresponda, `ip6tables`.
    
- La redirección del tráfico TCP hacia el proceso local de sshuttle.
    

Por ejemplo, la salida puede mostrar reglas como:

```
iptables -t nat -N sshuttle-12300
iptables -t nat -I OUTPUT 1 -j sshuttle-12300
iptables -t nat -A sshuttle-12300 -j REDIRECT --dest 172.16.5.0/32 -p tcp --to-ports 12300
```

Estas líneas ilustran cómo se crean cadenas y reglas para redirigir tráfico. Los valores concretos pueden variar según la versión, la configuración y el método de firewall utilizado.

## 5. Escanear objetivos internos con Nmap

Una vez que sshuttle está conectado y el tráfico se está redirigiendo correctamente, podemos utilizar Nmap directamente.

Ejemplo: comprobar si el puerto RDP está abierto en `172.16.5.19`.

```
sudo nmap -v -A -sT -p3389 172.16.5.19 -Pn
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`-v`|Muestra información detallada.|
|`-A`|Activa la detección de sistema operativo, versiones, scripts y traceroute cuando corresponda.|
|`-sT`|Realiza un escaneo TCP mediante conexiones completas.|
|`-p3389`|Escanea el puerto TCP 3389, utilizado habitualmente por RDP.|
|`-Pn`|Omite el descubrimiento inicial de hosts y trata el objetivo como activo.|

Salida relevante del ejemplo:

```
PORT     STATE SERVICE
3389/tcp open  ms-wbt-server
```

Esto indica que el puerto TCP `3389` está abierto y que Nmap lo identifica como un servicio de Microsoft Terminal Services.

**La ventaja principal:** no necesitamos ejecutar Nmap con `proxychains`; sshuttle se encarga de enrutar el tráfico de la red configurada.

## 6. Diferencias entre sshuttle y proxychains

|Característica|sshuttle|proxychains|
|---|---|---|
|Funcionamiento|Redirige tráfico mediante SSH y reglas de firewall.|Encadena conexiones de aplicaciones compatibles a través de proxies.|
|Configuración|Define el servidor SSH y las redes que se deben enrutar.|Requiere configurar el proxy o la cadena de proxies.|
|Uso con Nmap|Permite ejecutar Nmap directamente, según el tráfico y las funciones utilizadas.|Su compatibilidad depende del tipo de escaneo y del funcionamiento de la aplicación.|
|Protocolos|Está orientado al pivotaje mediante SSH.|Puede utilizar proxies compatibles configurados en la cadena.|

sudo apt-get install sshuttle

## 8. Puntos clave para el examen

- `sshuttle` permite pivotar hacia una red interna a través de SSH.
    
- `-r` indica el servidor remoto y el usuario SSH.
    
- El CIDR especificado determina qué red se enruta por el pivote.
    
- `-v` muestra información detallada del proceso.
    
- `sudo` permite configurar las reglas de red necesarias en la máquina local.
    
- Una vez establecido el túnel, podemos ejecutar herramientas como Nmap directamente, sin utilizar `proxychains`.
    
- El servidor SSH debe tener conectividad hacia los objetivos internos.
    
- Si no funciona, comprueba las credenciales SSH, la dirección del pivote, la red indicada, la conectividad desde el servidor remoto y las reglas de firewall.
