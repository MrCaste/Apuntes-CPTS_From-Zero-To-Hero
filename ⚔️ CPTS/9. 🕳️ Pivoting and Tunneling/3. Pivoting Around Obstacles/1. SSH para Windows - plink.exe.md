
## 1. Concepto

**Plink (PuTTY Link)** es una herramienta SSH de línea de comandos incluida en el paquete PuTTY para Windows. Permite establecer conexiones SSH y crear túneles para acceder a redes a las que no tenemos acceso directo.

Se puede utilizar para:

- Establecer conexiones SSH desde Windows.
    
- Crear **reenvíos dinámicos de puertos**.
    
- Crear un proxy SOCKS para pivotar hacia otras redes.
    
- Aprovechar herramientas existentes en el sistema (_Living off the Land_) cuando no queremos introducir herramientas adicionales.
    

## 2. Crear un túnel SOCKS con Plink

### Escenario

Tenemos acceso a una máquina Windows que utilizaremos como equipo de ataque. Desde ella queremos conectarnos a un servidor Ubuntu mediante SSH y utilizarlo como punto de pivote para alcanzar otros objetivos internos.

Ejecutamos:

```
plink -ssh -D 9050 ubuntu@10.129.15.50
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`-ssh`|Utiliza el protocolo SSH.|
|`-D 9050`|Crea un reenvío dinámico de puertos y establece un proxy SOCKS local en el puerto `9050`.|
|`ubuntu@10.129.15.50`|Usuario y dirección IP del servidor SSH al que nos conectamos.|

Una vez establecida la conexión SSH, Plink escucha localmente en el puerto `9050` y canaliza el tráfico a través del túnel SSH.

**Flujo de conexión:**

```
Aplicación en Windows
        |
        v
Proxy SOCKS: 127.0.0.1:9050
        |
        v
Túnel SSH creado con Plink
        |
        v
Servidor Ubuntu
        |
        v
Objetivos de la red interna
```

> **Importante:** El puerto `9050` corresponde al proxy SOCKS local de Plink, no a un servicio del objetivo interno.

## 3. Configurar Proxifier

**Proxifier** es una herramienta para Windows que permite redirigir las conexiones de aplicaciones a través de proxies SOCKS o HTTPS. También permite encadenar proxies.

Podemos utilizarlo para que aplicaciones de Windows, que normalmente no admiten proxies SOCKS directamente, aprovechen el túnel creado con Plink.

### Configuración del proxy

En Proxifier, añadimos un servidor proxy con estos valores:

|Campo|Valor|
|---|---|
|Address / Dirección|`127.0.0.1`|
|Port / Puerto|`9050`|
|Protocol / Protocolo|`SOCKS4`, según el ejemplo del módulo|

`127.0.0.1:9050` representa el proxy SOCKS local creado por Plink.

Una vez configurado, Proxifier permite dirigir las conexiones de las aplicaciones seleccionadas a través del túnel.

## 4. Acceder a un objetivo mediante RDP

Con Plink conectado y Proxifier configurado, podemos iniciar el cliente de Escritorio remoto de Windows:

```
mstsc.exe
```

Después, introducimos la dirección del objetivo Windows que queremos alcanzar mediante RDP.

El flujo de tráfico será:

```
mstsc.exe
    |
    v
Proxifier
    |
    v
Proxy SOCKS local: 127.0.0.1:9050
    |
    v
Túnel SSH de Plink
    |
    v
Servidor Ubuntu
    |
    v
Objetivo Windows (RDP)
```

El acceso depende de que el túnel funcione, el enrutamiento permita alcanzar el objetivo y el servicio RDP esté disponible.

## 5. Conceptos clave para el examen

- **Plink** es la versión de línea de comandos de PuTTY para conexiones como SSH en Windows.
    
- `-D 9050` crea un proxy SOCKS local a través de SSH.
    
- El proxy local permite canalizar tráfico hacia redes accesibles desde el servidor SSH.
    
- **Proxifier** permite utilizar el proxy con aplicaciones de Windows que no admiten SOCKS directamente.
    
- `mstsc.exe` es el cliente de Escritorio remoto de Windows.
    
- Este procedimiento permite utilizar una máquina Windows como equipo de ataque sin depender exclusivamente de herramientas de Linux.
    
- La técnica es especialmente útil cuando interesa aprovechar herramientas existentes en el sistema (_Living off the Land_).
