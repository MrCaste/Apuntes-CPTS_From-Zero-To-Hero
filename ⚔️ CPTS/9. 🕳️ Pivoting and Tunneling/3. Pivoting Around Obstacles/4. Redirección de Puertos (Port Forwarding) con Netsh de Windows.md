
## 1. Concepto

`netsh.exe` es una herramienta de línea de comandos de Windows que permite administrar y configurar diferentes aspectos de la red.

Entre sus funciones encontramos:

- Consultar rutas de red.
    
- Consultar la configuración del firewall.
    
- Configurar determinados parámetros de red.
    
- Crear reglas de redirección de puertos (_port forwarding_).
    

Durante un pentest, podemos utilizar `netsh` en una máquina Windows comprometida que tenga acceso a una red interna. Así, nuestro equipo de ataque puede alcanzar servicios internos a través de esa máquina pivote.

## 2. Escenario de pivotaje

Tenemos una estación de trabajo Windows con dos interfaces de red:

- Interfaz externa: `10.129.15.150`
    
- Interfaz interna: `172.16.5.19`
    

Queremos acceder mediante RDP a un servidor Windows interno en `172.16.5.25:3389`.

Para ello, configuramos una regla que redirige las conexiones recibidas en el puerto `8080` de la máquina pivote hacia el puerto `3389` del servidor interno.

```
Máquina de ataque
       |
       | Conexión al puerto 8080
       v
Windows pivote
10.129.15.150:8080
       |
       | Redirección mediante netsh
       v
Windows interno
172.16.5.25:3389 (RDP)
```

## 3. Crear una regla de redirección de puertos

En una consola de Windows con los privilegios necesarios, ejecutamos:

```
netsh.exe interface portproxy add v4tov4 listenport=8080 listenaddress=10.129.15.150 connectport=3389 connectaddress=172.16.5.25
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`interface portproxy`|Administra las reglas de redirección de puertos.|
|`add`|Añade una regla nueva.|
|`v4tov4`|Redirige tráfico de una dirección IPv4 a otra dirección IPv4.|
|`listenport=8080`|Puerto en el que se reciben las conexiones.|
|`listenaddress=10.129.15.150`|Dirección IPv4 local en la que se escucha.|
|`connectport=3389`|Puerto de destino al que se reenvía el tráfico.|
|`connectaddress=172.16.5.25`|Dirección IPv4 del servidor interno de destino.|

**Resultado:** las conexiones recibidas en `10.129.15.150:8080` se redirigen a `172.16.5.25:3389`.

## 4. Verificar la regla configurada

Para comprobar que la regla se ha creado correctamente:

```
netsh.exe interface portproxy show v4tov4
```

Salida de ejemplo:

```
Listen on ipv4:             Connect to ipv4:

Address         Port        Address         Port
--------------- ----------  --------------- ----------
10.129.15.150   8080        172.16.5.25     3389
```

Esta salida confirma la dirección y el puerto de escucha, así como la dirección y el puerto de destino.

## 5. Conectarse al servicio interno desde Linux

Una vez configurada la redirección, desde nuestra máquina de ataque podemos utilizar un cliente RDP para conectarnos al puerto `8080` de la máquina pivote.

Ejemplo:

```
xfreerdp /v:10.129.15.150:8080 /u:victor /p:'pass@123'
```

En este ejemplo:

|Parámetro|Descripción|
|---|---|
|`/v:10.129.15.150:8080`|Dirección y puerto de la máquina pivote.|
|`/u:victor`|Usuario de Windows utilizado para la conexión RDP.|
|`/p:'pass@123'`|Contraseña del usuario.|

Las credenciales son ilustrativas y corresponden al ejemplo del módulo. En una práctica real, utiliza las credenciales proporcionadas para el laboratorio.

El flujo de conexión será:

```
xfreerdp
    |
    v
10.129.15.150:8080
    |
    v
Regla portproxy de netsh
    |
    v
172.16.5.25:3389
```

## 6. Comandos importantes

### Añadir una regla de redirección

```
netsh interface portproxy add v4tov4 listenport=8080 listenaddress=10.129.15.150 connectport=3389 connectaddress=172.16.5.25
```

### Mostrar las reglas IPv4 a IPv4

```
netsh interface portproxy show v4tov4
```

### Eliminar la regla del ejemplo

```
netsh interface portproxy delete v4tov4 listenport=8080 listenaddress=10.129.15.150
```

El último comando elimina la regla identificada por la dirección y el puerto de escucha indicados.

## 7. Puntos clave para el examen

- `netsh` permite configurar reglas de redirección de puertos en Windows.
    
- `portproxy` se utiliza para reenviar conexiones desde un puerto local hacia otro host y puerto.
    
- `v4tov4` indica una redirección entre direcciones IPv4.
    
- `listenaddress` y `listenport` identifican dónde se reciben las conexiones.
    
- `connectaddress` y `connectport` identifican el destino al que se reenvía el tráfico.
    
- `show v4tov4` permite comprobar las reglas existentes.
    
- Una vez configurada la regla, el atacante se conecta al puerto de escucha de la máquina pivote, no directamente al servicio interno.
    
- La máquina pivote debe poder alcanzar el servicio de destino.
    
- La configuración requiere privilegios suficientes y una configuración de red compatible.
    

### Esquema para recordar

```
1. Identificar la máquina pivote y el servicio interno.
2. Crear la regla portproxy con netsh.
3. Verificar la regla con show v4tov4.
4. Conectarse al puerto de escucha desde la máquina de ataque.
5. Comprobar que el tráfico llega al servicio interno.
```
