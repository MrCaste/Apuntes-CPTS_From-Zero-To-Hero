
## 1. ¿Qué es HTTP Verb Tampering?

La manipulación de verbos HTTP consiste en aprovechar configuraciones inseguras del servidor web o errores en el código de la aplicación para **evadir controles de seguridad modificando el método HTTP de una petición**.

Aunque los métodos más habituales son `GET` y `POST`, HTTP admite otros métodos que pueden permitir acceder a funcionalidades no previstas si no se gestionan correctamente.

## 2. Métodos HTTP importantes

|Método|Descripción|
|---|---|
|`GET`|Solicita un recurso al servidor.|
|`POST`|Envía datos al servidor.|
|`HEAD`|Similar a `GET`, pero devuelve únicamente las cabeceras, sin el cuerpo de la respuesta.|
|`PUT`|Escribe el contenido de una petición en la ubicación especificada.|
|`DELETE`|Elimina el recurso de la ubicación especificada.|
|`OPTIONS`|Permite consultar las opciones y los métodos HTTP aceptados por el servidor.|
|`PATCH`|Aplica modificaciones parciales a un recurso.|

**Riesgo:** si el servidor permite métodos como `PUT` o `DELETE` sin las restricciones adecuadas, podrían utilizarse para modificar o eliminar recursos del servidor.

## 3. Tipos de vulnerabilidades

### A. Configuración insegura del servidor web

Puede ocurrir cuando la autenticación se aplica únicamente a determinados métodos HTTP, dejando otros métodos sin protección.

Ejemplo de configuración Apache:

```
<Limit GET POST>
    Require valid-user
</Limit>
```

Esta configuración exige autenticación para las peticiones `GET` y `POST`, pero no aplica esa misma restricción a los demás métodos.

**Posible explotación:**

1. Identificar una página protegida.
    
2. Comprobar qué métodos HTTP acepta.
    
3. Probar métodos alternativos, como `HEAD`.
    
4. Verificar si alguno permite acceder al recurso sin autenticación.
    

Si el control de autenticación se limita a ciertos métodos, podría producirse un **authentication bypass**.

### B. Codificación insegura de la aplicación

También puede producirse cuando los desarrolladores aplican filtros de seguridad a un método HTTP, pero utilizan los datos de otro método al ejecutar la operación.

Ejemplo en PHP:

```
$pattern = "/^[A-Za-z\s]+$/";

if(preg_match($pattern, $_GET["code"])) {
    $query = "Select * from ports where port_code like '%" . $_REQUEST["code"] . "%'";
    ...SNIP...
}
```

**Problema:**

- `$_GET["code"]` se utiliza para validar la entrada.
    
- `$_REQUEST["code"]` se utiliza para construir la consulta SQL.
    
- `$_REQUEST` puede incluir parámetros procedentes de `GET` y `POST`, según la configuración de PHP.
    

Esto provoca una inconsistencia: la aplicación valida un parámetro, pero puede utilizar otro valor al ejecutar la consulta.

**Posible explotación:**

1. Enviar una petición `POST` con el parámetro `code`.
    
2. Dejar vacío o controlar por separado el parámetro `GET` que se valida.
    
3. Comprobar si la aplicación procesa el valor de `POST` sin aplicar el filtro esperado.
    
4. Verificar si es posible eludir la protección contra SQL Injection.
    

La vulnerabilidad no se debe simplemente a utilizar `POST`, sino a la **falta de coherencia entre los datos validados y los datos utilizados**.

## 4. Diferencias entre ambos tipos

|Tipo|Causa|Posible consecuencia|
|---|---|---|
|Configuración insegura|La autenticación solo se aplica a determinados métodos HTTP.|Evasión de autenticación.|
|Codificación insegura|Los filtros no se aplican de forma coherente a todos los métodos o parámetros utilizados.|Evasión de filtros y posible explotación de otras vulnerabilidades, como SQL Injection.|

## 5. Checklist para HTB

Ante una posible vulnerabilidad de HTTP Verb Tampering:

1. Identificar el recurso que queremos analizar.
    
2. Probar los métodos HTTP habituales: `GET`, `POST`, `HEAD` y `OPTIONS`.
    
3. Comparar las respuestas y los códigos de estado.
    
4. Comprobar si los controles de autenticación dependen del método utilizado.
    
5. Revisar si los filtros de entrada se aplican de forma consistente a los parámetros `GET` y `POST`.
    
6. Verificar si la aplicación utiliza los mismos datos que valida.
    
7. Confirmar si un método alternativo permite acceder a una funcionalidad protegida o eludir un filtro.
    

### Concepto clave

**HTTP Verb Tampering aprovecha las diferencias en el tratamiento de los métodos HTTP para intentar eludir controles de seguridad.** Hay que distinguir entre una configuración insegura del servidor y un error en la validación de los datos de la aplicación.
