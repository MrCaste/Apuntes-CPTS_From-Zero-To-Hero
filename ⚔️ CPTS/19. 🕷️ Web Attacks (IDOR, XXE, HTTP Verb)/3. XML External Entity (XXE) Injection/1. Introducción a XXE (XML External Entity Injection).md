
## 1. ¿Qué es XXE?

**XXE (XML External Entity)** es una vulnerabilidad que aparece cuando una aplicación procesa datos XML controlados por el usuario sin analizarlos de forma segura.

Puede permitir:

- **Lectura de archivos locales** del servidor.
    
- Divulgación de información sensible.
    
- Acceso a recursos externos mediante solicitudes del servidor.
    
- Otras acciones maliciosas, dependiendo de la configuración del analizador XML.
    

El problema aparece cuando el analizador XML permite definir y resolver entidades externas controladas por el usuario.

## 2. Estructura de XML

XML es un lenguaje de marcado utilizado para almacenar y transferir datos estructurados.

Ejemplo:

```
<?xml version="1.0" encoding="UTF-8"?>
<email>
    <sender>john@inlanefreight.com</sender>
    <recipients>
        <to>HR@inlanefreight.com</to>
    </recipients>
    <body>Hello</body>
</email>
```

### Elementos importantes

|Concepto|Descripción|Ejemplo|
|---|---|---|
|**Tag**|Etiqueta que define un elemento.|`<sender>`|
|**Entity**|Referencia a un valor que el analizador sustituye.|`&company;`|
|**Element**|Etiqueta de apertura, contenido y etiqueta de cierre.|`<sender>john@example.com</sender>`|
|**Attribute**|Información adicional dentro de una etiqueta.|`encoding="UTF-8"`|
|**Declaration**|Define la versión XML y la codificación.|`<?xml version="1.0" encoding="UTF-8"?>`|

### Caracteres especiales

En XML, algunos caracteres deben representarse mediante referencias de entidad:

|Carácter|Referencia|
|---|---|
|`<`|`&lt;`|
|`>`|`&gt;`|
|`&`|`&amp;`|
|`"`|`&quot;`|

Los comentarios se escriben así:

```
<!-- Comentario XML -->
```

## 3. XML DTD

Un **DTD (Document Type Definition)** define la estructura que debe cumplir un documento XML.

Ejemplo:

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ELEMENT email (sender, body)>
    <!ELEMENT sender (#PCDATA)>
    <!ELEMENT body (#PCDATA)>
]>
<email>
    <sender>john@example.com</sender>
    <body>Hello</body>
</email>
```

Conceptos importantes:

- `DOCTYPE`: declara el tipo de documento.
    
- `ELEMENT`: declara un elemento y su estructura.
    
- `#PCDATA`: indica contenido de texto analizable.
    

Un DTD puede definirse dentro del documento XML o cargarse desde un archivo externo.

### DTD externo

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email SYSTEM "email.dtd">
```

También puede apuntar a una URL:

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email SYSTEM "http://inlanefreight.com/email.dtd">
```

La palabra clave `SYSTEM` permite hacer referencia a un recurso externo.

## 4. Entidades XML

Las entidades funcionan como variables: cuando el analizador encuentra una referencia, la sustituye por su valor.

### Entidad interna

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY company "Inlane Freight">
]>
<email>
    <sender>&company;</sender>
</email>
```

El analizador sustituye `&company;` por `Inlane Freight`.

### Entidades externas

Una entidad externa obtiene su valor de un recurso externo mediante `SYSTEM`.

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY company SYSTEM "http://localhost/company.txt">
    <!ENTITY signature SYSTEM "file:///var/www/html/signature.txt">
]>
<email>
    <sender>&company;</sender>
    <body>&signature;</body>
</email>
```

Si el analizador permite resolver estas entidades, intentará obtener su contenido desde las rutas indicadas y sustituir las referencias por los valores obtenidos.

Esto es peligroso cuando el usuario puede controlar el XML y el servidor permite resolver entidades externas.

### `SYSTEM` frente a `PUBLIC`

- `**SYSTEM**`: referencia un recurso externo mediante una ruta o URL.
    
- `**PUBLIC**`: permite identificar recursos externos mediante un identificador público, junto con la información necesaria para localizarlos.
    

En este módulo se utiliza principalmente `SYSTEM`.

## 5. Flujo básico de una vulnerabilidad XXE

1. La aplicación recibe datos XML controlados por el usuario.
    
2. El servidor procesa el XML mediante un analizador.
    
3. El documento define una entidad externa.
    
4. El analizador resuelve la entidad si tiene permitido hacerlo.
    
5. El contenido obtenido puede quedar incluido en el documento procesado.
    
6. Si la aplicación devuelve ese contenido, puede producirse una divulgación de información.
    

**Condición clave:** definir una entidad externa no implica automáticamente que exista una vulnerabilidad explotable. Depende de cómo esté configurado el analizador XML y de cómo la aplicación procese y devuelva los datos.

## 6. Chuleta para el laboratorio

|Elemento|Qué debes recordar|
|---|---|
|XXE|Inyección de entidades externas en XML.|
|DTD|Define la estructura del documento XML y puede declarar entidades.|
|`DOCTYPE`|Declara el tipo de documento.|
|`ENTITY`|Declara una entidad XML.|
|`SYSTEM`|Permite referenciar un recurso externo.|
|`&nombre;`|Hace referencia a una entidad definida.|
|`file://`|Puede utilizarse para referenciar archivos locales si el analizador lo permite.|
|`http://`|Puede utilizarse para referenciar recursos HTTP externos si el analizador lo permite.|

### Idea principal

Para identificar una posible XXE, busca funcionalidades que acepten XML —por ejemplo, API SOAP o formularios que procesen documentos XML— y comprueba si el analizador permite resolver entidades externas.
