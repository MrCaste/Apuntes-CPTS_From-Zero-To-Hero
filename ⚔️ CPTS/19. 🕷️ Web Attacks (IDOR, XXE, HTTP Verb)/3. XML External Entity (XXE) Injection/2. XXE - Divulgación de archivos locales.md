
## 1. Identificación de XXE

Una vulnerabilidad **XXE (XML External Entity)** aparece cuando una aplicación procesa XML controlado por el usuario y permite resolver entidades externas de forma insegura.

### Pasos para identificarla

1. Busca formularios o endpoints que acepten datos XML.
    
2. Intercepta la petición con **Burp Suite**.
    
3. Identifica los elementos XML que aparecen reflejados en la respuesta.
    
4. Define una entidad interna y comprueba si se sustituye por su valor.
    
5. Si funciona, prueba una entidad externa en un laboratorio autorizado.
    

Ejemplo de petición XML:

```
<?xml version="1.0" encoding="UTF-8"?>
<root>
    <name>Test</name>
    <tel>123456789</tel>
    <email>email@xxe.htb</email>
    <message>Hello</message>
</root>
```

En el laboratorio, la petición se envía a:

```
POST /submitDetails.php HTTP/1.1
Content-Type: application/xml
```

Si la respuesta contiene el valor del elemento `<email>`, sabemos que ese campo puede servir para comprobar si el contenido de una entidad se refleja.

### Comprobar la inyección de entidades internas

Añade un DTD al principio del documento XML, después de la declaración XML:

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY company "Inlane Freight">
]>
<root>
    <name>Test</name>
    <tel>123456789</tel>
    <email>&company;</email>
    <message>Hello</message>
</root>
```

Si la respuesta muestra `Inlane Freight` en lugar de `&company;`, el analizador está procesando la entidad definida.

**Importante:** esto demuestra que se procesan entidades internas, pero todavía hay que comprobar si se permite resolver entidades externas.

Si el XML ya contiene un `DOCTYPE`, no debes añadir otro: incorpora la declaración `ENTITY` al DTD existente.

## 2. Lectura de archivos locales

Si el analizador permite resolver entidades externas, podemos intentar leer archivos accesibles desde el servidor.

### Payload XXE

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY company SYSTEM "file:///etc/passwd">
]>
<root>
    <name>Test</name>
    <tel>123456789</tel>
    <email>&company;</email>
    <message>Hello</message>
</root>
```

**Funcionamiento:**

- `DOCTYPE` declara el tipo de documento.
    
- `ENTITY` define una entidad externa llamada `company`.
    
- `SYSTEM` indica el recurso externo.
    
- `file:///etc/passwd` referencia un archivo local.
    
- `&company;` solicita sustituir la referencia por el contenido de la entidad.
    

Si la aplicación devuelve el contenido de `/etc/passwd`, se confirma la divulgación de archivos locales mediante XXE.

### Archivos que pueden resultar interesantes

Durante una auditoría autorizada, comprueba si puedes acceder a:

- Archivos del sistema con información de usuarios.
    
- Archivos de configuración de la aplicación.
    
- Archivos que contengan credenciales.
    
- Claves SSH, como `id_rsa`, si tienes una ruta conocida y permisos de lectura.
    

El acceso depende de los permisos del proceso del servidor y de las restricciones del analizador XML.

**Caso especial:** algunas aplicaciones Java pueden permitir obtener listados de directorios mediante determinadas referencias externas, aunque no es un comportamiento universal.

## 3. Lectura del código fuente mediante PHP

Intentar leer directamente un archivo PHP puede fallar porque su contenido contiene caracteres que no encajan con el formato XML esperado.

Para resolverlo, PHP proporciona el wrapper `php://filter`, que permite codificar el contenido del archivo en Base64.

### Payload

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY company SYSTEM "php://filter/convert.base64-encode/resource=index.php">
]>
<root>
    <name>Test</name>
    <tel>123456789</tel>
    <email>&company;</email>
    <message>Hello</message>
</root>
```

Si la aplicación devuelve la entidad, la respuesta puede contener el código fuente de `index.php` codificado en Base64.

### Decodificar el contenido

Copia la cadena Base64 y decodifícala en tu terminal:

```
echo 'CADENA_BASE64' | base64 -d
```

También puedes utilizar el **Inspector de Burp Suite** para examinar y decodificar el contenido.

### ¿Por qué funciona?

1. El wrapper `php://filter/` permite aplicar filtros al recurso.
    
2. `convert.base64-encode` codifica el contenido en Base64.
    
3. `resource=index.php` identifica el archivo que se intenta leer.
    
4. El contenido codificado evita que caracteres especiales del código fuente rompan la estructura XML.
    

**Limitación:** esta técnica depende de PHP y de que la aplicación permita utilizar el wrapper y resolver la entidad.

## 4. Posible ejecución remota de comandos (RCE)

En determinadas configuraciones, una XXE puede llegar a permitir ejecución remota de comandos.

El contenido del módulo presenta dos posibilidades:

- Buscar archivos sensibles, como claves SSH, que puedan facilitar el acceso al servidor.
    
- Utilizar `expect://` en aplicaciones PHP que tengan instalado y habilitado el módulo `expect`.
    

El wrapper `expect://` **no está disponible por defecto en muchos servidores PHP modernos**, por lo que no debe asumirse que funcionará.

El material también describe una cadena de explotación en la que se descarga una web shell PHP desde un servidor controlado por el auditor y después se interactúa con ella. Su viabilidad depende de los wrappers disponibles, los permisos, la conectividad y la configuración del servidor.

Para el examen, recuerda que **XXE no implica automáticamente RCE**: la lectura de archivos suele ser un impacto más directamente asociado a esta vulnerabilidad.

## 5. Otros ataques posibles mediante XXE

### SSRF (Server-Side Request Forgery)

Si el servidor resuelve entidades externas mediante HTTP, puede ser posible inducirlo a realizar solicitudes a otros recursos.

Según la configuración, esto puede permitir:

- Enumerar servicios accesibles desde el servidor.
    
- Acceder a interfaces web internas.
    
- Intentar alcanzar recursos no accesibles directamente desde el exterior.
    

Este comportamiento corresponde a una posible cadena XXE → SSRF.

### Denegación de servicio (DoS)

Un ataque conocido consiste en definir entidades que se expanden repetidamente unas dentro de otras.

Ejemplo conceptual:

```
<!DOCTYPE email [
    <!ENTITY a0 "DOS">
    <!ENTITY a1 "&a0;&a0;&a0;&a0;">
    <!ENTITY a2 "&a1;&a1;&a1;&a1;">
]>
```

Cada entidad puede multiplicar el contenido de la anterior, provocando un consumo excesivo de memoria o recursos.

Esta técnica se conoce como **expansión de entidades**. Los analizadores modernos suelen implementar protecciones contra estas expansiones, por lo que su efectividad depende de la implementación y de sus límites de seguridad.

No es necesario enviar cargas de expansión masiva fuera de un entorno de pruebas controlado.

## 6. Flujo de explotación para el laboratorio

|Paso|Acción|Resultado esperado|
|---|---|---|
|1|Identificar un endpoint que acepte XML.|Localizar una entrada XML controlable.|
|2|Interceptar la petición con Burp.|Identificar los campos XML y la respuesta.|
|3|Inyectar una entidad interna.|Comprobar si el analizador procesa entidades.|
|4|Definir una entidad externa con `SYSTEM`.|Comprobar si permite resolver recursos externos.|
|5|Referenciar la entidad en un campo reflejado.|Intentar obtener el contenido en la respuesta.|
|6|Si el archivo no se muestra correctamente, evaluar Base64.|Evitar problemas con caracteres especiales del contenido.|
|7|Analizar el impacto y los límites.|Determinar qué información puede exponerse realmente.|

## 7. Chuleta rápida

|Payload o concepto|Utilidad|
|---|---|
|`<!DOCTYPE email [...]>`|Declarar un DTD interno.|
|`<!ENTITY company "valor">`|Definir una entidad interna.|
|`<!ENTITY company SYSTEM "file:///etc/passwd">`|Referenciar un archivo local mediante una entidad externa.|
|`&company;`|Referenciar la entidad definida.|
|`php://filter/convert.base64-encode/resource=index.php`|Intentar leer código fuente PHP codificado en Base64.|
|`expect://`|Posible ejecución de comandos en determinadas configuraciones PHP.|
|Entidades anidadas|Posible consumo excesivo de recursos.|
|Entidades HTTP externas|Posible cadena XXE → SSRF.|

### Ideas clave para el examen

- **Primero identifica si la aplicación acepta XML** y qué campos se reflejan en la respuesta.
    
- Una entidad interna permite comprobar si el analizador procesa las declaraciones del DTD.
    
- `SYSTEM` permite declarar una referencia externa; `file://` puede utilizarse para leer archivos locales.
    
- Si el contenido de un archivo rompe el formato XML, en PHP puede ser útil el wrapper `php://filter` con Base64.
    
- La divulgación de archivos puede revelar código fuente, credenciales o claves que faciliten otros ataques.
    
- XXE también puede utilizarse como punto de partida para SSRF o, en configuraciones concretas, RCE.
    
- El impacto real depende de la configuración del analizador XML, los wrappers disponibles y los permisos del proceso del servidor.
