
## 1. Tipos de protección

Las aplicaciones web pueden implementar distintas medidas para prevenir las inyecciones de comandos:

- **Listas negras (**_**blacklists**_**):** bloquean caracteres o palabras que se consideran peligrosos.
    
- **WAF (**_**Web Application Firewall**_**):** inspecciona las peticiones y puede bloquear inyecciones de comandos, SQLi, XSS y otros ataques.
    
- **Validaciones del backend:** la propia aplicación comprueba los datos recibidos y rechaza las entradas que considera inválidas.
    

Aunque existan estas medidas, una aplicación puede seguir siendo vulnerable si está mal diseñada o implementada.

## 2. Identificar un filtro o WAF

En el ejercicio de Host Checker, el payload utilizado anteriormente:

```
127.0.0.1; whoami
```

devuelve el mensaje `Invalid input`.

Esto indica que algún mecanismo de seguridad ha bloqueado la petición.

### Diferenciar el origen del bloqueo

- **Error dentro de la propia aplicación:** puede indicar que la validación del backend ha detectado el payload. En el ejercicio, el mensaje aparece en el campo de salida del Host Checker.
    
- **Página de error diferente:** si muestra información como la IP del cliente o detalles de la petición, podría indicar que el bloqueo procede de un WAF.
    

Estas señales son indicios, no una confirmación absoluta del mecanismo que ha bloqueado la petición.

## 3. Identificar el elemento bloqueado

El payload contiene tres elementos que pueden activar el filtro:

|Elemento|Ejemplo|Posible motivo del bloqueo|
|---|---|---|
|Dirección IP|`127.0.0.1`|En este ejercicio, funciona correctamente.|
|Punto y coma|`;`|Puede estar incluido en la lista negra.|
|Espacio||Puede estar bloqueado por el filtro.|
|Comando|`whoami`|Puede estar incluido en una lista de comandos prohibidos.|

**Objetivo:** determinar qué elemento provoca el rechazo antes de intentar evadir el filtro.

## 4. Identificar caracteres en una lista negra

Una aplicación puede comprobar si la entrada contiene caracteres prohibidos mediante código PHP similar al siguiente:

```
$blacklist = ['&', '|', ';', ...];

foreach ($blacklist as $character) {
    if (strpos($_POST['ip'], $character) !== false) {
        echo "Invalid input";
    }
}
```

El funcionamiento es el siguiente:

1. Se define una lista de caracteres prohibidos.
    
2. Se recorre la lista.
    
3. Se comprueba si cada carácter aparece en la entrada del usuario.
    
4. Si se encuentra uno, la aplicación muestra `Invalid input`.
    

Este ejemplo ilustra un filtro basado en caracteres; no demuestra que el código real del ejercicio sea exactamente ese.

## 5. Comprobar qué carácter está bloqueado

El método consiste en **reducir el payload y añadir un elemento cada vez**, comprobando cuándo aparece el error.

### Paso 1: comprobar la entrada válida

```
127.0.0.1
```

La dirección IP funciona correctamente.

### Paso 2: añadir únicamente el punto y coma

```
127.0.0.1;
```

La aplicación devuelve:

```
Invalid input
```

**Conclusión:** el punto y coma `;` está bloqueado por el filtro del ejercicio.

### Paso 3: continuar con otros operadores

Comprobar individualmente los operadores de inyección estudiados anteriormente, registrando cuáles son aceptados y cuáles rechazados.

No se debe asumir que todos están bloqueados: hay que comprobar cada uno.

## Checklist para el laboratorio

- Enviar primero una entrada válida.
    
- Probar el payload de inyección completo.
    
- Identificar el mensaje o comportamiento que indica el bloqueo.
    
- Reducir el payload a un solo elemento adicional.
    
- Comprobar los caracteres y operadores individualmente.
    
- Registrar qué elementos son aceptados y cuáles rechazados.
    
- Determinar si las señales apuntan a una validación del backend o a un posible WAF.
    

**Idea clave:** antes de intentar evadir un filtro, identifica qué parte de la entrada está provocando el bloqueo.
