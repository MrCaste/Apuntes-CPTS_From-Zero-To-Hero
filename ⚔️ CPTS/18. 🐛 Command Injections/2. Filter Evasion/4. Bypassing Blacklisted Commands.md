
## 1. Introducción

Hasta ahora hemos aprendido a evadir filtros de caracteres, como los que bloquean espacios o puntos y coma. Sin embargo, una aplicación también puede utilizar una **lista negra de comandos** (_command blacklist_).

Este filtro comprueba si la entrada contiene palabras o comandos prohibidos, por ejemplo:

- `whoami`
    
- `cat`
    

Una posible forma de evadir este tipo de filtro consiste en **ofuscar el comando**, modificando su representación sin cambiar el resultado que interpreta el shell.

## 2. Identificar una lista negra de comandos

En el laboratorio, el payload funcionaba después de evadir los filtros de caracteres, pero vuelve a ser bloqueado al añadir `whoami`.

Esto indica que puede existir un filtro adicional que detecta comandos prohibidos.

Un ejemplo simplificado de este mecanismo en PHP sería:

```
$blacklist = ['whoami', 'cat', ...];

foreach ($blacklist as $word) {
    if (strpos($_POST['ip'], $word) !== false) {
        echo "Invalid input";
    }
}
```

El código comprueba si la entrada contiene alguna de las palabras incluidas en la lista negra.

Si el filtro busca las cadenas literales, puede ser posible modificar la representación del comando para que el shell lo interprete de la misma forma, pero el filtro no encuentre la palabra original.

## 3. Linux y Windows: ofuscación mediante comillas

Una técnica consiste en insertar comillas simples o dobles entre los caracteres de un comando.

### 3.1. Comillas simples

Comando original:

```
whoami
```

Comando ofuscado:

```
w'h'o'am'i
```

En los shells compatibles, las comillas se interpretan y el comando termina ejecutándose como `whoami`.

Ejemplo de payload del laboratorio:

```
127.0.0.1%0aw'h'o'am'i
```

### 3.2. Comillas dobles

También podemos utilizar comillas dobles:

```
w"h"o"am"i
```

El resultado es equivalente a ejecutar `whoami`.

### Consideraciones importantes

- No mezcles comillas simples y dobles en una misma ofuscación de este tipo.
    
- El número de comillas debe ser par para que queden correctamente emparejadas.
    
- El comportamiento depende del shell y del contexto en el que se interprete el comando.
    

**Idea clave:** las comillas pueden cambiar la representación textual de un comando sin cambiar necesariamente el resultado de su interpretación.

## 4. Linux: utilizar `\` y `$@`

En Bash existen otros caracteres y construcciones que pueden utilizarse para ofuscar comandos.

### 4.1. Barra invertida `\`

Ejemplo:

```
w\ho\am\i
```

Bash interpreta las barras invertidas como caracteres de escape y, en este contexto, elimina su efecto especial antes de ejecutar el comando.

El resultado es equivalente a:

```
whoami
```

### 4.2. Parámetro posicional `$@`

Otra posibilidad es insertar `$@` entre partes del comando:

```
who$@ami
```

En el contexto del ejemplo, la expansión permite que el comando resultante sea equivalente a `whoami`.

**Importante:** el resultado depende del contexto de ejecución y de los parámetros posicionales disponibles.

Estas técnicas son específicas de shells compatibles con la sintaxis utilizada, por lo que no deben extrapolarse automáticamente a todos los intérpretes.

## 5. Windows: utilizar el carácter `^`

En Windows CMD podemos utilizar el carácter circunflejo o _caret_ (`^`) para dividir visualmente un comando.

Ejemplo:

```
who^ami
```

CMD interpreta el carácter `^` como un carácter de escape en este contexto y ejecuta el comando equivalente a:

```
whoami
```

Esta técnica es específica de CMD y no debe asumirse que funciona igual en PowerShell.

## 6. Tabla resumen

|Técnica|Sistema|Ejemplo|Objetivo|

|Comillas simples|Linux y Windows, según el shell|`w'h'o'am'i`|Ofuscar la representación del comando.|
|Comillas dobles|Linux y Windows, según el shell|`w"h"o"am"i`|Ofuscar la representación del comando.|

## 7. Procedimiento para el laboratorio

1. Comprueba que la inyección de comandos funciona con un comando permitido.
    
2. Añade el comando que quieres probar y observa si aparece `Invalid input`.
    
3. Si se bloquea, considera que puede existir una lista negra de comandos.
    
4. Prueba las técnicas de ofuscación compatibles con el sistema operativo y el shell.
    
5. Comprueba si la petición es aceptada.
    
6. Verifica la salida para confirmar que el comando se ha ejecutado realmente.
    
7. Si la técnica falla, revisa si alguno de los caracteres utilizados también está bloqueado.
    

## Chuleta para el examen

- **Lista negra de comandos:** bloquea palabras o comandos específicos.
    
- **Ofuscación:** modifica la representación textual de un comando sin cambiar necesariamente su interpretación.
    
- **Comillas:** pueden dividir visualmente un comando en partes.
    
- **Bash:** admite técnicas basadas en `\` y `$@`.
    
- **Windows CMD:** puede interpretar `^` como carácter de escape.
    
- **Idea principal:** un filtro que busca únicamente cadenas literales puede ser insuficiente si no tiene en cuenta cómo el shell interpreta la entrada.
