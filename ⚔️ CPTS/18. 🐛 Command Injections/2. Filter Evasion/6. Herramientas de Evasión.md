
Cuando la ofuscación manual no es suficiente para evadir filtros de seguridad, podemos utilizar **herramientas automatizadas** que generan comandos ofuscados para Linux y Windows.

## 1. Linux: Bashfuscator

**Bashfuscator** permite generar versiones ofuscadas de comandos Bash mediante distintas técnicas y capas de transformación.

### Instalación

```
git clone https://github.com/Bashfuscator/Bashfuscator
cd Bashfuscator
pip3 install setuptools==65
python3 setup.py install --user
```

Repositorio: [https://github.com/Bashfuscator/Bashfuscator](https://github.com/Bashfuscator/Bashfuscator)

### Uso básico

Acceder al directorio de ejecución y consultar la ayuda:

```
cd ./bashfuscator/bin/
./bashfuscator -h
```

Parámetros importantes:

|Parámetro|Función|
|---|---|
|`-h`|Muestra la ayuda.|
|`-l`|Lista los ofuscadores, compresores y codificadores disponibles.|
|`-c`|Especifica el comando que queremos ofuscar.|
|`-s`|Permite ajustar la semilla utilizada por la herramienta.|
|`-t`|Permite ajustar opciones relacionadas con las transformaciones.|
|`--no-mangling`|Desactiva el _mangling_.|
|`--layers`|Controla el número de capas de ofuscación.|

### Ofuscar un comando

Ejemplo: ofuscar la lectura de `/etc/passwd`.

```
./bashfuscator -c 'cat /etc/passwd'
```

Por defecto, la herramienta puede elegir técnicas aleatorias y producir payloads extremadamente largos.

Para generar un payload más corto:

```
./bashfuscator -c 'cat /etc/passwd' -s 1 -t 1 --no-mangling --layers 1
```

**Importante:** los parámetros utilizados permiten reducir la complejidad del resultado, pero el payload generado dependerá de las opciones y técnicas seleccionadas.

### Probar el payload

Podemos comprobar si el comando ofuscado funciona ejecutándolo mediante Bash:

```
bash -c 'PAYLOAD_GENERADO'
```

Sustituye `PAYLOAD_GENERADO` por el resultado real de Bashfuscator.

**Aplicación en Command Injection:**

1. Identificar un comando que queramos ejecutar.
    
2. Generar una versión ofuscada con Bashfuscator.
    
3. Comprobar que el payload funciona localmente.
    
4. Probarlo en la aplicación vulnerable.
    
5. Si falla, revisar los caracteres y operadores que bloquea el filtro, así como las características del shell que interpreta el comando.
    

Un payload puede funcionar localmente y fallar en la aplicación si utiliza caracteres bloqueados o una sintaxis incompatible con el entorno de ejecución.

## 2. Windows: DOSfuscation

**DOSfuscation** permite ofuscar comandos de Windows mediante técnicas de `cmd.exe` y PowerShell. A diferencia de Bashfuscator, funciona de forma interactiva.

### Instalación e inicio

```
git clone https://github.com/danielbohannon/Invoke-DOSfuscation.git
cd Invoke-DOSfuscation
Import-Module .\Invoke-DOSfuscation.psd1
Invoke-DOSfuscation
```

Repositorio: [https://github.com/danielbohannon/Invoke-DOSfuscation](https://github.com/danielbohannon/Invoke-DOSfuscation)

Consultar las opciones disponibles:

```
help
```

### Opciones principales

|Opción|Función|
|---|---|
|`BINARY`|Ofuscación de la sintaxis de binarios para `cmd.exe` y PowerShell.|
|`ENCODING`|Ofuscación mediante variables de entorno.|
|`PAYLOAD`|Ofuscación del payload mediante técnicas de DOSfuscation.|

### Generar un comando ofuscado

Ejemplo: leer un archivo `flag.txt`.

Primero, establecer el comando:

```
SET COMMAND type C:\Users\htb-student\Desktop\flag.txt
```

Después, seleccionar el modo de codificación:

```
encoding
1
```

La herramienta genera un comando que utiliza expresiones y variables de entorno para construir partes del comando original.

### Ejecutar el resultado

Copiar el payload generado y ejecutarlo en `cmd.exe`.

Si funciona correctamente, debería mostrar el contenido del archivo.

**Alternativa en Linux:** se puede utilizar PowerShell (`pwsh`) para ejecutar la herramienta y seguir el procedimiento indicado, siempre que se disponga de los requisitos necesarios.

## 3. Flujo de trabajo para el laboratorio

Cuando necesitemos evadir filtros de comandos:

1. **Identificar el comando original** que queremos ejecutar.
    
2. **Determinar qué caracteres o palabras bloquea el filtro.**
    
3. **Generar un payload ofuscado** con Bashfuscator (Linux) o DOSfuscation (Windows).
    
4. **Probarlo localmente** para verificar que la sintaxis es válida.
    
5. **Enviar el payload a la aplicación vulnerable** y comprobar la respuesta.
    
6. Si falla, analizar si el problema se debe a caracteres bloqueados, sintaxis incompatible, restricciones del shell o límites de longitud.
    
7. Ajustar las técnicas y volver a probar.
    

## Chuleta rápida

|Sistema|Herramienta|Uso|
|---|---|---|
|Linux|Bashfuscator|`./bashfuscator -c 'COMANDO'`|
|Linux|Bashfuscator con opciones adicionales|`./bashfuscator -c 'COMANDO' -s 1 -t 1 --no-mangling --layers 1`|
|Windows|DOSfuscation|`Invoke-DOSfuscation`|
|Windows|Establecer el comando|`SET COMMAND COMANDO`|
|Windows|Seleccionar codificación|`encoding`|

**Concepto clave para HTB:** la ofuscación modifica la representación de un comando para intentar evadir filtros sin cambiar su comportamiento. El resultado debe probarse en el contexto real de ejecución, ya que un payload válido localmente no garantiza que funcione contra los filtros de la aplicación.
