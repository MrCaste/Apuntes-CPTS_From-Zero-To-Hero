
## 1. Introducción

Cuando una aplicación utiliza filtros avanzados o un WAF (_Web Application Firewall_), las técnicas básicas de evasión pueden no ser suficientes.

La **ofuscación de comandos** consiste en modificar la representación de un comando para evitar que un filtro lo identifique, manteniendo su funcionalidad.

En esta sección se estudian tres técnicas principales:

- Manipulación de mayúsculas y minúsculas.
    
- Inversión de comandos.
    
- Codificación de comandos.
    

**Importante:** también hay que tener en cuenta los filtros de caracteres. Una técnica puede ser válida, pero fallar si contiene espacios u otros caracteres bloqueados.

## 2. Manipulación de mayúsculas y minúsculas

Esta técnica modifica las mayúsculas y minúsculas de un comando para evitar que coincida literalmente con una palabra de una lista negra.

Por ejemplo:

```
whoami
WHOAMI
WhOaMi
```

### 2.1. Windows

En CMD y PowerShell, los comandos suelen ser insensibles a mayúsculas y minúsculas (_case-insensitive_).

Por tanto, el siguiente comando puede ejecutarse correctamente:

```
WhOaMi
```

### 2.2. Linux

En Linux, los nombres de los comandos distinguen entre mayúsculas y minúsculas (_case-sensitive_).

Por ello, escribir `WhOaMi` directamente no equivale a ejecutar `whoami`.

Podemos transformar el comando a minúsculas utilizando `tr`:

```
$(tr "[A-Z]" "[a-z]"<<<"WhOaMi")
```

**Funcionamiento:**

1. Se proporciona el texto `WhOaMi`.
    
2. `tr` convierte las letras mayúsculas en minúsculas.
    
3. El resultado es `whoami`.
    
4. `$(...)` ejecuta la sustitución de comandos y permite utilizar el resultado como comando.
    

### 2.3. Alternativa con expansión de parámetros de Bash

También podemos convertir una cadena a minúsculas mediante la expansión de parámetros:

```
a="WhOaMi";printf %s "${a,,}"
```

La expresión `${a,,}` convierte las letras de la variable `a` a minúsculas.

### Consideración sobre los filtros

El primer ejemplo con `tr` contiene espacios literales. En el laboratorio, estos caracteres provocan el bloqueo de la petición.

El material propone sustituirlos por tabuladores codificados como `%09` para conseguir que el payload funcione.

**Idea clave:** una técnica de ofuscación debe adaptarse a todos los filtros presentes, no únicamente al filtro de comandos.

## 3. Invertir comandos

Otra técnica consiste en invertir el texto del comando para que la cadena original no aparezca directamente en el payload.

Por ejemplo, invertimos `whoami`:

```
echo 'whoami' | rev
```

Resultado:

```
imaohw
```

Después, podemos recuperar el comando original mediante `rev` y ejecutar el resultado utilizando una sustitución de comandos:

```
$(rev<<<'imaohw')
```

El shell invierte `imaohw`, obtiene `whoami` y ejecuta el comando.

### Ventajas

- La cadena original no aparece directamente en el payload.
    
- Puede evitar filtros que buscan coincidencias literales con nombres de comandos.
    
- Permite generar el comando durante la ejecución.
    

### Windows: PowerShell

En PowerShell podemos invertir una cadena utilizando índices negativos:

```
"whoami"[-1..-20] -join ''
```

Resultado:

```
imaohw
```

Para invertirla y ejecutar el resultado, el material presenta:

```
iex "$('imaohw'[-1..-20] -join '')"
```

**Nota:** el rango utilizado debe ser compatible con la longitud de la cadena y con el comportamiento de la expresión en PowerShell.

### Consideraciones

- Si el filtro bloquea otros caracteres del comando, también hay que tenerlos en cuenta al invertirlo.
    
- La técnica depende de que estén disponibles las herramientas utilizadas, como `rev`.
    
- Debemos verificar que el comando se ejecuta y no asumir que el filtro se ha evadido solo porque la petición es aceptada.
    

## 4. Codificar comandos

La tercera técnica consiste en codificar un comando para que el filtro no encuentre directamente las palabras o los caracteres originales.

El material presenta dos alternativas:

- **Base64:** codificación del contenido en una representación textual diferente.
    
- **Hexadecimal:** representación de los datos mediante caracteres hexadecimales, por ejemplo, utilizando `xxd`.
    

### 4.1. Linux: codificación Base64

Supongamos que queremos ejecutar el siguiente comando:

```
cat /etc/passwd | grep 33
```

Primero, lo codificamos en Base64:

```
echo -n 'cat /etc/passwd | grep 33' | base64
```

Resultado:

```
Y2F0IC9ldGMvcGFzc3dkIHwgZ3JlcCAzMw==
```

A continuación, podemos decodificarlo y ejecutar el resultado mediante Bash:

```
bash<<<$(base64 -d<<<Y2F0IC9ldGMvcGFzc3dkIHwgZ3JlcCAzMw==)
```

**Funcionamiento:**

1. El contenido codificado se introduce en `base64 -d`.
    
2. La sustitución de comandos `$(...)` recoge el resultado de la decodificación.
    
3. `bash<<<` proporciona el comando decodificado a Bash para su ejecución.
    

El comando original se ejecuta sin tener que escribir directamente sus caracteres dentro de la cadena codificada.

### ¿Por qué se utiliza `<<<`?

En este ejemplo se utiliza la sintaxis _here-string_ de Bash para proporcionar la entrada al comando.

Esto permite evitar el operador de tubería `|` en la parte que realiza la decodificación.

### 4.2. Alternativas

Si el filtro también bloquea nombres de herramientas como `bash` o `base64`, el material menciona otras posibilidades:

|Necesidad|Alternativa mencionada|
|---|---|
|Ejecutar comandos|`sh`|
|Decodificar Base64|`openssl`|
|Codificación hexadecimal|`xxd`|

La disponibilidad de estas herramientas depende del sistema.

## 5. Windows: codificación Base64 con PowerShell

PowerShell puede codificar cadenas en Base64, pero en el procedimiento del material se utiliza **UTF-16LE** para representar el texto.

### 5.1. Codificar el comando

```
[Convert]::ToBase64String([System.Text.Encoding]::Unicode.GetBytes('whoami'))
```

Resultado:

```
dwBoAG8AYQBtAGkA
```

La propiedad `Unicode` de .NET utiliza UTF-16LE en este contexto.

En Linux podemos obtener la misma representación mediante:

```
echo -n whoami | iconv -f utf-8 -t utf-16le | base64
```

### 5.2. Decodificar y ejecutar

En PowerShell, el material utiliza:

```
iex "$([System.Text.Encoding]::Unicode.GetString([System.Convert]::FromBase64String('dwBoAG8AYQBtAGkA')))"
```

**Funcionamiento:**

1. `FromBase64String()` decodifica la cadena Base64.
    
2. `GetString()` convierte los bytes a texto Unicode.
    
3. `iex` interpreta y ejecuta el comando resultante.
    

### Diferencia importante entre Linux y Windows

|Aspecto|Linux|Windows PowerShell|
|---|---|---|
|Codificación del ejemplo|Base64 de los bytes del texto|Base64 de texto UTF-16LE|
|Decodificación|`base64 -d`|`FromBase64String()` y `GetString()`|
|Ejecución|Bash|`iex`|
|Entrada del comando|`<<<`|Expresión de PowerShell|

No basta con codificar una cadena en Base64: el procedimiento de decodificación debe utilizar la codificación de texto correspondiente.

## 6. Otras técnicas de ofuscación

Además de las técnicas anteriores, el material menciona otras posibilidades:

- Comodines (_wildcards_).
    
- Expresiones regulares.
    
- Redirección de salida.
    
- Expansión de enteros.
    
- Otras transformaciones de caracteres y comandos.
    

La técnica adecuada dependerá de los caracteres permitidos, las herramientas disponibles y el nivel de filtrado de la aplicación.

## 7. Tabla resumen

|Técnica|Linux|Windows|Objetivo|
|---|---|---|---|
|Cambio de mayúsculas y minúsculas|Requiere una transformación si el comando distingue entre casos|Los comandos de CMD y PowerShell suelen ser insensibles a los casos|Evitar coincidencias literales.|
|Transformación con `tr`|Sí|No es la técnica presentada para Windows|Convertir texto a minúsculas.|
|Inversión con `rev`|Sí|No es la técnica presentada para Windows|Ocultar la cadena original invirtiéndola.|
|Inversión mediante índices|No es el ejemplo presentado|Sí, en PowerShell|Recuperar una cadena invertida.|
|Codificación Base64|`base64` y Bash|Métodos de .NET y PowerShell|Ocultar la representación original del comando.|
|Codificación hexadecimal|`xxd`|Depende de las herramientas disponibles|Representar datos mediante caracteres hexadecimales.|

## 8. Procedimiento para el laboratorio

1. Identifica qué comando está bloqueando el filtro.
    
2. Comprueba si el bloqueo depende de una coincidencia literal.
    
3. Selecciona una técnica compatible con el sistema operativo y el shell.
    
4. Revisa si el payload contiene espacios, operadores u otros caracteres bloqueados.
    
5. Ajusta la representación del comando a los filtros identificados.
    
6. Comprueba la respuesta y verifica la ejecución mediante la salida obtenida.
    
7. Si falla, comprueba tanto la técnica de ofuscación como los caracteres y las herramientas utilizados.
    

## Chuleta para el examen

- **Manipulación de casos:** puede funcionar directamente en Windows; en Linux, normalmente hay que transformar el texto a minúsculas si el comando original está escrito así.
    
- `**tr**`**:** permite transformar caracteres, por ejemplo, de mayúsculas a minúsculas.
    
- `**rev**`**:** invierte una cadena en Linux.
    
- `**$()**`**:** ejecuta una sustitución de comandos.
    
- **Base64:** permite representar un comando sin mostrar directamente su texto original.
    
- `**<<<**`**:** proporciona una cadena como entrada al comando en Bash.
    
- **PowerShell:** puede codificar y decodificar Base64 mediante clases de .NET.
    
- **UTF-16LE:** es importante para reproducir correctamente el ejemplo Base64 de PowerShell.
    
- **Idea principal:** la ofuscación modifica la representación del comando, pero su resultado depende de cómo lo interprete el shell y de los filtros que aplique la aplicación.
