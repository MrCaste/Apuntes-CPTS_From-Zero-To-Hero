
## 1. Evasión de operadores en lista negra

Cuando una aplicación utiliza listas negras (_blacklists_), puede bloquear operadores como `;`, `&&` o `||`.

Sin embargo, el carácter de nueva línea (`\n`) puede no estar bloqueado y permite separar comandos tanto en Linux como en Windows.

En el laboratorio, se prueba el siguiente payload:

```
127.0.0.1%0a
```

- `%0a` representa un carácter de nueva línea codificado en URL.
    
- La petición no es bloqueada y se obtiene la salida del `ping`.
    
- Esto indica que la nueva línea puede utilizarse como operador de inyección en este ejercicio.
    

**Importante:** cada aplicación tiene sus propios filtros; hay que comprobar qué caracteres están permitidos.

## 2. Identificar el filtro de espacios

Al intentar ejecutar un segundo comando con un espacio:

```
127.0.0.1%0a whoami
```

La aplicación devuelve:

```
Invalid input
```

Esto indica que existe otro filtro que está bloqueando la petición.

Al probar los elementos por separado, se determina que el **espacio también está incluido en la lista negra**.

Existen varias técnicas para representar la separación entre argumentos sin utilizar un espacio literal.

## 3. Métodos para evadir filtros de espacios

### 3.1. Utilizar tabuladores

Linux y Windows permiten utilizar tabuladores como separadores entre argumentos en determinados contextos.

En URL, un tabulador puede representarse mediante `%09`.

Ejemplo del laboratorio:

```
127.0.0.1%0a%09
```

La petición es aceptada y se obtiene la salida del `ping`, lo que demuestra que el tabulador no está bloqueado por el filtro utilizado.

**Concepto clave:** un tabulador no es lo mismo que un espacio, aunque ambos puedan actuar como separadores.

### 3.2. Utilizar la variable `$IFS`

En Linux, la variable de entorno `$IFS` (_Internal Field Separator_) define los caracteres que utiliza el shell para separar campos. Su valor predeterminado suele incluir espacios, tabuladores y saltos de línea.

Puede utilizarse su expansión para evitar escribir un espacio literal.

Ejemplo del laboratorio:

```
127.0.0.1%0a${IFS}
```

La aplicación acepta la petición y devuelve la salida del `ping`.

**Concepto clave:** `${IFS}` puede expandirse a caracteres separadores, pero su comportamiento depende del shell y del contexto de ejecución.

### 3.3. Utilizar la expansión de llaves de Bash

Bash dispone de una característica denominada _Brace Expansion_ o expansión de llaves.

Permite generar palabras a partir de una expresión entre llaves, separadas por comas.

Ejemplo:

```
{ls,-la}
```

Bash expande la expresión y ejecuta el comando equivalente a:

```
ls -la
```

En el contexto de una inyección de comandos, el material presenta el siguiente ejemplo:

```
127.0.0.1%0a{ls,-la}
```

Esta técnica evita escribir un espacio literal entre `ls` y `-la`.

**Importante:** la expansión de llaves es una característica de Bash; no debe asumirse que funciona de la misma manera en todos los shells.

## 4. Tabla resumen

|Técnica|Representación|Función|
|---|---|---|
|Nueva línea|`%0a`|Separar comandos cuando el filtro lo permite.|
|Tabulador|`%09`|Sustituir un espacio literal como separador.|
|Variable `$IFS`|`${IFS}`|Utilizar la expansión de una variable que contiene separadores.|
|Expansión de llaves|`{ls,-la}`|Generar argumentos separados sin escribir un espacio literal.|

## 5. Procedimiento para el laboratorio

1. Comprueba que la entrada válida `127.0.0.1` funciona.
    
2. Prueba un operador de inyección y observa si la aplicación lo bloquea.
    
3. Comprueba si la nueva línea (`%0a`) está permitida.
    
4. Si el espacio provoca `Invalid input`, prueba las técnicas de sustitución presentadas.
    
5. Compara las respuestas para identificar qué caracteres o construcciones acepta el filtro.
    
6. Recuerda que una petición aceptada no demuestra por sí sola que un segundo comando se haya ejecutado: hay que verificar el resultado.
    

## Chuleta para el examen

- `%0a`: representación URL de una nueva línea.
    
- `%09`: representación URL de un tabulador.
    
- `${IFS}`: expansión de una variable de shell que normalmente contiene separadores.
    
- `{ls,-la}`: expansión de llaves de Bash.
    
- **Idea principal:** los filtros que bloquean espacios literales pueden ser insuficientes si no contemplan otras formas de separar argumentos.
