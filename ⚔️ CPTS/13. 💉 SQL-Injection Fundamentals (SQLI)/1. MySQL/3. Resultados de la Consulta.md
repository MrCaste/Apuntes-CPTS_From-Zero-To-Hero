
## 1. Ordenar resultados: `ORDER BY`

Permite ordenar los resultados de una consulta por una columna determinada.

```
SELECT * FROM logins ORDER BY password;
```

- Por defecto, ordena de forma **ascendente** (`ASC`).
    
- `ASC`: orden ascendente.
    
- `DESC`: orden descendente.
    

**Orden descendente:**

```
SELECT * FROM logins ORDER BY password DESC;
```

También podemos ordenar por varias columnas. Si hay valores duplicados en la primera columna, se utiliza la siguiente para establecer el orden secundario.

```
SELECT * FROM logins ORDER BY password DESC, id ASC;
```

## 2. Limitar resultados: `LIMIT`

Permite especificar el número máximo de registros que devuelve una consulta.

**Obtener los dos primeros registros:**

```
SELECT * FROM logins LIMIT 2;
```

**Utilizar un desplazamiento (**`**OFFSET**`**):**

```
SELECT * FROM logins LIMIT 1, 2;
```

En MySQL, la sintaxis `LIMIT desplazamiento, cantidad` indica desde qué posición empezar y cuántos registros devolver.

- El desplazamiento empieza en `0`.
    
- `LIMIT 1, 2`: omite el primer registro y devuelve los dos siguientes.
    

Esto resulta útil para recuperar resultados por partes.

## 3. Filtrar resultados: `WHERE`

La cláusula `WHERE` permite seleccionar únicamente los registros que cumplen una condición.

**Sintaxis:**

```
SELECT * FROM table_name WHERE <condition>;
```

**Filtrar por un valor numérico:**

```
SELECT * FROM logins WHERE id > 1;
```

Devuelve los registros cuyo `id` es mayor que `1`.

**Filtrar por un nombre de usuario:**

```
SELECT * FROM logins WHERE username = 'admin';
```

Devuelve los registros cuyo nombre de usuario es exactamente `admin`.

También podemos utilizar `WHERE` con `UPDATE` para modificar únicamente los registros que cumplan una condición.

**Importante:**

- Las cadenas de texto y las fechas deben escribirse entre comillas simples (`'`) o dobles (`"`).
    
- Los números pueden escribirse directamente, sin comillas.
    
- Si se utiliza `UPDATE` sin `WHERE`, se pueden modificar todos los registros de la tabla.
    

## 4. Buscar patrones: `LIKE`

La cláusula `LIKE` permite buscar registros que coincidan con un patrón determinado.

**Buscar nombres de usuario que comiencen por** `**admin**`**:**

```
SELECT * FROM logins WHERE username LIKE 'admin%';
```

El símbolo `%` funciona como comodín y coincide con **cero o más caracteres**.

Por tanto, puede encontrar nombres como:

- `admin`
    
- `administrator`
    

### Comodines de `LIKE`

|Comodín|Función|Ejemplo|
|---|---|---|
|`%`|Coincide con cero o más caracteres.|`'admin%'`|
|`_`|Coincide con exactamente un carácter.|`'___'`|

**Buscar nombres de usuario de exactamente tres caracteres:**

```
SELECT * FROM logins WHERE username LIKE '___';
```

En el ejemplo de HTB, devuelve el usuario `tom`.

## 6. Aplicación en SQL Injection

Estos conceptos permiten comprender cómo se construyen las consultas SQL y cómo se controla su salida.

- `**ORDER BY**`: establece el orden de los resultados.
    
- `**LIMIT**`: controla cuántos registros se devuelven y permite recorrer resultados por partes.
    
- `**WHERE**`: filtra los registros según una condición.
    
- `**LIKE**`: permite buscar datos mediante patrones y comodines.
    

Es importante reconocer estas cláusulas al analizar consultas vulnerables a SQL Injection, ya que pueden formar parte de la consulta original ejecutada por la aplicación.
