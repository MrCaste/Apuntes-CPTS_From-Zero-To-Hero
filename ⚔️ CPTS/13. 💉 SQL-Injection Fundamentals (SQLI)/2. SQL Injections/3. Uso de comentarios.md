
## 1. Comentarios SQL

Los comentarios permiten documentar consultas o ignorar una parte de ellas. En MySQL, los principales tipos son:

|Sintaxis|Tipo|Descripción|
|---|---|---|
|`--`|Comentario de línea|Ignora el resto de la línea. Requiere un espacio después de los dos guiones.|
|`#`|Comentario de línea|Ignora el resto de la línea.|
|`/**/`|Comentario en línea|Permite introducir comentarios dentro de una consulta.|

### Comentario con `--`

```
SELECT username FROM logins; -- Selecciona los nombres de usuario
```

**Importante:** en MySQL, `--` debe ir seguido de un espacio o un carácter de control para iniciar un comentario.

En determinadas URL, el espacio puede representarse como `+`, por lo que es habitual encontrar `--+`. También se puede utilizar `-- -` para hacer visible el espacio necesario.

### Comentario con `#`

```
SELECT * FROM logins
WHERE username = 'admin'; # Ignora el resto de la línea
```

Si la consulta original contiene una condición adicional después del comentario, esta deja de evaluarse.

**Importante:** cuando se introduce `#` en una URL desde un navegador, normalmente se interpreta como el inicio de un fragmento y no se envía al servidor. Para transmitirlo como parte de la petición, se puede codificar como `%23`.

## 2. Elusión de autenticación mediante comentarios

Supongamos que la aplicación utiliza esta consulta para autenticar a un usuario:

```
SELECT * FROM logins
WHERE username = 'admin' AND password = 'something';
```

La consulta comprueba tanto el nombre de usuario como la contraseña.

En el laboratorio de HTB Academy, se estudia cómo un comentario puede hacer que la segunda condición deje de evaluarse.

### Ejemplo del laboratorio

Al introducir una entrada que termina con un comentario, la consulta resultante puede tener esta estructura:

```
SELECT * FROM logins
WHERE username = 'admin'-- ' AND password = 'something';
```

La parte situada después de `--` se interpreta como un comentario. Por tanto, la condición de la contraseña deja de formar parte de la consulta ejecutada.

En el escenario del laboratorio, esto permite comprobar cómo una consulta alterada puede aceptar el nombre de usuario sin validar la contraseña.

## 3. Consultas con paréntesis

Las consultas SQL pueden utilizar paréntesis para agrupar condiciones. Las expresiones dentro de ellos se evalúan antes de combinarlas con los operadores externos.

Consideremos esta consulta:

```
SELECT * FROM logins
WHERE (username = 'admin' AND id > 1)
AND password = '437b930db84b8079c2dd804a71936b5f';
```

La consulta comprueba tres condiciones:

1. El nombre de usuario debe ser `admin`.
    
2. El identificador debe ser mayor que `1`.
    
3. La contraseña debe coincidir con el valor almacenado o calculado por la aplicación.
    

La condición `id > 1` impide que el usuario administrador inicie sesión si su identificador es `1`.

### Contraseñas transformadas mediante hash

En este escenario, la aplicación transforma la contraseña introducida antes de utilizarla en la consulta.

Por ello, el valor que aparece en SQL no es necesariamente la contraseña original, sino su representación mediante hash.

El ejemplo muestra que proporcionar las credenciales correctas no garantiza el acceso si otra condición de la consulta es falsa.

## 4. El problema de los paréntesis sin cerrar

Los paréntesis deben estar correctamente equilibrados para que la consulta tenga una sintaxis válida.

Si se altera una consulta que contiene un paréntesis de apertura y se elimina el resto de la expresión mediante un comentario, puede quedar un paréntesis sin cerrar.

Por ejemplo, la estructura original es:

```
WHERE (username = 'admin' AND id > 1)
AND password = '...';
```

Si el comentario elimina la parte que contiene el paréntesis de cierre, la consulta puede producir un error de sintaxis.

**Concepto clave:** al analizar una SQL Injection, hay que tener en cuenta no solo las comillas, sino también los paréntesis que forman parte de la consulta original.

En el escenario de HTB Academy, el ejercicio muestra que la consulta puede quedar sintácticamente válida cuando el paréntesis se cierra antes de que comience el comentario. Esto permite comprender cómo la estructura de la consulta influye en el resultado de la inyección.

## 5. Chuleta rápida

|Elemento|Función|
|---|---|
|`--`|Comenta el resto de la línea en MySQL.|
|`#`|Comenta el resto de la línea.|
|`%23`|Representación URL del carácter `#`.|
|`--+`|Representación habitual de dos guiones seguidos de un espacio en una URL.|
|`/**/`|Comentario en línea.|
|`(condición1 AND condición2)`|Agrupa condiciones para evaluarlas conjuntamente.|
|Paréntesis equilibrados|Ayudan a mantener una sintaxis SQL válida.|

## 6. Aplicación práctica en HTB

Al analizar una posible SQL Injection:

1. Identificar cómo se construye la consulta original.
    
2. Determinar qué parte de la consulta se encuentra después de la entrada controlada.
    
3. Reconocer los comentarios SQL que podrían afectar al resto de la consulta.
    
4. Comprobar si las comillas y los paréntesis mantienen una sintaxis válida.
    
5. Identificar las condiciones adicionales que intervienen en la autenticación.
    
6. Tener en cuenta si la aplicación transforma la contraseña antes de consultar la base de datos.
    

**Idea fundamental:** los comentarios SQL pueden hacer que una parte de una consulta deje de evaluarse. Sin embargo, para comprender el resultado es necesario analizar la sintaxis completa, los paréntesis, las comillas y las condiciones que permanecen activas.
