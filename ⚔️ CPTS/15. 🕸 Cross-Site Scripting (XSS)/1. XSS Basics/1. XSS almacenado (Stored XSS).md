
## 📌 Concepto

El **XSS almacenado** ocurre cuando un payload JavaScript malicioso se guarda en la base de datos del backend y se ejecuta cuando un usuario visita la página que lo muestra.

Es uno de los tipos de XSS más críticos porque:

- **Es persistente:** el payload permanece almacenado y puede ejecutarse al recargar la página.
    
- **Afecta a otros usuarios:** cualquier usuario que visite la página vulnerable puede ejecutar el payload.
    
- **Puede ser difícil de eliminar:** en algunos casos hay que borrar el contenido malicioso de la base de datos.
    

## 🔎 Detección de XSS almacenado

### 1. Introducir una entrada de prueba

En una aplicación web, como una lista de tareas, introduce un valor en el formulario y comprueba cómo se muestra.

Si la aplicación muestra la entrada sin sanearla ni filtrarla correctamente, podría ser vulnerable a XSS.

### 2. Probar un payload básico

```
<script>alert(window.origin)</script>
```

Si aparece una alerta con el origen de la página, significa que el JavaScript se ha ejecutado.

**¿Por qué usar** `**window.origin**`**?**

Permite identificar el origen en el que se ejecuta el payload. Es útil cuando el formulario está dentro de un `iframe`, ya que ayuda a comprobar si el código se ejecuta en el contexto esperado.

### 3. Comprobar el código fuente

Pulsa `Ctrl + U` o haz clic derecho y selecciona **Ver código fuente de la página**.

Si el payload aparece en el HTML generado, comprueba cómo lo está interpretando el navegador.

Ejemplo:

```
<div></div>
<ul class="list-unstyled" id="todo">
    <ul>
        <script>alert(window.origin)</script>
    </ul>
</ul>
```

### 4. Comprobar si es persistente

1. Introduce el payload.
    
2. Comprueba si se ejecuta.
    
3. Recarga la página.
    
4. Verifica si vuelve a ejecutarse.
    

Si el payload continúa ejecutándose después de recargar, esto confirma que permanece almacenado y es consistente con un **Stored XSS**.

## 🧪 Payloads básicos de prueba

|Payload|Función|
|---|---|
|`<script>alert(window.origin)</script>`|Muestra el origen de la página si el JavaScript se ejecuta.|
|`<plaintext>`|Hace que el navegador muestre como texto plano el contenido HTML posterior.|
|`<script>print()</script>`|Abre el diálogo de impresión del navegador si el código se ejecuta.|

Algunos navegadores pueden bloquear `alert()` en determinados contextos, por lo que conviene conocer otras formas de comprobar la ejecución.

## ⚡ Flujo práctico de enumeración

1. **Identificar entradas controladas por el usuario:** formularios, comentarios, tareas, perfiles, etc.
    
2. **Introducir un valor de prueba:** comprobar cómo se refleja en la página.
    
3. **Probar un payload:** utilizar una prueba inocua como `alert(window.origin)`.
    
4. **Inspeccionar el HTML:** comprobar cómo se incorpora la entrada al documento.
    
5. **Recargar la página:** verificar si el payload persiste.
    
6. **Valorar el alcance:** determinar si otros usuarios que visiten la página también ejecutan el payload.
    

## 🧠 Chuleta para el examen

- **Stored XSS:** el payload se almacena en el backend y se ejecuta cuando se muestra posteriormente.
    
- **Persistent XSS:** otro nombre para el XSS almacenado.
    
- **Refrescar la página:** permite comprobar si el payload persiste.
    
- `**alert(window.origin)**`**:** prueba básica para verificar la ejecución de JavaScript e identificar su origen.
    
- `**Ctrl + U**`**:** permite inspeccionar el código fuente de la página.
    
- **Impacto:** puede afectar a todos los usuarios que visiten el contenido vulnerable, no solamente a quien introdujo el payload.
    
- **Eliminación:** puede requerir borrar el contenido malicioso almacenado en el backend.
    

> **Importante:** que una entrada aparezca en el HTML no demuestra por sí solo que exista XSS. Hay que comprobar si el navegador interpreta y ejecuta el contenido como código.
