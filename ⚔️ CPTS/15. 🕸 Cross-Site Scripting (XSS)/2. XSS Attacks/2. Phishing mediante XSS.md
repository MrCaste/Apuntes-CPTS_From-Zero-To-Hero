
## 1. Objetivo

Una vulnerabilidad **XSS** puede utilizarse para inyectar un formulario de inicio de sesión falso en una página legítima y engañar al usuario para que introduzca sus credenciales.

El ataque se divide en cuatro fases:

1. **Descubrir el XSS:** encontrar un payload que ejecute JavaScript.
    
2. **Inyectar el formulario:** mostrar un formulario HTML falso.
    
3. **Modificar la página:** eliminar elementos originales que puedan generar sospechas.
    
4. **Analizar la petición HTTP:** comprobar cómo se transmiten los datos del formulario.
    

> Realiza estas pruebas únicamente en laboratorios autorizados, como el entorno de HTB Academy.

## 2. Descubrimiento de XSS

El laboratorio utiliza un visor de imágenes que recibe una URL mediante el parámetro `url`:

```
http://SERVER_IP/phishing/index.php?url=https://www.hackthebox.eu/images/logo-htb.svg
```

Probamos un payload básico:

```
<script>alert(window.origin)</script>
```

Si no funciona, debemos inspeccionar cómo se refleja la entrada en el HTML.

### Inspección del código fuente

1. Introducir el payload en el parámetro vulnerable.
    
2. Abrir las herramientas de desarrollo con `F12`.
    
3. Inspeccionar el elemento afectado o consultar el código fuente con `Ctrl + U`.
    
4. Identificar el contexto en el que aparece la entrada.
    
5. Adaptar el payload al contexto HTML encontrado.
    

**Importante:** que un payload no funcione no significa necesariamente que no exista XSS. Puede que el contexto de inserción requiera una sintaxis diferente.

## 3. Inyección de HTML mediante JavaScript

La función `document.write()` permite escribir contenido HTML en el documento desde JavaScript.

Ejemplo básico:

```
document.write('<h3>Contenido de prueba</h3>');
```

En el laboratorio, se utiliza esta técnica para comprobar si es posible introducir contenido HTML en la página vulnerable.

### Formulario HTML de ejemplo

```
<h3>Please login to continue</h3>
<form>
    <input type="text" name="username" placeholder="Username">
    <input type="password" name="password" placeholder="Password">
    <input type="submit" value="Login">
</form>
```

Los elementos principales son:

|Elemento|Función|
|---|---|
|`<form>`|Agrupa los campos del formulario.|
|`input type="text"`|Permite introducir texto.|
|`input type="password"`|Oculta visualmente el texto introducido.|
|`name`|Identifica cada campo en los datos enviados.|
|`action`|Define el destino de la petición del formulario.|
|`method`|Define cómo se envían los datos, por ejemplo, mediante `GET` o `POST`.|

## 4. Inspección y modificación del DOM

El **DOM (Document Object Model)** representa la estructura de la página que el navegador está mostrando.

Para identificar un elemento:

1. Pulsar `Ctrl + Shift + C` en Firefox.
    
2. Seleccionar el elemento que queremos inspeccionar.
    
3. Buscar su atributo `id` en el HTML.
    

Por ejemplo:

```
<form id="urlform">
    <input type="text" name="url" placeholder="Image URL">
</form>
```

Podemos localizarlo mediante JavaScript:

```
document.getElementById('urlform');
```

Y eliminarlo del DOM con:

```
document.getElementById('urlform').remove();
```

### Conceptos que debes recordar

|Función|Utilidad|
|---|---|
|`document.write()`|Escribe contenido en el documento.|
|`document.getElementById()`|Busca un elemento por su identificador.|
|`.remove()`|Elimina un elemento del DOM.|
|`document.body.innerHTML`|Permite consultar o modificar el HTML interno del cuerpo de la página.|

**Nota:** modificar el DOM en el navegador no modifica automáticamente los archivos originales del servidor.

## 5. Analizar las peticiones HTTP

Los formularios HTML pueden transmitir sus campos mediante parámetros de una petición HTTP.

Por ejemplo, un formulario que utilice `GET` podría generar una petición como esta:

```
GET /?username=test&password=test&submit=Login HTTP/1.1
Host: 10.10.10.10
```

Esto permite observar cómo se codifican los campos enviados.

### Aspectos importantes

- Con `GET`, los datos suelen aparecer en la URL como parámetros de consulta.
    
- Con `POST`, los datos normalmente se transmiten en el cuerpo de la petición.
    
- Los campos incluidos dependen de sus atributos HTML y de los datos enviados.
    
- HTTPS protege los datos durante el transporte, pero no evita que una aplicación vulnerable pueda exponerlos al propio código que se ejecuta en el navegador.

### Flujo de análisis

```
Identificar una entrada controlable
              |
              v

              |
              v
Comprobar si se ejecuta JavaScript
              |
              v
Identificar el contexto de ejecución
              |
              v

              |
              v
Inspeccionar las peticiones HTTP generadas
```

### Medidas de prevención

- Codificar la salida según el contexto HTML, atributo o JavaScript.
    
- Evitar insertar entradas no confiables mediante `innerHTML` o `document.write()`.
    
- Utilizar mecanismos seguros del DOM, como `textContent`, cuando corresponda.
    
- Validar las entradas y aplicar una política CSP como defensa adicional.
    
- No confiar únicamente en la validación del lado del cliente.
    
- Proteger los formularios de autenticación y no considerar que una página legítima está libre de vulnerabilidades XSS.
