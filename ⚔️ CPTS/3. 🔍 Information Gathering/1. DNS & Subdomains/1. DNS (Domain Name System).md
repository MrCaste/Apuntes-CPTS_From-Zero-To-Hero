
## 1. ¿Qué es DNS?

El **DNS** traduce nombres de dominio legibles por humanos a direcciones IP que los equipos utilizan para comunicarse.

Ejemplo:

- Dominio: `www.example.com`
    
- IPv4: `192.0.2.1`
    

### ¿Cómo funciona la resolución DNS?

1. **Caché local:** el equipo comprueba si ya conoce la IP del dominio.
    
2. **Resolutor DNS:** si no está en caché, consulta a un resolutor, normalmente proporcionado por el ISP.
    
3. **Servidor raíz (Root):** indica qué servidor TLD corresponde a la extensión del dominio.
    
4. **Servidor TLD:** indica qué servidor autoritativo gestiona el dominio.
    
5. **Servidor autoritativo:** proporciona la información DNS del dominio.
    
6. **Resolutor:** devuelve el resultado y lo almacena en caché durante un tiempo.
    
7. **Conexión:** el equipo utiliza la IP obtenida para conectarse al servidor.
    

**Flujo:** equipo → resolutor → raíz → TLD → autoritativo → resolutor → equipo.

## 2. Archivo `hosts`

Permite asociar manualmente nombres de host con direcciones IP, evitando la resolución DNS para esas entradas.

|Sistema|Ruta|
|---|---|
|Windows|`C:\Windows\System32\drivers\etc\hosts`|
|Linux|`/etc/hosts`|
|macOS|`/etc/hosts`|

### Formato

```
<IP>    <Hostname>    [Alias]
```

Ejemplo:

```
127.0.0.1       localhost
192.168.1.10    devserver.local
```

### Uso en HTB

Cuando una máquina requiere acceder a un servicio mediante un dominio, añade su IP y nombre al archivo `/etc/hosts`.

```
sudo nano /etc/hosts
```

Ejemplo:

```
10.129.100.50    target.htb
10.129.100.50    www.target.htb
```

Comprueba la resolución:

```
getent hosts target.htb
```

> **Importante:** sustituye las IP y los dominios por los correspondientes a tu objetivo. Las entradas de `hosts` son locales y no modifican el DNS público.

## 3. Conceptos fundamentales

|Concepto|Descripción|
|---|---|
|Dominio|Nombre legible, como `example.com`.|
|Dirección IP|Dirección numérica de un equipo o servicio.|
|Resolutor DNS|Servidor que realiza las consultas DNS.|
|Servidor raíz|Dirige las consultas hacia los servidores TLD.|
|Servidor TLD|Gestiona la información de extensiones como `.com` o `.org`.|
|Servidor autoritativo|Proporciona respuestas DNS autoritativas para una zona.|
|Zona DNS|Parte del espacio de nombres DNS gestionada administrativamente.|
|Archivo de zona|Define los registros DNS de una zona.|
|TTL|Tiempo durante el cual una respuesta puede mantenerse en caché.|

### Archivo de zona DNS

Ejemplo simplificado:

```
$TTL 3600

@   IN SOA   ns1.example.com. admin.example.com. (
    2024060401
    3600
    900
    604800
    86400
)

@       IN NS      ns1.example.com.
@       IN NS      ns2.example.com.
@       IN MX 10   mail.example.com.
www     IN A       192.0.2.1
mail    IN A       198.51.100.1
ftp     IN CNAME   www.example.com.
```

- `SOA`: información administrativa de la zona.
    
- `NS`: servidores de nombres.
    
- `MX`: servidor de correo.
    
- `A`: dirección IPv4.
    
- `CNAME`: alias de otro nombre de host.
    
- `IN`: clase Internet.

## 4. Tipos de registros DNS

|Registro|Función|Utilidad en reconocimiento|
|---|---|---|
|`A`|Asocia un nombre con una dirección IPv4.|Identificar direcciones de servidores.|
|`AAAA`|Asocia un nombre con una dirección IPv6.|Descubrir infraestructura IPv6.|
|`CNAME`|Crea un alias hacia otro nombre de host.|Identificar servicios externos o nombres relacionados.|
|`MX`|Especifica servidores de correo.|Identificar infraestructura de correo.|
|`NS`|Indica los servidores de nombres de una zona.|Identificar la gestión DNS del dominio.|
|`TXT`|Almacena información textual.|Detectar políticas, verificaciones y tecnologías utilizadas.|
|`SOA`|Contiene información administrativa de la zona.|Obtener datos sobre la administración DNS.|
|`SRV`|Define el destino y puerto de un servicio.|Descubrir servicios específicos.|
|`PTR`|Asocia una IP con un nombre mediante DNS inverso.|Investigar nombres relacionados con direcciones IP.|

### Datos que conviene recordar

- `A` → IPv4.
    
- `AAAA` → IPv6.
    
- `CNAME` → alias.
    
- `MX` → correo.
    
- `NS` → servidores DNS.
    
- `TXT` → texto y posibles políticas de seguridad.
    
- `SOA` → información administrativa.
    
- `SRV` → servicio y puerto.
    
- `PTR` → resolución inversa.

## 5. Importancia del DNS en el reconocimiento web

DNS puede revelar información útil para identificar y mapear la infraestructura de un objetivo.

### Descubrimiento de activos

Los registros pueden revelar:

- Subdominios y servidores adicionales.
    
- Servidores de correo.
    
- Servidores DNS.
    
- Alias que apuntan a otros sistemas.
    
- Servicios y tecnologías utilizados por la organización.
    

### Mapeo de infraestructura

Ejemplos:

```
mail.example.com       → posible servidor de correo
dev.example.com        → posible entorno de desarrollo
vpn.example.com        → posible punto de acceso remoto
loadbalancer.example.com → posible balanceador de carga
```

Estos nombres son pistas que deben investigarse; no demuestran por sí solos que exista una vulnerabilidad.

### Monitorización de cambios

Los cambios en los registros pueden revelar:

- Nuevos subdominios.
    
- Cambios de infraestructura.
    
- Nuevos servicios.
    
- Proveedores o herramientas utilizadas.
    

Por ejemplo, un registro `TXT` puede contener información relacionada con la verificación de dominios o políticas como SPF.

## 6. Checklist para el examen

- Comprender cómo funciona la resolución DNS.
    
- Saber dónde se encuentra el archivo `hosts` en Linux y Windows.
    
- Saber asociar un dominio a una IP mediante `/etc/hosts`.
    
- Diferenciar los servidores raíz, TLD y autoritativos.
    
- Entender la diferencia entre zona DNS y archivo de zona.
    
- Identificar los registros `A`, `AAAA`, `CNAME`, `MX`, `NS`, `TXT`, `SOA`, `SRV` y `PTR`.
    
- Utilizar los registros DNS como pistas para descubrir activos.
    
- Reconocer que los registros DNS pueden revelar información sobre la infraestructura de un objetivo.
    

**Idea clave:** DNS no solo permite resolver nombres de dominio; también constituye una fuente de información para descubrir servidores, servicios y posibles puntos de entrada durante el reconocimiento web.
