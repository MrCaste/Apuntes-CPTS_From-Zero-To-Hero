
## 1. Herramientas de reconocimiento DNS

|Herramienta|Función principal|
|---|---|
|`dig`|Consultar registros DNS y analizar respuestas detalladas.|
|`nslookup`|Realizar consultas DNS básicas.|
|`host`|Consultar registros DNS con una salida sencilla.|
|`dnsenum`|Automatizar la enumeración DNS, buscar subdominios y probar transferencias de zona.|
|`fierce`|Descubrir subdominios, realizar búsquedas recursivas y detectar comodines.|
|`dnsrecon`|Combinar técnicas de reconocimiento DNS y generar resultados en diferentes formatos.|
|`theHarvester`|Recopilar información OSINT, como correos electrónicos y datos asociados a un dominio.|

**Para el reconocimiento manual,** `**dig**` **es una de las herramientas principales.**

---

## 2. Consultas DNS con `dig`

### Consultas básicas

```
# Consulta DNS predeterminada
dig example.com

# Dirección IPv4
dig example.com A

# Dirección IPv6
dig example.com AAAA

# Servidores de correo
dig example.com MX

# Servidores de nombres
dig example.com NS

# Registros de texto
dig example.com TXT

# Alias DNS
dig example.com CNAME

# Información administrativa de la zona
dig example.com SOA
```

### Consultar un servidor DNS específico

```
dig @1.1.1.1 example.com
```

Permite realizar la consulta utilizando el servidor DNS indicado, en este caso `1.1.1.1`.

### Seguir la resolución DNS

```
dig +trace example.com
```

Muestra el recorrido de la resolución DNS a través de los distintos niveles de la jerarquía.

### Resolución DNS inversa

```
dig -x 192.168.1.1
```

Busca un registro PTR asociado a la dirección IP.

### Obtener respuestas reducidas

```
# Solo las respuestas
dig +short example.com

# Mostrar únicamente la sección ANSWER
dig +noall +answer example.com
```

Son especialmente útiles para automatizar consultas y procesar resultados desde scripts.

### Consultar todos los registros con ANY

```
dig example.com ANY
```

**Importante:** una consulta `ANY` no garantiza que se devuelvan todos los registros existentes. Muchos servidores limitan o ignoran estas consultas.

## 3. Interpretar la salida de `dig`

Ejemplo:

```
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 16449
;; flags: qr rd ad; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0

;; QUESTION SECTION:
;google.com.             IN      A

;; ANSWER SECTION:
google.com.      0       IN      A       142.251.47.142

;; Query time: 0 msec
;; SERVER: 172.23.176.1#53(172.23.176.1) (UDP)
;; MSG SIZE  rcvd: 54
```

### Campos importantes

|Campo|Significado|
|---|---|
|`status: NOERROR`|La consulta se procesó sin errores DNS.|
|`qr`|Indica que el mensaje es una respuesta.|
|`rd`|Se solicitó recursión.|
|`ad`|El resolutor indica que los datos son auténticos según DNSSEC.|
|`QUERY`|Número de preguntas DNS.|
|`ANSWER`|Número de registros en la respuesta.|
|`AUTHORITY`|Número de registros en la sección de autoridad.|
|`ADDITIONAL`|Número de registros adicionales.|
|`IN`|Clase Internet.|
|`A`|Tipo de registro consultado: IPv4.|
|`0`|TTL restante de la respuesta en este ejemplo.|
|`Query time`|Tiempo empleado en la consulta.|
|`SERVER`|Servidor DNS consultado y puerto utilizado.|
|`UDP`|Protocolo de transporte utilizado en este ejemplo.|
|`MSG SIZE`|Tamaño del mensaje DNS recibido.|

### Estados DNS que debes reconocer

- `NOERROR`: la consulta no produjo un error DNS. No implica necesariamente que exista una respuesta.
    
- `NXDOMAIN`: el nombre consultado no existe según la respuesta DNS.
    
- `SERVFAIL`: el servidor no pudo completar la consulta.
    

### Advertencias

Si aparece:

```
WARNING: recursion requested but not available
```

Significa que se solicitó recursión, pero el servidor consultado no la ofrece para esa consulta.

La sección `OPT` puede aparecer debido a EDNS, que amplía las capacidades del protocolo DNS, entre ellas el tamaño de los mensajes.

## 4. Ejemplo práctico

Consulta:

```
dig +short hackthebox.com
```

Posible resultado:

```
104.18.20.126
104.18.21.126
```

La opción `+short` muestra las direcciones obtenidas sin imprimir toda la información de la respuesta.

Para investigar un dominio durante el reconocimiento, puedes consultar diferentes tipos de registros:

```
dig +short example.com A
dig +short example.com AAAA
dig +short example.com MX
dig +short example.com NS
dig +short example.com TXT
```

Sustituye `example.com` por el dominio autorizado que estés investigando.

---

## 5. Flujo de trabajo para reconocimiento DNS

1. **Consultar la resolución básica:**
    
    ```
    dig dominio.com
    ```
    
2. **Identificar direcciones IPv4 e IPv6:**
    
    ```
    dig dominio.com A
    dig dominio.com AAAA
    ```
    
3. **Identificar servidores DNS y correo:**
    
    ```
    dig dominio.com NS
    dig dominio.com MX
    ```
    
4. **Buscar información adicional:**
    
    ```
    dig dominio.com TXT
    dig dominio.com SOA
    ```
    
5. **Consultar un resolutor específico si necesitas comparar respuestas:**
    
    ```
    dig @1.1.1.1 dominio.com
    ```
    
6. **Mostrar el recorrido de resolución:**
    
    ```
    dig +trace dominio.com
    ```
    
7. **Simplificar la salida para scripts:**
    
    ```
    dig +short dominio.com
    ```
    

> Realiza enumeraciones extensivas únicamente sobre objetivos autorizados y evita generar un volumen excesivo de consultas, ya que algunos servidores pueden limitar o bloquear las peticiones.

## 6. Chuleta rápida

|Objetivo|Comando|
|---|---|
|Consulta DNS básica|`dig dominio.com`|
|Obtener IPv4|`dig dominio.com A`|
|Obtener IPv6|`dig dominio.com AAAA`|
|Buscar servidores de correo|`dig dominio.com MX`|
|Buscar servidores DNS|`dig dominio.com NS`|
|Consultar registros TXT|`dig dominio.com TXT`|
|Consultar CNAME|`dig dominio.com CNAME`|
|Consultar SOA|`dig dominio.com SOA`|
|Usar un DNS concreto|`dig @1.1.1.1 dominio.com`|
|Seguir la resolución|`dig +trace dominio.com`|
|Resolver una IP inversamente|`dig -x IP`|
|Obtener una salida breve|`dig +short dominio.com`|
|Mostrar solo las respuestas|`dig +noall +answer dominio.com`|
|Consultar registros ANY|`dig dominio.com ANY`|

**Idea clave:** `dig` permite consultar registros DNS, identificar direcciones y servidores asociados a un dominio y analizar cómo se resuelven sus nombres. Estas consultas constituyen una base para las siguientes técnicas de reconocimiento de subdominios y zonas DNS.
