
## 1. ¿Qué es un subdominio?

Un **subdominio** es una extensión de un dominio principal que permite organizar diferentes servicios, aplicaciones o secciones de una infraestructura.

Ejemplos para `example.com`:

|Subdominio|Posible función|
|---|---|
|`blog.example.com`|Blog|
|`shop.example.com`|Tienda online|
|`mail.example.com`|Servicio de correo|
|`dev.example.com`|Entorno de desarrollo|
|`staging.example.com`|Entorno de pruebas|
|`admin.example.com`|Panel administrativo|

Desde el punto de vista de DNS, los subdominios pueden estar asociados a registros `A`, `AAAA` o `CNAME`.

- `A`: dirección IPv4.
    
- `AAAA`: dirección IPv6.
    
- `CNAME`: alias que apunta a otro nombre de dominio.
    

## 2. ¿Por qué son importantes en el reconocimiento web?

Los subdominios pueden exponer recursos que no están enlazados desde la página principal.

Durante un pentest, conviene investigar:

- **Entornos de desarrollo y pruebas:** pueden tener configuraciones de seguridad diferentes a las de producción.
    
- **Paneles de administración:** interfaces de gestión o autenticación.
    
- **Aplicaciones heredadas:** software antiguo que podría contener vulnerabilidades conocidas.
    
- **Información sensible:** documentos internos, archivos de configuración u otros recursos expuestos.
    

**Importante:** encontrar un subdominio no implica que sea vulnerable. Cada servicio descubierto debe investigarse por separado.

## 3. Enumeración de subdominios

La **enumeración de subdominios** consiste en identificar y recopilar los nombres de los subdominios asociados a un dominio principal.

Existen dos enfoques principales:

### 3.1. Enumeración activa

Interactúa directamente con la infraestructura DNS o realiza peticiones al objetivo.

#### A. Transferencia de zona DNS

Una transferencia de zona puede revelar múltiples registros DNS de un dominio si el servidor está mal configurado y permite transferencias no autorizadas.

Esta técnica se estudia en detalle en la sección de _DNS Zone Transfers_.

#### B. Fuerza bruta de subdominios

Consiste en probar sistemáticamente nombres de subdominios a partir de una lista de palabras (_wordlist_).

Ejemplo de posibles nombres:

```
www
dev
staging
admin
mail
vpn
api
test
```

Herramientas mencionadas en el módulo:

|Herramienta|Utilidad|
|---|---|
|`dnsenum`|Enumeración DNS automatizada.|
|`ffuf`|Automatización de pruebas con listas de palabras.|
|`gobuster`|Enumeración mediante listas de palabras.|

La eficacia depende de la lista utilizada, de la configuración DNS y de las restricciones del objetivo.

**Ventajas:** permite controlar las pruebas y descubrir nombres que no aparecen en fuentes públicas.

**Desventajas:** genera consultas o peticiones que pueden ser detectadas o limitadas.

### 3.2. Enumeración pasiva

Utiliza fuentes externas para descubrir subdominios sin consultar directamente los servidores DNS del objetivo.

#### A. Certificate Transparency (CT)

Los registros de transparencia de certificados contienen información pública sobre certificados SSL/TLS.

Los certificados pueden incluir nombres de dominio y subdominios en el campo **Subject Alternative Name (SAN)**.

Por ejemplo, un certificado podría contener:

```
example.com
www.example.com
dev.example.com
api.example.com
```

Estos nombres proporcionan pistas para ampliar el reconocimiento.

#### B. Motores de búsqueda

Se pueden utilizar operadores como `site:` para encontrar resultados asociados a un dominio.

Ejemplo:

```
site:example.com
```

La búsqueda puede ayudar a identificar páginas y subdominios indexados.

#### C. Bases de datos y herramientas online

Existen servicios que agregan información DNS procedente de distintas fuentes y permiten buscar subdominios sin interactuar directamente con la infraestructura objetivo.

**Ventajas:** menor interacción directa con el objetivo y posibilidad de encontrar nombres históricos o publicados previamente.

**Desventajas:** los resultados pueden estar incompletos o desactualizados.

## 4. Comparación: enumeración activa vs. pasiva

|Característica|Activa|Pasiva|
|---|---|---|
|Interacción directa con el objetivo|Sí|No necesariamente|
|Fuerza bruta|Puede utilizarse|No es el enfoque descrito|
|Fuentes externas|No es imprescindible|Principal fuente de información|
|Detectabilidad|Puede ser mayor|Generalmente menor|
|Exhaustividad|Depende de las técnicas y listas|Depende de la información disponible|
|Ejemplos|`dnsenum`, `ffuf`, `gobuster`|CT, buscadores, bases de datos DNS|

## 5. Metodología recomendada

Para realizar un reconocimiento organizado:

1. **Identificar el dominio principal.**
    
2. **Consultar fuentes pasivas:** registros CT, motores de búsqueda y bases de datos públicas.
    
3. **Recopilar los nombres descubiertos:** registrar cada subdominio encontrado.
    
4. **Realizar enumeración activa autorizada:** utilizar herramientas y listas de palabras adecuadas.
    
5. **Comparar los resultados:** eliminar duplicados y conservar los nombres únicos.
    
6. **Investigar cada subdominio:** comprobar qué servicio aloja y si expone recursos relevantes.
    
7. **Documentar los hallazgos:** registrar nombres, direcciones IP, servicios y posibles riesgos.
    

La combinación de técnicas activas y pasivas permite obtener una visión más completa de la superficie de ataque.

---

## 6. Chuleta para el examen

- **Subdominio:** extensión de un dominio principal que puede alojar otro servicio.
    
- **Enumeración activa:** interacción directa con la infraestructura o el objetivo.
    
- **Enumeración pasiva:** recopilación de información desde fuentes externas.
    
- **Fuerza bruta DNS:** probar nombres a partir de una _wordlist_.
    
- **Transferencia de zona:** puede revelar múltiples registros si está permitida.
    
- **Certificate Transparency:** permite descubrir nombres incluidos en certificados SSL/TLS.
    
- **SAN:** campo del certificado que puede contener varios nombres de dominio.
    
- `**site:**`**:** operador de búsqueda para localizar resultados asociados a un dominio.
    
- **Estrategia más completa:** combinar enumeración activa y pasiva.
    

**Idea clave:** los subdominios amplían la superficie de ataque de una organización. Descubrirlos permite identificar aplicaciones, entornos y servicios que no necesariamente son visibles desde el dominio principal.
