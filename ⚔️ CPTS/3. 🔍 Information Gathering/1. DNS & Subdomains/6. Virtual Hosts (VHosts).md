
## 1. ¿Qué son los Virtual Hosts?

Los **Virtual Hosts (VHosts)** permiten alojar varios sitios web o aplicaciones en un mismo servidor web y dirección IP.

El servidor utiliza la cabecera HTTP `Host` para determinar qué sitio debe servir en cada solicitud.

### Diferencias entre subdominios y VHosts

|Concepto|Descripción|
|---|---|
|**Subdominio**|Extensión de un dominio principal, por ejemplo, `blog.example.com`. Normalmente se configura mediante registros DNS.|
|**Virtual Host**|Configuración del servidor web que permite alojar y servir un sitio concreto.|
|**Host no público**|Puede no disponer de un registro DNS público, pero seguir configurado en el servidor web.|

**Importante:** un VHost puede utilizar un subdominio o un dominio completamente diferente. También puede ser accesible aunque no tenga un registro DNS público.

Si conocemos la IP del servidor, podemos descubrir posibles VHosts enviando solicitudes HTTP con diferentes valores en la cabecera `Host`. Esta técnica se conoce como **VHost fuzzing**.

## 2. Cómo funciona la cabecera Host

Cuando un navegador solicita una página, envía una petición HTTP que incluye el nombre del dominio:

```
GET / HTTP/1.1
Host: www.inlanefreight.com
```

El servidor web consulta su configuración de hosts virtuales y sirve el contenido correspondiente al nombre solicitado.

Por tanto, **dos solicitudes dirigidas a la misma IP pueden mostrar páginas diferentes si cambia la cabecera** `**Host**`.

## 3. Tipos de alojamiento virtual

|Tipo|Funcionamiento|Ventajas|Desventajas|
|---|---|---|---|
|Basado en nombres|Utiliza la cabecera HTTP `Host`.|Económico, flexible y permite compartir IP.|Puede tener limitaciones con determinados protocolos SSL/TLS.|
|Basado en IP|Asigna una IP diferente a cada sitio.|Aislamiento y compatibilidad con distintos protocolos.|Necesita varias direcciones IP.|
|Basado en puertos|Cada sitio utiliza un puerto diferente.|Permite alojar varios sitios con una misma IP.|Menos habitual y puede requerir especificar el puerto en la URL.|

## 4. Descubrimiento de VHosts con Gobuster

**Gobuster** permite probar nombres de host virtuales utilizando una lista de palabras y analizar las respuestas del servidor.

### Comando básico

```
gobuster vhost -u http://<IP_OBJETIVO> -w <WORDLIST> --append-domain
```

Parámetros:

|Parámetro|Función|
|---|---|
|`vhost`|Activa el modo de enumeración de hosts virtuales.|
|`-u`|URL del servidor objetivo.|
|`-w`|Ruta de la wordlist.|
|`--append-domain`|Añade el dominio base a cada palabra de la lista.|
|`-t`|Permite modificar el número de hilos.|
|`-k`|Ignora errores de certificados TLS.|
|`-o`|Guarda los resultados en un archivo.|

En versiones recientes, `--append-domain` permite construir correctamente nombres completos a partir de las palabras de la lista.

### Ejemplo de HTB Academy

```
gobuster vhost -u http://inlanefreight.htb:81 \
-w /usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt \
--append-domain
```

Resultado de ejemplo:

```
Found: forum.inlanefreight.htb:81 Status: 200 [Size: 100]
```

Esto indica que Gobuster ha encontrado una posible entrada para `forum.inlanefreight.htb` que devuelve el código HTTP `200`.

**No des por confirmado un VHost únicamente por aparecer en los resultados:** comprueba que la respuesta sea realmente diferente de la página predeterminada del servidor.

## 5. Comprobar un VHost manualmente

Puedes enviar una solicitud HTTP a una IP utilizando un nombre de host específico mediante `curl`:

```
curl -s -H "Host: forum.inlanefreight.htb" http://<IP_OBJETIVO>/
```

Si el servidor utiliza el puerto 81:

```
curl -s -H "Host: forum.inlanefreight.htb" http://<IP_OBJETIVO>:81/
```

También puedes utilizar `-i` para visualizar las cabeceras HTTP y el código de respuesta:

```
curl -i -H "Host: forum.inlanefreight.htb" http://<IP_OBJETIVO>:81/
```

### Acceder a un VHost sin DNS público

Si descubres un VHost que no resuelve mediante DNS, puedes añadirlo manualmente a `/etc/hosts` en Linux:

```
<IP_OBJETIVO> forum.inlanefreight.htb
```

Después podrás acceder al nombre desde el navegador o mediante herramientas como `curl`.

## 6. Wordlists para VHost fuzzing

Una lista de palabras adecuada permite probar nombres potenciales de hosts virtuales.

Ejemplo utilizado en el módulo:

```
/usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt
```

Puedes adaptar la lista según la información obtenida durante el reconocimiento.

## 7. Consideraciones durante el escaneo

- El VHost fuzzing puede generar una cantidad significativa de tráfico.
    
- Los IDS y los WAF pueden detectar estas solicitudes.
    
- Es necesario contar con autorización para escanear el objetivo.
    
- Comprueba los códigos HTTP, el tamaño de las respuestas y el contenido para identificar posibles falsos positivos.
    

## Cheat Sheet

|Objetivo|Comando|
|---|---|
|Enumerar VHosts|`gobuster vhost -u http://<IP> -w <WORDLIST> --append-domain`|
|Enumerar en un puerto específico|`gobuster vhost -u http://<IP>:81 -w <WORDLIST> --append-domain`|
|Probar un VHost manualmente|`curl -i -H "Host: <VHOST>" http://<IP>/`|
|Ignorar errores de certificado|Añadir `-k` a Gobuster cuando corresponda.|
|Guardar resultados|Añadir `-o resultados.txt` a Gobuster.|
|Asociar un dominio a una IP localmente|Añadir una entrada a `/etc/hosts`.|

**Idea clave para el examen:** la enumeración DNS busca nombres mediante el sistema DNS; el VHost fuzzing prueba nombres directamente contra el servidor web mediante la cabecera HTTP `Host`. Por eso puede descubrir sitios que no aparecen en los registros DNS públicos.
