
## 1. ¿Qué es el Fingerprinting?

El **fingerprinting** consiste en identificar las tecnologías utilizadas por un sitio web o una aplicación, como el servidor web, el sistema operativo, los CMS y los frameworks.

### ¿Para qué sirve?

- **Ataques dirigidos:** identificar tecnologías y buscar vulnerabilidades relacionadas.
    
- **Detectar configuraciones incorrectas:** localizar software desactualizado, configuraciones por defecto y posibles debilidades.
    
- **Priorizar objetivos:** identificar sistemas que requieren una investigación más detallada.
    
- **Ampliar el reconocimiento:** combinar los resultados con la información obtenida mediante DNS, subdominios y VHosts.
    

## 2. Técnicas de Fingerprinting

|Técnica|Descripción|
|---|---|
|Banner Grabbing|Recopila información que el servidor expone, como el software y su versión.|
|Análisis de cabeceras HTTP|Examina cabeceras como `Server` y `X-Powered-By`.|
|Sondeo de respuestas|Envía solicitudes específicas para identificar comportamientos característicos.|
|Análisis del contenido|Busca indicios tecnológicos en el HTML, los scripts, las rutas y otros recursos.|

### Cabeceras importantes

|Cabecera|Información que puede revelar|
|---|---|
|`Server`|Software y, en ocasiones, versión del servidor web.|
|`X-Powered-By`|Tecnología adicional, como un lenguaje o framework.|
|`X-Redirect-By`|Tecnología responsable de una redirección, como WordPress.|
|`Link`|Enlaces a recursos que pueden revelar información sobre la aplicación.|

No todos los servidores muestran estas cabeceras, y su contenido puede estar oculto o modificado.

## 3. Herramientas de Fingerprinting

|Herramienta|Función principal|
|---|---|
|Wappalyzer|Identifica tecnologías web mediante una extensión de navegador o su servicio en línea.|
|BuiltWith|Genera informes sobre las tecnologías utilizadas por un sitio web.|
|WhatWeb|Identifica tecnologías web mediante firmas conocidas.|
|Nmap|Permite identificar servicios, versiones y sistemas operativos, además de utilizar scripts NSE.|
|Netcraft|Proporciona información sobre tecnologías, hosting y seguridad web.|
|wafw00f|Detecta e identifica posibles Web Application Firewalls (WAF).|
|Nikto|Analiza servidores web y puede identificar tecnologías, archivos y configuraciones potencialmente inseguras.|

## 4. Banner Grabbing con curl

Podemos obtener las cabeceras HTTP de un sitio sin descargar el contenido completo de la página.

### Comando básico

```
curl -I http://inlanefreight.com
```

También podemos utilizar:

```
curl -I https://inlanefreight.com
```

La opción `-I` solicita las cabeceras de la respuesta HTTP.

### Ejemplo de respuesta

```
HTTP/1.1 301 Moved Permanently
Server: Apache/2.4.41 (Ubuntu)
Location: https://inlanefreight.com/
Content-Type: text/html; charset=iso-8859-1
```

**Interpretación:**

- `301 Moved Permanently`: redirección permanente.
    
- `Server: Apache/2.4.41 (Ubuntu)`: identifica el servidor y la versión anunciada.
    
- `Location`: indica la dirección de destino de la redirección.
    
- `Content-Type`: indica el tipo de contenido de la respuesta.
    

Podemos seguir las redirecciones manualmente repitiendo la consulta contra la dirección indicada en `Location`.

### Ejemplo de información sobre WordPress

```
HTTP/1.1 301 Moved Permanently
Server: Apache/2.4.41 (Ubuntu)
X-Redirect-By: WordPress
Location: https://www.inlanefreight.com/
```

La cabecera `X-Redirect-By` indica que WordPress está realizando la redirección.

Otras pistas de WordPress incluyen rutas como:

```
/wp-json/
/wp-login.php
/index.php/wp-json/
```

La presencia de estas rutas o cabeceras ayuda a identificar el CMS, aunque conviene confirmar los resultados mediante otras comprobaciones.

## 5. Detectar WAF con wafw00f

Un **Web Application Firewall (WAF)** filtra las solicitudes HTTP para proteger una aplicación web frente a determinados ataques.

Antes de realizar más pruebas, conviene comprobar si existe un WAF, ya que podría filtrar las solicitudes o bloquear parte del reconocimiento.

### Instalación indicada en el módulo

```
pip3 install git+https://github.com/EnableSecurity/wafw00f
```

### Ejecución

```
wafw00f inlanefreight.com
```

### Ejemplo de resultado

```
[+] The site https://inlanefreight.com is behind Wordfence (Defiant) WAF.
[~] Number of requests: 2
```

**Interpretación:** la herramienta identifica Wordfence, desarrollado por Defiant, como el WAF del sitio analizado.

## 6. Fingerprinting con Nikto

Nikto es un escáner de servidores web que puede identificar tecnologías, archivos interesantes y posibles configuraciones inseguras.

### Instalación indicada en el módulo

```
sudo apt update && sudo apt install -y perl
git clone https://github.com/sullo/nikto
cd nikto/program
chmod +x ./nikto.pl
```

En Pwnbox, Nikto ya viene preinstalado según el módulo.

### Ejecutar únicamente las pruebas de identificación de software

```
nikto -h inlanefreight.com -Tuning b
```

|Parámetro|Función|
|---|---|
|`-h`|Especifica el host objetivo.|
|`-Tuning b`|Ejecuta los módulos de identificación de software.|

### Hallazgos del ejemplo de HTB

|Hallazgo|Interpretación|
|---|---|
|Apache/2.4.41 (Ubuntu)|Tecnología y versión anunciada del servidor.|
|Instalación de WordPress|Identificación del CMS.|
|`/wp-login.php`|Ruta de inicio de sesión de WordPress.|
|`/license.txt`|Archivo que podría aportar información sobre el software utilizado.|
|Ausencia de `Strict-Transport-Security`|Falta una cabecera de seguridad relacionada con el uso de HTTPS.|
|Ausencia de `X-Content-Type-Options`|Falta una cabecera que ayuda a evitar la interpretación incorrecta de tipos MIME.|
|`X-Redirect-By: WordPress`|Indicio de que WordPress gestiona una redirección.|
|Advertencia sobre BREACH|Nikto señala un posible riesgo relacionado con la compresión HTTP; requiere validación.|

Nikto también identifica las direcciones IPv4 e IPv6 resueltas para el objetivo y proporciona información sobre el certificado TLS.

**Importante:** los hallazgos de Nikto son indicios que deben verificarse. Una advertencia no demuestra por sí sola que exista una vulnerabilidad explotable.

## 7. Flujo práctico de Fingerprinting

1. **Obtener las cabeceras HTTP:**
    
    ```
    curl -I http://<DOMINIO>
    ```
    
2. **Seguir las redirecciones:** comprobar los valores de `Location` y repetir las consultas cuando sea necesario.
    
3. **Identificar el servidor y el CMS:** analizar las cabeceras `Server`, `X-Powered-By`, `X-Redirect-By` y `Link`.
    
4. **Detectar un posible WAF:**
    
    ```
    wafw00f <DOMINIO>
    ```
    
5. **Identificar software y configuraciones potencialmente inseguras:**
    
    ```
    nikto -h <DOMINIO> -Tuning b
    ```
    
6. **Correlacionar los resultados:** utilizar las tecnologías identificadas para orientar la investigación posterior.

|---|---|

|Detectar un WAF|`wafw00f <DOMINIO>`|
|Ejecutar Nikto para identificar software|`nikto -h <DOMINIO> -Tuning b`|
|Buscar WordPress|Revisar `/wp-login.php`, `/wp-json/` y cabeceras como `X-Redirect-By`.|
|Identificar el servidor web|Examinar la cabecera `Server`.|

### Conceptos clave para el examen

- **Banner Grabbing:** obtener información del software anunciado por un servicio.
    
- `**curl -I**`**:** consultar las cabeceras HTTP.
    
- `**Server**`**:** puede revelar el servidor web y su versión.
    
- `**X-Powered-By**`**:** puede revelar tecnologías adicionales.
    
- `**wafw00f**`**:** identifica posibles WAF.
    
- `**nikto -Tuning b**`**:** ejecuta las pruebas de identificación de software.
    
- **Fingerprinting:** permite identificar tecnologías y orientar la búsqueda de posibles vulnerabilidades, pero no demuestra por sí solo que sean explotables.
    

**Idea clave:** combina las comprobaciones manuales con herramientas automatizadas. Las cabeceras, las rutas y las respuestas del servidor aportan pistas que, analizadas conjuntamente, permiten construir un perfil tecnológico del objetivo.
