
## 1. ¿Qué es un ataque híbrido?

Un **Hybrid Attack** combina técnicas de **Dictionary Attack** y **Brute Force** para probar variaciones de contraseñas basadas en patrones predecibles.

En lugar de generar todas las combinaciones posibles, se parte de una wordlist y se modifican sus entradas para obtener nuevas contraseñas candidatas.

### Ejemplo

Si la contraseña original es `Summer2023`, un usuario podría cambiarla por:

```
Summer2023
Summer2023!
Summer2024
```

Los ataques híbridos aprovechan estos cambios previsibles, como añadir números, caracteres especiales o modificar el año.

### Diferencias entre ataques

|Ataque|Funcionamiento|
|---|---|
|Brute Force|Prueba combinaciones de caracteres.|
|Dictionary Attack|Prueba contraseñas de una wordlist.|
|Hybrid Attack|Utiliza palabras de una wordlist y genera variaciones, como añadir números o caracteres especiales.|
|Credential Stuffing|Prueba credenciales obtenidas de filtraciones contra otros servicios.|

**Idea clave:** los ataques híbridos reducen el espacio de búsqueda frente a una fuerza bruta tradicional cuando se conocen patrones probables de las contraseñas.

## 2. Filtrar una wordlist con `grep` y expresiones regulares

En el ejercicio de HTB, la política de contraseñas exige:

- Longitud mínima de 8 caracteres.
    
- Al menos una letra mayúscula.
    
- Al menos una letra minúscula.
    
- Al menos un número.
    

Se utiliza la wordlist `darkweb2017_top-10000.txt` de SecLists y se filtra progresivamente con `grep -E`.

### Paso 1. Descargar la wordlist

```
wget https://raw.githubusercontent.com/danielmiessler/SecLists/refs/heads/master/Passwords/Common-Credentials/darkweb2017_top-10000.txt
```

### Paso 2. Filtrar por longitud mínima

```
grep -E '^.{8,}$' darkweb2017_top-10000.txt > darkweb2017-minlength.txt
```

**Expresión regular:**

```
^.{8,}$
```

- `^`: inicio de la línea.
    
- `.`: cualquier carácter.
    
- `{8,}`: al menos 8 caracteres.
    
- `$`: final de la línea.
    

El resultado se guarda en `darkweb2017-minlength.txt`.

### Paso 3. Filtrar por mayúsculas

```
grep -E '[A-Z]' darkweb2017-minlength.txt > darkweb2017-uppercase.txt
```

- `[A-Z]`: exige que exista al menos una letra mayúscula.
    
- `>`: guarda el resultado en un archivo, sobrescribiéndolo si ya existe.
    

### Paso 4. Filtrar por minúsculas

```
grep -E '[a-z]' darkweb2017-uppercase.txt > darkweb2017-lowercase.txt
```

- `[a-z]`: exige que exista al menos una letra minúscula.
    

### Paso 5. Filtrar por números

```
grep -E '[0-9]' darkweb2017-lowercase.txt > darkweb2017-number.txt
```

- `[0-9]`: exige que exista al menos un dígito numérico.
    

### Paso 6. Contar las contraseñas restantes

```
wc -l darkweb2017-number.txt
```

Resultado del ejercicio:

```
89 darkweb2017-number.txt
```

La lista inicial de aproximadamente 10.000 contraseñas se reduce a **89 entradas** que cumplen los requisitos de la política.

### Resumen de los filtros

|Requisito|Expresión regular|Archivo de salida|
|---|---|---|
|Mínimo 8 caracteres|`^.{8,}$`|`darkweb2017-minlength.txt`|
|Una mayúscula|`[A-Z]`|`darkweb2017-uppercase.txt`|
|Una minúscula|`[a-z]`|`darkweb2017-lowercase.txt`|
|Un número|`[0-9]`|`darkweb2017-number.txt`|

**Importante:** cada comando filtra el resultado del paso anterior. Por eso, el último archivo contiene contraseñas que cumplen los cuatro requisitos.

## 3. Credential Stuffing

El **Credential Stuffing** consiste en probar combinaciones de nombres de usuario y contraseñas obtenidas previamente, normalmente mediante filtraciones de datos, contra otros servicios.

Su objetivo es aprovechar la **reutilización de contraseñas**: si una persona utiliza las mismas credenciales en varias plataformas, una filtración puede permitir el acceso a otras cuentas.

### Funcionamiento

1. **Obtención de credenciales:** se consiguen nombres de usuario y contraseñas procedentes de filtraciones u otras fuentes.
    
2. **Selección de objetivos:** se identifican otros servicios donde los usuarios podrían tener cuentas.
    
3. **Automatización:** se prueban las credenciales obtenidas contra los servicios seleccionados.
    
4. **Acceso:** si las credenciales siguen siendo válidas, puede producirse un acceso no autorizado.
    

### Credential Stuffing vs. Dictionary Attack

|Característica|Credential Stuffing|Dictionary Attack|
|---|---|---|
|Datos utilizados|Pares de usuario y contraseña obtenidos previamente.|Lista de contraseñas candidatas.|
|Objetivo|Aprovechar credenciales reutilizadas.|Encontrar una contraseña incluida en la wordlist.|
|Reutilización de contraseñas|Es fundamental para su éxito.|No es un requisito.|
|Fuente habitual|Filtraciones de credenciales.|Wordlists públicas o personalizadas.|

### Medidas defensivas

- Utilizar contraseñas fuertes y únicas para cada servicio.
    
- Activar la autenticación multifactor (**MFA**).
    
- Evitar reutilizar contraseñas.
    
- Vigilar intentos de autenticación sospechosos.

## 4. Comandos importantes para el examen

### Descargar archivos

```
wget URL
```

Descarga un archivo desde una URL.

### Filtrar líneas mediante expresiones regulares

```
grep -E 'REGEX' archivo.txt
```

Busca líneas que coincidan con una expresión regular extendida.

### Guardar resultados en otro archivo

```
grep -E 'REGEX' entrada.txt > salida.txt
```

Filtra el archivo de entrada y guarda las coincidencias en el archivo de salida.

### Contar líneas

```
wc -l archivo.txt
```

Cuenta las líneas del archivo. En este ejercicio, se utiliza para conocer cuántas contraseñas quedan después de aplicar los filtros.

### Expresiones regulares utilizadas

```
^.{8,}$
[A-Z]
[a-z]
[0-9]
```

|Expresión|Significado|
|---|---|
|`^`|Inicio de línea.|
|`.`|Cualquier carácter.|
|`{8,}`|Ocho o más repeticiones.|
|`$`|Final de línea.|
|`[A-Z]`|Una letra mayúscula.|
|`[a-z]`|Una letra minúscula.|
|`[0-9]`|Un dígito numérico.|

## 5. Resumen para el examen

- **Hybrid Attack:** combina wordlists con variaciones de contraseñas, como números, caracteres especiales o años.
    
- **Dictionary Attack:** prueba contraseñas de una lista predefinida.
    
- **Brute Force:** genera combinaciones de caracteres.
    
- **Credential Stuffing:** prueba credenciales filtradas contra otros servicios, aprovechando la reutilización de contraseñas.
    
- `**grep -E**`**:** filtra líneas mediante expresiones regulares extendidas.
    
- `**^.{8,}$**`**:** selecciona líneas de al menos 8 caracteres.
    
- `**[A-Z]**`**:** exige una mayúscula.
    
- `**[a-z]**`**:** exige una minúscula.
    
- `**[0-9]**`**:** exige un número.
    
- `**>**`**:** redirige la salida a un archivo.
    
- `**wc -l**`**:** cuenta las líneas de un archivo.
    
- **MFA:** añade un factor de autenticación adicional y ayuda a proteger cuentas aunque una contraseña haya sido comprometida.
    

### Idea fundamental

> Los ataques híbridos explotan patrones predecibles en las contraseñas; el Credential Stuffing aprovecha credenciales válidas reutilizadas. Filtrar una wordlist con `grep` permite reducirla a contraseñas que cumplen una política determinada.
