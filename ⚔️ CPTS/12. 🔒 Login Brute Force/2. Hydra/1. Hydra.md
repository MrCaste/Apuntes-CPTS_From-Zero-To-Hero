
## 1. ¿Qué es Hydra?

**Hydra** es una herramienta de fuerza bruta para probar credenciales contra diferentes servicios de red. Permite realizar múltiples intentos de autenticación en paralelo y es compatible con numerosos protocolos.

### Características principales

- **Velocidad:** utiliza tareas paralelas para realizar varios intentos simultáneamente.
    
- **Flexibilidad:** admite servicios como SSH, FTP, HTTP, SMTP, MySQL y RDP.
    
- **Facilidad de uso:** funciona desde la terminal mediante parámetros y módulos específicos para cada servicio.
    

### Comprobar si está instalado

```
hydra -h
```

### Instalar en Debian/Kali Linux

```
sudo apt-get -y update
sudo apt-get -y install hydra
```

## 2. Sintaxis básica

```
hydra [login_options] [password_options] [attack_options] [service_options]
```

### Parámetros principales

|Parámetro|Función|Ejemplo|
|---|---|---|
|`-l LOGIN`|Especifica un único nombre de usuario.|`-l admin`|
|`-L FILE`|Utiliza un archivo con nombres de usuario.|`-L usernames.txt`|
|`-p PASS`|Especifica una única contraseña.|`-p password123`|
|`-P FILE`|Utiliza un archivo con contraseñas.|`-P passwords.txt`|
|`-t TASKS`|Define el número de tareas paralelas.|`-t 4`|
|`-f`|Detiene el ataque al encontrar el primer inicio de sesión válido, según el alcance del objetivo y el comando.|`-f`|
|`-s PORT`|Especifica un puerto no predeterminado.|`-s 2121`|
|`-v`|Activa una salida detallada.|`-v`|
|`-V`|Muestra los intentos de autenticación.|`-V`|
|`-M FILE`|Lee los objetivos desde un archivo.|`-M targets.txt`|
|`-x MIN:MAX:CHARSET`|Genera contraseñas según longitudes y caracteres especificados.|`-x 6:8:abc123`|

**Diferencia importante:**

- `-l` y `-p`: un usuario y una contraseña.
    
- `-L` y `-P`: archivos con listas de usuarios y contraseñas.

## 3. Servicios compatibles

Hydra utiliza módulos específicos para interactuar con los mecanismos de autenticación de cada servicio.

|Módulo|Servicio|Uso|
|---|---|---|
|`ftp`|FTP|Autenticación en servicios de transferencia de archivos.|
|`ssh`|SSH|Autenticación remota mediante SSH.|
|`http-get`|HTTP GET|Autenticación HTTP mediante solicitudes GET.|
|`http-post-form`|Formularios HTTP POST|Prueba de credenciales en formularios web.|
|`smtp`|SMTP|Autenticación en servidores de correo saliente.|
|`pop3`|POP3|Autenticación en servicios de recepción de correo.|
|`imap`|IMAP|Autenticación para acceder al correo electrónico.|
|`mysql`|MySQL|Autenticación en bases de datos MySQL.|
|`mssql`|Microsoft SQL Server|Autenticación en bases de datos SQL Server.|
|`vnc`|VNC|Autenticación en servicios de escritorio remoto.|
|`rdp`|RDP|Autenticación en servicios de Escritorio remoto.|

La sintaxis y los parámetros pueden variar según el módulo y el tipo de autenticación.

## 4. Fuerza bruta contra autenticación HTTP

El ejercicio plantea un sitio web con autenticación HTTP y dos archivos:

- `usernames.txt`: nombres de usuario.
    
- `passwords.txt`: contraseñas candidatas.
    

### Comando

```
hydra -L usernames.txt -P passwords.txt www.example.com http-get
```

### Funcionamiento

1. `-L usernames.txt`: carga los nombres de usuario.
    
2. `-P passwords.txt`: carga las contraseñas.
    
3. `www.example.com`: especifica el objetivo.
    
4. `http-get`: selecciona el módulo de autenticación HTTP GET.
    

Hydra prueba combinaciones de usuarios y contraseñas para identificar credenciales válidas.

**Importante:** `http-get` se utiliza en escenarios de autenticación HTTP compatibles con ese módulo. No es equivalente a atacar cualquier formulario de inicio de sesión web.

## 5. Atacar múltiples servidores SSH

Si se dispone de varios servidores de laboratorio, sus direcciones IP pueden almacenarse en `targets.txt`.

Ejemplo de contenido:

```
192.168.1.101
192.168.1.102
192.168.1.103
```

### Comando del ejercicio

```
hydra -l root -p toor -M targets.txt ssh
```

### Funcionamiento

- `-l root`: utiliza el usuario `root`.
    
- `-p toor`: utiliza la contraseña `toor`.
    
- `-M targets.txt`: carga los objetivos desde un archivo.
    
- `ssh`: selecciona el módulo SSH.
    

Hydra prueba las credenciales especificadas contra los servidores enumerados.

## 6. Probar credenciales FTP en un puerto no estándar

El ejercicio plantea un servidor FTP que escucha en el puerto `2121`.

### Comando

```
hydra -L usernames.txt -P passwords.txt -s 2121 -V ftp.example.com ftp
```

### Funcionamiento

- `-L usernames.txt`: carga la lista de usuarios.
    
- `-P passwords.txt`: carga la lista de contraseñas.
    
- `-s 2121`: especifica el puerto del servicio.
    
- `-V`: muestra los intentos.
    
- `ftp.example.com`: indica el servidor objetivo.
    
- `ftp`: selecciona el módulo FTP.
    

**Idea clave:** utiliza `-s` cuando el servicio escucha en un puerto diferente del habitual.

## 7. Fuerza bruta contra un formulario web

Los formularios web pueden utilizar autenticación mediante parámetros enviados en una solicitud HTTP POST.

El ejercicio plantea:

- Usuario conocido: `admin`.
    
- Endpoint: `/login`.
    
- Campo del usuario: `user`.
    
- Campo de la contraseña: `pass`.
    
- Condición de éxito: respuesta HTTP `302`.
    

### Comando del ejercicio

```
hydra -l admin -P passwords.txt www.example.com http-post-form "/login:user=^USER^&pass=^PASS^:S=302"
```

### Estructura de `http-post-form`

```
"/ruta:datos_del_formulario:condición"
```

En el ejemplo:

```
/login:user=^USER^&pass=^PASS^:S=302
```

|Elemento|Significado|
|---|---|
|`/login`|Ruta del formulario de autenticación.|
|`user=^USER^`|Campo del usuario; Hydra sustituye `^USER^` por el nombre de usuario probado.|
|`pass=^PASS^`|Campo de la contraseña; Hydra sustituye `^PASS^` por cada contraseña candidata.|
|`S=302`|Indica que una respuesta HTTP 302 se considera una señal de éxito.|

### Diferencia entre `S=` y `F=`

- `S=`: define una condición que indica un posible **éxito**.
    
- `F=`: define una condición que indica un posible **fallo**.
    

Por ejemplo, si el formulario devuelve el mensaje `Invalid password` cuando las credenciales son incorrectas, puede utilizarse una condición de fallo basada en ese texto.

**Importante:** el código HTTP 302 no garantiza por sí solo que la autenticación haya tenido éxito. Hay que comprobar cómo responde realmente la aplicación a las credenciales válidas e inválidas.

## 8. Fuerza bruta con generación de contraseñas

Hydra permite generar contraseñas automáticamente mediante `-x`, sin necesidad de utilizar una wordlist.

### Ejemplo del ejercicio

```
hydra -l administrator -x 6:8:abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789 192.168.1.100 rdp
```

### Funcionamiento de `-x`

```
-x MIN:MAX:CHARSET
```

|Elemento|Significado|
|---|---|
|`6`|Longitud mínima.|
|`8`|Longitud máxima.|
|`abcdefghijklmnopqrstuvwxyz`|Letras minúsculas.|
|`ABCDEFGHIJKLMNOPQRSTUVWXYZ`|Letras mayúsculas.|
|`0123456789`|Dígitos numéricos.|

El comando genera contraseñas de entre 6 y 8 caracteres con el conjunto especificado y las prueba contra el servicio RDP del objetivo.

**Advertencia:** el número de combinaciones puede crecer enormemente. Con 62 caracteres posibles, incluso las longitudes indicadas implican un espacio de búsqueda muy grande.

## 10. Puntos clave para el examen CPTS/OSCP

- **Hydra** automatiza intentos de autenticación contra múltiples servicios.
    
- `-l` y `-p` permiten especificar credenciales individuales.
    
- `-L` y `-P` permiten utilizar wordlists.
    
- `-M` permite definir múltiples objetivos mediante un archivo.
    
- `-s` permite especificar un puerto no estándar.
    
- `-t` controla el número de tareas paralelas.
    
- `-V` muestra los intentos realizados.
    
- `-x` genera contraseñas según la longitud y los caracteres definidos.
    
- `http-get` y `http-post-form` corresponden a mecanismos de autenticación HTTP diferentes.
    
- En `http-post-form`, hay que identificar correctamente la ruta, los nombres de los campos y la condición que indica éxito o fallo.
    
- Una redirección HTTP `302` no demuestra automáticamente que se haya iniciado sesión correctamente.
    
- Las pruebas deben realizarse únicamente contra sistemas propios o entornos donde exista autorización explícita.
    

### Idea fundamental

> Para utilizar Hydra correctamente, primero identifica el servicio y su mecanismo de autenticación. Después selecciona el módulo adecuado, define las credenciales o wordlists y determina cómo reconocer una autenticación exitosa.
