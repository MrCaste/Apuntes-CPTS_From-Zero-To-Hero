
## 1. Filtros no recursivos de Path Traversal

Algunas aplicaciones utilizan filtros que eliminan la cadena `../` para evitar ataques de Directory Traversal.

Ejemplo de código vulnerable:

```
$language = str_replace('../', '', $_GET['language']);
```

El problema es que `str_replace()` elimina las coincidencias encontradas, pero no vuelve a analizar recursivamente el resultado.

### Bypass mediante secuencias anidadas

Entrada original:

```
....//
```

Al eliminar la subcadena `../`, puede quedar:

```
../
```

Por tanto, podemos intentar utilizar secuencias como:

```
....//....//....//....//etc/passwd
```

Ejemplo de petición:

```
/index.php?language=....//....//....//....//etc/passwd
```

### Otras variantes

El módulo también menciona variantes como:

```
..././
..../
....////
```

**Idea clave:** si el filtro elimina `../` una sola vez, comprueba si el resultado todavía contiene secuencias de Directory Traversal.

## 2. Bypass mediante codificación URL

Algunos filtros bloquean caracteres como:

- `.` — punto.
    
- `/` — barra diagonal.
    

Una posible técnica consiste en codificar los caracteres para comprobar si el filtro se aplica antes de que la aplicación decodifique la entrada.

### Codificación de `../`

|Carácter|Codificación URL|
|---|---|
|`.`|`%2e`|
|`/`|`%2f`|
|`../`|`%2e%2e%2f`|

Ejemplo de ruta codificada:

```
%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd
```

Petición de ejemplo:

```
/index.php?language=%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd
```

Para analizar y codificar parámetros puedes utilizar el **Decoder de Burp Suite**.

### Doble codificación

También se puede probar una segunda codificación de la cadena resultante.

Sin embargo, el resultado depende del orden en el que se apliquen los filtros y las decodificaciones. La doble codificación no garantiza que se pueda eludir la protección.

**Importante:** las técnicas de codificación URL dependen de cómo procese la entrada la aplicación y de la versión de PHP.

## 3. Rutas aprobadas mediante expresiones regulares

Algunas aplicaciones restringen las rutas que se pueden incluir mediante expresiones regulares.

Ejemplo del módulo:

```
if (preg_match('/^\./languages/.+$/', $_GET['language'])) {
    include($_GET['language']);
} else {
    echo 'Illegal path specified!';
}
```

La intención es permitir únicamente rutas que comiencen con el directorio de idiomas.

### Análisis de la restricción

Para investigar esta protección:

1. Identifica qué rutas utiliza la aplicación durante su funcionamiento normal.
    
2. Examina las peticiones enviadas por los formularios.
    
3. Determina cómo se valida el parámetro.
    
4. Comprueba si la validación impide realmente acceder a rutas fuera del directorio permitido.
    

El módulo muestra la siguiente combinación de ruta aprobada y Directory Traversal:

```
./languages/../../../../etc/passwd
```

Ejemplo de petición:

```
/index.php?language=./languages/../../../../etc/passwd
```

La idea es comenzar con el prefijo esperado y comprobar si los segmentos `../` permiten escapar del directorio previsto.

### Combinación de técnicas

Si existen varias restricciones, puede ser necesario analizar conjuntamente:

- El prefijo de la ruta.
    
- Los filtros de `../`.
    
- La codificación URL.
    
- Las validaciones mediante expresiones regulares.
    

No todos los bypasses funcionan en todas las aplicaciones.

## 4. Extensiones añadidas automáticamente

Algunas aplicaciones añaden una extensión al parámetro antes de incluir el archivo:

```
include($_GET['language'] . ".php");
```

Esto puede impedir la inclusión directa de archivos que no tengan esa extensión.

En las versiones modernas de PHP, las técnicas históricas de truncamiento de rutas y bytes nulos descritas a continuación ya no constituyen bypasses válidos en las condiciones indicadas por el módulo.

Aun así, es importante reconocerlas en aplicaciones antiguas.

---

## 5. Truncamiento de rutas (Path Truncation)

Según el módulo, versiones antiguas de PHP limitaban determinadas cadenas de ruta a **4096 caracteres**.

Cuando se superaba ese límite, la cadena podía truncarse y eliminar la parte final de la ruta.

El módulo también señala que:

- Las barras diagonales finales y los puntos individuales podían eliminarse en determinadas circunstancias.
    
- Varias barras diagonales podían interpretarse como una sola.
    
- El segmento `.` podía representar el directorio actual y ser ignorado en una ruta.
    

### Ejemplos de normalización de rutas

```
/etc/./passwd
```

Puede resolverse como:

```
/etc/passwd
```

De manera similar, en sistemas que normalizan las rutas de esa forma:

```
////etc/passwd
```

Puede hacer referencia a:

```
/etc/passwd
```

### Limitaciones

La técnica de truncamiento descrita en el módulo depende de versiones antiguas de PHP y de su comportamiento al procesar las rutas.

No debe asumirse que funciona en versiones modernas.

---

## 6. Inyección de bytes nulos (Null Byte Injection)

Un byte nulo se representa en una URL como:

```
%00
```

Históricamente, determinadas versiones antiguas de PHP permitían que un byte nulo terminara una cadena utilizada para construir una ruta.

Ejemplo conceptual:

```
/etc/passwd%00
```

Si una aplicación añadía posteriormente `.php`, la técnica histórica pretendía que la cadena se interpretara sin el sufijo añadido.

### Lo que debes recordar

- La técnica dependía de versiones antiguas de PHP.
    
- El módulo señala versiones anteriores a PHP 5.5 como vulnerables a este comportamiento.
    
- No debe considerarse un bypass funcional en versiones modernas.
    
- La presencia de `%00` no garantiza que una aplicación permita leer un archivo.

## 8. Chuleta para el examen

|Técnica|Concepto clave|
|---|---|
|Filtro no recursivo|Elimina `../` una vez, pero puede dejar secuencias válidas en el resultado.|
|Secuencias anidadas|Utilizan patrones que pueden transformarse en `../` después del filtrado.|
|Codificación URL|Representa caracteres mediante secuencias como `%2e` y `%2f`.|
|Doble codificación|Codifica una cadena que ya estaba codificada; depende del procesamiento de la aplicación.|
|Ruta aprobada|La aplicación intenta restringir la inclusión a un directorio permitido.|
|Path Traversal|Permite intentar salir de un directorio mediante segmentos `../`.|
|Path Truncation|Técnica histórica basada en límites de longitud de rutas en versiones antiguas de PHP.|
|Null Byte Injection|Técnica histórica que aprovechaba el tratamiento del byte nulo para terminar cadenas.|

### Idea clave

**No te limites a probar** `**../../../etc/passwd**`**.** Analiza cómo se construye la ruta, en qué orden se aplican los filtros y si la aplicación añade prefijos o extensiones. Las técnicas históricas deben distinguirse de los bypasses que realmente podrían funcionar en la versión y configuración del servidor evaluado.
