
## 1. Concepto

**Local File Inclusion (LFI)** es una vulnerabilidad que permite acceder o incluir archivos locales del servidor mediante parámetros controlados por el usuario.

Es habitual encontrarla en parámetros que seleccionan archivos o plantillas:

```
http://SERVER_IP:PORT/index.php?language=es.php
```

Si la aplicación utiliza el parámetro `language` para incluir archivos sin validarlo correctamente, podemos intentar acceder a otros archivos locales.

## 2. LFI básico

### Identificar el parámetro vulnerable

Ejemplo:

```
/index.php?language=es.php
```

Podemos probar rutas de archivos habituales.

**Linux:**

```
/etc/passwd
```

**Windows:**

```
C:\Windows\boot.ini
```

Si la aplicación permite leer el archivo, podría ser vulnerable a LFI.

### Ejemplo de PHP vulnerable

```
include($_GET['language']);
```

El valor del parámetro se pasa directamente a `include()`.

Ejemplo de prueba:

```
/index.php?language=/etc/passwd
```

Si funciona, podremos ver el contenido del archivo, siempre que el proceso del servidor tenga acceso a él.

## 3. Directory Traversal (Path Traversal)

Una aplicación puede añadir un directorio fijo a la entrada del usuario:

```
include("./languages/" . $_GET['language']);
```

Si introducimos `/etc/passwd`, la ruta resultante podría ser:

```
./languages//etc/passwd
```

Esa ruta no apunta necesariamente al archivo deseado.

### Utilizar `../`

La secuencia `../` permite retroceder un directorio en una ruta relativa.

Ejemplo de directorio inicial:

```
/var/www/html/languages/
```

Para llegar a la raíz del sistema, podemos utilizar:

```
../../../..
```

Después, indicamos la ruta del archivo.

Ejemplo para el laboratorio:

```
/index.php?language=../../../../etc/passwd
```

### Regla práctica

|Directorio inicial|Niveles hasta `/`|
|---|---|
|`/var/www/html/languages/`|4|
|`/var/www/html/`|3|
|`/var/www/`|2|
|`/var/`|1|

**Consejo:** utiliza el número mínimo de `../` necesario cuando conozcas la ubicación inicial.

## 4. Prefijo en el nombre del archivo

La aplicación puede añadir un prefijo a la entrada:

```
include("lang_" . $_GET['language']);
```

Si introducimos:

```
../../../etc/passwd
```

La ruta resultante sería:

```
lang_../../../etc/passwd
```

Esto puede provocar un error porque la ruta no es válida.

El módulo muestra como posible alternativa anteponer una barra:

```
/index.php?language=/../../../etc/passwd
```

**Importante:** no es un bypass universal. El resultado depende de cómo se construya la ruta y de los directorios existentes.

Además, los prefijos pueden dificultar otras técnicas de inclusión de archivos, como los filtros y wrappers de PHP o la inclusión remota de archivos (RFI).

## 5. Extensiones añadidas automáticamente

Otra implementación frecuente es:

```
include($_GET['language'] . ".php");
```

La aplicación añade automáticamente `.php`.

Si introducimos:

```
/etc/passwd
```

La ruta resultante será:

```
/etc/passwd.php
```

Como normalmente ese archivo no existe, la inclusión falla.

En las siguientes secciones del módulo se estudian técnicas para abordar las restricciones relacionadas con las extensiones.

## 6. LFI y código fuente PHP

El módulo plantea comprobar si podemos leer el código fuente de un archivo PHP, como `index.php`.

Hay que distinguir dos comportamientos:

- **Incluir un archivo PHP:** el servidor puede ejecutar su código y devolver el resultado renderizado.
    
- **Leer el código fuente:** permite ver el contenido original del archivo PHP.
    

Por tanto, conseguir que se incluya un archivo PHP no significa necesariamente que podamos visualizar su código fuente.

Los filtros de PHP, que se estudian en otra sección, permiten abordar este escenario.

## 7. Ataques de segundo orden (Second-Order LFI)

Un ataque LFI de segundo orden ocurre cuando almacenamos una entrada controlada por el usuario y otra funcionalidad de la aplicación la utiliza posteriormente para construir una ruta.

### Ejemplo conceptual

1. La aplicación permite registrar un nombre de usuario.
    
2. El nombre se almacena en una base de datos.
    
3. Otra funcionalidad utiliza ese nombre para construir la ruta de un archivo.
    
4. La aplicación procesa la ruta sin validarla correctamente.
    
5. El valor almacenado puede influir en el archivo que intenta abrir.
    

La entrada no necesita explotar la vulnerabilidad inmediatamente: puede almacenarse primero y utilizarse después.

### Dónde buscar

- Nombres de usuario utilizados en rutas.
    
- Avatares o imágenes de perfiles.
    
- Funcionalidades de descarga.
    
- Archivos cuyo nombre depende de datos almacenados.
    
- Valores recuperados de una base de datos y utilizados para construir rutas.
    

### LFI directo frente a LFI de segundo orden

|Característica|LFI directo|LFI de segundo orden|
|---|---|---|
|Entrada|Normalmente un parámetro de la petición|Puede almacenarse previamente|
|Explotación|Durante la petición inicial|Cuando otra funcionalidad reutiliza el valor|
|Ejemplo|`?language=...`|Nombre de usuario utilizado para construir una ruta|
|Investigación|Identificar el parámetro vulnerable|Seguir el dato desde su almacenamiento hasta su uso|

## 8. Metodología de enumeración

```
Identificar parámetros que seleccionan archivos
                  |
                  v

                  |
                  v

                  |
                  v

                  |
                  v

                  |
                  v

                  |
                  v

```

## 9. Chuleta para el examen

|Concepto|Qué recordar|
|---|---|
|LFI|Inclusión o acceso inseguro a archivos locales mediante entradas controladas.|
|`include()`|En PHP, incluye y procesa un archivo.|
|`../`|Retrocede un directorio en una ruta relativa.|
|Ruta absoluta|Especifica una ubicación completa, como `/etc/passwd`.|
|Prefijo|Texto añadido antes del valor proporcionado por el usuario.|
|Extensión automática|Sufijo añadido a la entrada, como `.php`.|
|LFI de segundo orden|Una entrada almacenada se utiliza posteriormente para construir una ruta vulnerable.|
|Código fuente PHP|No siempre es visible al incluir el archivo; puede ejecutarse en el servidor.|

### Idea clave

**No basta con encontrar un parámetro que acepte nombres de archivos.** Hay que averiguar cómo se construye la ruta, qué restricciones se aplican y si la aplicación incluye el archivo, lo ejecuta o permite leer su contenido.
