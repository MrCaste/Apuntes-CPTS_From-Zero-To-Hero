
## 1. PHP Wrappers

Los **PHP Wrappers** permiten acceder y manipular diferentes flujos de entrada/salida (streams) de PHP. En una vulnerabilidad **LFI (Local File Inclusion)**, pueden utilizarse para ampliar las posibilidades de explotación, por ejemplo:

- Leer el código fuente de archivos PHP.
    
- Acceder a información sensible presente en el código.
    
- En determinados escenarios, avanzar hacia la ejecución remota de código (RCE).
    

El wrapper principal de esta sección es:

```
php://filter/
```

Se utiliza para aplicar filtros al contenido de un recurso, como un archivo local.

---

## 2. Estructura de `php://filter`

La estructura utilizada en el módulo es:

```
php://filter/read=FILTRO/resource=ARCHIVO
```

|Parámetro|Función|
|---|---|
|`php://filter/`|Accede al wrapper de filtros de PHP.|
|`read=`|Especifica el filtro que se aplicará durante la lectura.|
|`convert.base64-encode`|Codifica el contenido del recurso en Base64.|
|`resource=`|Especifica el archivo o flujo al que se aplica el filtro.|

PHP dispone de diferentes categorías de filtros, como filtros de cadena, conversión, compresión y cifrado.

Para leer código fuente mediante LFI, el filtro más importante de esta sección es `**convert.base64-encode**`.

---

## 3. Enumeración de archivos PHP con FFUF

Antes de leer el código fuente, necesitamos identificar posibles archivos PHP existentes en la aplicación.

Podemos utilizar `ffuf` junto con una wordlist de SecLists:

```
ffuf -w /opt/useful/seclists/Discovery/Web-Content/directory-list-2.3-small.txt:FUZZ \
-u http://<SERVER_IP>:<PORT>/FUZZ.php
```

Ejemplo de resultados:

```
index     [Status: 200, Size: 2652, Words: 690, Lines: 64]
config    [Status: 302, Size: 0, Words: 1, Lines: 1]
```

### Consideraciones importantes

- No te limites a los códigos HTTP `200`.
    
- También pueden ser interesantes las respuestas `301`, `302` y `403`.
    
- Una respuesta HTTP no determina por sí sola si el código fuente del archivo puede leerse mediante LFI.
    
- Examina los archivos encontrados en busca de referencias a otros archivos PHP.
    
- Repite la enumeración con los nombres descubiertos para ampliar el mapa de la aplicación.
    

**Objetivo:** construir una lista de archivos PHP que puedan revelar información relevante sobre la aplicación.

## 4. Inclusión normal de archivos PHP

Si incluimos un archivo PHP mediante una vulnerabilidad LFI, normalmente se ejecutará su código en lugar de mostrarse directamente su código fuente.

Por ejemplo:

```
http://<SERVER_IP>:<PORT>/index.php?language=config
```

Si la aplicación añade automáticamente la extensión `.php`, intentará incluir:

```
config.php
```

Si `config.php` únicamente define variables o configuraciones y no genera contenido HTML, la respuesta podría aparecer vacía.

Esto dificulta la lectura del código fuente mediante una inclusión normal.

### Problema

```
LFI → include(config.php) → ejecución del PHP
```

El servidor ejecuta el archivo, pero no necesariamente muestra su contenido.

### Solución

Utilizar `php://filter` para codificar el contenido del archivo en Base64 antes de que sea interpretado como una página PHP normal.

---

## 5. Lectura del código fuente con Base64

Para leer el código fuente de `config.php`, utilizamos:

```
php://filter/read=convert.base64-encode/resource=config
```

Si la aplicación añade automáticamente `.php`, la petición completa sería:

```
http://<SERVER_IP>:<PORT>/index.php?language=php://filter/read=convert.base64-encode/resource=config
```

### ¿Por qué funciona?

1. `php://filter/` activa el wrapper de filtros.
    
2. `read=convert.base64-encode` indica que el contenido debe codificarse en Base64.
    
3. `resource=config` identifica el archivo que queremos leer.
    
4. La aplicación añade `.php` al final, por lo que el recurso acaba siendo `config.php`.
    
5. La respuesta contiene el código fuente codificado en lugar de ejecutarlo como una página PHP normal.
    

**Importante:** el nombre del recurso se coloca al final de la cadena para que la extensión añadida por la aplicación quede asociada al archivo solicitado.

## 6. Decodificar el contenido obtenido

Una vez obtenida la cadena Base64 de la respuesta HTTP, podemos decodificarla en nuestra máquina.

```
echo 'CADENA_BASE64' | base64 -d
```

Ejemplo:

```
echo 'PD9waHAK...SNIP...' | base64 -d
```

El resultado será el contenido original del archivo, siempre que la cadena se haya copiado correctamente.

### Errores frecuentes

- Copiar únicamente una parte de la cadena Base64.
    
- Incluir caracteres adicionales que no pertenecen a la respuesta.
    
- Intentar decodificar una respuesta que no contiene el contenido esperado.
    
- Confundir el código fuente codificado con el resultado HTML generado por la ejecución de PHP.
    

**Consejo:** si la decodificación falla, comprueba que has copiado la cadena completa. El código fuente de la página puede ayudarte a recuperar toda la respuesta.

---

## 7. Qué buscar en el código fuente

Una vez recuperado un archivo PHP, examina su contenido para identificar información que permita continuar la investigación.

Presta atención a:

- Credenciales y contraseñas.
    
- Configuración de bases de datos.
    
- Claves y otros secretos.
    
- Nombres de otros archivos PHP.
    
- Rutas internas de la aplicación.
    
- Funciones que procesan parámetros controlados por el usuario.
    
- Referencias a archivos de configuración adicionales.
    

El objetivo es seguir las referencias encontradas y recuperar otros archivos relevantes hasta comprender mejor el funcionamiento de la aplicación.

## 8. Flujo de trabajo para explotar LFI mediante PHP Filters

```
1. Identificar una posible vulnerabilidad LFI
                  |
                  v
2. Enumerar archivos PHP con FFUF
                  |
                  v
3. Seleccionar un archivo interesante
                  |
                  v
4. Probar la inclusión normal
                  |
                  v
5. Si no muestra el código fuente,
   utilizar php://filter
                  |
                  v
6. Aplicar convert.base64-encode
                  |
                  v
7. Copiar la respuesta Base64 completa
                  |
                  v
8. Decodificar con base64 -d
                  |
                  v
9. Analizar el código fuente
                  |
                  v
10. Enumerar y leer otros archivos
```

## 9. Chuleta para el examen

|Técnica o herramienta|Utilidad|
|---|---|
|`ffuf`|Enumerar posibles archivos PHP.|
|`php://filter/`|Aplicar filtros a un recurso.|
|`read=`|Especificar el filtro de lectura.|
|`resource=`|Identificar el archivo que se desea leer.|
|`convert.base64-encode`|Codificar el contenido del archivo en Base64.|
|`base64 -d`|Decodificar el contenido recuperado.|
|LFI normal sobre un PHP|Ejecuta el código incluido, por lo que puede no mostrar su código fuente.|
|PHP Filters + Base64|Permite obtener el código fuente codificado para recuperarlo posteriormente.|

### Payload principal

```
php://filter/read=convert.base64-encode/resource=config
```

### Comando de decodificación

```
echo 'CADENA_BASE64' | base64 -d
```

**Idea clave:** cuando una LFI ejecuta archivos PHP en lugar de mostrar su código fuente, utiliza `php://filter` con `convert.base64-encode` para intentar recuperar el contenido original. Después, decodifica la respuesta y analiza el código para descubrir información sensible y nuevas rutas de interés.
