
## 1. PAM (Pluggable Authentication Modules)

**PAM** es un sistema modular de autenticación utilizado en Linux. Gestiona la autenticación de usuarios, las sesiones y los cambios de contraseña.

- Módulos principales: `pam_unix.so` y `pam_unix2.so`.
    
- En sistemas Debian, suelen encontrarse en `/usr/lib/x86_64-linux-gnu/security/`.
    
- `pam_unix.so` interactúa con `/etc/passwd` y `/etc/shadow`.
    
- También existen módulos PAM para LDAP, Kerberos y otras operaciones.
    

Cuando un usuario cambia su contraseña mediante `passwd`, PAM gestiona el proceso.

## 2. Archivo `/etc/passwd`

Contiene información sobre los usuarios del sistema y normalmente es legible por todos los usuarios.

```
cat /etc/passwd
head -n 1 /etc/passwd
```

Cada entrada tiene **7 campos separados por** `**:**`:

```
usuario:contraseña:UID:GID:GECOS:directorio_home:shell
```

Ejemplo:

```
htb-student:x:1000:1000:,,,:/home/htb-student:/bin/bash
```

|Campo|Descripción|
|---|---|
|Usuario|Nombre de la cuenta|
|Contraseña|Normalmente `x`, indicando que el hash está en `/etc/shadow`|
|UID|Identificador del usuario|
|GID|Identificador del grupo principal|
|GECOS|Información descriptiva del usuario|
|Home|Directorio personal|
|Shell|Shell predeterminada|

### Consideraciones de seguridad

- En sistemas modernos, los hashes suelen almacenarse en `/etc/shadow`.
    
- En sistemas antiguos, `/etc/passwd` puede contener hashes directamente.
    
- Si el archivo tiene permisos de escritura indebidos, podría ser posible modificar entradas de usuarios.
    

**Escenario de escalada de privilegios:** si un atacante puede modificar `/etc/passwd`, podría eliminar el campo de contraseña de la cuenta `root`:

```
root::0:0:root:/root:/bin/bash
```

Esto puede permitir iniciar una sesión mediante `su` sin solicitar una contraseña, dependiendo de la configuración y del comportamiento del sistema.

**Comprobación de permisos:**

```
ls -l /etc/passwd
ls -ld /etc
```

## 3. Archivo `/etc/shadow`

Almacena los hashes de las contraseñas y otros datos relacionados con su caducidad. Normalmente, solo puede leerlo `root` o usuarios con los permisos correspondientes.

```
sudo cat /etc/shadow
```

Cada entrada contiene **9 campos separados por** `**:**`:

```
usuario:hash:ultimo_cambio:edad_minima:edad_maxima:aviso:inactividad:expiracion:reservado
```

|Campo|Descripción|
|---|---|
|Usuario|Nombre de la cuenta|
|Hash|Hash de la contraseña|
|Último cambio|Fecha del último cambio, expresada en días desde la época Unix|
|Edad mínima|Días mínimos antes de cambiar la contraseña|
|Edad máxima|Días máximos de validez|
|Aviso|Días de antelación para avisar de la expiración|
|Inactividad|Periodo antes de deshabilitar la cuenta tras expirar la contraseña|
|Expiración|Fecha de expiración de la cuenta|
|Reservado|Campo reservado|

### Valores importantes del campo de contraseña

- `!` o `*`: impiden la autenticación mediante una contraseña Unix convencional.
    
- Campo vacío: indica que no hay una contraseña establecida en ese campo; el acceso efectivo depende de la configuración y del método de autenticación.
    
- Un usuario sin entrada correspondiente en `/etc/shadow` puede presentar problemas de validez o autenticación.
    

**Importante:** bloquear la autenticación mediante contraseña no implica necesariamente que se hayan deshabilitado otros métodos, como las claves SSH o Kerberos.

### Formato de los hashes

```
$id$salt$hash
```

|Identificador|Algoritmo|
|---|---|
|`$1$`|MD5-crypt|
|`$2a$`|Blowfish|
|`$5$`|SHA-256-crypt|
|`$6$`|SHA-512-crypt|
|`$y$`|yescrypt|
|`$7$`|scrypt|
|`sha1`|SHA1crypt, según la nomenclatura del material|

El identificador permite reconocer el algoritmo empleado y seleccionar el modo de cracking adecuado.

**Dato clave:** muchas distribuciones modernas utilizan yescrypt, mientras que en sistemas antiguos pueden aparecer algoritmos diferentes.

## 4. Archivo `/etc/security/opasswd`

PAM puede utilizar este archivo para almacenar hashes de contraseñas anteriores e impedir que los usuarios las reutilicen.

```
sudo cat /etc/security/opasswd
```

Ejemplo:

```
cry0l1t3:1000:2:$1$HjFAfYTG$qNDkF0zJ3v8ylCOrKB0kt0,$1$kcUjWZJX$E9uMSmiQeRh4pAAgzuvkq1
```

Aspectos importantes:

- Normalmente requiere privilegios de `root` para leerlo.
    
- Puede contener varios hashes antiguos para un mismo usuario.
    
- Los hashes están separados por comas.
    
- El prefijo `$1$` identifica MD5-crypt, que suele ser menos resistente al cracking que algoritmos modernos como SHA-512-crypt.
    

### Interés para un pentest

Las contraseñas antiguas pueden revelar patrones de reutilización o variaciones de contraseñas actuales.

## 5. Extracción y cracking de hashes de Linux

Si disponemos de privilegios de `root`, podemos obtener los archivos de cuentas y preparar sus hashes para intentar recuperar las contraseñas en texto claro.

### Paso 1. Copiar los archivos

```
sudo cp /etc/passwd /tmp/passwd.bak
sudo cp /etc/shadow /tmp/shadow.bak
```

### Paso 2. Combinar los archivos con `unshadow`

`unshadow`, incluido en John the Ripper, combina `/etc/passwd` y `/etc/shadow` en un formato adecuado para el cracking.

```
unshadow /tmp/passwd.bak /tmp/shadow.bak > /tmp/unshadowed.hashes
```

### Paso 3. Crackear con Hashcat

```
hashcat -m 1800 -a 0 /tmp/unshadowed.hashes rockyou.txt -o /tmp/unshadowed.cracked
```

Parámetros:

|Parámetro|Función|
|---|---|
|`-m 1800`|Selecciona el modo SHA-512-crypt|
|`-a 0`|Ataque de diccionario|
|`rockyou.txt`|Diccionario de contraseñas|
|`-o`|Archivo donde guardar los resultados recuperados|

**Importante:** el modo `1800` corresponde a SHA-512-crypt. No sirve para todos los hashes de Linux; hay que identificar el algoritmo antes de elegir el modo.

### Consultar los resultados

```
cat /tmp/unshadowed.cracked
```

También podemos utilizar **John the Ripper**, incluyendo su modo `single`, que el material destaca como apropiado para este escenario.

## 6. Metodología práctica para HTB

Cuando tengas acceso a una máquina Linux, sigue este orden:

### Enumeración inicial

```
whoami
id
cat /etc/passwd
ls -l /etc/passwd /etc/shadow /etc/security/opasswd
ls -ld /etc
```

### Comprobar los archivos de autenticación

```
sudo cat /etc/shadow
sudo cat /etc/security/opasswd
```

Comprueba si tienes permisos suficientes para leerlos y si existen permisos de escritura inseguros.

### Preparar los hashes

```
sudo cp /etc/passwd /tmp/passwd.bak
sudo cp /etc/shadow /tmp/shadow.bak
unshadow /tmp/passwd.bak /tmp/shadow.bak > /tmp/unshadowed.hashes
```

### Intentar recuperar las contraseñas

```
hashcat -m 1800 -a 0 /tmp/unshadowed.hashes rockyou.txt -o /tmp/unshadowed.cracked
```

Adapta el modo de Hashcat al algoritmo identificado.

## 7. Puntos clave para el examen

- **PAM:** gestiona la autenticación y utiliza módulos como `pam_unix.so`.
    
- `**/etc/passwd**`**:** contiene información de las cuentas y suele ser legible por todos.
    
- `**/etc/shadow**`**:** almacena los hashes de las contraseñas y normalmente requiere privilegios administrativos.
    
- `**/etc/security/opasswd**`**:** puede contener hashes de contraseñas antiguas.
    
- `**unshadow**`**:** combina `passwd` y `shadow` para preparar los hashes para John the Ripper.
    
- **Hashcat** `**-m 1800**`**:** corresponde a SHA-512-crypt.
    
- **Permisos incorrectos:** los permisos de escritura sobre archivos críticos de autenticación pueden abrir vías de escalada de privilegios.
    
- **Reutilización de contraseñas:** los hashes antiguos pueden revelar patrones útiles durante una auditoría.
    

### Archivos que debes recordar

|Archivo|Utilidad|
|---|---|
|`/etc/passwd`|Información de las cuentas|
|`/etc/shadow`|Hashes de contraseñas actuales|
|`/etc/security/opasswd`|Historial de hashes de contraseñas, si está configurado|
