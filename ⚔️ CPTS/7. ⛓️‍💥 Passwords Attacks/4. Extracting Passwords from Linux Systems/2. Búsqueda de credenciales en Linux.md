
## 1. Introducción

La búsqueda de credenciales (_Credential Hunting_) es una de las primeras tareas después de obtener acceso a una máquina Linux. Puede permitirnos encontrar contraseñas, claves o cuentas que faciliten la **escalada de privilegios local (LPE)** y el movimiento lateral.

Podemos clasificar las fuentes de credenciales en cuatro categorías:

|Categoría|Qué buscar|
|---|---|
|Archivos|Configuraciones, bases de datos, notas, scripts, cronjobs y claves SSH|
|Historial|Historial de comandos y registros del sistema|
|Memoria|Credenciales almacenadas en memoria o caché|
|Keyrings|Contraseñas guardadas en navegadores y gestores de credenciales|

**Importante:** adapta la búsqueda al propósito de la máquina y a los servicios que ejecuta.

---

## 2. Búsqueda de archivos de configuración

Los archivos de configuración pueden contener usuarios, contraseñas y otros datos necesarios para que funcionen los servicios.

Extensiones habituales:

- `.conf`
    
- `.config`
    
- `.cnf`
    

### Buscar archivos de configuración

```
for l in $(echo ".conf .config .cnf"); do
    echo -e "\nFile extension: $l"
    find / -name "*$l" 2>/dev/null | grep -v "lib\|fonts\|share\|core"
done
```

### Buscar posibles credenciales en archivos `.cnf`

```
for i in $(find / -name "*.cnf" 2>/dev/null | grep -v "doc\|lib"); do
    echo -e "\nFile: $i"
    grep "user\|password\|pass" "$i" 2>/dev/null | grep -v "#"
done
```

Palabras clave interesantes:

```
user
username
password
pass
passwd
credential
secret
token
```

**Qué revisar:** configuraciones de bases de datos, servicios web, aplicaciones y cualquier archivo que contenga credenciales de autenticación.

---

## 3. Búsqueda de bases de datos

Las bases de datos almacenadas en archivos pueden contener información sensible o credenciales.

### Buscar archivos relacionados con bases de datos

```
for l in $(echo ".sql .db .*db .db*"); do
    echo -e "\nDB File extension: $l"
    find / -name "*$l" 2>/dev/null | grep -v "doc\|lib\|headers\|share\|man"
done
```

Extensiones y archivos interesantes:

- `.sql`: volcados o scripts SQL.
    
- `.db`: bases de datos.
    
- `.db*`: posibles archivos auxiliares o variantes.
    
- `key4.db` y `logins.json`: archivos relacionados con las credenciales de Firefox.
    

No todos los archivos encontrados contienen credenciales: hay que identificar la aplicación que los utiliza y comprobar su contenido.

---

## 4. Búsqueda de notas

Las notas pueden contener contraseñas, usuarios, direcciones de servicios o instrucciones de administración.

No siempre tienen una extensión reconocible, por lo que conviene buscar archivos `.txt` y archivos sin extensión.

```
find /home -type f \( -name "*.txt" -o ! -name "*.*" \) 2>/dev/null
```

Después, inspecciona los archivos interesantes:

```
cat /ruta/al/archivo
```

**Consejo:** presta atención a directorios personales, archivos ocultos y notas relacionadas con aplicaciones o tareas administrativas.

---

## 5. Búsqueda de scripts

Los scripts pueden contener credenciales utilizadas para ejecutar tareas automáticamente sin intervención humana.

Extensiones habituales:

- `.py`
    
- `.pyc`
    
- `.pl`
    
- `.go`
    
- `.jar`
    
- `.c`
    
- `.sh`
    

### Buscar scripts

```
for l in $(echo ".py .pyc .pl .go .jar .c .sh"); do
    echo -e "\nFile extension: $l"
    find / -name "*$l" 2>/dev/null | grep -v "doc\|lib\|headers\|share"
done
```

Una vez encontrados, busca contraseñas y usuarios:

```
grep -nEi "user|username|password|passwd|credential|secret|token|api_key" /ruta/al/script 2>/dev/null
```

Revisa especialmente scripts que conecten con bases de datos, servicios remotos o aplicaciones internas.

---

## 6. Enumeración de cronjobs

Los _cronjobs_ ejecutan comandos y scripts de forma programada. Pueden contener credenciales o ejecutar scripts que tengan información sensible.

### Revisar el cron del sistema

```
cat /etc/crontab
```

### Enumerar directorios de cron

```
ls -la /etc/cron.d/
ls -la /etc/cron.daily/
ls -la /etc/cron.hourly/
ls -la /etc/cron.monthly/
ls -la /etc/cron.weekly/
```

### Consultar tareas programadas del usuario actual

```
crontab -l
```

### Qué buscar

- Comandos que incluyan contraseñas.
    
- Scripts que se ejecuten con privilegios elevados.
    
- Rutas a archivos de configuración.
    
- Credenciales incluidas directamente en los scripts.
    
- Archivos ejecutados por `root` que puedan ser modificados por usuarios sin privilegios.
    

**Importante:** comprueba los permisos de los scripts invocados por cron, ya que pueden revelar oportunidades de escalada de privilegios.

---

## 7. Enumeración del historial de comandos

El historial puede revelar contraseñas introducidas como argumentos, comandos de cambio de usuario y rutas a archivos interesantes.

### Revisar historiales y archivos de configuración de Bash

```
tail -n 5 /home/*/.bash*
```

Archivos importantes:

|Archivo|Utilidad|
|---|---|
|`.bash_history`|Historial de comandos|
|`.bashrc`|Configuración de Bash|
|`.bash_profile`|Configuración del entorno de inicio de sesión|

### Buscar palabras clave en los historiales

```
grep -nEi "password|passwd|credential|secret|token|su |sudo|ssh" /home/*/.bash_history 2>/dev/null
```

**Qué buscar:** comandos que incluyan contraseñas, conexiones SSH, uso de `su`, ejecución de scripts y accesos a servicios.

Ten en cuenta que los historiales pueden estar vacíos, incompletos o no haberse guardado todavía.

---

## 8. Enumeración de archivos de registro (logs)

Los logs registran eventos del sistema, autenticaciones, actividad de servicios y errores.

### Logs importantes

|Archivo|Descripción|
|---|---|
|`/var/log/messages`|Actividad general del sistema|
|`/var/log/syslog`|Eventos generales del sistema|
|`/var/log/auth.log`|Autenticación en Debian y derivados|
|`/var/log/secure`|Autenticación en Red Hat/CentOS|
|`/var/log/boot.log`|Información del arranque|
|`/var/log/dmesg`|Información de hardware y controladores|
|`/var/log/kern.log`|Eventos del kernel|
|`/var/log/faillog`|Información sobre intentos fallidos de inicio de sesión|
|`/var/log/cron`|Actividad de tareas programadas|
|`/var/log/mail.log`|Eventos del servidor de correo|
|`/var/log/httpd/`|Logs de Apache, cuando se utiliza esa ruta|
|`/var/log/mysqld.log`|Logs de MySQL, si existe ese archivo|

Los nombres y rutas pueden variar según la distribución y los servicios instalados.

### Buscar eventos interesantes

```
grep -RniE "accepted|session opened|session closed|failure|failed|ssh|password changed|new user|delete user|sudo|COMMAND=" /var/log/ 2>/dev/null
```

Busca especialmente:

- Autenticaciones correctas o fallidas.
    
- Sesiones abiertas y cerradas.
    
- Uso de `sudo`.
    
- Creación o eliminación de usuarios.
    
- Cambios de contraseña.
    
- Actividad SSH.
    
- Información que identifique servicios, usuarios o procesos.
    

Los logs pueden ayudar a reconstruir la actividad del sistema y localizar otros archivos o cuentas que merezca la pena investigar.

## 9. Credenciales en memoria y caché

Algunas aplicaciones y procesos mantienen credenciales en memoria o las almacenan temporalmente para reutilizarlas.

### Mimipenguin

**Mimipenguin** permite intentar recuperar credenciales de determinadas sesiones en Linux. Requiere privilegios de administrador para las funciones descritas en el material.

```
sudo python3 mimipenguin.py
```

Ejemplo de salida:

```
[SYSTEM - GNOME] usuario:contraseña
```

El resultado depende del entorno y de las credenciales disponibles en el sistema.

## 10. LaZagne en Linux

**LaZagne** es una herramienta para recuperar credenciales almacenadas por diferentes aplicaciones.

Entre sus posibles fuentes se encuentran:

- Wi-Fi y `wpa_supplicant`.
    
- Libsecret y KWallet.
    
- Navegadores Chromium y Mozilla.
    
- Thunderbird.
    
- Git.
    
- Variables de entorno.
    
- GRUB y `fstab`.
    
- AWS.
    
- FileZilla y gFTP.
    
- SSH.
    
- Apache.
    
- `/etc/shadow`.
    
- Docker.
    
- KeePass.
    
- Sesiones y keyrings.
    

### Ejecutar LaZagne

El material muestra el siguiente comando con Python 2.7:

```
sudo python2.7 laZagne.py all
```

Para buscar específicamente credenciales de navegadores:

```
python3 laZagne.py browsers
```

La compatibilidad de estos comandos depende de la versión de LaZagne y del entorno Python instalado.

## 11. Credenciales almacenadas en Firefox

Firefox guarda información de inicio de sesión en el perfil de cada usuario.

Archivos relevantes:

|Archivo|Utilidad|
|---|---|
|`logins.json`|Contiene información de los inicios de sesión guardados, incluidos los campos cifrados|
|`key4.db`|Base de datos relacionada con las claves utilizadas por Firefox|
|`cert9.db`|Base de datos de certificados|

### Localizar perfiles de Firefox

```
ls -la ~/.mozilla/firefox/
```

También puedes buscar perfiles de otros usuarios si tienes permisos suficientes:

```
find /home -type f \( -name "logins.json" -o -name "key4.db" -o -name "cert9.db" \) 2>/dev/null
```

### Inspeccionar `logins.json`

```
cat ~/.mozilla/firefox/PROFILE/logins.json | jq .
```

Sustituye `PROFILE` por el nombre real del perfil.

El archivo puede revelar:

- URL del sitio.
    
- Nombre del campo de usuario.
    
- Nombre del campo de contraseña.
    
- Usuario cifrado.
    
- Contraseña cifrada.
    
- Fechas de creación y uso.
    

**Importante:** `logins.json` no suele mostrar las contraseñas en texto claro. Los valores cifrados deben tratarse junto con los archivos y mecanismos de protección correspondientes del perfil.

### Descifrar credenciales con Firefox Decrypt

El material propone Firefox Decrypt para recuperar las credenciales guardadas.

```
python3.9 firefox_decrypt.py
```

La herramienta permite seleccionar un perfil de Firefox y mostrar las credenciales que pueda descifrar.

La versión utilizada debe ser compatible con Python y con el formato del perfil.

## 12. Metodología práctica para HTB CPTS/OSCP

Después de conseguir una shell en Linux, puedes seguir este orden:

### Paso 1. Obtener contexto

```
whoami
id
hostname
pwd
```

Identifica el usuario actual, sus grupos y el propósito de la máquina.

### Paso 2. Buscar configuraciones y bases de datos

```
find / -type f \( -name "*.conf" -o -name "*.config" -o -name "*.cnf" -o -name "*.sql" -o -name "*.db" \) 2>/dev/null
```

### Paso 3. Buscar notas y scripts

```
find /home -type f \( -name "*.txt" -o -name "*.sh" -o -name "*.py" -o ! -name "*.*" \) 2>/dev/null
```

### Paso 4. Revisar cronjobs

```
cat /etc/crontab
ls -la /etc/cron.d/
crontab -l
```

### Paso 5. Revisar historiales y logs

```
cat ~/.bash_history 2>/dev/null
grep -RniE "password|passwd|credential|secret|token" /var/log/ 2>/dev/null
```

### Paso 6. Comprobar credenciales almacenadas

Si dispones de los permisos necesarios y las herramientas están disponibles:

```
sudo python3 mimipenguin.py
sudo python2.7 laZagne.py all
```

Revisa también los perfiles de navegador y sus archivos de credenciales.

### Paso 7. Validar los hallazgos

Cuando encuentres credenciales:

1. Identifica a qué usuario o servicio pertenecen.
    
2. Comprueba si son contraseñas, hashes, claves o tokens.
    
3. Determina si siguen siendo válidas.
    
4. Comprueba, dentro del alcance autorizado, si permiten acceder a otras cuentas o servicios.
    
5. Evalúa si ofrecen una vía de escalada de privilegios o movimiento lateral.

## 13. Puntos clave para el examen

- **Archivos:** busca configuraciones, bases de datos, notas, scripts, cronjobs y claves SSH.
    
- **Historial:** revisa `.bash_history`, `.bashrc` y `.bash_profile`.
    
- **Logs:** consulta los registros de autenticación, SSH, `sudo` y cron.
    
- **Memoria:** Mimipenguin permite intentar recuperar determinadas credenciales de sesiones.
    
- **LaZagne:** busca credenciales almacenadas por numerosas aplicaciones.
    
- **Firefox:** inspecciona `logins.json` y los archivos asociados al perfil.
    
- **Cronjobs:** revisa tanto las tareas programadas como los permisos de los scripts que ejecutan.
    
- **Contexto:** adapta la búsqueda a los servicios y la función de la máquina.
    
- **Validación:** encontrar una credencial no garantiza que siga siendo válida ni que proporcione privilegios elevados.
