
## 1. ¿Qué es LSASS?

**LSASS (Local Security Authority Subsystem Service)** es un proceso fundamental de Windows encargado de gestionar la autenticación, aplicar las políticas de seguridad y mantener información relacionada con las sesiones de inicio de sesión.

Tras el inicio de sesión, LSASS puede:

- Almacenar material de credenciales en memoria.
    
- Crear tokens de acceso (_Access Tokens_).
    
- Aplicar las políticas de seguridad.
    
- Generar registros en el registro de seguridad de Windows.
    
- Mantener información relacionada con NTLM, Kerberos y DPAPI.
    

**Objetivo del ataque:** obtener un volcado de memoria de LSASS y analizarlo fuera de línea para recuperar hashes, claves y otros materiales de autenticación.

---

## 2. Obtener un volcado de memoria de LSASS

Un _memory dump_ es una copia de parte o de toda la memoria de un proceso. Al analizarla fuera del sistema objetivo, podemos buscar credenciales sin tener que mantener una sesión activa.

### Método 1: Administrador de tareas

Si disponemos de una sesión gráfica interactiva:

1. Abrir el Administrador de tareas.
    
2. Acceder a la pestaña **Processes**.
    
3. Buscar **Local Security Authority Process**.
    
4. Hacer clic derecho sobre el proceso.
    
5. Seleccionar **Create dump file**.
    

Windows genera un archivo llamado:

```
lsass.DMP
```

Normalmente se guarda en el directorio temporal del usuario, accesible mediante `%temp%`.

Después, debemos transferir el archivo a nuestra máquina de análisis.

### Método 2: `rundll32.exe` y `comsvcs.dll`

Este método permite generar el volcado desde CMD o PowerShell, sin necesidad de una interfaz gráfica.

**Paso 1. Identificar el PID de LSASS.**

Desde CMD:

```
tasklist /svc
```

Busca la entrada `lsass.exe` y anota su PID.

Desde PowerShell:

```
Get-Process lsass
```

El identificador del proceso aparece en la columna `Id`.

**Paso 2. Generar el volcado.**

Desde una sesión de PowerShell elevada, el material de HTB utiliza:

```
rundll32 C:\windows\system32\comsvcs.dll, MiniDump 672 C:\lsass.dmp full
```

En este ejemplo:

- `672`: PID de LSASS obtenido previamente; debes sustituirlo por el PID real.
    
- `C:\lsass.dmp`: ruta del archivo de salida.
    
- `full`: solicita un volcado completo.
    

`rundll32.exe` invoca la función `MiniDump` exportada por `comsvcs.dll`, que utiliza la funcionalidad de volcado de memoria de Windows.

**Importante:** este método puede ser detectado o bloqueado por soluciones antivirus y mecanismos de protección de LSASS.

## 3. Analizar el volcado con Pypykatz

**Pypykatz** es una implementación en Python de funcionalidades de Mimikatz que permite analizar volcados de LSASS desde sistemas Linux.

Su principal ventaja es que podemos trabajar con una copia del volcado desde nuestra máquina atacante, sin ejecutar Mimikatz directamente en Windows.

### Ejecutar Pypykatz

```
pypykatz lsa minidump /home/kali/Documents/lsass.dmp
```

**Parámetros:**

- `lsa`: indica que se analizarán datos relacionados con la Local Security Authority.
    
- `minidump`: especifica que la fuente es un volcado de memoria.
    
- La última parte es la ruta al archivo.
    

La herramienta analiza las sesiones de inicio de sesión y muestra los materiales de autenticación que consigue recuperar.

### Información que puede aparecer

- Usuarios y dominios.
    
- SID y LUID de las sesiones.
    
- Hashes NT y, cuando están disponibles, hashes de otros tipos.
    
- Información relacionada con Kerberos.
    
- Datos y claves asociados a DPAPI.
    
- Información de otros paquetes de autenticación.
    

**Importante:** el resultado depende de las sesiones activas, del contenido de la memoria y de las protecciones del sistema. No siempre se recuperan contraseñas en texto plano.

## 4. Interpretar los resultados de Pypykatz

### 4.1. MSV

MSV está relacionado con la validación de credenciales mediante mecanismos de autenticación de Windows.

Ejemplo de salida:

```
== MSV ==
Username: bob
Domain: DESKTOP-33E7O54
LM: NA
NT: 64f12cddaa88057e06a81b54e73b949b
SHA1: cba4e545b7ec918129725154b29f055e4cd5aea8
DPAPI: NA
```

Los datos importantes son:

|Campo|Significado|
|---|---|
|`Username`|Nombre del usuario.|
|`Domain`|Dominio o equipo asociado a la sesión.|
|`LM`|Hash LM, si está disponible.|
|`NT`|Hash NT de la credencial, si está disponible.|
|`SHA1`|Hash SHA-1 mostrado por la herramienta.|
|`DPAPI`|Información relacionada con DPAPI, si está disponible.|

El hash NT recuperado puede guardarse y someterse a un ataque de diccionario con Hashcat.

### 4.2. WDigest

WDigest es un mecanismo de autenticación antiguo.

Históricamente, en sistemas Windows con WDigest habilitado, LSASS podía mantener credenciales en texto plano en memoria. Por eso, los sistemas afectados podían exponer contraseñas directamente en un volcado.

Sin embargo:

- En versiones antiguas, WDigest podía estar habilitado por defecto.
    
- En sistemas Windows modernos suele estar deshabilitado por defecto.
    
- La configuración y las actualizaciones de seguridad influyen en los datos disponibles.
    

Ejemplo de salida:

```
== WDIGEST ==
username bob
domainname DESKTOP-33E7O54
password None
```

`password None` indica que no se ha recuperado una contraseña en texto plano en ese campo.

**No confundas la presencia de una entrada WDigest con la recuperación garantizada de la contraseña.**

### 4.3. Kerberos

Kerberos es un protocolo de autenticación utilizado habitualmente en entornos Windows unidos a un dominio.

LSASS puede mantener información de autenticación relacionada con Kerberos, como:

- Tickets.
    
- Claves de sesión y claves de cifrado.
    
- Material de credenciales.
    
- Información de las sesiones de usuario.
    

Ejemplo:

```
== Kerberos ==
Username: bob
Domain: DESKTOP-33E7O54
```

La información recuperada puede ser relevante para evaluar el acceso a otros recursos del dominio, dependiendo del material obtenido y de su validez.

### 4.4. DPAPI

DPAPI (_Data Protection API_) protege datos sensibles mediante mecanismos de cifrado vinculados al usuario o al sistema.

Pypykatz puede recuperar información relacionada con las claves maestras DPAPI de determinadas sesiones.

Ejemplo:

```
== DPAPI ==
luid 1354633
key_guid 3e1d1091-b792-45df-ab8e-c66af044d69b
masterkey ...
sha1_masterkey ...
```

Estas claves pueden ser útiles para descifrar datos protegidos por DPAPI, incluidas credenciales almacenadas por determinadas aplicaciones.

## 5. Crackear hashes NT con Hashcat

Si conseguimos recuperar un hash NT de LSASS, podemos intentar recuperar la contraseña mediante un ataque de diccionario.

### Ejemplo

Hash obtenido del volcado:

```
64f12cddaa88057e06a81b54e73b949b
```

Ejecutamos Hashcat:

```
hashcat -m 1000 64f12cddaa88057e06a81b54e73b949b /usr/share/wordlists/rockyou.txt
```

**Parámetros:**

- `-m 1000`: modo para hashes NT.
    
- `64f12cddaa88057e06a81b54e73b949b`: hash que queremos crackear.
    
- `/usr/share/wordlists/rockyou.txt`: diccionario de contraseñas.
    

En el ejemplo de HTB, el resultado es:

```
64f12cddaa88057e06a81b54e73b949b:Password1
```

El hash se ha recuperado utilizando el diccionario proporcionado.

## 6. Flujo de trabajo completo

El procedimiento general de esta técnica es:

1. Obtener privilegios suficientes en el sistema Windows.
    
2. Identificar el proceso `lsass.exe`.
    
3. Crear un volcado de su memoria mediante un método disponible.
    
4. Transferir el archivo `.dmp` a la máquina atacante.
    
5. Analizar el volcado con Pypykatz.
    
6. Identificar hashes NT, información Kerberos y datos DPAPI relevantes.
    
7. Si se obtiene un hash NT, intentar crackearlo con Hashcat.
    
8. Evaluar las credenciales recuperadas dentro del alcance autorizado.
    

### Esquema rápido

```
Windows comprometido
        |
        v
   lsass.exe
        |
        v
   lsass.dmp
        |
        v
 Transferencia a Linux
        |
        v
     Pypykatz
        |
        +----> Hash NT ------> Hashcat
        |
        +----> Kerberos
        |
        +----> Claves DPAPI
        |
        +----> Otros materiales de autenticación
```

## 7. Comandos importantes

### Identificar el PID de LSASS

```
tasklist /svc
```

```
Get-Process lsass
```

### Generar el volcado desde PowerShell

```
rundll32 C:\windows\system32\comsvcs.dll, MiniDump <PID> C:\lsass.dmp full
```

### Analizar el volcado en Linux

```
pypykatz lsa minidump /ruta/al/lsass.dmp
```

### Crackear un hash NT

```
hashcat -m 1000 <HASH_NT> /usr/share/wordlists/rockyou.txt
```

## 8. Puntos clave para CPTS/OSCP

- **LSASS:** proceso crítico de Windows que gestiona la autenticación y puede contener material sensible en memoria.
    
- **Memory dump:** permite analizar las credenciales fuera de línea.
    
- **Administrador de tareas:** ofrece una opción gráfica para crear un volcado de LSASS.
    
- `**rundll32.exe**` **+** `**comsvcs.dll**`**:** método de línea de comandos para generar un volcado.
    
- **Pypykatz:** permite analizar volcados de LSASS desde Linux.
    
- **MSV:** puede proporcionar hashes NT asociados a sesiones de usuario.
    
- **WDigest:** puede exponer contraseñas en texto plano en sistemas antiguos o configuraciones vulnerables.
    
- **Kerberos:** LSASS puede contener tickets y otro material de autenticación.
    
- **DPAPI:** las claves maestras recuperadas pueden ayudar a descifrar datos protegidos.
    
- **Hashcat** `**-m 1000**`**:** permite atacar hashes NT mediante diccionarios.
    
- **No siempre se recuperan contraseñas en texto plano:** depende de la configuración, las sesiones y el material presente en la memoria.
    
- **Defensas:** antivirus y mecanismos de protección de LSASS pueden detectar o bloquear estas operaciones.
    

La diferencia principal respecto al ataque anterior es que **SAM almacena hashes de cuentas locales en una base de datos**, mientras que **LSASS puede contener material de autenticación asociado a las sesiones presentes en memoria**.
