
## 1. Componentes del proceso de autenticación

Windows utiliza distintos componentes para gestionar el inicio de sesión, validar credenciales y aplicar las políticas de seguridad.

Los componentes principales son:

|Componente|Función|
|---|---|
|`WinLogon.exe`|Gestiona las operaciones de inicio de sesión, bloqueo y desbloqueo del equipo.|
|`LogonUI.exe`|Presenta la interfaz gráfica para introducir las credenciales.|
|Proveedores de credenciales|Recopilan el nombre de usuario y la contraseña introducidos.|
|`LSASS.exe`|Gestiona la autenticación, las políticas de seguridad y las auditorías.|
|Paquetes de autenticación|Comprueban las credenciales mediante mecanismos como NTLM o Kerberos.|
|`SAM`|Almacena las cuentas y credenciales locales del sistema.|
|Active Directory|Almacena y administra las cuentas y credenciales del dominio.|

### Flujo de inicio de sesión

1. `WinLogon.exe` inicia `LogonUI.exe`.
    
2. El proveedor de credenciales recopila los datos introducidos por el usuario.
    
3. `WinLogon.exe` envía las credenciales a `LSASS.exe`.
    
4. LSASS utiliza el paquete de autenticación correspondiente.
    
5. Las credenciales se validan contra la base de datos local SAM o contra Active Directory, según el contexto.
    
6. Si la autenticación tiene éxito, se permite el inicio de sesión.
    

**Importante:** `LSASS.exe` es uno de los procesos más relevantes en la extracción de credenciales de Windows.

## 2. LSASS (Local Security Authority Subsystem Service)

LSASS es el servicio responsable de gestionar gran parte de la seguridad y autenticación en Windows.

**Ruta del ejecutable:**

```
%SystemRoot%\System32\Lsass.exe
```

### Funciones principales

- Autenticar usuarios.
    
- Aplicar las políticas de seguridad local.
    
- Gestionar los procesos de autenticación.
    
- Generar registros de auditoría de seguridad.
    
- Coordinar los paquetes de seguridad y autenticación.
    

### DLL y paquetes relacionados

|Archivo|Función|
|---|---|
|`Lsasrv.dll`|Aplica las políticas de seguridad y administra los paquetes de seguridad de LSA. Incluye la función Negotiate, que selecciona NTLM o Kerberos.|
|`Msv1_0.dll`|Paquete de autenticación utilizado habitualmente para inicios de sesión locales mediante mecanismos como NTLM.|
|`Samsrv.dll`|Gestiona las operaciones relacionadas con SAM y las cuentas locales.|
|`Kerberos.dll`|Proporciona soporte para la autenticación Kerberos.|
|`Netlogon.dll`|Proporciona funcionalidades relacionadas con el inicio de sesión en la red.|
|`Ntdsa.dll`|Gestiona la base de datos de Active Directory, las consultas LDAP y la replicación entre controladores de dominio. Solo se carga en controladores de dominio.|

### Concepto clave

La función **Negotiate** permite seleccionar el protocolo de autenticación apropiado entre NTLM y Kerberos.

## 3. Base de datos SAM

SAM (_Security Account Manager_) es la base de datos que almacena las cuentas de usuario locales de Windows.

Las contraseñas se almacenan como hashes, habitualmente LM o NTLM, en lugar de guardarse directamente en texto plano.

### Ubicaciones importantes

**Archivo SAM:**

```
%SystemRoot%\System32\config\SAM
```

**Ubicación en el Registro:**

```
HKLM\SAM
```

El acceso directo al archivo SAM está protegido y requiere privilegios elevados; para acceder a él se necesitan privilegios de nivel `SYSTEM`.

### Diferencias entre grupo de trabajo y dominio

|Característica|Grupo de trabajo|Dominio|
|---|---|---|
|Gestión de cuentas|Local|Centralizada|
|Base de datos principal de cuentas|SAM|Active Directory|
|Validación de credenciales de dominio|No aplica|Controladores de dominio|
|Archivo relevante|`SAM`|`NTDS.dit` en los controladores de dominio|

### SYSKEY

SYSKEY fue una característica introducida en Windows NT 4.0 para proteger la base de datos SAM frente a determinados ataques de descifrado sin conexión.

Cuando estaba habilitada, cifraba parcialmente SAM en el disco mediante una clave generada por el sistema.

## 4. Administrador de Credenciales de Windows

El Administrador de Credenciales permite almacenar y gestionar credenciales utilizadas para acceder a:

- Recursos de red.
    
- Sitios web.
    
- Aplicaciones.
    

Las credenciales guardadas están cifradas y asociadas al perfil del usuario.

### Ubicación

```
C:\Users\<Username>\AppData\Local\Microsoft\
```

Dentro de esta ubicación pueden encontrarse directorios como:

```
Vault
Credentials
```

La ruta exacta y el contenido dependen del tipo de credenciales almacenadas y de la configuración del sistema.

### Importancia durante una auditoría

Si obtenemos acceso a un sistema Windows, las credenciales guardadas pueden ser interesantes para ampliar nuestro acceso a otros recursos.

El módulo estudiará posteriormente diferentes métodos para recuperar y descifrar estas credenciales.

## 5. Active Directory y NTDS.dit

En un entorno de dominio, los controladores de dominio almacenan la base de datos de Active Directory en el archivo `NTDS.dit`.

Esta base de datos contiene información relevante para la autenticación y administración del dominio.

### Ubicación

```
%SystemRoot%\NTDS\ntds.dit
```

### Información almacenada

- Cuentas de usuario y hashes de contraseñas.
    
- Cuentas de grupo.
    
- Cuentas de equipo.
    
- Objetos de directiva de grupo (GPO).
    

### Replicación

Los controladores de dominio mantienen sus bases de datos sincronizadas mediante los mecanismos de replicación de Active Directory, con la excepción de las particularidades de los controladores de dominio de solo lectura (RODC).

### Importancia para el pentesting

`NTDS.dit` es un objetivo importante porque contiene información de autenticación de las cuentas del dominio.

Su extracción puede permitir recuperar hashes de contraseñas y realizar ataques posteriores contra las cuentas obtenidas.

---

## 6. Diferencias entre SAM, LSASS y NTDS.dit

|Elemento|Qué es|Qué información o función aporta|
|---|---|---|
|`SAM`|Base de datos local|Cuentas locales y hashes de contraseñas.|
|`LSASS.exe`|Proceso de seguridad|Gestiona la autenticación y puede mantener material de credenciales en memoria.|
|`NTDS.dit`|Base de datos de Active Directory|Cuentas de usuario, grupos, equipos, objetos de directiva y hashes de contraseñas.|
|Administrador de Credenciales|Funcionalidad de Windows|Almacena credenciales cifradas utilizadas por el usuario.|

## 7. Resumen de rutas y conceptos importantes

```
# LSASS
%SystemRoot%\System32\Lsass.exe

# Base de datos SAM
%SystemRoot%\System32\config\SAM

# SAM en el Registro
HKLM\SAM

# Perfil del usuario: almacenamiento de credenciales
C:\Users\<Username>\AppData\Local\Microsoft\

# Base de datos de Active Directory
%SystemRoot%\NTDS\ntds.dit
```

### Puntos clave para CPTS/OSCP

- **LSASS:** gestiona la autenticación y es relevante en los ataques de extracción de credenciales de memoria.
    
- **SAM:** almacena las cuentas y los hashes de contraseñas locales.
    
- **NTDS.dit:** contiene información de las cuentas de Active Directory y sus hashes de contraseñas.
    
- **Administrador de Credenciales:** puede contener credenciales guardadas y cifradas.
    
- **WinLogon:** coordina el inicio de sesión y envía las credenciales a LSASS.
    
- **LogonUI:** muestra la interfaz de inicio de sesión.
    
- **NTLM y Kerberos:** mecanismos de autenticación que pueden seleccionarse mediante Negotiate.
    
- **Grupo de trabajo:** utiliza las cuentas locales almacenadas en SAM.
    
- **Dominio:** centraliza la gestión de cuentas mediante Active Directory y los controladores de dominio.
