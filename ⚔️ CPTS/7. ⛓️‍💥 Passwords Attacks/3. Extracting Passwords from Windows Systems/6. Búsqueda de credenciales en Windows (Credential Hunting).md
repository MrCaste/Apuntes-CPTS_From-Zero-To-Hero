
## 1. ¿Qué es Credential Hunting?

El **Credential Hunting** consiste en buscar credenciales almacenadas en un sistema Windows al que hemos conseguido acceder, ya sea mediante una interfaz gráfica (GUI) o una consola (CLI).

El objetivo es encontrar información como:

- Contraseñas almacenadas en texto claro.
    
- Nombres de usuario y contraseñas guardadas por aplicaciones.
    
- Credenciales de servicios y herramientas de administración.
    
- Contraseñas en archivos de configuración y scripts.
    
- Credenciales almacenadas en navegadores.
    
- Bases de datos de contraseñas.
    

**Concepto clave:** debemos adaptar la búsqueda al uso que se hace del equipo. Por ejemplo, si conseguimos acceso a la estación de trabajo de un administrador de TI, conviene revisar las aplicaciones y herramientas que utiliza habitualmente.

## 2. Términos clave para buscar credenciales

Podemos utilizar diferentes palabras clave para localizar archivos que contengan credenciales.

### Palabras clave habituales

```
password
passphrase
key
username
user account
creds
users
passkey
configuration
dbcredential
dbpassword
pwd
login
credentials
```

En sistemas Windows en español, también podemos buscar:

```
contraseña
credenciales
usuario
clave
```

### Estrategia de búsqueda

1. Identificar qué aplicaciones utiliza el usuario.
    
2. Buscar archivos relacionados con contraseñas y configuración.
    
3. Revisar scripts y directorios de herramientas administrativas.
    
4. Examinar las credenciales almacenadas por aplicaciones.
    
5. Comprobar si existen credenciales que permitan acceder a otros sistemas.

## 3. Buscar credenciales con Windows Search

Si tenemos acceso a la interfaz gráfica, podemos utilizar la búsqueda integrada de Windows.

Permite localizar aplicaciones, configuraciones y archivos relacionados con las palabras clave introducidas.

Por ejemplo, podemos buscar:

```
password
credentials
config
```

Esta técnica es sencilla y puede revelar archivos que contengan información sensible.

**Importante:** los resultados dependen de las ubicaciones indexadas, los permisos y la configuración del sistema.

## 4. Extraer credenciales con LaZagne

**LaZagne** es una herramienta que permite recuperar credenciales almacenadas por diferentes aplicaciones de un sistema.

Cada módulo se centra en un conjunto de aplicaciones o ubicaciones.

### Módulos principales

|Módulo|Objetivo|
|---|---|
|`browsers`|Credenciales almacenadas en navegadores como Chrome, Firefox, Edge y Opera.|
|`chats`|Credenciales de aplicaciones de chat, como Skype.|
|`mails`|Credenciales relacionadas con clientes de correo, como Outlook y Thunderbird.|
|`memory`|Información de memoria relacionada con aplicaciones como KeePass y LSASS.|
|`sysadmin`|Credenciales de herramientas administrativas, como OpenVPN y WinSCP.|
|`windows`|Información de Windows, incluidos secretos LSA y Credential Manager.|
|`wifi`|Credenciales de redes Wi-Fi.|

### 4.1. Ejecutar LaZagne

Si disponemos del ejecutable `LaZagne.exe` en el equipo objetivo, podemos ejecutar todos sus módulos desde CMD:

```
start LaZagne.exe all
```

Para obtener información más detallada sobre las operaciones realizadas, podemos utilizar la opción `-vv`:

```
start LaZagne.exe all -vv
```

La herramienta intentará recuperar las credenciales de las aplicaciones compatibles.

### 4.2. Interpretar los resultados

Un resultado podría mostrar:

```
########## User: bob ##########

------------------- Winscp passwords -----------------

[+] Password found !!!
URL: 10.129.202.51
Login: admin
Password: ********
Port: 22
```

En este ejemplo, se han recuperado credenciales almacenadas por WinSCP.

La información relevante es:

- **URL:** dirección del sistema de destino.
    
- **Login:** usuario utilizado para conectarse.
    
- **Password:** contraseña recuperada.
    
- **Port:** puerto del servicio.
    

Estas credenciales podrían permitir acceder al sistema indicado, siempre que sigan siendo válidas.

### 4.3. Credenciales almacenadas en navegadores

Los navegadores pueden guardar contraseñas para facilitar los inicios de sesión.

Aunque suelen cifrar las credenciales almacenadas, existen herramientas que intentan recuperarlas a partir de sus bases de datos, dependiendo de las protecciones y condiciones del sistema.

Algunas herramientas mencionadas en el módulo son:

- **LaZagne:** admite numerosos navegadores.
    
- **firefox_decrypt:** permite trabajar con credenciales almacenadas en perfiles de Firefox.
    
- **decrypt-chrome-passwords:** orientada a recuperar contraseñas almacenadas por Chrome.

## 5. Buscar credenciales con `findstr`

El comando `findstr` permite buscar patrones de texto en archivos de Windows.

Puede resultar especialmente útil para localizar contraseñas escritas en archivos de configuración, scripts o documentos de texto.

### Comando del módulo

```
findstr /SIM /C:"password" *.txt *.ini *.cfg *.config *.xml *.git *.ps1 *.yml
```

### Parámetros

|Parámetro|Función|
|---|---|
|`/S`|Busca también en subdirectorios.|
|`/I`|Ignora las diferencias entre mayúsculas y minúsculas.|
|`/M`|Muestra los nombres de los archivos que contienen coincidencias.|
|`/C:"password"`|Busca la cadena especificada como una expresión literal.|

### Buscar otras palabras clave

Podemos repetir la búsqueda cambiando el término:

```
findstr /SIM /C:"password" *.txt *.ini *.cfg *.config *.xml *.ps1 *.yml
```

```
findstr /SIM /C:"username" *.txt *.ini *.cfg *.config *.xml *.ps1 *.yml
```

```
findstr /SIM /C:"credential" *.txt *.ini *.cfg *.config *.xml *.ps1 *.yml
```

**Nota:** el comando busca en los archivos que coinciden con los patrones especificados. No garantiza encontrar todas las credenciales del sistema.

## 6. Ubicaciones adicionales para buscar credenciales

Durante una evaluación, debemos revisar distintas ubicaciones en función del tipo de equipo y su uso.

### 6.1. SYSVOL y scripts de Active Directory

En entornos de dominio, conviene revisar:

- Contraseñas en archivos de directivas de grupo.
    
- Scripts almacenados en `SYSVOL`.
    
- Scripts de inicio de sesión.
    
- Scripts administrativos disponibles en recursos compartidos de TI.
    

Algunos scripts pueden contener credenciales utilizadas para automatizar tareas.

### 6.2. Archivos de configuración

Revisar especialmente:

```
web.config
unattend.xml
```

- `**web.config**`**:** puede contener información de conexión a bases de datos y credenciales de aplicaciones web.
    
- `**unattend.xml**`**:** puede contener información de configuración utilizada durante instalaciones automatizadas de Windows, incluidas credenciales en determinados escenarios.
    

### 6.3. Active Directory

Las descripciones de objetos de usuario y equipo pueden contener información sensible introducida por los administradores.

Conviene comprobar:

- Descripciones de usuarios.
    
- Descripciones de equipos.
    
- Información de cuentas y servicios.
    

### 6.4. Bases de datos de contraseñas

Buscar bases de datos de **KeePass** y otras herramientas de gestión de contraseñas.

Si encontramos una base de datos, todavía necesitaremos disponer de la contraseña maestra u otro método válido para acceder a su contenido.

### 6.5. Documentos y recursos compartidos

Revisar archivos y directorios accesibles en:

- Equipos de usuarios.
    
- Recursos compartidos de red.
    
- Directorios administrativos.
    
- SharePoint.
    
- Carpetas de proyectos y desarrollo.
    

Algunos nombres de archivo interesantes son:

```
pass.txt
passwords.docx
passwords.xlsx
```

También conviene buscar archivos de configuración y documentación que puedan contener contraseñas o credenciales de acceso.

## 7. Metodología práctica para CPTS/OSCP

Cuando consigamos acceso a un equipo Windows, podemos seguir este procedimiento.

### Paso 1. Identificar el contexto

Comprobar qué usuario estamos utilizando y qué función tiene el equipo.

```
whoami
```

### Paso 2. Buscar archivos con palabras clave

Utilizar Windows Search si tenemos acceso gráfico o `findstr` desde CMD.

```
findstr /SIM /C:"password" *.txt *.ini *.cfg *.config *.xml *.ps1 *.yml
```

### Paso 3. Examinar aplicaciones instaladas

Priorizar las aplicaciones que puedan almacenar credenciales:

- Navegadores.
    
- Clientes de correo.
    
- Clientes SSH y SFTP.
    
- Herramientas VPN.
    
- Herramientas administrativas.
    
- Gestores de contraseñas.
    

### Paso 4. Utilizar LaZagne

Si está disponible y tenemos autorización para ejecutarlo:

```
LaZagne.exe all
```

### Paso 5. Revisar archivos y recursos compartidos

Buscar archivos de configuración, scripts, documentación y posibles bases de datos de contraseñas.

### Paso 6. Validar las credenciales encontradas

Si encontramos una cuenta y una contraseña, debemos comprobar si siguen siendo válidas y a qué sistema pertenecen.

No debemos asumir que una credencial recuperada proporciona automáticamente acceso administrativo.

## 9. Puntos clave para el examen

- **Credential Hunting** consiste en buscar credenciales en archivos, aplicaciones, configuraciones y otros almacenes del sistema.
    
- Adapta la búsqueda al usuario y a la función del equipo.
    
- `findstr` permite localizar palabras clave en archivos de Windows.
    
- LaZagne puede recuperar credenciales almacenadas por numerosas aplicaciones.
    
- Los navegadores, clientes de correo y herramientas administrativas son ubicaciones interesantes.
    
- Revisa `SYSVOL`, scripts, `web.config`, `unattend.xml`, descripciones de objetos de AD y recursos compartidos.
    
- Las bases de datos de KeePass pueden contener numerosas credenciales, pero requieren acceso válido para descifrarlas.
    
- Una credencial encontrada puede permitir movimiento lateral, pero hay que comprobar su validez, alcance y privilegios.
