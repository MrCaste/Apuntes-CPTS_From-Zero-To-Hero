
## 1. Introducción

La búsqueda de credenciales en el tráfico de red consiste en analizar paquetes para localizar información sensible transmitida entre sistemas, como usuarios, contraseñas, hashes y otros datos de autenticación.

Aunque muchos servicios utilizan cifrado mediante TLS, todavía podemos encontrar protocolos sin cifrar debido a sistemas heredados, configuraciones incorrectas o aplicaciones de prueba.

**Objetivo:** identificar credenciales expuestas en el tráfico de red utilizando herramientas como **Wireshark** y **Pcredz**.

---

## 2. Protocolos sin cifrar y alternativas seguras

|Protocolo sin cifrar|Alternativa segura indicada en el material|Función|
|---|---|---|
|HTTP|HTTPS|Transferencia de páginas web y recursos|
|FTP|FTPS / SFTP|Transferencia de archivos|
|SNMP|SNMPv3 con cifrado|Administración y monitorización de dispositivos|
|POP3|POP3S|Recuperación de correos electrónicos|
|IMAP|IMAPS|Acceso y gestión del correo|
|SMTP|SMTPS|Envío de correos electrónicos|
|LDAP|LDAPS|Consulta y modificación de servicios de directorio|
|RDP|RDP con TLS|Acceso remoto a sistemas Windows|
|DNS tradicional|DNS over HTTPS (DoH)|Resolución de nombres de dominio|
|SMB|SMB sobre TLS (SMB 3.0)|Compartición de archivos y recursos|
|VNC|VNC con TLS/SSL|Control remoto gráfico|

**Importante:** si las credenciales se transmiten sin cifrar, alguien con acceso a una captura adecuada del tráfico puede llegar a recuperarlas.

## 3. Wireshark

**Wireshark** es un analizador de paquetes que permite inspeccionar tráfico de red en tiempo real o mediante capturas guardadas.

Su motor de filtros permite localizar rápidamente paquetes relevantes.

### Filtros de visualización importantes

|Filtro|Función|
|---|---|
|`ip.addr == 56.48.210.13`|Tráfico relacionado con una IP|
|`tcp.port == 80`|Tráfico TCP asociado al puerto 80|
|`http`|Paquetes HTTP|
|`dns`|Tráfico DNS|
|`tcp.flags.syn == 1 && tcp.flags.ack == 0`|Paquetes SYN iniciales|
|`icmp`|Tráfico ICMP, como solicitudes Ping|
|`http.request.method == "POST"`|Solicitudes HTTP POST|
|`tcp.stream eq 53`|Flujo TCP número 53|
|`eth.addr == 00:11:22:33:44:55`|Tráfico relacionado con una dirección MAC|
|`ip.src == 192.168.24.3 && ip.dst == 56.48.210.3`|Tráfico de una IP de origen hacia una IP de destino|

### Buscar credenciales en HTTP

Para identificar solicitudes POST, que pueden incluir formularios de inicio de sesión:

```
http.request.method == "POST"
```

Para buscar paquetes HTTP que contengan la cadena `passw`:

```
http contains "passw"
```

Este tipo de búsqueda puede ayudar a localizar campos como `username`, `user` o `password`.

**Importante:** una solicitud POST no implica necesariamente que contenga credenciales. Hay que inspeccionar el contenido del paquete y comprobar si la información está cifrada.

### Inspeccionar una conversación

Cuando encuentres un paquete interesante:

1. Selecciónalo en Wireshark.
    
2. Examina los detalles de los protocolos.
    
3. Comprueba los datos transmitidos.
    
4. Identifica las direcciones IP y los puertos implicados.
    
5. Sigue el flujo de la comunicación para reconstruir la conversación.
    

También puedes utilizar **Edit → Find Packet** para buscar manualmente cadenas de texto dentro de los paquetes.

## 4. Pcredz

**Pcredz** es una herramienta que permite extraer información sensible del tráfico de red, tanto de capturas guardadas como de interfaces en vivo.

Entre los datos que puede detectar se incluyen:

- Números de tarjetas de crédito.
    
- Credenciales POP.
    
- Credenciales SMTP.
    
- Credenciales IMAP.
    
- Cadenas de comunidad SNMP.
    
- Credenciales FTP.
    
- Credenciales HTTP Basic.
    
- Credenciales en formularios HTTP.
    
- Hashes NTLMv1 y NTLMv2.
    
- Hashes de autenticación Kerberos AS-REQ con preautenticación y etype 23.
    

Los hashes pueden aparecer en protocolos como DCE-RPC, SMB, LDAP, MSSQL y HTTP, dependiendo del tráfico capturado.

### Analizar una captura PCAP

El material utiliza el siguiente comando:

```
./Pcredz -f demo.pcapng -t -v
```

Parámetros:

|Parámetro|Función|
|---|---|
|`-f demo.pcapng`|Archivo de captura que se va a analizar|
|`-t`|Activa el análisis de números de tarjetas de crédito en la versión mostrada|
|`-v`|Activa la salida detallada|

Pcredz analiza el archivo e informa de los datos sensibles que logra identificar.

Ejemplos de resultados que aparecen en el material:

```
Found SNMPv2 Community string: ...
FTP User: ...
FTP Pass: ...
```

Estos resultados demuestran que una captura puede revelar credenciales o cadenas de comunidad transmitidas mediante protocolos vulnerables a la interceptación.

**Nota:** las opciones exactas pueden variar según la versión de Pcredz.

## 5. Metodología práctica para HTB CPTS/OSCP

Cuando recibas una captura de tráfico, sigue estos pasos:

### Paso 1. Extraer la captura

Si has descargado un archivo comprimido, extráelo para obtener el archivo `.pcapng`.

### Paso 2. Abrirlo con Wireshark

Carga `demo.pcapng` y empieza filtrando los protocolos que puedan transmitir información sensible.

```
http
ftp
snmp
```

### Paso 3. Buscar solicitudes HTTP POST

```
http.request.method == "POST"
```

Inspecciona los paquetes y busca formularios de autenticación o campos con nombres de usuario y contraseñas.

### Paso 4. Buscar cadenas relacionadas con contraseñas

```
http contains "passw"
```

Si encuentras paquetes relevantes, inspecciona su contenido y sigue el flujo de comunicación.

### Paso 5. Automatizar la extracción con Pcredz

```
./Pcredz -f demo.pcapng -t -v
```

Revisa la salida en busca de credenciales FTP, cadenas SNMP, credenciales HTTP y hashes de autenticación.

### Paso 6. Clasificar los resultados

Distingue entre:

- **Credenciales en texto claro:** usuario y contraseña recuperados directamente.
    
- **Hashes:** valores que pueden requerir identificación y cracking.
    
- **Cadenas de comunidad SNMP:** información utilizada para acceder a determinadas funciones SNMP.
    
- **Otros datos sensibles:** información que pueda facilitar el acceso a cuentas o servicios.
    

### Paso 7. Validar los hallazgos

En un laboratorio autorizado, comprueba a qué servicio pertenecen las credenciales y si siguen siendo válidas. No asumas que una credencial capturada proporciona acceso a otros servicios.

## 6. Puntos clave para el examen

- **Wireshark:** permite inspeccionar paquetes y filtrar el tráfico relevante.
    
- **HTTP POST:** puede contener credenciales si el tráfico no está cifrado.
    
- `**http contains "passw"**`**:** permite buscar paquetes HTTP que contengan esa cadena.
    
- **Pcredz:** automatiza la extracción de credenciales y otros datos sensibles de capturas.
    
- **FTP:** puede exponer usuarios y contraseñas si se utiliza sin cifrado.
    
- **SNMP:** una captura puede revelar cadenas de comunidad.
    
- **NTLM y Kerberos:** el tráfico de autenticación puede contener hashes aprovechables en determinados escenarios.
    
- **Tráfico cifrado:** no debe asumirse que las credenciales son recuperables directamente del contenido capturado.
    
- **Metodología:** filtrar, inspeccionar, extraer, clasificar y validar los hallazgos.
    

### Comandos que debes recordar

```
# Abrir la captura con Wireshark
wireshark demo.pcapng

# Analizar la captura con Pcredz
./Pcredz -f demo.pcapng -t -v
```
