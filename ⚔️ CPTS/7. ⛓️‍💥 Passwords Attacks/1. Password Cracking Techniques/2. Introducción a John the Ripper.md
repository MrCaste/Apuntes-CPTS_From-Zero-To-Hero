
## 1. ¿Qué es John the Ripper?

**John the Ripper (JtR o** `**john**`**)** es una herramienta de código abierto utilizada para recuperar contraseñas a partir de hashes y probar la seguridad de credenciales.

Permite realizar ataques de diccionario, fuerza bruta y ataques basados en reglas, además de trabajar con hashes extraídos de archivos y servicios.

Se recomienda utilizar la versión **Jumbo**, ya que incluye optimizaciones, compatibilidad con numerosos formatos de hash y herramientas adicionales para procesar archivos protegidos.

---

## 2. Modos de cracking

### 2.1. Single Crack Mode

El modo `--single` genera contraseñas candidatas utilizando información asociada al usuario, como:

- Nombre de usuario.
    
- Nombre completo.
    
- Directorio personal.
    
- Información GECOS de sistemas Linux.
    

Después aplica reglas para generar variaciones probables de esa información.

**Ejemplo:**

Archivo `passwd`:

```
r0lf:$6$ues25dIanlctrWxg$nZHVz2z4kCy1760Ee28M1xtHdGoy0C2cYzZ8l2sVa1kIa8K9gAcdBP.GI6ng/qA4oaMrgElZ1Cb9OeXO4Fvy3/:0:0:Rolf Sebastian:/home/r0lf:/bin/bash
```

Ejecutar el ataque:

```
john --single passwd
```

John utiliza la información disponible para generar posibles contraseñas y comprobarlas contra el hash.

**Cuándo utilizarlo:** cuando disponemos de información sobre los usuarios, especialmente en sistemas Linux.

### 2.2. Wordlist Mode

El modo `--wordlist` realiza un ataque de diccionario. Prueba las contraseñas de una lista de palabras contra los hashes proporcionados.

**Sintaxis:**

```
john --wordlist=<wordlist_file> <hash_file>
```

**Ejemplo:**

```
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
```

El archivo de hashes debe contener valores que John pueda reconocer y procesar.

Las listas de palabras deben ser archivos de texto con una contraseña por línea.

También podemos aplicar reglas para generar variaciones de las palabras de la lista:

```
john --wordlist=/usr/share/wordlists/rockyou.txt --rules hashes.txt
```

Las reglas pueden realizar transformaciones como:

- Añadir números.
    
- Cambiar mayúsculas y minúsculas.
    
- Añadir caracteres especiales.
    

**Cuándo utilizarlo:** cuando tenemos una lista de contraseñas probables y queremos probarlas rápidamente.

### 2.3. Incremental Mode

El modo `--incremental` realiza un ataque de tipo fuerza bruta, generando contraseñas candidatas sin depender de una wordlist predefinida.

Utiliza modelos estadísticos para priorizar combinaciones probables.

**Sintaxis:**

```
john --incremental hashes.txt
```

John dispone de configuraciones incrementales en su archivo `john.conf`, donde se pueden definir conjuntos de caracteres y longitudes.

Consultar los modos incrementales:

```
grep '# Incremental modes' -A 100 /etc/john/john.conf
```

Entre los ejemplos de configuraciones disponibles en el material están:

|Modo|Descripción|
|---|---|
|`Custom`|Utiliza un conjunto de caracteres personalizado.|
|`UTF8`|Trabaja con un conjunto de caracteres UTF-8 definido en la configuración.|
|`Latin1`|Utiliza el conjunto de caracteres Latin-1 definido en la configuración.|
|`ASCII`|Utiliza caracteres ASCII y, en el ejemplo del módulo, establece una longitud máxima de 13 caracteres.|

**Importante:** este modo puede consumir muchos recursos y tardar bastante tiempo, especialmente con contraseñas largas. Restringir la longitud y los caracteres posibles puede reducir el tiempo necesario.

## 3. Identificación del formato de un hash

Antes de realizar un ataque, debemos identificar el tipo de hash para seleccionar el formato correcto.

Un hash hexadecimal de 32 caracteres, por ejemplo, podría corresponder a MD5, pero también a otros formatos. **La longitud por sí sola no permite identificarlo con certeza.**

### 3.1. Utilizar hashID

La herramienta `hashid` analiza un hash y propone posibles algoritmos.

**Ejemplo:**

```
hashid -j 193069ceb0461e1d40d216e32c79c704
```

La opción `-j` muestra también los formatos compatibles con John the Ripper.

Entre los posibles resultados pueden aparecer:

- MD5 → `raw-md5`
    
- MD4 → `raw-md4`
    
- NTLM → `nt`
    
- LM → `lm`
    
- RIPEMD-128 → `ripemd-128`
    

Un mismo hash puede coincidir con varios formatos posibles. Por tanto, hay que utilizar también el contexto del que procede el hash para determinar el algoritmo más probable.

### 3.2. Especificar el formato en John

Si conocemos el formato del hash, podemos indicárselo a John mediante `--format`.

**Ejemplo con MD5:**

```
john --format=raw-md5 --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
```

**Ejemplo con NTLM:**

```
john --format=nt --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
```

**Ejemplo con SHA-256 sin formato adicional:**

```
john --format=raw-sha256 --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
```

El formato debe coincidir con el tipo real de hash. No todos los hashes que tienen la misma longitud utilizan el mismo algoritmo.

### 3.3. Formatos compatibles con John

John admite numerosos formatos. Algunos importantes son:

|Formato|Uso|
|---|---|
|`raw-md5`|Hashes MD5 sin formato adicional.|
|`raw-md4`|Hashes MD4 sin formato adicional.|
|`raw-sha1`|Hashes SHA-1 sin formato adicional.|
|`raw-sha256`|Hashes SHA-256 sin formato adicional.|
|`raw-sha512`|Hashes SHA-512 sin formato adicional.|
|`nt`|Hashes NTLM de Windows.|
|`lm`|Hashes LM de Windows.|
|`mscash`|Domain Cached Credentials.|
|`mscash2`|Domain Cached Credentials versión 2.|
|`netntlmv2`|Respuestas de autenticación NetNTLMv2.|
|`krb5`|Hashes relacionados con Kerberos 5.|
|`mssql`|Hashes de contraseñas de Microsoft SQL Server.|
|`mysql`|Hashes de contraseñas de MySQL.|
|`zip`|Hashes extraídos de archivos ZIP protegidos.|
|`rar`|Hashes extraídos de archivos RAR protegidos.|
|`pdf`|Hashes extraídos de documentos PDF protegidos.|
|`ssh`|Formato asociado a determinadas claves privadas SSH protegidas.|

Para consultar los formatos disponibles en una instalación concreta:

```
john --list=formats
```

## 4. Descifrado de archivos protegidos con John

John también permite atacar archivos protegidos por contraseña, como documentos PDF, archivos ZIP y RAR, bases de datos KeePass y claves privadas SSH.

Para ello, incluye herramientas auxiliares conocidas como `***2john**`, que extraen del archivo la información necesaria para generar un hash compatible con John.

### 4.1. Flujo de trabajo general

El procedimiento es:

1. Seleccionar la herramienta adecuada para el tipo de archivo.
    
2. Extraer la representación compatible con John.
    
3. Guardarla en un archivo.
    
4. Ejecutar John contra ese archivo.
    
5. Consultar la contraseña recuperada, si el ataque tiene éxito.
    

**Sintaxis general:**

```
<tool> <file_to_crack> > file.hash
```

### 4.2. Ejemplos de herramientas

#### Archivos ZIP

```
zip2john archivo.zip > zip.hash
```

Cracking:

```
john --wordlist=/usr/share/wordlists/rockyou.txt zip.hash
```

#### Archivos RAR

```
rar2john archivo.rar > rar.hash
```

Cracking:

```
john --wordlist=/usr/share/wordlists/rockyou.txt rar.hash
```

#### Documentos PDF

```
pdf2john archivo.pdf > pdf.hash
```

Cracking:

```
john --wordlist=/usr/share/wordlists/rockyou.txt pdf.hash
```

#### Claves privadas SSH

```
ssh2john id_rsa > ssh.hash
```

Cracking:

```
john --wordlist=/usr/share/wordlists/rockyou.txt ssh.hash
```

#### Bases de datos KeePass

```
keepass2john archivo.kdbx > keepass.hash
```

Cracking:

```
john --wordlist=/usr/share/wordlists/rockyou.txt keepass.hash
```

**Nota:** el nombre y la ubicación de las herramientas pueden variar según la instalación. En algunas versiones, `ssh2john` y otras utilidades se distribuyen como scripts dentro del directorio de John.

### 4.3. Localizar herramientas 2john

Para buscar las herramientas instaladas:

```
locate '*2john*'
```

Esto permite identificar utilidades disponibles, como:

- `zip2john`
    
- `rar2john`
    
- `keepass2john`
    
- `putty2john`
    
- `bitlocker2john`
    
- `gpg2john`
    
- `office2john.py`
    
- `7z2john.pl`
    

La disponibilidad exacta depende de la versión y de cómo se haya instalado John the Ripper.

---

## 5. Consultar contraseñas recuperadas

Después de ejecutar John, podemos mostrar las contraseñas recuperadas de forma fiable mediante `--show`.

**Ejemplo:**

```
john --show hashes.txt
```

Si se utilizó un formato específico:

```
john --format=raw-md5 --show hashes.txt
```

Esto resulta útil para consultar los resultados sin tener que volver a ejecutar el ataque.

## 7. Puntos clave para el CPTS

- **Identifica el formato del hash antes de atacarlo.** Utiliza `hashid -j` como ayuda, pero confirma el formato con el contexto.
    
- Utiliza `--single` cuando dispongas de información relevante sobre los usuarios.
    
- Utiliza `--wordlist` para probar contraseñas de una lista y `--rules` para generar variaciones.
    
- Utiliza `--incremental` cuando necesites generar combinaciones sin depender de una wordlist.
    
- Si un archivo está protegido por contraseña, busca la herramienta `*2john` correspondiente a su formato.
    
- Guarda la salida de las herramientas de extracción en un archivo `.hash` y utiliza ese archivo como entrada de John.
    
- Emplea `--format` cuando conozcas el tipo de hash y necesites evitar una identificación incorrecta.
    
- Utiliza `john --show` para consultar los resultados del cracking.
    
- En una prueba de penetración, prioriza las técnicas que tengan más probabilidades de éxito en el tiempo disponible.
