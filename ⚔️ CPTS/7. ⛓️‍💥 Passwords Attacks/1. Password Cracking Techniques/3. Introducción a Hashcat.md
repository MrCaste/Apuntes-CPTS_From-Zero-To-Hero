
## 1. ¿Qué es Hashcat?

**Hashcat** es una herramienta de cracking de contraseñas compatible con Linux, Windows y macOS. Destaca por su soporte para GPU y permite atacar numerosos formatos de hash mediante diferentes técnicas.

Al igual que John the Ripper, admite ataques de diccionario, reglas y fuerza bruta mediante máscaras, entre otros.

### Sintaxis básica

```
hashcat -a <modo_ataque> -m <tipo_hash> <hashes> [wordlist, reglas, máscara...]
```

|Parámetro|Función|
|---|---|
|`-a`|Especifica el modo de ataque.|
|`-m`|Especifica el tipo de hash mediante su identificador numérico.|
|`<hashes>`|Hash individual o archivo con uno o varios hashes del mismo tipo.|
|`wordlist`|Lista de contraseñas candidatas para los modos que la utilizan.|
|`-r`|Aplica un archivo de reglas para transformar las contraseñas candidatas.|

---

## 2. Identificación del tipo de hash

Hashcat admite cientos de formatos de hash, cada uno con un identificador numérico específico.

### 2.1. Consultar los tipos de hash

```
hashcat --help
```

En la sección `Hash Modes` aparecen los identificadores y nombres de los algoritmos compatibles.

### 2.2. Tabla de formatos frecuentes

|Tipo de hash|Identificador (`-m`)|
|---|---|
|MD4|`900`|
|MD5|`0`|
|SHA-1|`100`|
|SHA-256|`1400`|
|SHA-512|`1700`|
|NTLM|`1000`|
|MD5 Crypt|`500`|

**Importante:** el identificador depende del formato exacto del hash, no solo de su algoritmo o longitud.

### 2.3. Identificar hashes con hashID

Podemos utilizar `hashid` con la opción `-m` para obtener posibles formatos e identificadores de Hashcat.

```
hashid -m '$1$FNr44XZC$wQxY6HHLrgrGX0e1195k.1'
```

En este ejemplo, la herramienta propone MD5 Crypt y muestra el identificador `500`.

**Flujo recomendado:**

1. Identificar el formato probable con `hashid -m`.
    
2. Consultar `hashcat --help` o la documentación de Hashcat para verificar el identificador.
    
3. Ejecutar el ataque con el modo de hash correcto.

## 3. Ataque de diccionario (Dictionary Attack)

El ataque de diccionario utiliza una lista de contraseñas candidatas y calcula sus hashes para compararlos con el objetivo.

Se selecciona mediante `-a 0`.

### 3.1. Sintaxis

```
hashcat -a 0 -m <tipo_hash> <hash> <wordlist>
```

### 3.2. Ejemplo con MD5

Supongamos que obtenemos el siguiente hash de una base de datos SQL:

```
e3e3ec5831ad5e7288241960e5d4fdb8
```

Si identificamos que corresponde a MD5, utilizamos el modo `0`:

```
hashcat -a 0 -m 0 e3e3ec5831ad5e7288241960e5d4fdb8 /usr/share/wordlists/rockyou.txt
```

Hashcat probará las contraseñas de `rockyou.txt` hasta recuperar la contraseña o agotar la lista.

### 3.3. Aplicar reglas

Una wordlist por sí sola puede no ser suficiente. Podemos aplicar reglas para generar variaciones de las palabras originales.

Las reglas permiten realizar transformaciones como:

- Añadir números al final.
    
- Cambiar mayúsculas y minúsculas.
    
- Sustituir letras por números o símbolos (_leet_).
    
- Añadir caracteres especiales.
    

Los archivos de reglas suelen encontrarse en:

```
/usr/share/hashcat/rules/
```

Listar las reglas disponibles:

```
ls -l /usr/share/hashcat/rules/
```

### 3.4. Ataque de diccionario con reglas

```
hashcat -a 0 -m 0 1b0556a75770563578569ae21392630c /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
```

En este ejemplo, `best64.rule` aplica 64 transformaciones habituales a las contraseñas de la lista.

**Idea clave:** las reglas amplían el número de contraseñas candidatas sin necesidad de crear manualmente una wordlist con todas sus variaciones.

## 4. Ataque de máscara (Mask Attack)

El ataque de máscara se selecciona con `-a 3`.

Permite definir un patrón conocido de contraseña para reducir el espacio de búsqueda. En lugar de probar todas las combinaciones posibles, Hashcat genera candidatas que cumplen la estructura indicada.

### 4.1. Caracteres integrados

|Símbolo|Conjunto de caracteres|
|---|---|
|`?l`|Letras minúsculas: `abcdefghijklmnopqrstuvwxyz`|
|`?u`|Letras mayúsculas: `ABCDEFGHIJKLMNOPQRSTUVWXYZ`|
|`?d`|Dígitos: `0123456789`|
|`?h`|Dígitos hexadecimales en minúsculas: `0123456789abcdef`|
|`?H`|Dígitos hexadecimales en mayúsculas: `0123456789ABCDEF`|
|`?s`|Caracteres especiales definidos por Hashcat.|
|`?a`|Todos los conjuntos `?l`, `?u`, `?d` y `?s`.|
|`?b`|Todos los valores posibles de un byte: `0x00–0xff`.|

### 4.2. Ejemplo de máscara

Imaginemos que sabemos que la contraseña tiene esta estructura:

- Una letra mayúscula.
    
- Cuatro letras minúsculas.
    
- Un dígito.
    
- Un carácter especial.
    

La máscara correspondiente es:

```
?u?l?l?l?l?d?s
```

Ejecutamos el ataque contra un hash MD5:

```
hashcat -a 3 -m 0 1e293d6912d074c0fd15844d803400dd '?u?l?l?l?l?d?s'
```

Hashcat probará las combinaciones que cumplan ese patrón.

**Importante:** una máscara incorrecta puede excluir la contraseña correcta. Cuanto más precisa sea la información disponible sobre su estructura, más se reduce el espacio de búsqueda.

### 4.3. Conjuntos de caracteres personalizados

Hashcat permite definir conjuntos de caracteres propios con los parámetros `-1`, `-2`, `-3` y `-4`.

Después se utilizan mediante `?1`, `?2`, `?3` y `?4`, respectivamente.

Esto permite restringir el ataque a los caracteres que nos interesan.

---

## 5. Diferencias entre los modos de ataque

|Modo|Parámetro|Funcionamiento|Cuándo utilizarlo|
|---|---|---|---|
|Diccionario|`-a 0`|Prueba palabras de una lista.|Cuando disponemos de contraseñas probables.|
|Diccionario con reglas|`-a 0` y `-r`|Transforma las palabras de una lista para generar variantes.|Cuando la contraseña puede contener modificaciones habituales.|
|Máscara|`-a 3`|Genera candidatas siguiendo un patrón definido.|Cuando conocemos la longitud o estructura de la contraseña.|

## 6. Chuleta rápida para el CPTS

### Identificar un hash

```
hashid -m 'HASH'
```

### Consultar los modos de hash

```
hashcat --help
```

### Ataque de diccionario contra MD5

```
hashcat -a 0 -m 0 hash.txt /usr/share/wordlists/rockyou.txt
```

### Ataque de diccionario con reglas

```
hashcat -a 0 -m 0 hash.txt /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
```

### Listar reglas disponibles

```
ls -l /usr/share/hashcat/rules/
```

### Ataque de máscara contra MD5

```
hashcat -a 3 -m 0 hash.txt '?u?l?l?l?l?d?s'
```

### Recordatorio de parámetros

```
-a 0    Ataque de diccionario
-a 3    Ataque de máscara
-m 0    MD5
-m 100  SHA-1
-m 500  MD5 Crypt
-m 1000 NTLM
-m 1400 SHA-256
-m 1700 SHA-512
-r      Aplicar reglas
```

## 7. Puntos clave para el CPTS

- **Identifica correctamente el tipo de hash** antes de ejecutar Hashcat.
    
- `-a` define el modo de ataque y `-m` define el tipo de hash.
    
- El ataque de diccionario utiliza `-a 0`.
    
- Puedes ampliar una wordlist mediante reglas con `-r`.
    
- `best64.rule` contiene transformaciones habituales de contraseñas.
    
- El ataque de máscara utiliza `-a 3` y permite restringir las combinaciones según un patrón.
    
- Aprende los símbolos `?l`, `?u`, `?d`, `?s` y `?a`.
    
- Si conoces la estructura de una contraseña, una máscara adecuada puede reducir considerablemente el tiempo de cracking.
    
- Comprueba siempre la compatibilidad del formato y las capacidades de tu instalación antes de lanzar ataques.
