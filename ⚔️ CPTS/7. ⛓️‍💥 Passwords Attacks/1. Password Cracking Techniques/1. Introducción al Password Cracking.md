
## 1. ¿Qué es el Password Cracking?

Las contraseñas suelen almacenarse mediante **hashes** para protegerlas en caso de que un atacante obtenga acceso a la base de datos.

Una función hash transforma una entrada de cualquier tamaño en una salida de tamaño normalmente fijo. Algunos algoritmos comunes son:

- **MD5**
    
- **SHA-256**
    

Ejemplo con la contraseña `Soccer06!`:

```
echo -n 'Soccer06!' | md5sum
```

Resultado:

```
40291c1d19ee11a7df8495c4cccefdfa
```

Con SHA-256:

```
echo -n 'Soccer06!' | sha256sum
```

Resultado:

```
a025dc6fabb09c2b8bfe23b5944635f9b68433ebd9a1a09453dd4fee00766d93
```

**Importante:** `echo -n` evita añadir un salto de línea al contenido que se va a hashear.

El hashing está diseñado para funcionar en una sola dirección: no se puede recuperar directamente la contraseña original a partir del hash. El **password cracking** consiste en intentar descubrir la contraseña que genera ese hash.

Las principales técnicas son:

- Tablas arcoíris (_rainbow tables_).
    
- Ataques de diccionario (_dictionary attacks_).
    
- Ataques de fuerza bruta (_brute-force attacks_).
    
- Ataques de máscara (_mask attacks_), que se estudiarán en secciones posteriores.
    

---

## 2. Tablas arcoíris (Rainbow Tables)

Las tablas arcoíris contienen correspondencias precalculadas entre contraseñas y sus hashes.

Si un hash aparece en una tabla, es posible identificar rápidamente la contraseña correspondiente sin tener que calcular todas las posibilidades desde cero.

Ejemplos de hashes MD5:

|Contraseña|Hash MD5|
|---|---|
|`123456`|`e10adc3949ba59abbe56e057f20f883e`|
|`password`|`5f4dcc3b5aa765d61d8327deb882cf99`|
|`12345678`|`25d55ad283aa400af464c76d713c07ad`|
|`abc123`|`e99a18c428cb38d5f260853678922e03`|

### 2.1. Salt

Para dificultar el uso de tablas arcoíris, se utiliza una **salt**: una secuencia de bytes que se combina con la contraseña antes de calcular su hash.

Ejemplo:

```
echo -n 'Th1sIsTh3S@lt_Soccer06!' | md5sum
```

El resultado es diferente al hash MD5 de `Soccer06!` sin salt.

Características importantes:

- La salt debería ser aleatoria y única para cada contraseña almacenada.
    
- No necesita mantenerse en secreto.
    
- El sistema debe conocerla para verificar la contraseña durante la autenticación.
    
- La combinación de contraseña y salt impide reutilizar directamente las tablas precalculadas para contraseñas sin salt.
    
- Una salt de un byte multiplica por 256 las combinaciones que habría que considerar para cubrir todos sus valores posibles.

## 3. Ataque de fuerza bruta (Brute Force)

Consiste en probar todas las combinaciones posibles de caracteres hasta encontrar una que produzca el hash buscado.

Características:

- Puede probar letras, números y símbolos.
    
- El tiempo necesario aumenta considerablemente con la longitud y complejidad de la contraseña.
    
- Las contraseñas cortas pueden ser objetivos viables con hardware de consumo.
    
- Con tiempo suficiente, permite probar todas las combinaciones de un espacio de búsqueda finito.
    
- En la práctica, suele resultar más eficiente utilizar ataques de diccionario o de máscara cuando se dispone de información sobre la contraseña.
    

### Velocidad del cracking

La velocidad depende de dos factores principales:

1. El algoritmo de hashing utilizado.
    
2. El hardware disponible.
    

Según el ejemplo del módulo, un portátil empresarial podría superar los cinco millones de intentos por segundo contra MD5, pero alcanzar solamente unos diez mil por segundo contra DCC2.

**Conclusión:** un hash más costoso de calcular reduce la velocidad a la que se pueden probar contraseñas.

## 4. Ataque de diccionario (Dictionary Attack)

Un ataque de diccionario, también llamado _wordlist attack_, consiste en probar contraseñas de una lista de palabras en lugar de generar todas las combinaciones posibles.

Es especialmente útil durante un pentest porque permite priorizar contraseñas que ya se sabe que son comunes o que han aparecido en filtraciones.

### 4.1. Listas de contraseñas habituales

Algunas fuentes conocidas son:

- `rockyou.txt`
    
- SecLists
    

Para consultar las primeras 20 contraseñas de `rockyou.txt`:

```
head --lines=20 /usr/share/wordlists/rockyou.txt
```

Ejemplo de salida:

```
123456
12345
123456789
password
iloveyou
princess
1234567
rockyou
12345678
abc123
```

### 4.2. RockYou

`rockyou.txt` contiene más de 14 millones de contraseñas reales filtradas tras el ataque sufrido por RockYou en 2009.

Las contraseñas se almacenaban sin cifrar, lo que permitió obtenerlas directamente.

Esta lista resulta útil para probar contraseñas habituales durante ejercicios autorizados de password cracking.

## 5. Comparativa de técnicas

|Técnica|Funcionamiento|Ventaja principal|Limitación|
|---|---|---|---|
|Rainbow Tables|Busca hashes en tablas precalculadas.|Identificación rápida si existe una correspondencia.|Las salts dificultan su reutilización.|
|Brute Force|Prueba todas las combinaciones posibles.|No depende de disponer de una lista de contraseñas.|Puede requerir muchísimo tiempo.|
|Dictionary Attack|Prueba contraseñas de una wordlist.|Eficiente cuando la contraseña es habitual.|No encuentra contraseñas que no estén en la lista.|
|Mask Attack|Restringe las combinaciones según un patrón.|Reduce el espacio de búsqueda cuando se conoce la estructura de la contraseña.|Depende de que el patrón elegido sea correcto.|

## 6. Puntos clave para el CPTS

- Utiliza `md5sum` y `sha256sum` para calcular hashes en Linux.
    
- Recuerda que `echo -n` evita añadir un salto de línea al calcular el hash de una contraseña.
    
- **Hashing no es lo mismo que cifrado:** el hashing está diseñado para ser unidireccional.
    
- Las salts dificultan los ataques basados en hashes precalculados y deberían ser únicas para cada contraseña.
    
- El brute force prueba combinaciones posibles; el dictionary attack utiliza una lista de contraseñas probables.
    
- `rockyou.txt` y SecLists son recursos habituales para ataques de diccionario.
    
- La velocidad de cracking depende del algoritmo de hashing y del hardware.
    
- En un pentest, conviene comenzar con técnicas eficientes, como los ataques de diccionario, antes de recurrir a búsquedas exhaustivas.
