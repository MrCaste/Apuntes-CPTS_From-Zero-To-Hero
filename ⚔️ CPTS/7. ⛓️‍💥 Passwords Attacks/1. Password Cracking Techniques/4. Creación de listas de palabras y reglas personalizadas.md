
## 1. Conceptos clave

Los usuarios suelen crear contraseñas siguiendo patrones predecibles, incluso cuando existen políticas de contraseñas complejas.

**Patrones habituales:**

- Primera letra en mayúscula: `Password`
    
- Añadir números: `Password123`
    
- Añadir un año: `Password2026`
    
- Añadir un mes: `Password10`
    
- Añadir un símbolo al final: `Password2026!`
    
- Sustituir letras por números o símbolos: `P@ssw0rd2026!`
    

Para crear listas de contraseñas personalizadas, podemos combinar:

- Información obtenida mediante **OSINT**.
    
- Palabras relacionadas con la empresa, sus empleados o sus intereses.
    
- Fechas, nombres, lugares y aficiones.
    
- Reglas de mutación con **Hashcat** o **John the Ripper (JtR)**.

## 2. Reglas personalizadas con Hashcat

Hashcat permite transformar las palabras de una lista mediante reglas para generar posibles contraseñas.

### Sintaxis de las reglas

|Regla|Función|Ejemplo|
|---|---|---|
|`:`|No modifica la palabra|`password` → `password`|
|`l`|Convierte todas las letras a minúsculas|`PASSWORD` → `password`|
|`u`|Convierte todas las letras a mayúsculas|`password` → `PASSWORD`|
|`c`|Primera letra mayúscula y resto minúsculas|`password` → `Password`|
|`sXY`|Sustituye todas las apariciones de `X` por `Y`|`so0` → `passw0rd`|
|`$!`|Añade `!` al final|`password` → `password!`|

Las reglas pueden combinarse para generar diferentes variantes.

### Crear una lista de palabras inicial

```
cat password.list
```

Contenido:

```
password
```

### Crear un archivo de reglas

```
nano custom.rule
```

Contenido:

```
:
c
so0
c so0
sa@
c sa@
c sa@ so0
$!
$! c
$! so0
$! sa@
$! c so0
$! c sa@
$! so0 sa@
$! c so0 sa@
```

Cada línea representa una transformación que Hashcat aplicará a las palabras originales.

### Generar la lista de contraseñas mutadas

```
hashcat --force password.list -r custom.rule --stdout | sort -u > mut_password.list
```

**Parámetros importantes:**

- `--force`: fuerza la ejecución ignorando determinadas advertencias.
    
- `-r custom.rule`: aplica las reglas del archivo indicado.
    
- `--stdout`: muestra las palabras generadas en lugar de intentar descifrar hashes.
    
- `sort -u`: ordena los resultados y elimina duplicados.
    
- `>`: guarda los resultados en el archivo de salida.
    

Consultar la lista generada:

```
cat mut_password.list
```

En el ejemplo del módulo, una única palabra de entrada produce estas variantes:

```
password
Password
passw0rd
Passw0rd
p@ssword
P@ssword
P@ssw0rd
password!
Password!
passw0rd!
p@ssword!
Passw0rd!
P@ssword!
p@ssw0rd!
P@ssw0rd!
```

## 3. Reglas predefinidas

Hashcat y John the Ripper incluyen reglas predefinidas para generar variantes de contraseñas.

Una de las más utilizadas es:

```
/usr/share/hashcat/rules/best64.rule
```

Aplicarla a una lista:

```
hashcat --force password.list -r /usr/share/hashcat/rules/best64.rule --stdout | sort -u > mut_password.list
```

Estas reglas aplican transformaciones habituales que pueden aumentar las posibilidades de encontrar una contraseña válida.

## 4. Generación de listas personalizadas mediante OSINT

La información personal y corporativa puede utilizarse para crear listas de palabras más específicas.

**Información útil para investigar:**

- Nombre de la empresa.
    
- Nombre y apellidos del usuario.
    
- Mascotas y familiares.
    
- Fechas de nacimiento y otros años importantes.
    
- Deportes, aficiones e intereses.
    
- Ciudad, región o país.
    
- Palabras relacionadas con la actividad de la organización.
    

Por ejemplo, si conocemos el nombre de una mascota, podemos añadirlo a la lista y generar variantes mediante reglas:

```
bella
Bella
BELLA
bella2026
Bella2026!
B3lla2026!
```

Son ejemplos de patrones posibles, no contraseñas necesariamente válidas.

**Importante:** las reglas de contraseñas de una organización pueden ayudarnos a reducir las posibilidades. Si exige mayúsculas, minúsculas, números, símbolos y una longitud mínima, conviene tener estos requisitos en cuenta al generar la lista.

## 5. Generar listas de palabras con CeWL

**CeWL** permite rastrear un sitio web y extraer palabras que pueden ser relevantes para una organización.

### Comando

```
cewl https://www.inlanefreight.com -d 4 -m 6 --lowercase -w inlane.wordlist
```

**Parámetros:**

- `-d 4`: establece la profundidad de rastreo en 4.
    
- `-m 6`: establece una longitud mínima de palabra de 6 caracteres.
    
- `--lowercase`: guarda las palabras en minúsculas.
    
- `-w inlane.wordlist`: guarda las palabras extraídas en el archivo indicado.
    

### Comprobar el número de palabras

```
wc -l inlane.wordlist
```

En el ejemplo del módulo se obtienen 326 líneas.

### Aplicar reglas a la lista de CeWL

Podemos combinar las palabras extraídas del sitio web con las reglas personalizadas:

```
hashcat --force inlane.wordlist -r custom.rule --stdout | sort -u > inlane_mutated.list
```

Así obtenemos una lista adaptada a la organización y con diferentes variantes de cada palabra.

## 6. Descifrar hashes con listas personalizadas

Una vez generada la lista, podemos utilizarla para intentar descifrar un hash con Hashcat.

### Sintaxis general

```
hashcat -m <hash_mode> hash.txt wordlist.txt
```

Por ejemplo, para un hash MD5:

```
hashcat -m 0 hash.txt inlane_mutated.list
```

**Nota:** antes de ejecutar el ataque debemos identificar correctamente el tipo de hash y seleccionar el modo correspondiente. No debemos asumir que todos los hashes utilizan MD5.

Para consultar los resultados:

```
hashcat -m <hash_mode> hash.txt --show
```

Si no se encuentra la contraseña, podemos mejorar la lista con más palabras relevantes, ajustar las reglas o considerar otros patrones.

## 7. Puntos clave para el CPTS

- Los usuarios suelen seguir patrones predecibles al crear contraseñas, incluso cuando existen políticas de complejidad.
    
- El **OSINT** ayuda a recopilar palabras y datos personales que pueden utilizarse para generar listas dirigidas.
    
- Hashcat permite crear variantes de palabras mediante reglas personalizadas.
    
- `--stdout` permite generar contraseñas sin ejecutar directamente un ataque contra un hash.
    
- `sort -u` elimina las entradas duplicadas de la lista generada.
    
- `best64.rule` es un conjunto de reglas predefinidas útil para probar mutaciones habituales.
    
- **CeWL** extrae palabras de sitios web para crear listas relacionadas con una organización.
    
- Combinar OSINT, listas personalizadas y reglas puede ser más eficaz que utilizar únicamente listas genéricas.
    
- Antes de descifrar un hash, hay que identificar su formato y elegir el modo correcto de Hashcat.
    
- La longitud mínima, los tipos de caracteres obligatorios y otros requisitos de la política de contraseñas deben tenerse en cuenta al preparar el ataque.
