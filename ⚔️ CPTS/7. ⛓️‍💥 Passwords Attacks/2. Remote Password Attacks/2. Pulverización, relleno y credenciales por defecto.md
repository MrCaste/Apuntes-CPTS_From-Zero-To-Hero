
## 1. Password Spraying (Pulverización de contraseñas)

Consiste en probar **una misma contraseña contra múltiples usuarios** para identificar cuentas vulnerables, reduciendo la probabilidad de bloquear una cuenta por demasiados intentos.

Es especialmente útil cuando se sospecha que los usuarios mantienen contraseñas predeterminadas o comunes.

### Herramientas

- **NetExec:** ataques contra servicios como SMB en entornos Windows y Active Directory.
    
- **Kerbrute:** permite realizar operaciones de enumeración y autenticación Kerberos en Active Directory.
    
- **Burp Suite:** útil para probar autenticaciones en aplicaciones web.
    

### Ejemplo con NetExec

```
netexec smb 10.100.38.0/24 -u usernames.list -p 'ChangeMe123!'
```

**Parámetros:**

- `smb`: protocolo objetivo.
    
- `10.100.38.0/24`: rango de direcciones IP.
    
- `-u usernames.list`: lista de usuarios.
    
- `-p 'ChangeMe123!'`: contraseña que se probará contra los usuarios.
    

**Concepto clave:** una contraseña contra muchos usuarios.

## 2. Credential Stuffing (Relleno de credenciales)

Consiste en utilizar **credenciales robadas de un servicio para intentar acceder a otros servicios**.

Este ataque aprovecha la reutilización de contraseñas por parte de los usuarios.

Por ejemplo, unas credenciales obtenidas de una filtración pueden funcionar también en SSH, correo electrónico u otros sistemas empresariales.

### Formato de la lista de credenciales

El archivo `user_pass.list` debe contener pares de credenciales en el formato:

```
usuario1:contraseña1
usuario2:contraseña2
usuario3:contraseña3
```

### Ejemplo con Hydra contra SSH

```
hydra -C user_pass.list ssh://10.100.38.23
```

**Parámetros:**

- `-C user_pass.list`: archivo que contiene parejas de usuario y contraseña.
    
- `ssh://10.100.38.23`: servicio y dirección del objetivo.
    

**Concepto clave:** reutilizar parejas de credenciales obtenidas previamente.

## 3. Default Credentials (Credenciales por defecto)

Muchos dispositivos y aplicaciones incluyen credenciales predeterminadas que deberían cambiarse durante la configuración.

Si los administradores no las modifican, pueden permitir el acceso no autorizado.

### ¿Dónde buscar credenciales por defecto?

- Documentación oficial del producto.
    
- Listas públicas de credenciales conocidas.
    
- Herramientas específicas de búsqueda.
    
- Información del fabricante y modelo del dispositivo.
    

### Instalar Default Credentials Cheat Sheet

```
pip3 install defaultcreds-cheat-sheet
```

### Buscar credenciales de un producto

```
creds search linksys
```

El comando muestra combinaciones conocidas de nombres de usuario y contraseñas para el producto indicado.

Los resultados pueden incluir credenciales vacías, contraseñas comunes y combinaciones específicas del fabricante.

### Uso en un ataque

Una vez identificadas posibles credenciales, podemos crear una lista con el formato `usuario:contraseña` y utilizarla con herramientas como Hydra:

```
hydra -C user_pass.list ssh://10.100.38.23
```

El servicio objetivo debe admitir el protocolo especificado.

### Ejemplos de credenciales predeterminadas

|Fabricante|IP predeterminada|Usuario|Contraseña|

|3Com|`192.168.1.1`|`admin`|`Admin`|
|Belkin|`192.168.2.1`|`admin`|`admin`|

## 4. Diferencias importantes para el examen

|Técnica|Funcionamiento|Ejemplo|
|---|---|---|
|**Password Spraying**|Una contraseña contra muchos usuarios.|Probar `ChangeMe123!` contra una lista de usuarios.|
|**Credential Stuffing**|Parejas de credenciales robadas contra otro servicio.|Reutilizar usuarios y contraseñas filtrados en SSH.|
|**Default Credentials**|Probar credenciales predeterminadas de un producto.|Buscar las credenciales iniciales de un router.|
|**Brute Force tradicional**|Probar múltiples contraseñas contra una cuenta o varias cuentas.|Probar una lista de contraseñas contra un usuario concreto.|

## 6. Puntos clave para CPTS/OSCP

- **Password Spraying:** una contraseña, muchos usuarios.
    
- **Credential Stuffing:** credenciales previamente filtradas, reutilizadas en otros servicios.
    
- **Default Credentials:** credenciales iniciales conocidas del fabricante o producto.
    
- Antes de probar credenciales, identifica los servicios y usuarios disponibles.
    
- Ten en cuenta las políticas de bloqueo de cuentas y los límites de autenticación.
    
- Ajusta las herramientas al protocolo utilizado por el servicio.
    
- En una auditoría real, realiza estas pruebas únicamente con autorización y respetando el alcance establecido.
