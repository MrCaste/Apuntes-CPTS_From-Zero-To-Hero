
## 1. SSH (Secure Shell)

SSH permite administrar sistemas remotos mediante una conexión cifrada.

- **Puerto por defecto:** TCP/22.
    
- **Servidor habitual:** OpenSSH.
    
- **Funciones:** ejecución remota de comandos, transferencia de archivos y reenvío de puertos (_port forwarding_).
    
- **Versiones:** SSH-2 es más seguro que SSH-1, que está obsoleto.
    

### Métodos de autenticación

OpenSSH admite distintos métodos de autenticación:

- Contraseña.
    
- Clave pública.
    
- Basada en el host.
    
- Teclado interactivo.
    
- Desafío-respuesta.
    
- GSSAPI.
    

### Autenticación mediante claves públicas

Se utiliza un par de claves:

- **Clave privada:** permanece en el equipo del usuario y debe mantenerse secreta. Puede protegerse con una _passphrase_.
    
- **Clave pública:** se instala en el servidor, normalmente en `~/.ssh/authorized_keys`.
    

El cliente demuestra que posee la clave privada correspondiente sin tener que transmitirla al servidor.

### Configuración del servidor

Archivo principal:

```
/etc/ssh/sshd_config
```

Consultar la configuración efectiva disponible en el archivo:

```
cat /etc/ssh/sshd_config | grep -v "#" | sed -r '/^\s*$/d'
```

Algunas opciones de configuración relevantes:

|Directiva|Función / riesgo|
|---|---|
|`PasswordAuthentication yes`|Permite autenticación por contraseña; puede facilitar ataques de fuerza bruta.|
|`PermitEmptyPasswords yes`|Permite contraseñas vacías.|
|`PermitRootLogin yes`|Permite intentar iniciar sesión directamente como `root`.|
|`Protocol 1`|Configuración obsoleta e insegura; SSH-1 no debe utilizarse.|
|`X11Forwarding yes`|Permite reenviar aplicaciones gráficas mediante X11.|
|`AllowTcpForwarding yes`|Permite el reenvío de conexiones TCP.|
|`PermitTunnel yes`|Permite crear túneles de red.|
|`DebianBanner yes`|Muestra información de banner específica de Debian.|

**Importante:** estas opciones no son vulnerabilidades por sí solas en todos los contextos. El riesgo depende de la configuración completa, los permisos y la exposición del servicio.

### Enumeración con Nmap

```
sudo nmap -sV -p22 <IP>
```

Identifica el servicio y puede revelar la versión de OpenSSH.

### Auditar la configuración criptográfica con ssh-audit

Instalación desde su repositorio:

```
git clone https://github.com/jtesta/ssh-audit.git
cd ssh-audit
```

Ejecutar la auditoría:

```
./ssh-audit.py <IP>
```

Permite identificar:

- Banner y versión del servidor.
    
- Algoritmos de intercambio de claves.
    
- Algoritmos de claves del host.
    
- Algoritmos de cifrado y MAC.
    
- Configuraciones criptográficas débiles u obsoletas.
    

### Identificar los métodos de autenticación

Conectar en modo verbose:

```
ssh -v <usuario>@<IP>
```

Buscar una línea similar a:

```
Authentications that can continue: publickey,password,keyboard-interactive
```

Esto indica los métodos que el servidor permite probar en ese momento.

Para seleccionar explícitamente la autenticación por contraseña:

```
ssh -v <usuario>@<IP> -o PreferredAuthentications=password
```

### Interpretar el banner SSH

Ejemplo:

```
SSH-2.0-OpenSSH_8.2p1
```

- `SSH-2.0`: versión del protocolo SSH.
    
- `OpenSSH_8.2p1`: versión del software del servidor.
    

La versión puede orientar la investigación de vulnerabilidades conocidas, pero debe verificarse su aplicabilidad antes de intentar explotarlas.

## 2. Rsync

Rsync permite sincronizar y transferir archivos entre sistemas locales y remotos. Utiliza un algoritmo de transferencia diferencial para reducir la cantidad de datos transmitidos.

- **Puerto por defecto:** TCP/873.
    
- Puede funcionar sin autenticación si el servidor está mal configurado.
    
- Puede exponer archivos, copias de seguridad, configuraciones o claves SSH.
    
- También puede utilizar SSH como transporte seguro.
    

### Detectar Rsync

```
sudo nmap -sV -p873 <IP>
```

Ejemplo:

```
873/tcp open rsync (protocol version 31)
```

### Consultar los recursos compartidos

Podemos conectarnos al puerto para consultar los módulos publicados:

```
nc -nv <IP> 873
```

Una vez conectado, escribir:

```
#list
```

Ejemplo de respuesta:

```
@RSYNCD: 31.0
dev             Dev Tools
@RSYNCD: EXIT
```

En este ejemplo, el servidor publica un recurso llamado `dev`.

### Enumerar el contenido de un recurso

```
rsync -av --list-only rsync://<IP>/dev
```

Permite listar los archivos y directorios accesibles sin descargarlos.

Ejemplo de salida:

```
drwxr-xr-x             48 2022/09/19 09:43:10 .
-rw-r--r--               0 2022/09/19 09:34:50 build.sh
-rw-r--r--               0 2022/09/19 09:36:02 secrets.yaml
drwx------              54 2022/09/19 09:43:10 .ssh
```

Prestar especial atención a:

- Archivos de configuración.
    
- Archivos YAML con posibles secretos.
    
- Copias de seguridad.
    
- Directorios `.ssh`.
    
- Scripts de despliegue o compilación.
    

### Descargar el contenido accesible

```
rsync -av rsync://<IP>/dev/ ./dev/
```

Descarga los archivos accesibles del módulo `dev` al directorio local `./dev/`.

### Utilizar Rsync a través de SSH

Si el servicio está configurado para transferir archivos mediante SSH:

```
rsync -av -e ssh ./local/ <usuario>@<IP>:/ruta/remota/
```

Si SSH utiliza un puerto distinto:

```
rsync -av -e "ssh -p 2222" ./local/ <usuario>@<IP>:/ruta/remota/
```

**Flujo de enumeración de Rsync:**

1. Escanear TCP/873.
    
2. Consultar los módulos disponibles.
    
3. Listar los archivos de cada módulo.
    
4. Descargar los archivos permitidos.
    
5. Revisar las configuraciones y buscar posibles credenciales.
    
6. Comprobar si las credenciales encontradas se reutilizan en otros servicios.

## 3. R-Services

Los R-Services son servicios antiguos de Unix para ejecutar comandos, copiar archivos e iniciar sesiones remotas.

Transmiten información sin cifrar y utilizan mecanismos de confianza que pueden permitir accesos sin contraseña si están mal configurados.

### Puertos importantes

|Puerto TCP|Servicio|Función|
|---|---|---|
|512|`rexec`|Ejecución remota de comandos.|
|513|`rlogin`|Inicio de sesión remoto.|
|514|`rsh`|Shell remota y operaciones relacionadas con `rcp`.|

Otros comandos relacionados son:

|Comando|Función|
|---|---|
|`rcp`|Copia archivos entre sistemas.|
|`rexec`|Ejecuta comandos remotos mediante autenticación tradicional.|
|`rlogin`|Abre una sesión en un sistema remoto.|
|`rsh`|Ejecuta comandos o abre una shell remota.|
|`rwho`|Muestra usuarios conectados en los sistemas que anuncian esta información.|
|`rusers`|Consulta información sobre usuarios conectados.|
|`rstat`|Consulta estadísticas del sistema remoto.|
|`ruptime`|Muestra información sobre la disponibilidad de sistemas remotos.|

### Detectar R-Services

```
sudo nmap -sV -p512,513,514 <IP>
```

Una respuesta posible:

```
512/tcp open  exec?
513/tcp open  login?
514/tcp open  tcpwrapped
```

La detección del puerto no demuestra por sí sola que sea posible acceder sin autenticación.

## 4. Relaciones de confianza: `/etc/hosts.equiv` y `.rhosts`

Los R-Services pueden utilizar archivos de confianza para autorizar conexiones desde determinados hosts y usuarios.

### `/etc/hosts.equiv`

Archivo de configuración global del sistema:

```
/etc/hosts.equiv
```

Ejemplo:

```
pwnbox cry0l1t3
```

Esta entrada declara una relación de confianza entre el host `pwnbox` y el usuario local `cry0l1t3`, sujeta a las reglas de los R-Services y al resto de la configuración.

### `.rhosts`

Archivo de confianza asociado a un usuario, normalmente ubicado en su directorio personal.

Ejemplo:

```
htb-student 10.0.17.5
+            10.0.17.10
+            +
```

Interpretación:

- `htb-student 10.0.17.5`: declara confianza para el usuario y host indicados.
    
- `+ 10.0.17.10`: el comodín puede permitir cualquier nombre de usuario desde ese host, dependiendo del servicio y de la implementación.
    
- `+ +`: configuración extremadamente permisiva que puede confiar en cualquier usuario desde cualquier host compatible.
    

Estas configuraciones pueden permitir accesos sin las credenciales habituales. La interpretación exacta depende del servicio y de la implementación.

**Importante:** los archivos de confianza no son credenciales. Son reglas de autorización; una regla demasiado permisiva puede eliminar la necesidad de una autenticación convencional.

## 5. Interacción con R-Services

### Iniciar sesión mediante rlogin

```
rlogin <IP> -l <usuario>
```

Ejemplo:

```
rlogin 10.0.17.2 -l htb-student
```

Si el servicio está habilitado y la política de confianza autoriza la conexión, puede abrirse una sesión remota.

### Consultar usuarios conectados con rwho

```
rwho
```

Ejemplo:

```
root          web01:pts/0       Dec 2 21:34
htb-student   workstn01:tty1    Dec 2 19:57  2:25
```

Puede revelar:

- Nombres de usuario.
    
- Hosts desde los que se mantienen sesiones.
    
- Terminales utilizadas.
    
- Información temporal de las sesiones.
    

Esto ayuda a identificar cuentas y sistemas que merecen una investigación adicional.

### Consultar usuarios con rusers

```
rusers -al <IP>
```

Puede mostrar el usuario, el host, la terminal, la hora de inicio de sesión y otros datos disponibles en el sistema remoto.

**Nota:** la disponibilidad de `rwho` y `rusers` depende de los servicios y de las herramientas instaladas. No todos los sistemas los tienen habilitados.

## 6. Flujo de trabajo recomendado

### SSH

1. Identificar el servicio y su versión:
    
    ```
    sudo nmap -sV -p22 <IP>
    ```
    
2. Auditar los algoritmos y la configuración:
    
    ```
    ./ssh-audit.py <IP>
    ```
    
3. Identificar los métodos de autenticación:
    
    ```
    ssh -v <usuario>@<IP>
    ```
    
4. Revisar las versiones vulnerables, las configuraciones inseguras y las posibilidades de autenticación con credenciales autorizadas.
    

### Rsync

1. Identificar el puerto:
    
    ```
    sudo nmap -sV -p873 <IP>
    ```
    
2. Listar módulos:
    
    ```
    nc -nv <IP> 873
    ```
    
    Después, introducir `#list`.
    
3. Enumerar un módulo:
    
    ```
    rsync -av --list-only rsync://<IP>/<modulo>
    ```
    
4. Descargar los archivos accesibles:
    
    ```
    rsync -av rsync://<IP>/<modulo>/ ./descarga/
    ```
    
5. Buscar configuraciones, credenciales y claves expuestas.
    

### R-Services

1. Escanear los puertos:
    
    ```
    sudo nmap -sV -p512,513,514 <IP>
    ```
    
2. Comprobar si existen relaciones de confianza inseguras.
    
3. Probar `rlogin` o `rsh` únicamente cuando el acceso esté autorizado.
    
4. Enumerar usuarios y sesiones con `rwho` y `rusers`, si están disponibles.

### Conceptos clave

- **SSH:** protocolo cifrado para la administración remota; TCP/22.
    
- **Rsync:** sincronización de archivos; TCP/873. Los módulos expuestos pueden revelar archivos sensibles.
    
- **R-Services:** servicios antiguos que pueden transmitir información sin cifrar; puertos TCP/512, 513 y 514.
    
- `**ssh-audit**`**:** identifica algoritmos y configuraciones criptográficas débiles.
    
- `**.rhosts**` **y** `**/etc/hosts.equiv**`**:** archivos de confianza que, si están mal configurados, pueden permitir accesos sin la autenticación convencional.
    
- **Credenciales reutilizadas:** las credenciales descubiertas en un servicio pueden ser relevantes para otros servicios, siempre que se comprueben de forma autorizada.
