
## 1. RDP (Remote Desktop Protocol)

Protocolo de Microsoft que permite controlar un sistema Windows remotamente mediante una interfaz gráfica (GUI).

- **Puerto TCP:** `3389`
    
- **Puerto UDP:** `3389`
    
- **Uso:** acceso al escritorio remoto de Windows.
    
- **Seguridad:** admite TLS y NLA (Network Level Authentication). NLA exige autenticarse antes de establecer la sesión de escritorio.
    
- **Riesgos:** contraseñas débiles, configuraciones de cifrado inseguras y certificados autofirmados.
    

### Enumeración con Nmap

```
nmap -sV -sC -p3389 <IP>
```

Enumerar información específica del servicio RDP:

```
nmap -sV -sC -p3389 --script rdp* <IP>
```

Podemos obtener información como:

- Nombre del equipo.
    
- Dominio NetBIOS y DNS.
    
- Versión del producto Windows.
    
- Si NLA está habilitado.
    
- Protocolos y mecanismos de seguridad admitidos.
    

Para inspeccionar los paquetes intercambiados:

```
nmap -sV -sC -p3389 --packet-trace --disable-arp-ping -n <IP>
```

**Nota:** las cookies RDP utilizadas por Nmap, como `mstshash=nmap`, pueden ser identificadas por herramientas de monitorización y sistemas EDR.

### Comprobar la seguridad de RDP

Herramienta `rdp-sec-check`:

```
git clone https://github.com/CiscoCXSecurity/rdp-sec-check.git
cd rdp-sec-check
```

Instalar la dependencia Perl indicada por la herramienta si es necesaria:

```
sudo cpan
```

Dentro de CPAN:

```
install Encoding::BER
```

Ejecutar la comprobación:

```
./rdp-sec-check.pl <IP>
```

Permite identificar los protocolos y métodos de cifrado que admite el servidor, incluido el uso de NLA mediante CredSSP.

### Conectarse por RDP desde Linux

Con `xfreerdp`:

```
xfreerdp /u:<USUARIO> /p:'<CONTRASEÑA>' /v:<IP>
```

En sistemas donde se utiliza FreeRDP 3, el ejecutable puede ser `xfreerdp3`:

```
xfreerdp3 /v:<IP> /u:<USUARIO> /p:'<CONTRASEÑA>'
```

Si aparece una advertencia de certificado, comprueba si es autofirmado y si el nombre del certificado coincide con el servidor esperado antes de aceptarlo.

## 2. WinRM (Windows Remote Management)

Protocolo de administración remota de Windows basado en WS-Management y SOAP. Permite ejecutar comandos y administrar sistemas remotamente, normalmente mediante PowerShell.

|Puerto|Protocolo|
|---|---|
|TCP 5985|HTTP|
|TCP 5986|HTTPS|

WinRM puede permitirnos obtener una consola remota si disponemos de credenciales válidas y los permisos necesarios.

### Enumeración con Nmap

```
nmap -sV -sC -p5985,5986 --disable-arp-ping -n <IP>
```

La presencia del puerto `5985` o `5986` indica que merece la pena comprobar si WinRM permite el acceso con las credenciales disponibles.

### Comprobar WinRM desde PowerShell

```
Test-WsMan <IP>
```

Este cmdlet permite comprobar si el equipo responde a las solicitudes de WS-Management. Una respuesta satisfactoria no garantiza que tengamos permisos para iniciar una sesión remota.

### Conectarse mediante Evil-WinRM

Desde Kali Linux:

```
evil-winrm -i <IP> -u <USUARIO> -p '<CONTRASEÑA>'
```

Ejemplo:

```
evil-winrm -i 10.129.201.248 -u 'Cry0l1t3' -p 'P455w0rD!'
```

Si la autenticación funciona y el usuario tiene permisos suficientes, obtendremos una consola PowerShell remota.

**Importante:** si encontramos credenciales durante la enumeración de otros servicios, podemos comprobarlas contra WinRM en el laboratorio autorizado.

## 3. WMI (Windows Management Instrumentation)

WMI es una interfaz de administración de Windows que permite consultar información del sistema y realizar tareas administrativas de forma remota.

Se puede utilizar mediante PowerShell, VBScript, WMIC o herramientas como Impacket.

### Puertos

- **TCP 135:** puerto inicial para la comunicación RPC.
    
- **Puertos dinámicos RPC:** la comunicación puede continuar mediante un puerto dinámico después de establecer la conexión inicial.
    

Por tanto, encontrar abierto el puerto `135` no garantiza por sí solo que WMI sea accesible: también deben ser posibles las comunicaciones RPC necesarias.

### Ejecutar comandos mediante Impacket

La herramienta `wmiexec.py` permite ejecutar comandos remotamente mediante WMI utilizando credenciales válidas.

```
impacket-wmiexec <DOMINIO>/<USUARIO>:'<CONTRASEÑA>'@<IP>
```

Si el entorno dispone de los scripts de Impacket en la ruta habitual:

```
/usr/share/doc/python3-impacket/examples/wmiexec.py <USUARIO>:'<CONTRASEÑA>'@<IP> "hostname"
```

Ejemplo:

```
impacket-wmiexec 'DOMINIO/usuario:Contraseña@10.129.201.248'
```

Una vez autenticados, podemos ejecutar comandos remotos, siempre que la cuenta tenga los permisos necesarios.

**Nota:** el nombre del ejecutable puede variar según cómo se haya instalado Impacket. En Kali suele estar disponible como `impacket-wmiexec` o como un script dentro de los directorios de Impacket.

## 4. Flujo de enumeración recomendado

### Paso 1. Escanear los puertos de administración remota

```
sudo nmap -sV -sC -p135,3389,5985,5986 <IP>
```

Si queremos ampliar la enumeración de RDP:

```
sudo nmap -sV -sC -p3389 --script rdp* <IP>
```

### Paso 2. Interpretar los resultados

|Puerto|Servicio|Siguiente paso|
|---|---|---|
|`135/tcp`|MSRPC|Comprobar la posibilidad de enumerar o utilizar RPC/WMI.|
|`3389/tcp`|RDP|Obtener información con Nmap y comprobar el acceso gráfico.|
|`5985/tcp`|WinRM HTTP|Probar el acceso mediante Evil-WinRM con credenciales autorizadas.|
|`5986/tcp`|WinRM HTTPS|Comprobar el acceso mediante Evil-WinRM con credenciales autorizadas.|

### Paso 3. Comprobar las credenciales encontradas

Si obtenemos credenciales válidas en otro servicio, podemos comprobar si permiten acceder a RDP, WinRM o WMI. La reutilización de contraseñas es una posibilidad importante durante una auditoría.

### Paso 4. Seleccionar la herramienta adecuada

- **RDP:** `xfreerdp3` para acceder al escritorio remoto.
    
- **WinRM:** `evil-winrm` para obtener una consola PowerShell remota.
    
- **WMI:** `impacket-wmiexec` para ejecutar comandos remotamente.

## 5. Resumen rápido para el examen

- **RDP:** TCP/UDP `3389`. Acceso gráfico remoto. Enumerar con Nmap y comprobar NLA.
    
- **WinRM:** TCP `5985` (HTTP) y `5986` (HTTPS). Administración remota mediante PowerShell. Utilizar `evil-winrm`.
    
- **WMI:** TCP `135` para el inicio de la comunicación RPC, seguido normalmente de puertos dinámicos. Utilizar `impacket-wmiexec`.
    
- **Nmap:** `-sV` identifica servicios y versiones; `-sC` ejecuta scripts predeterminados.
    
- **Credenciales:** comprobar si las credenciales encontradas permiten autenticarse en servicios de administración remota.
    
- **Permisos:** que un puerto esté abierto o que un servicio responda no significa que tengamos acceso remoto; la autenticación, los permisos y las reglas del firewall también importan.
