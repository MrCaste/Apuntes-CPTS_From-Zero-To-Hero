
## 1. ¿Qué es SNMP?

**SNMP (Simple Network Management Protocol)** permite monitorizar y administrar dispositivos de red, como routers, switches, servidores y dispositivos IoT. También permite consultar información y modificar configuraciones de forma remota.

|Puerto|Protocolo|Función|
|---|---|---|
|`161/UDP`|SNMP|Consultas y comandos de administración|
|`162/UDP`|SNMP Traps|Notificaciones de eventos enviadas por el agente|

Los **traps** permiten que un dispositivo envíe notificaciones al cliente cuando ocurre un evento, sin que este tenga que solicitar la información previamente.

---

## 2. MIB y OID

### MIB (Management Information Base)

Es un archivo de texto que describe los objetos SNMP disponibles en un dispositivo y cómo acceder a ellos.

Contiene información como:

- Identificadores de objetos.
    
- Nombres y tipos de datos.
    
- Permisos de acceso.
    
- Descripciones de los objetos.
    

La MIB **no contiene los datos del dispositivo**, sino que describe los objetos y la información que puede obtenerse de ellos.

### OID (Object Identifier)

Un OID identifica un objeto dentro de una estructura jerárquica.

Ejemplo:

```
.1.3.6.1.2.1.1.5.0
```

Los OID permiten consultar información específica del sistema. Cuanto más larga es la secuencia numérica, más específico es el objeto identificado.

---

## 3. Versiones de SNMP

|Versión|Características|Riesgos|
|---|---|---|
|SNMPv1|Consultas, configuración y traps|Sin autenticación integrada ni cifrado|
|SNMPv2c|Utiliza cadenas de comunidad y añade funcionalidades|La cadena de comunidad se transmite en texto plano|
|SNMPv3|Autenticación mediante usuario y contraseña, además de opciones de cifrado|Mayor complejidad de configuración|

**Importante para el examen:** SNMPv1 y SNMPv2c pueden exponer información si el servicio es accesible y conocemos una cadena de comunidad válida. SNMPv3 incorpora mecanismos de seguridad adicionales.

---

## 4. Community Strings

Las **community strings** funcionan como una especie de contraseña para controlar el acceso a la información SNMP, especialmente en SNMPv1 y SNMPv2c.

Una cadena habitual es:

```
public
```

Otras pueden ser nombres personalizados definidos por el administrador.

Si la cadena es válida y el dispositivo permite el acceso, podemos consultar información interna del sistema.

### Riesgos principales

- Las cadenas de comunidad pueden transmitirse en texto plano.
    
- Una cadena débil o predecible puede descubrirse mediante diccionarios.
    
- Una configuración permisiva puede exponer información del sistema, usuarios, paquetes instalados y otros datos.
    
- Si existen permisos de escritura mal configurados, podría ser posible modificar valores del dispositivo.

## 5. Configuración de SNMP

El archivo de configuración habitual de `snmpd` es:

```
cat /etc/snmp/snmpd.conf
```

Para mostrar únicamente las líneas no comentadas y no vacías:

```
cat /etc/snmp/snmpd.conf | grep -v "#" | sed -r '/^\s*$/d'
```

Ejemplo de configuración:

```
sysLocation    Sitting on the Dock of the Bay
sysContact     Me <me@example.org>
sysServices    72
master  agentx
agentaddress  127.0.0.1,[::1]
view   systemonly  included   .1.3.6.1.2.1.1
view   systemonly  included   .1.3.6.1.2.1.25.1
rocommunity  public default -V systemonly
rocommunity6 public default -V systemonly
rouser authPrivUser authpriv -V systemonly
```

### Configuraciones peligrosas

|Directiva|Riesgo|
|---|---|
|`rwuser noauth`|Proporciona acceso de escritura al árbol OID completo sin autenticación|
|`rwcommunity <cadena> <IPv4>`|Puede proporcionar acceso de escritura al árbol OID completo|
|`rwcommunity6 <cadena> <IPv6>`|Configura acceso de escritura equivalente mediante IPv6|

Una configuración incorrecta de permisos puede permitir que un usuario no autorizado consulte o modifique información del dispositivo.

## 6. Enumeración con Nmap

SNMP utiliza UDP, por lo que debemos comprobar el puerto `161/UDP`.

```
sudo nmap -sU -p161 <IP>
```

Para obtener información adicional sobre el servicio:

```
sudo nmap -sU -sV -p161 <IP>
```

**Objetivo:** comprobar si SNMP está disponible antes de intentar enumerar sus objetos.

## 7. Enumeración con snmpwalk

`snmpwalk` permite recorrer los OID accesibles y consultar la información asociada a ellos.

### Consultar SNMPv2c

```
snmpwalk -v2c -c public <IP>
```

Ejemplo:

```
snmpwalk -v2c -c public 10.129.14.128
```

Parámetros:

- `-v2c`: utiliza SNMP versión 2c.
    
- `-c public`: establece la cadena de comunidad.
    
- `<IP>`: dirección del objetivo.
    

### Información que podemos obtener

En función de los permisos y los OID expuestos, la salida puede revelar:

- Sistema operativo y versión del kernel.
    
- Nombre del host.
    
- Contacto del administrador.
    
- Ubicación del dispositivo.
    
- Tiempo de actividad.
    
- Información del sistema.
    
- Paquetes instalados.
    

Ejemplo de salida:

```
iso.3.6.1.2.1.1.1.0 = STRING: "Linux htb 5.11.0-34-generic..."
iso.3.6.1.2.1.1.4.0 = STRING: "mrb3n@inlanefreight.htb"
iso.3.6.1.2.1.1.5.0 = STRING: "htb"
iso.3.6.1.2.1.1.6.0 = STRING: "Sitting on the Dock of the Bay"
```

OID útiles del ejemplo:

|OID|Información|
|---|---|
|`.1.3.6.1.2.1.1.1.0`|Descripción del sistema|
|`.1.3.6.1.2.1.1.4.0`|Contacto del sistema|
|`.1.3.6.1.2.1.1.5.0`|Nombre del host|
|`.1.3.6.1.2.1.1.6.0`|Ubicación del sistema|

**Nota:** estos OID corresponden a los ejemplos de la lección. La información realmente disponible dependerá de la configuración del objetivo.

## 8. Descubrir community strings con onesixtyone

Si no conocemos la cadena de comunidad, podemos utilizar `onesixtyone` para probar una lista de posibles valores.

### Instalar la herramienta

```
sudo apt install onesixtyone
```

### Utilizar una lista de SecLists

```
onesixtyone -c /opt/useful/seclists/Discovery/SNMP/snmp.txt <IP>
```

Ejemplo:

```
onesixtyone -c /opt/useful/seclists/Discovery/SNMP/snmp.txt 10.129.14.128
```

Salida de ejemplo:

```
10.129.14.128 [public] Linux htb 5.11.0-37-generic...
```

En este caso, se ha identificado la cadena de comunidad `public`.

### Crear listas personalizadas

Si las cadenas de comunidad siguen un patrón basado en los nombres de los equipos, podemos generar diccionarios personalizados con herramientas como `crunch`.

**Flujo de trabajo:**

1. Probar cadenas habituales.
    
2. Utilizar un diccionario de SecLists.
    
3. Identificar patrones si el objetivo utiliza nombres personalizados.
    
4. Utilizar la cadena encontrada para consultar los OID con `snmpwalk` o `braa`.

## 9. Enumeración de OID con braa

`braa` permite consultar OID de forma masiva utilizando una cadena de comunidad conocida.

### Instalar la herramienta

```
sudo apt install braa
```

### Sintaxis

```
braa <COMMUNITY>@<IP>:.1.3.6.*
```

Ejemplo:

```
braa public@10.129.14.128:.1.3.6.*
```

La salida puede incluir información sobre el sistema, el contacto, el hostname y otros objetos accesibles.

**Diferencia práctica:**

- `snmpwalk`: recorre los OID y muestra la información obtenida.
    
- `onesixtyone`: prueba posibles cadenas de comunidad.
    
- `braa`: permite consultar múltiples OID de manera masiva.
    

---

## 10. Flujo de trabajo recomendado

1. **Comprobar si SNMP está disponible:**
    
    ```
    sudo nmap -sU -sV -p161 <IP>
    ```
    
2. **Probar una cadena de comunidad habitual:**
    
    ```
    snmpwalk -v2c -c public <IP>
    ```
    
3. **Si no funciona, probar un diccionario:**
    
    ```
    onesixtyone -c /opt/useful/seclists/Discovery/SNMP/snmp.txt <IP>
    ```
    
4. **Consultar todos los OID accesibles con la cadena encontrada:**
    
    ```
    snmpwalk -v2c -c <COMMUNITY> <IP>
    ```
    
5. **Buscar información interesante:**
    
    - Hostname.
        
    - Sistema operativo y kernel.
        
    - Contactos y direcciones de correo.
        
    - Ubicación del dispositivo.
        
    - Información del sistema y paquetes instalados.
        
6. **Consultar OID de forma masiva:**
    
    ```
    braa <COMMUNITY>@<IP>:.1.3.6.*
    ```
    
7. **Analizar los resultados** para identificar información útil para continuar la enumeración del objetivo.

## 11. Comandos clave para el examen

|Objetivo|Comando|
|---|---|
|Escanear SNMP por UDP|`sudo nmap -sU -p161 <IP>`|
|Detectar la versión del servicio|`sudo nmap -sU -sV -p161 <IP>`|
|Enumerar SNMPv2c|`snmpwalk -v2c -c public <IP>`|
|Buscar community strings|`onesixtyone -c /opt/useful/seclists/Discovery/SNMP/snmp.txt <IP>`|
|Consultar OID masivamente|`braa public@<IP>:.1.3.6.*`|
|Leer la configuración local|`cat /etc/snmp/snmpd.conf`|
|Mostrar la configuración sin comentarios|`cat /etc/snmp/snmpd.conf \| grep -v "#" \| sed -r '/^\s*$/d'`|

### Ideas importantes

- SNMP utiliza **UDP 161** para consultas y administración, y **UDP 162** para traps.
    
- Las MIB describen los objetos disponibles; los OID identifican esos objetos.
    
- SNMPv1 y SNMPv2c presentan riesgos importantes cuando se exponen sin controles adecuados.
    
- Las community strings permiten controlar el acceso a la información SNMP.
    
- `snmpwalk` enumera los OID accesibles.
    
- `onesixtyone` busca cadenas de comunidad mediante diccionarios.
    
- `braa` permite consultar múltiples OID.
    
- Una configuración con permisos de escritura excesivos puede permitir modificar valores del dispositivo.
