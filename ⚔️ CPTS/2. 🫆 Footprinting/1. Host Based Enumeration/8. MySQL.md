
## 1. ¿Qué es MySQL?

**MySQL** es un sistema de gestión de bases de datos relacionales que utiliza SQL para almacenar, consultar, modificar y eliminar información.

Funciona mediante una arquitectura cliente-servidor:

- **Servidor MySQL:** almacena y administra los datos.
    
- **Cliente MySQL:** se conecta al servidor y ejecuta consultas SQL.
    
- **Bases de datos:** contienen tablas formadas por filas y columnas.
    

Se utiliza habitualmente en aplicaciones web, especialmente en arquitecturas LAMP (Linux, Apache, MySQL y PHP) y LEMP (Linux, Nginx, MySQL y PHP).

Un ejemplo habitual es WordPress, que almacena publicaciones, usuarios, contraseñas y configuraciones en una base de datos.

**Puerto predeterminado:** `3306/TCP`.

## 2. Configuración por defecto

El archivo de configuración habitual de MySQL en Linux es:

```
/etc/mysql/mysql.conf.d/mysqld.cnf
```

Para instalar MySQL en Debian/Kali:

```
sudo apt install mysql-server -y
```

Para mostrar la configuración sin comentarios ni líneas vacías:

```
cat /etc/mysql/mysql.conf.d/mysqld.cnf | grep -v "#" | sed -r '/^\s*$/d'
```

Algunos parámetros importantes:

|Parámetro|Función|
|---|---|
|`user`|Usuario del sistema con el que se ejecuta el servicio|
|`password`|Puede establecer credenciales en determinadas configuraciones|
|`admin_address`|Dirección IP de escucha de la interfaz administrativa|
|`debug`|Configuración de depuración|
|`sql_warnings`|Controla la información generada por determinadas advertencias SQL|
|`secure_file_priv`|Limita determinadas operaciones de importación y exportación de archivos|
|`port`|Puerto utilizado por el servidor|
|`datadir`|Directorio donde se almacenan los datos|
|`socket`|Ruta del socket local|

### Configuraciones peligrosas

- **Credenciales expuestas:** los archivos de configuración con permisos incorrectos pueden revelar usuarios y contraseñas.
    
- **Depuración excesiva:** `debug` y determinadas advertencias pueden revelar información interna.
    
- **Permisos de archivos incorrectos:** pueden permitir que usuarios no autorizados lean archivos sensibles.
    
- **Exposición de la base de datos:** permitir conexiones externas sin controles adecuados amplía la superficie de ataque.
    
- `**secure_file_priv**`**:** sus restricciones influyen en las operaciones de importación y exportación de archivos.
    

Si conseguimos leer un archivo de configuración que contiene credenciales válidas, podemos comprobar si permiten acceder al servidor MySQL.

## 3. Enumeración con Nmap

El puerto habitual de MySQL es `3306/TCP`.

### Escaneo básico

```
sudo nmap <IP> -sV -sC -p3306
```

### Ejecutar scripts relacionados con MySQL

```
sudo nmap <IP> -sV -sC -p3306 --script mysql*
```

Los scripts pueden proporcionar información como:

- Versión del servidor.
    
- Información del protocolo.
    
- Capacidades de autenticación.
    
- Usuarios o credenciales que determinados scripts consigan identificar.
    
- Información sobre configuraciones inseguras.
    

### Interpretar los resultados con cuidado

Nmap puede mostrar posibles credenciales débiles o contraseñas vacías. Sin embargo, estos resultados pueden ser falsos positivos.

**Confirma manualmente cualquier credencial detectada.** Por ejemplo, un resultado que indique que `root` tiene una contraseña vacía no demuestra necesariamente que sea posible iniciar sesión sin contraseña.

## 4. Conexión al servidor MySQL

Para conectarnos necesitamos un cliente MySQL y unas credenciales válidas.

### Sintaxis

```
mysql -u <USUARIO> -p<CONTRASEÑA> -h <IP>
```

**Importante:** si proporcionamos la contraseña directamente con `-p`, no debe haber un espacio entre la opción y la contraseña.

Ejemplo:

```
mysql -u root -pP4SSw0rd -h 10.129.14.128
```

También podemos dejar que el cliente solicite la contraseña:

```
mysql -u root -p -h <IP>
```

### Probar una conexión sin contraseña

```
mysql -u root -h <IP>
```

Si aparece un error como:

```
ERROR 1045 (28000): Access denied for user 'root'@'10.129.14.1' (using password: NO)
```

significa que el servidor ha rechazado el acceso sin contraseña.

## 5. Enumeración de bases de datos

Una vez conectados correctamente, podemos utilizar consultas SQL para enumerar el servidor.

### Mostrar todas las bases de datos

```
SHOW DATABASES;
```

### Consultar la versión del servidor

```
SELECT VERSION();
```

### Seleccionar una base de datos

```
USE <DATABASE>;
```

### Mostrar las tablas

```
SHOW TABLES;
```

### Mostrar las columnas de una tabla

```
SHOW COLUMNS FROM <TABLE>;
```

### Consultar todos los registros de una tabla

```
SELECT * FROM <TABLE>;
```

### Buscar registros que coincidan con un valor

```
SELECT * FROM <TABLE> WHERE <COLUMN> = "<STRING>";
```

Estas consultas permiten conocer la estructura de la base de datos y localizar información relevante según los permisos de la cuenta utilizada.

## 6. Bases de datos importantes

En una instalación de MySQL podemos encontrar varias bases de datos del sistema.

|Base de datos|Función|
|---|---|
|`information_schema`|Contiene metadatos sobre bases de datos, tablas, columnas y otros objetos|
|`mysql`|Almacena información interna relacionada con el funcionamiento y la administración del servidor|
|`performance_schema`|Proporciona información para analizar el rendimiento y la actividad del servidor|
|`sys`|Incluye vistas que facilitan el análisis del rendimiento y la administración|

### Enumerar la base de datos `mysql`

```
USE mysql;
SHOW TABLES;
```

Entre sus tablas se encuentra `user`, que contiene información relacionada con las cuentas de MySQL y sus privilegios, según la versión y la implementación.

### Enumerar la base de datos `sys`

```
USE sys;
SHOW TABLES;
```

Ejemplo de consulta:

```
SELECT host, unique_users FROM host_summary;
```

Esta consulta permite consultar los hosts y el número de usuarios únicos asociados en la vista correspondiente.

**Nota:** la información que podamos consultar depende de los permisos de nuestra cuenta.

## 7. MySQL y MariaDB

**MariaDB** es una bifurcación del proyecto MySQL y mantiene una compatibilidad considerable con sus clientes y herramientas.

Por ello, durante la enumeración podemos encontrar un servidor MariaDB al conectarnos mediante el cliente `mysql`.

No debemos asumir que el nombre del cliente identifica exactamente el motor del servidor: conviene comprobar la versión y el banner.

## 8. Flujo de trabajo recomendado

1. **Comprobar el puerto 3306:**
    
    ```
    sudo nmap <IP> -sV -sC -p3306
    ```
    
2. **Ejecutar los scripts específicos de MySQL:**
    
    ```
    sudo nmap <IP> -sV -sC -p3306 --script mysql*
    ```
    
3. **Analizar los resultados:** identificar la versión, las capacidades y las posibles configuraciones inseguras.
    
4. **Verificar manualmente las credenciales detectadas**, sin asumir que todos los resultados de Nmap son correctos.
    
5. **Intentar una conexión con credenciales válidas:**
    
    ```
    mysql -u <USUARIO> -p -h <IP>
    ```
    
6. **Enumerar las bases de datos:**
    
    ```
    SHOW DATABASES;
    ```
    
7. **Seleccionar las bases de datos interesantes y enumerar sus tablas:**
    
    ```
    USE <DATABASE>;
    SHOW TABLES;
    ```
    
8. **Inspeccionar las columnas y los registros relevantes:**
    
    ```
    SHOW COLUMNS FROM <TABLE>;
    SELECT * FROM <TABLE>;
    ```
    
9. **Buscar información útil**, como usuarios, direcciones de correo, configuraciones y otros datos accesibles con los privilegios obtenidos.
