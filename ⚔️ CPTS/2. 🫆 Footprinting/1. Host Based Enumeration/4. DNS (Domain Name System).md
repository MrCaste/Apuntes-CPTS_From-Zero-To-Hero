
## 1. Conceptos básicos

DNS traduce nombres de dominio a direcciones IP y también permite consultar información adicional, como servidores de correo, servidores DNS y subdominios.

### Tipos de servidores DNS

|Tipo|Función|
|---|---|
|**Root Server**|Interviene en la resolución de dominios de nivel superior (TLD).|
|**Authoritative Nameserver**|Tiene autoridad sobre una zona y proporciona información vinculante sobre ella.|
|**Non-authoritative Nameserver**|Obtiene información de zonas mediante consultas DNS recursivas o iterativas.|
|**Caching DNS Server**|Guarda temporalmente respuestas DNS en caché.|
|**Forwarding Server**|Reenvía consultas a otro servidor DNS.|
|**Resolver**|Realiza la resolución de nombres localmente en el equipo o router.|

DNS normalmente no está cifrado. Algunas alternativas para proteger las consultas son **DoT**, **DoH** y **DNSCrypt**.

## 2. Registros DNS

|Registro|Función|
|---|---|
|`A`|Asocia un dominio con una dirección IPv4.|
|`AAAA`|Asocia un dominio con una dirección IPv6.|
|`MX`|Identifica los servidores de correo del dominio.|
|`NS`|Identifica los servidores DNS del dominio.|
|`TXT`|Almacena información textual, como configuraciones SPF y DMARC o verificaciones de servicios.|
|`CNAME`|Crea un alias que apunta a otro nombre de dominio.|
|`PTR`|Permite la resolución inversa: de una dirección IP a un nombre.|
|`SOA`|Contiene información administrativa sobre la zona DNS, incluyendo el contacto responsable y parámetros de gestión.|

### Consultar el registro SOA

```
dig soa www.inlanefreight.com
```

El registro SOA contiene un correo de contacto. En el formato DNS, el primer punto que separa el usuario del dominio se representa con `.` en lugar de `@`. Por ejemplo:

```
hostmaster.amazon.com.
```

Corresponde a:

```
hostmaster@amazon.com
```

## 3. Configuración de BIND9

BIND9 es un servidor DNS habitual en sistemas Linux.

### Archivos de configuración principales

```
/etc/bind/named.conf
/etc/bind/named.conf.local
/etc/bind/named.conf.options
/etc/bind/named.conf.log
```

- **Archivos de configuración local:** definen el comportamiento general y las zonas DNS.
    
- **Archivos de zona:** contienen los registros DNS de una zona.
    
- **Archivos de resolución inversa:** permiten relacionar direcciones IP con nombres mediante registros PTR.
    

### Ejemplo de configuración de una zona

```
zone "domain.com" {
    type master;
    file "/etc/bind/db.domain.com";
    allow-update { key rndc-key; };
};
```

### Archivos de zona

Un archivo de zona en formato BIND debe contener:

- Exactamente un registro `SOA`.
    
- Al menos un registro `NS`.
    

Ejemplo de registros:

```
$ORIGIN domain.com
$TTL 86400

@       IN SOA    dns1.domain.com. hostmaster.domain.com. (
                  2001062501
                  21600
                  3600
                  604800
                  86400 )

        IN NS     ns1.domain.com.
        IN NS     ns2.domain.com.

        IN MX 10  mx.domain.com.
        IN MX 20  mx2.domain.com.

        IN A      10.129.14.5

server1 IN A      10.129.14.5
server2 IN A      10.129.14.7
ns1     IN A      10.129.14.2
ns2     IN A      10.129.14.3

ftp     IN CNAME  server1
mx      IN CNAME  server1
mx2     IN CNAME  server2
www     IN CNAME  server2
```

Un error de sintaxis puede provocar que toda la zona se considere inutilizable y que el servidor responda con `SERVFAIL`.

### Archivos de resolución inversa

Las consultas inversas utilizan registros `PTR` y el dominio especial `in-addr.arpa` para IPv4.

Ejemplo:

```
$ORIGIN 14.129.10.in-addr.arpa

5 IN PTR server1.domain.com.
```

Este registro asocia la dirección `10.129.14.5` con `server1.domain.com`.

## 4. Configuraciones DNS potencialmente peligrosas

|Opción|Función|
|---|---|
|`allow-query`|Define qué hosts pueden realizar consultas al servidor.|
|`allow-recursion`|Define qué hosts pueden realizar consultas recursivas.|
|`allow-transfer`|Define qué hosts pueden realizar transferencias de zona.|
|`zone-statistics`|Recopila estadísticas de las zonas.|

Una configuración incorrecta de `allow-transfer` puede permitir que un usuario no autorizado descargue registros de una zona, incluyendo nombres de host y direcciones IP internas.

## 5. Enumeración DNS con DIG

La herramienta `dig` permite consultar registros DNS a un servidor específico. La sintaxis general es:

```
dig <tipo_registro> <dominio> @<servidor_DNS>
```

### Consultar servidores de nombres (NS)

```
dig ns inlanefreight.htb @10.129.14.128
```

Permite identificar los servidores DNS responsables del dominio.

La respuesta puede incluir una dirección IP adicional para el servidor de nombres descubierto.

### Consultar la versión del servidor DNS

```
dig CH TXT version.bind 10.129.120.85
```

Utiliza una consulta de clase `CHAOS` y tipo `TXT`. Solo funcionará si el servidor tiene configurada y permite revelar esta información.

### Consultar registros disponibles con ANY

```
dig any inlanefreight.htb @10.129.14.128
```

Puede devolver registros como `TXT`, `SOA` y `NS`. **No garantiza que se muestren todos los registros de la zona.**

### Transferencia de zona (AXFR)

Una transferencia de zona permite obtener los registros DNS de una zona mediante una consulta de transferencia completa. Normalmente se utiliza TCP/53.

```
dig axfr inlanefreight.htb @10.129.14.128
```

Si la transferencia está permitida indebidamente, puede revelar nombres de host, direcciones IP y otros registros del dominio.

También conviene probar posibles zonas internas descubiertas:

```
dig axfr internal.inlanefreight.htb @10.129.14.128
```

**Qué buscar en los resultados:**

- Subdominios y nombres de host.
    
- Direcciones IP internas.
    
- Servidores de correo.
    
- Servidores DNS.
    
- Equipos como controladores de dominio, estaciones de trabajo, servidores VPN o WSUS.
    

## 6. Fuerza bruta de subdominios

Si la transferencia de zona no está permitida, se pueden probar posibles nombres de host mediante una wordlist.

### Fuerza bruta con Bash y DIG

```
for sub in $(cat /opt/useful/seclists/Discovery/DNS/subdomains-top1million-110000.txt); do
    dig $sub.inlanefreight.htb @10.129.14.128 |
    grep -v ';\|SOA' |
    sed -r '/^\s*$/d' |
    grep $sub |
    tee -a subdomains.txt
done
```

El bucle prueba cada nombre de la lista y guarda los resultados coincidentes en `subdomains.txt`.

Wordlist utilizada:

```
/opt/useful/seclists/Discovery/DNS/subdomains-top1million-110000.txt
```

### Fuerza bruta con DNSenum

```
dnsenum --dnsserver 10.129.14.128 \
    --enum -p 0 -s 0 \
    -o subdomains.txt \
    -f /opt/useful/seclists/Discovery/DNS/subdomains-top1million-110000.txt \
    inlanefreight.htb
```

DNSenum automatiza distintas tareas de enumeración, como:

- Obtener servidores de nombres.
    
- Identificar servidores de correo.
    
- Intentar transferencias de zona.
    
- Consultar versiones de BIND.
    
- Realizar fuerza bruta de subdominios.
    

## 7. Flujo de trabajo recomendado

Durante el footprinting de DNS, sigue este orden:

1. **Identificar el servicio DNS:**
    
    ```
    sudo nmap -sV -sC -p53 <IP>
    ```
    
2. **Consultar los servidores de nombres:**
    
    ```
    dig ns <DOMINIO> @<IP_DNS>
    ```
    
3. **Consultar registros adicionales:**
    
    ```
    dig any <DOMINIO> @<IP_DNS>
    ```
    
4. **Probar una transferencia de zona:**
    
    ```
    dig axfr <DOMINIO> @<IP_DNS>
    ```
    
5. **Si AXFR falla, enumerar subdominios:**
    
    ```
    dnsenum --dnsserver <IP_DNS> --enum -p 0 -s 0 \
        -o subdomains.txt \
        -f /opt/useful/seclists/Discovery/DNS/subdomains-top1million-110000.txt \
        <DOMINIO>
    ```
    
6. **Analizar los resultados** y registrar los subdominios, las direcciones IP y los posibles sistemas internos identificados.
    

## 8. Comandos clave para el examen

|Objetivo|Comando|
|---|---|
|Consultar registros NS|`dig ns <DOMINIO> @<DNS>`|
|Consultar registros SOA|`dig soa <DOMINIO>`|
|Consultar registros generales|`dig any <DOMINIO> @<DNS>`|
|Consultar versión de BIND|`dig CH TXT version.bind <DNS>`|
|Intentar transferencia de zona|`dig axfr <DOMINIO> @<DNS>`|
|Enumerar subdominios con wordlist|Bucle Bash con `dig`|
|Automatizar la enumeración DNS|`dnsenum --dnsserver <DNS> --enum -p 0 -s 0 -o subdomains.txt -f <WORDLIST> <DOMINIO>`|

**Idea clave:** una transferencia AXFR mal configurada puede revelar una gran parte de la infraestructura DNS de una organización. Si no funciona, la fuerza bruta de subdominios es una alternativa para descubrir hosts adicionales.
