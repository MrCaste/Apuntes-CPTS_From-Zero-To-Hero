
## 1. Conceptos básicos

**MSSQL (Microsoft SQL Server)** es un sistema de gestión de bases de datos relacionales desarrollado por Microsoft. Es de código cerrado y se encuentra habitualmente en entornos Windows, especialmente en aplicaciones basadas en .NET.

- **Puerto TCP por defecto:** `1433`.
    
- **Autenticación:** Windows Authentication o autenticación propia de SQL Server.
    
- **Protocolo de consultas:** T-SQL (Transact-SQL).
    
- **Cliente recomendado para pentesting:** `mssqlclient.py` de Impacket.
    
- **Instancia por defecto:** `MSSQLSERVER`.
    

### Clientes MSSQL

- SQL Server Management Studio (SSMS).
    
- mssql-cli.
    
- SQL Server PowerShell.
    
- HeidiSQL.
    
- Impacket `mssqlclient.py`.
    

Para localizar el cliente de Impacket:

```
locate mssqlclient
```

Rutas habituales:

```
/usr/bin/impacket-mssqlclient
/usr/share/doc/python3-impacket/examples/mssqlclient.py
```

## 2. Bases de datos del sistema

|Base de datos|Descripción|
|---|---|
|`master`|Información del sistema y de la instancia de SQL Server.|
|`model`|Plantilla utilizada para crear nuevas bases de datos.|
|`msdb`|Trabajos programados y alertas del Agente SQL Server.|
|`tempdb`|Almacena objetos temporales.|
|`resource`|Contiene objetos del sistema; es de solo lectura.|

## 3. Configuración por defecto y errores de seguridad

Algunos aspectos que debemos revisar durante el reconocimiento:

- **Cuentas** `**sa**`**:** comprobar si están habilitadas y si utilizan credenciales débiles o predeterminadas.
    
- **Cifrado:** las conexiones podrían no exigir cifrado.
    
- **Certificados autofirmados:** pueden ser susceptibles de suplantación si no se validan correctamente.
    
- **Named Pipes:** comprobar si están habilitadas.
    
- **Autenticación Windows:** puede permitir el acceso mediante credenciales de dominio o cuentas locales válidas.
    

Si comprometemos una cuenta de Windows con acceso a MSSQL, podríamos obtener acceso a bases de datos y, dependiendo de los permisos, facilitar la escalada de privilegios o el movimiento lateral.

## 4. Reconocimiento con Nmap

MSSQL escucha habitualmente en el puerto TCP `1433`.

### Escaneo básico de servicio

```
sudo nmap -sV -sC -p1433 <IP>
```

### Escaneo con scripts específicos de MSSQL

```
sudo nmap -sV -p1433 \
--script ms-sql-info,ms-sql-empty-password,ms-sql-xp-cmdshell,ms-sql-config,ms-sql-ntlm-info,ms-sql-tables,ms-sql-hasdbaccess,ms-sql-dac,ms-sql-dump-hashes \
--script-args mssql.instance-port=1433,mssql.username=sa,mssql.password=,mssql.instance-name=MSSQLSERVER \
<IP>
```

Estos scripts pueden proporcionar información sobre:

- Nombre del servidor y de la instancia.
    
- Versión de Microsoft SQL Server.
    
- Puerto utilizado.
    
- Información de NTLM y del dominio o equipo.
    
- Existencia de contraseñas vacías.
    
- Tablas y bases de datos accesibles.
    
- Configuración del servicio.
    
- Posibles hashes recuperables, según los permisos y la configuración.
    

**Importante:** los resultados de los scripts pueden contener falsos positivos. Por ejemplo, que Nmap informe de una contraseña vacía para `sa` no garantiza que realmente podamos autenticarnos sin contraseña. Hay que verificarlo manualmente.

## 5. Reconocimiento con Metasploit

Podemos utilizar el módulo auxiliar `mssql_ping` para obtener información de la instancia.

```
msfconsole
```

```
use auxiliary/scanner/mssql/mssql_ping
set RHOSTS <IP>
run
```

Puede revelar:

- Nombre del servidor.
    
- Nombre de la instancia.
    
- Si está agrupado en clúster.
    
- Versión de MSSQL.
    
- Puerto TCP.
    
- Ruta de las Named Pipes.
    

Ejemplo de Named Pipe:

```
\\SQL-01\pipe\sql\query
```

## 6. Conexión con mssqlclient.py

Si obtenemos credenciales válidas, podemos conectarnos remotamente mediante Impacket.

### Autenticación SQL

```
impacket-mssqlclient <USUARIO>:<CONTRASEÑA>@<IP>
```

También podemos utilizar el script directamente:

```
python3 mssqlclient.py <USUARIO>:<CONTRASEÑA>@<IP>
```

### Autenticación de Windows

```
impacket-mssqlclient <DOMINIO>/<USUARIO>@<IP> -windows-auth
```

Ejemplo:

```
impacket-mssqlclient Administrator@10.129.201.248 -windows-auth
```

El cliente solicitará la contraseña.

Si aparece un mensaje indicando que se requiere cifrado y se cambia a TLS, significa que el cliente ha negociado una conexión cifrada.

## 7. Enumeración de bases de datos

Una vez autenticados, podemos ejecutar consultas T-SQL.

### Listar las bases de datos

```
SELECT name FROM sys.databases;
```

### Consultar la versión

```
SELECT @@VERSION;
```

### Consultar la base de datos actual

```
SELECT DB_NAME();
```

### Seleccionar una base de datos

```
USE <NOMBRE_BASE_DATOS>;
```

### Listar las tablas de la base de datos actual

```
SELECT TABLE_NAME
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_TYPE = 'BASE TABLE';
```

### Consultar las columnas de una tabla

```
SELECT COLUMN_NAME, DATA_TYPE
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME = '<TABLA>';
```

### Consultar los datos de una tabla

```
SELECT * FROM <TABLA>;
```

### Buscar registros que coincidan con un valor

```
SELECT *
FROM <TABLA>
WHERE <COLUMNA> = '<VALOR>';
```

## 8. Flujo de trabajo recomendado

1. **Identificar el puerto:** comprobar si TCP `1433` está abierto.
    
2. **Detectar el servicio:** utilizar Nmap con `-sV` y scripts predeterminados.
    
3. **Enumerar MSSQL:** ejecutar los scripts `ms-sql-*` para recopilar información adicional.
    
4. **Comprobar los resultados:** verificar manualmente posibles credenciales vacías y otros hallazgos.
    
5. **Buscar credenciales:** revisar las credenciales disponibles durante la auditoría y comprobar si permiten acceder a MSSQL.
    
6. **Conectarse:** utilizar `impacket-mssqlclient`, con `-windows-auth` cuando corresponda.
    
7. **Enumerar bases de datos:** consultar `sys.databases`.
    
8. **Investigar los permisos:** determinar a qué bases de datos y tablas tenemos acceso.
    
9. **Buscar información relevante:** enumerar tablas, columnas y registros accesibles.

**Puntos clave:**

- MSSQL utiliza normalmente TCP `1433`.
    
- `mssqlclient.py` permite conectarse y ejecutar consultas T-SQL.
    
- `-windows-auth` se utiliza para la autenticación de Windows.
    
- Las bases de datos del sistema incluyen `master`, `model`, `msdb` y `tempdb`.
    
- Los resultados de Nmap deben confirmarse manualmente.
    
- Una autenticación válida no implica automáticamente privilegios administrativos: hay que comprobar los permisos de la cuenta.
