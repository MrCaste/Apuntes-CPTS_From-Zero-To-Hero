
## 1. Diferencias entre IMAP y POP3

### IMAP (Internet Message Access Protocol)

- Permite gestionar los correos directamente en el servidor.
    
- Admite carpetas y estructuras jerárquicas de buzones.
    
- Sincroniza los cambios entre varios clientes.
    
- Los correos permanecen en el servidor hasta que se eliminan.
    
- Requiere una conexión activa para gestionar el buzón, aunque algunos clientes permiten trabajar sin conexión y sincronizar después.
    
- Puerto estándar: `143`.
    
- IMAPS con TLS/SSL: `993`.
    

### POP3 (Post Office Protocol)

- Permite listar, recuperar y eliminar correos del servidor.
    
- Tiene menos funcionalidades que IMAP.
    
- Puerto estándar: `110`.
    
- POP3S con TLS/SSL: `995`.
    

**Importante:** sin cifrado adicional, las credenciales y los mensajes pueden transmitirse en texto plano. TLS/SSL protege la comunicación.

SMTP se utiliza generalmente para enviar correos electrónicos, mientras que IMAP y POP3 permiten acceder a los buzones.

## 2. Puertos que debemos enumerar

|Puerto|Servicio|Descripción|
|---|---|---|
|`110/TCP`|POP3|Acceso a correo mediante POP3|
|`995/TCP`|POP3S|POP3 cifrado con TLS/SSL|
|`143/TCP`|IMAP|Acceso a correo mediante IMAP|
|`993/TCP`|IMAPS|IMAP cifrado con TLS/SSL|

### Escaneo inicial con Nmap

```
sudo nmap <IP> -sV -p110,143,993,995 -sC
```

Permite identificar:

- Servicios y versiones.
    
- Capacidades disponibles en IMAP y POP3.
    
- Certificados SSL/TLS.
    
- Nombres de host, organizaciones y otros datos incluidos en los certificados.
    

**Qué revisar en la salida:**

- El nombre común (`CN`) del certificado, que puede revelar el hostname del servidor.
    
- La organización (`O`) y otros datos del certificado.
    
- Las capacidades del servicio, que indican las funcionalidades y comandos disponibles.
    
- La versión del servidor de correo.

## 3. Comandos IMAP

Los comandos IMAP se identifican mediante una etiqueta, como `A001`, que permite asociar las respuestas del servidor a cada comando.

|Comando|Función|
|---|---|
|`A001 LOGIN username password`|Autenticarse en el servidor|
|`A001 LIST "" *`|Listar todos los directorios o buzones|
|`A001 CREATE "INBOX"`|Crear un buzón|
|`A001 DELETE "INBOX"`|Eliminar un buzón|
|`A001 RENAME "ToRead" "Important"`|Renombrar un buzón|
|`A001 LSUB "" *`|Listar los buzones suscritos|
|`A001 SELECT INBOX`|Seleccionar un buzón|
|`A001 UNSELECT INBOX`|Salir del buzón seleccionado|
|`A001 FETCH <ID> all`|Recuperar los datos asociados a un mensaje|
|`A001 CLOSE`|Eliminar los mensajes marcados como eliminados|
|`A001 LOGOUT`|Cerrar la conexión|

---

## 4. Comandos POP3

|Comando|Función|
|---|---|
|`USER username`|Indicar el usuario|
|`PASS password`|Autenticarse con la contraseña|
|`STAT`|Mostrar el número de correos almacenados|
|`LIST`|Mostrar los identificadores y tamaños de los correos|
|`RETR <ID>`|Recuperar un correo por su identificador|
|`DELE <ID>`|Marcar un correo para eliminarlo|
|`CAPA`|Mostrar las capacidades del servidor|
|`RSET`|Restablecer la información de eliminación transmitida|
|`QUIT`|Cerrar la conexión|

## 5. Configuraciones peligrosas

Algunas configuraciones de Dovecot pueden exponer información sensible mediante registros de depuración o mecanismos de autenticación mal configurados.

|Configuración|Riesgo o función|
|---|---|
|`auth_debug`|Habilita registros de depuración de autenticación|
|`auth_debug_passwords`|Permite registrar las contraseñas transmitidas y el esquema de autenticación|
|`auth_verbose`|Registra los intentos de autenticación fallidos y sus motivos|
|`auth_verbose_passwords`|Permite registrar las contraseñas utilizadas, con posibilidad de truncarlas|
|`auth_anonymous_username`|Especifica el nombre de usuario utilizado para la autenticación SASL anónima|

Estas configuraciones pueden revelar información sensible si se habilitan o configuran incorrectamente.

## 6. Enumeración con cURL

Si disponemos de credenciales válidas, podemos interactuar con un servidor IMAP cifrado mediante `curl`.

### Listar buzones

```
curl -k 'imaps://<IP>' --user <USUARIO>:<CONTRASEÑA>
```

Ejemplo:

```
curl -k 'imaps://10.129.14.128' --user user:p4ssw0rd
```

Una respuesta como esta indica que existen dos buzones:

```
* LIST (\HasNoChildren) "." Important
* LIST (\HasNoChildren) "." INBOX
```

### Obtener información detallada

```
curl -k 'imaps://<IP>' --user <USUARIO>:<CONTRASEÑA> -v
```

La opción `-v` permite observar:

- La negociación TLS.
    
- La versión TLS y el cifrado utilizado.
    
- Los detalles del certificado.
    
- El banner y la versión del servidor.
    
- Los comandos IMAP enviados y las respuestas recibidas.
    

**Nota:** `-k` permite continuar aunque el certificado no sea de confianza, por ejemplo, si es autofirmado.

## 7. Interacción cifrada con OpenSSL

Podemos establecer una conexión TLS directamente para interactuar con IMAP o POP3.

### POP3S

```
openssl s_client -connect <IP>:pop3s
```

Equivale normalmente a conectarse al puerto `995`.

### IMAPS

```
openssl s_client -connect <IP>:imaps
```

Equivale normalmente a conectarse al puerto `993`.

Tras establecer la conexión, podemos observar el certificado y el banner del servicio. Si la conexión queda abierta y el servidor acepta comandos, podemos interactuar directamente con el protocolo.

Un error de verificación como `self signed certificate` indica que el certificado es autofirmado; no significa necesariamente que la conexión TLS no se haya establecido.

## 8. Credenciales reutilizadas

Si durante la enumeración de otros servicios encontramos credenciales, podemos probarlas contra IMAP y POP3 dentro del laboratorio.

Ejemplo del módulo:

```
robin:robin
```

El usuario `robin` había sido identificado previamente durante la enumeración SMTP, y se descubrió que utilizaba su nombre de usuario como contraseña.

Con estas credenciales podemos comprobar si es posible acceder a su buzón.

**Objetivo:** verificar si las credenciales obtenidas en un servicio también permiten acceder a otros servicios de correo.

---

## 9. Flujo de trabajo recomendado

1. **Escanear los puertos de correo:**
    
    ```
    sudo nmap <IP> -sV -p110,143,993,995 -sC
    ```
    
2. **Analizar las capacidades** de IMAP y POP3 para identificar funcionalidades disponibles.
    
3. **Revisar los certificados** para extraer hostnames, organizaciones y otros datos útiles.
    
4. **Buscar credenciales** obtenidas durante la enumeración de otros servicios y probarlas contra IMAP/POP3.
    
5. **Conectarse mediante cURL** para comprobar el acceso y listar los buzones:
    
    ```
    curl -k 'imaps://<IP>' --user <USUARIO>:<CONTRASEÑA>
    ```
    
6. **Usar OpenSSL** para establecer una conexión cifrada e inspeccionar el certificado, el banner y las respuestas del servidor:
    
    ```
    openssl s_client -connect <IP>:imaps
    ```
    
7. **Enumerar los buzones y mensajes** utilizando los comandos del protocolo correspondiente.

## 10. Comandos clave para el examen

|Objetivo|Comando|
|---|---|
|Enumerar IMAP y POP3|`sudo nmap <IP> -sV -p110,143,993,995 -sC`|
|Acceder mediante IMAPS|`curl -k 'imaps://<IP>' --user <USUARIO>:<CONTRASEÑA>`|
|Ver detalles de la conexión IMAPS|`curl -k 'imaps://<IP>' --user <USUARIO>:<CONTRASEÑA> -v`|
|Conectar a POP3S|`openssl s_client -connect <IP>:pop3s`|
|Conectar a IMAPS|`openssl s_client -connect <IP>:imaps`|
|Listar buzones IMAP|`A001 LIST "" *`|
|Seleccionar la bandeja de entrada|`A001 SELECT INBOX`|
|Recuperar un mensaje IMAP|`A001 FETCH <ID> all`|
|Consultar el número de correos POP3|`STAT`|
|Listar correos POP3|`LIST`|
|Recuperar un correo POP3|`RETR <ID>`|

### Ideas importantes

- **IMAP:** permite administrar y sincronizar buzones en el servidor.
    
- **POP3:** ofrece funciones más básicas para listar, recuperar y eliminar correos.
    
- **Puertos cifrados:** IMAPS `993` y POP3S `995`.
    
- **Nmap:** permite descubrir servicios, capacidades y certificados.
    
- **cURL:** facilita la interacción con IMAP cuando tenemos credenciales.
    
- **OpenSSL:** permite establecer conexiones TLS y examinar certificados y banners.
    
- **Credenciales reutilizadas:** las credenciales encontradas en SMTP u otros servicios pueden permitir acceder a los buzones.
    
- **Configuraciones peligrosas:** los registros de autenticación pueden exponer contraseñas y otros datos sensibles.
