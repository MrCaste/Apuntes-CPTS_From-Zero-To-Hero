
## 1. Conceptos básicos

SMTP es el protocolo utilizado para enviar correos electrónicos entre clientes y servidores de correo, o entre dos servidores SMTP.

### Puertos habituales

|Puerto|Uso|
|---|---|
|`25/TCP`|Comunicación SMTP entre servidores y conexiones SMTP tradicionales.|
|`587/TCP`|Envío de correo por clientes autenticados; normalmente utiliza `STARTTLS` para cifrar la conexión.|
|`465/TCP`|SMTP con cifrado TLS desde el inicio de la conexión.|

SMTP transmite comandos, datos y, si no se cifra, credenciales en texto plano. Por eso se utilizan mecanismos como TLS y la extensión ESMTP.

### Componentes del sistema de correo

|Componente|Función|
|---|---|
|**MUA (Mail User Agent)**|Cliente de correo que utiliza el usuario.|
|**MSA (Mail Submission Agent)**|Recibe y valida los mensajes enviados por los clientes.|
|**MTA (Mail Transfer Agent)**|Envía y retransmite correos entre servidores.|
|**MDA (Mail Delivery Agent)**|Entrega los mensajes al buzón del destinatario.|

Flujo simplificado:

```
MUA → MSA → MTA → MDA → Buzón del destinatario
```

Los protocolos IMAP y POP3 se utilizan para acceder a los mensajes almacenados en el buzón.

## 2. SMTP, ESMTP y autenticación

**ESMTP** amplía las funcionalidades de SMTP. Permite negociar capacidades adicionales y utilizar mecanismos como `STARTTLS` y `AUTH`.

- `EHLO`: inicia la sesión y solicita las capacidades del servidor ESMTP.
    
- `HELO`: inicia una sesión SMTP tradicional.
    
- `STARTTLS`: solicita actualizar la conexión a una conexión cifrada.
    
- `AUTH PLAIN`: mecanismo de autenticación del cliente.
    

La autenticación y el cifrado son importantes para impedir el uso no autorizado del servidor y proteger las credenciales.

## 3. Comandos SMTP importantes

|Comando|Función|
|---|---|
|`HELO`|Inicia la sesión SMTP identificando al cliente.|
|`EHLO`|Inicia la sesión y solicita las capacidades ESMTP.|
|`AUTH PLAIN`|Permite autenticar al cliente.|
|`MAIL FROM`|Especifica el remitente del mensaje.|
|`RCPT TO`|Especifica el destinatario.|
|`DATA`|Inicia la transmisión del contenido del correo.|
|`RSET`|Cancela la transacción actual sin cerrar la conexión.|
|`VRFY`|Solicita comprobar un nombre de usuario o buzón.|
|`EXPN`|Solicita expandir o comprobar una lista de correo.|
|`NOOP`|Solicita una respuesta para mantener activa la conexión.|
|`QUIT`|Termina la sesión SMTP.|

## 4. Enumeración SMTP con Telnet

Podemos conectarnos manualmente al puerto SMTP para identificar el servidor y consultar sus capacidades.

### Conexión e identificación

```
telnet <IP> 25
```

Una vez conectado:

```
HELO mail1.inlanefreight.htb
```

O, para solicitar las capacidades ESMTP:

```
EHLO mail1
```

El servidor puede responder con información como:

```
250-mail1.inlanefreight.htb
250-PIPELINING
250-SIZE 10240000
250-ETRN
250-ENHANCEDSTATUSCODES
250-8BITMIME
250-SMTPUTF8
250 CHUNKING
```

**Qué buscar:**

- Nombre del servidor SMTP.
    
- Tamaño máximo de los mensajes.
    
- Capacidades disponibles.
    
- Soporte de comandos como `VRFY`.
    
- Posibles mecanismos de autenticación.
    

### Enumeración de usuarios con VRFY

```
VRFY root
VRFY cry0l1t3
VRFY testuser
```

El servidor puede indicar si un usuario existe, pero el resultado depende de su configuración.

Por ejemplo:

```
252 2.0.0 root
```

Un código `252` no confirma necesariamente que el usuario exista. Algunos servidores devuelven respuestas similares para cualquier nombre, incluso para usuarios inexistentes.

**Importante:** no confíes únicamente en los resultados de herramientas automáticas; contrasta las respuestas del servidor.

## 5. Envío manual de un correo electrónico

Si el servidor permite la operación, podemos construir un correo directamente desde Telnet.

```
telnet <IP> 25
```

A continuación, introducimos los comandos SMTP:

```
EHLO inlanefreight.htb
MAIL FROM: <origen@inlanefreight.htb>
RCPT TO: <destino@inlanefreight.htb>
DATA
From: <origen@inlanefreight.htb>
To: <destino@inlanefreight.htb>
Subject: Prueba

Contenido del mensaje.
.
QUIT
```

### Secuencia del envío

1. `EHLO`: inicia la sesión ESMTP.
    
2. `MAIL FROM`: establece el remitente.
    
3. `RCPT TO`: establece el destinatario.
    
4. `DATA`: inicia el contenido del mensaje.
    
5. Se introducen las cabeceras y el cuerpo.
    
6. Una línea con un único punto (`.`) termina el contenido.
    
7. `QUIT`: cierra la sesión.
    

Una respuesta como `250 2.0.0 Ok: queued as ...` indica que el servidor ha aceptado el mensaje para su procesamiento; no garantiza que haya llegado al buzón final.

## 6. Cabeceras de correo electrónico

Las cabeceras contienen información útil para analizar un mensaje, como:

- Remitente y destinatario.
    
- Fecha de creación y envío.
    
- Servidores por los que ha pasado el mensaje.
    
- Información sobre el contenido y su formato.
    

Las cabeceras pueden ayudar a investigar el origen y la ruta de un correo electrónico.

## 7. Configuraciones peligrosas

### Retransmisión abierta (Open Relay)

Un servidor SMTP configurado como **open relay** puede permitir que usuarios no autorizados retransmitan correos electrónicos a otros dominios.

En Postfix, una configuración excesivamente permisiva podría ser:

```
mynetworks = 0.0.0.0/0
```

Esta configuración considera cualquier dirección IPv4 como parte de las redes de confianza, lo que puede permitir el uso indebido del servidor para retransmitir correo.

Los servidores de retransmisión deben restringir quién puede utilizarlos y validar adecuadamente las conexiones.

### Mail spoofing

El _mail spoofing_ consiste en falsificar la dirección del remitente de un correo electrónico.

Entre los mecanismos utilizados para ayudar a combatir este problema están:

- **SPF:** especifica qué servidores están autorizados a enviar correo para un dominio.
    
- **DKIM:** permite verificar una firma criptográfica asociada al mensaje.
    

## 8. Reconocimiento SMTP con Nmap

### Detección del servicio y sus capacidades

```
sudo nmap -sC -sV -p25 <IP>
```

El script NSE `smtp-commands` puede identificar las capacidades SMTP que anuncia el servidor mediante `EHLO`.

Ejemplo de resultado:

```
25/tcp open smtp Postfix smtpd
|_smtp-commands: mail1.inlanefreight.htb, PIPELINING, SIZE 10240000, VRFY, ETRN, ...
```

Esto permite identificar:

- El servicio y su versión, si se puede determinar.
    
- El nombre del servidor.
    
- Los comandos y extensiones disponibles.
    
- Si se anuncia `VRFY`.
    

### Comprobar si el servidor es un Open Relay

```
sudo nmap -p25 --script smtp-open-relay -v <IP>
```

El script `smtp-open-relay` realiza distintas pruebas para determinar si el servidor permite retransmitir mensajes sin la autorización adecuada.

Un resultado como:

```
| smtp-open-relay: Server is an open relay (16/16 tests)
```

indica que las pruebas realizadas han identificado un posible servidor de retransmisión abierta.

## 9. Flujo de trabajo recomendado

1. **Identificar los puertos SMTP habituales:**
    
    ```
    sudo nmap -sV -sC -p25,465,587 <IP>
    ```
    
2. **Enumerar el servicio SMTP y sus capacidades:**
    
    ```
    sudo nmap -sC -sV -p25 <IP>
    ```
    
3. **Conectarse manualmente al servidor:**
    
    ```
    telnet <IP> 25
    ```
    
4. **Consultar las capacidades ESMTP:**
    
    ```
    EHLO test
    ```
    
5. **Comprobar si** `**VRFY**` **proporciona información útil:**
    
    ```
    VRFY <usuario>
    ```
    
6. **Comprobar posibles problemas de retransmisión abierta:**
    
    ```
    sudo nmap -p25 --script smtp-open-relay -v <IP>
    ```
    
7. **Analizar las respuestas**, teniendo en cuenta que las políticas del servidor pueden limitar la enumeración o devolver resultados ambiguos.
