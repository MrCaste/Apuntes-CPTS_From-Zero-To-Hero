
## 1. Conceptos básicos

- **SMB** es un protocolo cliente-servidor para acceder a archivos, directorios, impresoras y otros recursos compartidos en red.
    
- Se utiliza principalmente en Windows, aunque **Samba** permite implementar SMB en Linux y Unix.
    
- Los permisos de acceso se gestionan mediante **ACL (Access Control Lists)**.
    
- Puertos principales:
    
    - **TCP 445:** SMB directo.
        
    - **TCP 139:** SMB sobre NetBIOS.
        
    - **TCP/UDP 137 y 138:** servicios NetBIOS asociados a nombres y datagramas.
        
- **CIFS** es una implementación antigua basada principalmente en SMB 1.0.
    
- Las versiones SMB 2 y SMB 3 incorporan mejoras de rendimiento y seguridad.
    

### Componentes de Samba

- `smbd`: proporciona el servicio SMB.
    
- `nmbd`: implementa servicios NetBIOS.
    

## 2. Configuración de Samba

Archivo de configuración:

```
cat /etc/samba/smb.conf
```

Mostrar la configuración sin comentarios ni líneas vacías:

```
cat /etc/samba/smb.conf | grep -v "#\|\;"
```

### Parámetros importantes

|Parámetro|Función|
|---|---|
|`[sharename]`|Nombre del recurso compartido.|
|`workgroup = WORKGROUP`|Grupo de trabajo.|
|`path = /path/here/`|Directorio compartido.|
|`server string = STRING`|Descripción del servidor.|
|`browseable = yes`|Permite enumerar el recurso compartido.|
|`read only = yes`|Permite únicamente la lectura.|
|`read only = no`|Permite modificar el contenido, si los permisos lo permiten.|
|`writable = yes`|Permite escribir en el recurso.|
|`guest ok = yes`|Permite el acceso de invitados sin contraseña.|
|`usershare allow guests = yes`|Permite el acceso de invitados a los recursos definidos por usuarios.|
|`map to guest = bad user`|Puede mapear usuarios no válidos a una sesión de invitado.|
|`create mask = 0777`|Define los permisos máximos aplicables a los archivos nuevos.|
|`directory mask = 0777`|Define los permisos máximos aplicables a los directorios nuevos.|
|`logon script = script.sh`|Script asociado al inicio de sesión.|
|`magic script = script.sh`|Script especial ejecutado al cerrar el archivo correspondiente.|
|`magic output = script.out`|Archivo donde se guarda la salida del script mágico.|

### Configuración potencialmente peligrosa

Ejemplo de un recurso compartido con permisos amplios:

```
[notes]
    comment = CheckIT
    path = /mnt/notes/

    browseable = yes
    read only = no
    writable = yes
    guest ok = yes

    enable privileges = yes
    create mask = 0777
    directory mask = 0777
```

Riesgos que debemos comprobar durante la enumeración:

- Recursos compartidos visibles para usuarios no autenticados.
    
- Acceso anónimo sin contraseña.
    
- Permisos de escritura que permitan crear o modificar archivos.
    
- Permisos demasiado amplios sobre archivos y directorios.
    
- Posibilidad de obtener información sensible desde los recursos compartidos.
    

Los permisos efectivos dependen de la configuración del servidor y de los permisos aplicables al recurso.

Después de modificar la configuración, se puede reiniciar el servicio:

```
sudo systemctl restart smbd
```

## 3. Enumeración de recursos compartidos

### 3.1. Enumeración con `smbclient`

Listar los recursos compartidos mediante una sesión anónima:

```
smbclient -N -L //<IP>
```

- `-L`: muestra los recursos compartidos disponibles.
    
- `-N`: no solicita contraseña.
    

Ejemplo:

```
smbclient -N -L //10.129.14.128
```

Podemos encontrar recursos como:

- `home`
    
- `dev`
    
- `notes`
    
- `print$`
    
- `IPC$`
    

**Importante:** que un recurso aparezca en la lista no significa que tengamos permiso para leerlo o escribir en él.

### 3.2. Conectarse a un recurso

```
smbclient //<IP>/<SHARE>
```

Ejemplo:

```
smbclient //10.129.14.128/notes
```

Si el servidor permite el acceso anónimo, podemos entrar sin credenciales válidas.

Dentro de la sesión SMB:

```
help
ls
pwd
cd <directorio>
get <archivo>
put <archivo>
mkdir <directorio>
rm <archivo>
exit
```

Comandos importantes:

|Comando|Función|
|---|---|
|`ls`|Lista archivos y directorios.|
|`cd`|Cambia de directorio.|
|`get <archivo>`|Descarga un archivo al equipo local.|
|`put <archivo>`|Sube un archivo al recurso compartido.|
|`mkdir <directorio>`|Crea un directorio.|
|`rm <archivo>`|Elimina un archivo, si tenemos permisos.|
|`help`|Muestra los comandos disponibles.|
|`exit`|Cierra la sesión.|
|`!<comando>`|Ejecuta un comando en el sistema local sin cerrar la sesión SMB.|

Ejemplo de descarga e inspección:

```
smb: \> ls
smb: \> get prep-prod.txt
smb: \> !ls
smb: \> !cat prep-prod.txt
```

### 3.3. Comprobar las conexiones del servidor

En el servidor Samba:

```
smbstatus
```

Permite consultar información como:

- Versión de Samba.
    
- Usuarios conectados.
    
- IP y equipo cliente.
    
- Recursos compartidos utilizados.
    
- Versión del protocolo SMB.
    
- Archivos bloqueados.
    

## 4. Reconocimiento con Nmap

Escanear los puertos SMB habituales con detección de versiones y scripts predeterminados:

```
sudo nmap -sV -sC -p139,445 <IP>
```

Permite obtener información sobre:

- Estado de los puertos 139 y 445.
    
- Versión del servicio Samba.
    
- Nombre NetBIOS del servidor.
    
- Configuración de la firma SMB.
    
- Información temporal del servicio.
    

En el resultado, presta atención a:

```
139/tcp open  netbios-ssn
445/tcp open  netbios-ssn
```

Y a los scripts:

```
nbstat
smb2-security-mode
smb2-time
```

La salida de Nmap puede ser limitada. Por eso, conviene complementarla con herramientas que permitan realizar consultas SMB y RPC específicas.

## 5. Enumeración con `rpcclient`

`rpcclient` permite ejecutar funciones MS-RPC contra un servidor SMB.

Conexión sin proporcionar un usuario:

```
rpcclient -U "" <IP>
```

Para intentar una sesión anónima sin contraseña:

```
rpcclient -N -U "" <IP>
```

### Comandos principales

|Comando|Información obtenida|
|---|---|
|`srvinfo`|Información del servidor.|
|`enumdomains`|Dominios o grupos de trabajo enumerados por el servidor.|
|`querydominfo`|Información del dominio, servidor y usuarios.|
|`netshareenumall`|Enumera los recursos compartidos.|
|`netsharegetinfo <share>`|Obtiene información sobre un recurso específico.|
|`enumdomusers`|Enumera usuarios del dominio o entorno SMB.|
|`queryuser <RID>`|Consulta información de un usuario por su RID.|
|`querygroup <RID>`|Consulta información de un grupo por su RID.|

Ejemplo de enumeración:

```
rpcclient $> srvinfo
rpcclient $> enumdomains
rpcclient $> querydominfo
rpcclient $> netshareenumall
rpcclient $> netsharegetinfo notes
rpcclient $> enumdomusers
```

### Enumerar usuarios y consultar sus RID

```
rpcclient $> enumdomusers
```

Ejemplo de resultado:

```
user:[mrb3n] rid:[0x3e8]
user:[cry0l1t3] rid:[0x3e9]
```

Consultar un usuario por su RID:

```
rpcclient $> queryuser 0x3e9
```

La consulta puede revelar:

- Nombre de usuario.
    
- Nombre completo.
    
- Directorio personal.
    
- Ruta del perfil.
    
- RID del usuario.
    
- RID del grupo principal.
    
- Fechas relacionadas con la contraseña.
    
- Contadores de inicio de sesión y errores de contraseña.
    

Consultar un grupo por su RID:

```
rpcclient $> querygroup 0x201
```

### 5.1. Fuerza bruta de RIDs

Si podemos consultar usuarios por RID, pero no conocemos todos los RID asignados, podemos recorrer un rango y filtrar los resultados.

```
for i in $(seq 500 1100); do
    rpcclient -N -U "" <IP> \
        -c "queryuser 0x$(printf '%x\n' "$i")" |
        grep "User Name\|user_rid\|group_rid" &&
        echo ""
done
```

Este procedimiento:

1. Recorre los RID del 500 al 1100.
    
2. Convierte cada número decimal a hexadecimal.
    
3. Consulta el RID mediante `queryuser`.
    
4. Filtra los campos relevantes.
    

El rango es un ejemplo y puede adaptarse al entorno.

**Objetivo:** descubrir usuarios y sus grupos aunque no todos aparezcan mediante la enumeración normal.

## 6. Enumeración con Impacket

`samrdump.py` automatiza consultas RPC para obtener información de usuarios.

```
samrdump.py <IP>
```

Puede mostrar:

- Dominios o grupos de trabajo.
    
- Usuarios y sus identificadores.
    
- Nombre completo y comentarios.
    
- Grupo principal.
    
- Estado de la cuenta.
    
- Contador de contraseñas incorrectas.
    
- Fecha del último cambio de contraseña.
    
- Ruta del script de inicio de sesión.
    

Es una alternativa a enumerar manualmente mediante `rpcclient`.

## 7. Enumeración con SMBMap

Listar los recursos compartidos y los permisos disponibles:

```
smbmap -H <IP>
```

Ejemplo:

```
smbmap -H 10.129.14.128
```

La salida muestra los recursos compartidos y los permisos detectados, por ejemplo:

```
Share       Permissions
-----       -----------
print$      NO ACCESS
home        NO ACCESS
dev         NO ACCESS
notes       READ,WRITE
IPC$        NO ACCESS
```

Debemos identificar especialmente:

- Recursos con permisos `READ`.
    
- Recursos con permisos `WRITE`.
    
- Recursos con permisos `READ,WRITE`.
    
- Recursos sin acceso.
    

Un recurso con permisos de escritura puede permitir modificar o crear archivos, dependiendo de las restricciones efectivas.

## 8. Enumeración con CrackMapExec

Enumerar los recursos compartidos utilizando credenciales vacías:

```
crackmapexec smb <IP> --shares -u '' -p ''
```

Ejemplo:

```
crackmapexec smb 10.129.14.128 --shares -u '' -p ''
```

Puede mostrar:

- Nombre del servidor.
    
- Sistema operativo identificado.
    
- Dominio o grupo de trabajo.
    
- Estado de la firma SMB.
    
- Compatibilidad con SMBv1.
    
- Recursos compartidos y permisos detectados.
    

Compara los resultados con los de `smbclient` y `smbmap`: cada herramienta puede proporcionar información diferente.

## 9. Enumeración con enum4linux-ng

`enum4linux-ng` automatiza múltiples consultas SMB y RPC.

### Instalación

```
git clone https://github.com/cddmp/enum4linux-ng.git
cd enum4linux-ng
pip3 install -r requirements.txt
```

### Enumeración completa

```
./enum4linux-ng.py <IP> -A
```

La opción `-A` solicita una enumeración amplia.

Puede obtener información sobre:

- Puertos y servicios accesibles.
    
- Nombres NetBIOS.
    
- Dominio o grupo de trabajo.
    
- Dialectos SMB admitidos.
    
- Si la firma SMB es obligatoria.
    
- Posibilidad de establecer sesiones anónimas.
    
- Sistema operativo estimado.
    
- Usuarios y grupos.
    
- Recursos compartidos y accesibilidad.
    
- Políticas de contraseñas.
    
- Políticas de bloqueo de cuentas.
    
- Impresoras.
    

### Datos importantes para revisar

En la información del protocolo:

```
SMB 1.0: false
SMB 2.02: true
SMB 2.1: true
SMB 3.0: true
SMB signing required: false
```

En la información de las políticas, revisa especialmente:

- Longitud mínima de contraseña.
    
- Complejidad obligatoria.
    
- Umbral de bloqueo.
    
- Duración del bloqueo.
    
- Ventana de observación.
    

La herramienta puede fallar al comprobar determinados recursos o servicios. Sus resultados deben verificarse manualmente.

## 10. Flujo de trabajo recomendado

### Paso 1: identificar los puertos SMB

```
sudo nmap -sV -sC -p139,445 <IP>
```

### Paso 2: enumerar recursos compartidos de forma anónima

```
smbclient -N -L //<IP>
```

### Paso 3: comprobar los permisos de los recursos

```
smbmap -H <IP>
```

### Paso 4: enumerar recursos con credenciales vacías

```
crackmapexec smb <IP> --shares -u '' -p ''
```

### Paso 5: acceder a los recursos accesibles

```
smbclient -N //<IP>/<SHARE>
```

Dentro de la sesión:

```
ls
cd <directorio>
get <archivo>
```

### Paso 6: enumerar información mediante RPC

```
rpcclient -N -U "" <IP>
```

Una vez conectado:

```
srvinfo
enumdomains
querydominfo
netshareenumall
enumdomusers
```

### Paso 7: automatizar la enumeración

```
samrdump.py <IP>
```

```
./enum4linux-ng.py <IP> -A
```

### Paso 8: revisar y contrastar los resultados

Busca:

- Usuarios y RID identificados.
    
- Recursos compartidos accesibles.
    
- Archivos potencialmente sensibles.
    
- Permisos de escritura.
    
- Acceso anónimo o mediante sesiones nulas.
    
- Políticas de contraseñas débiles.
    
- Información del sistema y del dominio.
    
- Diferencias entre los resultados de las herramientas.
    

## Ideas clave para el examen

- **TCP 445:** SMB directo.
    
- **TCP 139:** SMB sobre NetBIOS.
    
- `**smbclient -N -L //<IP>**`**:** enumera recursos compartidos sin introducir contraseña.
    
- `**smbclient //<IP>/<SHARE>**`**:** conecta a un recurso compartido.
    
- `**get <archivo>**`**:** descarga un archivo desde SMB.
    
- `**smbstatus**`**:** muestra el estado de las conexiones del servidor Samba.
    
- `**rpcclient**`**:** permite consultar información SMB mediante MS-RPC.
    
- `**enumdomusers**`**:** enumera usuarios.
    
- `**queryuser <RID>**`**:** obtiene información de un usuario a partir de su RID.
    
- `**smbmap -H <IP>**`**:** comprueba recursos compartidos y permisos.
    
- `**crackmapexec smb <IP> --shares -u '' -p ''**`**:** enumera recursos con credenciales vacías.
    
- `**samrdump.py <IP>**`**:** automatiza la enumeración de usuarios mediante RPC.
    
- `**enum4linux-ng.py <IP> -A**`**:** realiza una enumeración amplia de SMB y RPC.
    
- Un recurso visible no implica que sea accesible.
    
- Un recurso accesible en lectura no implica que permita escribir.
    
- El acceso anónimo puede revelar usuarios, archivos, recursos compartidos y políticas.
    
- No confíes únicamente en una herramienta automatizada: **contrasta los resultados con varias herramientas y valida manualmente los hallazgos**.
