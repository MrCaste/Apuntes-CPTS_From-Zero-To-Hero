
## 1. FTP (File Transfer Protocol)

FTP es un protocolo de transferencia de archivos que funciona sobre TCP.

### Puertos y canales

FTP utiliza dos canales:

- **Puerto TCP 21:** canal de control para enviar comandos y recibir respuestas del servidor.
    
- **Puerto TCP 20:** asociado al canal de datos en el modo activo.
    

### FTP activo vs. pasivo

|Modo|Funcionamiento|
|---|---|
|Activo|El cliente establece el canal de control y comunica al servidor el puerto del cliente al que debe conectarse para transferir datos.|
|Pasivo|El servidor anuncia un puerto de datos y el cliente inicia la conexión hacia él.|

El modo pasivo facilita las transferencias cuando el cliente está detrás de un firewall que bloquea conexiones entrantes.

### Características de seguridad

- FTP tradicional transmite información en **texto plano**, incluidas las credenciales.
    
- Algunos servidores permiten el acceso anónimo sin credenciales legítimas.
    
- Los banners pueden revelar el servicio, su versión y otros detalles del sistema.
    
- Los permisos de lectura y escritura determinan qué archivos podemos descargar o modificar.

## 2. TFTP (Trivial File Transfer Protocol)

TFTP es un protocolo de transferencia de archivos más sencillo que FTP.

|Característica|FTP|TFTP|
|---|---|---|
|Transporte|TCP|UDP|
|Autenticación de usuario|Puede requerir credenciales|No proporciona autenticación de usuario|
|Contraseña|Puede utilizarse|No dispone de inicio de sesión protegido por contraseña|
|Listado de directorios|Sí|No|
|Seguridad|Puede transmitir datos en texto plano|Carece de mecanismos de seguridad y autenticación propios de FTP|

TFTP utiliza UDP, por lo que necesita mecanismos de recuperación en la capa de aplicación para gestionar las transferencias.

### Comandos de TFTP

|Comando|Función|
|---|---|
|`connect`|Establece el host remoto y, opcionalmente, el puerto.|
|`get`|Descarga archivos del host remoto.|
|`put`|Sube archivos al host remoto.|
|`quit`|Sale del cliente TFTP.|
|`status`|Muestra el estado de la conexión y la configuración de transferencia.|
|`verbose`|Activa o desactiva la salida detallada.|

**Importante:** TFTP no permite listar directorios. Su acceso depende de los permisos de los archivos y directorios compartidos.

## 3. Configuración de vsFTPd

`vsFTPd` es uno de los servidores FTP utilizados habitualmente en sistemas Linux.

### Instalación

```
sudo apt install vsftpd
```

Archivo de configuración principal:

```
/etc/vsftpd.conf
```

Consultar la configuración sin mostrar las líneas comentadas:

```
cat /etc/vsftpd.conf | grep -v "#"
```

### Opciones importantes

|Configuración|Función|
|---|---|
|`listen=NO`|Indica que el servicio no se ejecuta como demonio independiente, sino mediante `inetd`.|
|`listen_ipv6=YES`|Habilita la escucha en IPv6.|
|`anonymous_enable=NO`|Deshabilita el acceso anónimo.|
|`local_enable=YES`|Permite iniciar sesión a usuarios locales.|
|`dirmessage_enable=YES`|Muestra mensajes al entrar en determinados directorios.|
|`use_localtime=YES`|Utiliza la hora local.|
|`xferlog_enable=YES`|Activa el registro de transferencias.|
|`connect_from_port_20=YES`|Utiliza el puerto 20 para conexiones de datos en modo activo.|
|`secure_chroot_dir`|Especifica un directorio vacío utilizado por el servicio.|
|`pam_service_name=vsftpd`|Define el servicio PAM utilizado para la autenticación.|
|`rsa_cert_file`|Especifica el certificado RSA.|
|`rsa_private_key_file`|Especifica la clave privada RSA.|
|`ssl_enable=NO`|Deshabilita el soporte SSL/TLS.|

### Usuarios bloqueados: `/etc/ftpusers`

Este archivo contiene los usuarios a los que se les deniega el acceso FTP.

```
cat /etc/ftpusers
```

Ejemplo:

```
guest
john
kevin
```

Aunque estos usuarios existan en Linux, no podrán iniciar sesión mediante FTP si están incluidos en la lista de bloqueo.

## 4. Configuraciones potencialmente peligrosas

Las siguientes opciones pueden habilitar el acceso anónimo y operaciones de escritura.

|Configuración|Función|
|---|---|
|`anonymous_enable=YES`|Permite iniciar sesión de forma anónima.|
|`anon_upload_enable=YES`|Permite subir archivos a usuarios anónimos.|
|`anon_mkdir_write_enable=YES`|Permite crear directorios a usuarios anónimos.|
|`no_anon_password=YES`|No solicita contraseña a los usuarios anónimos.|
|`anon_root=/home/username/ftp`|Establece el directorio raíz para usuarios anónimos.|
|`write_enable=YES`|Habilita comandos FTP de escritura, modificación y eliminación, sujetos a permisos y otras restricciones.|

**Riesgos principales:**

- Acceso no autorizado a archivos.
    
- Exposición de documentos internos.
    
- Subida de archivos no autorizados.
    
- Modificación o eliminación de archivos cuando los permisos lo permiten.
    

La posibilidad de subir archivos a un servidor FTP asociado a un servidor web puede ser especialmente relevante durante la evaluación de seguridad. No implica por sí sola que se consiga ejecución de comandos.

## 5. Enumeración manual de FTP

### Conectarse al servidor

```
ftp <IP>
```

Ejemplo:

```
ftp 10.129.14.136
```

Si el servidor permite acceso anónimo, introducir:

```
Name: anonymous
```

El servidor puede devolver códigos como:

- `220`: servicio preparado; normalmente incluye el banner.
    
- `230`: inicio de sesión correcto.
    
- `226`: transferencia o listado completado.
    

### Comandos útiles dentro del cliente FTP

|Comando|Función|
|---|---|
|`ls`|Lista los archivos y directorios accesibles.|
|`pwd`|Muestra el directorio remoto actual.|
|`cd <directorio>`|Cambia de directorio remoto.|
|`get <archivo>`|Descarga un archivo.|
|`put <archivo>`|Sube un archivo.|
|`status`|Muestra el estado de la sesión FTP.|
|`debug`|Activa información de depuración.|
|`trace`|Muestra información sobre los comandos y el tráfico del protocolo.|
|`ls -R`|Intenta listar recursivamente los directorios accesibles.|
|`exit`|Cierra la sesión FTP.|

### Obtener información de la sesión

```
ftp> status
ftp> debug
ftp> trace
ftp> ls
```

`debug` y `trace` pueden proporcionar información adicional sobre los comandos enviados y las respuestas del servidor.

### Ocultación de identificadores

La opción:

```
hide_ids=YES
```

hace que los listados muestren `ftp` en lugar de los nombres de usuario y grupo reales.

Esto dificulta identificar los propietarios originales de los archivos a partir del listado.

### Listado recursivo

```
ftp> ls -R
```

Permite explorar los directorios accesibles y obtener una visión más amplia de la estructura de archivos, siempre que el servidor lo permita.

## 6. Descargar y subir archivos

### Descargar un archivo

Dentro de una sesión FTP:

```
ftp> get "Important Notes.txt"
```

Si el nombre contiene espacios, se puede utilizar el nombre entre comillas o escapar los espacios según el cliente.

### Descargar archivos y directorios accesibles

Para descargar recursivamente los archivos disponibles mediante FTP anónimo:

```
wget -m --no-passive ftp://anonymous:anonymous@<IP>
```

- `-m`: activa el modo de descarga espejo, recorriendo el contenido accesible.
    
- `--no-passive`: utiliza el modo FTP activo en lugar del pasivo.
    

Los archivos se guardan localmente, normalmente en un directorio con el nombre del host.

**Precaución:** descargar todo el contenido puede generar un volumen de tráfico inusual y alertas de seguridad. Hazlo únicamente cuando esté autorizado.

### Subir un archivo

Crear un archivo local:

```
touch testupload.txt
```

Dentro de la sesión FTP:

```
ftp> put testupload.txt
```

Comprobar el resultado:

```
ftp> ls
```

La subida solo funcionará si el servidor y los permisos permiten escribir en el directorio remoto.

## 7. Enumeración de FTP con Nmap

### Actualizar la base de datos de scripts NSE

```
sudo nmap --script-updatedb
```

Los scripts NSE suelen encontrarse en:

```
/usr/share/nmap/scripts/
```

Localizar scripts relacionados con FTP:

```
find / -type f -name 'ftp*' 2>/dev/null | grep scripts
```

### Scripts FTP relevantes

|Script|Función|
|---|---|
|`ftp-anon`|Comprueba si se permite el acceso anónimo y puede mostrar el contenido accesible.|
|`ftp-syst`|Consulta información de estado del servidor mediante el comando `STAT`.|
|`ftp-brute`|Comprueba credenciales mediante fuerza bruta.|
|`ftp-bounce`|Comprueba el comportamiento relacionado con FTP bounce.|
|`ftp-vsftpd-backdoor`|Comprueba una vulnerabilidad de puerta trasera asociada a determinadas versiones de vsFTPd.|
|`ftp-proftpd-backdoor`|Comprueba una vulnerabilidad de puerta trasera asociada a ProFTPD.|

### Escaneo inicial

```
sudo nmap -sV -p 21 -sC -A <IP>
```

- `-sV`: detecta el servicio y su versión.
    
- `-p 21`: escanea el puerto TCP 21.
    
- `-sC`: ejecuta los scripts NSE predeterminados.
    
- `-A`: habilita funciones de detección adicionales, como detección de SO, trazado de ruta y scripts predeterminados.
    

El resultado puede revelar:

- Banner y versión del servidor FTP.
    
- Si se permite acceso anónimo.
    
- Archivos y directorios accesibles.
    
- Posibles permisos de escritura.
    
- Información de estado del servidor.
    

### Ejecutar scripts concretos

```
sudo nmap -p 21 --script ftp-anon,ftp-syst <IP>
```

### Rastrear las interacciones de NSE

```
sudo nmap -sV -p 21 -sC -A <IP> --script-trace
```

`--script-trace` muestra las interacciones de los scripts con el servicio, incluyendo comandos enviados y respuestas recibidas.

## 8. Interacción directa con el servicio

### Netcat

```
nc -nv <IP> 21
```

### Telnet

```
telnet <IP> 21
```

Estas herramientas permiten conectarse directamente al servicio y observar el banner o interactuar con él.

### FTP con TLS/SSL

Si el servidor utiliza TLS, puede emplearse OpenSSL para iniciar una conexión FTP protegida y examinar su certificado.

```
openssl s_client -connect <IP>:21 -starttls ftp
```

El certificado puede revelar información útil, como:

- Nombre del host.
    
- Organización.
    
- Unidad organizativa.
    
- Dirección de correo electrónico.
    
- Datos geográficos incluidos en el certificado.
    

Un error de certificado autofirmado no demuestra por sí mismo que el servicio sea vulnerable; indica que el certificado no está firmado por una autoridad de confianza reconocida por el cliente.

## 9. Flujo de enumeración recomendado

```
# 1. Detectar el servicio FTP y su versión
sudo nmap -sV -p 21 <IP>

# 2. Ejecutar scripts predeterminados
sudo nmap -sV -p 21 -sC <IP>

# 3. Comprobar acceso anónimo
sudo nmap -p 21 --script ftp-anon <IP>

# 4. Obtener información de estado
sudo nmap -p 21 --script ftp-syst <IP>

# 5. Inspeccionar las interacciones de los scripts
sudo nmap -sV -p 21 -sC <IP> --script-trace

# 6. Conectarse manualmente
ftp <IP>

# 7. Listar los archivos accesibles
ftp> ls

# 8. Descargar un archivo autorizado
ftp> get <archivo>

# 9. Comprobar si se permite la escritura
ftp> put testupload.txt

# 10. Examinar un servicio FTP protegido con TLS
openssl s_client -connect <IP>:21 -starttls ftp
```

## 10. Checklist para el examen

- Identificar el puerto FTP habitual: TCP 21.
    
- Diferenciar el canal de control del canal de datos.
    
- Entender las diferencias entre FTP activo y pasivo.
    
- Recordar que FTP tradicional transmite datos en texto plano.
    
- Comprobar si se permite acceso anónimo.
    
- Identificar banners y versiones del servicio.
    
- Revisar los archivos y directorios accesibles.
    
- Comprobar los permisos de lectura y escritura.
    
- Reconocer las opciones importantes de `vsftpd.conf`.
    
- Recordar el propósito de `/etc/ftpusers`.
    
- Utilizar `ftp-anon` y `ftp-syst` con Nmap.
    
- Utilizar `--script-trace` para inspeccionar la interacción de NSE.
    
- Diferenciar FTP de TFTP: TCP frente a UDP y disponibilidad de autenticación y listado de directorios.
    
- Utilizar OpenSSL para inspeccionar conexiones FTP con TLS.
