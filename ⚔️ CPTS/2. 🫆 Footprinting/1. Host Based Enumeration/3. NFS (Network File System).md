
## 1. Conceptos básicos

- **NFS** permite acceder a sistemas de archivos remotos como si fueran locales.
    
- Se utiliza principalmente en sistemas Linux y Unix.
    
- A diferencia de SMB, utiliza un protocolo diferente y no permite la comunicación directa entre clientes NFS y servidores SMB.
    
- Se basa en **ONC-RPC/SUN-RPC**, que utiliza el puerto TCP/UDP 111.
    
- El puerto habitual de NFS es **2049 TCP/UDP**.
    

### Versiones de NFS

|Versión|Características|
|---|---|
|NFSv2|Versión antigua; inicialmente funcionaba completamente sobre UDP.|
|NFSv3|Incorpora tamaños de archivo variables y mejor gestión de errores.|
|NFSv4|Incluye Kerberos, ACL, operaciones con estado y mejoras de seguridad. Simplifica el funcionamiento a través de cortafuegos.|
|NFSv4.1|Añade soporte para acceso paralelo a archivos distribuidos y multirruta.|

**Importante:** NFSv4 utiliza normalmente el puerto 2049, mientras que las versiones anteriores pueden necesitar servicios RPC adicionales y puertos dinámicos.

### Autenticación y autorización

NFS puede utilizar UID/GID de Unix y pertenencia a grupos para gestionar el acceso.

Un problema importante es que el cliente y el servidor pueden tener asignaciones de UID/GID diferentes. Por tanto, la identidad asociada a un archivo puede interpretarse de forma distinta en ambos sistemas.

La configuración del servidor determina qué sistemas de archivos se exportan y qué permisos tienen los clientes.

## 2. Configuración de NFS

El archivo principal de configuración de las exportaciones es:

```
cat /etc/exports
```

Este archivo define qué directorios se comparten, qué clientes pueden acceder y qué permisos se aplican.

### Opciones principales

|Opción|Descripción|
|---|---|
|`rw`|Permite lectura y escritura.|
|`ro`|Permite únicamente lectura.|
|`sync`|Confirma las operaciones después de escribir los cambios en el almacenamiento correspondiente.|
|`async`|Permite responder antes de que los cambios se hayan confirmado en el almacenamiento, con posibles riesgos de pérdida de datos.|
|`secure`|Requiere conexiones desde puertos de origen privilegiados, normalmente inferiores a 1024.|
|`insecure`|Permite conexiones desde puertos de origen no privilegiados.|
|`no_subtree_check`|Deshabilita la comprobación de subárboles.|
|`root_squash`|Mapea las solicitudes de UID/GID 0 a una identidad anónima.|
|`no_root_squash`|Evita ese mapeo y permite que las solicitudes de root conserven su identidad.|
|`nohide`|Permite que un sistema de archivos montado debajo de un directorio exportado pueda exponerse mediante su propia exportación.|

### Ejemplo de exportación

Una entrada de `/etc/exports` puede tener esta estructura:

```
/mnt/nfs 10.129.14.0/24(sync,no_subtree_check)
```

Esto comparte `/mnt/nfs` con los clientes autorizados de la subred indicada.

Después de modificar la configuración, el servidor puede reiniciar el servicio y consultar las exportaciones:

```
sudo systemctl restart nfs-kernel-server
sudo exportfs
```

### Configuraciones peligrosas

Presta especial atención a:

- `rw`: permite modificar archivos cuando los demás permisos lo permiten.
    
- `insecure`: acepta conexiones desde puertos no privilegiados.
    
- `no_root_squash`: conserva la identidad de root del cliente en lugar de mapearla a una identidad anónima.
    
- Exportaciones accesibles desde subredes demasiado amplias.
    

`**no_root_squash**` **es especialmente importante durante una auditoría**, porque puede permitir que un cliente con acceso de escritura cree archivos que conserven UID/GID 0.

## 3. Reconocimiento con Nmap

Escanear los puertos principales de NFS:

```
sudo nmap -sV -sC -p111,2049 <IP>
```

Los servicios que pueden aparecer incluyen:

- `rpcbind`, normalmente en el puerto 111.
    
- `nfs`, normalmente en el puerto 2049.
    
- `mountd`, utilizado para operaciones de montaje.
    
- `nlockmgr`, asociado a la gestión de bloqueos.
    
- `nfs_acl`, asociado a las ACL de NFS.
    

Los servicios auxiliares pueden utilizar puertos dinámicos, por lo que el escaneo de los puertos principales no siempre muestra toda la superficie de NFS.

### 3.1. Scripts NSE de NFS

Para ejecutar los scripts NSE relacionados con NFS:

```
sudo nmap --script nfs* -sV -p111,2049 <IP>
```

Los scripts pueden proporcionar información sobre:

|Script|Función|
|---|---|
|`rpcinfo`|Enumera servicios RPC, versiones y puertos.|
|`nfs-showmount`|Muestra las exportaciones NFS detectadas.|
|`nfs-ls`|Enumera archivos y directorios de los recursos accesibles.|
|`nfs-statfs`|Obtiene estadísticas del sistema de archivos.|

Ejemplo de información relevante:

```
/mnt/nfs 10.129.14.0/24
```

Esto indica que el servidor exporta `/mnt/nfs` para la subred especificada.

Si `nfs-ls` muestra archivos como `id_rsa`, `id_rsa.pub` o scripts, conviene comprobar sus permisos y su contenido.

## 4. Enumerar exportaciones con `showmount`

Para listar los recursos NFS exportados:

```
showmount -e <IP>
```

Ejemplo:

```
showmount -e 10.129.14.128
```

Salida posible:

```
Export list for 10.129.14.128:
/mnt/nfs 10.129.14.0/24
```

Debemos identificar:

- Las rutas exportadas.
    
- Los hosts o subredes autorizados.
    
- Si podemos acceder a esas rutas desde nuestra máquina.
    

Que una exportación aparezca en la lista no garantiza que podamos montarla ni que tengamos permisos de lectura o escritura.

## 5. Montar un recurso compartido NFS

Una vez identificada una exportación accesible, podemos montarla en nuestro equipo para inspeccionar su contenido.

### 5.1. Crear el directorio de montaje

```
mkdir target-NFS
```

### 5.2. Montar el recurso

Ejemplo utilizado en el laboratorio:

```
sudo mount -t nfs <IP>:/ ./target-NFS/ -o nolock
```

Después, inspeccionar el contenido:

```
cd target-NFS
tree .
```

**Nota:** el ejemplo monta la raíz de las exportaciones visibles a través de ese punto de montaje. Si el servidor requiere montar una exportación concreta, utiliza su ruta, por ejemplo:

```
sudo mount -t nfs <IP>:/mnt/nfs ./target-NFS -o nolock
```

### 5.3. Inspeccionar archivos y permisos

Listar los archivos con nombres de usuario y grupo:

```
ls -l mnt/nfs/
```

Mostrar UID y GID numéricos:

```
ls -n mnt/nfs/
```

Esto permite identificar:

- Propietarios y grupos de los archivos.
    
- Permisos de lectura, escritura y ejecución.
    
- Archivos potencialmente sensibles.
    
- UID/GID que pueden no corresponder a usuarios locales conocidos.
    

Los archivos pueden mostrar nombres de usuario diferentes dependiendo de cómo se resuelvan los UID/GID en el cliente.

### 5.4. Desmontar el recurso

Cuando terminemos:

```
cd ..
sudo umount ./target-NFS
```

## 6. NFS y escalada de privilegios

NFS puede ser relevante durante una escalada de privilegios, especialmente cuando se combina con permisos de escritura y configuraciones inseguras.

### Caso importante: `no_root_squash`

Si una exportación permite escritura y tiene `no_root_squash`, las operaciones realizadas por root desde el cliente pueden conservar UID/GID 0 en los archivos creados.

Esto puede ser peligroso si el servidor confía en esos archivos o si pueden ejecutarse con privilegios elevados.

### Caso contrario: `root_squash`

Con `root_squash` habilitado, las solicitudes de root se mapean a una identidad anónima. Esto limita la capacidad de modificar archivos protegidos como si fuéramos root en el servidor.

Por ejemplo, en el laboratorio se indica que, si `root_squash` está activo, no podremos editar `backup.sh` como root únicamente por haber montado el recurso.

### Archivos que conviene revisar

Durante la enumeración, presta atención a:

- Claves privadas, como `id_rsa`.
    
- Claves públicas, como `id_rsa.pub`.
    
- Scripts de administración o copias de seguridad.
    
- Archivos con permisos de escritura inesperados.
    
- UID/GID que permitan identificar posibles relaciones con usuarios del sistema.
    

No basta con tener acceso al recurso: la escalada depende de los permisos efectivos, de la configuración de la exportación y de cómo el servidor utilice los archivos.

## 7. Flujo de trabajo recomendado

### Paso 1: escanear los puertos principales

```
sudo nmap -sV -sC -p111,2049 <IP>
```

### Paso 2: ejecutar los scripts NSE de NFS

```
sudo nmap --script nfs* -sV -p111,2049 <IP>
```

### Paso 3: enumerar las exportaciones

```
showmount -e <IP>
```

### Paso 4: crear el punto de montaje

```
mkdir target-NFS
```

### Paso 5: montar la exportación

```
sudo mount -t nfs <IP>:/mnt/nfs ./target-NFS -o nolock
```

### Paso 6: enumerar el contenido y los permisos

```
tree target-NFS
ls -la target-NFS
ls -ln target-NFS
```

### Paso 7: inspeccionar archivos relevantes

Busca claves SSH, scripts, copias de seguridad y archivos que puedan revelar información útil para otros pasos de la auditoría.

### Paso 8: revisar la configuración de permisos

Comprueba especialmente:

- Si la exportación permite lectura o escritura.
    
- Qué clientes pueden acceder.
    
- Si se utiliza `root_squash` o `no_root_squash`.
    
- Si los UID/GID y los permisos permiten operaciones inesperadas.
    

### Paso 9: desmontar el recurso

```
sudo umount ./target-NFS
```

## Ideas clave para el examen

- **TCP/UDP 111:** `rpcbind`, utilizado para descubrir servicios RPC.
    
- **TCP/UDP 2049:** puerto habitual de NFS.
    
- `**/etc/exports**`**:** archivo de configuración de las exportaciones NFS.
    
- `**showmount -e <IP>**`**:** enumera las exportaciones disponibles.
    
- `**nmap --script nfs***`**:** ejecuta scripts NSE para enumerar NFS.
    
- `**mount -t nfs**`**:** monta un recurso NFS localmente.
    
- `**ls -l**`**:** muestra permisos, propietarios y grupos.
    
- `**ls -n**`**:** muestra UID/GID numéricos.
    
- `**umount**`**:** desmonta el recurso.
    
- `**rw**`**:** permite escritura cuando los permisos efectivos lo permiten.
    
- `**root_squash**`**:** mapea las solicitudes de root a una identidad anónima.
    
- `**no_root_squash**`**:** puede permitir que las operaciones de root conserven UID/GID 0 en archivos creados desde el cliente.
    
- `**insecure**`**:** permite conexiones desde puertos de origen no privilegiados.
    
- Las exportaciones accesibles pueden revelar archivos sensibles y permisos útiles para continuar la enumeración.
