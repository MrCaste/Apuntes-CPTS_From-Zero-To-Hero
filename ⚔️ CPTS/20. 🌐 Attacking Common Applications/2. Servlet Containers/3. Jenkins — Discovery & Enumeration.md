
## 1. Identificar Jenkins y su versión

Durante el reconocimiento web, comprueba si el servicio corresponde a Jenkins y trata de identificar la versión instalada.

**Dónde buscar la versión:**

- **Código fuente HTML:** revisa comentarios, metadatos y referencias a archivos JavaScript o CSS que puedan contener información de versión.
    
- **Página de inicio de sesión:** comprueba si muestra la versión o información sobre la instalación.
    
- **Pie de página y páginas informativas:** busca referencias explícitas a la versión.
    
- **Cabeceras HTTP:** revisa si la respuesta revela información sobre el servidor o la tecnología utilizada.
    
- **Archivos de documentación accesibles:** comprueba si existe documentación que identifique la versión instalada.
    

No todos estos métodos revelarán la versión. Si no aparece explícitamente, registra la identificación como pendiente de confirmar.

**Puertos indicados en el módulo:**

|Puerto|Uso|
|---|---|
|`8080/TCP`|Puerto predeterminado de Jenkins indicado en el material.|
|`5000/TCP`|Comunicación entre el servidor principal y los secundarios.|

En el laboratorio, Jenkins está disponible en el puerto `8000`.

## 2. Identificar las páginas importantes

### Página de inicio de sesión

```
http://jenkins.inlanefreight.local:8000/login?from=%2F
```

Comprueba:

- Si aparece la página de login de Jenkins.
    
- Si es necesario autenticarse.
    
- Si la página revela información sobre la versión.
    

### Configuración de seguridad

```
http://jenkins.inlanefreight.local:8000/configureSecurity/
```

Si tienes permisos para acceder, revisa:

- El método de autenticación configurado.
    
- Si Jenkins utiliza su propia base de datos de usuarios o un servicio externo, como LDAP.
    
- Las opciones relacionadas con la creación de cuentas.
    
- La configuración general de seguridad.
    

La ruta puede requerir autenticación y permisos suficientes.

## 3. Comprobar las credenciales

Durante la enumeración, comprueba si la instancia utiliza credenciales débiles o predeterminadas, siempre dentro del alcance autorizado.

El módulo proporciona este ejemplo:

```
admin:admin
```

Comprueba también si Jenkins permite acceder sin autenticación.

**No des por hecho que las credenciales predeterminadas funcionan:** debes validar el acceso en el objetivo.

---

## 4. Comprobar el acceso y los privilegios

Si consigues acceder a Jenkins, determina qué permisos tienes y qué funcionalidades están disponibles.

Presta especial atención a:

- Los permisos de la cuenta autenticada.
    
- Las funciones administrativas accesibles.
    
- Las posibilidades de ejecutar tareas o procesos.
    
- Los privilegios de la cuenta del sistema operativo que ejecuta Jenkins.
    

Si Jenkins se ejecuta como `SYSTEM` en Windows, una ejecución de comandos con esos mismos privilegios podría proporcionar acceso altamente privilegiado al equipo.

---

## 5. Checklist de enumeración

- Identificar Jenkins y localizar el puerto del servicio.
    
- Obtener la versión mediante la información visible, el código fuente o los recursos accesibles.
    
- Diferenciar una versión confirmada de una versión inferida.
    
- Revisar `/login?from=%2F`.
    
- Comprobar si se requiere autenticación.
    
- Probar credenciales débiles dentro del alcance autorizado.
    
- Revisar `/configureSecurity/` si tienes permisos.
    
- Identificar el mecanismo de autenticación.
    
- Determinar los permisos de la cuenta.
    
- Valorar el impacto según los privilegios con los que se ejecuta Jenkins.
    

**Nota sobre el material:** el extracto proporcionado no indica una versión concreta de Jenkins ni describe un procedimiento específico para obtenerla. Por eso, la versión debe tratarse como un dato que hay que investigar durante la enumeración, no como un resultado ya conocido.
