## 1. Identificar WordPress

Comprobar rutas habituales:

```
curl -s http://TARGET/robots.txt
```

Rutas importantes:

- `/wp-login.php` → inicio de sesión.
    
- `/wp-admin/` → panel de administración.
    
- `/wp-content/plugins/` → plugins instalados.
    
- `/wp-content/themes/` → temas instalados.
    
- `/wp-content/uploads/` → archivos subidos.
    

## 2. Enumeración manual

### Identificar la versión

```
curl -s http://TARGET/ | grep -i WordPress
```

Buscar referencias a versiones en el código HTML y los feeds RSS.

### Enumerar temas

```
curl -s http://TARGET/ | grep -i themes
```

### Enumerar plugins

```
curl -s http://TARGET/ | grep -i plugins
```

Las rutas encontradas pueden revelar nombres y versiones mediante parámetros como `?ver=5.4.2`.

### Buscar información de versiones

Si existen archivos `readme.txt` accesibles, pueden revelar la versión de un plugin o tema.

## 3. Enumeración de usuarios

WordPress puede revelar usuarios mediante:

- Mensajes de error diferentes en `/wp-login.php`.
    
- Autores de publicaciones.
    
- Feeds RSS.
    
- Herramientas automáticas.
    

## 4. WPScan

Herramienta para enumerar versiones, usuarios, plugins, temas y vulnerabilidades conocidas.

### Escaneo básico

```
wpscan --url http://TARGET
```

### Enumeración

```
wpscan --url http://TARGET --enumerate
```

### Enumerar todos los plugins

```
wpscan --url http://TARGET --enumerate ap
```

### Consultar vulnerabilidades con API

```
wpscan --url http://TARGET --enumerate --api-token TOKEN
```

### Guardar resultados

```
wpscan --url http://TARGET -o resultados.txt
```

## 5. Qué buscar en los resultados

- **Versiones antiguas:** posibles vulnerabilidades conocidas.
    
- **Plugins vulnerables:** pueden ofrecer vías de explotación.
    
- **Usuarios válidos:** información útil para evaluar la autenticación.
    
- **Directory Listing:** permite ver el contenido de determinados directorios.
    
- **XML-RPC (**`**/xmlrpc.php**`**):** interfaz remota que puede ampliar la superficie de ataque.
    
- **Archivos expuestos:** pueden revelar información sensible.
    

## 6. Vulnerabilidades que debes reconocer

|Vulnerabilidad|Significado|
|---|---|
|LFI|Inclusión de archivos locales.|
|SQLi|Manipulación de consultas SQL.|
|RCE|Ejecución remota de código.|
|User Enumeration|Identificación de usuarios válidos.|
|Directory Listing|Visualización del contenido de directorios.|

## 7. Metodología para una prueba

1. Identificar WordPress y sus rutas.
    
2. Averiguar la versión del núcleo.
    
3. Enumerar temas, plugins y sus versiones.
    
4. Buscar usuarios válidos.
    
5. Ejecutar WPScan.
    
6. Investigar las vulnerabilidades encontradas y comprobar si son aplicables.
    
7. Priorizar los componentes vulnerables y documentar los hallazgos.
    

**Importante:** combina la enumeración manual con WPScan. El escáner puede pasar por alto plugins que sí se encuentran inspeccionando el código fuente.
