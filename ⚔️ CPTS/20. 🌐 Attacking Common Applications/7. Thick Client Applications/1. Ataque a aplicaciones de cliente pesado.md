
## 1. ¿Qué son las aplicaciones de cliente pesado?

Son aplicaciones instaladas localmente que realizan gran parte del procesamiento en el equipo del usuario.

Pueden utilizar tecnologías como Java, C++, .NET o Silverlight.

### Arquitecturas

- **Dos niveles:** la aplicación se comunica directamente con la base de datos.
    
- **Tres niveles:** la aplicación se comunica con un servidor de aplicaciones, que accede a la base de datos.
    

La arquitectura de tres niveles evita que el cliente tenga que comunicarse directamente con la base de datos.

### Vulnerabilidades habituales

- Credenciales codificadas en el programa (_hardcoded credentials_).
    
- Secuestro de DLL (_DLL Hijacking_).
    
- Desbordamiento de búfer (_Buffer Overflow_).
    
- Inyección SQL.
    
- Almacenamiento inseguro de información sensible.
    
- Gestión incorrecta de sesiones y errores.

## 3. Análisis de la aplicación

Las aplicaciones pueden almacenar credenciales en archivos locales, código fuente o memoria.

### Análisis estático

Examina los archivos sin ejecutar la aplicación para localizar:

- Usuarios y contraseñas.
    
- Tokens y cadenas de conexión.
    
- Rutas de archivos.
    
- Información sensible codificada en el programa.
    

### Análisis dinámico

Ejecuta la aplicación mientras monitorizas su comportamiento para identificar:

- Archivos temporales creados.
    
- Operaciones sobre el registro de Windows.
    
- Datos almacenados en memoria.
    
- Comunicaciones con otros servicios.

## 4. Caso práctico: recuperar credenciales de una aplicación

El módulo presenta una aplicación de Windows que reinicia un servicio Oracle y oculta su funcionamiento.

### Paso 1. Ejecutar y monitorizar el programa

Se obtiene `Restart-OracleService.exe` desde el recurso compartido SMB `NETLOGON`.

Al ejecutarlo, aparentemente no ocurre nada.

Con ProcMon se descubre que crea archivos temporales en:

```
C:\Users\Matt\AppData\Local\Temp
```

**Objetivo:** identificar los archivos que genera y qué hace con ellos.

### Paso 2. Recuperar los archivos temporales

El programa crea archivos y los elimina automáticamente.

En el laboratorio, se modifican los permisos de la carpeta temporal para impedir la eliminación de archivos y poder examinarlos.

Aparece un archivo `.bat` que contiene instrucciones para:

1. Comprobar el nombre del usuario.
    
2. Crear un archivo de texto con contenido codificado en Base64.
    
3. Generar un script de PowerShell.
    
4. Decodificar el contenido y reconstruir un ejecutable.
    
5. Ejecutar el ejecutable y eliminar los archivos temporales.
    

### Paso 3. Analizar el script

El script de PowerShell utiliza:

```
[System.Convert]::FromBase64String($salida)
```

Esta función decodifica una cadena Base64 en bytes.

Después, los bytes se escriben en un archivo `.exe`.

**Conclusión:** el programa original genera otro ejecutable que puede analizarse por separado.

### Paso 4. Analizar el ejecutable con x64dbg

Se abre el ejecutable con x64dbg y se utiliza la vista **Memory Map** para identificar regiones de memoria interesantes.

El módulo detecta una región que contiene los bytes `MZ`, característicos de un ejecutable de Windows.

Se exporta esa región de memoria a un archivo para examinarla.

### Paso 5. Identificar el ejecutable .NET

Se utiliza `strings64.exe` para extraer cadenas:

```
C:\TOOLS\Strings\strings64.exe .\restart-service_00000000001E0000.bin
```

La salida contiene referencias a:

```
.NETFramework,Version=v4.0,Profile=Client
.NET Framework 4 Client Profile
```

Esto indica que el archivo contiene un ejecutable .NET.

### Paso 6. Desofuscar y recuperar el código

Se utiliza De4dot para intentar limpiar el binario:

```
de4dot restart-service_00000000001E0000.bin
```

Después, se abre el archivo resultante con dnSpy para examinar el código C#.

El análisis revela que el programa es una implementación personalizada de `runas.exe`, diseñada para reiniciar un servicio Oracle utilizando **credenciales codificadas directamente en el programa**.

## 5. Metodología para HTB

Cuando encuentres una aplicación de cliente pesado, sigue este orden:

1. **Identificar el ejecutable:** determinar su formato, tecnología y lenguaje.
    
2. **Extraer cadenas:** buscar usuarios, contraseñas, rutas y tokens.
    
3. **Monitorizar la ejecución:** utilizar ProcMon para descubrir archivos temporales y operaciones del programa.
    
4. **Examinar los archivos generados:** comprobar si contienen scripts, configuraciones o datos codificados.
    
5. **Analizar los binarios:** utilizar herramientas de ingeniería inversa y depuración.
    
6. **Examinar la memoria:** buscar datos sensibles que no aparezcan directamente en los archivos.
    
7. **Identificar credenciales:** comprobar si el código utiliza contraseñas o cuentas de servicio.
    
8. **Evaluar el acceso obtenido:** determinar si las credenciales permiten acceder a otros servicios o sistemas.
    

### Idea clave

**No te fíes únicamente del comportamiento visible de una aplicación.** Puede crear archivos temporales, reconstruir ejecutables en tiempo de ejecución o almacenar credenciales en memoria.

La combinación de monitorización, extracción de cadenas e ingeniería inversa permite descubrir información que no resulta evidente al ejecutar el programa.
