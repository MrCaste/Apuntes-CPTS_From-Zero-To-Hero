
## 1. ¿En qué consiste esta vulnerabilidad?

La enumeración de tilde en IIS permite descubrir nombres de archivos y directorios a través de los **nombres cortos 8.3 de Windows**.

Windows puede asignar a los archivos y directorios nombres cortos con un máximo de ocho caracteres para el nombre y tres para la extensión. Por ejemplo:

- Nombre original: `SecretDocuments`
    
- Nombre corto: `SECRET~1`
    

El carácter `~` y el número identifican el nombre corto generado por Windows.

### ¿Por qué es vulnerable?

En determinadas versiones y configuraciones de IIS, las respuestas del servidor a solicitudes HTTP permiten distinguir entre nombres cortos existentes e inexistentes.

Un atacante puede enviar solicitudes con diferentes combinaciones de caracteres y analizar las respuestas para descubrir nombres de archivos y directorios que no conoce.

**Importante:** esto no significa que todos los archivos descubiertos sean accesibles. La enumeración revela información sobre sus nombres; el acceso dependerá de los permisos y de cómo esté configurado el servidor.

## 2. Enumeración inicial con Nmap

Identificar los puertos abiertos y los servicios:

```
nmap -p- -sV -sC --open 10.129.224.91
```

Resultado relevante:

```
80/tcp open http Microsoft IIS httpd 7.5
```

Se identifica **Microsoft IIS 7.5** en el puerto 80.

Esto hace que merezca la pena comprobar si el servidor es susceptible a la enumeración de nombres cortos.

## 3. Detectar nombres cortos con IIS ShortName Scanner

La herramienta automatiza el envío de solicitudes HTTP con distintas combinaciones de caracteres.

```
java -jar iis_shortname_scanner.jar 0 5 http://10.129.204.231/
```

Cuando pregunte si se desea utilizar un proxy, pulsa `Enter` para continuar sin él.

El resultado identifica:

**Directorios:**

- `ASPNET~1`
    
- `UPLOAD~1`
    

**Archivos:**

- `CSASPX~1.CS`
    
- `CSASPX~1.CS??`
    
- `TRANSF~1.ASP`
    

El resultado `Vulnerable!` indica que la herramienta ha detectado un comportamiento compatible con la enumeración de nombres cortos.

### ¿Qué hacemos con esta información?

El nombre `TRANSF~1.ASP` es especialmente interesante, pero el material indica que una solicitud GET directa a esa ruta no permite acceder al recurso.

Por tanto, necesitamos intentar descubrir el nombre original del archivo, utilizando el nombre corto como pista.

## 4. Crear una wordlist específica

En lugar de probar nombres aleatorios, filtramos las wordlists disponibles para obtener palabras que comiencen por `transf`.

```
egrep -r ^transf /usr/share/wordlists/* | sed 's/^[^:]*://' > /tmp/list.txt
```

El comando:

- `egrep -r ^transf`: busca recursivamente palabras que comiencen por `transf`.
    
- `sed 's/^[^:]*://'`: elimina la parte anterior a los dos puntos de cada resultado.
    
- `> /tmp/list.txt`: guarda los resultados en una wordlist.
    

**Objetivo:** reducir las posibles palabras que podrían completar el nombre del archivo.

## 5. Descubrir el nombre con ffuf

Utilizamos `ffuf` para probar las palabras de la lista contra el servidor, añadiendo las extensiones `.aspx` y `.asp`.

```
ffuf -u http://10.129.204.231/FUZZ -w /tmp/list.txt -e .aspx,.asp
```

Parámetros:

- `-u`: URL objetivo.
    
- `FUZZ`: posición donde ffuf sustituye cada palabra de la lista.
    
- `-w`: wordlist que se utilizará.
    
- `-e`: extensiones que se probarán.
    

### ¿Qué buscamos?

Buscamos una respuesta que permita identificar el archivo asociado al nombre corto `TRANSF~1.ASP`.

Si encontramos un nombre candidato válido, podremos comprobar si corresponde al recurso identificado durante la enumeración.

## Resumen del proceso

1. **Nmap:** identificar IIS y su versión.
    
2. **IIS ShortName Scanner:** comprobar si se pueden enumerar nombres cortos 8.3.
    
3. **Analizar los resultados:** identificar nombres como `TRANSF~1.ASP`.
    
4. **Crear una wordlist:** filtrar palabras que comiencen por `transf`.
    
5. **ffuf:** probar los nombres candidatos y las extensiones `.aspx` y `.asp`.
    

**Idea clave:** no necesitamos conocer el nombre completo del recurso desde el principio. Primero aprovechamos las respuestas de IIS para obtener su nombre corto y después utilizamos una wordlist para intentar descubrir el nombre original.
