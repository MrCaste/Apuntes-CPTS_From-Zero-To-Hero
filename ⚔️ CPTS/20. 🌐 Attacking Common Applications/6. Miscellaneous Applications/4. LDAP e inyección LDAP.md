
## 1. ¿Qué es LDAP?

**LDAP (Lightweight Directory Access Protocol)** es un protocolo utilizado para acceder y gestionar información almacenada en servicios de directorio, como usuarios, grupos y equipos.

- **LDAP:** protocolo para consultar y modificar información de directorios.
    
- **Active Directory (AD):** servicio de directorio de Microsoft que utiliza LDAP, entre otros protocolos.
    
- **Puertos habituales:** `389` para LDAP y `636` para LDAPS.
    
- **Seguridad:** LDAP no cifra el tráfico por defecto. Para protegerlo se puede utilizar LDAPS o StartTLS.

- **Puerto 80:** servidor web Apache.
    
- **Puerto 389:** servidor LDAP OpenLDAP.
    

Como ambos servicios están disponibles, podemos investigar si la aplicación web utiliza LDAP para autenticar a sus usuarios.

## 3. Consultar LDAP con ldapsearch

`ldapsearch` permite buscar y recuperar información almacenada en un directorio LDAP.

Ejemplo:

```
ldapsearch -H ldap://ldap.example.com:389 -D "cn=admin,dc=example,dc=com" -w secret123 -b "ou=people,dc=example,dc=com" "(mail=john.doe@example.com)"
```

Parámetros:

- `-H`: servidor y dirección del servicio LDAP.
    
- `-D`: DN del usuario con el que se realiza la autenticación.
    
- `-w`: contraseña.
    
- `-b`: DN base desde el que se realiza la búsqueda.
    
- El último argumento es el filtro LDAP utilizado para buscar la entrada.
    

La respuesta puede mostrar el DN de la entrada encontrada y atributos como `cn`, `sn`, `uid` y `mail`.

## 4. Inyección LDAP

La **inyección LDAP** ocurre cuando una aplicación incorpora entradas del usuario en consultas LDAP sin validarlas ni escaparlas correctamente.

Esto puede permitir modificar la lógica de las consultas, eludir la autenticación o acceder a información no autorizada.

### Caracteres y operadores relevantes

|Entrada|Función|
|---|---|
|`*`|Comodín que puede coincidir con cualquier número de caracteres.|
|`( )`|Agrupan expresiones.|
|`\|`|Operador lógico OR.|
|`&`|Operador lógico AND.|
|`(cn=*)`|Filtro que busca entradas con un atributo `cn` presente.|
|`(objectClass=*)`|Filtro que busca entradas con un atributo `objectClass` presente.|

### Ejemplo de consulta vulnerable

La aplicación utiliza la siguiente consulta para autenticar usuarios:

```
(&(objectClass=user)(sAMAccountName=$username)(userPassword=$password))
```

Los valores de `$username` y `$password` se incorporan a la consulta.

Si no se gestionan correctamente las entradas, un atacante puede intentar introducir caracteres especiales para alterar el comportamiento del filtro.

El material muestra dos pruebas:

**Prueba 1: comodín en el usuario**

```
Username: *
Password: dummy
```

**Prueba 2: comodín en la contraseña**

```
Username: dummy
Password: *
```

El resultado depende de cómo la aplicación construya y evalúe la consulta LDAP.

## 6. Prevención

Para evitar las inyecciones LDAP:

- Validar las entradas del usuario.
    
- Escapar correctamente los caracteres especiales de LDAP.
    
- Utilizar consultas que separen los datos de la estructura de la consulta.
    
- Utilizar LDAPS o StartTLS para proteger las comunicaciones.
