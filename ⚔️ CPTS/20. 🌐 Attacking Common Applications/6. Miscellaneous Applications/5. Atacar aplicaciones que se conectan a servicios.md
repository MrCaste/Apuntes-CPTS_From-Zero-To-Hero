
## 1. Examinar un ejecutable ELF

Las aplicaciones que se conectan a bases de datos pueden contener **cadenas de conexión (**_**connection strings**_**) con credenciales**. Podemos analizarlas mediante GDB para recuperarlas.

### 1.1. Ejecutar el binario

```
./octopus_checker
```

Si aparece un mensaje de error del controlador ODBC, no significa necesariamente que el binario no contenga credenciales. En el ejemplo, la aplicación intenta conectarse a Microsoft SQL Server.

### 1.2. Abrir el binario con GDB

```
gdb ./octopus_checker
```

Configurar el formato de desensamblado Intel:

```
set disassembly-flavor intel
```

Desensamblar la función principal:

```
disas main
```

**Objetivo:** identificar llamadas a funciones relacionadas con conexiones a bases de datos y localizar `SQLDriverConnect`.

### 1.3. Establecer un breakpoint

En el ejemplo, `SQLDriverConnect@plt` está en la dirección `0x5555555551b0`.

```
b *0x5555555551b0
run
```

> La dirección corresponde al binario del laboratorio. En otros ejecutables debes localizar la dirección correcta.

### 1.4. Leer la cadena de conexión

Cuando GDB se detenga en el breakpoint, examinar el registro `RDX`:

```
x/s $rdx
```

En el ejemplo, se obtiene:

```
DRIVER={ODBC Driver 17 for SQL Server};SERVER=localhost, 1401;UID=username;PWD=password;
```

Los campos importantes son:

|Campo|Significado|
|---|---|
|`DRIVER`|Controlador utilizado|
|`SERVER`|Servidor y puerto de la base de datos|
|`UID`|Usuario|
|`PWD`|Contraseña|

En Linux x86-64, `RDX` contiene el tercer argumento de una función según la convención de llamadas System V AMD64. En este caso, apunta a la cadena de conexión cuando se alcanza el breakpoint mostrado.

**Flujo de trabajo:**

1. Abrir el binario con GDB.
    
2. Desensamblar `main`.
    
3. Localizar `SQLDriverConnect`.
    
4. Establecer un breakpoint en su dirección.
    
5. Ejecutar el programa.
    
6. Examinar la cadena apuntada por `RDX` con `x/s $rdx`.
    
7. Comprobar si las credenciales pueden reutilizarse en otros servicios de la red.

## 2. Examinar archivos DLL de .NET

Una DLL (_Dynamic Link Library_) contiene código que otros programas pueden utilizar durante su ejecución.

En el laboratorio, `MultimasterAPI.dll` es un ensamblado .NET.

### 2.1. Identificar información del archivo

En PowerShell:

```
Get-FileMetaData .\MultimasterAPI.dll
```

La inspección puede revelar información como la versión de .NET, rutas, nombres de métodos y cadenas de texto.

### 2.2. Analizar el código con dnSpy

Utilizar **dnSpy** para inspeccionar el ensamblado .NET y consultar su código descompilado.

En el laboratorio, se examina:

```
MultimasterAPI.Controllers
└── ColleagueController
```

Al inspeccionar los métodos, se encuentra una cadena de conexión a la base de datos que contiene una contraseña.

**Flujo de trabajo:**

1. Identificar la DLL.
    
2. Comprobar si es un ensamblado .NET.
    
3. Abrirla con dnSpy.
    
4. Examinar los controladores y métodos relevantes.
    
5. Buscar cadenas de conexión y credenciales incrustadas.

## 3. Qué hacer con las credenciales encontradas

Después de recuperar credenciales de una aplicación:

- Comprobar si permiten acceder al servicio de base de datos.
    
- Evaluar si la contraseña se reutiliza en otras cuentas o servicios de la red.
    
- Considerar el _password spraying_ para comprobar la reutilización de contraseñas, siempre dentro del alcance autorizado.
    

## Comandos que debes recordar

|Objetivo|Comando|
|---|---|
|Identificar el tipo de archivo|`file ./binario`|
|Abrir el ejecutable|`gdb ./binario`|
|Configurar sintaxis Intel|`set disassembly-flavor intel`|
|Desensamblar `main`|`disas main`|
|Establecer un breakpoint por dirección|`b *DIRECCION`|
|Ejecutar el programa|`run`|
|Leer una cadena desde `RDX`|`x/s $rdx`|
|Consultar metadatos de una DLL|`Get-FileMetaData .\archivo.dll`|

### Idea clave para el examen

**Las credenciales pueden estar almacenadas directamente en un ejecutable o en una DLL.** Si no aparecen mediante una búsqueda estática sencilla, puedes analizar el flujo de ejecución con GDB o inspeccionar el código .NET descompilado con dnSpy.
