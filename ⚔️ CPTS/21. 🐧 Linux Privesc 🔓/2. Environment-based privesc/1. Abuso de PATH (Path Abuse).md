
## 1. ¿Qué es PATH?

`PATH` es una variable de entorno que contiene los directorios donde Linux busca los ejecutables cuando introducimos un comando sin especificar su ruta absoluta.

```
echo $PATH
env | grep PATH
```

Ejemplo:

```
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

Cuando ejecutamos `ls`, Linux busca ese ejecutable siguiendo el orden de los directorios definidos en `PATH`.

## 2. ¿Cómo funciona el ataque?

El **PATH Hijacking** consiste en conseguir que un usuario o proceso ejecute nuestro archivo malicioso en lugar del ejecutable legítimo.

Esto puede permitir una escalada de privilegios si conseguimos que un proceso ejecutado como `root` utilice nuestro archivo.

**Condiciones necesarias:**

- Poder modificar el `PATH` utilizado por el proceso o escribir en un directorio que aparezca antes que el ejecutable legítimo.
    
- Que el proceso invoque un comando sin su ruta absoluta.
    
- Que nuestro archivo tenga permisos de ejecución.
    

## 3. Explotación

### Paso 1. Consultar PATH

```
echo $PATH
```

### Paso 2. Añadir el directorio actual al principio

```
export PATH=.:$PATH
```

El punto `.` representa el directorio actual.

Al colocarlo al principio, Linux buscará primero los ejecutables de nuestro directorio antes de consultar `/usr/bin`, `/bin`, etc.

### Paso 3. Crear un ejecutable falso

Creamos un archivo llamado `ls`:

```
echo 'echo "PATH ABUSE!!"' > ls
chmod +x ls
```

### Paso 4. Ejecutar el comando

```
ls
```

Resultado:

```
PATH ABUSE!!
```

En lugar de ejecutar `/bin/ls`, se ejecuta nuestro archivo `./ls`.

## 4. Aplicación en escalada de privilegios

Si encontramos un script ejecutado como `root` que utiliza comandos sin rutas absolutas, podríamos intentar aprovechar la búsqueda de ejecutables mediante `PATH`.

Por ejemplo, un script privilegiado que ejecuta:

```
#!/bin/bash
ls /root
```

Si conseguimos que ese proceso utilice un `PATH` controlado por nosotros y encuentre primero nuestro ejecutable `ls`, el código se ejecutaría con los privilegios del proceso.

**Importante:** Modificar nuestro propio `PATH` no modifica automáticamente el de `root` ni el de otros procesos.

## 5. Comandos importantes

|Comando|Función|
|---|---|
|`echo $PATH`|Mostrar los directorios de búsqueda.|
|`export PATH=.:$PATH`|Añadir el directorio actual al principio de PATH.|
|`which ls`|Localizar el ejecutable encontrado en PATH.|
|`type -a ls`|Mostrar las distintas ubicaciones o definiciones de `ls`.|
|`chmod +x archivo`|Dar permisos de ejecución.|
|`/bin/ls`|Ejecutar el binario legítimo mediante su ruta absoluta.|

### Clave para CPTS / OSCP

**Buscar scripts o procesos privilegiados que ejecuten comandos sin rutas absolutas y comprobar si podemos controlar algún directorio de su PATH.**

El objetivo es conseguir que el proceso ejecute nuestro archivo en lugar del binario legítimo.
