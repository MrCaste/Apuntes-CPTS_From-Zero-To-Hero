
## 1. Concepto

Una **shell restringida** limita los comandos que puedes ejecutar, los directorios a los que puedes acceder o las variables de entorno que puedes modificar.

Tipos principales:

- **rbash:** Bash restringida.
    
- **rksh:** Korn Shell restringida.
    
- **rzsh:** Z Shell restringida.
    

El objetivo es encontrar una forma de ejecutar comandos que la shell normalmente bloquea.

## 2. Métodos de escape

### 2.1. Inyección de comandos

Consiste en introducir un comando dentro de los argumentos de otro para conseguir que también se ejecute.

**Ejemplo del material:**

```
ls -l `pwd`
```

Las comillas invertidas ejecutan `pwd` y sustituyen su contenido por la salida del comando. Después, `ls` utiliza esa salida como argumento.

**Importante:** este ejemplo demuestra la sustitución de comandos, pero no garantiza escapar de `rbash`. La shell puede bloquear la ejecución de `pwd`.

### 2.2. Sustitución de comandos

Permite ejecutar un comando dentro de otro mediante `$(...)` o comillas invertidas.

**Ejemplo:**

```
echo "Directorio actual: $(pwd)"
```

Primero se ejecuta `pwd` y después se muestra su resultado con `echo`.

También se puede escribir así:

```
echo "Directorio actual: `pwd`"
```

**Objetivo:** comprobar si la shell permite ejecutar comandos mediante sustitución aunque existan restricciones sobre su ejecución directa.

### 2.3. Encadenamiento de comandos

Consiste en escribir varios comandos en una misma línea utilizando operadores.

|Operador|Funcionamiento|
|---|---|
|`;`|Ejecuta el siguiente comando independientemente del resultado del anterior.|
|`&&`|Ejecuta el siguiente comando si el anterior termina correctamente.|
|`\|`|Envía la salida de un comando a la entrada del siguiente.|

**Ejemplos:**

```
pwd; whoami
```

Ejecuta `pwd` y después `whoami`.

```
mkdir prueba && echo "Directorio creado"
```

Muestra el mensaje si `mkdir` termina correctamente.

```
echo "texto" | grep "texto"
```

Envía la salida de `echo` a `grep`.

**Objetivo:** comprobar si la shell permite encadenar comandos y si alguno de ellos puede ejecutarse pese a las restricciones.

### 2.4. Variables de entorno

Las variables de entorno almacenan valores que utilizan los programas y la shell. Algunas controlan la búsqueda de ejecutables o la selección de herramientas.

**Ejemplo para consultar** `**PATH**`**:**

```
echo "$PATH"
```

**Ejemplo para consultar** `**SHELL**`**:**

```
echo "$SHELL"
```

**Ejemplo de modificación de** `**PATH**` **en una shell no restringida:**

```
export PATH=/usr/local/bin:/usr/bin:/bin
```

Esto cambia los directorios donde se buscan los ejecutables.

**Importante:** en `rbash`, modificar `PATH` puede estar bloqueado. Que una variable tenga un valor determinado no significa que puedas modificarla o utilizarla para escapar.

### 2.5. Funciones de shell

Una función permite agrupar comandos bajo un nombre para reutilizarlos.

**Ejemplo:**

```
mi_funcion() {
    echo "Prueba de función"
}
```

Para ejecutarla:

```
mi_funcion
```

Si la shell permite definir funciones, puedes comprobar su comportamiento y las restricciones que se aplican a los comandos que contienen.

**Importante:** definir una función no elimina por sí mismo las restricciones de `rbash`.

## 3. Comprobaciones iniciales

Cuando consigas acceso a una shell restringida, puedes empezar identificando el entorno:

```
echo "$0"
echo "$SHELL"
echo "$PATH"
```

Comprueba qué comandos funcionan y cuáles están bloqueados. No des por hecho que todas las técnicas sirven en todas las shells: el resultado depende de la configuración y de las restricciones concretas.
