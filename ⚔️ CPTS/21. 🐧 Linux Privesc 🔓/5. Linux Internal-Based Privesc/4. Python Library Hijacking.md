
Consiste en aprovechar permisos incorrectos sobre módulos de Python o sus rutas de búsqueda para ejecutar código con privilegios elevados.

## 1. Enumeración

### Comprobar permisos de sudo

```
sudo -l
```

Busca scripts de Python que puedas ejecutar como `root`.

### Revisar los módulos importados

```
import psutil
```

Si el script importa módulos, comprueba dónde están instalados:

```
pip3 show psutil
```

Buscar la función utilizada:

```
grep -r "def virtual_memory" /usr/local/lib/python3.8/dist-packages/psutil/
```

### Comprobar permisos del módulo

```
ls -l /ruta/al/modulo.py
```

Si puedes modificar un módulo que utiliza un script ejecutado como `root`, podrías insertar código que se ejecutaría con esos privilegios.

## 2. Vectores de ataque

### A. Permisos de escritura inseguros

Si puedes modificar un módulo importado por un script privilegiado, puedes insertar código en la función que utiliza el script.

Ejemplo de prueba:

```
import os
os.system('id')
```

Al ejecutar el script privilegiado, comprueba si el comando se ejecuta como `root`.

### B. Secuestro de la ruta de búsqueda

Python busca módulos siguiendo un orden de rutas:

```
python3 -c 'import sys; print("\n".join(sys.path))'
```

Si una ruta con mayor prioridad es escribible y el módulo original está en una ruta posterior, puedes crear un módulo con el mismo nombre en la ruta prioritaria.

Ejemplo: si el script importa `psutil`, Python podría importar un archivo `psutil.py` controlado por ti antes que el módulo legítimo.

Comprueba los permisos de las rutas:

```
ls -ld /usr/lib/python3.8
```

### C. Variable de entorno `PYTHONPATH`

`PYTHONPATH` permite indicar directorios adicionales donde Python busca módulos.

Comprueba si `sudo` permite establecer variables de entorno:

```
sudo -l
```

Si aparece `SETENV` para Python, puede ser posible controlar la ruta de búsqueda:

```
sudo PYTHONPATH=/tmp/ /usr/bin/python3 ./mem_status.py
```

Este ejemplo presupone que `/tmp/` contiene un módulo que el script importa y que se cumplen las demás condiciones necesarias.

## 3. Comprobar la escalada

Utiliza una prueba sencilla para comprobar los privilegios efectivos:

```
import os
os.system('id')
```

Si el resultado muestra `uid=0(root)`, el código se ha ejecutado con privilegios de root.

## Resumen para el examen

|Vector|Qué comprobar|
|---|---|
|Permisos inseguros|Si puedes modificar un módulo importado por un script privilegiado|
|Ruta de búsqueda|Si una ruta prioritaria es escribible|
|`PYTHONPATH`|Si puedes controlar las rutas de importación del proceso privilegiado|
|`sudo -l`|Si puedes ejecutar Python o un script como root y si aparece `SETENV`|

**Idea clave:** Python importa módulos buscando en determinadas rutas. Si puedes controlar el módulo que importa un programa ejecutado con privilegios elevados, puedes conseguir que tu código se ejecute con esos privilegios.
