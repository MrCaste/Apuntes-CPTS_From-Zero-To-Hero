
## 1. SUID (Set User ID)

El bit **SUID** permite ejecutar un binario con los permisos de su propietario, en lugar de hacerlo únicamente con los permisos del usuario actual. Si pertenece a `root`, puede permitir escalar privilegios.

Se identifica mediante una `s` en los permisos del propietario:

```
-rwsr-xr-x 1 root root 16728 payroll
```

### Enumerar binarios SUID

```
find / -user root -perm -4000 -exec ls -ldb {} \; 2>/dev/null
```

Alternativa más sencilla:

```
find / -type f -perm -4000 2>/dev/null
```

### Qué buscar

- Binarios poco habituales o personalizados.
    
- Programas vulnerables o con funciones que permitan ejecutar comandos.
    
- Binarios que puedan cargar bibliotecas compartidas manipulables.
    
- Versiones antiguas de programas potencialmente vulnerables.
    

**Ejemplo del material:** aparece un binario llamado `payroll` con SUID de `root`. Conviene investigarlo para determinar si tiene alguna vulnerabilidad aprovechable.

## 2. SGID (Set Group ID)

El bit **SGID** permite que un ejecutable se ejecute con los permisos del grupo propietario, en lugar de utilizar únicamente el grupo habitual del usuario.

Se identifica mediante una `s` en los permisos del grupo.

### Enumerar binarios con SUID o SGID

```
find / -user root -perm -6000 -exec ls -ldb {} \; 2>/dev/null
```

Para buscar todos los archivos ejecutables con alguno de estos permisos:

```
find / -type f \( -perm -4000 -o -perm -2000 \) 2>/dev/null
```

**Importante:** SGID no implica necesariamente privilegios de `root`; depende del grupo propietario y de los permisos que tenga ese grupo.

## 3. GTFOBins

**GTFOBins** es un repositorio que documenta cómo determinados binarios de Linux pueden aprovecharse para:

- Escapar de shells restringidas.
    
- Ejecutar comandos.
    
- Escalar privilegios.
    
- Leer o escribir archivos.
    
- Transferir archivos.
    
- Crear conexiones de shell.
    

### Procedimiento práctico

1. Enumera los binarios SUID y SGID.
    
2. Identifica los programas que puedes ejecutar.
    
3. Busca esos programas en GTFOBins.
    
4. Comprueba si existe una técnica aplicable a sus permisos y configuración.
    
5. Prueba la técnica en el laboratorio autorizado.
    

Recurso: [GTFOBins](https://gtfobins.github.io/).

### Ejemplo del material: `apt-get`

El contenido muestra esta técnica:

```
sudo apt-get update -o APT::Update::Pre-Invoke::=/bin/sh
```

La opción `Pre-Invoke` permite especificar un comando que APT ejecutará antes de la operación de actualización. En el ejemplo, se abre una shell con privilegios de `root`.

**Condición:** este ejemplo requiere que `sudo` permita ejecutar `apt-get` con los privilegios necesarios. No funcionará automáticamente en cualquier sistema.

## 4. Comandos que debes recordar

|Objetivo|Comando|
|---|---|
|Buscar binarios SUID de `root`|`find / -user root -perm -4000 -exec ls -ldb {} \; 2>/dev/null`|
|Buscar todos los binarios SUID|`find / -type f -perm -4000 2>/dev/null`|
|Buscar binarios SUID y SGID|`find / -type f \( -perm -4000 -o -perm -2000 \) 2>/dev/null`|
|Consultar tu identidad y grupos|`id`|
|Comprobar los permisos de un archivo|`ls -l /ruta/al/archivo`|

## 5. Flujo de trabajo para CPTS/OSCP

1. **Enumerar:** buscar binarios SUID y SGID.
    
2. **Filtrar:** prestar atención a binarios personalizados, antiguos o poco habituales.
    
3. **Investigar:** consultar GTFOBins y comprobar la versión del programa.
    
4. **Validar:** verificar los permisos efectivos y si la técnica es aplicable.
    
5. **Explotar:** probar únicamente en el entorno autorizado y comprobar el resultado con `id`.
    

**Idea clave:** encontrar un binario SUID o SGID no significa que sea vulnerable. Hay que identificar una característica explotable y comprobar que los permisos permiten aprovecharla.
