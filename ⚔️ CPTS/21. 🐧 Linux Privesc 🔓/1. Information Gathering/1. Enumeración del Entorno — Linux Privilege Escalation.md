
La enumeración es fundamental para identificar posibles vías de **escalada de privilegios (Privilege Escalation)**.

Podemos realizarla manualmente o utilizar herramientas como **LinPEAS** y **LinEnum**.

## 1. Enumeración básica del sistema

Al conseguir acceso inicial a una máquina Linux, debemos identificar nuestro usuario, sus privilegios y el sistema operativo.

```
whoami              # Usuario actual
id                  # UID, GID y grupos del usuario
hostname            # Nombre del equipo
ip a                # Interfaces de red y direcciones IP
sudo -l             # Comandos que podemos ejecutar con sudo
```

**Importante:** `sudo -l` puede revelar comandos que podemos ejecutar como `root` u otros usuarios.

### Sistema operativo y kernel

```
cat /etc/os-release     # Distribución y versión del SO
uname -a                # Versión del kernel y arquitectura
cat /proc/version       # Información alternativa del kernel
lscpu                   # Arquitectura y procesador
```

**Objetivo:** identificar versiones desactualizadas que puedan contener vulnerabilidades conocidas.

> Los exploits del kernel pueden provocar inestabilidad o bloquear el sistema.

---

## 2. Variables de entorno y PATH

```
echo $PATH      # Directorios donde se buscan ejecutables
env             # Todas las variables de entorno
```

**Qué buscar:**

- Contraseñas, tokens o credenciales en variables de entorno.
    
- Directorios modificables por nuestro usuario dentro de `$PATH`.
    

Un `PATH` mal configurado puede permitir **PATH Hijacking** si un proceso privilegiado ejecuta comandos sin especificar su ruta absoluta.

---

## 3. Servicios y mecanismos de seguridad

Identificar servicios en ejecución, especialmente aquellos ejecutados como `root`.

```
ps aux
ss -tulnp
```

Buscar servicios vulnerables o mal configurados, como:

- Nagios
    
- Exim
    
- Samba
    
- ProFTPd
    

También interesa identificar mecanismos de seguridad como **AppArmor, SELinux, iptables, ufw y Fail2ban**.

---

## 4. Enumeración de usuarios y grupos

### Usuarios existentes

```
cat /etc/passwd
```

Cada entrada contiene:

```
usuario:contraseña:UID:GID:información:home:shell
```

Ejemplo:

```
htb-student:x:1008:1008::/home/htb-student:/bin/bash
```

El carácter `x` indica que el hash de la contraseña normalmente se almacena en `/etc/shadow`.

Listar únicamente los nombres de usuario:

```
cut -d ':' -f1 /etc/passwd
```

### Usuarios con shell

```
grep "sh$" /etc/passwd
```

Permite identificar cuentas que tienen configuradas shells como `/bin/bash` o `/bin/sh`.

### Grupos del sistema

```
cat /etc/group
getent group sudo
id
```

**Qué buscar:**

- Usuarios pertenecientes al grupo `sudo`.
    
- Grupos que permitan acceder a archivos o recursos privilegiados.
    
- Cuentas de servicio con permisos interesantes.
    

### Shells disponibles

```
cat /etc/shells
```

Permite identificar shells instaladas, incluyendo Bash, Dash, Tmux o Screen.

---

## 5. Enumeración de red

Después de comprometer una máquina, debemos comprobar si tiene acceso a otras redes internas.

### Interfaces y rutas

```
ip a
ip route
netstat -rn
```

**Objetivo:** identificar otras subredes accesibles y posibles oportunidades de pivoting.

### DNS interno

```
cat /etc/resolv.conf
```

Puede revelar servidores DNS internos, especialmente útiles en entornos de Active Directory.

### Tabla ARP

```
arp -a
ip neigh
```

Permite identificar direcciones IP de equipos con los que el sistema ha tenido comunicación reciente.

---

## 6. Enumeración de discos y sistemas de archivos

### Dispositivos de almacenamiento

```
lsblk
```

Muestra discos, particiones y dispositivos de almacenamiento.

**Objetivo:** identificar unidades adicionales que puedan contener copias de seguridad, archivos sensibles o credenciales.

### Sistemas de archivos montados

```
df -h
```

Muestra los sistemas de archivos montados y su espacio disponible.

### Configuración de montajes

```
cat /etc/fstab
```

Buscar posibles credenciales:

```
grep -Ei 'password|username|credential' /etc/fstab
```

También podemos consultar:

```
mount
```

**Qué buscar:**

- Sistemas de archivos adicionales.
    
- Recursos compartidos.
    
- Credenciales en configuraciones de montaje.
    
- Archivos sensibles en particiones accesibles.
    

---

## 7. Enumeración de directorios personales

Listar los directorios de usuarios:

```
ls -la /home
```

Revisar los archivos accesibles de cada usuario.

### Archivos interesantes

```
cat ~/.bash_history
ls -la ~/.ssh
ls -la ~/.config
ls -la ~/.gnupg
```

|Archivo o directorio|Información interesante|
|---|---|
|`.bash_history`|Comandos ejecutados anteriormente|
|`.ssh/`|Claves SSH y configuraciones|
|`.config/`|Configuraciones y posibles credenciales|
|`.gnupg/`|Archivos relacionados con GPG|
|`.bashrc`|Variables y comandos de inicio|
|`.profile`|Configuración del entorno del usuario|

**Importante:** revisar también los directorios personales de otros usuarios si tenemos permisos de lectura.

---

## 8. Buscar archivos ocultos

Los archivos y directorios cuyo nombre comienza por `.` están ocultos en los listados normales.

### Buscar archivos ocultos

```
find / -type f -name ".*" 2>/dev/null
```

### Buscar directorios ocultos

```
find / -type d -name ".*" 2>/dev/null
```

El parámetro `2>/dev/null` oculta los errores de permisos.

**Objetivo:** localizar archivos que puedan contener contraseñas, notas, configuraciones o claves SSH.

---

## 9. Buscar credenciales en archivos de configuración

Los archivos `.conf` y `.config` pueden almacenar contraseñas de bases de datos, usuarios o servicios.

### Localizar archivos de configuración

```
find / -type f \( -name "*.conf" -o -name "*.config" \) 2>/dev/null
```

### Buscar posibles credenciales

```
grep -RiE 'password|passwd|secret|token|credential' /etc /opt /var/www /home 2>/dev/null
```

**Qué buscar:**

- Contraseñas de usuarios.
    
- Credenciales de bases de datos.
    
- Tokens de autenticación.
    
- Claves SSH.
    
- Archivos de configuración de aplicaciones.
    
- Credenciales reutilizadas en otros servicios.
    

---

## 10. Identificación de hashes

En algunos sistemas mal configurados pueden aparecer hashes directamente en `/etc/passwd`.

Los hashes suelen encontrarse en `/etc/shadow`, que normalmente requiere privilegios elevados para su lectura.

|Prefijo|Algoritmo|
|---|---|
|`$1$`|MD5|
|`$5$`|SHA-256|
|`$6$`|SHA-512|
|`$2a$`|BCrypt|
|`$7$`|Scrypt|
|`$argon2i$`|Argon2i|

Si encontramos hashes accesibles, podemos evaluar su resistencia mediante herramientas como John the Ripper o Hashcat.

---

## 11. Archivos temporales

Revisar los directorios:

```
ls -la /tmp /var/tmp /dev/shm
```

|Directorio|Características|
|---|---|
|`/tmp`|Archivos temporales, normalmente eliminados periódicamente|
|`/var/tmp`|Archivos temporales que pueden conservarse durante más tiempo|
|`/dev/shm`|Sistema de archivos temporal basado en memoria compartida|

**Qué buscar:**

- Archivos temporales con credenciales.
    
- Logs.
    
- Scripts.
    
- Copias de seguridad.
    
- Archivos modificables utilizados por procesos privilegiados.
    

---

## 12. Herramientas de enumeración automática

Además de la enumeración manual, podemos utilizar:

- **LinPEAS:** identifica posibles vectores de escalada de privilegios y configuraciones inseguras.
    
- **LinEnum:** automatiza diferentes comprobaciones del sistema Linux.
    

Estas herramientas complementan la enumeración manual, pero no la sustituyen.

## Idea clave para el examen

Cuando obtengas una shell en Linux, **no empieces directamente buscando exploits del kernel**.

Prioriza:

1. `**sudo -l**` → Posibles permisos para ejecutar comandos privilegiados.
    
2. `**id**` → Grupos que puedan proporcionar privilegios adicionales.
    
3. `**/home**` → Historiales, claves SSH y archivos sensibles.
    
4. **Archivos de configuración** → Contraseñas y credenciales.
    
5. **Procesos y servicios** → Aplicaciones vulnerables ejecutadas como root.
    
6. **Discos y montajes** → Copias de seguridad o datos sensibles.
    
7. **Kernel y sistema operativo** → Posibles vulnerabilidades conocidas.
    

El objetivo es encontrar una **mala configuración o información sensible que permita escalar privilegios**, antes de recurrir a exploits más complejos.
