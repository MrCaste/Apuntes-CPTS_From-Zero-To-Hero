
## 1. Interfaces de red y configuración

```bash
ip a
ifconfig
ip route
cat /etc/hosts
cat /etc/resolv.conf
```

- `ip a`: IPs, interfaces y subredes disponibles.
- `ip route`: rutas de red que pueden revelar otras subredes accesibles.
- `/etc/hosts`: nombres de equipos asociados a direcciones IP.
- `/etc/resolv.conf`: servidores DNS configurados.
- Comprueba si existen varias interfaces que permitan pivotar a otras redes.

## 2. Últimos inicios de sesión y usuarios conectados

```bash
lastlog
last
who
w
```

- `lastlog`: último inicio de sesión registrado por usuario.
- `last`: historial de sesiones anteriores.
- `who`: usuarios conectados.
- `w`: usuarios conectados y procesos que están ejecutando.

**Objetivo:** identificar usuarios interesantes, administradores y posibles sesiones de otros usuarios.

## 3. Historial de comandos

```bash
history
cat ~/.bash_history
```

Buscar historiales de otros usuarios o archivos con nombres similares:

```bash
find / -type f \( -name '*_hist' -o -name '*_history' \) -exec ls -l {} \; 2>/dev/null
```

Revisar historiales en busca de:
- Contraseñas o credenciales utilizadas en comandos.
- Conexiones SSH a otros equipos.
- Scripts creados o ejecutados.
- Tareas cron y configuraciones de servicios.
- Rutas interesantes o información sobre el entorno.

**Importante:** `history` muestra el historial de la sesión actual; para consultar otros historiales necesitas permisos de lectura sobre sus archivos.

## 4. Tareas cron

```bash
ls -la /etc/cron.daily/
ls -la /etc/cron.hourly/
ls -la /etc/cron.weekly/
ls -la /etc/cron.monthly/
cat /etc/crontab
ls -la /etc/cron.d/
```

Buscar posibles scripts programados:

```bash
find / -type f -name "*.sh" 2>/dev/null
```

**Qué comprobar:**
- Scripts ejecutados periódicamente por `root`.
- Permisos de escritura sobre scripts o directorios utilizados por cron.
- Uso de rutas relativas en lugar de rutas absolutas.
- Archivos que se ejecutan automáticamente y que puedes modificar.

Una tarea cron mal configurada puede permitir escalar privilegios si puedes controlar un archivo o comando que ejecuta con permisos superiores.

## 5. Procesos y servicios en ejecución

```bash
ps aux
ps aux | grep root
ss -tulnp
```

- `ps aux`: procesos en ejecución, usuarios y comandos.
- `ps aux | grep root`: procesos ejecutados por `root` que conviene investigar.
- `ss -tulnp`: puertos TCP/UDP, sockets en escucha y procesos asociados cuando tienes permisos suficientes para verlos.

**Busca:** servicios desconocidos, scripts personalizados, procesos ejecutados como `root` y aplicaciones que puedan tener configuraciones incorrectas.

## 6. Información de procesos mediante `/proc`

`/proc` es un sistema de archivos virtual que expone información sobre procesos y el kernel.

```bash
find /proc -name cmdline -exec cat {} \; 2>/dev/null | tr " " "\n"
```

Este comando busca los archivos `cmdline` de `/proc` y muestra los argumentos de los procesos, separándolos por líneas.

También puedes consultar los procesos individualmente:

```bash
cat /proc/<PID>/cmdline
```

Sustituye `<PID>` por el identificador del proceso.

**Objetivo:** descubrir comandos, rutas, argumentos y conexiones que puedan revelar información útil.

## 7. Paquetes instalados

En sistemas basados en Debian/Ubuntu:

```bash
apt list --installed
```

Guardar los nombres de los paquetes y sus versiones en un archivo:

```bash
apt list --installed | tr "/" " " | cut -d" " -f1,3 | sed 's/[0-9]://g' | tee -a installed_pkgs.list
```

- `tr "/" " "`: sustituye `/` por espacios.
- `cut -d" " -f1,3`: extrae los campos 1 y 3.
- `sed 's/[0-9]://g'`: elimina patrones como `1:` al principio de las versiones que utilizan una época.
- `tee -a`: muestra la salida y la añade al archivo `installed_pkgs.list`.

**Nota:** `tee -a` añade información al archivo; si repites el comando, puedes generar duplicados.

## 8. Versión de sudo

```bash
sudo -V
sudo -l
```

- `sudo -V`: muestra la versión instalada de sudo.
- `sudo -l`: muestra los comandos que tu usuario puede ejecutar mediante sudo.

Comprueba si la versión de sudo presenta vulnerabilidades conocidas y si los permisos configurados ofrecen alguna vía de escalada.

## 9. Binarios instalados

```bash
ls -l /bin /usr/bin /usr/sbin
```

Además de los paquetes instalados, puede haber binarios compilados manualmente.

Busca herramientas que puedan resultar útiles, como:

- `python`, `perl`, `ruby`: ejecución de scripts.
- `gcc`: compilación de programas.
- `nc`: conexiones de red.
- `curl`, `wget`: transferencia de archivos.
- `nmap`: enumeración de red.
- `strace`: análisis de llamadas al sistema.

## 10. Comprobar binarios con GTFOBins

GTFOBins documenta formas de utilizar determinados binarios Unix para realizar acciones que pueden resultar útiles durante una escalada de privilegios.

Página: https://gtfobins.github.io/

El módulo propone comparar los ejecutables de GTFOBins con los paquetes instalados:

```bash
for i in $(curl -s https://gtfobins.org/api.json | jq -r '.executables | keys[]'); do
    if grep -q "$i" installed_pkgs.list; then
        echo "Check GTFO for: $i"
    fi
done
```

**Importante:** que un binario aparezca en la lista no significa que sea vulnerable. Debes comprobar si existe una vía de explotación aplicable a sus permisos y a tu situación.

## 11. Analizar programas con strace

```bash
strace ping -c1 10.129.112.20
```

`strace` permite observar las llamadas al sistema realizadas por un programa.

Para guardar la salida en un archivo:

```bash
strace -o strace.log <comando>
```

Para filtrar las llamadas relacionadas con archivos:

```bash
strace -e trace=%file <comando>
```

Puede ayudar a identificar:
- Archivos que intenta abrir un programa.
- Rutas utilizadas por un servicio.
- Accesos fallidos a archivos o directorios.
- Comunicaciones y operaciones del sistema.

## 12. Archivos de configuración

```bash
find / -type f \( -name "*.conf" -o -name "*.config" \) -exec ls -l {} \; 2>/dev/null
```

Este comando busca archivos de configuración y muestra sus permisos.

Para localizar posibles scripts:

```bash
find / -type f -name "*.sh" 2>/dev/null | grep -v "src\|snap\|share"
```

**Qué revisar:**
- Credenciales, contraseñas, tokens o claves.
- Rutas a scripts y ejecutables.
- Configuraciones de servicios.
- Permisos de lectura y escritura.
- Scripts personalizados que se ejecuten como `root`.

Un archivo puede ser legible aunque no tengas permiso para listar su directorio, siempre que conozcas su ruta y tengas permisos suficientes sobre el archivo.

## 13. Procesos ejecutados por root

```bash
ps aux | grep root
```

Examina los comandos completos y las rutas de los procesos que se ejecutan con privilegios elevados.

Si encuentras un script o binario personalizado, comprueba sus permisos y los de los archivos y directorios de los que depende.
