
## 1. Buscar credenciales en archivos

Las credenciales pueden aparecer en:

- Archivos de configuración: `.conf`, `.config`, `.xml`.
    
- Scripts de shell: `.sh`.
    
- Historiales de comandos: `.bash_history`.
    
- Copias de seguridad: `.bak`.
    
- Archivos de texto y bases de datos.
    
- Configuraciones de aplicaciones web.
    

### Buscar archivos de configuración

```
find / ! -path "*/proc/*" -iname "*config*" -type f 2>/dev/null
```

Busca archivos cuyo nombre contenga `config`, ignorando mayúsculas y minúsculas, y excluye las rutas de `/proc`.

### Buscar posibles contraseñas en archivos PHP

```
find / -type f -name "wp*.php" -exec grep -iHnE "pass" {} + 2>/dev/null
```

- `-name "wp*.php"`: busca archivos cuyo nombre empiece por `wp` y termine en `.php`.
    
- `grep -iHnE "pass"`: busca líneas que contengan `pass`, sin distinguir mayúsculas, mostrando el archivo y el número de línea.
    
- `{}`: representa los archivos encontrados.
    
- `+`: agrupa varios archivos por ejecución de `grep`.
    

**Importante:** encontrar una coincidencia con `pass` no garantiza que sea una contraseña válida.

## 2. Revisar la configuración de WordPress

La raíz web suele encontrarse en directorios bajo `/var`, como `/var/www`. Los archivos de configuración pueden contener credenciales de bases de datos.

En `wp-config.php`, busca:

```
grep 'DB_USER\|DB_PASSWORD' wp-config.php
```

Ejemplo de salida:

```
define( 'DB_USER', 'wordpressuser' );
define( 'DB_PASSWORD', 'WPadmin123!' );
```

- `DB_USER`: usuario de la base de datos.
    
- `DB_PASSWORD`: contraseña de la base de datos.
    

Estas credenciales podrían permitir acceder a la base de datos y, si se reutilizan, a otros servicios o usuarios.

## 3. Buscar claves SSH

Las claves SSH pueden permitir conectarte como otro usuario o acceder a otros equipos.

Comprueba el directorio SSH del usuario actual:

```
ls -la ~/.ssh
```

Busca especialmente:

|Archivo|Utilidad|
|---|---|
|`id_rsa`|Clave privada SSH.|
|`id_rsa.pub`|Clave pública SSH.|
|`known_hosts`|Información de los hosts a los que se ha conectado el usuario.|

Si encuentras claves privadas accesibles de otros usuarios, comprueba a qué cuentas podrían pertenecer y si permiten autenticarse en otros sistemas.

### Revisar los hosts conocidos

```
cat ~/.ssh/known_hosts
```

Este archivo puede proporcionar pistas sobre otros equipos del entorno con los que el usuario se ha conectado anteriormente.

## Checklist para HTB

- Buscar archivos de configuración que puedan contener credenciales.
    
- Revisar archivos de configuración de aplicaciones web, especialmente `wp-config.php`.
    
- Examinar scripts, historiales, copias de seguridad y archivos de texto accesibles.
    
- Buscar claves privadas SSH.
    
- Revisar `known_hosts` para identificar posibles objetivos.
    
- Comprobar si las credenciales encontradas permiten acceder a otros usuarios, bases de datos o sistemas.
    

**Prioridad:** empieza por las configuraciones de aplicaciones web y las claves SSH accesibles. Las credenciales encontradas pueden abrir nuevas vías de acceso o escalada de privilegios.
