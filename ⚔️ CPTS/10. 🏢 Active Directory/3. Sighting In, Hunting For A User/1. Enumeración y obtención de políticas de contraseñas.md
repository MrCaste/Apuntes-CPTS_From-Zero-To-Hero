
## 1. Enumerar la política de contraseñas desde Linux con credenciales

Si disponemos de credenciales válidas del dominio, podemos obtener la política de contraseñas mediante herramientas como **CrackMapExec** o `rpcclient`.

### CrackMapExec

```
crackmapexec smb <IP_DC> -u <USUARIO> -p '<CONTRASEÑA>' --pass-pol
```

Ejemplo:

```
crackmapexec smb 172.16.5.5 -u avazquez -p 'Password123' --pass-pol
```

La salida puede mostrar:

- `Minimum password length`: longitud mínima de la contraseña.
    
- `Password history length`: número de contraseñas anteriores recordadas.
    
- `Maximum password age`: vigencia máxima de la contraseña.
    
- `Minimum password age`: vigencia mínima de la contraseña.
    
- `Account Lockout Threshold`: número de intentos fallidos antes del bloqueo.
    
- `Locked Account Duration`: duración del bloqueo.
    
- `Reset Account Lockout Counter`: tiempo tras el que se reinicia el contador de intentos fallidos.
    
- `Domain Password Complex`: indica si está habilitada la complejidad de contraseñas.
    

**Importante:** conocer estos valores permite evaluar el riesgo de contraseñas débiles y determinar qué precauciones tomar antes de realizar pruebas de autenticación.

## 2. Enumerar la política de contraseñas mediante una sesión nula SMB

Una **sesión nula SMB (SMB Null Session)** permite conectarse a determinados servicios SMB/RPC sin proporcionar credenciales.

Si el controlador de dominio lo permite, podríamos enumerar información como:

- Usuarios y grupos.
    
- Información del dominio.
    
- Equipos.
    
- Atributos de cuentas.
    
- Política de contraseñas.
    

Esta configuración suele estar relacionada con permisos anónimos heredados o configuraciones incorrectas.

### 2.1. Comprobar el acceso con `rpcclient`

```
rpcclient -U "" -N <IP_DC>
```

Ejemplo:

```
rpcclient -U "" -N 172.16.5.5
```

Si se establece la conexión, podemos consultar información del dominio.

**Consultar información del dominio:**

```
querydominfo
```

Ejemplo de salida:

```
Domain:     INLANEFREIGHT
Total Users:    3650
Total Groups:   0
Total Aliases:  37
Server Role:    ROLE_DOMAIN_PDC
```

**Consultar la política de contraseñas:**

```
getdompwinfo
```

Ejemplo:

```
min_password_length: 8
password_properties: 0x00000001
    DOMAIN_PASSWORD_COMPLEX
```

Interpretación:

- `min_password_length: 8`: la contraseña debe tener al menos ocho caracteres.
    
- `DOMAIN_PASSWORD_COMPLEX`: la complejidad de las contraseñas está habilitada.
    

Para salir de `rpcclient`:

```
exit
```

### 2.2. Enumerar con `enum4linux`

La opción `-P` permite obtener información sobre la política de contraseñas.

```
enum4linux -P <IP_DC>
```

Ejemplo:

```
enum4linux -P 172.16.5.5
```

La salida puede incluir:

- Longitud mínima de la contraseña.
    
- Historial de contraseñas.
    
- Vigencia mínima y máxima.
    
- Complejidad.
    
- Umbral de bloqueo.
    
- Duración del bloqueo.
    
- Tiempo de observación del bloqueo.
    

La herramienta puede intentar conectarse mediante SMB sin credenciales. Que falle por un puerto o protocolo no significa necesariamente que todos los métodos de enumeración vayan a fallar.

### 2.3. Enumerar con `enum4linux-ng`

`enum4linux-ng` es una reescritura de `enum4linux` en Python que proporciona una salida más estructurada y permite exportar los resultados.

```
enum4linux-ng -P <IP_DC> -oA <NOMBRE_ARCHIVO>
```

Ejemplo:

```
enum4linux-ng -P 172.16.5.5 -oA ilfreight
```

La opción `-oA` permite guardar los resultados en formatos como JSON y YAML.

Consultar el archivo JSON:

```
cat ilfreight.json
```

También puede mostrar si el servidor permite una sesión nula:

```
[+] Server allows session using username '', password ''
```

**Importante:** una sesión nula permitida no implica automáticamente que todos los objetos del dominio sean accesibles. Hay que comprobar qué información puede enumerarse realmente.

## 3. Enumerar una sesión nula desde Windows

Desde una máquina Windows podemos intentar establecer una sesión nula contra el recurso IPC$ del controlador de dominio.

```
net use \\<DC>\ipc$ "" /u:""
```

Ejemplo:

```
net use \\DC01\ipc$ "" /u:""
```

Si aparece:

```
The command completed successfully.
```

se ha establecido la conexión.

### Errores de autenticación habituales

|Código|Significado|
|---|---|
|`1331`|La cuenta está deshabilitada.|
|`1326`|El nombre de usuario o la contraseña son incorrectos.|
|`1909`|La cuenta está bloqueada.|

Estos errores proporcionan información sobre el resultado del intento de autenticación, pero deben interpretarse en su contexto.

## 4. Enumerar la política mediante una vinculación anónima LDAP

Una **vinculación anónima LDAP (LDAP Anonymous Bind)** permite consultar determinados objetos del directorio sin autenticarse, si la configuración del servidor lo permite.

Puede exponer información como:

- Usuarios.
    
- Grupos.
    
- Equipos.
    
- Atributos de objetos.
    
- Política de contraseñas.
    

Es una configuración heredada que puede persistir cuando se han concedido permisos anónimos a aplicaciones o servicios.

### 4.1. Usar `ldapsearch`

```
ldapsearch -H ldap://<IP_DC> -x -b "DC=<DOMINIO>,DC=<TLD>" -s sub "*" 
```

Ejemplo:

```
ldapsearch -H ldap://172.16.5.5 -x -b "DC=INLANEFREIGHT,DC=LOCAL" -s sub "*"
```

Para localizar campos relacionados con la política de contraseñas:

```
ldapsearch -H ldap://172.16.5.5 -x -b "DC=INLANEFREIGHT,DC=LOCAL" -s sub "*" | grep -m 1 -B 10 pwdHistoryLength
```

**Nota:** en versiones modernas de `ldapsearch`, se utiliza `-H` para especificar el servidor LDAP; la opción `-h` aparece en ejemplos antiguos.

### Atributos importantes

|Atributo LDAP|Significado|
|---|---|
|`minPwdLength`|Longitud mínima de la contraseña.|
|`pwdHistoryLength`|Historial de contraseñas.|
|`maxPwdAge`|Vigencia máxima de la contraseña.|
|`minPwdAge`|Vigencia mínima de la contraseña.|
|`lockoutThreshold`|Intentos fallidos antes del bloqueo.|
|`lockoutDuration`|Duración del bloqueo.|
|`lockOutObservationWindow`|Periodo de observación de los intentos fallidos.|
|`pwdProperties`|Propiedades de la política de contraseñas.|

Ejemplo de salida:

```
lockoutThreshold: 5
minPwdLength: 8
pwdProperties: 1
pwdHistoryLength: 24
```

En este ejemplo, la longitud mínima es de ocho caracteres y el umbral de bloqueo es de cinco intentos fallidos.

**Importante:** los valores de `maxPwdAge`, `minPwdAge` y `lockoutDuration` pueden aparecer representados en unidades de tiempo LDAP y como números negativos. No deben interpretarse directamente como segundos sin convertirlos correctamente.

## 5. Enumerar la política de contraseñas desde Windows

Si tenemos acceso a un sistema Windows unido al dominio, podemos utilizar herramientas integradas o herramientas de enumeración.

### 5.1. Usar `net accounts`

```
net accounts
```

Ejemplo de salida:

```
Minimum password age (days):             1
Maximum password age (days):             Unlimited
Minimum password length:                 8
Length of password history maintained:   24
Lockout threshold:                       5
Lockout duration (minutes):              30
Lockout observation window (minutes):    30
```

Esta salida permite identificar rápidamente:

- Longitud mínima de las contraseñas.
    
- Historial de contraseñas.
    
- Vigencia mínima y máxima.
    
- Umbral de bloqueo.
    
- Duración del bloqueo.
    
- Tiempo de observación de intentos fallidos.
    

**Precaución:** `net accounts` muestra la política aplicable al contexto consultado. No hay que asumir que siempre refleja todas las políticas efectivas del dominio o las posibles políticas específicas de contraseñas.

### 5.2. Usar PowerView

Importar el módulo:

```
Import-Module .\PowerView.ps1
```

Consultar la política del dominio:

```
Get-DomainPolicy
```

Entre los campos relevantes de `SystemAccess` encontramos:

|Campo|Significado|
|---|---|
|`MinimumPasswordAge`|Edad mínima de la contraseña.|
|`MaximumPasswordAge`|Edad máxima de la contraseña.|
|`MinimumPasswordLength`|Longitud mínima.|
|`PasswordComplexity`|Estado de la complejidad.|
|`PasswordHistorySize`|Número de contraseñas anteriores recordadas.|
|`LockoutBadCount`|Umbral de intentos fallidos.|
|`ResetLockoutCount`|Tiempo para reiniciar el contador.|
|`LockoutDuration`|Duración del bloqueo.|
|`ClearTextPassword`|Indica si se permite almacenar contraseñas mediante cifrado reversible.|

También puede mostrar información de la GPO de la que procede la política, como `Default Domain Policy`.

## 6. Analizar la política de contraseñas

En el ejemplo de `INLANEFREIGHT.LOCAL`, la política obtenida es:

|Parámetro|Valor|
|---|---|
|Longitud mínima|8 caracteres|
|Historial|24 contraseñas|
|Vigencia máxima|Sin límite configurado|
|Vigencia mínima|Aproximadamente 1 día|
|Complejidad|Habilitada|
|Umbral de bloqueo|5 intentos|
|Duración del bloqueo|30 minutos|
|Reinicio del contador|30 minutos|

### Interpretación para una evaluación de seguridad

- **Longitud mínima de ocho caracteres:** puede permitir contraseñas relativamente débiles, aunque la longitud por sí sola no determina su fortaleza.
    
- **Sin vigencia máxima configurada:** las contraseñas pueden no tener una caducidad periódica obligatoria según esta política.
    
- **Complejidad habilitada:** no garantiza que las contraseñas sean robustas. Contraseñas predecibles pueden cumplir los requisitos de complejidad.
    
- **Umbral de bloqueo de cinco intentos:** varios intentos fallidos pueden provocar el bloqueo de una cuenta.
    
- **Bloqueo de 30 minutos:** las cuentas afectadas permanecen bloqueadas durante ese periodo si la política permite su desbloqueo automático.
    
- **Historial de 24 contraseñas:** limita la reutilización de contraseñas anteriores según la política aplicable.
    

### Complejidad de las contraseñas

Según la explicación de HTB, la política de complejidad requiere cumplir tres de estas cuatro categorías:

1. Letras mayúsculas.
    
2. Letras minúsculas.
    
3. Números.
    
4. Caracteres especiales.
    

Cumplir los requisitos de complejidad no significa necesariamente que una contraseña sea difícil de adivinar.

### Valores predeterminados de referencia indicados por HTB

|Política|Valor predeterminado|
|---|---|
|Historial de contraseñas|24 contraseñas|
|Vigencia máxima|42 días|
|Vigencia mínima|1 día|
|Longitud mínima|7 caracteres|
|Complejidad|Habilitada|
|Cifrado reversible|Deshabilitado|
|Duración del bloqueo|No definida|
|Umbral de bloqueo|0|
|Reinicio del contador de bloqueo|No definido|

Estos valores son los valores de referencia presentados en el material, no una garantía de que todos los dominios actuales utilicen esa configuración.

## 7. Password Spraying: precauciones antes de empezar

Después de enumerar la política de contraseñas, el siguiente paso del módulo es recopilar una lista de usuarios objetivo para preparar un posible ataque de **password spraying**.

El password spraying consiste en probar una misma contraseña contra varias cuentas, en lugar de probar muchas contraseñas contra una sola cuenta.

Antes de realizarlo, debemos conocer:

- El umbral de bloqueo.
    
- La duración del bloqueo.
    
- El periodo de observación de intentos fallidos.
    
- Si las cuentas se desbloquean automáticamente o requieren intervención administrativa.
    
- Las restricciones y reglas de la evaluación.
    

### Si no conocemos la política

HTB recomienda actuar con extrema precaución:

- Siempre que sea posible, obtener la política de contraseñas antes de realizar pruebas.
    
- Si procede, solicitar esa información al cliente.
    
- Si no es posible obtenerla, limitar los intentos y respetar las reglas de la evaluación.
    
- El material recomienda, como máximo, uno o dos intentos de password spraying cuando se desconoce la política; si se realizan dos, aconseja esperar más de una hora entre ellos.
    
- Evitar bloquear cuentas a toda costa.
    

**No debe asumirse que todas las organizaciones utilizan un umbral de cinco intentos o que desbloquean automáticamente las cuentas.** Algunas requieren que un administrador las desbloquee manualmente.

## 10. Flujo de trabajo recomendado para el laboratorio

1. **Con credenciales:** intentar obtener la política con CrackMapExec.
    
2. **Sin credenciales:** comprobar si el objetivo permite una sesión nula SMB con `rpcclient`.
    
3. **Enumeración SMB adicional:** probar `enum4linux` o `enum4linux-ng`.
    
4. **LDAP:** comprobar si es posible realizar consultas anónimas con `ldapsearch`.
    
5. **Desde Windows:** utilizar `net accounts` y, si está disponible, `Get-DomainPolicy`.
    
6. **Interpretar los resultados:** identificar longitud mínima, complejidad, historial, umbral de bloqueo y duración.
    
7. **Antes de password spraying:** comprobar las reglas de la evaluación y actuar con precaución para no bloquear cuentas.
    
8. **Siguiente paso del módulo:** recopilar una lista de usuarios objetivo.
    

**Idea clave para CPTS/OSCP:** saber obtener la política de contraseñas con y sin credenciales, interpretar sus valores y evaluar el riesgo de bloqueo antes de probar credenciales.
