
## 1. Objetivo

Antes de realizar un ataque de **Password Spraying**, necesitamos una lista de usuarios válidos del dominio contra los que comprobar credenciales.

Podemos obtenerla mediante diferentes métodos:

- **SMB Null Session:** enumerar usuarios sin credenciales si el controlador de dominio permite sesiones nulas.
    
- **LDAP Anonymous Bind:** consultar LDAP sin autenticación si la configuración lo permite.
    
- **Kerbrute:** comprobar qué usuarios existen utilizando una lista de posibles nombres de usuario.
    
- **Credenciales válidas:** consultar Active Directory con un usuario autenticado.
    
- **Recopilación de información externa:** utilizar correos electrónicos públicos, LinkedIn y herramientas de generación de nombres de usuario.
    

Antes de empezar, debemos conocer la política de contraseñas del dominio siempre que sea posible, especialmente el umbral de bloqueo y el tiempo de reinicio del contador de intentos fallidos.

---

## 2. Obtener usuarios mediante una sesión nula SMB

Una sesión nula SMB permite acceder a determinados servicios sin proporcionar credenciales, siempre que el servidor lo permita.

### 2.1. Enumerar usuarios con enum4linux

La opción `-U` permite enumerar usuarios del dominio.

```
enum4linux -U <IP_DC>
```

Para extraer únicamente los nombres de usuario:

```
enum4linux -U <IP_DC> | grep "user:" | cut -f2 -d"[" | cut -f1 -d"]"
```

Ejemplo:

```
enum4linux -U 172.16.5.5 | grep "user:" | cut -f2 -d"[" | cut -f1 -d"]"
```

Salida:

```
administrator
guest
krbtgt
lab_adm
htb-student
avazquez
pfalcon
fanthony
wdillard
lbradford
sgage
asanchez
dbranch
ccruz
njohnson
mholliday
```

El resultado es una lista de nombres de usuario que podemos guardar para utilizarla en posteriores tareas de enumeración.

Para guardarla directamente en un archivo:

```
enum4linux -U <IP_DC> | grep "user:" | cut -f2 -d"[" | cut -f1 -d"]" > users.txt
```

### 2.2. Enumerar usuarios con rpcclient

Conectarnos anónimamente:

```
rpcclient -U "" -N <IP_DC>
```

Ejemplo:

```
rpcclient -U "" -N 172.16.5.5
```

Una vez dentro, ejecutar:

```
enumdomusers
```

Ejemplo de salida:

```
user:[administrator] rid:[0x1f4]
user:[guest] rid:[0x1f5]
user:[krbtgt] rid:[0x1f6]
user:[lab_adm] rid:[0x3e9]
user:[htb-student] rid:[0x457]
user:[avazquez] rid:[0x458]
```

El comando muestra los usuarios del dominio junto con sus **RID (Relative Identifier)**.

Para salir:

```
exit
```

**Importante:** si la sesión nula no está permitida, necesitaremos otro método de enumeración.

## 3. Enumerar usuarios con CrackMapExec

CrackMapExec permite enumerar usuarios y consultar información relacionada con los intentos de autenticación fallidos.

### 3.1. Enumerar usuarios

```
crackmapexec smb <IP_DC> --users
```

Ejemplo:

```
crackmapexec smb 172.16.5.5 --users
```

La salida incluye información como:

```
INLANEFREIGHT.LOCAL\administrator  badpwdcount: 0
INLANEFREIGHT.LOCAL\guest          badpwdcount: 0
INLANEFREIGHT.LOCAL\lab_adm        badpwdcount: 0
INLANEFREIGHT.LOCAL\htb-student    badpwdcount: 0
INLANEFREIGHT.LOCAL\avazquez       badpwdcount: 20
```

Los campos más importantes son:

|Campo|Significado|
|---|---|
|`badpwdcount`|Número de intentos de contraseña incorrectos que refleja el atributo consultado.|
|`badpwdtime`|Fecha y hora del último intento de contraseña incorrecto.|

Estos valores son útiles para evaluar el riesgo de bloqueo antes de realizar pruebas de autenticación.

### 3.2. Consultar con credenciales válidas

También podemos enumerar usuarios autenticándonos con una cuenta válida:

```
crackmapexec smb <IP_DC> -u <USUARIO> -p '<CONTRASEÑA>' --users
```

Ejemplo:

```
crackmapexec smb 172.16.5.5 -u htb-student -p 'Academy_student_AD!' --users
```

Si las credenciales son válidas y el servidor permite la operación, obtendremos la lista de usuarios y la información adicional disponible.

### 3.3. Precaución con varios controladores de dominio

En un entorno con varios DC, el valor de `badpwdcount` puede mantenerse por separado en cada controlador de dominio.

Por tanto, consultar solamente un DC no siempre proporciona una visión completa de los intentos fallidos.

Según el material de HTB, para obtener una visión más precisa debemos consultar todos los DC y considerar la suma de los valores, o consultar el controlador de dominio que tiene el rol FSMO de **PDC Emulator**.

**No debemos interpretar** `**badpwdcount**` **como un contador global necesariamente sincronizado entre todos los DC.**

## 4. Obtener usuarios mediante LDAP anónimo

Si el servidor LDAP permite vinculaciones anónimas, podemos consultar los objetos de Active Directory sin proporcionar credenciales.

### 4.1. Usar ldapsearch

El siguiente comando consulta los objetos que coinciden con el filtro LDAP indicado:

```
ldapsearch -H ldap://<IP_DC> -x -b "DC=<DOMINIO>,DC=<TLD>" -s sub "(&(objectclass=user))"
```

Ejemplo para `INLANEFREIGHT.LOCAL`:

```
ldapsearch -H ldap://172.16.5.5 -x -b "DC=INLANEFREIGHT,DC=LOCAL" -s sub "(&(objectclass=user))"
```

Para extraer los nombres de las cuentas mediante `sAMAccountName`:

```
ldapsearch -H ldap://<IP_DC> -x -b "DC=<DOMINIO>,DC=<TLD>" -s sub "(&(objectclass=user))" | grep "sAMAccountName:" | cut -f2 -d" "
```

Ejemplo:

```
ldapsearch -H ldap://172.16.5.5 -x -b "DC=INLANEFREIGHT,DC=LOCAL" -s sub "(&(objectclass=user))" | grep "sAMAccountName:" | cut -f2 -d" "
```

Posible salida:

```
guest
ACADEMY-EA-DC01$
ACADEMY-EA-MS01$
ACADEMY-EA-WEB01$
htb-student
avazquez
pfalcon
fanthony
wdillard
lbradford
sgage
asanchez
dbranch
```

**Nota:** el filtro `objectclass=user` también puede devolver cuentas de equipo. En el ejemplo, las cuentas terminadas en `$` corresponden a equipos del dominio.

Si necesitamos una lista exclusivamente de cuentas de usuario, tendremos que filtrar los resultados y distinguir las cuentas de usuario de las cuentas de equipo.

### 4.2. Usar windapsearch

`windapsearch.py` facilita la enumeración de objetos LDAP.

Para enumerar usuarios mediante una vinculación anónima:

```
./windapsearch.py --dc-ip <IP_DC> -u "" -U
```

Ejemplo:

```
./windapsearch.py --dc-ip 172.16.5.5 -u "" -U
```

La opción `-u ""` indica que se utilizará un nombre de usuario vacío para intentar la vinculación anónima, mientras que `-U` solicita la enumeración de usuarios.

La herramienta puede mostrar:

- Número de usuarios encontrados.
    
- Nombre del objeto (`cn`).
    
- Nombre principal de usuario (`userPrincipalName`).
    
- Información adicional disponible en LDAP.
    

Ejemplo:

```
[+] No username provided. Will try anonymous bind.
[+] Found: DC=INLANEFREIGHT,DC=LOCAL
[+] ...success! Binded as:

[+] Enumerating all AD users
[+] Found 2906 users:
```

Si la vinculación anónima está permitida, podremos obtener una lista de usuarios sin disponer de credenciales de dominio.

## 5. Enumerar usuarios con Kerbrute

Cuando no podemos obtener usuarios mediante SMB o LDAP, podemos recurrir a **Kerbrute**.

Esta herramienta utiliza Kerberos para comprobar qué nombres de usuario son válidos en el dominio.

### 5.1. Funcionamiento

El proceso de enumeración se basa en las respuestas del KDC (Key Distribution Center):

- Si el KDC devuelve `PRINCIPAL UNKNOWN`, el nombre de usuario no existe.
    
- Si el KDC solicita la preautenticación Kerberos, el nombre de usuario existe.
    

Esto permite validar nombres de usuario sin conocer sus contraseñas.

Según el material de HTB, esta técnica de enumeración no provoca fallos de inicio de sesión convencionales ni incrementa el contador de contraseñas incorrectas de la misma manera que un intento de contraseña fallido.

Sin embargo, la actividad puede quedar registrada y ser detectada por los defensores.

### 5.2. Preparar una lista de nombres de usuario

Podemos utilizar listas de posibles nombres de usuario, como las disponibles en el repositorio `statistically-likely-usernames`.

También podemos generar candidatos utilizando información pública de la organización, por ejemplo, nombres y apellidos obtenidos de fuentes autorizadas.

El formato de los nombres de usuario dependerá de las convenciones del dominio:

- `inicialapellido`
    
- `nombreapellido`
    
- `nombre.apellido`
    
- `iniciales`
    

En el ejemplo de HTB se utiliza una lista de nombres de usuario en formato `flast`.

### 5.3. Ejecutar Kerbrute

```
kerbrute userenum -d <DOMINIO> --dc <IP_DC> <WORDLIST>
```

Ejemplo:

```
kerbrute userenum -d inlanefreight.local --dc 172.16.5.5 /opt/jsmith.txt
```

La salida muestra los usuarios válidos:

```
[+] VALID USERNAME: jjones@inlanefreight.local
[+] VALID USERNAME: sbrown@inlanefreight.local
[+] VALID USERNAME: tjohnson@inlanefreight.local
[+] VALID USERNAME: jwilson@inlanefreight.local
[+] VALID USERNAME: bdavis@inlanefreight.local
[+] VALID USERNAME: njohnson@inlanefreight.local
[+] VALID USERNAME: asanchez@inlanefreight.local
```

Los nombres identificados pueden recopilarse en una lista para su posterior análisis.

### 5.4. Detección de Kerbrute

HTB destaca el evento de Windows **4768**, relacionado con solicitudes de tickets de autenticación Kerberos (TGT).

Cuando el registro de eventos Kerberos está habilitado, un volumen anormal de estos eventos puede ayudar a identificar una enumeración de usuarios.

**Importante:** que la enumeración no genere los fallos de autenticación habituales no significa que sea invisible o indetectable.

Además, cuando se pasa de enumerar usuarios a probar contraseñas, los intentos fallidos de preautenticación Kerberos pueden incrementar el contador de fallos y provocar bloqueos.

## 6. Crear una lista mediante recopilación de información externa

Si no podemos enumerar usuarios mediante SMB, LDAP o Kerberos, podemos recopilar información pública para generar candidatos.

Las fuentes mencionadas por HTB incluyen:

- Direcciones de correo electrónico corporativas publicadas.
    
- Perfiles de empleados en LinkedIn.
    
- Información pública de la organización.
    
- Herramientas como `linkedin2username`.
    
- Listas de nombres de usuario probables.
    

La herramienta `linkedin2username` permite generar posibles nombres de usuario a partir de información de perfiles de LinkedIn.

Esta lista no será necesariamente completa ni contendrá solo usuarios válidos, por lo que tendremos que validarla con los métodos disponibles.

## 7. Mantener un registro de las pruebas

Antes de realizar un password spraying, debemos mantener un registro detallado de nuestras actividades.

Como mínimo, registrar:

|Dato|Motivo|
|---|---|
|Cuentas objetivo|Evitar repetir intentos innecesarios.|
|Controlador de dominio utilizado|Identificar el sistema contra el que se realizaron las pruebas.|
|Fecha|Mantener la cronología de la evaluación.|
|Hora|Correlacionar los intentos con los registros del sistema.|
|Contraseñas probadas|Evitar duplicar intentos y facilitar la auditoría.|
|Resultado|Identificar éxitos, fallos y posibles bloqueos.|

Este registro permite correlacionar los resultados con los logs del cliente y explicar cualquier actividad de autenticación sospechosa.

Si se produce un bloqueo de cuenta, también ayuda a identificar las pruebas relacionadas.

## 8. Precauciones antes de realizar password spraying

La enumeración de usuarios es solo una parte del proceso. Antes de probar contraseñas debemos revisar la política de contraseñas y las condiciones de la evaluación.

Puntos importantes:

- Identificar el umbral de bloqueo de cuentas.
    
- Conocer la duración del bloqueo y el tiempo de reinicio del contador.
    
- Revisar los contadores de intentos fallidos cuando estén disponibles.
    
- Tener en cuenta que varios controladores de dominio pueden reflejar contadores diferentes.
    
- Evitar repetir intentos innecesarios.
    
- Registrar todas las pruebas.
    
- No asumir que una política habitual se aplica al entorno objetivo.
    

Si desconocemos la política de contraseñas, HTB recomienda extremar las precauciones y reservar los intentos de spraying para cuando se hayan agotado las demás opciones.

**El objetivo es evitar bloquear cuentas de la organización durante la evaluación.**

## 10. Flujo de trabajo recomendado

1. **Buscar una lista de usuarios existente:** aprovechar los datos obtenidos durante la enumeración inicial.
    
2. **Probar SMB anónimo:** utilizar `enum4linux` o `rpcclient` si el servidor lo permite.
    
3. **Probar LDAP anónimo:** utilizar `ldapsearch` o `windapsearch.py`.
    
4. **Enumerar con credenciales:** si disponemos de ellas, utilizar CrackMapExec para consultar usuarios.
    
5. **Usar Kerbrute:** validar candidatos cuando los métodos anteriores no estén disponibles.
    
6. **Recurrir a fuentes externas:** generar candidatos mediante información pública si no podemos enumerar directamente.
    
7. **Analizar los contadores de fallos:** revisar `badpwdcount` y `badpwdtime` cuando estén disponibles.
    
8. **Registrar las pruebas:** anotar las cuentas, el DC, la fecha, la hora, las contraseñas probadas y los resultados.
    
9. **Revisar la política de contraseñas:** determinar las restricciones antes de probar credenciales.
    

### Conceptos clave para CPTS/OSCP

- **SMB Null Session:** enumeración SMB sin credenciales cuando está permitida.
    
- **LDAP Anonymous Bind:** consulta LDAP anónima cuando está permitida.
    
- `**enumdomusers**`**:** enumera usuarios mediante `rpcclient`.
    
- `**--users**`**:** permite enumerar usuarios con CrackMapExec.
    
- `**badpwdcount**`**:** contador de intentos de contraseña incorrectos reflejado por el DC consultado.
    
- `**badpwdtime**`**:** fecha y hora del último intento de contraseña incorrecto.
    
- **Kerbrute** `**userenum**`**:** valida nombres de usuario utilizando Kerberos.
    
- **Evento 4768:** evento asociado a solicitudes de TGT que puede ayudar a detectar actividad anormal de enumeración.
    
- **Password Spraying:** prueba una contraseña contra varias cuentas; debe realizarse conociendo las restricciones de bloqueo y siguiendo las reglas de la evaluación.
