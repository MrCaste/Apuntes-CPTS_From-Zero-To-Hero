
## 1. Enumeración inicial con PowerView

### Buscar ACL interesantes en el dominio

```
Find-InterestingDomainAcl
```

Devuelve muchas ACE y puede generar demasiado ruido. Es más eficiente realizar una **enumeración dirigida** a partir del usuario que controlamos.

### Obtener el SID del usuario

```
$sid = Convert-NameToSid wley
```

### Buscar objetos sobre los que tiene permisos

```
Get-DomainObjectACL -Identity * | Where-Object {$_.SecurityIdentifier -eq $sid}
```

- `-Identity *`: consulta los objetos del dominio.
    
- `SecurityIdentifier`: identifica al usuario o grupo que posee el permiso.
    
- `$sid`: SID del usuario que estamos investigando.
    

**Importante:** la consulta puede tardar varios minutos en dominios grandes.

### Resolver los GUID de las ACE

Para obtener nombres legibles de los permisos, utiliza `-ResolveGUIDs`:

```
Get-DomainObjectACL -ResolveGUIDs -Identity * |
Where-Object {$_.SecurityIdentifier -eq $sid}
```

Por ejemplo, el GUID:

```
00299570-246d-11d0-a768-00aa006e0529
```

corresponde a:

```
User-Force-Change-Password
```

Este derecho permite forzar el cambio de contraseña del objeto afectado sin conocer su contraseña actual.

### Convertir manualmente un GUID

Si no disponemos de `-ResolveGUIDs`, podemos utilizar el módulo de Active Directory:

```
$guid = "00299570-246d-11d0-a768-00aa006e0529"

Get-ADObject `
    -SearchBase "CN=Extended-Rights,$((Get-ADRootDSE).ConfigurationNamingContext)" `
    -Filter {ObjectClass -like 'ControlAccessRight'} `
    -Properties * |
Select-Object Name, DisplayName, DistinguishedName, rightsGuid |
Where-Object {$_.rightsGuid -eq $guid} |
Format-List
```

Resultado relevante:

```
Name        : User-Force-Change-Password
DisplayName : Reset Password
```

## 2. Enumeración alternativa con herramientas nativas

Si PowerView no está disponible, podemos consultar las ACL con los cmdlets integrados de PowerShell y el módulo de Active Directory.

### Exportar los usuarios del dominio

```
Get-ADUser -Filter * |
Select-Object -ExpandProperty SamAccountName > ad_users.txt
```

### Buscar permisos de un usuario concreto

```
foreach ($line in [System.IO.File]::ReadLines("C:\Users\htb-student\Desktop\ad_users.txt")) {
    Get-Acl "AD:\$(Get-ADUser $line)" |
    Select-Object -ExpandProperty Access |
    Where-Object {$_.IdentityReference -match 'INLANEFREIGHT\\wley'}
}
```

Cambia la ruta del archivo y la identidad por los valores de tu entorno.

La propiedad `Access` contiene las entradas de acceso de cada objeto. Entre los campos importantes están:

- `ActiveDirectoryRights`: permisos concedidos.
    
- `ObjectType`: GUID del derecho u objeto afectado.
    
- `IdentityReference`: usuario o grupo al que se concede el permiso.
    
- `AccessControlType`: indica si la ACE permite o deniega el acceso.
    
- `IsInherited`: indica si el permiso se hereda.
    

**Limitación:** este método es más lento porque consulta las ACL de los usuarios individualmente.

## 3. Seguir la cadena de permisos

El objetivo no es limitarse a encontrar una ACE interesante: hay que comprobar qué otros objetos permite controlar y qué privilegios se pueden obtener mediante grupos anidados.

### Paso 1. Buscar los permisos de `wley`

```
$sid = Convert-NameToSid wley

Get-DomainObjectACL -ResolveGUIDs -Identity * |
Where-Object {$_.SecurityIdentifier -eq $sid}
```

En el ejemplo del módulo, `wley` tiene el derecho `User-Force-Change-Password` sobre `damundsen`.

### Paso 2. Enumerar los permisos de `damundsen`

```
$sid2 = Convert-NameToSid damundsen

Get-DomainObjectACL -ResolveGUIDs -Identity * |
Where-Object {$_.SecurityIdentifier -eq $sid2} -Verbose
```

Se encuentra una ACE que concede `GenericWrite` sobre el grupo `Help Desk Level 1`.

Este permiso permite modificar determinados atributos del objeto. En el escenario del módulo, se aprovecha para modificar la pertenencia al grupo.

### Paso 3. Investigar los grupos anidados

```
Get-DomainGroup -Identity "Help Desk Level 1" |
Select-Object memberof
```

Resultado del ejemplo:

```
CN=Information Technology,OU=Security Groups,OU=Corp,DC=INLANEFREIGHT,DC=LOCAL
```

`Help Desk Level 1` pertenece a `Information Technology`.

Por tanto, los miembros del primer grupo pueden beneficiarse de los permisos que correspondan a la pertenencia al segundo grupo.

### Paso 4. Enumerar los permisos de `Information Technology`

```
$itgroupsid = Convert-NameToSid "Information Technology"

Get-DomainObjectACL -ResolveGUIDs -Identity * |
Where-Object {$_.SecurityIdentifier -eq $itgroupsid} -Verbose
```

En el ejemplo se descubre que `Information Technology` tiene `GenericAll` sobre el usuario `adunn`.

`GenericAll` representa un control amplio sobre el objeto afectado. Dependiendo del tipo de objeto y de los permisos efectivos, puede permitir acciones como modificar atributos, cambiar contraseñas o alterar la pertenencia a grupos.

### Paso 5. Enumerar los permisos de `adunn`

```
$adunnsid = Convert-NameToSid adunn

Get-DomainObjectACL -ResolveGUIDs -Identity * |
Where-Object {$_.SecurityIdentifier -eq $adunnsid} -Verbose
```

En el escenario del módulo, `adunn` tiene estos derechos extendidos sobre el dominio:

```
DS-Replication-Get-Changes
DS-Replication-Get-Changes-In-Filtered-Set
```

Estos permisos forman parte de los derechos relacionados con la replicación de Active Directory. El módulo identifica que `adunn` puede aprovecharlos para realizar un ataque DCSync, que se estudiará en su sección correspondiente.

## 4. Cadena de ataque del laboratorio

La ruta de ataque identificada en el módulo es:

```
wley
  |
  | ForceChangePassword
  v
damundsen
  |
  | GenericWrite sobre el grupo
  v
Help Desk Level 1
  |
  | Pertenencia a grupo anidado
  v
Information Technology
  |
  | GenericAll
  v
adunn
  |
  | DS-Replication-Get-Changes
  | DS-Replication-Get-Changes-In-Filtered-Set
  v
Posible ataque DCSync
```

### Resumen de cada salto

|Principal controlado|Permiso o relación|Objetivo|
|---|---|---|
|`wley`|`ForceChangePassword`|Obtener control sobre `damundsen` mediante el cambio de contraseña.|
|`damundsen`|`GenericWrite` sobre `Help Desk Level 1`|Modificar la pertenencia al grupo en el escenario descrito.|
|`Help Desk Level 1`|Miembro de `Information Technology`|Identificar los privilegios derivados del grupo anidado.|
|`Information Technology`|`GenericAll` sobre `adunn`|Obtener control sobre el objeto de `adunn`.|
|`adunn`|Derechos de replicación del dominio|Investigar la posibilidad de realizar DCSync.|

**Clave:** después de cada salto, vuelve a enumerar las ACL utilizando el SID del nuevo usuario o grupo. El control de una cuenta puede abrir nuevas rutas que no eran visibles desde la cuenta inicial.

## 5. Enumeración de ACL con BloodHound

BloodHound permite representar gráficamente los permisos y las rutas de ataque identificadas a partir de los datos recopilados por SharpHound.

### Investigar el usuario inicial

1. Ingiere los datos del dominio con SharpHound y cárgalos en BloodHound.
    
2. Busca `WLEY@INLANEFREIGHT.LOCAL`.
    
3. Abre la pestaña **Node Info**.
    
4. Localiza **Outbound Control Rights**.
    
5. Revisa:
    
    - **First Degree Object Control**: objetos controlados directamente.
        
    - **Transitive Object Control**: objetos que se pueden alcanzar mediante una cadena de relaciones y permisos.
        
6. Haz clic en el número de objetos del control directo para revisar las ACE encontradas.
    

En el ejemplo del módulo, la primera relación interesante es:

```
WLEY --ForceChangePassword--> DAMUNDSEN
```

### Consultar cómo abusar de una ACE

Haz clic derecho sobre la relación entre los nodos y selecciona **Help**.

La ayuda puede incluir:

- Descripción del permiso.
    
- Herramientas y comandos relevantes.
    
- Consideraciones de seguridad operacional (OpSec).
    
- Referencias externas.
    

### Encontrar rutas de ataque

Revisa las relaciones transitivas para visualizar la cadena completa de permisos y grupos anidados.

También puedes utilizar las consultas predefinidas de BloodHound para identificar permisos de replicación asociados a DCSync.

**Importante:** una ruta gráfica indica una posibilidad de acceso basada en los datos recopilados; hay que validar los permisos efectivos, las condiciones del entorno y los posibles cambios desde la última recopilación.

## 6. Checklist práctico de enumeración

Cuando consigas controlar un usuario en un dominio, sigue este orden:

1. **Obtener el SID del usuario:**
    
    ```
    $sid = Convert-NameToSid <usuario>
    ```
    
2. **Enumerar las ACL dirigidas a ese SID:**
    
    ```
    Get-DomainObjectACL -ResolveGUIDs -Identity * |
    Where-Object {$_.SecurityIdentifier -eq $sid}
    ```
    
3. **Identificar las ACE interesantes**, especialmente:
    
    - `ForceChangePassword`
        
    - `GenericAll`
        
    - `GenericWrite`
        
    - `WriteDACL`
        
    - `WriteOwner`
        
    - `Add Members`
        
    - Derechos de replicación del dominio.
        
4. **Identificar el objeto afectado** mediante `ObjectDN`.
    
5. **Interpretar el permiso** y comprobar qué operaciones permite sobre ese tipo de objeto.
    
6. **Investigar los grupos relacionados** y sus relaciones de anidamiento:
    
    ```
    Get-DomainGroup -Identity "<grupo>" | Select-Object memberof
    ```
    
7. **Repetir la enumeración** usando el SID de cada nuevo usuario o grupo relevante.
    
8. **Contrastar los resultados con BloodHound** para localizar rutas de ataque directas y transitivas.
    
9. **Validar los privilegios efectivos** antes de intentar aprovecharlos.

## 7. Conceptos que debes recordar

- **SID:** identifica al usuario o grupo cuyos permisos queremos rastrear.
    
- `**Get-DomainObjectACL**`**:** permite enumerar las ACE de los objetos del dominio.
    
- `**-ResolveGUIDs**`**:** convierte los GUID de las ACE en nombres legibles.
    
- `**Find-InterestingDomainAcl**`**:** busca ACL potencialmente interesantes, pero puede producir demasiados resultados.
    
- `**GenericWrite**`**:** permite modificar determinados atributos del objeto afectado; su impacto depende del objeto y de los atributos modificables.
    
- `**GenericAll**`**:** concede un control amplio sobre el objeto afectado.
    
- **Grupos anidados:** pueden proporcionar privilegios indirectos a través de otros grupos.
    
- **BloodHound:** facilita visualizar relaciones, permisos y rutas de ataque transitivas.
    
- **DCSync:** utiliza derechos de replicación de Active Directory para solicitar información de credenciales; requiere los permisos apropiados.
    
- **Enumeración dirigida:** resulta más eficiente que revisar indiscriminadamente todas las ACL del dominio.
