
## 1. ¿Qué son las ACL?

Las **Access Control Lists (ACL)** determinan quién puede acceder a un objeto de Active Directory y qué acciones puede realizar sobre él.

Cada objeto de AD tiene una ACL, que puede contener múltiples **Access Control Entries (ACE)**.

- **ACL:** lista de permisos asociados a un objeto.
    
- **ACE:** entrada individual que especifica los permisos de una entidad de seguridad.
    
- **Security Principal:** usuario, grupo o equipo al que se le asignan permisos.
    
- **SID:** identificador de seguridad de un usuario o grupo.
    
- **Access Mask:** conjunto de derechos de acceso otorgados por una ACE.
    

Una ACL mal configurada puede permitir que un usuario de bajos privilegios controle cuentas, modifique grupos o escale privilegios dentro del dominio.

### Tipos de ACL

|Tipo|Descripción|
|---|---|
|**DACL (Discretionary ACL)**|Define quién puede acceder al objeto y qué permisos tiene. Contiene ACE que permiten o deniegan el acceso.|
|**SACL (System ACL)**|Define qué accesos deben generar eventos de auditoría.|

Si un objeto no tiene DACL, el sistema permite el acceso sin restricciones de DACL. Si existe una DACL vacía, se deniega el acceso mediante esa DACL.

### Tipos de ACE

|ACE|Función|
|---|---|
|**Access Denied**|Deniega explícitamente determinados permisos.|
|**Access Allowed**|Concede explícitamente determinados permisos.|
|**System Audit**|Registra los intentos de acceso definidos en la SACL.|

Una ACE incluye:

1. El SID de la entidad de seguridad.
    
2. El tipo de ACE.
    
3. Los indicadores de herencia.
    
4. La máscara de acceso con los derechos concedidos o denegados.
    

**Importante:** los permisos pueden heredarse de objetos superiores. Al analizar una ACL, hay que comprobar el objeto afectado, la herencia y los derechos efectivos; no basta con mirar el nombre del permiso.

---

## 2. ¿Por qué son importantes las ACL en pentesting?

Una ACL mal configurada puede conceder a un usuario permisos que no debería tener.

Esto puede permitir:

- **Escalada de privilegios:** obtener control sobre cuentas o grupos privilegiados.
    
- **Movimiento lateral:** conseguir acceso a otros sistemas o cuentas.
    
- **Persistencia:** modificar permisos para conservar el acceso.
    

Herramientas como **BloodHound** y **PowerView** permiten identificar relaciones de control entre usuarios, grupos y otros objetos de Active Directory.

## 3. Permisos ACE importantes

Estos son los permisos que debes reconocer al analizar las relaciones de BloodHound.

|Permiso|Capacidad|Posible abuso|
|---|---|---|
|`ForceChangePassword`|Restablecer la contraseña de otro usuario sin conocer la actual.|Cambiar la contraseña de una cuenta objetivo.|
|`GenericWrite`|Modificar atributos no protegidos del objeto.|Modificar atributos de usuario, añadir un SPN o modificar la membresía de un grupo cuando los permisos concretos lo permiten.|
|`GenericAll`|Control total sobre el objeto objetivo, sujeto a las restricciones aplicables.|Controlar una cuenta o grupo, cambiar contraseñas o modificar membresías.|
|`AddSelf`|Permite que una entidad se agregue a determinados grupos.|Añadirse a un grupo vulnerable.|
|`AddMember`|Permite añadir miembros a un grupo.|Agregar una cuenta controlada a un grupo privilegiado.|
|`WriteOwner`|Cambiar el propietario del objeto.|Tomar la propiedad y, si se consigue el permiso adecuado sobre la DACL, ampliar el control.|
|`WriteDACL`|Modificar la DACL del objeto.|Concederse permisos adicionales sobre el objeto.|
|`AllExtendedRights`|Conjunto de derechos extendidos sobre el objeto.|Puede permitir operaciones como restablecer contraseñas o modificar membresías, según los derechos efectivos.|

**No todos los permisos tienen el mismo efecto sobre cualquier objeto.** Su impacto depende de si el objetivo es un usuario, grupo, equipo u otro objeto de AD, así como de las restricciones y permisos efectivos.

## 4. Enumeración de ACL con PowerView

PowerView permite consultar objetos de Active Directory y analizar sus permisos.

### 4.1. Consultar las ACL de un usuario

```
Get-DomainObjectAcl -Identity forend -ResolveGUIDs
```

- `-Identity forend`: especifica el objeto que queremos analizar.
    
- `-ResolveGUIDs`: intenta mostrar los nombres asociados a los GUID de los derechos y propiedades.
    

Busca permisos como `GenericAll`, `GenericWrite`, `WriteDACL`, `WriteOwner` y `ForceChangePassword`.

### 4.2. Consultar las ACL de un dominio

```
Get-DomainObjectAcl -SearchBase "DC=inlanefreight,DC=local" -ResolveGUIDs
```

La salida puede ser extensa. Conviene filtrar los resultados por el objeto o la entidad de seguridad que te interesa.

> El DN debe adaptarse al dominio del laboratorio.

### 4.3. Identificar al propietario de un objeto

```
Get-DomainObject -Identity forend
```

Esta consulta permite inspeccionar las propiedades del objeto. Comprueba la propiedad `nTSecurityDescriptor` o la información de propietario que exponga la versión de PowerView utilizada.

### 4.4. Buscar los miembros de un grupo

```
Get-DomainGroupMember -Identity "Domain Admins"
```

Permite consultar los miembros del grupo especificado. Cambia el nombre por el grupo que estés investigando.

### 4.5. Analizar los permisos desde BloodHound

Flujo de trabajo:

1. Importar los datos de enumeración del dominio.
    
2. Buscar el usuario o grupo que controlas.
    
3. Examinar sus relaciones de salida.
    
4. Identificar permisos sobre usuarios, grupos o equipos.
    
5. Seguir la ruta hasta un objetivo de mayor privilegio.
    
6. Validar el permiso concreto antes de intentar abusar de él.
    

Los nombres de las relaciones de BloodHound representan derechos o capacidades potenciales. Debes comprobar el objeto objetivo y las condiciones necesarias antes de asumir que una ruta es explotable.

## 5. Abuso de `ForceChangePassword`

Este permiso permite restablecer la contraseña de un usuario sin conocer su contraseña actual.

### Ejemplo con PowerView

```
$Password = ConvertTo-SecureString 'NuevaPassword123!' -AsPlainText -Force
Set-DomainUserPassword -Identity targetuser -AccountPassword $Password
```

- `targetuser`: usuario sobre el que tienes el permiso.
    
- `$Password`: nueva contraseña que se establecerá.
    

**Impacto:** si la cuenta objetivo tiene privilegios superiores, conseguir acceso a ella puede permitir escalar privilegios o realizar movimiento lateral.

**Precaución:** cambiar una contraseña puede interrumpir servicios y alertar a los administradores. En una evaluación autorizada, confirma el alcance y documenta el cambio.

---

## 6. Abuso de `GenericWrite`

`GenericWrite` permite escribir en atributos no protegidos de un objeto.

Su impacto depende del tipo de objeto y de los atributos que puedan modificarse.

### Posibles escenarios

- **Usuario:** modificar atributos y, si se puede escribir el atributo correspondiente, asignar un SPN para intentar un ataque de Kerberoasting.
    
- **Grupo:** modificar atributos o la membresía cuando los derechos efectivos permiten esa operación.
    
- **Equipo:** puede formar parte de escenarios de abuso de delegación restringida basada en recursos, si se cumplen los requisitos correspondientes.
    

### Inspeccionar un objeto

```
Get-DomainObject -Identity targetuser
```

Antes de modificarlo, identifica qué atributo puedes cambiar y qué efecto tendría ese cambio.

---

## 7. Abuso de `AddSelf` y de permisos sobre grupos

`AddSelf` indica que una entidad puede agregarse a sí misma a determinados grupos.

Otros permisos, como `AddMember` o `GenericAll` sobre un grupo, también pueden permitir modificar su membresía.

### Enumerar los miembros de un grupo

```
Get-DomainGroupMember -Identity "Target Group"
```

### Intentar añadir un usuario a un grupo

Cuando los permisos efectivos permiten modificar la membresía, PowerView dispone de:

```
Add-DomainGroupMember -Identity "Target Group" -Members "controlleduser"
```

- `Target Group`: grupo objetivo.
    
- `controlleduser`: cuenta que quieres añadir.
    

**Impacto:** si el grupo concede privilegios relevantes, modificar su membresía puede permitir escalada de privilegios.

No presupongas que tener `AddSelf` equivale a poder agregar cualquier usuario: revisa la relación y el derecho exacto identificado en BloodHound.

---

## 8. Abuso de `GenericAll`

`GenericAll` representa control total sobre el objeto objetivo dentro de los límites de los controles y restricciones aplicables.

### Si el objetivo es un usuario

Puede permitir operaciones como restablecer su contraseña o modificar atributos relevantes.

```
$Password = ConvertTo-SecureString 'NuevaPassword123!' -AsPlainText -Force
Set-DomainUserPassword -Identity targetuser -AccountPassword $Password
```

### Si el objetivo es un grupo

Puede permitir modificar su membresía:

```
Add-DomainGroupMember -Identity "Target Group" -Members "controlleduser"
```

### Si el objetivo es un equipo

Si el entorno utiliza LAPS y tu cuenta tiene los derechos necesarios para leer el atributo que contiene la contraseña administrada, podría ser posible obtener la contraseña de administrador local del equipo.

**Idea clave:** el permiso es el mismo, pero el abuso depende del tipo de objeto controlado.

---

## 9. Otros permisos relevantes

### `WriteOwner`

Permite cambiar el propietario de un objeto. Obtener la propiedad puede facilitar la modificación de su DACL, pero no debes asumir que equivale automáticamente a tener control total.

### `WriteDACL`

Permite modificar la DACL del objeto. Si puedes cambiarla, podrías conceder a una entidad permisos adicionales.

El flujo conceptual es:

1. Identificar el objeto sobre el que tienes `WriteDACL`.
    
2. Comprobar la ACE y los derechos efectivos.
    
3. Determinar qué permiso adicional sería útil.
    
4. Modificar la ACL únicamente si está autorizado.
    
5. Validar el acceso obtenido.
    
6. Revertir los cambios al finalizar.
    

### `AllExtendedRights`

Representa derechos extendidos sobre el objeto. No significa que todas las operaciones posibles estén permitidas en cualquier contexto: hay que identificar el derecho concreto y el objeto afectado.

## 10. Otros casos de abuso de ACL

### Leer la contraseña de una gMSA

Si BloodHound muestra una relación `ReadGMSAPassword`, puede existir una vía para recuperar la contraseña de una **Group Managed Service Account (gMSA)**.

Herramientas como `GMSAPasswordReader` pueden ayudar a leer la contraseña cuando se dispone de los permisos necesarios.

### Derechos extendidos menos comunes

También pueden aparecer derechos como:

- `Unexpire-Password`
    
- `Reanimate-Tombstones`
    
- `ReadGMSAPassword`
    

No todos tienen el mismo impacto. Es necesario investigar qué operación permiten y cuáles son sus requisitos.

## 11. Metodología práctica para analizar ACL

Cuando encuentres una relación sospechosa en BloodHound:

1. **Identifica tu punto de partida:** usuario o grupo que controlas.
    
2. **Busca relaciones de control:** examina las ACE y las rutas relevantes.
    
3. **Identifica el objeto objetivo:** usuario, grupo, equipo u otro objeto.
    
4. **Interpreta el permiso:** determina qué operación permite realmente.
    
5. **Comprueba los requisitos:** atributos modificables, permisos efectivos, privilegios del objetivo y posibles restricciones.
    
6. **Elige el abuso adecuado:** contraseña, membresía, atributos, DACL u otra vía.
    
7. **Valida el resultado:** comprueba si el cambio produjo el acceso esperado.
    
8. **Documenta y revierte:** registra las modificaciones y restaura el estado inicial cuando corresponda.
    

### Escenarios habituales

|Escenario|Objetivo|
|---|---|
|Permisos de restablecimiento de contraseña|Obtener acceso a una cuenta más privilegiada.|
|Gestión de membresía de grupos|Añadir una cuenta controlada a un grupo relevante.|
|Derechos excesivos sobre usuarios, grupos o equipos|Identificar y aprovechar una relación de control no prevista.|

---

## 12. Consideraciones de seguridad

Los ataques a ACL pueden ser destructivos. Cambiar contraseñas, alterar grupos o modificar DACL puede afectar a usuarios y servicios.

Durante un pentest autorizado:

- Confirma que la operación está dentro del alcance.
    
- Obtén aprobación para cambios potencialmente disruptivos.
    
- Documenta el estado inicial y cada modificación.
    
- Verifica que los cambios se han revertido correctamente.
    
- Incluye los hallazgos y su impacto en el informe.

## 13. Chuleta rápida

|Permiso|¿Qué buscar?|Posible acción|
|---|---|---|
|`ForceChangePassword`|Usuario objetivo|Restablecer su contraseña.|
|`GenericWrite`|Usuario, grupo o equipo|Modificar atributos permitidos.|
|`GenericAll`|Usuario o grupo|Controlar el objeto según sus derechos efectivos.|
|`AddSelf`|Grupo objetivo|Agregarse al grupo cuando la relación lo permite.|
|`AddMember`|Grupo objetivo|Añadir una cuenta al grupo.|
|`WriteOwner`|Objeto objetivo|Cambiar su propietario.|
|`WriteDACL`|Objeto objetivo|Modificar sus permisos.|
|`AllExtendedRights`|Objeto y derecho concreto|Investigar las operaciones que permite.|
|`ReadGMSAPassword`|Cuenta gMSA|Comprobar si puedes leer su contraseña.|

### Comandos que conviene recordar

```
# Consultar las ACL de un usuario
Get-DomainObjectAcl -Identity forend -ResolveGUIDs

# Inspeccionar un objeto
Get-DomainObject -Identity targetuser

# Consultar miembros de un grupo
Get-DomainGroupMember -Identity "Domain Admins"

# Restablecer la contraseña cuando tienes el permiso necesario
$Password = ConvertTo-SecureString 'NuevaPassword123!' -AsPlainText -Force
Set-DomainUserPassword -Identity targetuser -AccountPassword $Password

# Añadir un miembro cuando tienes los permisos necesarios
Add-DomainGroupMember -Identity "Target Group" -Members "controlleduser"
```

**Concepto fundamental:** una ACL no es solo una lista de permisos. Es un mapa de relaciones de control entre objetos de Active Directory. Para detectar una posible escalada, identifica quién controla qué objeto, qué derecho tiene y qué consecuencias tendría ejercerlo.
