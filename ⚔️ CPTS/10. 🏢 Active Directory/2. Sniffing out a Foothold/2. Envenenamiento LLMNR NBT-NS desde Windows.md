
## 1. Objetivo

Realizar ataques de envenenamiento LLMNR/NBT-NS desde un host Windows utilizando **Inveigh** para capturar hashes de autenticación y obtener posibles credenciales válidas del dominio.

Inveigh funciona de forma similar a Responder, pero dispone de implementaciones en PowerShell y C#.

El flujo de trabajo es:

1. Ejecutar Inveigh desde Windows.
    
2. Habilitar la suplantación de solicitudes LLMNR/NBT-NS.
    
3. Capturar hashes NetNTLMv1/NetNTLMv2.
    
4. Consultar los usuarios y hashes recopilados.
    
5. Intentar descifrar los hashes offline con herramientas como Hashcat.
    
6. Utilizar las credenciales recuperadas para continuar la enumeración del dominio.
    

---

## 2. Inveigh: descripción general

Inveigh permite realizar ataques de suplantación y envenenamiento desde un host Windows.

Entre los protocolos que puede manejar se encuentran:

- LLMNR
    
- DNS
    
- mDNS
    
- NBNS
    
- DHCPv6
    
- ICMPv6
    
- HTTP
    
- HTTPS
    
- SMB
    
- LDAP
    
- WebDAV
    
- Proxy Auth
    

Existen dos implementaciones principales:

|Versión|Características|
|---|---|
|PowerShell|Implementación original; ya no se actualiza.|
|C# (InveighZero)|Implementación mantenida por el autor de la herramienta.|

En el laboratorio de HTB Academy, los archivos están disponibles en `C:\Tools`.

## 3. Inveigh mediante PowerShell

### 3.1. Importar el módulo

Desde PowerShell:

```
Import-Module .\Inveigh.ps1
```

### 3.2. Consultar los parámetros disponibles

```
(Get-Command Invoke-Inveigh).Parameters
```

Este comando muestra los parámetros que admite `Invoke-Inveigh`, lo que permite consultar sus opciones antes de ejecutar la herramienta.

### 3.3. Iniciar Inveigh

Comando utilizado en el módulo:

```
Invoke-Inveigh Y -NBNS Y -ConsoleOutput Y -FileOutput Y
```

Parámetros importantes:

|Parámetro|Función|
|---|---|
|`Y`|Habilita la suplantación LLMNR en la versión mostrada en el módulo.|
|`-NBNS Y`|Habilita la suplantación NBNS.|
|`-ConsoleOutput Y`|Muestra la salida en la consola.|
|`-FileOutput Y`|Guarda la salida en archivos.|

La salida de ejemplo indica que Inveigh habilita la suplantación LLMNR y NBNS, además de la captura SMB y HTTP.

**Importante:** esta sintaxis corresponde a la versión de PowerShell mostrada en el material. Los parámetros pueden variar entre versiones.

### 3.4. Interpretar la salida

Durante la ejecución pueden aparecer mensajes como:

```
LLMNR request for academy-ea-web0 received from 172.16.5.125 [response sent]
```

Esto indica que:

- Se recibió una solicitud LLMNR para `academy-ea-web0`.
    
- La solicitud procedía de `172.16.5.125`.
    
- Inveigh envió una respuesta.
    

También pueden aparecer mensajes relacionados con SMB:

```
SMB(445) negotiation request detected
SMB(445) NTLM challenge sent
```

Estos mensajes indican actividad de negociación SMB y el envío de un desafío NTLM. Por sí solos, no garantizan que se haya capturado un hash completo.

## 4. Errores al iniciar los servicios

En los ejemplos del módulo aparece el siguiente error:

```
Error starting HTTP listener
An attempt was made to access a socket in a way forbidden by its access permissions
```

También puede aparecer:

```
Failed to start HTTP listener on port 80, check IP and port usage.
```

Esto indica que Inveigh no pudo iniciar el listener HTTP en el puerto correspondiente.

Una posible causa es que otro proceso esté utilizando el puerto o que existan restricciones de acceso al socket.

**Punto importante:** que falle el listener HTTP no significa necesariamente que toda la herramienta haya dejado de funcionar. En el ejemplo, Inveigh sigue recibiendo solicitudes LLMNR y enviando respuestas.

## 5. Inveigh en C#: InveighZero

La versión de C# es la implementación mantenida de la herramienta.

En el laboratorio, el ejecutable compilado se encuentra en `C:\Tools`.

### 5.1. Ejecutar el binario

Desde PowerShell:

```
.\Inveigh.exe
```

Inveigh muestra el estado de sus diferentes módulos.

Ejemplo:

```
[+] LLMNR Packet Sniffer
[+] HTTP Listener
[+] LDAP Listener
[+] SMB Packet Sniffer
[ ] DHCPv6
[ ] ICMPv6
[ ] MDNS
[ ] NBNS
```

Interpretación:

- `[+]`: opción habilitada.
    
- `[ ]`: opción deshabilitada.
    
- Los mensajes de actividad indican qué solicitudes está observando la herramienta y si ha enviado respuestas.
    

**Importante:** los protocolos habilitados dependen de la versión y de la configuración. No hay que asumir que todos están activos por defecto.

### 5.2. Consola interactiva

Mientras Inveigh se ejecuta, podemos pulsar:

```
ESC
```

Esto permite entrar o salir de la consola interactiva.

Desde ella podemos consultar hashes capturados, filtrar registros, revisar usuarios, obtener credenciales en texto plano cuando existan y detener la herramienta.

---

## 6. Comandos de la consola interactiva

Después de entrar en la consola, podemos consultar los comandos disponibles:

```
HELP
```

Los comandos más importantes son:

|Comando|Función|
|---|---|
|`GET CONSOLE`|Consulta la salida de consola almacenada en la cola.|
|`GET LOG`|Muestra entradas del registro; admite una cadena de búsqueda.|
|`GET NTLMV1`|Consulta hashes NTLMv1 capturados.|
|`GET NTLMV2`|Consulta hashes NTLMv2 capturados.|
|`GET NTLMV1UNIQUE`|Muestra hashes NTLMv1 únicos por usuario.|
|`GET NTLMV2UNIQUE`|Muestra hashes NTLMv2 únicos por usuario.|
|`GET NTLMV1USERNAMES`|Muestra usuarios y datos de origen asociados a capturas NTLMv1.|
|`GET NTLMV2USERNAMES`|Muestra usuarios y datos de origen asociados a capturas NTLMv2.|
|`GET CLEARTEXT`|Consulta las credenciales en texto plano capturadas.|
|`GET CLEARTEXTUNIQUE`|Consulta las credenciales únicas en texto plano.|
|`HISTORY`|Muestra el historial de comandos.|
|`RESUME`|Reanuda la salida de consola en tiempo real.|
|`STOP`|Detiene Inveigh.|

### 6.1. Consultar hashes NTLMv2 únicos

```
GET NTLMV2UNIQUE
```

Permite visualizar los hashes NTLMv2 capturados sin mostrar múltiples copias de un mismo hash por usuario.

### 6.2. Consultar los usuarios capturados

```
GET NTLMV2USERNAMES
```

El resultado puede incluir:

- Dirección IP de origen.
    
- Nombre del host.
    
- Nombre de usuario.
    
- Desafío asociado a la autenticación.
    

Ejemplo del formato de salida:

```
Dirección IP   | Host             | Nombre de usuario          | Desafío
172.16.5.125   | ACADEMY-EA-FILE   | INLANEFREIGHT\backupagent   | ...
172.16.5.125   | ACADEMY-EA-FILE   | INLANEFREIGHT\forend        | ...
```

Esta información permite identificar qué cuentas han generado material de autenticación y decidir cuáles merece la pena investigar.

## 7. ¿Qué hacer con los hashes capturados?

Una vez recopilados los hashes, el siguiente paso es intentar recuperar las contraseñas offline.

El proceso es similar al utilizado con Responder desde Linux:

1. Consultar los hashes capturados.
    
2. Identificar el tipo de hash.
    
3. Guardar el material de autenticación en el formato requerido por la herramienta.
    
4. Seleccionar el modo de Hashcat adecuado.
    
5. Probar un diccionario u otra estrategia de cracking.
    
6. Validar las credenciales recuperadas en el entorno autorizado.
    

Para NetNTLMv2, el modo de Hashcat utilizado en la sección anterior es:

```
5600
```

No debemos confundir un hash NetNTLMv2 con un hash NT: son materiales de autenticación diferentes y no se utilizan de la misma manera.

Capturar un hash tampoco significa que se haya recuperado la contraseña.

## 8. Mitigación

La técnica está identificada por MITRE ATT&CK como:

**T1557.001 — Adversary-in-the-Middle: LLMNR/NBT-NS Poisoning and SMB Relay.**

Las medidas principales de mitigación son las siguientes.

### 8.1. Deshabilitar LLMNR mediante GPO

Ruta de directiva:

```
Configuración del equipo
└── Plantillas administrativas
    └── Red
        └── Cliente DNS
            └── Desactivar la resolución de nombres de multidifusión
```

Habilitar la directiva **Desactivar la resolución de nombres de multidifusión** para deshabilitar LLMNR.

Antes de aplicar el cambio a toda la organización, conviene probarlo para detectar posibles dependencias de resolución de nombres.

### 8.2. Deshabilitar NBT-NS

El material indica que NBT-NS no se deshabilita directamente mediante una GPO estándar de la misma manera que LLMNR.

Puede deshabilitarse localmente desde la configuración de red:

1. Abrir el Centro de redes y recursos compartidos.
    
2. Seleccionar Cambiar configuración del adaptador.
    
3. Abrir las propiedades del adaptador.
    
4. Seleccionar Protocolo de Internet versión 4 (TCP/IPv4).
    
5. Entrar en Propiedades y después en Avanzadas.
    
6. Abrir la pestaña WINS.
    
7. Seleccionar Deshabilitar NetBIOS sobre TCP/IP.
    

### 8.3. Deshabilitar NBT-NS mediante PowerShell

El módulo propone el siguiente script:

```
$regkey = "HKLM:SYSTEM\CurrentControlSet\services\NetBT\Parameters\Interfaces"

Get-ChildItem $regkey | ForEach-Object {
    Set-ItemProperty `
        -Path "$regkey\$($_.PSChildName)" `
        -Name NetbiosOptions `
        -Value 2 `
        -Verbose
}
```

El script recorre las interfaces de NetBIOS y establece `NetbiosOptions` en `2`, valor asociado a la desactivación de NetBIOS sobre TCP/IP.

Debe ejecutarse con los privilegios necesarios y probarse antes de distribuirlo a todos los equipos.

Para aplicarlo mediante GPO:

1. Crear o editar una directiva de grupo.
    
2. Acceder a Configuración del equipo.
    
3. Abrir Configuración de Windows.
    
4. Entrar en Scripts (Inicio o apagado).
    
5. Configurar el script en Inicio.
    
6. Distribuirlo a las unidades organizativas correspondientes.
    
7. Reiniciar los equipos o los adaptadores afectados cuando proceda.
    

El script puede almacenarse en SYSVOL para distribuirlo desde un controlador de dominio.

Ejemplo de ruta UNC del módulo:

```
\\inlanefreight.local\SYSVOL\INLANEFREIGHT.LOCAL\scripts
```

### 8.4. Otras medidas

- Filtrar el tráfico LLMNR y NetBIOS cuando sea viable.
    
- Habilitar SMB Signing para dificultar los ataques de retransmisión SMB/NTLM.
    
- Utilizar sistemas de detección y prevención de intrusiones.
    
- Segmentar la red para aislar los equipos que necesiten mantener estos protocolos.
    
- Probar los cambios antes de aplicarlos a toda la organización.

## 9. Detección

Si no es posible deshabilitar completamente LLMNR y NetBIOS, es importante detectar comportamientos sospechosos.

### 9.1. Monitorizar el tráfico

El módulo recomienda observar el tráfico relacionado con:

|Puerto|Protocolo|
|---|---|
|UDP 5355|LLMNR|
|UDP 137|NBT-NS|

Una cantidad o un patrón de respuestas inesperadas a solicitudes de nombres inexistentes puede indicar actividad de suplantación.

### 9.2. Generar solicitudes señuelo

Una técnica defensiva consiste en generar solicitudes LLMNR/NBT-NS para hosts inexistentes y alertar si algún sistema responde.

La respuesta puede indicar que un equipo está intentando suplantar el mecanismo legítimo de resolución de nombres.

Esta técnica debe implementarse de forma controlada para evitar falsos positivos o interferencias en la red.

### 9.3. Monitorizar eventos de Windows

El material menciona los siguientes identificadores:

```
4697
7045
```

Pueden utilizarse como parte de la supervisión de eventos relacionados con la instalación de servicios, aunque no son indicadores exclusivos de envenenamiento LLMNR/NBT-NS.

### 9.4. Monitorizar el registro de Windows

Clave indicada en el módulo:

```
HKLM\Software\Policies\Microsoft\Windows NT\DNSClient
```

Valor:

```
EnableMulticast
```

Un valor DWORD de `0` indica que LLMNR está deshabilitado mediante esta configuración.

## 12. Puntos clave para el examen

- Inveigh permite estudiar el envenenamiento LLMNR/NBT-NS desde Windows.
    
- La versión original de PowerShell está obsoleta; el autor mantiene la implementación en C#.
    
- `Invoke-Inveigh` se utiliza con la versión PowerShell y `Inveigh.exe` con la versión C#.
    
- `GET NTLMV2UNIQUE` muestra hashes NTLMv2 únicos.
    
- `GET NTLMV2USERNAMES` permite identificar los usuarios asociados a las capturas.
    
- Pulsar `ESC` permite acceder a la consola interactiva de Inveigh.
    
- `STOP` detiene la herramienta.
    
- LLMNR puede deshabilitarse mediante una GPO.
    
- NBT-NS puede deshabilitarse desde la configuración de red o mediante un script de PowerShell distribuido por GPO.
    
- SMB Signing ayuda a mitigar ataques de retransmisión SMB/NTLM.
    
- La detección puede apoyarse en la monitorización de tráfico, solicitudes señuelo, eventos de Windows y cambios en el registro.
    
- Tras obtener hashes, conviene determinar si las cuentas capturadas pueden ayudar a avanzar en la evaluación antes de dedicar tiempo al cracking.
    
- Si el cracking no proporciona credenciales útiles, el módulo continúa con técnicas de enumeración y password spraying.
