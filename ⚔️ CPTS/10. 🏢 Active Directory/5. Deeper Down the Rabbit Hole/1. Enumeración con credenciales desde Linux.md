
## 1. Objetivo

Una vez obtenidas credenciales válidas de un usuario de dominio, podemos realizar una enumeración más profunda de Active Directory.

Nos interesa recopilar información sobre:

- Usuarios y atributos.
    
- Grupos y pertenencias.
    
- Equipos del dominio.
    
- Sesiones de usuarios.
    
- Recursos compartidos SMB.
    
- Permisos y ACL.
    
- Objetos de directiva de grupo (GPO).
    
- Relaciones de confianza entre dominios.
    
- Usuarios y grupos privilegiados.
    
- Posibles rutas para escalar privilegios o realizar movimiento lateral.
    

La mayoría de las herramientas de esta sección necesitan credenciales válidas de dominio, aunque algunas funciones pueden trabajar sin autenticación si el entorno permite consultas anónimas.

### Credenciales del laboratorio

```
Dominio: INLANEFREIGHT.LOCAL
Usuario: forend
Contraseña: Klmcargo2
Controlador de dominio: 172.16.5.5
```

> Estas credenciales corresponden al laboratorio de HTB de esta sección.

# 2. CrackMapExec (CME)

**CrackMapExec (CME)** es una herramienta de enumeración y evaluación de entornos Windows y Active Directory. Actualmente, su sucesor es **NetExec**.

Permite trabajar con diferentes protocolos, entre ellos:

- SMB.
    
- MSSQL.
    
- SSH.
    
- WinRM.
    

## 2.1. Consultar la ayuda

```
crackmapexec -h
```

Para consultar las opciones específicas de SMB:

```
crackmapexec smb -h
```

### Parámetros importantes

|Parámetro|Descripción|
|---|---|
|`-u`|Usuario o archivo de usuarios.|
|`-p`|Contraseña o archivo de contraseñas.|
|`-H`|Hash de autenticación.|
|`-d`|Dominio.|
|`-k`|Utiliza autenticación Kerberos.|
|`--users`|Enumera usuarios del dominio.|
|`--groups`|Enumera grupos del dominio.|
|`--loggedon-users`|Intenta enumerar usuarios con sesiones iniciadas en el equipo objetivo.|
|`--shares`|Enumera los recursos compartidos SMB y sus permisos.|
|`-M`|Ejecuta un módulo de la herramienta.|

En los ejemplos del laboratorio se utiliza `sudo` para ejecutar los comandos.

---

## 2.2. Enumerar usuarios del dominio

```
sudo crackmapexec smb 172.16.5.5 -u forend -p 'Klmcargo2' --users
```

Este comando autentica al usuario `forend` contra el controlador de dominio y enumera los usuarios.

### Información importante

La salida puede incluir atributos como:

- Nombre de usuario.
    
- `badpwdcount`.
    
- `badpwdtime`.
    

`**badpwdcount**` indica el número de intentos de contraseña incorrectos registrados para la cuenta.

`**badpwdtime**` indica el momento asociado al último intento de contraseña incorrecto.

Ejemplo:

```
INLANEFREIGHT.LOCAL\administrator  badpwdcount: 0
INLANEFREIGHT.LOCAL\avazquez      badpwdcount: 3
```

En este ejemplo, `avazquez` presenta un contador de tres intentos fallidos.

### ¿Por qué es útil?

Estos atributos ayudan a identificar cuentas que requieren precaución antes de realizar pruebas de autenticación.

El contador no garantiza por sí solo que conozcamos todos los intentos recientes ni que la cuenta esté a salvo de un bloqueo. Los valores pueden depender de la configuración del dominio y de la información disponible en el controlador consultado.

---

## 2.3. Enumerar grupos del dominio

```
sudo crackmapexec smb 172.16.5.5 -u forend -p 'Klmcargo2' --groups
```

Este comando enumera los grupos y puede mostrar el número de miembros de cada uno.

Ejemplo de grupos interesantes:

```
Administrators
Backup Operators
Domain Admins
Domain Users
Contractors
Accounting
Engineering
Executives
Human Resources
```

### ¿Qué grupos conviene revisar?

|Grupo|Motivo de interés|
|---|---|
|`Administrators`|Puede incluir administradores del sistema.|
|`Domain Admins`|Grupo privilegiado del dominio.|
|`Backup Operators`|Sus permisos pueden permitir operaciones sensibles sobre datos del sistema.|
|`Executives`|Puede contener usuarios con acceso a información corporativa sensible.|
|`Engineering`|Puede disponer de acceso a sistemas o recursos técnicos.|
|`IT`|Puede contener personal con funciones administrativas.|

La pertenencia a un grupo debe investigarse junto con sus permisos efectivos. Un nombre de grupo por sí solo no demuestra que todos sus miembros tengan privilegios administrativos.

**Recomendación:** guarda los resultados en archivos para consultarlos posteriormente y compararlos con los obtenidos mediante otras herramientas.

---

## 2.4. Enumerar usuarios con sesión iniciada

También podemos consultar las sesiones de usuarios en otros equipos.

```
sudo crackmapexec smb 172.16.5.130 -u forend -p 'Klmcargo2' --loggedon-users
```

En el laboratorio, `172.16.5.130` corresponde al servidor `ACADEMY-EA-FILE`.

Ejemplo de resultado:

```
INLANEFREIGHT\clusteragent
INLANEFREIGHT\lab_adm
INLANEFREIGHT\svc_qualys
INLANEFREIGHT\wley
```

### ¿Por qué es importante?

Un servidor de archivos puede ser utilizado por distintos usuarios y administradores. Identificar las sesiones permite determinar qué cuentas están utilizando ese equipo.

Si una cuenta privilegiada tiene una sesión iniciada, el equipo puede resultar interesante para una investigación autorizada.

Ten en cuenta que esta enumeración depende de los permisos disponibles y de la información que el sistema objetivo permita consultar.

### Interpretar `(Pwn3d!)`

Si la salida contiene:

```
[+] INLANEFREIGHT.LOCAL\forend:Klmcargo2 (Pwn3d!)
```

CME indica que la cuenta tiene acceso privilegiado reconocido por la herramienta en ese host.

No significa que el usuario sea automáticamente administrador del dominio: se refiere al acceso reconocido en el sistema objetivo.

# 3. Enumerar recursos compartidos SMB

Los recursos compartidos pueden contener documentos, scripts, archivos de configuración o información sensible.

## 3.1. Enumerar los recursos compartidos

```
sudo crackmapexec smb 172.16.5.5 -u forend -p 'Klmcargo2' --shares
```

Ejemplo de resultado:

```
Share                Permissions
ADMIN$
C$
Department Shares    READ
IPC$                 READ
NETLOGON             READ
SYSVOL               READ
User Shares          READ
ZZZ_archive          READ
```

### Interpretación

|Recurso|Descripción|
|---|---|
|`ADMIN$`|Recurso administrativo de Windows.|
|`C$`|Recurso administrativo que apunta a la unidad C:.|
|`IPC$`|Recurso utilizado para comunicación entre procesos y determinadas operaciones RPC.|
|`NETLOGON`|Recurso relacionado con scripts de inicio de sesión y archivos de soporte del dominio.|
|`SYSVOL`|Recurso que distribuye archivos del dominio, incluidas determinadas políticas y scripts.|
|`Department Shares`|Recurso compartido personalizado para departamentos.|
|`User Shares`|Recurso compartido personalizado para usuarios.|
|`ZZZ_archive`|Recurso personalizado de archivo.|

Los recursos personalizados merecen atención porque pueden contener información corporativa que no debería estar disponible para cualquier usuario.

**Importante:** disponer de permisos `READ` permite leer los datos accesibles, pero no implica que se puedan modificar archivos.

---

## 3.2. Enumerar archivos con `spider_plus`

El módulo `spider_plus` permite recorrer los recursos compartidos accesibles y recopilar información sobre los archivos encontrados.

Ejemplo del laboratorio:

```
sudo crackmapexec smb 172.16.5.5 -u forend -p 'Klmcargo2' -M spider_plus --share 'Department Shares'
```

La herramienta genera un archivo JSON con información sobre los archivos enumerados.

En el ejemplo del material, la ruta de salida es:

```
/tmp/cme_spider_plus/172.16.5.5.json
```

Podemos consultar el comienzo del archivo con:

```
head -n 10 /tmp/cme_spider_plus/172.16.5.5.json
```

Ejemplo de contenido:

```
{
    "Department Shares": {
        "Accounting/Private/AddSelect.bat": {
            "atime_epoch": "2022-03-31 14:44:42",
            "ctime_epoch": "2022-03-31 14:44:39",
            "mtime_epoch": "2022-03-31 15:14:46",
            "size": "278 Bytes"
        }
    }
}
```

### ¿Qué buscar?

Durante una evaluación autorizada, presta atención a archivos como:

- `web.config`.
    
- Scripts `.bat` y `.ps1`.
    
- Archivos de configuración.
    
- Documentos que contengan información sensible.
    
- Scripts con credenciales incorporadas.
    

Los nombres y metadatos ayudan a priorizar los archivos que conviene revisar.

# 4. SMBMap

**SMBMap** es otra herramienta para enumerar recursos compartidos SMB desde Linux.

Permite:

- Enumerar recursos compartidos.
    
- Consultar permisos.
    
- Listar directorios y archivos.
    
- Realizar listados recursivos.
    
- Descargar o subir archivos cuando los permisos lo permiten.
    
- Buscar información en recursos accesibles.
    

## 4.1. Enumerar recursos y permisos

```
smbmap -u forend -p 'Klmcargo2' -d INLANEFREIGHT.LOCAL -H 172.16.5.5
```

Ejemplo de resultado:

```
Disk                  Permissions
ADMIN$                NO ACCESS
C$                    NO ACCESS
Department Shares     READ ONLY
IPC$                  READ ONLY
NETLOGON              READ ONLY
SYSVOL                READ ONLY
User Shares           READ ONLY
ZZZ_archive           READ ONLY
```

Esto confirma que el usuario puede leer determinados recursos, pero no acceder a los recursos administrativos `ADMIN$` y `C$`.

---

## 4.2. Listar directorios recursivamente

Para enumerar los directorios del recurso `Department Shares`:

```
smbmap -u forend -p 'Klmcargo2' -d INLANEFREIGHT.LOCAL -H 172.16.5.5 -R 'Department Shares' --dir-only
```

El parámetro `-R` permite recorrer recursivamente el recurso compartido, mientras que `--dir-only` limita la salida a directorios.

Ejemplo:

```
Accounting
Executives
Finance
HR
IT
Legal
Marketing
Operations
R&D
Temp
Warehouse
```

### ¿Por qué utilizar `--dir-only`?

Permite identificar la estructura de directorios sin mostrar todos los archivos.

Después podemos investigar los directorios de interés y consultar los archivos que contienen, siempre dentro del alcance autorizado.

# 5. rpcclient

`rpcclient` es una herramienta de Samba que permite interactuar con servicios MS-RPC de Windows.

Entre otras funciones, puede consultar información de usuarios y grupos de Active Directory.

Dependiendo de la configuración del dominio, puede funcionar con autenticación o mediante una sesión SMB anónima.

## 5.1. Conectar mediante una sesión nula

```
rpcclient -U "" -N 172.16.5.5
```

Parámetros:

- `-U ""`: utiliza un nombre de usuario vacío.
    
- `-N`: evita solicitar una contraseña.
    
- `172.16.5.5`: dirección del controlador de dominio.
    

Esta conexión solo funcionará si el sistema permite la autenticación anónima necesaria. En caso contrario, tendremos que utilizar credenciales válidas.

## 5.2. Enumerar usuarios

Una vez dentro de `rpcclient`, podemos ejecutar:

```
enumdomusers
```

Ejemplo:

```
user:[administrator] rid:[0x1f4]
user:[guest] rid:[0x1f5]
user:[krbtgt] rid:[0x1f6]
user:[lab_adm] rid:[0x3e9]
user:[htb-student] rid:[0x457]
user:[avazquez] rid:[0x458]
user:[pfalcon] rid:[0x459]
```

El resultado muestra los nombres de usuario y sus RID.

---

## 5.3. Comprender SID y RID

Un **SID (Security Identifier)** identifica un objeto de seguridad, como un usuario o grupo.

Un **RID (Relative Identifier)** es la parte final del SID que identifica un objeto dentro de la autoridad de seguridad correspondiente.

Ejemplo del laboratorio:

```
SID del dominio:
S-1-5-21-3842939050-3880317879-2865463114
```

El usuario `htb-student` tiene el RID decimal `1111`, equivalente al hexadecimal `0x457`.

Por tanto, su SID completo es:

```
S-1-5-21-3842939050-3880317879-2865463114-1111
```

### RID conocidos

|Cuenta|RID decimal|RID hexadecimal|
|---|---|---|
|Administrator integrado|500|`0x1f4`|
|Guest|501|`0x1f5`|
|krbtgt|502|`0x1f6`|

Estos valores son habituales para las cuentas integradas correspondientes de un dominio de Active Directory.

---

## 5.4. Consultar un usuario mediante su RID

Si conocemos el RID de un usuario, podemos consultar sus atributos con `queryuser`.

```
queryuser 0x457
```

Ejemplo de información devuelta:

```
User Name   : htb-student
Full Name   : Htb Student
Home Drive  :
Profile Path:
Description :
user_rid    : 0x457
group_rid   : 0x201
bad_password_count: 0x00000000
logon_count : 0x0000001d
```

Entre los atributos que pueden resultar interesantes se encuentran:

- Nombre de usuario.
    
- Nombre completo.
    
- Descripción.
    
- Último cambio de contraseña.
    
- Contador de contraseñas incorrectas.
    
- Contador de inicios de sesión.
    

La información exacta disponible depende de la respuesta del servicio y de los permisos de la cuenta.

# 6. Impacket

**Impacket** es una colección de herramientas y bibliotecas de Python para interactuar con protocolos de Windows y redes.

En esta sección se destacan `psexec.py` y `wmiexec.py`.

## 6.1. psexec.py

`psexec.py` permite obtener una shell remota en un equipo Windows cuando se dispone de credenciales con privilegios de administrador local suficientes.

En términos generales, la herramienta:

1. Se autentica en el equipo objetivo.
    
2. Sube un ejecutable al recurso administrativo `ADMIN$`.
    
3. Registra e inicia un servicio remoto mediante RPC y el Administrador de Control de Servicios.
    
4. Establece la comunicación mediante una named pipe.
    
5. Proporciona una shell remota.
    

### Ejemplo del laboratorio

```
psexec.py 'INLANEFREIGHT.LOCAL/wley:transporter@4'@172.16.5.125
```

Una vez obtenida la shell, se puede comprobar el contexto de ejecución:

```
whoami
```

En el ejemplo del material, la sesión se obtiene como `SYSTEM`.

**Concepto clave:** `psexec.py` necesita credenciales con los privilegios adecuados y suele dejar artefactos, como el ejecutable subido y el servicio creado.

---

## 6.2. wmiexec.py

`wmiexec.py` utiliza WMI (Windows Management Instrumentation) para ejecutar comandos en el sistema remoto.

Ejemplo del material:

```
wmiexec.py 'INLANEFREIGHT.LOCAL/wley:transporter@4'@172.16.5.5
```

### Características

- Proporciona una shell seminteractiva.
    
- Ejecuta los comandos a través de WMI.
    
- Normalmente ejecuta los comandos con el contexto de la cuenta utilizada para autenticarse.
    
- No utiliza el mismo mecanismo de creación de servicio y subida de ejecutable que `psexec.py`.
    

### Limitaciones y detección

Aunque puede generar menos artefactos de tipo archivo que otros métodos, **no es indetectable**.

Los defensores pueden investigar la actividad WMI y los procesos creados como consecuencia de los comandos remotos.

El material destaca el evento de Windows:

- **4688:** se ha creado un nuevo proceso.
    

Por ejemplo, un defensor podría observar procesos `cmd.exe` creados para ejecutar comandos remotos.

La presencia de este evento por sí sola no demuestra actividad maliciosa, ya que WMI también se utiliza para administrar sistemas legítimamente.

### Diferencia entre ambas herramientas

|Característica|`psexec.py`|`wmiexec.py`|
|---|---|---|
|Mecanismo|Servicio remoto y named pipe|WMI|
|Ejecutable subido al objetivo|Sí, según el procedimiento descrito|No requiere el mismo mecanismo de subida|
|Contexto de ejecución|Puede obtener `SYSTEM` si se cumplen las condiciones necesarias|Normalmente, el usuario autenticado|
|Interactividad|Shell remota interactiva|Shell seminteractiva|
|Detección|Puede generar artefactos de servicio y archivo|Puede generar eventos de WMI y creación de procesos|

# 7. Windapsearch

**Windapsearch** es un script de Python que utiliza consultas LDAP para enumerar objetos de Active Directory.

En el entorno del laboratorio está disponible en:

```
/opt/windapsearch/
```

Consultar la ayuda:

```
windapsearch.py -h
```

### Opciones importantes

|Parámetro|Descripción|
|---|---|
|`--dc-ip`|Dirección IP del controlador de dominio.|
|`-d`|Dominio.|
|`-u`|Usuario utilizado para la autenticación LDAP.|
|`-p`|Contraseña.|
|`-U`|Enumera usuarios.|
|`-G`|Enumera grupos.|
|`-C`|Enumera equipos.|
|`--da`|Enumera miembros de Domain Admins.|
|`-PU`|Busca usuarios privilegiados, incluyendo miembros de grupos anidados.|
|`--user-spns`|Busca usuarios con SPN, según las funciones disponibles en la versión.|
|`--gpos`|Enumera objetos de directiva de grupo.|

La herramienta puede intentar un bind anónimo si no se proporcionan credenciales, pero el éxito dependerá de la configuración del servidor LDAP.

## 7.1. Enumerar Domain Admins

```
python3 windapsearch.py --dc-ip 172.16.5.5 -u forend@inlanefreight.local -p 'Klmcargo2' --da
```

El comando busca miembros del grupo `Domain Admins`.

La salida puede mostrar nombres y atributos como `userPrincipalName`.

## 7.2. Enumerar usuarios privilegiados

```
python3 windapsearch.py --dc-ip 172.16.5.5 -u forend@inlanefreight.local -p 'Klmcargo2' -PU
```

Esta opción amplía la búsqueda a usuarios privilegiados e incluye consultas recursivas para tener en cuenta la pertenencia a grupos anidados.

### ¿Por qué importan los grupos anidados?

Un usuario puede obtener privilegios indirectamente al pertenecer a un grupo que, a su vez, pertenece a otro grupo privilegiado.

Por eso, enumerar únicamente los miembros directos de `Domain Admins` puede ofrecer una visión incompleta de los permisos efectivos.

**Concepto clave:** `--da` y `-PU` permiten enfoques complementarios para identificar cuentas privilegiadas.

# 8. BloodHound.py

**BloodHound** representa las relaciones de Active Directory mediante grafos para ayudar a descubrir rutas de ataque y relaciones de privilegios.

El proyecto utiliza un recolector de datos y una interfaz gráfica para analizar los resultados.

En esta sección se utiliza `bloodhound-python`, un recolector que puede ejecutarse desde Linux con credenciales válidas de dominio.

## 8.1. Consultar las opciones

```
bloodhound-python -h
```

### Métodos de recopilación

El parámetro `-c` permite seleccionar los datos que se recopilarán.

|Método|Información principal|
|---|---|
|`Group`|Grupos y relaciones de pertenencia.|
|`LocalAdmin`|Información de administración local.|
|`Session`|Sesiones de usuario.|
|`Trusts`|Relaciones de confianza.|
|`Default`|Conjunto predeterminado de recopilación.|
|`DCOnly`|Recopilación centrada en el controlador de dominio.|
|`ObjectProps`|Propiedades de objetos.|
|`ACL`|Listas de control de acceso.|
|`RDP`|Información relacionada con acceso RDP.|
|`PSRemote`|Información relacionada con PowerShell Remoting.|
|`All`|Recopila todos los tipos admitidos por esa versión, excepto los que la propia ayuda excluya expresamente.|

Los métodos disponibles pueden variar según la versión del recolector.

---

## 8.2. Ejecutar BloodHound.py

Ejemplo del laboratorio:

```
sudo bloodhound-python -u 'forend' -p 'Klmcargo2' -ns 172.16.5.5 -d inlanefreight.local -c all
```

### Parámetros

|Parámetro|Descripción|
|---|---|
|`-u`|Usuario de dominio.|
|`-p`|Contraseña.|
|`-ns`|Servidor DNS utilizado para resolver los nombres del dominio.|
|`-d`|Nombre del dominio.|
|`-c all`|Solicita todos los métodos de recopilación disponibles en esa versión.|

El recolector consulta Active Directory y, dependiendo del método seleccionado y de los permisos disponibles, también puede recopilar información de los equipos.

Ejemplo de salida:

```
INFO: Found AD domain: inlanefreight.local
INFO: Found 1 domains
INFO: Found 2 domains in the forest
INFO: Found 564 computers
INFO: Found 2951 users
INFO: Found 183 groups
INFO: Found 2 trusts
```

Los valores anteriores pertenecen al entorno de ejemplo de HTB; en otros entornos, los resultados serán diferentes.

## 8.4. Cargar los datos en BloodHound

El flujo general descrito en el material es:

1. Iniciar el servicio de base de datos requerido por la instalación.
    
2. Abrir la interfaz gráfica de BloodHound.
    
3. Seleccionar **Upload Data**.
    
4. Cargar el archivo ZIP o los archivos JSON generados.
    
5. Esperar a que finalice la importación.
    
6. Consultar la información y las relaciones representadas en el grafo.
    

La forma de iniciar los servicios depende de la versión y de cómo esté instalada la herramienta. El material muestra el uso de Neo4j y una instalación tradicional de BloodHound; las instalaciones modernas pueden utilizar componentes y procedimientos diferentes.

## 8.5. Encontrar rutas hacia Domain Admins

Una de las consultas predefinidas mencionadas es:

**Find Shortest Paths to Domain Admins**

Esta consulta busca rutas de relaciones que podrían permitir alcanzar privilegios de administrador de dominio.

BloodHound puede representar relaciones entre:

- Usuarios.
    
- Grupos.
    
- Equipos.
    
- Permisos.
    
- ACL.
    
- GPO.
    
- Sesiones.
    
- Relaciones de confianza.
    

El grafo ayuda a detectar combinaciones de permisos y relaciones que no son evidentes al revisar listados de usuarios por separado.

### Concepto clave

BloodHound no concede privilegios automáticamente. Ayuda a identificar relaciones y posibles rutas que deben verificarse y analizarse.

# 9. Comparativa de herramientas

|Herramienta|Uso principal|Información que interesa|
|---|---|---|
|CrackMapExec / NetExec|Enumeración SMB y autenticación|Usuarios, grupos, sesiones y recursos compartidos.|

|Impacket `wmiexec.py`|Ejecución remota mediante WMI|Comandos remotos en el contexto de la cuenta autenticada.|

|BloodHound.py|Recopilación de relaciones de AD|Datos para analizar rutas de ataque mediante grafos.|

# 10. Flujo de trabajo recomendado

1. **Validar las credenciales** contra el controlador de dominio.
    
2. **Enumerar usuarios** y revisar atributos relevantes, como `badpwdcount`.
    
3. **Enumerar grupos** e identificar los grupos privilegiados y los de interés.
    
4. **Buscar sesiones** en equipos relevantes.
    
5. **Enumerar recursos SMB** y determinar qué archivos y directorios son accesibles.
    
6. **Consultar atributos y RID** de los usuarios con `rpcclient`.

# Chuleta rápida

## CrackMapExec

```
# Ayuda
crackmapexec -h
crackmapexec smb -h

# Enumerar usuarios
sudo crackmapexec smb <IP_DC> -u <USUARIO> -p '<CONTRASEÑA>' --users

# Enumerar grupos
sudo crackmapexec smb <IP_DC> -u <USUARIO> -p '<CONTRASEÑA>' --groups

# Enumerar usuarios con sesión iniciada
sudo crackmapexec smb <IP_HOST> -u <USUARIO> -p '<CONTRASEÑA>' --loggedon-users

# Enumerar recursos compartidos
sudo crackmapexec smb <IP_HOST> -u <USUARIO> -p '<CONTRASEÑA>' --shares

# Recorrer un recurso compartido
sudo crackmapexec smb <IP_HOST> -u <USUARIO> -p '<CONTRASEÑA>' -M spider_plus --share '<RECURSO>'
```

## SMBMap

```
# Enumerar recursos y permisos
smbmap -u <USUARIO> -p '<CONTRASEÑA>' -d <DOMINIO> -H <IP_HOST>

# Listar directorios recursivamente
smbmap -u <USUARIO> -p '<CONTRASEÑA>' -d <DOMINIO> -H <IP_HOST> -R '<RECURSO>' --dir-only
```

## rpcclient

```
# Intentar una sesión nula
rpcclient -U "" -N <IP_DC>
```

Dentro de la sesión:

```
enumdomusers
queryuser <RID>
```

## Impacket

```
# Shell remota mediante servicio
psexec.py '<DOMINIO>/<USUARIO>:<CONTRASEÑA>'@<IP_HOST>

# Shell seminteractiva mediante WMI
wmiexec.py '<DOMINIO>/<USUARIO>:<CONTRASEÑA>'@<IP_HOST>
```

## Windapsearch

```
# Enumerar Domain Admins
python3 windapsearch.py --dc-ip <IP_DC> -u <USUARIO>@<DOMINIO> -p '<CONTRASEÑA>' --da

# Enumerar usuarios privilegiados
python3 windapsearch.py --dc-ip <IP_DC> -u <USUARIO>@<DOMINIO> -p '<CONTRASEÑA>' -PU
```

## BloodHound.py

```
# Consultar ayuda
bloodhound-python -h

# Recopilar información
sudo bloodhound-python -u '<USUARIO>' -p '<CONTRASEÑA>' -ns <IP_DC> -d <DOMINIO> -c all

# Comprimir los JSON generados
zip -r bloodhound.zip *.json
```

## Conceptos esenciales para el examen

- `**badpwdcount**`**:** contador de contraseñas incorrectas de una cuenta.
    
- `**--users**` **/** `**--groups**`**:** enumeración de usuarios y grupos con CME.
    
- `**--loggedon-users**`**:** busca información sobre sesiones de usuarios en un equipo.
    
- `**--shares**`**:** enumera los recursos SMB y los permisos visibles para la cuenta.
    
- **RID:** identificador relativo que forma parte del SID de un objeto.
    
- `**enumdomusers**`**:** enumera usuarios y RID con `rpcclient`.
    
- `**queryuser**`**:** consulta información de un usuario mediante su RID.
    
- `**psexec.py**`**:** puede proporcionar una shell como `SYSTEM` si se cumplen los requisitos de privilegios.
    
- `**wmiexec.py**`**:** ejecuta comandos remotos mediante WMI; no es indetectable.
    
- `**--da**`**:** busca miembros de Domain Admins con Windapsearch.
    
- `**-PU**`**:** busca usuarios privilegiados teniendo en cuenta grupos anidados.
    
- **BloodHound:** permite visualizar relaciones y posibles rutas de ataque en Active Directory.
    
- **Enumeración autenticada:** una cuenta de bajos privilegios puede revelar información importante sin ser administradora del dominio.
