
### 1. Objetivos de la enumeración

Una vez obtenidas credenciales válidas de dominio, podemos enumerar Active Directory desde un host Windows para identificar:

- Usuarios, grupos y equipos del dominio.
    
- Cuentas con SPN, potencialmente vulnerables a **Kerberoasting**.
    
- Relaciones de confianza entre dominios y bosques.
    
- Pertenencias a grupos privilegiados y membresías anidadas.
    
- Permisos de administrador local sobre equipos.
    
- ACL y configuraciones incorrectas que permitan movimiento lateral o escalada de privilegios.
    
- Recursos compartidos con archivos sensibles, contraseñas o claves privadas.
    
- Sistemas operativos obsoletos y otros problemas relevantes para el informe de seguridad.
    

Las herramientas principales de esta sección son:

|Herramienta|Función|
|---|---|
|`ActiveDirectory`|Módulo de PowerShell para consultar y administrar objetos de AD.|
|`PowerView`|Enumeración avanzada de usuarios, grupos, ACL, equipos y relaciones de confianza.|
|`SharpView`|Implementación en .NET de funciones similares a PowerView.|
|`Snaffler`|Busca recursos compartidos y archivos potencialmente sensibles.|
|`SharpHound`|Recopila datos de AD para analizarlos con BloodHound.|
|`BloodHound`|Visualiza relaciones entre objetos e identifica posibles rutas de ataque.|

# 2. Módulo de PowerShell ActiveDirectory

El módulo `ActiveDirectory` proporciona cmdlets para consultar información del dominio.

### 2.1. Comprobar los módulos disponibles

```
Get-Module
```

Para mostrar también los módulos disponibles que todavía no están cargados:

```
Get-Module -ListAvailable
```

Si el módulo está disponible, cargarlo:

```
Import-Module ActiveDirectory
```

Comprobar que se ha cargado:

```
Get-Module
```

> **Nota:** Que el módulo aparezca en `Get-Module -ListAvailable` no garantiza que esté instalado en todos los equipos. Si no está disponible, no podrás importarlo sin disponer de él.

### 2.2. Obtener información del dominio

```
Get-ADDomain
```

Información especialmente interesante:

|Propiedad|Información|
|---|---|
|`DNSRoot`|Nombre DNS del dominio.|
|`DomainSID`|SID del dominio.|
|`DomainMode`|Nivel funcional del dominio.|
|`Forest`|Bosque al que pertenece.|
|`ChildDomains`|Dominios hijos.|
|`ParentDomain`|Dominio padre, si existe.|
|`PDCEmulator`|Controlador de dominio que ejerce el rol PDC Emulator.|
|`RIDMaster`|Controlador que ejerce el rol RID Master.|
|`InfrastructureMaster`|Controlador que ejerce el rol Infrastructure Master.|
|`UsersContainer`|Contenedor predeterminado de usuarios.|
|`ComputersContainer`|Contenedor predeterminado de equipos.|

Para consultar un dominio concreto:

```
Get-ADDomain -Identity <DOMINIO>
```

### 2.3. Encontrar usuarios con SPN

Las cuentas de usuario con un atributo `ServicePrincipalName` configurado pueden ser candidatas a un ataque de **Kerberoasting**.

```
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName
```

Mostrar únicamente el nombre de cuenta y sus SPN:

```
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName |
Select-Object SamAccountName, ServicePrincipalName
```

**Qué debemos revisar:**

- Nombre de la cuenta de servicio.
    
- SPN asociado.
    
- Si la cuenta está habilitada.
    
- Sus grupos y privilegios.
    
- Si tiene permisos excesivos.
    

Tener un SPN no demuestra por sí solo que la cuenta sea vulnerable: indica que merece investigarse como posible objetivo de Kerberoasting.

### 2.4. Enumerar relaciones de confianza

```
Get-ADTrust -Filter *
```

Información importante:

|Propiedad|Significado|
|---|---|
|`Name`|Nombre del dominio de confianza.|
|`Source`|Dominio de origen de la relación.|
|`Target`|Dominio de destino.|
|`Direction`|Dirección de la confianza.|
|`IntraForest`|Indica si la relación es dentro del mismo bosque.|
|`ForestTransitive`|Indica si la confianza es transitiva a nivel de bosque.|
|`SelectiveAuthentication`|Indica si se utiliza autenticación selectiva.|
|`SIDFilteringForestAware`|Información sobre el filtrado de SID en la relación.|
|`TGTDelegation`|Indica si se permite delegación de TGT según la confianza.|

**Interpretación:**

- `Bidirectional`: la confianza es bidireccional.
    
- `IntraForest = True`: la relación es dentro del bosque.
    
- `ForestTransitive = True`: la confianza es transitiva a nivel de bosque.
    

Las confianzas pueden abrir posibilidades de movimiento entre dominios, pero su existencia no implica automáticamente que podamos explotar la relación.

### 2.5. Enumerar grupos

Listar todos los grupos:

```
Get-ADGroup -Filter * | Select-Object Name
```

Obtener información detallada de un grupo:

```
Get-ADGroup -Identity "Backup Operators"
```

Listar los miembros del grupo:

```
Get-ADGroupMember -Identity "Backup Operators"
```

Ejemplo con un grupo privilegiado:

```
Get-ADGroupMember -Identity "Domain Admins"
```

Para mostrar también miembros de grupos anidados:

```
Get-ADGroupMember -Identity "Domain Admins" -Recursive
```

**Qué debemos buscar:**

- Usuarios pertenecientes a grupos privilegiados.
    
- Cuentas de servicio incluidas en grupos sensibles.
    
- Grupos anidados que concedan privilegios indirectos.
    
- Membresías inesperadas o excesivas.
    

Una cuenta que no aparece directamente en `Domain Admins` puede heredar privilegios a través de un grupo anidado.

# 3. PowerView

PowerView es una herramienta de PowerShell para enumerar Active Directory y detectar relaciones y configuraciones incorrectas.

Permite consultar:

- Usuarios, grupos, equipos y unidades organizativas.
    
- ACL y permisos sobre objetos.
    
- GPO.
    
- Relaciones de confianza.
    
- Recursos compartidos.
    
- Sesiones de usuario.
    
- Acceso de administrador local.
    
- Cuentas con SPN.
    
- Archivos potencialmente interesantes en recursos compartidos.
    

### 3.1. Importar PowerView

```
cd C:\Tools\
Import-Module .\PowerView.ps1
```

### 3.2. Enumerar información de un usuario

Consultar el usuario `mmorgan`:

```
Get-DomainUser -Identity mmorgan -Domain inlanefreight.local
```

Mostrar propiedades relevantes:

```
Get-DomainUser -Identity mmorgan -Domain inlanefreight.local |
Select-Object name, samaccountname, description, memberof, whencreated, pwdlastset, lastlogontimestamp, accountexpires, admincount, userprincipalname, serviceprincipalname, useraccountcontrol
```

Propiedades interesantes:

|Propiedad|Utilidad|
|---|---|
|`samaccountname`|Nombre de inicio de sesión de la cuenta.|
|`description`|Puede contener información útil o sensible.|
|`memberof`|Grupos a los que pertenece el usuario.|
|`whencreated`|Fecha de creación de la cuenta.|
|`pwdlastset`|Último cambio de contraseña.|
|`lastlogontimestamp`|Referencia aproximada del último inicio de sesión replicado.|
|`accountexpires`|Fecha de expiración de la cuenta.|
|`admincount`|Puede señalar cuentas protegidas o asociadas a grupos privilegiados.|
|`serviceprincipalname`|SPN configurados para la cuenta.|
|`useraccountcontrol`|Indicadores del estado y configuración de la cuenta.|

**Precaución:** `admincount = 1` no garantiza que la cuenta conserve actualmente privilegios administrativos. Es necesario verificar sus grupos y permisos efectivos.

### 3.3. Enumerar miembros de grupos de forma recursiva

```
Get-DomainGroupMember -Identity "Domain Admins" -Recurse
```

`-Recurse` permite descubrir miembros que obtienen pertenencia indirecta mediante grupos anidados.

Esto ayuda a identificar usuarios que heredan privilegios de grupos importantes sin aparecer directamente como miembros de ellos.

### 3.4. Enumerar relaciones de confianza

```
Get-DomainTrustMapping
```

Muestra las relaciones de confianza visibles desde el dominio actual, incluyendo:

- Dominio de origen.
    
- Dominio de destino.
    
- Tipo de confianza.
    
- Dirección.
    
- Atributos de la relación.
    

Puede revelar dominios adicionales que conviene investigar.

### 3.5. Comprobar el acceso de administrador local

```
Test-AdminAccess -ComputerName ACADEMY-EA-MS01
```

Ejemplo de resultado:

```
ComputerName       IsAdmin
------------       -------
ACADEMY-EA-MS01    True
```

Si `IsAdmin` es `True`, la herramienta indica que el usuario actual dispone de acceso administrativo en el equipo consultado.

Podemos repetir la comprobación en otros equipos a los que tengamos acceso de red.

### 3.6. Encontrar usuarios con SPN

```
Get-DomainUser -SPN -Properties samaccountname, ServicePrincipalName
```

Esta consulta permite localizar cuentas que podrían ser candidatas a Kerberoasting.

Debemos investigar qué privilegios tiene cada cuenta antes de valorar su interés.

# 4. SharpView

SharpView es una implementación en .NET de numerosas funciones de PowerView.

Puede resultar útil cuando interesa utilizar una herramienta compilada en lugar de importar un script de PowerShell.

### 4.1. Consultar la ayuda de una función

```
.\SharpView.exe Get-DomainUser -Help
```

Esto muestra los argumentos admitidos por el método.

### 4.2. Enumerar un usuario

```
.\SharpView.exe Get-DomainUser -Identity forend
```

La salida puede incluir:

- SID y GUID.
    
- Nombre de cuenta.
    
- DN.
    
- Grupos.
    
- Fechas de creación y modificación.
    
- Último inicio de sesión.
    
- Último cambio de contraseña.
    
- Contadores de contraseñas incorrectas.
    
- Configuración de la cuenta.
    

### 4.3. Qué debemos recordar

- SharpView implementa muchas funciones similares a PowerView.
    
- Podemos consultar la ayuda de cada función con `-Help`.
    
- Permite realizar distintas tareas de reconocimiento sin depender del mismo flujo de importación de PowerShell que utiliza PowerView.
    
- No garantiza por sí solo la evasión de controles de seguridad ni que su ejecución pase desapercibida.

# 5. Enumeración de recursos compartidos

Los recursos compartidos SMB pueden contener información sensible accesible para usuarios que no deberían tener acceso a ella.

Debemos buscar, dentro del alcance autorizado:

- Archivos de configuración.
    
- Contraseñas almacenadas de forma insegura.
    
- Claves SSH.
    
- Copias de seguridad.
    
- Archivos de bases de datos.
    
- Scripts administrativos.
    
- Documentación interna.
    
- Datos personales o empresariales sensibles.
    

El objetivo es detectar permisos excesivos y exposición de información.

### 5.1. Enumerar recursos compartidos con PowerView

```
Get-NetShare
```

Para consultar los recursos compartidos de un equipo remoto:

```
Get-NetShare -ComputerName <EQUIPO>
```

Para buscar recursos compartidos accesibles en el dominio:

```
Find-DomainShare
```

Para buscar archivos interesantes en recursos compartidos legibles:

```
Find-InterestingDomainShareFile
```

Estas funciones pueden generar bastantes resultados en entornos grandes. Conviene guardar y revisar las salidas con cuidado.

# 6. Snaffler

Snaffler busca información potencialmente sensible en recursos compartidos de un entorno de Active Directory.

Su funcionamiento general es:

1. Obtener una lista de equipos del dominio.
    
2. Enumerar los recursos compartidos.
    
3. Identificar directorios y archivos legibles.
    
4. Examinar los archivos accesibles para encontrar datos potencialmente interesantes.
    
5. Generar resultados que permitan investigar los recursos de mayor interés.
    

Se ejecuta desde un host unido al dominio o en el contexto de un usuario de dominio, según los requisitos del entorno.

### 6.1. Ejecutar Snaffler

```
.\Snaffler.exe -s -d INLANEFREIGHT.LOCAL -o snaffler.log -v data
```

Parámetros:

|Parámetro|Función|
|---|---|
|`-s`|Imprime los resultados en la consola.|
|`-d`|Especifica el dominio que se va a examinar.|
|`-o`|Especifica el archivo de salida.|
|`-v`|Configura el nivel de verbosidad.|

El nivel `data` permite comenzar con una salida más manejable, aunque la cantidad de resultados dependerá del entorno.

También aparece en el material este ejemplo:

```
.\Snaffler.exe -d INLANEFREIGHT.LOCAL -s -v data
```

En este caso no se especifica un archivo de salida con `-o`.

### 6.2. Interpretar los resultados

Snaffler puede mostrar:

- Recursos compartidos encontrados.
    
- Rutas UNC.
    
- Archivos con extensiones potencialmente interesantes.
    
- Reglas que han provocado la clasificación de un archivo.
    
- Colores que ayudan a priorizar los resultados.
    

Ejemplos de extensiones interesantes mostradas en el laboratorio:

|Extensión|Posible interés|
|---|---|
|`.key`|Posible clave privada o material criptográfico.|
|`.ppk`|Clave privada en formato PuTTY.|
|`.kdb`|Posible base de datos de claves.|
|`.sqldump`|Volcado de una base de datos.|
|`.mdf`|Archivo de datos de SQL Server.|
|`.psafe3`|Posible base de datos de contraseñas.|
|`.kwallet`|Posible archivo de cartera de KDE.|
|`.keychain`|Posible almacén de claves.|

**Importante:** la extensión no demuestra que el archivo contenga credenciales utilizables. Hay que verificar su contenido y sensibilidad de forma autorizada.

### 6.3. Buenas prácticas

- Guardar la salida en un archivo.
    
- Revisar primero los resultados de mayor interés.
    
- Registrar la ruta completa del recurso y del archivo.
    
- Documentar los datos sensibles expuestos y los permisos que permiten acceder a ellos.
    
- No asumir que todo archivo señalado contiene secretos válidos.

# 7. BloodHound y SharpHound

BloodHound permite visualizar relaciones entre usuarios, grupos, equipos, permisos y otros objetos de Active Directory para descubrir posibles rutas de ataque.

**SharpHound** es el recolector que obtiene los datos. **BloodHound** es la herramienta que los procesa y permite analizarlos gráficamente.

## 7.1. Métodos de recopilación de SharpHound

El material muestra los siguientes métodos:

|Método|Información general|
|---|---|
|`Group`|Membresías de grupos.|
|`LocalGroup` / `LocalAdmin`|Información sobre grupos locales y administración local.|
|`Session`|Sesiones de usuario.|
|`LoggedOn`|Información sobre usuarios conectados.|
|`Trusts`|Relaciones de confianza.|
|`ACL`|Permisos y listas de control de acceso.|
|`Container`|Relaciones con contenedores y unidades organizativas.|
|`RDP`|Relaciones relacionadas con el acceso RDP.|
|`ObjectProps`|Propiedades de los objetos.|
|`DCOnly`|Recopilación centrada en el controlador de dominio y consultas de directorio compatibles con este método.|

La disponibilidad exacta de los métodos depende de la versión de SharpHound.

Consultar la ayuda:

```
.\SharpHound.exe --help
```

## 7.2. Ejecutar SharpHound

Ejemplo del laboratorio:

```
.\SharpHound.exe -c All --zipfilename ILFREIGHT
```

- `-c All`: solicita todos los métodos de recopilación admitidos por esa versión.
    
- `--zipfilename ILFREIGHT`: especifica el nombre base del archivo ZIP generado.
    

Al terminar, SharpHound genera los datos que después se importarán en BloodHound.

La recopilación puede tardar y generar bastante información. Debe elegirse el método apropiado según el alcance y las restricciones de la evaluación.

## 7.3. Importar los datos en BloodHound

Flujo de trabajo descrito en el laboratorio:

1. Ejecutar SharpHound desde el host de ataque.
    
2. Localizar el archivo ZIP generado.
    
3. Transferirlo a la máquina donde se ejecuta BloodHound, si es necesario.
    
4. Abrir BloodHound.
    
5. Seleccionar **Upload Data**.
    
6. Elegir el archivo ZIP.
    
7. Esperar a que termine la importación.
    
8. Buscar el dominio en la interfaz y examinar sus nodos y relaciones.
    

Una vez importados los datos, podemos consultar usuarios, equipos, grupos, permisos y posibles rutas de ataque.

## 7.4. Consultas útiles de BloodHound

### Find Computers with Unsupported Operating Systems

Busca equipos que utilizan sistemas operativos obsoletos o sin soporte.

**Utilidad:**

- Identificar sistemas heredados.
    
- Detectar equipos que pueden estar expuestos a vulnerabilidades antiguas.
    
- Recomendar segmentación, actualización o sustitución.
    

No debemos asumir que un equipo sigue activo solo porque aparece en Active Directory. Hay que validar su estado antes de elaborar conclusiones.

### Find Computers where Domain Users are Local Admin

Busca equipos donde el grupo `Domain Users` tiene privilegios de administrador local.

**Por qué importa:**

- Puede conceder permisos administrativos locales a un conjunto excesivo de usuarios.
    
- Si una cuenta comprometida pertenece al grupo afectado, podría tener acceso administrativo al equipo.
    
- El acceso administrativo puede permitir nuevas oportunidades de movimiento lateral.
    

La existencia de la relación debe comprobarse en el entorno real; no garantiza automáticamente que todos los usuarios puedan conectarse por cualquier protocolo.

### Raw Query

BloodHound también permite ejecutar consultas Cypher personalizadas desde el área **Raw Query**.

Estas consultas permiten investigar relaciones específicas que no siempre quedan cubiertas por las consultas predefinidas.

# 8. Flujo de trabajo recomendado

Una secuencia práctica para la enumeración con credenciales desde Windows:

### Paso 1. Identificar el dominio

```
Get-Module -ListAvailable
Import-Module ActiveDirectory
Get-ADDomain
```

### Paso 2. Enumerar usuarios y cuentas de servicio

```
Get-ADUser -Filter * | Select-Object SamAccountName
```

```
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName |
Select-Object SamAccountName, ServicePrincipalName
```

### Paso 3. Identificar grupos y privilegios

```
Get-ADGroup -Filter * | Select-Object Name
```

```
Get-ADGroupMember -Identity "Domain Admins" -Recursive
```

Con PowerView:

```
Get-DomainGroupMember -Identity "Domain Admins" -Recurse
```

### Paso 4. Revisar relaciones de confianza

```
Get-ADTrust -Filter *
```

Con PowerView:

```
Get-DomainTrustMapping
```

### Paso 5. Comprobar el acceso administrativo

```
Test-AdminAccess -ComputerName <EQUIPO>
```

Con PowerView, para buscar otros equipos donde el usuario actual tenga administración local:

```
Find-LocalAdminAccess
```

### Paso 6. Revisar los recursos compartidos

```
Get-NetShare
```

```
Find-DomainShare
```

```
Find-InterestingDomainShareFile
```

Para ampliar la búsqueda de archivos potencialmente sensibles, utilizar Snaffler:

```
.\Snaffler.exe -s -d <DOMINIO> -o snaffler.log -v data
```

### Paso 7. Recopilar y correlacionar los datos

```
.\SharpHound.exe -c All --zipfilename <NOMBRE_ARCHIVO>
```

Importar el ZIP en BloodHound y revisar:

- Relaciones de confianza.
    
- Membresías directas y anidadas.
    
- Permisos sobre objetos.
    
- Derechos de administrador local.
    
- Equipos obsoletos.
    
- Posibles rutas de ataque.
    

### Paso 8. Documentar los hallazgos

Registrar:

- Usuarios, grupos y equipos relevantes.
    
- Permisos excesivos.
    
- Cuentas de servicio con privilegios.
    
- Recursos compartidos con datos sensibles.
    
- Relaciones de confianza.
    
- Evidencias de cada hallazgo.
    
- Riesgo e impacto potencial.
    
- Recomendaciones de corrección.
    

También conviene documentar las herramientas y los archivos transferidos durante la evaluación, así como sus ubicaciones, y limpiar los artefactos de prueba al finalizar cuando corresponda.

# 10. Conceptos clave para el examen

- **ActiveDirectory:** módulo integrado de PowerShell para consultar objetos de AD cuando está disponible.
    
- **PowerView:** herramienta de enumeración avanzada que facilita consultas de dominio, grupos, ACL, equipos, sesiones y recursos compartidos.
    
- **SharpView:** implementación en .NET de muchas funciones similares a PowerView.
    
- **SPN:** una cuenta de usuario con SPN configurado puede ser candidata a Kerberoasting.
    
- **Grupos anidados:** pueden conceder privilegios indirectos que no se aprecian mirando únicamente la membresía directa.
    
- **Relaciones de confianza:** permiten relaciones entre dominios, pero su existencia no demuestra por sí sola que exista una ruta explotable.
    
- **Snaffler:** automatiza la búsqueda de archivos potencialmente sensibles en recursos compartidos accesibles.
    
- **SharpHound:** recopila información sobre el dominio para analizarla con BloodHound.
    
- **BloodHound:** correlaciona relaciones y permisos para identificar posibles rutas de ataque y configuraciones incorrectas.
    
- **Documentación:** no todos los hallazgos tienen que servir para escalar privilegios; la exposición de datos, los permisos excesivos y los sistemas obsoletos también pueden ser importantes para el informe.
