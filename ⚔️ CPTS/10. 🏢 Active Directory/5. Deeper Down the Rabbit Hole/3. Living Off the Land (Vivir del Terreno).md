
## 1. Concepto de Living Off the Land (LotL)

**Living Off the Land (LotL)** consiste en utilizar herramientas y funcionalidades nativas de Windows y Active Directory para enumerar un entorno sin necesidad de introducir herramientas externas.

Es especialmente útil cuando:

- No tenemos acceso a Internet desde el equipo comprometido.
    
- No podemos transferir herramientas al host.
    
- Queremos aprovechar las utilidades que ya existen en Windows.
    
- Necesitamos recopilar información del host, la red y el dominio.
    
- Queremos reducir la cantidad de herramientas externas introducidas en el entorno.
    

> **Importante:** utilizar herramientas nativas no garantiza pasar desapercibido. Los comandos de Windows y PowerShell pueden generar registros y alertas en soluciones de seguridad como EDR, IDS/IPS y sistemas de monitorización.

## 2. Enumeración básica del host

### 2.1. Comandos esenciales

|Comando|Información obtenida|
|---|---|
|`hostname`|Nombre del equipo.|
|`[System.Environment]::OSVersion.Version`|Versión del sistema operativo.|
|`systeminfo`|Información general del equipo, SO, revisiones y configuración.|
|`wmic qfe get Caption,Description,HotFixID,InstalledOn`|Parches y actualizaciones instalados.|
|`ipconfig /all`|Interfaces de red, direcciones IP, DNS y configuración de red.|
|`set`|Variables de entorno de la sesión CMD.|
|`echo %USERDOMAIN%`|Dominio asociado al contexto actual en CMD.|
|`echo %logonserver%`|Servidor de inicio de sesión utilizado en CMD.|
|`whoami`|Identidad del usuario o contexto de seguridad actual.|
|`qwinsta`|Sesiones iniciadas en el equipo.|

**Comando recomendado para una primera revisión:**

```
systeminfo
```

Proporciona una visión general del sistema sin tener que ejecutar cada consulta por separado.

### 2.2. Consultar variables de entorno en PowerShell

```
Get-ChildItem Env: | Format-Table Key,Value
```

Permite identificar información como:

- `COMPUTERNAME`: nombre del equipo.
    
- `USERDOMAIN`: dominio asociado al contexto.
    
- `USERNAME`: usuario actual.
    
- `USERPROFILE`: directorio del perfil.
    
- `APPDATA`: directorio de datos de aplicaciones.
    
- `TEMP` y `TMP`: directorios temporales.
    
- `PATH`: rutas en las que se buscan ejecutables.
    

**Nota:** si la sesión se ejecuta como `SYSTEM`, las variables y rutas del perfil pueden corresponder a la cuenta del sistema, no a un usuario interactivo.

### 2.3. Consultar módulos y políticas de PowerShell

```
Get-Module
Get-Module -ListAvailable
Get-ExecutionPolicy -List
```

- `Get-Module`: muestra los módulos cargados.
    
- `Get-Module -ListAvailable`: muestra los módulos disponibles.
    
- `Get-ExecutionPolicy -List`: consulta las políticas de ejecución por ámbito.
    

Para comprobar la versión de PowerShell:

```
Get-Host
$PSVersionTable
```

### 2.4. Historial de comandos de PowerShell

```
Get-Content "$env:APPDATA\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt"
```

El historial puede revelar:

- Comandos ejecutados anteriormente.
    
- Rutas de scripts y archivos de configuración.
    
- Nombres de equipos y recursos.
    
- Información sensible introducida accidentalmente en comandos.
    

La ruta depende del usuario y del contexto de ejecución. Si la sesión se ejecuta como `SYSTEM`, el historial consultado puede no ser el del usuario que inició sesión de forma interactiva.

## 3. Seguridad operacional y registros de PowerShell

### 3.1. Registro de bloques de script

Windows PowerShell puede registrar las instrucciones ejecutadas cuando está habilitado **Script Block Logging**.

Ubicación en el Visor de eventos:

`Applications and Services Logs > Microsoft > Windows > PowerShell > Operational`

Un evento importante es el **4104**, asociado al registro de bloques de script.

También puede consultarse:

`Windows PowerShell`

El evento **400** puede proporcionar información sobre el inicio de una sesión de PowerShell.

### 3.2. PowerShell 2.0 y sus limitaciones

El material de HTB presenta la posibilidad de iniciar una sesión con una versión antigua de PowerShell:

```
powershell.exe -Version 2
```

La finalidad del ejemplo es mostrar que las versiones antiguas pueden carecer de determinadas capacidades de registro incorporadas en versiones posteriores.

**Puntos importantes:**

- PowerShell 2.0 no dispone de Script Block Logging como PowerShell 3.0 y posteriores.
    
- El intento de iniciar una versión antigua puede quedar registrado.
    
- Los defensores pueden detectar el uso de versiones antiguas o investigar la ausencia de registros esperados.
    
- El comportamiento real depende de la versión instalada, las características habilitadas y las políticas de seguridad.
    

No debe asumirse que este método elimina todos los registros ni que está disponible en sistemas actuales.

### 3.3. Política de ejecución

El módulo también muestra este comando:

```
Set-ExecutionPolicy Bypass -Scope Process
```

`-Scope Process` limita el cambio al proceso actual de PowerShell; no establece una política permanente para todo el sistema.

Sin embargo, **Bypass no desactiva todas las defensas de Windows** ni garantiza que cualquier script pueda ejecutarse. Las políticas de grupo y otros controles pueden seguir aplicándose.

## 4. Comprobación de las defensas del host

### 4.1. Estado del Firewall de Windows

```
netsh advfirewall show allprofiles
```

Muestra la configuración de los perfiles:

- `Domain`
    
- `Private`
    
- `Public`
    

Permite revisar:

- Si el firewall está habilitado.
    
- Las políticas de tráfico entrante y saliente.
    
- El estado de las reglas locales.
    
- La configuración de registro de conexiones permitidas y descartadas.
    

**Importante:** que el firewall local aparezca desactivado no significa que el equipo esté desprotegido. Puede haber filtrado de red, reglas centralizadas u otros controles.

### 4.2. Comprobar el servicio de Windows Defender

Desde CMD:

```
sc query windefend
```

Muestra el estado del servicio asociado a Microsoft Defender Antivirus.

### 4.3. Consultar el estado de Microsoft Defender

Desde PowerShell:

```
Get-MpComputerStatus
```

Entre los campos que pueden resultar relevantes están:

|Campo|Significado|
|---|---|
|`AMServiceEnabled`|Estado del servicio antimalware.|
|`AntivirusEnabled`|Estado de la protección antivirus.|
|`AntispywareEnabled`|Estado de la protección antispyware.|
|`BehaviorMonitorEnabled`|Estado de la supervisión del comportamiento.|
|`DefenderSignaturesOutOfDate`|Indica si las firmas están desactualizadas.|
|`AntivirusSignatureAge`|Antigüedad de las firmas antivirus.|
|`IsTamperProtected`|Estado de la protección contra alteraciones.|
|`FullScanAge`|Antigüedad del último análisis completo, cuando está disponible.|

Esta información permite identificar posibles problemas de configuración y documentarlos durante una evaluación.

## 5. Comprobar si hay otros usuarios conectados

Antes de realizar pruebas en un host compartido, conviene identificar las sesiones activas.

```
qwinsta
```

También puede utilizarse:

```
query user
```

La información puede incluir:

- Nombre de usuario.
    
- Identificador de sesión.
    
- Estado de la sesión.
    
- Sesiones de consola y RDP.
    

Una sesión activa puede indicar que otra persona está utilizando el equipo. Esto es relevante para evitar interrupciones, pérdida de acceso o interferencias durante una evaluación autorizada.

## 6. Enumeración de red

### 6.1. Comandos principales

|Comando|Utilidad|
|---|---|
|`ipconfig /all`|Identificar interfaces, direcciones IP, DNS y configuración de red.|
|`arp -a`|Consultar las entradas almacenadas en la caché ARP.|
|`route print`|Consultar las tablas de rutas IPv4 e IPv6.|
|`netsh advfirewall show allprofiles`|Revisar el estado y la configuración del firewall local.|

### 6.2. Tabla ARP

```
arp -a
```

Muestra las asociaciones conocidas entre direcciones IP y direcciones MAC.

Ejemplo:

```
Interface: 172.16.5.25

Internet Address      Physical Address
172.16.5.5            00-50-56-b9-08-26
172.16.5.130          00-50-56-b9-f0-e1
172.16.5.240          00-50-56-b9-9d-66
```

**¿Qué debemos buscar?**

- Direcciones IP de otros equipos.
    
- Posibles controladores de dominio.
    
- Equipos internos que puedan ser relevantes para la evaluación.
    
- Interfaces asociadas a diferentes segmentos de red.
    

La caché ARP no enumera toda la red: muestra las asociaciones presentes en la caché para las interfaces correspondientes. Las entradas dinámicas pueden caducar.

### 6.3. Tabla de rutas

```
route print
```

Muestra las rutas conocidas por el sistema, las interfaces utilizadas y las puertas de enlace.

Ejemplo simplificado:

```
Network Destination    Netmask          Gateway       Interface
0.0.0.0                0.0.0.0          10.129.0.1    10.129.201.234
10.129.0.0             255.255.0.0      On-link       10.129.201.234
172.16.4.0             255.255.254.0    On-link       172.16.5.25
```

Conceptos importantes:

- **Network Destination:** destino de la ruta.
    
- **Netmask:** máscara de red.
    
- **Gateway:** puerta de enlace para alcanzar el destino.
    
- **Interface:** interfaz de salida.
    
- **Metric:** valor utilizado para decidir entre rutas adecuadas.
    

En el ejemplo aparecen interfaces de dos redes distintas. Esto puede indicar que el host tiene conectividad con varios segmentos.

**Aplicación en pentesting:** identificar redes accesibles desde el host y estudiar posibles rutas de pivoting. Una ruta conocida no garantiza que los servicios de esa red sean accesibles.

## 7. Windows Management Instrumentation (WMI)

**WMI** es una tecnología de Windows utilizada para consultar información del sistema y realizar tareas administrativas, tanto localmente como de forma remota cuando existen los permisos y la conectividad necesarios.

### 7.1. Comandos WMI importantes

|Comando|Información|
|---|---|
|`wmic qfe get Caption,Description,HotFixID,InstalledOn`|Parches instalados.|
|`wmic computersystem get Name,Domain,Manufacturer,Model,Username,Roles /format:List`|Información del equipo y del dominio.|
|`wmic process list /format:list`|Procesos del sistema.|
|`wmic ntdomain list /format:list`|Información sobre dominios y controladores de dominio detectados por WMI.|
|`wmic useraccount list /format:list`|Información sobre cuentas de usuario visibles para la consulta.|
|`wmic group list /format:list`|Información sobre grupos locales.|
|`wmic sysaccount list /format:list`|Información sobre cuentas del sistema.|

### 7.2. Consultar dominios y controladores de dominio

```
wmic ntdomain get Caption,Description,DnsForestName,DomainName,DomainControllerAddress
```

Permite obtener información sobre los dominios que aparecen en la consulta, incluidos sus nombres y direcciones de controladores de dominio cuando están disponibles.

Ejemplo de la información mostrada por HTB:

```
Caption          DnsForestName             DomainControllerAddress
INLANEFREIGHT    INLANEFREIGHT.LOCAL       \\172.16.5.5
LOGISTICS        INLANEFREIGHT.LOCAL       \\172.16.5.240
FREIGHTLOGISTIC  FREIGHTLOGISTICS.LOCAL    \\172.16.5.238
```

**Nota:** `wmic.exe` está obsoleto en versiones modernas de Windows y puede no estar disponible. WMI sigue existiendo; pueden utilizarse alternativas como `Get-CimInstance` cuando proceda.

## 8. Enumeración de Active Directory con comandos Net

Los comandos `net.exe` permiten consultar información local y del dominio sin depender de herramientas externas.

### 8.1. Política de contraseñas

```
net accounts
net accounts /domain
```

- `net accounts`: información de las políticas de cuentas locales.
    
- `net accounts /domain`: información de la política de cuentas del dominio.
    

Se pueden obtener datos relacionados con la duración de las contraseñas y el bloqueo de cuentas.

### 8.2. Enumerar usuarios

```
net user
net user /domain
net user %username%
net user wrouse /domain
```

- `net user`: lista usuarios locales.
    
- `net user /domain`: lista usuarios del dominio.
    
- `net user %username%`: consulta la cuenta indicada por la variable de entorno.
    
- `net user wrouse /domain`: consulta información sobre un usuario concreto.
    

La salida de la consulta de dominio puede mostrar:

- Estado de la cuenta.
    
- Fechas relacionadas con la contraseña.
    
- Último inicio de sesión, si está disponible.
    
- Grupos a los que pertenece el usuario.
    

### 8.3. Enumerar grupos

```
net localgroup
net group /domain
net group "Domain Admins" /domain
net group "Domain Computers" /domain
net group "Domain Controllers" /domain
net group "NOMBRE_DEL_GRUPO" /domain
```

|Comando|Utilidad|
|---|---|
|`net localgroup`|Lista los grupos locales.|
|`net group /domain`|Lista grupos del dominio.|
|`net group "Domain Admins" /domain`|Consulta los miembros del grupo Domain Admins.|
|`net group "Domain Computers" /domain`|Consulta el grupo Domain Computers.|
|`net group "Domain Controllers" /domain`|Consulta el grupo Domain Controllers.|
|`net group "NOMBRE_DEL_GRUPO" /domain`|Consulta los miembros de un grupo específico.|

### 8.4. Administradores locales

```
net localgroup Administrators
```

Muestra los miembros del grupo local de administradores del equipo.

**Importante:** no confundas el grupo local `Administrators` con el grupo de dominio `Domain Admins`. La pertenencia a `Domain Admins` suele proporcionar privilegios elevados en el dominio, pero no debe deducirse la configuración efectiva de un equipo únicamente a partir del nombre de un grupo.

### 8.5. Recursos compartidos

```
net share
net view
net view /domain
net view \\NOMBRE_DEL_EQUIPO /ALL
```

Permiten consultar recursos compartidos locales, equipos visibles y recursos compartidos anunciados por otros equipos, dependiendo de los permisos, la resolución de nombres y la conectividad.

### 8.6. Conectar una unidad de red

```
net use X: \\NOMBRE_DEL_EQUIPO\NOMBRE_DEL_RECURSO
```

Asocia el recurso compartido indicado a una letra de unidad local.

### 8.7. Precaución con los comandos Net

Los comandos `net.exe` pueden ser monitorizados por EDR y otras herramientas de seguridad.

Aunque algunas fuentes proponen variantes como `net1`, **no debe asumirse que cambiar el nombre del ejecutable evita la detección**. El comportamiento de monitorización depende de las reglas, los registros y la telemetría disponible.

## 9. Dsquery: consultas nativas de Active Directory

`dsquery` es una utilidad de línea de comandos para buscar objetos de Active Directory.

Está disponible en equipos que tengan instaladas las herramientas necesarias de AD DS o las herramientas administrativas correspondientes. No debe asumirse que el ejecutable está disponible en todos los equipos Windows.

### 9.1. Buscar usuarios

```
dsquery user
```

Devuelve los nombres distinguidos (DN) de los objetos de usuario encontrados.

Ejemplo:

```
CN=Administrator,CN=Users,DC=INLANEFREIGHT,DC=LOCAL
CN=Htb Student,CN=Users,DC=INLANEFREIGHT,DC=LOCAL
CN=Annie Vazquez,OU=Finance,OU=Financial-LON,OU=Employees,OU=Corp,DC=INLANEFREIGHT,DC=LOCAL
```

### 9.2. Buscar equipos

```
dsquery computer
```

Permite enumerar objetos de equipo del dominio.

Ejemplo:

```
CN=ACADEMY-EA-DC01,OU=Domain Controllers,DC=INLANEFREIGHT,DC=LOCAL
CN=ACADEMY-EA-MS01,OU=Web Servers,OU=Servers,OU=Computers,OU=Corp,DC=INLANEFREIGHT,DC=LOCAL
CN=SQL01,OU=SQL Servers,OU=Servers,OU=Computers,OU=Corp,DC=INLANEFREIGHT,DC=LOCAL
```

La ubicación del objeto en el DN puede revelar la OU a la que pertenece y ayudar a identificar la función del equipo.

### 9.3. Buscar objetos dentro de un contenedor

```
dsquery * "CN=Users,DC=INLANEFREIGHT,DC=LOCAL"
```

Busca objetos bajo el contenedor especificado.

El asterisco `*` indica que se quieren consultar distintos tipos de objetos, en lugar de limitar la búsqueda a usuarios o equipos.

### 9.4. Limitar resultados y seleccionar atributos

Ejemplo del módulo:

```
dsquery * -filter "(userAccountControl:1.2.840.113556.1.4.803:=8192)" -limit 5 -attr sAMAccountName
```

Este filtro busca objetos cuyo atributo `userAccountControl` tenga establecido el bit `8192`, asociado a `SERVER_TRUST_ACCOUNT`, utilizado normalmente por cuentas de equipo de controladores de dominio.

El parámetro `-limit 5` limita los resultados a cinco objetos y `-attr sAMAccountName` selecciona el atributo que se quiere mostrar.

**Importante:** el filtro busca el bit indicado; no demuestra por sí solo que el controlador de dominio esté disponible o funcionando correctamente.

## 10. Filtros LDAP y userAccountControl (UAC)

Los filtros LDAP permiten combinar criterios y localizar objetos con atributos concretos.

### 10.1. Buscar cuentas con PASSWD_NOTREQD

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=32))" -attr distinguishedName userAccountControl
```

El filtro busca objetos que cumplan estos criterios:

- `objectCategory=person`
    
- `objectClass=user`
    
- El bit `32` de `userAccountControl` está establecido.
    

El bit `32` corresponde a `PASSWD_NOTREQD`, que indica que la cuenta no requiere contraseña según ese atributo.

**Precaución:** encontrar este atributo no significa necesariamente que la cuenta tenga una contraseña vacía. Es un indicador que debe investigarse junto con la configuración y el estado real de la cuenta.

### 10.2. Valores UAC importantes

|Valor decimal|Indicador|
|---|---|
|`32`|`PASSWD_NOTREQD`: la contraseña no es obligatoria según el atributo.|
|`64`|`PASSWD_CANT_CHANGE`: indicador relacionado con la imposibilidad de cambiar la contraseña; su aplicación efectiva también depende de permisos y ACL.|
|`8192`|`SERVER_TRUST_ACCOUNT`: cuenta de equipo utilizada normalmente por un controlador de dominio.|

Los valores UAC son máscaras de bits. Un mismo objeto puede tener varios indicadores establecidos simultáneamente, por lo que el valor decimal total puede ser la suma de varios bits.

### 10.3. Reglas de coincidencia LDAP

|OID|Función|
|---|---|
|`1.2.840.113556.1.4.803`|Coincide cuando están establecidos todos los bits especificados en la máscara.|
|`1.2.840.113556.1.4.804`|Coincide cuando está establecido al menos uno de los bits especificados.|
|`1.2.840.113556.1.4.1941`|Coincidencia transitiva para DN, útil para recorrer relaciones como pertenencias anidadas a grupos.|

### 10.4. Operadores lógicos LDAP

|Operador|Significado|
|---|---|
|`&`|AND: todos los criterios deben cumplirse.|
|`|`|OR: debe cumplirse al menos uno de los criterios.|
|`!`|NOT: niega el criterio indicado.|

**Ejemplo: buscar usuarios con el bit 64 establecido**

```
(&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=64))
```

**Ejemplo: buscar usuarios que no tengan establecido el bit 64**

```
(&(objectClass=user)(!userAccountControl:1.2.840.113556.1.4.803:=64))
```

Estos filtros pueden adaptarse para buscar otros atributos y estados de cuentas de Active Directory.

## 11. Flujo de trabajo recomendado para el laboratorio

### Paso 1: identificar el host y el contexto actual

```
hostname
whoami
systeminfo
ipconfig /all
```

Objetivo: conocer el equipo, la identidad actual, el sistema operativo y sus interfaces de red.

### Paso 2: comprobar las sesiones existentes

```
qwinsta
```

Objetivo: identificar sesiones activas antes de continuar las pruebas.

### Paso 3: revisar las rutas y los hosts conocidos

```
arp -a
route print
```

Objetivo: identificar otros equipos conocidos por el host y las redes a las que tiene rutas configuradas.

### Paso 4: comprobar las defensas

```
netsh advfirewall show allprofiles
sc query windefend
```

Desde PowerShell:

```
Get-MpComputerStatus
Get-ExecutionPolicy -List
```

Objetivo: documentar la configuración visible del firewall, Defender y PowerShell.

### Paso 5: enumerar usuarios, grupos y equipos

```
net user /domain
net group /domain
net group "Domain Admins" /domain
net group "Domain Controllers" /domain
net accounts /domain
```

Objetivo: recopilar información sobre cuentas, grupos privilegiados, equipos y política de contraseñas.

### Paso 6: buscar objetos con Dsquery

```
dsquery user
dsquery computer
dsquery * "CN=Users,DC=INLANEFREIGHT,DC=LOCAL"
```

Objetivo: obtener objetos y sus nombres distinguidos para entender la estructura del dominio.

### Paso 7: aplicar filtros LDAP

Ejemplo para buscar cuentas con `PASSWD_NOTREQD`:

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=32))" -attr distinguishedName userAccountControl
```

Objetivo: identificar cuentas que requieren una revisión adicional.

## 13. Conceptos clave que debes recordar

1. **Living Off the Land:** utilizar herramientas nativas de Windows para enumerar el entorno sin depender de herramientas externas.
    
2. `**systeminfo**`**:** proporciona una visión general del host y de su configuración.
    
3. **PowerShell:** permite consultar módulos, variables de entorno, políticas e información del sistema.
    
4. **Script Block Logging:** puede registrar comandos y bloques de script; el evento 4104 es especialmente relevante.
    
5. `**arp -a**`**:** muestra las asociaciones IP-MAC presentes en la caché ARP, no todos los hosts de la red.
    
6. `**route print**`**:** revela las redes y puertas de enlace conocidas por el equipo.
    
7. **WMI:** permite consultar información de equipos, procesos, cuentas y dominios.
    
8. **Comandos Net:** permiten enumerar usuarios, grupos, equipos, políticas y recursos compartidos.
    
9. **Dsquery:** permite buscar objetos de Active Directory sin depender de PowerView o BloodHound.
    
10. **Filtros LDAP:** combinan criterios para localizar objetos con atributos específicos.
    
11. **UAC:** utiliza indicadores de bits; los valores pueden combinarse.
    
12. **OID** `**1.2.840.113556.1.4.803**`**:** comprueba que estén establecidos todos los bits indicados.
    
13. **OID** `**1.2.840.113556.1.4.804**`**:** comprueba si está establecido alguno de los bits indicados.
    
14. **OID** `**1.2.840.113556.1.4.1941**`**:** permite realizar coincidencias transitivas en relaciones de DN.
    
15. **Enumeración no equivale a explotación:** encontrar usuarios, rutas, grupos o configuraciones interesantes proporciona pistas que deben validarse antes de extraer conclusiones.
