
## Objetivos del reconocimiento externo

El **reconocimiento externo (External Reconnaissance)** permite recopilar información pública sobre una organización antes de comenzar un pentest.

Objetivos principales:

- Validar la información proporcionada por el cliente y confirmar el alcance.
    
- Identificar infraestructura pública relacionada con el objetivo.
    
- Encontrar posibles credenciales filtradas en brechas de datos.
    
- Descubrir nombres de usuario, correos electrónicos y convenciones de nomenclatura.
    
- Identificar tecnologías, servicios y posibles puntos de entrada.
    
- Localizar información sensible publicada accidentalmente en documentos, repositorios o servicios de almacenamiento.
    

El reconocimiento es un proceso iterativo: recopilamos información, analizamos los resultados y utilizamos los hallazgos para orientar las siguientes fases de enumeración.

## 2. ¿Qué información buscamos?

|Categoría|Información que buscamos|
|---|---|
|**IP Space**|ASN, bloques de red, direcciones IP públicas, proveedores de hosting y registros DNS.|
|**Domain Information**|Dominios, subdominios, servidores DNS, correo, VPN y servicios expuestos.|
|**Schema Format**|Formato de correos electrónicos, nombres de usuario y posibles políticas de contraseñas.|
|**Data Disclosures**|Documentos públicos, metadatos, enlaces internos, recursos compartidos y credenciales expuestas.|
|**Breach Data**|Nombres de usuario, contraseñas y hashes procedentes de filtraciones de datos.|

### IP Space y ASN

Un **ASN (Autonomous System Number)** identifica un sistema autónomo que anuncia bloques de direcciones IP.

Podemos investigar la infraestructura pública mediante:

- Hurricane Electric BGP Toolkit.
    
- IANA.
    
- ARIN, principalmente para recursos de Norteamérica.
    
- RIPE, principalmente para recursos de Europa.
    
- BGP Toolkit y registros públicos de IP.
    

La información obtenida puede revelar direcciones IP, bloques de red, proveedores y servicios relacionados con el objetivo.

**Importante:** una dirección IP relacionada con el dominio no implica automáticamente que esté dentro del alcance autorizado. Si la infraestructura pertenece a un proveedor externo, debemos confirmar que las pruebas están permitidas.

## 3. Enumeración de DNS

DNS permite identificar infraestructura relacionada con un dominio y validar información recopilada previamente.

### Recursos útiles

- DomainTools.
    
- ViewDNS.info.
    
- Registros DNS públicos.
    
- Consultas directas a servidores DNS.
    

### Consultar servidores de nombres

```
nslookup ns1.inlanefreight.com
nslookup ns2.inlanefreight.com
```

Estas consultas permiten obtener las direcciones IP asociadas a los servidores de nombres.

### Registros que debemos investigar

|Registro|Función|
|---|---|
|`A`|Asocia un nombre con una dirección IPv4.|
|`AAAA`|Asocia un nombre con una dirección IPv6.|
|`MX`|Identifica servidores de correo.|
|`NS`|Identifica servidores de nombres DNS.|
|`SOA`|Contiene información administrativa de la zona DNS.|
|`PTR`|Permite resolver una dirección IP hacia un nombre mediante DNS inverso.|

### Reverse IP Lookup

Una búsqueda inversa de IP puede mostrar otros dominios que resuelven a la misma dirección IP.

Esto puede ayudar a descubrir relaciones entre dominios, aunque los resultados deben validarse porque pueden estar desactualizados o corresponder a infraestructura compartida.

**Herramientas:**

- ViewDNS.info.
    
- DomainTools.
    
- `nslookup`.

## 4. Recopilación de información pública

Las redes sociales, las ofertas de trabajo y las páginas web corporativas pueden revelar información útil sobre el entorno tecnológico de una organización.

### Redes sociales y ofertas de trabajo

Fuentes relevantes:

- LinkedIn.
    
- Indeed.
    
- Glassdoor.
    
- Twitter/X.
    
- Facebook.
    
- Instagram.
    

Podemos identificar:

- Tecnologías utilizadas por la empresa.
    
- Versiones de software mencionadas en ofertas de trabajo.
    
- Herramientas de administración y seguridad.
    
- Estructura organizativa.
    
- Nombres de empleados y posibles cuentas corporativas.
    

Por ejemplo, una oferta de trabajo que mencione SharePoint 2013 o SharePoint 2016 puede proporcionar una pista sobre las tecnologías utilizadas por la organización.

Sin embargo, estas referencias no demuestran por sí solas qué versiones siguen instaladas actualmente.

### Páginas web corporativas

Conviene revisar:

- Páginas de contacto.
    
- Páginas de empleados.
    
- Secciones «Sobre nosotros».
    
- Documentos publicados.
    
- Enlaces a intranets y portales corporativos.
    
- Información de contacto y organigramas.
    

Los documentos públicos pueden contener metadatos que revelen nombres de usuarios, nombres de equipos, software utilizado o referencias a recursos internos.

## 5. Google Dorks

Los operadores de búsqueda permiten localizar documentos y datos publicados en páginas web.

### Buscar documentos PDF

```
filetype:pdf inurl:inlanefreight.com
```

Busca documentos PDF asociados al dominio indicado.

### Buscar direcciones de correo electrónico

```
intext:"@inlanefreight.com" inurl:inlanefreight.com
```

Busca páginas del dominio que contengan el texto `@inlanefreight.com`.

### ¿Qué hacemos cuando encontramos documentos?

1. Anotar la URL y la ubicación del documento.
    
2. Descargar una copia local.
    
3. Revisar su contenido y sus metadatos.
    
4. Identificar nombres, correos, tecnologías y referencias a recursos internos.
    
5. Guardar los resultados para utilizarlos durante las siguientes fases del pentest.
    

Es importante conservar evidencias y resultados desde el principio para evitar perder información útil.

## 6. Recolección de nombres de usuario

Una vez identificados nombres de empleados y direcciones de correo, podemos deducir las convenciones de nomenclatura utilizadas por la organización.

Por ejemplo, si encontramos:

```
emma.williams@inlanefreight.com
john.smith@inlanefreight.com
```

Podemos inferir un posible formato:

```
nombre.apellido
```

También podrían existir otros formatos, como:

```
ninicialapellido
nombreapellido
n.apellido
```

Estas variantes son hipótesis que debemos validar.

### Herramienta: linkedin2username

Permite generar posibles nombres de usuario a partir de información pública de empleados.

La lista resultante puede utilizarse durante la enumeración de cuentas, siempre dentro del alcance autorizado.

## 7. Búsqueda de credenciales filtradas

Las filtraciones de datos pueden contener contraseñas en texto claro, hashes y nombres de usuario.

### Recursos mencionados

|Recurso|Utilidad|
|---|---|
|**Have I Been Pwned**|Comprobar si una cuenta de correo aparece en brechas conocidas.|
|**DeHashed**|Buscar información procedente de bases de datos filtradas.|
|**TruffleHog**|Detectar secretos y credenciales expuestos en repositorios y fuentes compatibles.|
|**GitHub**|Investigar repositorios públicos que puedan contener información sensible.|
|**GreyHat Warfare**|Buscar archivos expuestos en servicios de almacenamiento en la nube.|

### Información que podemos encontrar

- Nombres de usuario.
    
- Direcciones de correo.
    
- Contraseñas en texto claro.
    
- Hashes de contraseñas.
    
- Credenciales antiguas.
    
- Información sobre servicios y aplicaciones.
    

Una contraseña filtrada puede estar obsoleta, por lo que no debemos asumir que sigue siendo válida.

### Ejemplo de DeHashed

El módulo muestra una consulta mediante un script:

```
sudo python3 dehashed.py -q inlanefreight.local -p
```

El ejemplo devuelve registros que pueden incluir:

```
email
username
password
hashed_password
name
database_name
```

**Nota:** el módulo advierte que los cambios en la API de DeHashed pueden requerir modificaciones en el script utilizado.

## 8. Proceso práctico de enumeración externa

El proceso recomendado consiste en comenzar con información amplia e ir reduciendo el ámbito de investigación.

### Fase 1: Recopilación pasiva

Buscar información pública sin realizar escaneos intrusivos:

- Dominios y subdominios.
    
- Registros DNS.
    
- Direcciones IP y ASN.
    
- Redes sociales y ofertas de trabajo.
    
- Documentos públicos.
    
- Correos electrónicos y nombres de empleados.
    
- Credenciales filtradas.
    

### Fase 2: Validación de resultados

Contrastar los datos obtenidos utilizando varias fuentes.

Por ejemplo:

1. Obtener una IP mediante BGP Toolkit.
    
2. Comprobarla mediante una búsqueda inversa de IP.
    
3. Validar los servidores de nombres mediante `nslookup`.
    
4. Registrar los resultados y sus fuentes.
    

### Fase 3: Análisis de hallazgos

Determinar qué información puede resultar útil:

- ¿Existe una convención de nombres de usuario?
    
- ¿Hay documentos con metadatos relevantes?
    
- ¿Se han expuesto credenciales?
    
- ¿Qué tecnologías utiliza la organización?
    
- ¿Se han encontrado servicios o dominios que deban validarse con el cliente?
    

### Fase 4: Enumeración activa

Una vez agotada la recopilación pasiva, podemos realizar comprobaciones activas autorizadas para validar los hallazgos y obtener más información.

Las acciones deben ajustarse al alcance y a las reglas de enfrentamiento (_Rules of Engagement_).

## 10. Consideraciones importantes durante un pentest

- **Validar siempre el alcance:** no todas las IP relacionadas con un dominio están autorizadas para realizar pruebas.
    
- **Tener en cuenta la infraestructura de terceros:** los servicios pueden estar alojados en AWS, Azure, Google Cloud o proveedores compartidos.
    
- **No asumir que los datos están actualizados:** los registros DNS, las credenciales y la información pública pueden ser antiguos.
    
- **Guardar las evidencias:** conservar documentos, capturas, resultados y fuentes.
    
- **Comenzar con reconocimiento pasivo:** después, pasar a la enumeración activa según los permisos disponibles.
    
- **Confirmar las hipótesis:** una oferta de trabajo, un correo o un registro DNS puede proporcionar una pista, pero no siempre confirma la configuración actual.
    
- **Revisar las reglas de enfrentamiento:** si existe alguna duda sobre la autorización para probar un servicio, debe aclararse antes de actuar.

## Conceptos clave para el examen

- **External Reconnaissance:** recopilación de información pública sobre un objetivo antes de realizar pruebas.
    
- **ASN:** identificador de un sistema autónomo que anuncia bloques de direcciones IP.
    
- **Netblock:** bloque o rango de direcciones IP.
    
- **Reverse IP Lookup:** búsqueda de dominios asociados a una dirección IP.
    
- **Google Dorks:** operadores de búsqueda para localizar información específica.
    
- **Data Disclosure:** exposición involuntaria de información.
    
- **Breach Data:** información procedente de filtraciones de datos.
    
- **Schema Format:** convención de nombres de usuario o direcciones de correo.
    
- **Passive Recon:** recopilación de información sin interactuar directamente de forma intrusiva con los sistemas objetivo.
    
- **Active Enumeration:** comprobaciones directas para validar información y obtener nuevos datos.
    
- **Rules of Engagement:** condiciones y límites autorizados para la evaluación.
    

**Idea fundamental:** el reconocimiento externo permite descubrir información que puede facilitar las siguientes fases de un pentest, pero todos los hallazgos deben validarse y cualquier prueba activa debe mantenerse dentro del alcance autorizado.
