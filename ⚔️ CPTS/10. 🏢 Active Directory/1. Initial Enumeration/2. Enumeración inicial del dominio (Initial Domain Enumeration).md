
## 1. Objetivos de la enumeración interna

El objetivo es identificar los equipos, servicios y posibles vulnerabilidades de una red interna para encontrar una vía de entrada al dominio de Active Directory.

### Información que debemos recopilar

|Dato|Descripción|
|---|---|
|Usuarios de AD|Cuentas válidas que podrían utilizarse para comprobar credenciales.|
|Equipos unidos a AD|Controladores de dominio, servidores SQL, servidores web, servidores de archivos, Exchange, etc.|
|Servicios clave|Kerberos, NetBIOS, LDAP, DNS y SMB.|
|Hosts vulnerables|Equipos con sistemas operativos antiguos, servicios vulnerables o configuraciones inseguras.|
|Credenciales|Contraseñas o hashes que permitan obtener un punto de apoyo (_foothold_).|

### Escenario del laboratorio

- Dominio: `INLANEFREIGHT.LOCAL`
    
- Red autorizada del ejemplo: `172.16.5.0/23`
    
- Controlador de dominio identificado: `172.16.5.5`
    
- Host de ejemplo: `ACADEMY-EA-DC01`
    
- Punto de partida: sin credenciales de dominio.
    
- Enfoque: pruebas internas no evasivas.
    

> Los resultados y direcciones IP de este apartado pertenecen al escenario de HTB. En otros laboratorios pueden cambiar.

## 2. Metodología de enumeración

La enumeración debe realizarse de forma progresiva:

1. Escuchar el tráfico de red para identificar hosts.
    
2. Validar los resultados mediante comprobaciones activas.
    
3. Enumerar puertos y servicios con Nmap.
    
4. Identificar controladores de dominio y equipos críticos.
    
5. Buscar posibles vulnerabilidades y configuraciones inseguras.
    
6. Enumerar usuarios válidos del dominio.
    
7. Documentar los resultados y buscar un punto de apoyo.
    

Es importante guardar las salidas de las herramientas para poder analizarlas posteriormente y reutilizarlas en otras fases.

---

## 3. Identificación pasiva de hosts

La enumeración pasiva permite observar la actividad de la red sin iniciar un escaneo activo de los objetivos.

### 3.1. Wireshark

Permite capturar y analizar el tráfico de red.

```
sudo -E wireshark
```

En el laboratorio, la captura permitió observar tráfico ARP y MDNS.

**ARP** puede revelar las direcciones IP de equipos que realizan solicitudes dentro del segmento de red.

**MDNS** puede revelar nombres de equipos mediante consultas de resolución de nombres locales.

Ejemplo observado:

```
ACADEMY-EA-WEB01.local
```

### 3.2. Tcpdump

Alternativa para capturar tráfico desde una terminal, especialmente útil cuando no tenemos interfaz gráfica.

```
sudo tcpdump -i ens224
```

Guardar el tráfico en un archivo PCAP:

```
sudo tcpdump -i ens224 -w captura.pcap
```

Leer una captura guardada:

```
tcpdump -r captura.pcap
```

El archivo `.pcap` puede abrirse posteriormente con Wireshark para analizar los paquetes.

### 3.3. Responder en modo análisis

Responder permite escuchar y analizar solicitudes LLMNR, NBT-NS y MDNS, entre otras funciones.

Para escuchar el tráfico sin realizar envenenamiento:

```
sudo responder -I ens224 -A
```

- `-I ens224`: selecciona la interfaz de red.
    
- `-A`: activa el modo de análisis pasivo.
    

Este modo permite identificar nombres de equipos y observar solicitudes de resolución de nombres.

**Importante:** el modo `-A` se utiliza para analizar el tráfico sin enviar respuestas de envenenamiento.

## 4. Identificación activa de hosts con fping

Después de la observación pasiva, podemos realizar un barrido ICMP para identificar equipos que responden a solicitudes de ping.

### Comando

```
fping -asgq 172.16.5.0/23
```

### Parámetros

|Parámetro|Función|
|---|---|
|`-a`|Muestra los hosts activos.|
|`-s`|Muestra estadísticas al finalizar.|
|`-g`|Genera objetivos a partir de una red o rango.|
|`-q`|Reduce la salida durante el escaneo.|

### Ejemplo de resultados

```
172.16.5.5
172.16.5.25
172.16.5.50
172.16.5.100
172.16.5.125
172.16.5.200
172.16.5.225
172.16.5.238
172.16.5.240

510 targets
9 alive
501 unreachable
```

Esto indica que nueve objetivos respondieron a las comprobaciones ICMP del ejemplo.

**Limitación:** un host que no responde a ICMP no tiene por qué estar apagado. Puede bloquear estas solicitudes mediante un firewall.

Por tanto, los resultados de `fping` deben combinarse con la información obtenida mediante tráfico pasivo y otros métodos de enumeración.

## 5. Enumeración de servicios con Nmap

Una vez identificados los hosts, debemos determinar qué puertos están abiertos, qué servicios ejecutan y qué sistemas operativos podrían utilizar.

### 5.1. Preparar una lista de objetivos

Crear un archivo con las direcciones IP identificadas:

```
nano hosts.txt
```

Ejemplo:

```
172.16.5.5
172.16.5.25
172.16.5.50
172.16.5.100
172.16.5.125
```

La lista debe adaptarse a los resultados del laboratorio.

### 5.2. Escanear los objetivos

```
sudo nmap -v -A -iL hosts.txt -oN /home/htb-student/Documents/host-enum
```

|Parámetro|Función|
|---|---|
|`-v`|Aumenta el nivel de detalle de la salida.|
|`-A`|Activa detección de SO, detección de versiones, scripts predeterminados y traceroute.|
|`-iL hosts.txt`|Lee los objetivos desde un archivo.|
|`-oN`|Guarda los resultados en formato normal de Nmap.|

### Guardar los resultados en varios formatos

El módulo recomienda utilizar `-oA` para conservar los resultados en varios formatos:

```
sudo nmap -A -iL hosts.txt -oA /home/htb-student/Documents/host-enum
```

Esto genera archivos con extensiones `.nmap`, `.xml` y `.gnmap`.

El formato XML resulta especialmente útil para procesar resultados mediante otras herramientas.

## 6. Puertos importantes en Active Directory

Durante la enumeración inicial debemos prestar atención a los servicios habituales de AD.

|Puerto TCP/UDP|Servicio|Utilidad|
|---|---|---|
|`53`|DNS|Resolución de nombres y descubrimiento de información del dominio.|
|`88`|Kerberos|Autenticación de Active Directory.|
|`135`|MSRPC|Comunicación mediante RPC de Microsoft.|
|`139`|NetBIOS|Servicios de red heredados de Windows.|
|`389`|LDAP|Consulta y acceso al directorio.|
|`445`|SMB|Compartición de archivos y otros servicios de Windows.|
|`464`|Kerberos kpasswd|Cambio y gestión de contraseñas mediante Kerberos.|
|`636`|LDAPS|LDAP protegido mediante TLS.|
|`3268`|Global Catalog LDAP|Consultas al catálogo global del bosque.|
|`3269`|Global Catalog LDAPS|Acceso protegido al catálogo global.|
|`3389`|RDP|Acceso remoto al escritorio de Windows.|

Los servicios disponibles dependen de la configuración del equipo. No todos los puertos tienen que estar abiertos en cada host.

## 8. Identificar sistemas potencialmente vulnerables

La detección de versiones puede revelar equipos que utilizan sistemas operativos o servicios antiguos.

En el ejemplo del módulo, Nmap identifica:

```
80/tcp    open  http       Microsoft IIS httpd 7.5
445/tcp   open  microsoft-ds
1433/tcp  open  ms-sql-s    Microsoft SQL Server 2008 R2
```

También obtiene información que apunta a:

```
Windows Server 2008 R2 Standard
Microsoft SQL Server 2008 R2 RTM
```

### ¿Por qué es importante?

Los sistemas antiguos pueden presentar:

- Vulnerabilidades conocidas.
    
- Parches ausentes.
    
- Protocolos heredados.
    
- Configuraciones inseguras.
    
- Servicios con versiones obsoletas.
    

El módulo menciona como ejemplos de vulnerabilidades históricas:

- EternalBlue.
    
- MS08-067.
    
- BlueKeep.
    

La detección de un sistema antiguo **no demuestra que sea vulnerable a una explotación concreta**. Es necesario validar la versión exacta, los parches instalados y las condiciones de explotación.

Antes de ejecutar pruebas que puedan causar inestabilidad, debemos obtener autorización expresa del cliente.

## 9. Enumeración de usuarios con Kerbrute

Una vez identificados el controlador de dominio y el dominio DNS, podemos intentar enumerar cuentas de usuario válidas mediante Kerberos.

### ¿Qué es Kerbrute?

Kerbrute es una herramienta que permite realizar enumeración de cuentas de Active Directory y otras comprobaciones relacionadas con Kerberos.

Aprovecha las respuestas del protocolo para identificar nombres de usuario válidos.

El resultado puede utilizarse para construir una lista de usuarios y orientar las siguientes fases de enumeración.

> La enumeración no es completamente invisible: las solicitudes Kerberos pueden generar eventos y alertas. Los fallos de preautenticación también pueden contribuir a los contadores de intentos fallidos y provocar bloqueos según las políticas del dominio.

### 9.1. Descargar el repositorio

```
sudo git clone https://github.com/ropnop/kerbrute.git
```

Entrar en el directorio:

```
cd kerbrute
```

### 9.2. Consultar las opciones de compilación

```
make help
```

En el ejemplo aparecen estas opciones:

```
windows
linux
mac
clean
all
```

### 9.3. Compilar los binarios

Para compilar las versiones disponibles para las distintas plataformas:

```
sudo make all
```

Para compilar únicamente la versión Linux, se puede utilizar:

```
make linux
```

Los binarios compilados se guardan en el directorio `dist/`.

Consultar su contenido:

```
ls -l dist/
```

Ejemplo:

```
kerbrute_darwin_amd64
kerbrute_linux_386
kerbrute_linux_amd64
kerbrute_windows_386.exe
kerbrute_windows_amd64.exe
```

### 9.4. Consultar la ayuda

```
./dist/kerbrute_linux_amd64
```

Esto muestra el uso general de la herramienta y sus comandos disponibles.

### 9.5. Enumerar usuarios

El módulo utiliza el siguiente comando:

```
kerbrute userenum -d INLANEFREIGHT.LOCAL --dc 172.16.5.5 jsmith.txt -o valid_ad_users
```

|Parámetro|Función|
|---|---|
|`userenum`|Realiza enumeración de nombres de usuario.|
|`-d INLANEFREIGHT.LOCAL`|Especifica el dominio.|
|`--dc 172.16.5.5`|Especifica el controlador de dominio.|
|`jsmith.txt`|Wordlist de posibles nombres de usuario.|
|`-o valid_ad_users`|Guarda los resultados en un archivo.|

La wordlist debe existir en el directorio actual o indicarse mediante una ruta válida.

### 9.6. Interpretar los resultados

Ejemplo:

```
[+] VALID USERNAME: jjones@INLANEFREIGHT.LOCAL
[+] VALID USERNAME: sbrown@INLANEFREIGHT.LOCAL
[+] VALID USERNAME: tjohnson@INLANEFREIGHT.LOCAL
[+] VALID USERNAME: evalentin@INLANEFREIGHT.LOCAL
```

En el ejemplo del módulo, Kerbrute encuentra 56 cuentas válidas entre 48.705 nombres probados.

Los resultados permiten construir una lista inicial de usuarios del dominio para las siguientes fases de evaluación.

## 10. ¿Por qué es importante obtener acceso como SYSTEM?

`NT AUTHORITY\SYSTEM` es una cuenta integrada de Windows con privilegios muy elevados sobre el sistema local.

Si obtenemos este contexto en un equipo unido al dominio, podremos realizar determinadas operaciones de enumeración utilizando la identidad de la cuenta de equipo.

El módulo destaca que este acceso puede facilitar la enumeración del dominio, aunque **no equivale automáticamente a tener privilegios de administrador de dominio**.

### Vías de acceso mencionadas en el módulo

- Explotación de vulnerabilidades remotas de Windows.
    
- Abuso de servicios ejecutados como SYSTEM.
    
- Abuso de `SeImpersonatePrivilege` mediante técnicas como Juicy Potato, cuando el sistema y las condiciones lo permiten.
    
- Vulnerabilidades de escalada de privilegios local.
    
- Obtención de administración local y ejecución de herramientas en el contexto de SYSTEM.
    

### Acciones que puede facilitar el acceso como SYSTEM

- Enumeración de Active Directory.
    
- Uso de herramientas como BloodHound y PowerView.
    
- Determinadas operaciones de Kerberoasting y AS-REP Roasting.
    
- Captura de tráfico y análisis de autenticación con herramientas compatibles.
    
- Investigación de permisos y ACL.
    
- Análisis de tokens y contextos de seguridad.
    

Las posibilidades concretas dependen de la configuración del equipo, la identidad de la cuenta de equipo y las restricciones de seguridad existentes.

## 11. Consideraciones sobre el tipo de prueba

El nivel de ruido que podemos generar depende del objetivo y las reglas de enfrentamiento del pentest.

### Prueba no evasiva

El cliente conoce la evaluación y las actividades están autorizadas. Aun así, debemos evitar acciones innecesariamente disruptivas.

### Prueba evasiva o Red Team

Se intenta reproducir el comportamiento de un adversario real, por lo que la detección y el sigilo tienen más importancia.

### Precauciones

- No asumir que un escaneo agresivo es inocuo.
    
- Revisar qué hacen los scripts de Nmap antes de ejecutarlos.
    
- Evitar pruebas que puedan interrumpir sistemas críticos.
    
- Validar las versiones detectadas antes de intentar explotar vulnerabilidades.
    
- Documentar los resultados y mantener las actividades dentro del alcance autorizado.

## 12. Flujo de trabajo práctico

```
1. Escuchar tráfico de red
   Wireshark / tcpdump / Responder -A
              |
              v
2. Identificar hosts
   ARP / MDNS / otros datos observados
              |
              v
3. Validar hosts activos
   fping -asgq <red/CIDR>
              |
              v
4. Enumerar puertos y servicios
   Nmap -A -iL hosts.txt -oA <prefijo>
              |
              v
5. Identificar el dominio y el DC
   DNS / LDAP / Kerberos / SMB / RDP
              |
              v
6. Buscar usuarios válidos
   Kerbrute userenum
              |
              v
7. Documentar hallazgos
   Hosts / puertos / versiones / usuarios
              |
              v
8. Evaluar posibles vías de acceso
   Siempre según el alcance autorizado
```

## Conceptos clave para el examen

- **Passive Enumeration:** observación del tráfico y recopilación de información sin iniciar un escaneo activo de los objetivos.
    
- **Active Enumeration:** interacción directa con los hosts para validar su estado y descubrir servicios.
    
- **ARP:** protocolo utilizado para resolver direcciones IPv4 en direcciones MAC dentro de una red local.
    
- **MDNS:** mecanismo de resolución de nombres en redes locales.
    
- **LLMNR/NBT-NS:** mecanismos de resolución de nombres que pueden intervenir en determinados ataques de red.
    
- **Kerbrute:** herramienta de enumeración de usuarios y pruebas relacionadas con Kerberos.
    
- **Kerberos:** protocolo de autenticación utilizado por Active Directory.
    
- **LDAP:** protocolo para consultar y administrar información del directorio.
    
- **SMB:** protocolo de compartición de archivos y comunicación con servicios de Windows.
    
- **SYSTEM:** contexto de seguridad local de Windows con privilegios muy elevados.
    
- **Foothold:** primer punto de apoyo obtenido en un sistema o entorno.
    
- **TTPs:** tácticas, técnicas y procedimientos empleados durante una evaluación o ataque.
    

**Idea fundamental:** identifica primero los hosts, valida qué servicios ejecutan, determina qué equipos son críticos y busca cuentas válidas o configuraciones vulnerables. Documentar cada hallazgo facilita las siguientes fases de enumeración y explotación.
