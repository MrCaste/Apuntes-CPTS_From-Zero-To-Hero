
## 1. Objetivo: movimiento lateral

Una vez conseguido un punto de apoyo (_foothold_) en un dominio, debemos buscar formas de movernos lateralmente entre equipos o escalar privilegios hasta comprometer el dominio.

No siempre necesitamos ser administradores locales para acceder a otros hosts. Podemos encontrar cuentas con permisos específicos de acceso remoto o administración de servicios.

### Principales vías de acceso remoto

|Permiso / tecnología|Función|Arista de BloodHound|
|---|---|---|
|RDP|Acceder al escritorio gráfico de un equipo remoto.|`CanRDP`|
|WinRM / PowerShell Remoting|Ejecutar comandos o abrir sesiones PowerShell remotas.|`CanPSRemote`|
|MSSQL|Administrar una instancia de SQL Server y, en determinadas condiciones, ejecutar comandos del sistema operativo.|`SQLAdmin`|

**Regla práctica:** cada vez que comprometas una cuenta nueva, vuelve a enumerar sus permisos y relaciones en BloodHound. El acceso conseguido puede abrir nuevas rutas de movimiento lateral.

## 2. Enumeración de acceso RDP

RDP permite conectarse de forma remota al escritorio gráfico de un equipo Windows.

Aunque una cuenta no tenga privilegios de administrador local, podría tener permiso para iniciar sesión por RDP. Desde ese equipo podríamos encontrar información sensible, credenciales o posibilidades de escalada de privilegios.

### Enumerar miembros del grupo Remote Desktop Users

Con PowerView:

```
Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Desktop Users"
```

Ejemplo del laboratorio:

```
ComputerName : ACADEMY-EA-MS01
GroupName    : Remote Desktop Users
MemberName   : INLANEFREIGHT\Domain Users
SID          : S-1-5-21-3842939050-3880317879-2865463114-513
IsGroup      : True
```

En este caso, el grupo `Domain Users` aparece como miembro de `Remote Desktop Users`, por lo que los usuarios del dominio podrían tener acceso RDP al equipo, sujeto a las demás restricciones de inicio de sesión y a la configuración efectiva.

### Enumerar RDP con BloodHound

Podemos buscar las aristas `CanRDP` y comprobar si un usuario tiene acceso:

- Directamente.
    
- Mediante la pertenencia a grupos.
    
- A uno o varios equipos del dominio.
    

También podemos utilizar las consultas predefinidas:

- `Find Workstations where Domain Users can RDP`
    
- `Find Servers where Domain Users can RDP`
    

### Conectarse mediante RDP

Desde Linux:

```
xfreerdp3 /v:IP_OBJETIVO /u:USUARIO /p:'CONTRASEÑA'
```

También podemos utilizar Remmina.

Desde Windows:

```
mstsc.exe
```

**Qué comprobar después de acceder:**

- Archivos de configuración y documentos sensibles.
    
- Credenciales almacenadas o expuestas.
    
- Permisos locales.
    
- Posibilidades de escalada de privilegios.
    
- Acceso a otros sistemas.

## 3. Enumeración y acceso mediante WinRM

**WinRM (Windows Remote Management)** permite administrar equipos Windows de forma remota. PowerShell Remoting utiliza esta infraestructura para ejecutar comandos o abrir sesiones interactivas.

El grupo local `Remote Management Users` permite conceder acceso de administración remota sin tener que convertir necesariamente al usuario en administrador local.

### Enumerar el grupo Remote Management Users

```
Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Management Users"
```

Ejemplo del laboratorio:

```
ComputerName : ACADEMY-EA-MS01
GroupName    : Remote Management Users
MemberName   : INLANEFREIGHT\forend
SID          : S-1-5-21-3842939050-3880317879-2865463114-5614
IsGroup      : False
```

La cuenta `forend` aparece en el grupo, lo que indica una posible vía de acceso mediante WinRM.

### Buscar usuarios con acceso WinRM en BloodHound

Consulta Cypher del módulo:

```
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:CanPSRemote*1..]->(c:Computer)
RETURN p2
```

Esta consulta busca rutas desde usuarios, a través de su pertenencia a grupos, hasta equipos a los que pueden acceder mediante `CanPSRemote`.

### Conectarse desde Windows con Enter-PSSession

```
$password = ConvertTo-SecureString "CONTRASEÑA" -AsPlainText -Force

$cred = New-Object System.Management.Automation.PSCredential(
    "INLANEFREIGHT\forend",
    $password
)

Enter-PSSession -ComputerName ACADEMY-EA-MS01 -Credential $cred
```

Una vez dentro de la sesión remota:

```
hostname
```

Para salir:

```
Exit-PSSession
```

### Conectarse desde Linux con Evil-WinRM

Instalar la herramienta:

```
gem install evil-winrm
```

Conectarse utilizando una contraseña:

```
evil-winrm -i IP_OBJETIVO -u forend
```

La herramienta solicitará la contraseña si no se especifica en los argumentos.

Opciones relevantes:

|Parámetro|Función|
|---|---|
|`-i`|IP o nombre del objetivo.|
|`-u`|Usuario.|
|`-p`|Contraseña.|
|`-H`|Hash NTLM.|
|`-P`|Puerto; por defecto, 5985.|
|`-S`|Habilita SSL.|
|`-r`|Realm para autenticación Kerberos.|
|`-s`|Ruta local con scripts PowerShell.|
|`-e`|Ruta local con ejecutables.|

**Importante:** disponer de acceso WinRM no implica automáticamente tener privilegios de administrador local. El nivel de acceso depende de los permisos efectivos de la cuenta.

## 4. Acceso privilegiado a MSSQL

Una cuenta con privilegios `sysadmin` en una instancia de SQL Server puede administrar esa instancia y, si la configuración lo permite, ejecutar comandos del sistema operativo mediante procedimientos como `xp_cmdshell`.

Estas credenciales pueden obtenerse mediante diferentes vías:

- Kerberoasting.
    
- Captura de credenciales.
    
- Password spraying.
    
- Archivos de configuración, como `web.config`.
    
- Cadenas de conexión a bases de datos.
    
- Archivos encontrados mediante herramientas como Snaffler.
    

### Enumerar administradores SQL con BloodHound

Consulta Cypher del módulo:

```
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:SQLAdmin*1..]->(c:Computer)
RETURN p2
```

La arista `SQLAdmin` permite identificar usuarios que tienen derechos de administración sobre instancias SQL.

### Enumerar instancias SQL con PowerUpSQL

Importar el módulo:

```
Import-Module .\PowerUpSQL.ps1
```

Buscar instancias del dominio:

```
Get-SQLInstanceDomain
```

Ejemplo del laboratorio:

```
ComputerName : ACADEMY-EA-DB01.INLANEFREIGHT.LOCAL
Instance     : ACADEMY-EA-DB01.INLANEFREIGHT.LOCAL,1433
DomainAccount: damundsen
Service      : MSSQLSvc
Spn          : MSSQLSvc/ACADEMY-EA-DB01.INLANEFREIGHT.LOCAL:1433
```

La información obtenida identifica una instancia SQL asociada al servicio `MSSQLSvc`, normalmente en el puerto TCP 1433.

### Probar consultas con PowerUpSQL

```
Get-SQLQuery -Verbose `
    -Instance "172.16.5.150,1433" `
    -username "INLANEFREIGHT\damundsen" `
    -password "CONTRASEÑA" `
    -query 'SELECT @@version'
```

Si la autenticación funciona, la consulta devuelve información sobre la versión del servidor SQL.

## 5. Conectarse a MSSQL desde Linux con Impacket

Podemos utilizar `mssqlclient.py` para conectarnos a una instancia SQL desde Linux.

### Autenticación Windows

```
mssqlclient.py INLANEFREIGHT/damundsen@172.16.5.150 -windows-auth
```

La herramienta solicitará la contraseña.

Una vez conectado, podemos consultar los comandos disponibles:

```
SQL> help
```

Entre las opciones que muestra el laboratorio están:

|Comando|Función|
|---|---|
|`help`|Muestra los comandos disponibles.|
|`lcd <ruta>`|Cambia el directorio local.|
|`enable_xp_cmdshell`|Intenta habilitar la ejecución de comandos del sistema operativo mediante `xp_cmdshell`.|
|`disable_xp_cmdshell`|Intenta deshabilitar `xp_cmdshell`.|
|`xp_cmdshell <comando>`|Ejecuta un comando del sistema operativo si está habilitado y la cuenta tiene los permisos necesarios.|
|`sp_start_job <comando>`|Inicia un trabajo mediante SQL Server Agent; el resultado puede ser indirecto.|
|`exit`|Termina la sesión.|

### Comprobar la versión de SQL Server

También se puede ejecutar una consulta SQL:

```
SELECT @@version;
```

### Habilitar xp_cmdshell en el laboratorio

Desde `mssqlclient.py`:

```
SQL> enable_xp_cmdshell
```

Esta operación requiere los privilegios adecuados y puede modificar la configuración de SQL Server. No debe asumirse que funcionará en todas las instancias.

Después, el módulo muestra cómo comprobar los privilegios del contexto que ejecuta los comandos:

```
SQL> xp_cmdshell whoami /priv
```

## 6. SeImpersonatePrivilege y escalada de privilegios

En el laboratorio, la salida de `whoami /priv` muestra, entre otros, los siguientes privilegios:

```
SeAssignPrimaryTokenPrivilege
SeIncreaseQuotaPrivilege
SeChangeNotifyPrivilege
SeManageVolumePrivilege
SeImpersonatePrivilege
SeCreateGlobalPrivilege
SeIncreaseWorkingSetPrivilege
```

El que destaca es:

```
SeImpersonatePrivilege
```

Este privilegio permite que un proceso suplante el contexto de seguridad de un cliente bajo determinadas condiciones.

Puede ser relevante para una escalada de privilegios local, dependiendo de la versión de Windows, la configuración del sistema y las condiciones de ejecución.

El módulo menciona estas herramientas como ejemplos históricos de técnicas relacionadas:

- JuicyPotato.
    
- PrintSpoofer.
    
- RoguePotato.
    

**No confundas los permisos SQL con los privilegios de Windows:** ser `sysadmin` en SQL Server no equivale automáticamente a ser administrador del dominio. Sin embargo, si se consigue ejecutar código del sistema operativo con una cuenta de servicio que tiene privilegios locales aprovechables, puede abrirse una nueva vía de escalada.

## 7. Flujo práctico de enumeración

```
1. Obtener credenciales de un usuario
              |
              v
2. Consultar BloodHound
   - CanRDP
   - CanPSRemote
   - SQLAdmin
              |
              v
3. Enumerar los permisos en los equipos
   - Remote Desktop Users
   - Remote Management Users
   - Administradores locales
              |
              v
4. Probar las vías de acceso autorizadas
   - RDP
   - WinRM
   - MSSQL
              |
              v
5. Enumerar el nuevo host o servicio
   - Archivos sensibles
   - Credenciales
   - Privilegios locales
              |
              v
6. Buscar nuevas rutas de movimiento lateral
              |
              v
7. Repetir la enumeración con cada cuenta o host nuevo
```

## 8. Chuleta rápida para el examen

|Objetivo|Comando|
|---|---|
|Enumerar usuarios con acceso RDP|`Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Desktop Users"`|
|Enumerar usuarios con acceso WinRM|`Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Management Users"`|
|Buscar acceso WinRM en BloodHound|Arista `CanPSRemote`|
|Buscar administración SQL en BloodHound|Arista `SQLAdmin`|
|Abrir una sesión PowerShell remota|`Enter-PSSession -ComputerName HOST -Credential $cred`|
|Conectarse a WinRM desde Linux|`evil-winrm -i IP -u USUARIO`|
|Buscar instancias SQL|`Get-SQLInstanceDomain`|
|Consultar la versión de SQL Server|`Get-SQLQuery -Instance "IP,1433" -username "DOMINIO\USUARIO" -password "CONTRASEÑA" -query 'SELECT @@version'`|
|Conectarse a MSSQL desde Linux|`mssqlclient.py DOMINIO/usuario@IP -windows-auth`|
|Comprobar privilegios del proceso SQL|`xp_cmdshell whoami /priv`|

### Ideas clave

1. **No necesitas ser administrador local para tener acceso remoto:** una cuenta puede tener permisos RDP o WinRM sin pertenecer al grupo de administradores locales.
    
2. **BloodHound permite descubrir rutas indirectas:** comprueba siempre las relaciones heredadas mediante grupos.
    
3. `**CanRDP**`**,** `**CanPSRemote**` **y** `**SQLAdmin**` **representan tipos de acceso diferentes.**
    
4. **Las credenciales SQL deben investigarse:** busca instancias y comprueba si las credenciales encontradas funcionan.
    
5. `**xp_cmdshell**` **puede proporcionar ejecución de comandos del sistema operativo**, pero depende de la configuración y los permisos.
    
6. `**SeImpersonatePrivilege**` **puede abrir una vía de escalada local**, dependiendo de las condiciones del objetivo.
    
7. **La enumeración es iterativa:** cada nueva cuenta o equipo comprometido puede revelar más privilegios y rutas de ataque.
