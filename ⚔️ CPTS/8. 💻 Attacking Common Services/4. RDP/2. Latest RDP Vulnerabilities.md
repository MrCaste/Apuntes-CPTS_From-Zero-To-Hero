
## 1. BlueKeep (CVE-2019-0708)

**BlueKeep** es una vulnerabilidad crítica de RDP publicada en 2019 que permite la **ejecución remota de código (RCE) sin autenticación previa**.

- **Servicio afectado:** RDP.
    
- **Puerto:** TCP/3389.
    
- **Tipo de vulnerabilidad:** Use-After-Free (UAF).
    
- **Impacto:** ejecución de código remoto con privilegios de `LocalSystem`.
    
- **Identificador:** `CVE-2019-0708`.
    

La vulnerabilidad afecta a determinadas versiones de Windows; no todas las versiones están expuestas.

## 2. Concepto de la vulnerabilidad

BlueKeep aprovecha peticiones manipuladas durante el establecimiento de la conexión RDP, cuando cliente y servidor intercambian la configuración inicial.

El fallo se produce en una función relacionada con la creación de un canal virtual. Mediante una técnica **Use-After-Free**, el atacante puede aprovechar memoria que ya ha sido liberada para ejecutar código arbitrario.

### ¿Qué es Use-After-Free (UAF)?

Es un error de gestión de memoria que ocurre cuando un programa intenta utilizar una región de memoria después de haberla liberado.

En BlueKeep, este comportamiento puede permitir manipular la memoria del kernel y conseguir la ejecución de instrucciones controladas por el atacante.

## 3. Funcionamiento del ataque

### Fase 1: inicialización y explotación

1. **Origen:** el atacante envía una petición manipulada durante el intercambio inicial de configuración de RDP.
    
2. **Proceso:** la petición llega a una función vulnerable utilizada para crear un canal virtual.
    
3. **Privilegios:** el servicio RDP se ejecuta con privilegios de `LocalSystem`.
    
4. **Destino:** la manipulación de la función permite redirigir la ejecución hacia un proceso del kernel.
    

### Fase 2: ejecución remota de código

5. **Origen:** el atacante introduce un payload diseñado para aprovechar el fallo de memoria.
    
6. **Proceso:** se manipula la memoria del kernel para dirigir la ejecución hacia las instrucciones controladas por el atacante.
    
7. **Privilegios:** las instrucciones se ejecutan con los privilegios elevados del kernel.
    
8. **Destino:** el payload puede establecer una conexión de retorno (_reverse shell_) hacia el equipo del atacante.
    

**Resultado:** un atacante podría ejecutar código remotamente sin disponer previamente de credenciales válidas.

## 4. Detección y evaluación

El módulo se centra en el concepto de BlueKeep y no proporciona comandos concretos para detectar o explotar esta vulnerabilidad.

Como punto de partida para una evaluación:

```
nmap -Pn -p3389 <IP>
```

Este comando permite comprobar si el puerto RDP está abierto, pero **no confirma que el sistema sea vulnerable a BlueKeep**.

Para determinar la exposición, es necesario comprobar la versión de Windows, las actualizaciones de seguridad instaladas y las condiciones específicas de la vulnerabilidad.

## 5. Riesgos y precauciones

La explotación de BlueKeep puede provocar inestabilidad en el sistema, incluida una pantalla azul de la muerte (**BSoD**).

Antes de intentar explotarla en una prueba de penetración:

- Confirmar que el sistema objetivo está dentro del alcance autorizado.
    
- Verificar si existen actualizaciones de seguridad que solucionen la vulnerabilidad.
    
- Valorar el riesgo de interrupción del servicio.
    
- Informar al cliente y obtener su autorización antes de ejecutar un exploit que pueda afectar a la disponibilidad del sistema.
