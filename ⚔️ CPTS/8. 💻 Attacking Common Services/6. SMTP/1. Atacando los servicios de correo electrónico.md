
## 1. Protocolos y puertos

Los servidores de correo permiten enviar, recibir y almacenar mensajes mediante distintos protocolos.

|Protocolo|Puerto|Función|
|---|---|---|
|SMTP|TCP/25|Envío y retransmisión de correos sin cifrar|
|IMAP|TCP/143|Acceso al correo almacenado en el servidor|
|POP3|TCP/110|Descarga de correos desde el servidor|
|SMTPS|TCP/465|SMTP cifrado|
|SMTP + STARTTLS|TCP/587|Envío de correo con posibilidad de cifrado|
|IMAPS|TCP/993|IMAP cifrado|
|POP3S|TCP/995|POP3 cifrado|

**Diferencia entre POP3 e IMAP:**

- **POP3:** normalmente descarga los mensajes y los elimina del servidor, aunque puede configurarse para conservarlos.
    
- **IMAP:** mantiene los mensajes en el servidor, facilitando el acceso desde varios dispositivos.
    
- **SMTP:** se utiliza para enviar y retransmitir mensajes.

## 2. Enumeración de servidores de correo

### 2.1. Consultar registros MX

Los registros **MX (Mail eXchanger)** identifican los servidores encargados de recibir el correo de un dominio.

**Con** `**host**`**:**

```
host -t MX <DOMINIO>
```

Ejemplo:

```
host -t MX hackthebox.eu
```

**Con** `**dig**`**:**

```
dig mx <DOMINIO> | grep "MX" | grep -v ";"
```

Ejemplo:

```
dig mx inlanefreight.com | grep "MX" | grep -v ";"
```

Un dominio puede tener varios registros MX para distribuir la carga y proporcionar redundancia. Los resultados también pueden revelar si utiliza un proveedor externo como Google Workspace, Microsoft 365 o Zoho.

### 2.2. Resolver la dirección IP del servidor

Una vez identificado el servidor de correo, podemos consultar su registro A:

```
host -t A <SERVIDOR_CORREO>
```

Ejemplo:

```
host -t A mail1.inlanefreight.htb
```

### 2.3. Escanear los puertos de correo con Nmap

```
sudo nmap -Pn -sV -sC -p25,143,110,465,587,993,995 <IP>
```

- `-Pn`: omite el descubrimiento de hosts mediante ping.
    
- `-sV`: identifica las versiones de los servicios.
    
- `-sC`: ejecuta los scripts predeterminados de Nmap.
    
- `-p`: especifica los puertos que queremos examinar.
    

Los resultados pueden revelar el software utilizado, como Postfix, y las capacidades SMTP anunciadas por el servidor.

## 3. Enumeración de usuarios mediante SMTP

Algunos servidores SMTP permiten comprobar si determinados usuarios existen. Esta información puede utilizarse posteriormente para orientar pruebas de credenciales.

Los comandos principales son `VRFY`, `EXPN` y `RCPT TO`.

### 3.1. Conectarse al servicio SMTP

```
telnet <IP> 25
```

### 3.2. Comando VRFY

Comprueba si el servidor reconoce un usuario.

```
VRFY root
VRFY www-data
VRFY usuario_inexistente
```

Una respuesta como:

```
252 2.0.0 root
```

puede indicar que el servidor reconoce el nombre, aunque **el código 252 no confirma necesariamente que la cuenta exista**.

En cambio, una respuesta como:

```
550 5.1.1 <new-user>: Recipient address rejected: User unknown
```

indica que el servidor rechaza ese destinatario como desconocido.

La utilidad de estas respuestas depende de la configuración y de la implementación del servidor.

### 3.3. Comando EXPN

Intenta expandir una lista de distribución o un alias para obtener sus destinatarios.

```
EXPN support-team
```

Una respuesta podría revelar varias direcciones:

```
250 2.0.0 carol@inlanefreight.htb
250 2.1.5 elisa@inlanefreight.htb
```

Esto puede permitir descubrir usuarios pertenecientes a listas de distribución.

### 3.4. Comando RCPT TO

Especifica el destinatario de un mensaje. Algunos servidores permiten utilizarlo para comprobar qué destinatarios aceptan.

```
MAIL FROM:test@htb.com
RCPT TO:julio
RCPT TO:kate
RCPT TO:john
```

Una respuesta como:

```
550 5.1.1 julio... User unknown
```

indica que el servidor rechaza ese destinatario.

Una respuesta como:

```
250 2.1.5 john... Recipient ok
```

indica que acepta el destinatario, aunque no siempre garantiza que exista un buzón real.

### 3.5. Automatizar la enumeración con smtp-user-enum

Podemos probar una lista de usuarios mediante distintos métodos.

**Sintaxis:**

```
smtp-user-enum -M <VRFY|EXPN|RCPT> -U <LISTA_USUARIOS> -D <DOMINIO> -t <IP>
```

Ejemplo:

```
smtp-user-enum -M RCPT -U userlist.txt -D inlanefreight.htb -t <IP>
```

Parámetros:

- `-M`: método de enumeración.
    
- `-U`: archivo con los nombres de usuario.
    
- `-D`: dominio que se añade a las direcciones de correo cuando es necesario.
    
- `-t`: servidor objetivo.
    

**Objetivo:** identificar qué nombres de usuario acepta el servidor.

## 4. Enumeración de usuarios mediante POP3

Algunas implementaciones de POP3 también pueden revelar si un nombre de usuario es válido.

### Conexión

```
telnet <IP> 110
```

### Comando USER

```
USER julio
USER john
```

Ejemplo de respuesta:

```
-ERR
```

o:

```
+OK
```

Una respuesta `+OK` puede indicar que el servidor reconoce el usuario, mientras que `-ERR` puede indicar que no lo reconoce.

**Importante:** el comportamiento depende del servidor. No todos permiten enumerar usuarios de esta manera.

## 5. Enumeración de Microsoft 365 con O365spray

Los proveedores de correo en la nube utilizan implementaciones propias. Por ello, las técnicas de enumeración pueden diferir de las utilizadas contra servidores SMTP, POP3 o IMAP tradicionales.

`O365spray` permite validar dominios de Microsoft 365, enumerar usuarios y realizar pruebas de contraseñas.

### 5.1. Validar el dominio

```
python3 o365spray.py --validate --domain <DOMINIO>
```

Ejemplo:

```
python3 o365spray.py --validate --domain msplaintext.xyz
```

### 5.2. Enumerar usuarios

```
python3 o365spray.py --enum -U users.txt --domain <DOMINIO>
```

Ejemplo:

```
python3 o365spray.py --enum -U users.txt --domain msplaintext.xyz
```

Si encuentra cuentas válidas, la herramienta puede guardarlas en un archivo para utilizarlas en fases posteriores.

## 6. Ataques contra contraseñas

Una vez identificados los usuarios, podemos evaluar la seguridad de sus credenciales mediante pruebas autorizadas.

### 6.1. Hydra contra POP3

Ejemplo de password spraying con una contraseña y una lista de usuarios:

```
hydra -L users.txt -p 'Company01!' -f <IP> pop3
```

Parámetros:

- `-L users.txt`: lista de usuarios.
    
- `-p 'Company01!'`: contraseña que se probará contra los usuarios.
    
- `-f`: detiene el ataque al encontrar una credencial válida.
    
- `pop3`: servicio objetivo.
    

**Diferencia entre los ataques:**

- **Password spraying:** prueba una o pocas contraseñas contra muchos usuarios.
    
- **Fuerza bruta:** prueba numerosas contraseñas contra una cuenta o un conjunto de cuentas.
    

Las defensas del proveedor pueden bloquear o limitar los intentos de autenticación.

### 6.2. Password spraying contra Microsoft 365

O365spray incluye un modo específico para probar contraseñas:

```
python3 o365spray.py --spray -U usersfound.txt -p '<CONTRASEÑA>' --count 1 --lockout 1 --domain <DOMINIO>
```

Parámetros relevantes:

- `--spray`: activa el modo password spraying.
    
- `-U`: archivo con los usuarios.
    
- `-p`: contraseña que se probará.
    
- `--count`: número de contraseñas por ciclo de spraying.
    
- `--lockout`: intervalo relacionado con la protección frente a bloqueos.
    
- `--domain`: dominio objetivo.
    

**Precaución:** estos parámetros no garantizan que una cuenta esté protegida frente al bloqueo. Las políticas y los mecanismos de protección del proveedor determinan el comportamiento real.

Para otros proveedores existen herramientas específicas, pero su funcionamiento puede cambiar cuando se actualizan los mecanismos de autenticación.

## 7. Ataques específicos de SMTP

### 7.1. Open relay

Un **open relay** es un servidor SMTP mal configurado que permite retransmitir correo sin exigir la autenticación o autorización adecuada.

Un atacante podría abusar de esta configuración para:

- Suplantar la dirección aparente del remitente.
    
- Enviar mensajes de phishing.
    
- Utilizar la infraestructura del servidor para retransmitir mensajes.
    

Que un servidor permita retransmitir correo no significa que todos los mensajes vayan a llegar a su destino ni que el remitente quede completamente oculto.

### 7.2. Detectar un open relay con Nmap

```
nmap -p25 -Pn --script smtp-open-relay <IP>
```

Una respuesta como:

```
25/tcp open smtp
|_smtp-open-relay: Server is an open relay (14/16 tests)
```

indica que el servidor ha superado varias pruebas de retransmisión abierta.

### 7.3. Comprobar el envío de correo con Swaks

`Swaks` es una herramienta para probar servidores SMTP y realizar operaciones de envío de correo.

**Sintaxis general:**

```
swaks --from <REMITENTE> --to <DESTINATARIO> --header 'Subject: <ASUNTO>' --body '<MENSAJE>' --server <IP>
```

Ejemplo de laboratorio:

```
swaks --from notifications@inlanefreight.com \
      --to employees@inlanefreight.com \
      --header 'Subject: Company Notification' \
      --body 'Mensaje de prueba autorizado.' \
      --server <IP>
```

Una respuesta SMTP `250 OK` después de transmitir el mensaje indica que el servidor ha aceptado la operación correspondiente; no garantiza por sí sola la entrega final en el buzón.

## 8. Flujo de trabajo para HTB Academy

Cuando encontremos un servidor de correo, podemos seguir este orden:

1. **Identificar los servidores de correo:**
    
    ```
    host -t MX <DOMINIO>
    ```
    
2. **Resolver la IP del servidor:**
    
    ```
    host -t A <SERVIDOR_CORREO>
    ```
    
3. **Escanear los puertos habituales:**
    
    ```
    sudo nmap -Pn -sV -sC -p25,143,110,465,587,993,995 <IP>
    ```
    
4. **Comprobar si SMTP permite enumerar usuarios:**
    
    ```
    telnet <IP> 25
    ```
    
    Probar `VRFY`, `EXPN` y `RCPT TO` si están disponibles.
    
5. **Automatizar la enumeración SMTP:**
    
    ```
    smtp-user-enum -M RCPT -U userlist.txt -D <DOMINIO> -t <IP>
    ```
    
6. **Comprobar si POP3 revela usuarios:**
    
    ```
    telnet <IP> 110
    ```
    
7. **Si el dominio utiliza Microsoft 365**, evaluar la enumeración específica con O365spray.
    
8. **Evaluar las credenciales** con las técnicas adecuadas y dentro del alcance autorizado.
    
9. **Comprobar si SMTP es un open relay:**
    
    ```
    nmap -p25 -Pn --script smtp-open-relay <IP>
    ```
    

## 9. Conceptos clave para el examen

|Concepto|Qué recordar|
|---|---|
|SMTP|Envío y retransmisión de correo.|
|POP3|Descarga de mensajes; normalmente puede eliminarlos del servidor.|
|IMAP|Acceso a mensajes conservados en el servidor.|
|Registro MX|Identifica los servidores de correo de un dominio.|
|`VRFY`|Comprueba cómo responde SMTP a un nombre de usuario.|
|`EXPN`|Puede revelar los miembros de una lista de distribución.|
|`RCPT TO`|Especifica el destinatario y puede permitir enumerarlo.|
|`USER` en POP3|Puede revelar información sobre la existencia de usuarios.|
|`smtp-user-enum`|Automatiza la enumeración SMTP.|
|O365spray|Enumera usuarios y prueba credenciales en Microsoft 365.|
|Password spraying|Prueba pocas contraseñas contra muchos usuarios.|
|Open relay|Permite retransmitir correo sin la autorización adecuada.|
|`smtp-open-relay`|Script de Nmap para comprobar retransmisiones abiertas.|
|Swaks|Cliente para probar operaciones SMTP y el envío de correo.|
