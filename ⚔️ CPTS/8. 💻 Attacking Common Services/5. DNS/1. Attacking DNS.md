
## 1. Enumeración DNS

El **Domain Name System (DNS)** traduce nombres de dominio a direcciones IP y permite identificar información relevante sobre la infraestructura de una organización.

- **Puerto principal:** UDP/53.
    
- **También utiliza:** TCP/53, especialmente para transferencias de zona y respuestas que requieren conexiones TCP.
    
- **Objetivo de la enumeración:** identificar servidores DNS, subdominios, registros y posibles configuraciones incorrectas.
    

### Escaneo con Nmap

```
nmap -p53 -Pn -sV -sC <IP>
```

- `-p53`: analiza el puerto 53.
    
- `-Pn`: omite el descubrimiento de hosts.
    
- `-sV`: detecta versiones de servicios.
    
- `-sC`: ejecuta scripts predeterminados.
    

Ejemplo de resultado:

```
PORT   STATE SERVICE VERSION
53/tcp open  domain  ISC BIND 9.11.3
```

**Importante:** si quieres comprobar ambos protocolos, analiza UDP y TCP:

```
sudo nmap -sU -sT -p53 <IP>
```

## 2. Transferencia de zona DNS (AXFR)

Una **transferencia de zona DNS** permite copiar los registros de una zona DNS de un servidor a otro.

Si el servidor DNS permite transferencias de zona a clientes no autorizados, podemos obtener información como:

- Subdominios.
    
- Direcciones IP asociadas a los dominios.
    
- Servidores DNS.
    
- Nombres de hosts y servicios internos expuestos en la zona.
    

Las transferencias de zona utilizan TCP/53.

### Enumerar una zona con `dig`

```
dig AXFR @<DNS_SERVER> <DOMAIN>
```

Ejemplo:

```
dig AXFR @ns1.inlanefreight.htb inlanefreight.htb
```

También podemos especificar la IP del servidor DNS:

```
dig AXFR @10.129.110.213 inlanefreight.htb
```

Si la transferencia está permitida, obtendremos los registros de la zona.

Ejemplo de salida:

```
inlanefreight.htb.         IN A 10.129.110.22
admin.inlanefreight.htb.   IN A 10.129.110.21
hr.inlanefreight.htb.      IN A 10.129.110.25
support.inlanefreight.htb. IN A 10.129.110.28
```

En este ejemplo descubrimos varios subdominios y sus direcciones IP.

**Interpretación:**

- Si aparecen los registros de la zona, la transferencia ha sido satisfactoria.
    
- Si el servidor rechaza la solicitud, puede tener restringidas las transferencias de zona.
    
- Un resultado negativo no demuestra que no existan otros métodos de enumeración DNS.
    

### Enumerar con Fierce

`fierce` permite identificar servidores DNS e intentar transferencias de zona.

```
fierce --domain <DOMAIN>
```

Ejemplo:

```
fierce --domain zonetransfer.me
```

Puede devolver registros `A`, `AAAA`, `MX`, `NS`, `TXT`, `CNAME` y otros datos DNS.

## 3. Enumeración de subdominios

La enumeración de subdominios permite identificar servicios y sistemas asociados al dominio principal.

Herramientas destacadas en el módulo:

- **Subfinder:** obtiene subdominios a partir de fuentes públicas.
    
- **Sublist3r:** permite enumerar subdominios y realizar búsquedas mediante listas de nombres.
    
- **Subbrute:** permite realizar fuerza bruta DNS utilizando resolutores especificados.
    

### Subfinder

```
subfinder -d <DOMAIN> -v
```

Ejemplo:

```
subfinder -d inlanefreight.com -v
```

Puede descubrir nombres como:

```
www.inlanefreight.com
ns1.inlanefreight.com
ns2.inlanefreight.com
support.inlanefreight.com
```

### Subbrute

Clonar el repositorio:

```
git clone https://github.com/TheRook/subbrute.git
```

Entrar en el directorio:

```
cd subbrute
```

Crear un archivo con un servidor DNS que se utilizará como resolutor:

```
echo "ns1.inlanefreight.com" > resolvers.txt
```

Ejecutar la enumeración utilizando una lista de nombres:

```
./subbrute.py <DOMAIN> -s ./names.txt -r ./resolvers.txt
```

Ejemplo:

```
./subbrute.py inlanefreight.com -s ./names.txt -r ./resolvers.txt
```

- `-s`: archivo con los nombres que se probarán.
    
- `-r`: archivo con los resolutores DNS.
    

Esta herramienta resulta especialmente interesante en pruebas internas donde no existe acceso directo a Internet, siempre que se disponga de un resolutor accesible y de una lista adecuada.

## 4. Identificar registros CNAME

Un registro `CNAME` crea un alias que apunta a otro nombre de dominio.

Puede utilizarse para dirigir un subdominio a servicios externos, como plataformas de alojamiento o redes de distribución de contenido.

### Consultar un subdominio

Con `host`:

```
host <SUBDOMAIN>
```

Ejemplo:

```
host support.inlanefreight.com
```

Posible resultado:

```
support.inlanefreight.com is an alias for inlanefreight.s3.amazonaws.com
```

Esto indica que el subdominio apunta a un servicio de Amazon S3.

También podemos utilizar `nslookup`:

```
nslookup <SUBDOMAIN>
```

### ¿Qué es un subdomain takeover?

Un **subdomain takeover** puede producirse cuando un subdominio apunta mediante un registro DNS a un recurso externo que ya no existe o que puede ser reclamado por otra persona.

Ejemplo:

```
sub.target.com. 60 IN CNAME anotherdomain.com
```

Si el recurso de destino deja de estar controlado por su propietario original y el servicio permite reclamarlo, un atacante podría llegar a controlar el contenido servido bajo `sub.target.com`.

### Procedimiento de evaluación

1. Enumerar los subdominios.
    
2. Identificar los registros `CNAME`.
    
3. Comprobar a qué servicio externo apunta cada subdominio.
    
4. Verificar si el recurso de destino existe y está correctamente configurado.
    
5. Determinar si el proveedor permite reclamar el recurso y si el subdominio es realmente vulnerable.
    

**Importante:** un error como `NoSuchBucket` puede ser un indicio de una configuración incorrecta, pero por sí solo no demuestra que el subdominio sea vulnerable.

El módulo recomienda consultar el repositorio `can-i-take-over-xyz` para comprobar los servicios susceptibles de sufrir este tipo de problema y sus condiciones específicas.

## 5. DNS Spoofing y DNS Cache Poisoning

El **DNS spoofing** consiste en proporcionar respuestas DNS falsas para dirigir las conexiones hacia una dirección IP distinta de la legítima.

El **DNS cache poisoning** consiste en introducir registros falsos en una caché DNS para que las consultas posteriores utilicen información manipulada.

Estos ataques pueden permitir redirigir a los usuarios hacia páginas fraudulentas o infraestructura controlada por un atacante.

Entre los posibles escenarios se encuentran:

- Interceptar comunicaciones entre un cliente y su servidor DNS.
    
- Explotar un servidor DNS vulnerable para modificar sus registros.
    
- Manipular respuestas DNS en una red local mediante técnicas de intermediario (_Man-in-the-Middle_, MITM).
    

### Envenenamiento DNS en una red local con Ettercap

El módulo muestra cómo configurar Ettercap para responder a consultas DNS con una dirección IP controlada por el atacante dentro de un laboratorio autorizado.

Editar el archivo:

```
sudo nano /etc/ettercap/etter.dns
```

Añadir las entradas correspondientes al dominio de laboratorio:

```
inlanefreight.com      A   192.168.225.110
*.inlanefreight.com    A   192.168.225.110
```

Estas entradas indican que el dominio y sus subdominios coincidentes deben resolverse a `192.168.225.110`.

El módulo describe el siguiente flujo de trabajo con la interfaz gráfica de Ettercap:

1. Iniciar Ettercap.
    
2. Escanear la red en busca de hosts activos.
    
3. Seleccionar el equipo objetivo.
    
4. Configurar el host de destino y la puerta de enlace según el laboratorio.
    
5. Abrir **Plugins → Manage Plugins**.
    
6. Activar el plugin `dns_spoof`.
    
7. Comprobar cómo resuelve el dominio el equipo de prueba.
    

Este procedimiento requiere una posición de red adecuada para interceptar o influir en las consultas del objetivo. La configuración del archivo por sí sola no garantiza que el ataque funcione.

### Verificar la resolución DNS

Desde Windows:

```
ping inlanefreight.com
```

Si el nombre se resuelve a la dirección IP manipulada, la salida mostrará esa dirección.

Por ejemplo:

```
Pinging inlanefreight.com [192.168.225.110]
```

Esto permite comprobar la resolución obtenida por el cliente, aunque no demuestra por sí solo el mecanismo que la produjo.

## 6. Flujo de trabajo para un laboratorio de DNS

1. **Enumerar el servicio:**
    
    ```
    nmap -p53 -Pn -sV -sC <IP>
    ```
    
2. **Probar una transferencia de zona:**
    
    ```
    dig AXFR @<DNS_SERVER> <DOMAIN>
    ```
    
3. **Buscar subdominios:**
    
    ```
    subfinder -d <DOMAIN> -v
    ```
    
4. **Comprobar registros de un subdominio:**
    
    ```
    host <SUBDOMAIN>
    ```
    
5. **Investigar los CNAME:** identificar servicios externos y posibles recursos inexistentes o mal configurados.
    
6. **Evaluar la exposición:** determinar si los registros DNS revelan hosts, servicios o recursos que amplíen la superficie de ataque.
    
7. **Validar las hipótesis:** distinguir entre un indicio de vulnerabilidad y una vulnerabilidad confirmada.

|Transferencia de zona|`dig AXFR @<DNS_SERVER> <DOMAIN>`|

|Consultar un nombre DNS|`host <DOMAIN>`|
|Consultar registros con nslookup|`nslookup <DOMAIN>`|
|Comprobar la resolución desde Windows|`ping <DOMAIN>`|

### Conceptos que debes recordar

- **AXFR:** transferencia de zona DNS. Si está mal restringida, puede revelar todos los registros de una zona.
    
- **Subfinder:** enumera subdominios mediante fuentes de información públicas.
    
- **Subbrute:** realiza fuerza bruta DNS con listas de nombres y resolutores configurados.
    
- **CNAME:** alias DNS que puede apuntar a un servicio externo.
    
- **Subdomain takeover:** posible toma de control de un subdominio debido a un recurso externo reclamable.
    
- **DNS spoofing:** respuestas DNS falsas para redirigir tráfico.
    
- **DNS cache poisoning:** contaminación de una caché DNS con registros falsos.
    
- **Ettercap:** herramienta que puede utilizarse en escenarios MITM para manipular tráfico, incluidas respuestas DNS.
