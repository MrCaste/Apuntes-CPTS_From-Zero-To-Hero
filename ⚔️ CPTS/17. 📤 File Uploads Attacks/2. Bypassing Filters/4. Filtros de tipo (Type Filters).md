
## 1. Concepto

Los filtros de tipo comprueban el tipo de contenido del archivo, no solamente su extensión. Esto permite detectar archivos cuyo nombre indica que son imágenes, pero cuyo contenido no corresponde a una imagen real.

Existen dos métodos principales de validación:

|Método|Qué comprueba|Cómo se obtiene|
|---|---|---|
|`Content-Type`|El tipo declarado en la petición HTTP.|Cabecera enviada por el cliente.|
|Tipo MIME|El formato detectado a partir del contenido del archivo.|Análisis del contenido, como la firma del archivo (_magic bytes_).|

**Importante:** ambos métodos pueden combinarse con filtros de extensión. Hay que identificar qué comprobaciones realiza realmente la aplicación.

---

## 2. Validación mediante `Content-Type`

### ¿Cómo funciona?

Cuando seleccionamos un archivo, el navegador suele establecer automáticamente su tipo de contenido. Sin embargo, este valor puede manipularse al modificar la petición HTTP.

Ejemplo de validación PHP:

```
$type = $_FILES['uploadFile']['type'];

if (!in_array($type, array(
    'image/jpg',
    'image/jpeg',
    'image/png',
    'image/gif'
))) {
    echo "Only images are allowed";
    die();
}
```

La aplicación obtiene el tipo declarado por el cliente y comprueba si está permitido.

### Evasión mediante Burp Suite

Si el servidor únicamente confía en la cabecera `Content-Type`, podemos modificarla en la petición de subida.

Por ejemplo:

```
Content-Disposition: form-data; name="uploadFile"; filename="shell.php"
Content-Type: image/gif
```

Aunque el archivo se llame `shell.php`, la petición declara que su contenido es una imagen GIF.

Si la aplicación solo comprueba esa cabecera, podría aceptar el archivo.

### Enumerar los tipos permitidos

Podemos utilizar una lista de SecLists para probar diferentes valores de `Content-Type`.

Descargar la lista:

```
wget https://raw.githubusercontent.com/danielmiessler/SecLists/refs/heads/master/Discovery/Web-Content/web-all-content-types.txt
```

Extraer los tipos de imagen:

```
grep 'image/' web-all-content-types.txt > image-content-types.txt
```

El archivo `image-content-types.txt` contiene los valores que podemos probar con Burp Intruder.

**Procedimiento:**

1. Capturar una petición válida de subida.
    
2. Enviar la petición a Intruder.
    
3. Seleccionar como posición de fuzzing el `Content-Type` del archivo.
    
4. Cargar `image-content-types.txt` como lista de payloads.
    
5. Comparar las respuestas para identificar los tipos aceptados.
    

### Atención a las dos cabeceras

En una petición `multipart/form-data` pueden aparecer dos cabeceras diferentes:

- **Cabecera HTTP principal:** declara el tipo de contenido de la petición completa.
    
- **Cabecera de la parte del archivo:** declara el tipo de contenido del archivo adjunto.
    

Por ejemplo:

```
Content-Type: multipart/form-data; boundary=----Boundary

------Boundary
Content-Disposition: form-data; name="uploadFile"; filename="shell.php"
Content-Type: image/gif

[CONTENIDO DEL ARCHIVO]
------Boundary--
```

En este ejemplo, la cabecera que declara el tipo del archivo es `Content-Type: image/gif`, situada dentro de la parte `multipart`.

## 3. Validación mediante el tipo MIME

### ¿Qué es el tipo MIME?

El tipo MIME identifica la categoría o formato de un archivo. Puede determinarse inspeccionando su contenido, especialmente los primeros bytes, que a menudo contienen una firma característica.

Ejemplos:

- Una imagen GIF puede comenzar con `GIF87a` o `GIF89a`.
    
- Un archivo de texto puede identificarse como texto ASCII, independientemente de que tenga una extensión `.jpg`.
    

### Comprobar el tipo de archivo en Linux

Crear un archivo de texto con extensión de imagen:

```
echo "this is a text file" > text.jpg
```

Comprobar su tipo:

```
file text.jpg
```

Resultado esperado:

```
text.jpg: ASCII text
```

La extensión es `.jpg`, pero el contenido sigue siendo texto.

Ahora, escribir una firma GIF al principio:

```
echo "GIF8" > text.jpg
```

Volver a comprobarlo:

```
file text.jpg
```

El comando puede identificarlo como datos de imagen GIF, aunque el archivo no sea una imagen GIF válida y completa.

**Conclusión:** la extensión no determina necesariamente el tipo detectado a partir del contenido.

## 4. ¿Cómo comprueba PHP el tipo MIME?

Una aplicación puede utilizar `mime_content_type()` para detectar el tipo MIME del archivo:

```
$type = mime_content_type($_FILES['uploadFile']['tmp_name']);

if (!in_array($type, array(
    'image/jpg',
    'image/jpeg',
    'image/png',
    'image/gif'
))) {
    echo "Only images are allowed";
    die();
}
```

Diferencia respecto al método anterior:

|Método|Fuente del tipo|
|---|---|
|`$_FILES['uploadFile']['type']`|Valor declarado en la petición de subida.|
|`mime_content_type($_FILES['uploadFile']['tmp_name'])`|Tipo detectado a partir del archivo almacenado temporalmente.|

Modificar la cabecera `Content-Type` no debería ser suficiente si el servidor también analiza el contenido del archivo.

## 5. Evasión mediante firmas de archivo (_Magic Bytes_)

En el laboratorio del módulo se demuestra una aplicación que comprueba tanto el `Content-Type` como el tipo MIME.

### Problema

Cambiar únicamente la cabecera no funciona porque el servidor también inspecciona el contenido.

### Técnica del módulo

El ejercicio utiliza la cadena `GIF8` al principio del contenido del archivo para imitar la firma de una imagen GIF:

```
GIF8
```

En el laboratorio, se combina esta firma con un archivo PHP y se utiliza una cabecera `Content-Type` permitida.

Si las comprobaciones son insuficientes, el archivo puede superar la validación.

**Importante:** `GIF8` por sí solo no convierte un archivo en una imagen GIF válida. Además, la aceptación y la ejecución del código dependen de cómo estén implementados los filtros y de la configuración del servidor.

### ¿Por qué aparece `GIF8` en la respuesta?

Si PHP ejecuta el código del archivo, el contenido anterior a la apertura de PHP puede enviarse como texto al navegador.

Por ejemplo, si el archivo comienza con:

```
GIF8
```

antes del código PHP, ese texto puede aparecer al principio de la respuesta.

## 6. Combinar pruebas de validación

Una aplicación puede comprobar simultáneamente:

- La extensión del archivo.
    
- La cabecera `Content-Type`.
    
- El tipo MIME detectado.
    
- El contenido del archivo.
    

En el laboratorio, conviene identificar cada comprobación y comparar las respuestas al modificar un elemento cada vez.

|Comprobación|Qué investigar|
|---|---|
|Extensión|Si se permiten únicamente extensiones concretas.|
|`Content-Type`|Si el servidor confía en el tipo declarado por el cliente.|
|Tipo MIME|Si se analiza el contenido real del archivo.|
|Firma del archivo|Si se comprueba que el contenido corresponde a un formato válido.|
|Ejecución|Si el servidor interpreta el archivo como código ejecutable.|

Superar una comprobación no significa necesariamente que se hayan superado las demás.

## 7. Flujo de trabajo para el laboratorio

1. Intentar subir un archivo con contenido PHP y observar el mensaje de error.
    
2. Probar variaciones de extensión para determinar si existe un filtro adicional.
    
3. Si las extensiones no cambian el resultado, investigar la validación del contenido.
    
4. Modificar la cabecera `Content-Type` mediante Burp Suite.
    
5. Si sigue fallando, comprobar si el servidor analiza el tipo MIME del archivo.
    
6. Comparar las respuestas al modificar las cabeceras y el contenido.
    
7. Verificar por separado si el archivo se acepta, dónde se almacena y si el servidor ejecuta su código.
    

## 🎯 Chuleta para el examen

- `**Content-Type**`**:** valor declarado en la petición HTTP; puede ser manipulado por el cliente.
    
- **Tipo MIME:** clasificación del archivo a partir de su contenido.
    
- `**mime_content_type()**`**:** función PHP para detectar el tipo MIME de un archivo.
    
- **Magic bytes:** bytes iniciales que ayudan a identificar el formato de un archivo.
    
- `**GIF87a**` **/** `**GIF89a**`**:** firmas características de imágenes GIF.
    
- **Burp Intruder:** permite probar diferentes valores de `Content-Type`.
    
- `**file**`**:** comando Linux que ayuda a identificar el tipo de archivo.
    
- **Dos cabeceras posibles:** la cabecera principal de la petición y la cabecera de la parte del archivo.
    
- **Firma imitada ≠ archivo válido:** incluir `GIF8` no garantiza que el archivo sea una imagen real.
    
- **Archivo aceptado ≠ código ejecutado:** la ejecución depende también de la configuración del servidor web.
