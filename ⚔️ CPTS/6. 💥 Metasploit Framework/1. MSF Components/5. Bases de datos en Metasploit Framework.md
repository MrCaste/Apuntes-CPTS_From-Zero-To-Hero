
## 1. ¿Para qué sirven las bases de datos?

Metasploit utiliza **PostgreSQL** para almacenar y organizar los resultados de las evaluaciones de seguridad.

Permiten guardar:

- Hosts descubiertos.
    
- Servicios y puertos abiertos.
    
- Vulnerabilidades identificadas.
    
- Credenciales recopiladas.
    
- Loot (información extraída de los sistemas).
    
- Notas y otros resultados de las evaluaciones.
    

Además, permiten importar y exportar resultados de herramientas externas, como Nmap, y utilizar la información almacenada para configurar módulos de Metasploit.

## 2. Configurar la base de datos

### Comprobar el estado de PostgreSQL

```
sudo service postgresql status
```

### Iniciar PostgreSQL

```
sudo systemctl start postgresql
```

### Inicializar la base de datos de Metasploit

```
sudo msfdb init
```

Este comando inicializa la base de datos de MSF, crea el usuario y las bases de datos necesarias y configura el esquema inicial.

### Comprobar el estado de la base de datos

```
sudo msfdb status
```

### Iniciar Metasploit con la base de datos

```
sudo msfdb run
```

### Reinicializar la base de datos

Si existen problemas con la configuración o con la contraseña del usuario de MSF, el módulo propone:

```
msfdb reinit
cp /usr/share/metasploit-framework/config/database.yml ~/.msf4/
sudo service postgresql restart
msfconsole -q
```

Una vez dentro de `msfconsole`, comprobar la conexión:

```
db_status
```

Si funciona, aparecerá un mensaje similar a:

```
[*] Connected to msf. Connection type: postgresql.
```

**Nota:** Si `msfdb init` produce errores relacionados con Metasploit desactualizado, el material recomienda actualizarlo con `apt update` e intentar inicializar la base de datos nuevamente.

Consultar los comandos disponibles:

```
help database
```

|Comando|Función|
|---|---|
|`db_connect`|Conectarse a una base de datos existente.|
|`db_disconnect`|Desconectarse de la base de datos actual.|
|`db_export`|Exportar los datos de la base de datos.|
|`db_import`|Importar resultados de escaneo.|
|`db_nmap`|Ejecutar Nmap y almacenar automáticamente sus resultados.|
|`db_rebuild_cache`|Reconstruir la caché de módulos almacenada.|
|`db_status`|Mostrar el estado de la conexión.|
|`hosts`|Consultar los hosts almacenados.|
|`services`|Consultar los servicios almacenados.|
|`creds`|Consultar las credenciales almacenadas.|
|`loot`|Consultar la información extraída.|
|`notes`|Consultar las notas almacenadas.|
|`vulns`|Consultar las vulnerabilidades almacenadas.|
|`workspace`|Gestionar los espacios de trabajo.|

## 4. Workspaces

Los _workspaces_ permiten separar los resultados de diferentes evaluaciones, redes, subredes, dominios o máquinas.

### Listar los workspaces

```
workspace
```

El asterisco `*` indica cuál está activo.

### Crear un workspace

```
workspace -a Target_1
```

### Cambiar de workspace

```
workspace Target_1
```

### Eliminar un workspace

```
workspace -d Target_1
```

### Renombrar un workspace

```
workspace -r
```

El material muestra la opción de renombrado, pero no desarrolla su sintaxis completa.

### Mostrar la ayuda

```
workspace -h
```

Otros comandos disponibles:

```
workspace -v
workspace -D
```

- `-v`: muestra los workspaces de forma detallada.
    
- `-D`: elimina todos los workspaces.
    

**Importante:** Organiza cada evaluación en su propio workspace para mantener separados los resultados.

## 5. Importar resultados de Nmap

El comando `db_import` permite importar resultados de escaneo a la base de datos.

Se recomienda utilizar archivos **XML**.

### Importar un escaneo

```
db_import Target.xml
```

Después, consultar los resultados:

```
hosts
services
```

- `hosts`: muestra los equipos descubiertos.
    
- `services`: muestra los servicios y puertos identificados.
    

La información importada queda asociada al workspace activo.

## 6. Ejecutar Nmap desde msfconsole

También puedes ejecutar Nmap directamente desde Metasploit con `db_nmap`.

```
db_nmap -sV -sS 10.10.10.8
```

- `-sV`: detecta versiones de los servicios.
    
- `-sS`: realiza un escaneo TCP SYN.
    

Los resultados se guardan automáticamente en la base de datos.

Para consultarlos:

```
hosts
services
```

**Ventaja:** No necesitas exportar e importar manualmente los resultados de Nmap.

## 7. Exportar y respaldar los datos

Para consultar los formatos disponibles:

```
db_export -h
```

El material indica los formatos `xml` y `pwdump`.

### Exportar la base de datos a XML

```
db_export -f xml backup.xml
```

La exportación permite conservar los resultados y volver a importarlos cuando sea necesario.

## 8. Gestionar hosts

El comando `hosts` muestra los equipos registrados en la base de datos.

### Consultar los hosts

```
hosts
```

### Mostrar las opciones

```
hosts -h
```

Opciones importantes:

|Opción|Función|
|---|---|
|`-a`|Añadir hosts.|
|`-d`|Eliminar hosts.|
|`-u`|Mostrar únicamente hosts activos.|
|`-S`|Filtrar resultados mediante una búsqueda.|
|`-c`|Mostrar columnas específicas.|
|`-o`|Exportar la salida a CSV.|
|`-R`|Establecer `RHOSTS` a partir de los resultados de la búsqueda.|
|`-n`|Modificar el nombre de un host.|
|`-m`|Modificar los comentarios de un host.|
|`-i`|Modificar la información de un host.|
|`-t`|Añadir o especificar etiquetas para un conjunto de hosts.|

Ejemplos:

```
hosts -u
hosts -S 10.10.10.40
hosts -R
```

`hosts -R` permite establecer `RHOSTS` utilizando los resultados de la consulta actual.

## 9. Gestionar servicios

El comando `services` permite consultar y administrar los servicios descubiertos.

### Consultar los servicios

```
services
```

### Mostrar las opciones

```
services -h
```

Opciones importantes:

|Opción|Función|
|---|---|
|`-a`|Añadir servicios.|
|`-d`|Eliminar servicios.|
|`-u`|Mostrar servicios activos.|
|`-p`|Filtrar por puertos.|
|`-s`|Filtrar por nombres de servicios.|
|`-r`|Especificar el protocolo (`tcp` o `udp`) al añadir servicios.|
|`-S`|Buscar servicios.|
|`-o`|Exportar la salida a CSV.|
|`-R`|Establecer `RHOSTS` a partir de los resultados de la búsqueda.|
|`-U`|Actualizar información de servicios existentes.|

Ejemplos:

```
services
services -p 445
services -s smb
services -R
```

## 10. Gestionar credenciales

El comando `creds` permite consultar, añadir, filtrar y eliminar credenciales recopiladas durante las interacciones con los objetivos.

### Listar las credenciales

```
creds
```

### Mostrar las opciones

```
creds -h
```

### Filtrar credenciales

```
creds -u administrator
creds -P password
creds -p 22
creds -s ssh,smb
creds -t ntlm
creds -v
```

- `-u`: filtra por usuario.
    
- `-P`: filtra por contraseña.
    
- `-p`: filtra por puertos.
    
- `-s`: filtra por servicios.
    
- `-t`: filtra por tipo de credencial.
    
- `-v`: muestra hashes y otros valores largos sin truncarlos.
    

### Añadir credenciales manualmente

Usuario y contraseña:

```
creds add user:admin password:'notpassword'
```

Añadir únicamente una contraseña:

```
creds add password:'password without username'
```

Añadir un usuario con un hash NTLM:

```
creds add user:admin ntlm:HASH_NTLM
```

Añadir un usuario y una clave SSH:

```
creds add user:sshadmin ssh-key:/path/to/id_rsa
```

### Exportar credenciales

```
creds -o credentials.csv
```

También se pueden exportar en formatos compatibles con John the Ripper o Hashcat utilizando las extensiones correspondientes:

```
creds -o hashes.jtr
creds -o hashes.hcat
```

### Eliminar credenciales

```
creds -d -s smb
```

Este ejemplo elimina las credenciales asociadas al servicio SMB.

## 11. Gestionar Loot

El _loot_ es la información extraída de los sistemas durante una evaluación. Puede incluir volcados de hashes y archivos como `passwd` o `shadow`.

### Consultar el loot

```
loot
```

### Mostrar las opciones

```
loot -h
```

Opciones principales:

|Opción|Función|
|---|---|
|`-a`|Añadir loot.|
|`-d`|Eliminar loot asociado a hosts y tipos determinados.|
|`-f`|Especificar el archivo que se va a añadir.|
|`-i`|Añadir información descriptiva.|
|`-t`|Filtrar o especificar tipos de loot.|
|`-S`|Buscar entradas.|

Ejemplo de consulta:

```
loot -t hash
```

Ejemplo de adición:

```
loot -f hashes.txt -i "Hash dump" -a 10.10.10.40 -t hash
```

## 12. Flujo de trabajo práctico

Secuencia básica para organizar una evaluación con Metasploit:

**1. Iniciar PostgreSQL e inicializar la base de datos, si es necesario.**

```
sudo systemctl start postgresql
sudo msfdb init
```

**2. Iniciar Metasploit con la base de datos.**

```
sudo msfdb run
```

**3. Crear un workspace para el objetivo.**

```
workspace -a Target_1
```

**4. Ejecutar Nmap desde Metasploit.**

```
db_nmap -sV -sS 10.10.10.40
```

**5. Consultar los resultados.**

```
hosts
services
```

**6. Consultar las credenciales y el loot recopilados.**

```
creds
loot
```

**7. Exportar una copia de los resultados.**

```
db_export -f xml backup.xml
```

### Comandos que debes recordar

|Objetivo|Comando|
|---|---|
|Comprobar la conexión|`db_status`|
|Ver los workspaces|`workspace`|
|Crear un workspace|`workspace -a <nombre>`|
|Cambiar de workspace|`workspace <nombre>`|
|Importar resultados|`db_import <archivo.xml>`|
|Escanear y guardar resultados|`db_nmap <opciones> <IP>`|
|Consultar hosts|`hosts`|
|Consultar servicios|`services`|
|Consultar credenciales|`creds`|
|Consultar loot|`loot`|
|Exportar resultados|`db_export -f xml <archivo.xml>`|

**Idea clave:** La base de datos de Metasploit centraliza los resultados de reconocimiento y explotación. Los _workspaces_ separan las evaluaciones, `db_nmap` y `db_import` incorporan resultados, y los comandos `hosts`, `services`, `creds` y `loot` permiten consultar la información almacenada.
