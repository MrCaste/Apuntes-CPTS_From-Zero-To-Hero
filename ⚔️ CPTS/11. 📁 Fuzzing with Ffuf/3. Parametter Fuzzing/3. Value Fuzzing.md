
## 1. Objetivo

Una vez descubierto un parámetro funcional, el siguiente paso es encontrar el **valor correcto** que espera la aplicación.

En el laboratorio anterior descubrimos el parámetro `id`, pero al enviar `id=key` recibimos:

```
<div class='center'><p>Invalid id!</p></div>
```

Esto indica que debemos probar distintos valores para identificar uno válido.

## 2. Crear una wordlist personalizada

Cuando no existe una wordlist adecuada, podemos crear una propia según el tipo de dato que espera el parámetro.

En este laboratorio suponemos que `id` acepta valores numéricos secuenciales.

### Generar números del 1 al 1000

```
for i in $(seq 1 1000); do echo $i >> ids.txt; done
```

Este comando:

- `seq 1 1000`: genera los números del 1 al 1000.
    
- `echo $i`: imprime cada número.
    
- `>> ids.txt`: añade cada número al archivo `ids.txt`.
    

### Comprobar la wordlist

```
cat ids.txt
```

El archivo contendrá:

```
1
2
3
4
5
...
1000
```

**Importante:** si ejecutas el comando varias veces, los números se añadirán de nuevo al archivo. Para regenerarlo desde cero, utiliza:

```
seq 1 1000 > ids.txt
```

## 3. Fuzzing de valores con ffuf

Ahora colocamos `FUZZ` en el **valor** del parámetro `id`, no en su nombre.

```
ffuf -w ids.txt:FUZZ \
-u http://admin.academy.htb:PORT/admin/admin.php \
-X POST \
-d 'id=FUZZ' \
-H 'Content-Type: application/x-www-form-urlencoded' \
-fs TAMAÑO
```

Sustituye:

- `PORT` por el puerto asignado al laboratorio.
    
- `TAMAÑO` por el tamaño de las respuestas que quieras filtrar.
    

### Parámetros importantes

|Parámetro|Función|
|---|---|
|`-w ids.txt:FUZZ`|Utiliza la wordlist de valores numéricos.|
|`-u`|Define la URL objetivo.|
|`-X POST`|Envía peticiones POST.|
|`-d 'id=FUZZ'`|Prueba cada número como valor del parámetro `id`.|
|`-H`|Especifica la cabecera HTTP.|
|`-fs`|Filtra respuestas según su tamaño.|

## 4. Interpretar los resultados

Durante el escaneo, `ffuf` prueba sucesivamente los valores de `ids.txt`.

Si una petición devuelve una respuesta diferente a las respuestas de error habituales, puede indicar que hemos encontrado un valor válido.

El procedimiento es:

1. Identificar el valor que produce una respuesta diferente.
    
2. Anotar el valor de `id`.
    
3. Enviar una petición POST manual con `curl`.
    
4. Comprobar la respuesta de la aplicación.
    

## 5. Validar el valor con curl

Una vez identificado el valor, podemos probarlo manualmente:

```
curl -X POST \
  'http://admin.academy.htb:PORT/admin/admin.php' \
  -d 'id=VALOR_ENCONTRADO' \
  -H 'Content-Type: application/x-www-form-urlencoded'
```

Sustituye `VALOR_ENCONTRADO` por el número que haya devuelto el escaneo.

Según el ejercicio, el objetivo es encontrar el valor que permita obtener la flag.

## 6. Resumen para el examen

- **Parameter fuzzing:** descubre nombres de parámetros.
    
- **Value fuzzing:** descubre valores válidos para un parámetro conocido.
    
- **Wordlist personalizada:** resulta útil cuando no existe una lista apropiada.
    
- **Generar números:** `seq 1 1000 > ids.txt`.
    
- **Fuzzing de valores POST:** `-d 'id=FUZZ'`.
    
- **Validación manual:** utilizar `curl` con el valor encontrado.
    
- **Filtrado:** `-fs` permite excluir respuestas de un tamaño determinado.
    
- Una respuesta diferente es un indicio de que el valor puede ser válido; hay que comprobarlo manualmente.
