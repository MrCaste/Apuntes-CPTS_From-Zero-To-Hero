
## 1. Objetivo

El **parameter fuzzing** permite descubrir parámetros HTTP que una aplicación web utiliza, pero que no están documentados o visibles directamente.

Los parámetros pueden enviarse mediante peticiones **GET** o **POST**.

En esta sección nos centramos en los parámetros GET.

## 2. Identificar parámetros GET

Los parámetros GET se envían en la URL después del símbolo `?`.

Ejemplo:

```
http://admin.academy.htb:PORT/admin/admin.php?param1=key
```

- `?`: indica el comienzo de los parámetros.
    
- `param1`: nombre del parámetro.
    
- `key`: valor del parámetro.
    
- `&`: permite añadir parámetros adicionales.
    

Ejemplo con varios parámetros:

```
http://example.com/page.php?user=admin&id=1
```

## 3. Wordlist para enumerar parámetros

SecLists contiene una wordlist específica para este propósito:

```
/opt/useful/seclists/Discovery/Web-Content/burp-parameter-names.txt
```

En Kali también puede encontrarse en:

```
/usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt
```

## 4. Fuzzing de parámetros con ffuf

Para descubrir parámetros, colocamos `FUZZ` en el nombre del parámetro y mantenemos un valor de prueba, en este caso `key`.

```
ffuf -w /opt/useful/seclists/Discovery/Web-Content/burp-parameter-names.txt:FUZZ \
-u 'http://admin.academy.htb:PORT/admin/admin.php?FUZZ=key' \
-fs TAMAÑO
```

Sustituye `PORT` por el puerto del laboratorio y `TAMAÑO` por el tamaño de las respuestas que quieras filtrar.

### Parámetros importantes

|Parámetro|Función|
|---|---|
|`-w`|Especifica la wordlist.|
|`-u`|Define la URL objetivo.|
|`FUZZ`|Marcador que se sustituye por cada posible nombre de parámetro.|
|`-fs`|Filtra las respuestas por tamaño.|

**Importante:** el tamaño que debes excluir depende de las respuestas que genere tu objetivo. No existe un tamaño universal.

## 5. Analizar los resultados

Al visitar inicialmente:

```
http://admin.academy.htb:PORT/admin/admin.php
```

la aplicación muestra:

```
No tienes acceso para leer la flag
```

Esto sugiere que puede existir algún mecanismo adicional para autorizar el acceso.

Tras ejecutar el fuzzing de parámetros, encontramos un parámetro que produce una respuesta diferente.

Al probarlo manualmente, la aplicación devuelve:

```
This method is deprecated
```

Esto indica que el parámetro encontrado corresponde a un método obsoleto y que, según el resultado del laboratorio, ya no está en uso.

Por tanto, **encontrar un parámetro no significa que sea funcional o que permita acceder a la información protegida**.

## 6. Flujo de trabajo

1. Identificar una página interesante, como `admin/admin.php`.
    
2. Comprobar la respuesta que devuelve sin parámetros.
    
3. Seleccionar una wordlist de nombres de parámetros.
    
4. Colocar `FUZZ` en el nombre del parámetro GET.
    
5. Ejecutar `ffuf`.
    
6. Filtrar las respuestas repetitivas mediante `-fs`.
    
7. Investigar los resultados diferentes manualmente.
    
8. Comprobar si el parámetro sigue activo y cómo responde la aplicación.
    

## 7. Resumen para el examen

- **GET:** transmite parámetros en la URL.
    
- **Separador inicial:** `?`.
    
- **Parámetros adicionales:** se separan mediante `&`.
    
- **Wordlist:** `burp-parameter-names.txt`.
    
- **Fuzzing:** `?FUZZ=key`.
    
- **Filtro por tamaño:** `-fs`.
    
- **Resultado diferente:** puede indicar un parámetro válido, pero debe comprobarse manualmente.
    
- **Parámetro encontrado:** no implica necesariamente que esté activo ni que permita eludir controles de acceso.
