
## 1. Objetivo

Identificar **subdominios** de un dominio mediante `ffuf`, utilizando una wordlist con nombres comunes.

Ejemplos:

- `www.inlanefreight.com`
    
- `blog.inlanefreight.com`
    
- `support.inlanefreight.com`
    

## 2. Wordlist

SecLists incluye wordlists específicas para enumerar subdominios DNS:

```
/opt/useful/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

En Kali, también puede encontrarse en:

```
/usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

## 3. Enumeración de subdominios con ffuf

La clave `FUZZ` representa la parte del dominio que queremos descubrir.

```
ffuf -w /opt/useful/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ \
-u https://FUZZ.inlanefreight.com/
```

**Funcionamiento:**

1. `-w`: especifica la wordlist.
    
2. `:FUZZ`: define la palabra clave que se sustituirá por cada entrada.
    
3. `-u`: establece la URL objetivo.
    
4. `FUZZ.inlanefreight.com`: prueba los posibles subdominios.
    

Ejemplos de resultados:

```
[Status: 301] FUZZ: support
[Status: 301] FUZZ: blog
[Status: 200] FUZZ: www
```

Podemos comprobar los subdominios encontrados visitando las URL correspondientes.

## 4. Enumeración en dominios de laboratorio

Ejemplo para `academy.htb`:

```
ffuf -w /opt/useful/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ \
-u http://FUZZ.academy.htb/
```

Si no aparecen resultados, **no significa necesariamente que no existan subdominios**.

### ¿Por qué puede fallar?

Si únicamente añadimos el dominio principal a `/etc/hosts`, por ejemplo:

```
10.129.XX.XX academy.htb
```

Esto no registra automáticamente sus subdominios.

Cuando `ffuf` prueba `dev.academy.htb`, el sistema necesita resolver ese nombre. Si no existe una entrada correspondiente en `/etc/hosts` ni un registro DNS que lo resuelva, no podrá localizar el servidor.

**Importante:** en un laboratorio HTB, que el dominio principal funcione no garantiza que sus subdominios estén configurados en DNS público.

## 5. Comandos útiles

### Comprobar el archivo de hosts

```
cat /etc/hosts
```

### Comprobar la resolución DNS de un subdominio

```
nslookup dev.academy.htb
```

También podemos probar:

```
dig dev.academy.htb
```

### Probar manualmente un subdominio

```
curl -I http://dev.academy.htb/
```

Estos comandos permiten comprobar si un nombre se resuelve y si el servidor responde.

## 6. Resumen para el examen

- **Subdomain fuzzing:** busca nombres como `dev.dominio.com` o `blog.dominio.com`.
    
- **Wordlist:** `Discovery/DNS/subdomains-top1million-5000.txt`.
    
- **Parámetro principal:** `-w`.
    
- **Posición de** `**FUZZ**`**:** antes del dominio principal, como en `https://FUZZ.dominio.com/`.
    
- **HTTP 200:** el servidor devuelve una respuesta satisfactoria.
    
- **HTTP 301/302:** el servidor redirige la petición.
    
- **Sin resultados:** no demuestra que no existan subdominios; puede ser un problema de resolución DNS o de configuración del laboratorio.
    
- `**/etc/hosts**`**:** una entrada para el dominio principal no incluye automáticamente sus subdominios.
