
## 1. VHosts vs. Subdominios

- **Subdomain fuzzing:** busca subdominios, normalmente mediante nombres que se resuelven a través de registros DNS.
    
- **VHost fuzzing:** busca hosts virtuales que el servidor web ofrece en una misma IP, enviando distintos valores en la cabecera HTTP `Host`.
    

Un servidor puede alojar varios sitios web en la misma IP. Algunos VHosts pueden no tener registros DNS públicos, por lo que no se descubrirán mediante el fuzzing de subdominios tradicional.

**Diferencia clave:** los VHosts se pueden descubrir modificando la cabecera `Host` de las peticiones HTTP, sin necesitar una entrada DNS para cada uno.

## 2. Fuzzing de VHosts con ffuf

Utilizamos una wordlist de nombres habituales y sustituimos `FUZZ` en la cabecera `Host`.

```
ffuf -w /opt/useful/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ \
-u http://academy.htb:PORT/ \
-H 'Host: FUZZ.academy.htb'
```

En Kali, la wordlist también puede encontrarse en:

```
/usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

### Parámetros importantes

|Parámetro|Función|
|---|---|
|`-w`|Especifica la wordlist.|
|`-u`|Define la URL del servidor objetivo.|
|`-H`|Añade una cabecera HTTP personalizada.|
|`FUZZ`|Marcador que `ffuf` sustituye por cada palabra de la lista.|

**Importante:** sustituye `PORT` por el puerto real del laboratorio.

## 3. Interpretar los resultados

Al ejecutar el escaneo, podemos encontrar que muchos nombres devuelven:

```
mail2    [Status: 200, Size: 900, Words: 423, Lines: 56]
dns2     [Status: 200, Size: 900, Words: 423, Lines: 56]
ns3      [Status: 200, Size: 900, Words: 423, Lines: 56]
webmail  [Status: 200, Size: 900, Words: 423, Lines: 56]
```

Esto no significa que todos esos VHosts existan. En el ejemplo de HTB, todas las peticiones devuelven la misma respuesta porque se está accediendo al mismo servidor y únicamente se cambia la cabecera `Host`.

### ¿Cómo identificar un posible VHost?

Hay que buscar respuestas que se diferencien de las demás, especialmente en:

- `**Status**`**:** código HTTP devuelto.
    
- `**Size**`**:** tamaño de la respuesta.
    
- `**Words**`**:** cantidad de palabras.
    
- `**Lines**`**:** cantidad de líneas.
    

Si un VHost existe y el servidor sirve una página diferente para ese nombre, es posible que la respuesta tenga un tamaño distinto.

Por ejemplo, si casi todas las respuestas tienen `Size: 900`, pero una devuelve `Size: 2500`, esa entrada merece investigarse.

Un tamaño diferente es un **indicio**, no una confirmación definitiva.

## 4. Resumen para el examen

- **Subdomain fuzzing:** busca subdominios mediante nombres como `dev.dominio.com`.
    
- **Vhost fuzzing:** prueba distintos nombres mediante la cabecera HTTP `Host`.
    
- **Parámetro fundamental:** `-H 'Host: FUZZ.dominio.htb'`.
    
- **No es necesario añadir manualmente cada VHost a** `**/etc/hosts**` **para realizar el escaneo.**
    
- Si todas las respuestas tienen el mismo código y tamaño, puede que el servidor esté devolviendo la misma página para todos los nombres.
    
- Compara `Status`, `Size`, `Words` y `Lines` para detectar respuestas diferentes.
    
- Una respuesta distinta puede revelar un VHost, pero hay que investigarla para confirmarlo.
