
## 1. Opciones de filtrado y coincidencia

`ffuf` permite filtrar o seleccionar respuestas según distintos criterios:

- Código HTTP.
    
- Tamaño de la respuesta.
    
- Número de palabras.
    
- Número de líneas.
    
- Expresiones regulares.
    

### Matchers: seleccionar resultados

|Parámetro|Función|
|---|---|
|`-mc`|Seleccionar por código HTTP.|
|`-ml`|Seleccionar por número de líneas.|
|`-mr`|Seleccionar por expresión regular.|
|`-ms`|Seleccionar por tamaño de respuesta.|
|`-mw`|Seleccionar por número de palabras.|

### Filters: excluir resultados

|Parámetro|Función|
|---|---|
|`-fc`|Excluir códigos HTTP.|
|`-fl`|Excluir respuestas según el número de líneas.|
|`-fr`|Excluir respuestas que coincidan con una expresión regular.|
|`-fs`|Excluir respuestas según su tamaño.|
|`-fw`|Excluir respuestas según el número de palabras.|

Consultar todas las opciones:

```
ffuf -h
```

## 2. Filtrar resultados durante el VHost Fuzzing

En el escaneo anterior, la mayoría de los nombres probados devolvían la misma respuesta:

```
Status: 200, Size: 900, Words: 423, Lines: 56
```

Como conocemos el tamaño de las respuestas incorrectas, podemos excluirlas mediante `-fs 900`.

```
ffuf -w /opt/useful/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ \
-u http://academy.htb:PORT/ \
-H 'Host: FUZZ.academy.htb' \
-fs 900
```

Si la wordlist está en la ruta habitual de Kali, podemos utilizar:

```
/usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

### ¿Qué hace `-fs 900`?

- `-fs`: filtra por tamaño de respuesta.
    
- `900`: excluye las respuestas cuyo tamaño sea de 900 bytes.
    

Al eliminar las respuestas repetitivas, podemos identificar posibles VHosts que devuelvan contenido diferente.

**Importante:** el tamaño que debemos filtrar depende de la respuesta que obtengamos en nuestro propio objetivo. No hay que asumir que siempre será de 900 bytes.

## 3. Identificar un VHost válido

En el ejemplo de HTB, después de filtrar las respuestas aparece:

```
admin    [Status: 200, Size: 0, Words: 1, Lines: 1]
```

Esto indica que `admin.academy.htb` devuelve una respuesta diferente a las respuestas comunes.

Para acceder al VHost desde nuestra máquina, debemos añadirlo a `/etc/hosts`, junto con la IP del objetivo:

```
IP_DEL_OBJETIVO academy.htb admin.academy.htb
```

Editar el archivo:

```
sudo nano /etc/hosts
```

Después, podemos visitar:

```
http://admin.academy.htb:PORT/
```

Debemos utilizar el puerto real asignado al laboratorio. Si el objetivo se ha reiniciado, hay que comprobar si el puerto ha cambiado.

### Confirmar que es un VHost diferente

Podemos comparar el contenido servido por el dominio principal con el del VHost encontrado.

Por ejemplo, en el laboratorio, al acceder a:

```
http://admin.academy.htb:PORT/blog/index.php
```

se obtiene un `404 PAGE NOT FOUND`, mientras que el dominio principal devuelve contenido diferente.

Esto aporta evidencia de que estamos accediendo a un VHost distinto.

## 4. Fuzzing recursivo del VHost encontrado

Una vez identificado `admin.academy.htb`, podemos buscar directorios y páginas mediante fuzzing recursivo.

```
ffuf -w /opt/useful/seclists/Discovery/Web-Content/directory-list-2.3-small.txt:FUZZ \
-u http://admin.academy.htb:PORT/FUZZ \
-recursion \
-recursion-depth 1 \
-e .php \
-v
```

### Parámetros

- `-w`: wordlist de directorios.
    
- `-u`: URL del VHost objetivo.
    
- `FUZZ`: posición donde se prueban los nombres.
    
- `-recursion`: activa el fuzzing recursivo.
    
- `-recursion-depth 1`: limita la profundidad de recursión a un nivel.
    
- `-e .php`: prueba también la extensión `.php`.
    
- `-v`: muestra resultados detallados.
    

La ruta de la wordlist puede variar según dónde esté instalado SecLists.

## 5. Resumen para el examen

- `**-fs SIZE**`**:** excluye respuestas de un tamaño determinado.
    
- `**-fc CODE**`**:** excluye códigos HTTP.
    
- `**-fw WORDS**`**:** excluye respuestas con un número concreto de palabras.
    
- `**-fl LINES**`**:** excluye respuestas con un número concreto de líneas.
    
- `**-mc CODE**`**:** selecciona respuestas por código HTTP.
    
- Si todas las respuestas de un VHost fuzzing son iguales, identifica una característica común, como su tamaño, y utiliza un filtro.
    
- Un resultado diferente es un indicio de un posible VHost válido, pero debes comprobarlo.
    
- Para acceder al VHost desde el navegador, añade su nombre a `/etc/hosts` asociado a la IP del objetivo.
    
- Después de identificarlo, realiza enumeración de directorios y archivos sobre el VHost concreto.
