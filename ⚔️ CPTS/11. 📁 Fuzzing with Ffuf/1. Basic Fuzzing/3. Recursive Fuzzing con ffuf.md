
## 1. ¿Qué es el Recursive Fuzzing?

El **Recursive Fuzzing** permite automatizar la enumeración de directorios y archivos dentro de una aplicación web.

En lugar de ejecutar manualmente `ffuf` para cada directorio encontrado, la herramienta inicia nuevos escaneos automáticamente cuando descubre directorios adicionales.

Esto resulta especialmente útil cuando una web contiene estructuras como:

```
/
├── blog/
│   ├── admin/
│   └── uploads/
├── forum/
│   └── user/
│       └── content/
└── login/
```

Sin recursividad, tendríamos que ejecutar un escaneo independiente para cada directorio.

---

## 2. Parámetros importantes

|Parámetro|Función|
|---|---|
|`-recursion`|Activa el escaneo recursivo.|
|`-recursion-depth`|Establece la profundidad máxima de recursividad.|
|`-e`|Especifica las extensiones que se probarán, por ejemplo `.php`.|
|`-v`|Muestra las URL completas en los resultados.|
|`-w`|Especifica el diccionario utilizado.|
|`-u`|Define la URL objetivo.|

**Importante:** al utilizar `-recursion`, la URL debe terminar en `FUZZ`. Esta modalidad solo admite la palabra clave `FUZZ` para la recursividad.

---

## 3. Escaneo recursivo básico

Comando utilizado en HTB Academy:

```
ffuf -w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-small.txt:FUZZ \
-u http://TARGET:PORT/FUZZ \
-recursion \
-recursion-depth 1 \
-e .php \
-v
```

### Explicación

- `-w`: utiliza el diccionario de directorios.
    
- `:FUZZ`: asigna la palabra clave al diccionario.
    
- `-u`: indica la URL objetivo.
    
- `-recursion`: activa la enumeración recursiva.
    
- `-recursion-depth 1`: limita la profundidad a un nivel de recursividad.
    
- `-e .php`: prueba también los nombres con extensión `.php`.
    
- `-v`: muestra las URL completas para identificar en qué directorio está cada archivo.
    

### Ejemplo de resultados

```
[Status: 301] | URL | http://TARGET:PORT/blog
[Status: 200] | URL | http://TARGET:PORT/index.php
[Status: 200] | URL | http://TARGET:PORT/blog/index.php
```

Cuando encuentra un directorio como `/blog/`, `ffuf` añade automáticamente un nuevo trabajo de escaneo para buscar contenido dentro de él.

---

## 4. Controlar la profundidad de recursividad

La recursividad puede aumentar considerablemente el número de peticiones, por lo que conviene limitar la profundidad.

### Profundidad 1

```
-recursion-depth 1
```

Busca directorios en la web principal y realiza un nivel adicional de enumeración dentro de los directorios descubiertos.

Si encuentra una estructura como:

```
/login/user/
```

no continuará enumerando su contenido si eso requiere superar la profundidad configurada.

### Profundidad mayor

```
-recursion-depth 2
```

Permite explorar un nivel adicional de directorios.

**Recomendación:** comienza con una profundidad de `1`. Después, realiza escaneos más profundos en los directorios que parezcan interesantes.

---

## 5. Enumerar extensiones durante la recursividad

Podemos utilizar `-e` para probar archivos con extensiones concretas:

```
-e .php
```

De esta manera, además de buscar directorios, `ffuf` busca nombres de archivos con la extensión indicada.

Por ejemplo:

```
/blog/index.php
/forum/index.php
/login.php
```

Las extensiones habituales que pueden investigarse incluyen:

- `.php`
    
- `.html`
    
- `.aspx`
    

Debemos elegir las extensiones en función de la aplicación objetivo y de los resultados de la enumeración anterior.

---

## 6. ¿Por qué utilizar `-v`?

Cuando se ejecuta un escaneo recursivo, se generan resultados de diferentes directorios.

Con `-v`, `ffuf` muestra las URL completas, lo que permite identificar la ubicación de cada recurso.

Por ejemplo:

```
http://TARGET:PORT/index.php
http://TARGET:PORT/blog/index.php
http://TARGET:PORT/forum/index.php
```

Sin esta información, puede resultar más difícil distinguir qué archivo pertenece a cada directorio.

---

## 7. Consideraciones sobre el rendimiento

La recursividad puede aumentar considerablemente el número de peticiones porque:

1. Se realiza el escaneo inicial.
    
2. Se crean nuevos trabajos para los directorios encontrados.
    
3. Se repite el proceso hasta alcanzar la profundidad configurada.
    

Por ello, un escaneo recursivo puede tardar bastante más que uno básico.

Para evitar escaneos innecesariamente largos:

- Limita `-recursion-depth`.
    
- Empieza con diccionarios pequeños.
    
- Prioriza los directorios interesantes.
    
- Evita aumentar excesivamente el número de hilos en sistemas remotos.

## Conceptos clave para el examen

- **Recursive Fuzzing:** automatiza la búsqueda de contenido en directorios y subdirectorios.
    
- `**-recursion**`**:** activa la recursividad.
    
- `**-recursion-depth**`**:** limita los niveles explorados.
    
- `**-e**`**:** permite buscar archivos con extensiones específicas.
    
- `**-v**`**:** muestra las URL completas.
    
- `**FUZZ**`**:** debe aparecer al final de la URL utilizada para el escaneo recursivo.
    
- **Rendimiento:** la recursividad aumenta el número de peticiones y el tiempo de escaneo.
    

**Flujo recomendado:** enumerar directorios, identificar las extensiones utilizadas y ejecutar un escaneo recursivo con una profundidad limitada para descubrir archivos y rutas adicionales.
