
## 1. Preparar peticiones HTTP para SQLMap

SQLMap permite analizar vulnerabilidades SQL Injection en diferentes partes de una petición HTTP:

- Parámetros **GET**.
    
- Parámetros **POST**.
    
- Cookies de sesión.
    
- Cabeceras HTTP.
    
- Cuerpos JSON y XML.
    
- Métodos HTTP como `GET`, `POST` y `PUT`.
    

Es importante reproducir correctamente la petición original, especialmente cuando necesita cookies, cabeceras específicas o datos POST.

### Copiar peticiones desde el navegador

Una forma sencilla de preparar una petición consiste en:

1. Abrir las herramientas de desarrollador (`F12`).
    
2. Acceder a la pestaña **Network**.
    
3. Seleccionar la petición que queremos analizar.
    
4. Hacer clic derecho y seleccionar **Copy as cURL**.
    
5. Pegar el comando en la terminal y sustituir `curl` por `sqlmap`.
    

Ejemplo:

```
sqlmap 'http://www.example.com/?id=1' \
-H 'User-Agent: Mozilla/5.0' \
-H 'Accept: */*' \
--compressed
```

**Importante:** SQLMap necesita un parámetro que pueda analizar o una opción que permita descubrir parámetros automáticamente, como `--crawl`, `--forms` o `-g`.

## 2. Analizar parámetros GET y POST

### GET

Utilizamos `-u` o `--url` para indicar la URL que queremos analizar.

```
sqlmap -u 'http://www.example.com/?id=1'
```

SQLMap analizará el parámetro `id` para comprobar si es vulnerable a SQL Injection.

### POST

Para enviar datos mediante POST utilizamos `--data`.

```
sqlmap -u 'http://www.example.com/' --data='uid=1&name=test'
```

SQLMap analizará los parámetros:

- `uid`
    
- `name`
    

### Seleccionar un parámetro específico

Si sabemos qué parámetro queremos analizar, utilizamos `-p`.

```
sqlmap -u 'http://www.example.com/' \
--data='uid=1&name=test' \
-p uid
```

Esto limita las pruebas al parámetro `uid`.

### Marcar manualmente el punto de inyección

También podemos utilizar un asterisco `*` para indicar dónde queremos que SQLMap introduzca sus payloads.

```
sqlmap -u 'http://www.example.com/' \
--data='uid=1*&name=test'
```

En este caso, SQLMap probará la inyección en el valor de `uid`.

**Diferencia:**

- `-p uid`: selecciona el parámetro completo.
    
- `*`: indica una posición concreta donde introducir los payloads.

## 3. Analizar peticiones HTTP completas

Cuando una petición contiene muchas cabeceras, cookies o un cuerpo POST complejo, es recomendable utilizar `-r`.

Esta opción permite cargar una petición HTTP completa desde un archivo.

### Capturar la petición con Burp Suite

1. Interceptar la petición utilizando Burp Suite.
    
2. Seleccionar la petición HTTP.
    
3. Hacer clic derecho y utilizar **Copy to file**.
    
4. Guardarla como `req.txt`.
    

Ejemplo del contenido:

```
GET /?id=1 HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html
Accept-Language: en-US,en;q=0.5
Connection: close
```

Ejecutamos:

```
sqlmap -r req.txt
```

SQLMap utilizará los datos de la petición guardada.

### Marcar el punto de inyección dentro del archivo

Podemos modificar directamente la petición:

```
GET /?id=1* HTTP/1.1
Host: www.example.com
```

O colocar el marcador en cualquier otro parámetro:

```
GET /?id=* HTTP/1.1
Host: www.example.com
```

Después ejecutamos:

```
sqlmap -r req.txt
```

**Consejo:** utilizar `-r` suele ser la mejor opción cuando estamos trabajando con Burp Suite, aplicaciones autenticadas o peticiones HTTP complejas.
