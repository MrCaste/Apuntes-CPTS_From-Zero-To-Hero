
## 1. Enumeración de servicios de red

Los procesos pueden comunicarse mediante **sockets de red** o **Named Pipes**.

Un servicio mal configurado que se ejecuta con privilegios elevados puede permitir escalar privilegios.

### Enumerar puertos y conexiones

```
netstat -ano
```

Muestra:

- Puertos TCP/UDP abiertos.
    
- Direcciones locales y remotas.
    
- Estado de las conexiones.
    
- PID del proceso asociado.
    

**Buscar especialmente servicios que escuchan únicamente en localhost:**

```
127.0.0.1:14147    LISTENING    3812
```

Los servicios que escuchan en `127.0.0.1` o `::1` no son accesibles directamente desde otras máquinas, pero pueden ser vulnerables a ataques locales.

### Identificar el proceso asociado a un puerto

```
tasklist /FI "PID eq 3812"
```

## 2. Servicios interesantes

### FileZilla Server

**Puerto:** `14147` (interfaz administrativa en el ejemplo del módulo).

```
127.0.0.1:14147    LISTENING
```

Si la interfaz administrativa está mal protegida, podría permitir:

- Acceder a la configuración del servidor FTP.
    
- Obtener credenciales almacenadas.
    
- Crear recursos FTP que expongan directorios sensibles.
    
- Aprovechar los privilegios del usuario que ejecuta FileZilla.
    

### Splunk Universal Forwarder

Algunas configuraciones antiguas permiten desplegar aplicaciones sin autenticación.

Si Splunk se ejecuta como `NT AUTHORITY\SYSTEM`, una configuración vulnerable podría permitir ejecutar código con esos privilegios.

**Herramientas mencionadas:**

- SplunkWhisperer2.
    
- Splunk Universal Forwarder Hijacking.
    

### Erlang

**Puerto interesante:** `25672`.

Algunas aplicaciones basadas en Erlang utilizan una _cookie_ como secreto de autenticación entre nodos.

**Buscar:**

- Cookies débiles.
    
- Cookies almacenadas en archivos accesibles.
    
- Configuraciones inseguras del clúster.
    

**Aplicaciones que utilizan Erlang:**

- RabbitMQ.
    
- CouchDB.
    
- SolarWinds.

## 3. Named Pipes

Las **Named Pipes** permiten la comunicación entre procesos de Windows.

Pueden convertirse en una vía de escalada si un proceso privilegiado utiliza una tubería con permisos demasiado permisivos.

### Enumerar Named Pipes con PipeList

```
pipelist.exe /accepteula
```

Muestra:

- Nombre de la tubería.
    
- Número de instancias.
    
- Número máximo de instancias.
    

### Enumerar Named Pipes con PowerShell

```
gci \\.\pipe\
```

Permite listar las tuberías existentes sin utilizar herramientas externas.

---

## 4. Enumerar permisos de Named Pipes

Podemos utilizar **AccessChk** de Sysinternals para revisar las DACL de las tuberías.

### Comprobar permisos de una tubería

```
accesschk.exe /accepteula \\.\Pipe\lsass -v
```

Muestra los usuarios y grupos que tienen permisos sobre la tubería.

**Permisos importantes:**

| Permiso                 | Significado                                              |
| ----------------------- | -------------------------------------------------------- |
| `FILE_READ_DATA`        | Permite leer datos.                                      |
| `FILE_WRITE_DATA`       | Permite escribir datos.                                  |
| `FILE_READ_ATTRIBUTES`  | Permite leer atributos.                                  |
| `FILE_WRITE_ATTRIBUTES` | Permite modificar atributos.                             |
| `FILE_ALL_ACCESS`       | Acceso completo.                                         |
| `RW Everyone`           | El grupo Everyone tiene permisos de lectura y escritura. |

### Buscar Named Pipes con permisos de escritura

```
accesschk.exe -w \pipe\* -v
```

**Objetivo:** identificar tuberías que permitan escritura a usuarios con pocos privilegios.

## 5. Ejemplo: WindscribeService

El módulo muestra una vulnerabilidad de escalada de privilegios relacionada con la tubería `WindscribeService`.

### Enumerar sus permisos

```
accesschk.exe -accepteula -w \pipe\WindscribeService -v
```

**Resultado:**

```
\pipe\WindscribeService
  RW Everyone
      FILE_ALL_ACCESS
```

Esto significa que el grupo `Everyone` tiene acceso completo a la tubería.

En la versión vulnerable del servicio, estos permisos pueden aprovecharse para escalar privilegios a `NT AUTHORITY\SYSTEM`.

> Los permisos de escritura sobre una Named Pipe no garantizan por sí solos una escalada. También debe existir un comportamiento vulnerable en el servicio que la utiliza.

## 6. Access Tokens y SeImpersonatePrivilege

Los procesos de Windows utilizan **Access Tokens** para determinar la identidad y los privilegios con los que se ejecutan.

Algunas cuentas de servicio, como las utilizadas por servidores web IIS, pueden disponer de `SeImpersonatePrivilege`.

### Comprobar privilegios

```
whoami /priv
```

**Buscar:**

```
SeImpersonatePrivilege    Enabled
```

Este privilegio puede permitir técnicas de suplantación de tokens cuando se cumplen las condiciones necesarias.

**Herramientas mencionadas en el módulo:**

- Juicy Potato.
    
- Rogue Potato.
    
- Lonely Potato.

## 8. Posibles vías de escalada

|Hallazgo|Posible vía|
|---|---|
|Servicio vulnerable en localhost|Explotación local del servicio.|
|FileZilla Admin mal protegido|Acceso a configuración o credenciales.|
|Splunk vulnerable ejecutándose como SYSTEM|Ejecución de código privilegiado.|
|Cookie Erlang débil o expuesta|Acceso no autorizado al clúster.|
|Named Pipe con permisos excesivos|Abuso de una funcionalidad vulnerable del servicio.|
|`SeImpersonatePrivilege`|Técnicas de suplantación de tokens.|

**Objetivo:** identificar procesos o mecanismos de comunicación que puedan utilizarse para obtener privilegios superiores a los de nuestro usuario actual.
