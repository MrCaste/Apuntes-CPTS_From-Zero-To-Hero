
## 1. Enumeración de red

Al obtener acceso a un sistema Windows, debemos identificar sus interfaces de red, rutas y otros hosts accesibles.

Esto permite detectar máquinas **dual-homed** (conectadas a varias redes), que pueden servir para realizar pivoting o movimiento lateral.

### Interfaces de red, IP y DNS

```
ipconfig /all
```

Información importante:

- **IPv4 Address:** direcciones IP del equipo.
    
- **Subnet Mask:** subredes a las que pertenece.
    
- **Default Gateway:** puertas de enlace.
    
- **DNS Servers:** servidores DNS configurados.
    
- **DNS Suffix:** posible información sobre el dominio.
    
- **Ethernet Adapters:** interfaces de red disponibles.
    

**Ejemplo:**

```
Ethernet0: 10.129.43.8/16
Ethernet1: 192.168.20.56/24
```

El equipo tiene dos interfaces conectadas a redes diferentes. Esto puede permitirnos acceder a una red interna desde el host comprometido.

### Tabla ARP

```
arp -a
```

Muestra las direcciones IP y MAC almacenadas en la caché ARP.

Sirve para identificar otros dispositivos con los que el equipo se ha comunicado recientemente.

**Ejemplo:**

```
10.129.0.1       00-50-56-b9-4d-df
10.129.43.12     00-50-56-b9-da-ad
10.129.43.13     00-50-56-b9-5b-9f
```

Estas direcciones pueden ser objetivos interesantes para enumeración posterior o movimiento lateral.

> La caché ARP no representa necesariamente todos los dispositivos existentes en la red.

### Tabla de enrutamiento

```
route print
```

Permite identificar:

- Redes directamente accesibles.
    
- Puertas de enlace.
    
- Rutas configuradas.
    
- Interfaces utilizadas para alcanzar cada red.
    

**Ejemplo:**

```
Network Destination    Netmask          Gateway
10.129.0.0             255.255.0.0      On-link
192.168.20.0           255.255.255.0    On-link
```

El host tiene acceso directo a las redes:

```
10.129.0.0/16
192.168.20.0/24
```

Esto puede revelar oportunidades de **pivoting** hacia redes que no son accesibles directamente desde nuestra máquina atacante.

## 2. Enumeración de protecciones

Antes de ejecutar herramientas de enumeración o explotación, debemos identificar las protecciones existentes.

Las principales son:

- Windows Defender.
    
- Antivirus de terceros.
    
- EDR (Endpoint Detection and Response).
    
- AppLocker.
    

### Comprobar Windows Defender

```
Get-MpComputerStatus
```

Propiedades importantes:

|Propiedad|Descripción|
|---|---|
|`AntivirusEnabled`|Indica si el antivirus está habilitado.|
|`RealTimeProtectionEnabled`|Indica si la protección en tiempo real está habilitada.|
|`BehaviorMonitorEnabled`|Indica si la monitorización de comportamiento está habilitada.|
|`OnAccessProtectionEnabled`|Indica si la protección al acceder a archivos está habilitada.|
|`AntispywareEnabled`|Indica si la protección antispyware está habilitada.|

**Ejemplo:**

```
AntivirusEnabled          : True
RealTimeProtectionEnabled : False
BehaviorMonitorEnabled    : False
OnAccessProtectionEnabled : False
```

En este ejemplo, Windows Defender está habilitado, pero varias de sus protecciones están desactivadas.

### Enumerar AppLocker

AppLocker permite restringir qué ejecutables, scripts y otros archivos pueden ejecutar determinados usuarios.

**Mostrar las reglas efectivas:**

```
Get-AppLockerPolicy -Effective | Select-Object -ExpandProperty RuleCollections
```

Debemos prestar atención a:

- `PathConditions`: rutas permitidas o restringidas.
    
- `PublisherConditions`: reglas basadas en firmas digitales.
    
- `HashConditions`: reglas basadas en hashes.
    
- `Action`: indica `Allow` o `Deny`.
    
- `UserOrGroupSid`: usuario o grupo al que se aplica la regla.
    

**Ejemplo de reglas:**

```
%PROGRAMFILES%\*    Allow
%WINDIR%\*          Allow
```

Estas reglas permiten ejecutar archivos ubicados en las rutas indicadas para los usuarios o grupos correspondientes.

### Comprobar si AppLocker bloquea un ejecutable

```
Get-AppLockerPolicy -Local | Test-AppLockerPolicy -Path C:\Windows\System32\cmd.exe -User Everyone
```

**Ejemplo de resultado:**

```
FilePath                       PolicyDecision
--------                       --------------
C:\Windows\System32\cmd.exe    Denied
```

`Denied` indica que la política local evaluada bloquea ese ejecutable para el usuario o grupo especificado.

Podemos cambiar la ruta para comprobar otros ejecutables:

```
Get-AppLockerPolicy -Local | Test-AppLockerPolicy -Path C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe -User Everyone
```

> `-Local` comprueba la política local, mientras que `-Effective` permite consultar las reglas efectivas. Para evaluar las restricciones realmente aplicadas, es preferible utilizar la política efectiva.

## 3. Checklist de enumeración

### Información de red

```
ipconfig /all
arp -a
route print
```

### Windows Defender

```
Get-MpComputerStatus
```

### AppLocker

```
# Enumerar reglas efectivas
Get-AppLockerPolicy -Effective | Select-Object -ExpandProperty RuleCollections

# Comprobar si cmd.exe está bloqueado
Get-AppLockerPolicy -Local | Test-AppLockerPolicy -Path C:\Windows\System32\cmd.exe -User Everyone
```

## 4. Objetivos de la enumeración

1. Identificar interfaces y redes internas accesibles.
    
2. Detectar hosts interesantes para movimiento lateral.
    
3. Comprobar las rutas disponibles para pivoting.
    
4. Identificar antivirus y protecciones activas.
    
5. Comprobar las restricciones de AppLocker.
    
6. Seleccionar las herramientas y técnicas de enumeración o escalada adecuadas.
