
## 1. Enumerar programas instalados

Buscar aplicaciones de terceros que puedan tener vulnerabilidades conocidas y permitir una escalada de privilegios.

**CMD:**
```cmd
wmic product get name
```

**PowerShell:**
```powershell
Get-ItemProperty "HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*" |
Select-Object DisplayName, DisplayVersion

Get-ItemProperty "HKLM:\Software\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*" |
Select-Object DisplayName, DisplayVersion
```

- Identificar programas y versiones instaladas.
- Investigar las versiones vulnerables de las aplicaciones de terceros.
- Comprobar si el servicio vulnerable se encuentra en ejecución y con qué privilegios.

## 2. Ejemplo: Druva inSync 6.6.3

La versión **Druva inSync 6.6.3** es vulnerable a una inyección de comandos mediante un servicio RPC local.

- Servicio: `Druva inSync Client Service`.
- Puerto RPC local: `6064`.
- Proceso: `inSyncCPHwnet64`.
- El servicio se ejecuta como `NT AUTHORITY\SYSTEM`.
- La vulnerabilidad permite ejecutar comandos con privilegios elevados.

## 3. Enumerar puertos locales

Comprobar si existe un servicio escuchando en el puerto `6064`.

```cmd
netstat -ano | findstr 6064
```

Ejemplo:
```text
TCP    127.0.0.1:6064    0.0.0.0:0    LISTENING    3324
```

Datos importantes:
- `127.0.0.1:6064`: servicio escuchando en el puerto local 6064.
- `LISTENING`: esperando conexiones.
- `3324`: PID del proceso asociado.

## 4. Identificar el proceso

Utilizar el PID obtenido para identificar el proceso.

```powershell
Get-Process -Id 3324
```

Ejemplo de resultado:
```text
ProcessName
-----------
inSyncCPHwnet64
```

Esto permite relacionar el puerto abierto con el proceso de Druva inSync.

## 5. Enumerar el servicio

Buscar servicios cuyo nombre visible empiece por `Druva`.

```powershell
Get-Service | Where-Object {$_.DisplayName -like 'Druva*'}
```

Ejemplo:
```text
Status   Name               DisplayName
------   ----               -----------
Running  inSyncCPHService   Druva inSync Client Service
```

Comprobar conjuntamente:
1. La aplicación y su versión.
2. El puerto local que utiliza.
3. El proceso asociado.
4. El servicio que se está ejecutando.
5. Los privilegios de la cuenta que ejecuta el servicio.

## 6. Explotación de Druva inSync

El PoC de HTB se conecta al servicio RPC local mediante un socket TCP y envía una petición que incluye un comando.

La conexión utiliza:
```text
127.0.0.1:6064
```

El encabezado del protocolo y los datos enviados identifican una petición RPC de Druva inSync. El comando se construye para ejecutar `cmd.exe` mediante una ruta que termina en el directorio de Windows.

El PoC original crea un usuario local llamado `pwnd`:

```powershell
$cmd = "net user pwnd /add"
```

**Importante:** crear el usuario no significa que se haya añadido automáticamente al grupo de administradores. El resultado depende de los permisos con los que se ejecute el comando.

En el laboratorio, el objetivo es demostrar que la vulnerabilidad permite ejecutar comandos con los privilegios del servicio, que en este caso son `SYSTEM`.

## 7. Comprobar el resultado

Si la explotación funciona, comprobar la identidad y el equipo desde la sesión obtenida:

```cmd
whoami
hostname
```

Resultado esperado en el ejemplo de HTB:

```text
nt authority\system
WINLPE-WS01
```

`NT AUTHORITY\SYSTEM` indica que se ha conseguido ejecutar comandos con privilegios de sistema local.

## 8. Flujo de enumeración para el examen

1. Enumerar los programas instalados:
   ```cmd
   wmic product get name
   ```

2. Identificar aplicaciones de terceros y versiones potencialmente vulnerables.

3. Comprobar si el servicio está escuchando en un puerto local:
   ```cmd
   netstat -ano
   ```

4. Relacionar el puerto con el PID:
   ```powershell
   Get-Process -Id <PID>
   ```

5. Buscar el servicio:
   ```powershell
   Get-Service
   ```

6. Investigar la vulnerabilidad concreta de la aplicación y verificar sus requisitos.

7. Comprobar si el servicio se ejecuta como `SYSTEM` y si la vulnerabilidad permite ejecutar comandos con esos privilegios.

8. Si se trata de un laboratorio autorizado, validar la escalada con:
   ```cmd
   whoami
   ```

## Conceptos clave

- **Software vulnerable:** una aplicación de terceros puede ofrecer una vía de escalada incluso cuando Windows está actualizado.
- **Enumeración de puertos:** permite localizar servicios que escuchan localmente.
- **PID:** permite relacionar un puerto con el proceso que lo utiliza.
- **Servicio como SYSTEM:** si una vulnerabilidad permite ejecutar comandos en el contexto de ese servicio, puede conducir a una escalada a `SYSTEM`.
- **Principio de mínimo privilegio:** los usuarios no deberían tener permisos innecesarios para instalar software.
- **Lista blanca de aplicaciones:** permite restringir la ejecución a programas aprobados.
