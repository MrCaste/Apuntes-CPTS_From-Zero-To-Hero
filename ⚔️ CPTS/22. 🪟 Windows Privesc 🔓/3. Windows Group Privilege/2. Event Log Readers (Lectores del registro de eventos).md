
## 1. Comprobar la pertenencia al grupo

```
net localgroup "Event Log Readers"
```

Este grupo permite leer determinados registros de eventos de la máquina local sin necesidad de ser administrador.

**Objetivo:** buscar información sensible, como credenciales que hayan quedado registradas en los comandos ejecutados.

## 2. Buscar credenciales con `wevtutil`

Windows puede registrar la creación de procesos mediante el **evento 4688**. Si está habilitado el registro de líneas de comandos, estas pueden incluir usuarios y contraseñas.

Buscar `/user` en el registro Security:

```
wevtutil qe Security /rd:true /f:text | Select-String "/user"
```

Ejemplo de información que podría aparecer:

```
Process Command Line: net use T: \\fs01\backups /user:tim MyStr0ngP@ssword
```

En este caso, el comando revela el usuario `tim` y una contraseña que se pasó como argumento.

### Consultar un equipo remoto

```
wevtutil qe Security /rd:true /f:text /r:share01 /u:julie.clay /p:Welcome1
```

Parámetros:

- `/r`: equipo remoto.
    
- `/u`: usuario para autenticarse.
    
- `/p`: contraseña.
    

## 3. Buscar eventos 4688 con PowerShell

Filtrar los eventos de creación de procesos cuya línea de comandos contenga `/user`:

```
Get-WinEvent -LogName Security |
    Where-Object { $_.ID -eq 4688 -and $_.Properties[8].Value -like '*/user*' } |
    Select-Object @{Name='CommandLine'; Expression={$_.Properties[8].Value}}
```

**Importante:** según el material, consultar el registro `Security` con `Get-WinEvent` requiere permisos de administrador o permisos adecuados sobre la clave de registro correspondiente. Pertenecer únicamente a `Event Log Readers` no garantiza ese acceso.

## 4. Buscar información en los registros de PowerShell

El registro **PowerShell Operational** también puede contener información sensible si están habilitados:

- Script Block Logging.
    
- Module Logging.
    

Este registro puede ser accesible para usuarios sin privilegios.

Consultar eventos:

```
Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational"
```

Buscar posibles referencias a usuarios o contraseñas:

```
Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" |
    Select-Object TimeCreated, Id, Message
```

Para filtrar mensajes que mencionen contraseñas:

```
Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" |
    Where-Object { $_.Message -match 'password|passwd|pwd' } |
    Select-Object TimeCreated, Id, Message
```

## Chuleta rápida

|Objetivo|Comando|
|---|---|
|Comprobar miembros del grupo|`net localgroup "Event Log Readers"`|
|Buscar `/user` en Security|`wevtutil qe Security /rd:true /f:text \| Select-String "/user"`|
|Filtrar eventos 4688|`Get-WinEvent -LogName Security`|
|Consultar el registro de PowerShell|`Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational"`|

### Flujo de enumeración

1. Ejecutar `net localgroup "Event Log Readers"` para comprobar la pertenencia al grupo.
    
2. Consultar los registros accesibles.
    
3. Buscar comandos que incluyan `/user`, contraseñas u otros argumentos sensibles.
    
4. Revisar los eventos 4688 y los registros de PowerShell si están disponibles.
    

**Nota:** los resultados dependen de que la auditoría correspondiente esté habilitada, de que los eventos sigan almacenados y de los permisos de acceso al registro.
