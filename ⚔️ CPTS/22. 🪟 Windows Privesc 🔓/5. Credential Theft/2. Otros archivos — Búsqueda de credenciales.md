
Durante la enumeración de Windows podemos encontrar **credenciales en archivos locales, carpetas compartidas, bases de datos y documentos**.

Estos archivos pueden contener contraseñas en texto plano, claves privadas o información que permita escalar privilegios.

## 1. Buscar credenciales en archivos

### Buscar archivos que contengan la palabra `password`

```
findstr /SIM /C:"password" *.txt *.ini *.cfg *.config *.xml
```

|Parámetro|Función|
|---|---|
|`/S`|Busca recursivamente en subdirectorios.|
|`/I`|Ignora mayúsculas y minúsculas.|
|`/M`|Muestra únicamente los nombres de los archivos.|
|`/C:`|Busca una cadena literal.|

**Ejemplo de resultado:**

```
C:\Users\htb-student\Documents\stuff.txt
```

### Mostrar las líneas que contienen contraseñas

Eliminar `/M`:

```
findstr /SI "password" *.xml *.ini *.txt *.config
```

Resultado:

```
stuff.txt:password: l#-x9r11_2_GL!
```

### Buscar en todos los tipos de archivos

```
findstr /SPIN "password" *.*
```

|Parámetro|Función|
|---|---|
|`/S`|Búsqueda recursiva.|
|`/P`|Omite archivos con caracteres no imprimibles.|
|`/I`|Ignora mayúsculas y minúsculas.|
|`/N`|Muestra el número de línea.|

Resultado:

```
stuff.txt:1:password: l#-x9r11_2_GL!
```

**Importante:** este comando busca desde el directorio actual. Si lo ejecutamos desde `C:\`, intentará recorrer sus subdirectorios accesibles.

### Buscar con PowerShell

```
Select-String -Path C:\Users\htb-student\Documents\*.txt -Pattern "password"
```

Resultado:

```
stuff.txt:1:password: l#-x9r11_2_GL!
```

Para buscar varias palabras:

```
Select-String -Path "C:\Users\htb-student\Documents\*.txt" -Pattern "password","passwd","credential","secret"
```

## 2. Buscar archivos por nombre o extensión

En lugar de buscar dentro de los archivos, podemos localizar aquellos cuyos nombres o extensiones sean interesantes.

### CMD: buscar archivos de configuración

```
where /R C:\ *.config
```

Ejemplo:

```
C:\inetpub\wwwroot\web.config
```

### CMD: buscar nombres relacionados con contraseñas

```
dir /S /B *pass*.txt
dir /S /B *pass*.xml
dir /S /B *pass*.ini
dir /S /B *cred*
dir /S /B *vnc*
```

- `/S`: búsqueda recursiva.
    
- `/B`: muestra únicamente las rutas.
    

### PowerShell: buscar extensiones interesantes

```
Get-ChildItem C:\ -Recurse -Include *.rdp,*.config,*.vnc,*.cred -ErrorAction Ignore
```

**Extensiones importantes:**

|Extensión|Posible contenido|
|---|---|
|`.config`|Configuración de aplicaciones y posibles credenciales.|
|`.rdp`|Configuraciones de conexiones RDP.|
|`.vnc`|Configuraciones de acceso remoto.|
|`.cred`|Información relacionada con credenciales.|
|`.kdbx`|Bases de datos de KeePass.|
|`.ppk`|Claves privadas SSH de PuTTY.|
|`.vmdk`|Discos virtuales de VMware.|
|`.vdhx`|Discos virtuales de Hyper-V.|

Los archivos `.vmdk` y `.vdhx` pueden contener sistemas de archivos completos, incluidos archivos de configuración y otros datos sensibles.

### Buscar archivos interesantes en Active Directory

En entornos de dominio, **Snaffler** permite enumerar recursos compartidos y localizar archivos potencialmente sensibles.

Es especialmente útil cuando los usuarios tienen permisos de lectura sobre carpetas compartidas que pertenecen a otros empleados.

## 3. Contraseñas en Sticky Notes

La aplicación **Sticky Notes** almacena las notas en una base de datos SQLite.

Algunos usuarios guardan contraseñas en estas notas.

### Ubicación de la base de datos

```
C:\Users\<usuario>\AppData\Local\Packages\Microsoft.MicrosoftStickyNotes_8wekyb3d8bbwe\LocalState\
```

Archivos importantes:

```
plum.sqlite
plum.sqlite-wal
plum.sqlite-shm
```

- `plum.sqlite`: base de datos principal.
    
- `plum.sqlite-wal`: registro de escritura que puede contener datos recientes.
    
- `plum.sqlite-shm`: archivo auxiliar de memoria compartida.
    

**Conviene conservar los tres archivos** al copiar la base de datos para analizarla, ya que algunas notas recientes pueden encontrarse en el archivo WAL.

### Enumerar los archivos

```
Get-ChildItem "C:\Users\htb-student\AppData\Local\Packages\Microsoft.MicrosoftStickyNotes_8wekyb3d8bbwe\LocalState"
```

## 4. Leer Sticky Notes con PSSQLite

Podemos utilizar el módulo **PSSQLite** para consultar la base de datos directamente desde PowerShell.

### Paso 1. Importar el módulo

```
Set-ExecutionPolicy Bypass -Scope Process
```

Acceder al directorio donde se encuentra el módulo:

```
cd C:\temp\PSSQLite
```

Importarlo:

```
Import-Module .\PSSQLite.psd1
```

**Importante:** el directorio debe contener los archivos necesarios del módulo, incluidos:

```
PSSQLite.psd1
PSSQLite.psm1
```

Si falta `PSSQLite.psm1`, PowerShell no podrá importar correctamente el módulo.

### Paso 2. Definir la ruta de la base de datos

```
$db = 'C:\Users\htb-student\AppData\Local\Packages\Microsoft.MicrosoftStickyNotes_8wekyb3d8bbwe\LocalState\plum.sqlite'
```

### Paso 3. Extraer las notas

```
Invoke-SqliteQuery -Database $db -Query "SELECT Text FROM Note" | Format-Table -Wrap
```

**Explicación:**

|Elemento|Función|
|---|---|
|`Invoke-SqliteQuery`|Ejecuta una consulta SQLite.|
|`-Database $db`|Especifica la base de datos.|
|`SELECT Text FROM Note`|Extrae la columna `Text` de la tabla `Note`.|
|`Format-Table -Wrap`|Muestra el contenido sin truncar las líneas largas.|

Ejemplo de resultado:

```
Text
----
vCenter
root:Vc3nt3R_adm1n!
Thycotic demo tomorrow at 10am
```

En este ejemplo encontramos posibles credenciales:

```
Usuario: root
Contraseña: Vc3nt3R_adm1n!
```

La nota también menciona `vCenter`, lo que podría indicar dónde se utilizan esas credenciales.

## 5. Leer Sticky Notes desde Kali

Otra opción es copiar la base de datos al equipo atacante y analizarla desde Linux.

### Método 1. SQLite

Una vez copiados los archivos `plum.sqlite*` al mismo directorio:

```
sqlite3 plum.sqlite
```

Dentro de SQLite:

```
.tables
```

Consultar las notas:

```
SELECT Text FROM Note;
```

Salir:

```
.quit
```

También podemos hacerlo directamente:

```
sqlite3 plum.sqlite "SELECT Text FROM Note;"
```

### Método 2. Strings

Si no queremos utilizar SQLite, podemos buscar cadenas legibles:

```
strings plum.sqlite
```

También debemos revisar el archivo WAL:

```
strings plum.sqlite-wal
```

Ejemplo:

```
vCenter
root:Vc3nt3R_adm1n!
```

**Diferencia:**

- `sqlite3`: permite consultar los registros de la base de datos.
    
- `strings`: extrae cadenas legibles de archivos binarios.
    

`strings` puede recuperar información interesante, pero es menos preciso que consultar directamente SQLite.

## 6. Otros archivos interesantes

El módulo menciona varias ubicaciones que pueden contener credenciales, hashes o información sensible.

### Archivos del sistema

```
%SYSTEMDRIVE%\pagefile.sys
%WINDIR%\debug\NetSetup.log
%WINDIR%\repair\sam
%WINDIR%\repair\system
%WINDIR%\repair\software
%WINDIR%\repair\security
```

**Qué buscar:**

- `pagefile.sys`: puede contener fragmentos de información que estuvieron en memoria.
    
- `NetSetup.log`: información relacionada con operaciones de configuración y unión a dominios.
    
- Archivos de `repair`: posibles copias de archivos del Registro, incluidos SAM y SYSTEM.
    

### Logs y archivos del Registro

```
%WINDIR%\iis6.log
%WINDIR%\system32\config\AppEvent.Evt
%WINDIR%\system32\config\SecEvent.Evt
%WINDIR%\system32\config\default.sav
%WINDIR%\system32\config\security.sav
%WINDIR%\system32\config\software.sav
%WINDIR%\system32\config\system.sav
%WINDIR%\system32\CCM\logs\*.log
```

Pueden contener información útil sobre aplicaciones, configuraciones y eventos del sistema.

### Archivos de usuario y configuraciones

```
%USERPROFILE%\ntuser.dat
%USERPROFILE%\LocalS~1\Tempor~1\Content.IE5\index.dat
%WINDIR%\System32\drivers\etc\hosts
C:\ProgramData\Configs\*
C:\Program Files\Windows PowerShell\*
```

Estas ubicaciones pueden revelar configuraciones, rutas, nombres de servidores o información útil para continuar la enumeración.

No todos estos archivos contienen contraseñas directamente y algunos requieren privilegios elevados para acceder a ellos.

## 7. Checklist para HTB / CPTS / OSCP

### Buscar contraseñas dentro de archivos

```
findstr /SPIN "password" *.*
```

### Buscar contraseñas en archivos de configuración

```
findstr /SI "password" *.xml *.ini *.txt *.config
```

### Buscar archivos de configuración

```
where /R C:\ *.config
```

### Buscar archivos interesantes con PowerShell

```
Get-ChildItem C:\ -Recurse -Include *.rdp,*.config,*.vnc,*.cred -ErrorAction Ignore
```

### Buscar bases de datos de Sticky Notes

```
Get-ChildItem C:\Users -Filter plum.sqlite -Recurse -ErrorAction SilentlyContinue
```

### Leer notas con PSSQLite

```
Import-Module C:\temp\PSSQLite\PSSQLite.psd1

$db = 'C:\Users\htb-student\AppData\Local\Packages\Microsoft.MicrosoftStickyNotes_8wekyb3d8bbwe\LocalState\plum.sqlite'

Invoke-SqliteQuery -Database $db -Query "SELECT Text FROM Note" | Format-Table -Wrap
```

### Leer notas desde Kali

```
sqlite3 plum.sqlite "SELECT Text FROM Note;"
```

O:

```
strings plum.sqlite-wal
```

## Resumen rápido

|Técnica|Herramienta|Objetivo|
|---|---|---|
|Buscar contraseñas en archivos|`findstr`|Encontrar credenciales en texto plano.|
|Buscar cadenas con PowerShell|`Select-String`|Localizar información sensible dentro de archivos.|
|Buscar archivos por extensión|`where`, `dir`, `Get-ChildItem`|Encontrar configuraciones y archivos interesantes.|
|Enumerar recursos compartidos|Snaffler|Localizar archivos sensibles en Active Directory.|
|Leer Sticky Notes|PSSQLite|Extraer notas almacenadas en SQLite.|
|Analizar Sticky Notes desde Kali|`sqlite3`|Consultar directamente la base de datos.|
|Extraer cadenas de archivos binarios|`strings`|Recuperar texto legible, incluso del archivo WAL.|

**Para el examen:**

1. Buscar archivos que contengan `password`, `credential` o `secret`.
    
2. Enumerar archivos `.config`, `.rdp`, `.kdbx`, `.ppk` y otros formatos interesantes.
    
3. Revisar las bases de datos de Sticky Notes.
    
4. Comprobar tanto `plum.sqlite` como `plum.sqlite-wal`.
    
5. Revisar archivos de configuración, logs y copias del Registro.
    
6. En entornos AD, investigar también los recursos compartidos con Snaffler.
    

**No dependas únicamente de WinPEAS u otras herramientas automáticas:** la enumeración manual puede revelar archivos que estas herramientas no detectan.
