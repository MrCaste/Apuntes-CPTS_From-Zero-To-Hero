
## 1. Firewalls e IDS/IPS

### Firewall

Un firewall controla el tráfico de red mediante reglas que determinan si los paquetes se permiten, se descartan o se rechazan.

- **Dropped:** el paquete se descarta sin recibir respuesta.
    
- **Rejected:** el paquete se rechaza explícitamente, por ejemplo, mediante un RST TCP o un error ICMP.
    

Algunos códigos ICMP que pueden aparecer:

- `Net Unreachable`
    
- `Net Prohibited`
    
- `Host Unreachable`
    
- `Host Prohibited`
    
- `Port Unreachable`
    
- `Proto Unreachable`
    

### IDS e IPS

|Sistema|Función|
|---|---|
|IDS (_Intrusion Detection System_)|Detecta posibles ataques y notifica al administrador.|
|IPS (_Intrusion Prevention System_)|Detecta posibles ataques y aplica medidas defensivas automáticamente.|

Ambos pueden utilizar patrones y firmas para identificar actividades sospechosas, como escaneos de puertos o detección de servicios.

## 2. Escaneo SYN frente a ACK

El escaneo ACK puede ayudar a analizar cómo responde un firewall al tráfico TCP.

### Escaneo SYN (`-sS`)

```
sudo nmap <IP> -p 21,22,25 -sS -Pn -n --disable-arp-ping --packet-trace
```

### Escaneo ACK (`-sA`)

```
sudo nmap <IP> -p 21,22,25 -sA -Pn -n --disable-arp-ping --packet-trace
```

Opciones importantes:

|Opción|Función|
|---|---|
|`-p 21,22,25`|Escanea únicamente los puertos especificados.|
|`-sS`|Escaneo TCP SYN.|
|`-sA`|Escaneo TCP ACK.|
|`-Pn`|No realiza descubrimiento de hosts mediante sondas de ping.|
|`-n`|Deshabilita la resolución DNS.|
|`--disable-arp-ping`|Deshabilita las sondas ARP de descubrimiento.|
|`--packet-trace`|Muestra los paquetes enviados y recibidos.|

### Interpretación de las respuestas

|Respuesta|Interpretación|
|---|---|
|SYN-ACK (`SA`) en un escaneo SYN|El puerto está abierto.|
|RST en un escaneo ACK|El paquete ha recibido una respuesta; Nmap clasifica el puerto como `unfiltered`.|
|Error ICMP explícito|Puede indicar que el tráfico se rechaza.|
|Ninguna respuesta|Puede indicar que los paquetes se descartan; Nmap puede clasificar el puerto como `filtered`.|

**Importante:** el escaneo ACK no permite determinar si un puerto está abierto o cerrado. Sirve para comprobar si las sondas ACK están filtradas.

## 3. Detección de IDS/IPS

Los IDS/IPS pueden detectar escaneos agresivos y aplicar medidas de seguridad, como bloquear la dirección IP de origen.

Durante una evaluación autorizada, conviene observar cómo responde la red a diferentes patrones de escaneo y determinar si existen mecanismos de detección o bloqueo.

Un escaneo agresivo puede generar alertas o provocar que el IPS bloquee el tráfico procedente de la máquina de pruebas.

## 4. Señuelos (_Decoys_)

La opción `-D` permite generar direcciones IP señuelo para que las sondas parezcan proceder de diferentes direcciones de origen.

Ejemplo del material:

```
sudo nmap <IP> -p 80 -sS -Pn -n --disable-arp-ping --packet-trace -D RND:5
```

- `-D RND:5`: genera cinco direcciones IP aleatorias como señuelos.
    
- `--packet-trace`: permite observar las sondas enviadas.
    

El ejemplo muestra varias direcciones de origen en los paquetes enviados, incluida la IP real del escáner.

**Limitaciones:** los paquetes con direcciones de origen falsificadas pueden ser filtrados por routers o proveedores de Internet. Además, los señuelos inactivos pueden provocar problemas de comunicación o de interpretación de los resultados.

## 5. Probar reglas del firewall con una IP de origen diferente

La opción `-S` permite especificar una dirección IP de origen y `-e` seleccionar la interfaz de red.

### Escaneo inicial

```
sudo nmap <IP> -n -Pn -p 445 -O
```

### Escaneo con otra IP de origen

```
sudo nmap <IP> -n -Pn -p 445 -O -S <IP_ORIGEN> -e tun0
```

Opciones:

|Opción|Función|
|---|---|
|`-O`|Intenta detectar el sistema operativo.|
|`-S <IP_ORIGEN>`|Especifica la dirección IP de origen.|
|`-e tun0`|Selecciona la interfaz por la que se envían las sondas.|

En el ejemplo del material, el puerto 445 aparece inicialmente como `filtered`, pero se muestra como `open` al utilizar otra dirección de origen.

**Importante:** para que una prueba con una dirección de origen alternativa funcione, esa dirección debe ser válida para el entorno de red y las respuestas deben poder regresar al escáner. No basta con cambiar la IP arbitrariamente.

## 6. Resolución DNS y puerto de origen

Nmap realiza resolución DNS inversa de forma predeterminada, salvo que se desactive con `-n`.

También permite especificar servidores DNS y modificar el puerto de origen de las sondas.

### Especificar servidores DNS

```
sudo nmap <IP> --dns-server <DNS1>,<DNS2>
```

### Utilizar el puerto de origen 53

```
sudo nmap <IP> -p 50000 -sS -Pn -n --disable-arp-ping --packet-trace --source-port 53
```

- `--dns-server`: especifica los servidores DNS que utilizará Nmap.
    
- `--source-port 53`: utiliza el puerto 53 como puerto de origen de las sondas.
    

El material muestra un caso en el que el puerto 50000 aparece como `filtered` en un escaneo normal, pero como `open` al utilizar el puerto de origen 53.

Esto puede indicar que las reglas del firewall tratan de forma diferente el tráfico procedente de determinados puertos. **No significa que utilizar el puerto 53 permita evadir cualquier firewall.**

### Verificar la conectividad con Netcat

```
ncat -nv --source-port 53 <IP> 50000
```

Esta orden intenta establecer una conexión con el puerto 50000 utilizando el puerto de origen 53.

En el ejemplo, la conexión devuelve el banner:

```
220 ProFTPd
```

Esto permite identificar el servicio que responde en el puerto.

## 8. Conceptos clave para el examen

- `**filtered**`: Nmap no puede determinar con claridad si el puerto está abierto porque el filtrado impide obtener una respuesta concluyente.
    
- `**unfiltered**`: el escaneo ACK recibe una respuesta que indica que el paquete no está filtrado, pero no determina si el puerto está abierto o cerrado.
    
- **SYN-ACK**: indica un puerto abierto durante un escaneo SYN.
    
- **RST**: respuesta TCP que puede indicar que no existe una conexión aceptada para esa sonda.
    
- **Dropped frente a rejected**: los paquetes descartados no reciben respuesta; los rechazados generan una respuesta explícita.
    
- `**-D**`: introduce direcciones señuelo en el escaneo.
    
- `**-S**` **y** `**-e**`: permiten especificar la IP de origen y la interfaz de red.
    
- `**--source-port**`: permite comprobar si las reglas de filtrado tratan de forma diferente el tráfico según su puerto de origen.
    

Todas estas técnicas deben probarse únicamente en sistemas y redes para los que tengas autorización.
