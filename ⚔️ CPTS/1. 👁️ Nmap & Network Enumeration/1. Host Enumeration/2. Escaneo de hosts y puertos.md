
## 1. Objetivos del escaneo

Una vez identificado un host activo, queremos obtener información sobre:

- Puertos abiertos y sus servicios.
    
- Versiones de los servicios.
    
- Información proporcionada por los servicios.
    
- Sistema operativo.
    

## 2. Estados de los puertos en Nmap

|Estado|Descripción|
|---|---|
|`open`|El puerto acepta conexiones TCP, datagramas UDP o asociaciones SCTP.|
|`closed`|El puerto es accesible, pero no hay un servicio escuchando. En TCP suele responder con `RST`.|
|`filtered`|Nmap no puede determinar si está abierto o cerrado debido a la ausencia de respuesta o a un error.|
|`unfiltered`|El puerto es accesible, pero no se puede determinar si está abierto o cerrado. Aparece con el escaneo TCP ACK.|
|`open|filtered`|Nmap no recibe respuesta y no puede distinguir entre un puerto abierto y uno filtrado.|
|`closed|filtered`|Nmap no puede distinguir entre un puerto cerrado y uno filtrado. Aparece con el escaneo IP ID idle.|

## 3. Descubrimiento de puertos TCP

Por defecto, Nmap escanea los **1000 puertos TCP principales**.

- Como `root`, utiliza normalmente el escaneo SYN (`-sS`).
    
- Sin privilegios suficientes, utiliza el escaneo TCP Connect (`-sT`).
    

### Especificar los puertos

```
# Puertos concretos
sudo nmap 10.129.2.28 -p 22,25,80,139,445

# Rango de puertos
sudo nmap 10.129.2.28 -p 22-445

# 10 puertos principales
sudo nmap 10.129.2.28 --top-ports=10

# Todos los puertos TCP
sudo nmap 10.129.2.28 -p-

# Escaneo rápido de los 100 puertos principales
sudo nmap 10.129.2.28 -F
```

### Analizar los paquetes enviados y recibidos

```
sudo nmap 10.129.2.28 -p 21 --packet-trace -Pn -n --disable-arp-ping
```

Opciones importantes:

|Opción|Función|
|---|---|
|`-p`|Especifica los puertos que se escanearán.|
|`--top-ports=N`|Escanea los N puertos principales de Nmap.|
|`-p-`|Escanea todos los puertos TCP.|
|`-F`|Escanea los 100 puertos principales.|
|`--packet-trace`|Muestra los paquetes enviados y recibidos.|
|`-Pn`|Omite el descubrimiento de hosts y trata el objetivo como activo.|
|`-n`|Desactiva la resolución DNS.|
|`--disable-arp-ping`|Desactiva el descubrimiento mediante ARP ping.|
|`--reason`|Muestra el motivo por el que Nmap asigna un estado al puerto.|

### Interpretar un escaneo SYN

Ejemplo de salida:

```
SENT TCP 10.10.14.2:63090 > 10.129.2.28:21 S
RCVD TCP 10.129.2.28:21 > 10.10.14.2:63090 RA
```

- `SENT`: paquete enviado por Nmap.
    
- `RCVD`: paquete recibido del objetivo.
    
- `S`: indicador SYN, utilizado para iniciar una conexión TCP.
    
- `SA`: indicadores SYN y ACK; respuesta habitual de un puerto abierto.
    
- `RA`: indicadores RST y ACK; respuesta habitual de un puerto cerrado.
    

En el ejemplo, el objetivo responde con `RA`, por lo que el puerto TCP 21 aparece como `closed`.

## 4. Escaneo TCP Connect (`-sT`)

El escaneo TCP Connect utiliza el saludo de tres vías de TCP (_three-way handshake_) para comprobar el estado de los puertos.

```
sudo nmap 10.129.2.28 -p 443 -sT --packet-trace --disable-arp-ping -Pn -n --reason
```

Funcionamiento general:

1. Nmap envía un paquete SYN.
    
2. Si recibe SYN-ACK, el puerto está abierto.
    
3. Si recibe RST, el puerto está cerrado.
    
4. Si no obtiene una respuesta concluyente, puede aparecer como filtrado.
    

El escaneo Connect completa la conexión TCP, por lo que puede generar registros y ser detectado fácilmente por soluciones IDS/IPS. Sin embargo, interactúa con los servicios como una conexión TCP normal y puede ser útil cuando se prioriza la precisión.

El escaneo SYN (`-sS`) es semiabierto: no completa el saludo de tres vías y suele considerarse más discreto, aunque los IDS/IPS modernos también pueden detectarlo.

## 5. Puertos filtrados y firewalls

Un puerto puede aparecer como `filtered` cuando un firewall descarta o rechaza los paquetes.

### Paquetes descartados (_dropped_)

```
sudo nmap 10.129.2.28 -p 139 --packet-trace -n --disable-arp-ping -Pn
```

Si el firewall descarta los paquetes:

- Nmap no recibe respuesta.
    
- Puede retransmitir los paquetes.
    
- El puerto aparece como `filtered`.
    
- El escaneo tarda más debido a los tiempos de espera y reintentos.
    

Por defecto, `--max-retries` está establecido en `10`.

### Paquetes rechazados (_rejected_)

```
sudo nmap 10.129.2.28 -p 445 --packet-trace -n --disable-arp-ping -Pn
```

El objetivo puede devolver un error ICMP indicando que el puerto es inalcanzable. En el ejemplo del módulo aparece:

```
ICMP ... Port 445 unreachable (type=3/code=3)
```

El puerto sigue apareciendo como `filtered`. Si sabemos que el host está activo, esta respuesta puede indicar que una regla del firewall está rechazando el tráfico.

**Diferencia importante:**

- **Dropped:** no hay respuesta; Nmap espera y puede retransmitir.
    
- **Rejected:** se recibe una respuesta de error, como ICMP de puerto inalcanzable.
    

## 6. Descubrimiento de puertos UDP (`-sU`)

UDP no utiliza un saludo de tres vías como TCP. Por ello, el escaneo UDP suele ser mucho más lento: frecuentemente no se recibe respuesta y Nmap debe esperar antes de decidir el estado del puerto.

```
# Escaneo rápido de los 100 puertos principales UDP
sudo nmap 10.129.2.28 -F -sU

# Escanear un puerto UDP concreto
sudo nmap 10.129.2.28 -sU -p 137 -Pn -n --disable-arp-ping --packet-trace --reason
```

### Interpretación de los resultados UDP

|Respuesta|Estado habitual|
|---|---|
|El servicio responde mediante UDP|`open`|
|ICMP tipo 3, código 3: puerto inalcanzable|`closed`|
|No hay respuesta|`open|filtered`|
|Se recibe otra respuesta ICMP de error|Normalmente `open|filtered`|

Ejemplos:

```
# UDP 137: comprobar si el servicio responde
sudo nmap 10.129.2.28 -sU -p 137 -Pn -n --disable-arp-ping --packet-trace --reason

# UDP 100: comprobar si está cerrado
sudo nmap 10.129.2.28 -sU -p 100 -Pn -n --disable-arp-ping --packet-trace --reason

# UDP 138: analizar un puerto sin respuesta
sudo nmap 10.129.2.28 -sU -p 138 -Pn -n --disable-arp-ping --packet-trace --reason
```

**Importante:** que un puerto UDP aparezca como `open|filtered` no significa que esté abierto con certeza. Puede estar abierto y no responder a los datagramas enviados, o el tráfico puede estar siendo filtrado.

## 7. Detección de servicios y versiones (`-sV`)

La opción `-sV` permite obtener información adicional sobre los servicios de los puertos abiertos, como el nombre del servicio, su versión y otros detalles que el servicio revele.

```
sudo nmap 10.129.2.28 -p 445 -sV -Pn -n --disable-arp-ping --reason
```

Para analizar también el intercambio de paquetes:

```
sudo nmap 10.129.2.28 -p 445 -sV -Pn -n --disable-arp-ping --packet-trace --reason
```

Ejemplo de resultado:

```
PORT    STATE SERVICE     REASON  VERSION
445/tcp open  netbios-ssn syn-ack Samba smbd 3.X - 4.X
```

En este caso, Nmap identifica el servicio como Samba y obtiene información sobre su versión y el grupo de trabajo.

La detección de versiones puede tardar más que un escaneo básico porque Nmap envía sondas específicas al servicio y analiza las respuestas.

## 8. Flujo de trabajo práctico

### Paso 1: identificar los puertos TCP abiertos

```
sudo nmap <IP> -p-
```

### Paso 2: identificar los servicios y sus versiones

```
sudo nmap <IP> -p <PUERTOS> -sV
```

### Paso 3: escanear UDP

```
sudo nmap <IP> -sU -F
```

### Paso 4: investigar un puerto concreto

```
sudo nmap <IP> -p <PUERTO> -Pn -n --disable-arp-ping --packet-trace --reason
```

### Paso 5: interpretar el resultado

- `open`: investigar el servicio.
    
- `closed`: el puerto responde, pero está cerrado.
    
- `filtered`: comprobar las posibles reglas de filtrado y la ausencia o el tipo de respuesta.
    
- `open|filtered`: especialmente en UDP, no asumir que el puerto está abierto; puede ser necesario investigar más.
    
- `-sV`: utilizarlo para identificar los servicios y sus versiones.
    

**Idea clave:** primero identifica los puertos, después determina los servicios y sus versiones, y utiliza `--packet-trace` y `--reason` cuando necesites entender por qué Nmap asigna un estado concreto.
