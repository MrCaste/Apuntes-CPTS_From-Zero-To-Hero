
## 1. Optimización del escaneo

Nmap permite ajustar el rendimiento mediante diferentes opciones:

|Opción|Descripción|
|---|---|
|`-T <0-5>`|Selecciona la plantilla de temporización.|
|`--initial-rtt-timeout <tiempo>`|Establece el tiempo de espera RTT inicial.|
|`--max-rtt-timeout <tiempo>`|Establece el tiempo de espera RTT máximo.|
|`--max-retries <número>`|Limita el número de reintentos por paquete.|
|`--min-rate <número>`|Establece la tasa mínima de paquetes enviados por segundo.|
|`--min-parallelism <número>`|Establece el paralelismo mínimo de las pruebas.|

**Importante:** acelerar el escaneo puede reducir la precisión y provocar que algunos hosts o puertos pasen desapercibidos.

## 2. Ajustar los tiempos de espera (RTT)

El RTT (_Round-Trip Time_) es el tiempo que tarda un paquete en llegar al objetivo y recibir una respuesta.

Ejemplo de escaneo de una red utilizando los 100 puertos principales:

```
# Escaneo predeterminado
sudo nmap 10.129.2.0/24 -F

# Escaneo con tiempos RTT ajustados
sudo nmap 10.129.2.0/24 -F --initial-rtt-timeout 50ms --max-rtt-timeout 100ms
```

- `-F`: escanea los 100 puertos principales.
    
- `--initial-rtt-timeout 50ms`: establece el RTT inicial en 50 milisegundos.
    
- `--max-rtt-timeout 100ms`: establece el RTT máximo en 100 milisegundos.
    

**Conclusión:** reducir demasiado los tiempos de espera puede acelerar el escaneo, pero también provocar que se pierdan respuestas y hosts.

## 3. Limitar los reintentos

Nmap realiza reintentos cuando no recibe respuestas. El material indica que el valor predeterminado es 10.

```
# Escaneo normal
sudo nmap 10.129.2.0/24 -F

# Escaneo sin reintentos
sudo nmap 10.129.2.0/24 -F --max-retries 0
```

- `--max-retries 0`: no realiza reintentos cuando no recibe respuesta.
    

Para contar las líneas de resultados correspondientes a puertos TCP:

```
sudo nmap 10.129.2.0/24 -F | grep "/tcp" | wc -l
```

**Importante:** reducir los reintentos puede mejorar el rendimiento, pero también hacer que se pierdan puertos abiertos debido a paquetes sin respuesta.

## 4. Establecer una tasa mínima de paquetes

La opción `--min-rate` indica la tasa mínima de paquetes por segundo que Nmap intentará mantener.

```
# Escaneo predeterminado
sudo nmap 10.129.2.0/24 -F -oN tnet.default

# Escaneo con una tasa mínima de 300 paquetes por segundo
sudo nmap 10.129.2.0/24 -F -oN tnet.minrate300 --min-rate 300
```

- `--min-rate 300`: intenta mantener una tasa mínima de 300 paquetes por segundo.
    
- `-oN`: guarda los resultados en formato normal.
    
- `-F`: escanea los 100 puertos principales.
    

Para comparar el número de resultados:

```
cat tnet.default | grep "/tcp" | wc -l
cat tnet.minrate300 | grep "/tcp" | wc -l
```

En el ejemplo del material, ambos escaneos encontraron 23 resultados de puertos TCP, pero el escaneo optimizado tardó menos.

**Recomendación:** ajusta la tasa teniendo en cuenta el ancho de banda y las condiciones de la red.

## 5. Plantillas de temporización (`-T`)

Nmap proporciona seis plantillas que determinan la agresividad y velocidad del escaneo.

|Opción|Nombre|Característica|
|---|---|---|
|`-T 0`|`paranoid`|Temporización muy lenta.|
|`-T 1`|`sneaky`|Temporización lenta.|
|`-T 2`|`polite`|Reduce la agresividad del escaneo.|
|`-T 3`|`normal`|Configuración predeterminada.|
|`-T 4`|`aggressive`|Escaneo más rápido.|
|`-T 5`|`insane`|Escaneo muy agresivo.|

Ejemplos:

```
# Temporización predeterminada
sudo nmap 10.129.2.0/24 -F -oN tnet.default

# Temporización muy agresiva
sudo nmap 10.129.2.0/24 -F -oN tnet.T5 -T 5
```

Las plantillas permiten adaptar rápidamente el escaneo sin configurar manualmente cada parámetro.

**Precaución:** una temporización demasiado agresiva puede provocar que los sistemas de seguridad bloqueen el tráfico o que se pierda información durante el escaneo.

## 6. Flujo práctico para optimizar Nmap

```
# 1. Escaneo inicial de los 100 puertos principales
sudo nmap <IP> -F

# 2. Ajustar los tiempos RTT
sudo nmap <IP> -F --initial-rtt-timeout 50ms --max-rtt-timeout 100ms

# 3. Reducir los reintentos
sudo nmap <IP> -F --max-retries 0

# 4. Establecer una tasa mínima de paquetes
sudo nmap <IP> -F --min-rate 300

# 5. Utilizar una plantilla agresiva
sudo nmap <IP> -F -T 4

# 6. Guardar los resultados para compararlos
sudo nmap <IP> -F -oN resultado.txt
```

> **Para el examen:** recuerda que acelerar un escaneo no garantiza obtener los mismos resultados. Los tiempos RTT demasiado cortos, la reducción de reintentos y las tasas elevadas pueden provocar que se pasen por alto hosts o puertos. Elige los parámetros según las condiciones de la red.
