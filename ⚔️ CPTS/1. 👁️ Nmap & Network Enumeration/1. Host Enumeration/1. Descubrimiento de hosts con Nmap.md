
## 1. Descubrimiento de hosts

El descubrimiento de hosts permite identificar qué sistemas están activos dentro de una red antes de realizar un escaneo de puertos y servicios.

Nmap ofrece diferentes técnicas para comprobar si un host está activo. Una de ellas utiliza solicitudes de eco ICMP, aunque los firewalls pueden bloquearlas.

**Importante:** si Nmap no recibe respuesta, no significa necesariamente que el host esté apagado; puede estar filtrando las solicitudes de descubrimiento.

Se recomienda guardar los resultados de cada escaneo para compararlos y documentarlos posteriormente.

---

## 2. Escanear un rango de red

Para descubrir hosts activos en una subred:

```
sudo nmap 10.129.2.0/24 -sn -oA tnet
```

Para mostrar únicamente las direcciones IP detectadas en la salida:

```
sudo nmap 10.129.2.0/24 -sn -oA tnet | grep for | cut -d" " -f5
```

### Opciones utilizadas

|Opción|Descripción|
|---|---|
|`10.129.2.0/24`|Rango de direcciones que se va a analizar.|
|`-sn`|Desactiva el escaneo de puertos y realiza descubrimiento de hosts.|
|`-oA tnet`|Guarda los resultados en los formatos de salida habituales de Nmap usando `tnet` como prefijo.|
|`grep for`|Filtra las líneas que contienen `for`.|
|`cut -d" " -f5`|Extrae el quinto campo separado por espacios.|

---

## 3. Escanear una lista de IPs

Cuando tenemos una lista de objetivos, podemos guardarlos en un archivo:

```
cat hosts.lst
```

Ejemplo de contenido:

```
10.129.2.4
10.129.2.10
10.129.2.11
10.129.2.18
10.129.2.19
10.129.2.20
10.129.2.28
```

Ejecutar el descubrimiento de hosts sobre esa lista:

```
sudo nmap -sn -oA tnet -iL hosts.lst
```

Para mostrar únicamente las IPs detectadas:

```
sudo nmap -sn -oA tnet -iL hosts.lst | grep for | cut -d" " -f5
```

|Opción|Descripción|
|---|---|
|`-iL hosts.lst`|Lee los objetivos desde el archivo indicado.|
|`-sn`|Desactiva el escaneo de puertos.|
|`-oA tnet`|Guarda los resultados en varios formatos.|

**Nota:** los hosts que no aparecen en los resultados pueden estar apagados o no responder al método de descubrimiento utilizado.

---

## 4. Escanear varias IPs

Podemos indicar las direcciones IP directamente:

```
sudo nmap -sn -oA tnet 10.129.2.18 10.129.2.19 10.129.2.20
```

Si las direcciones son consecutivas, también podemos especificar un rango:

```
sudo nmap -sn -oA tnet 10.129.2.18-20
```

Ambos métodos permiten realizar el descubrimiento sobre los objetivos indicados sin escanear sus puertos.

---

## 5. Escanear una sola IP

Para comprobar si un host está activo:

```
sudo nmap 10.129.2.18 -sn -oA host
```

Nmap puede utilizar solicitudes ARP para descubrir hosts dentro de la red local.

Por eso, aunque esperemos utilizar ICMP, la respuesta ARP puede ser suficiente para que Nmap determine que el host está activo.

---

## 6. Descubrimiento mediante ICMP

### Enviar solicitudes de eco ICMP

Para indicar explícitamente a Nmap que utilice solicitudes de eco ICMP:

```
sudo nmap 10.129.2.18 -sn -oA host -PE
```

|Opción|Descripción|
|---|---|
|`-PE`|Utiliza solicitudes de eco ICMP para el descubrimiento.|
|`-sn`|Desactiva el escaneo de puertos.|

### Mostrar los paquetes enviados y recibidos

Podemos utilizar `--packet-trace` para observar el tráfico generado durante el escaneo:

```
sudo nmap 10.129.2.18 -sn -oA host -PE --packet-trace
```

Esta opción permite comprobar qué paquetes se envían y qué respuestas se reciben.

### Mostrar el motivo por el que Nmap considera activo un host

```
sudo nmap 10.129.2.18 -sn -oA host -PE --reason
```

La opción `--reason` muestra el motivo por el que Nmap ha determinado el estado del host.

Por ejemplo, la salida puede indicar:

```
Host is up, received arp-response
```

Esto significa que Nmap ha considerado activo el host porque recibió una respuesta ARP.

### Deshabilitar el descubrimiento mediante ARP

Si queremos observar el comportamiento de las solicitudes ICMP sin que el descubrimiento ARP determine el resultado:

```
sudo nmap 10.129.2.18 -sn -oA host -PE --packet-trace --disable-arp-ping
```

Con estas opciones podemos observar directamente una solicitud de eco ICMP y su respuesta.

|Opción|Descripción|
|---|---|
|`--disable-arp-ping`|Deshabilita el descubrimiento mediante ping ARP.|
|`-PE`|Solicita el descubrimiento mediante eco ICMP.|
|`--packet-trace`|Muestra los paquetes enviados y recibidos.|

**Concepto clave:** ARP e ICMP son mecanismos diferentes. En una red local, Nmap puede detectar un host mediante ARP aunque hayamos especificado `-PE`. Para comprobar el comportamiento de ICMP de forma aislada, podemos utilizar `--disable-arp-ping`.

## 7. Comandos esenciales para el examen

|Objetivo|Comando|
|---|---|
|Descubrir hosts de una subred|`sudo nmap 10.129.2.0/24 -sn`|
|Guardar resultados en varios formatos|`sudo nmap 10.129.2.0/24 -sn -oA tnet`|
|Leer objetivos desde un archivo|`sudo nmap -sn -iL hosts.lst`|
|Escanear varias IPs|`sudo nmap -sn 10.129.2.18 10.129.2.19 10.129.2.20`|
|Escanear un rango de IPs|`sudo nmap -sn 10.129.2.18-20`|
|Utilizar eco ICMP|`sudo nmap 10.129.2.18 -sn -PE`|
|Mostrar paquetes enviados y recibidos|`sudo nmap 10.129.2.18 -sn -PE --packet-trace`|
|Mostrar el motivo del resultado|`sudo nmap 10.129.2.18 -sn --reason`|
|Deshabilitar el descubrimiento ARP|`sudo nmap 10.129.2.18 -sn -PE --disable-arp-ping`|

## 8. Resumen final

- `-sn`: realiza descubrimiento de hosts sin escanear puertos.
    
- `-oA`: guarda los resultados en varios formatos.
    
- `-iL`: obtiene los objetivos de un archivo.
    
- `-PE`: utiliza solicitudes de eco ICMP.
    
- `--packet-trace`: permite observar los paquetes enviados y recibidos.
    
- `--reason`: explica por qué Nmap ha asignado un estado.
    
- `--disable-arp-ping`: deshabilita el descubrimiento mediante ping ARP.
    
- Un host que no responde al descubrimiento puede estar filtrando las solicitudes, no necesariamente estar apagado.
    
- ARP e ICMP permiten descubrir hosts de formas diferentes; hay que comprobar qué mecanismo ha producido el resultado.
